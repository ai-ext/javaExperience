# 04. 시나리오 전체 평가 — 8개 기준 (2026-10-22)

## 방법

- 시나리오 md 전부(101단계 + labs L12~16 + DB-01~14, 약 9만 줄)를 7묶음으로 나눠 정독했다(서브에이전트, 같은 기준표). 요구사항·계약·채점 기준·직접 확인·힌트는 정독했고, 정답 코드 접기와 MyBatis 대안은 훑었다. 4~9장은 6장 이후 일부 JSON을 줄 앞부분만 읽었다.
- 직접 확인한 것
  - HTML 렌더: 4-2, 14-4를 브라우저로 열었다. 슬라이드형 "focused journey"는 101개 중 7개 페이지에만 있다. 14-4 한 페이지에 요청 버튼 43개, 접기 131개가 있다.
  - 정답 snapshot 실행: 1-6·7-3·10-12는 컴파일, 4-2·9-5·16-4는 Testcontainers 테스트까지 돌렸다(JDK 21 컨테이너 + Colima). 결과는 14/36/46개 통과, 실패 0.
  - 시드 대조: 각 묶음에서 채점 기대값(4-3 순서, 8-1 집계, 15장 랭킹 3주치, DB-01 50건 등)을 덤프 SQL로 계산했고 모두 일치했다.
  - 지적 원문 대조: 아래 "확인" 표시 항목은 원문을 열어 직접 봤다.

## 과제로 줄 때 — 범위 제안

"뭐부터 개발할지 순서대로, 실무처럼"이라는 목적에 맞춰 고르면 아래와 같다.

| 주차 | 필수 | 이유 |
|---|---|---|
| 1 | (Java 처음인 사람만 0-1·0-3·0-5) 1-1~1-6, 2-1~2-3, 3-0~3-2 | API 하나가 받기 → 저장 → 계층 → 검증 → 인증으로 커지는 순서가 그대로 실무 순서다 |
| 2 | 4-0~4-3, 5-0~5-3, 7-1~7-3 | 멱등·동시성·트리 조회, 그리고 지금까지 만든 것을 테스트로 고정한다 |
| 3 | 8-1·8-2, 9-1·9-3, 그리고 16-1 | 쿼리 집계·고정 시계, Flyway·백필, 커밋 후 이벤트 |
| 4 | 티켓 5개 (T-004, T-007, T-017, T-019, 고급 1) 또는 10장 | "주어진 코드 위에서 고치기" 또는 "명세서만 보고 만들기" |

선택: 6장(분량 축소 후), 11~15장은 배치될 팀 성격에 따라 1~2단계씩, DB-01·02·03·05·10·13.
빼기: 0-7·0-8, 1-7·1-9, L12~L14(현 구조), 2-4(테스트를 배우기 전이라).

## 과제로 바꾸기 위한 최소 손질

1. 시작 브랜치 정리(#1·#2·#3)
2. 학습자용 배포본에서 정답 접기·힌트 코드를 빼거나 별도 브랜치로 옮긴다. 남길 것은 상황·만들 것·직접 확인·채점 기준 네 섹션이다
3. 필수 경로 단계의 오기·거짓 양성(#5~#9) 수정
4. T 항목 중 정답 시그니처에 묶인 것은 "만들 것"에 시그니처를 명시하거나 학습자가 직접 테스트를 쓰는 과제로 바꾼다
