# P7 R4. 화면 검사 (1440·390 × 라이트·다크) — 숫자 먼저, 스크린샷은 마지막

- 기준: 커밋 `5d6bda3`(HEAD) 의 생성 HTML. 저장소 루트를 `python3 -m http.server`(127.0.0.1)로 띄우고 gstack browse 로 열었다.
- 범위: 홈(`index.html`), 과정 지도(`course/map.html`), D01·D04·D08·D09·D12·D15, J04·J11, B01·B05·B16·E01. 시나리오 25개(기본 화면 + 접기 전부 열림 + 흐름 중간 정지 + 원인 접기 열고 중간 정지 + 지도 노드 고름) × 4 조합 = 100 화면.
- 방법: `tools/site/html-check/` (아래 "도구") 로 축소·작은 글자·겹침·넘침·안 그려짐·반복·가로 넘침·흐름 조작부를 JSON 으로 받고, 대비·조작 요소 크기·제목 구조는 같은 방식의 임시 측정 스크립트로 쟀다. 스크린샷은 숫자로 안 잡히는 보기 문제만 마지막에 6장(잘라서).
- 테마: 사이트에 테마 단추가 없고 CSS 가 `prefers-color-scheme` 과 `:root[data-theme]` 를 함께 본다. `document.documentElement.dataset.theme` 으로 강제했다.
- 결론: **blocker 0, major 1, minor 8**, 참고 4. check.js 6종 + 가로 넘침 + 흐름 조작부는 100 화면 모두 실제 문제 0건(반복 `dup` 7종은 전부 오탐). 남은 문제는 숫자 검사 바깥(말줄임·대비·한국어 줄바꿈·홈 다크 미지원)에 모여 있다.

## 5. 도구 (이번에 추가)

- `tools/site/html-check/check.js` — `~/reference/tools/html-check/check.js` 그대로(출처 주석 한 줄만 추가).
- `tools/site/html-check/extra.js` — 사이트 전용: `__hscroll`(가로 스크롤 + html·body overflow 로 잘린 요소), `__flowCheck`(흐름 조작부), `__hideSrOnly`(sr-only 오탐 제거).
- `tools/site/html-check/run-site.sh` — 빈 포트에 http 서버를 띄우고 시나리오 `[{name, path, js?, root?, flow?}]` 마다 새로 열어 검사, `이름<TAB>JSON`, 마지막 줄 콘솔 에러. `VIEWPORT`·`THEME`·`SUMMARY=1`. 서버는 trap 으로 항상 끄고, 브라우저 데몬도 끈다(`KEEP_BROWSER=1` 이면 유지). browse 의 `js` 는 코드에 `await` 가 있으면 async 본문으로 감싸 마지막 식을 돌려주지 않아서 모든 호출에 명시적 `return` 을 쓴다.
- `tools/site/html-check/scenarios-course.json` — 위 25 시나리오.
- `tools/site/html-check/check-generated.sh` + `npm run check:generated` — 다시 빌드한 HTML 이 커밋된 HTML 과 다르면 차이(`git diff --stat`)와 새 파일을 보이고 exit 1. 되돌리지 않는다. 빌드가 HTML 을 덮어쓰므로 커밋 안 된 HTML 변경이 있으면 빌드 전에 exit 2 로 멈춘다. 현재 HEAD: "생성 HTML = 커밋된 HTML"(exit 0).
- `npm run check:html` — `run-site.sh html-check/scenarios-course.json`.
- 변형 검사(사본이 아니라 열린 페이지에 js 로 주입, 저장소 파일은 그대로): 다음 단추 리스너 끊기 → `flow: 다음 후 1 / 8`, 단계 목록 opacity 0.2 → `flow: 단계2 안 보임`, 390 에서 600px 상자 → `hscroll: 화면 밖으로 잘린 요소 1개`(이 변형으로 html·body overflow 가 스크롤을 숨기는 것을 찾아 `__hscroll` 을 고쳤다), 본문 7px → `minFont 6.2px`. 네 가지 모두 잡혔다. 생성 HTML 가드는 J04.html 끝에 한 줄 추가 → exit 2, J04.md 에 한 줄 추가 후 빌드 → `course/java/J04.html | 1 +` 로 실패 확인 뒤 둘 다 되돌렸다.

## 6. 토큰·크기 비교

- 숫자: `SUMMARY=1` 출력은 조합당 **1,977 B**(25 시나리오, 약 30초), 4 조합 7.9 KB. 전체 항목 출력은 조합당 3,148 B. 한글이 많아 대략 조합당 수백 토큰, 4 조합 합쳐 수천 토큰 이하로 추정(토큰 수는 재지 않았다).
- 스크린샷: 잘라 찍은 6장 = ⌈w/28⌉×⌈h/28⌉ 합 **2,964 토큰**(434·378·350·660·350·792). 파일 크기는 63~203 KB.
- 같은 100 화면을 화면 크기 스크린샷으로 봤다면 1440×900 50장 × 1,716 + 390×844 50장 × 434 ≈ **107,500 토큰**이고, 그것도 각 페이지 첫 화면만 보인다(D04 흐름 영역만 390 에서 높이 3,895px).
- 숫자 검사로 100 화면의 기하 문제를 0 으로 확정한 뒤, 스크린샷 6장은 숫자로 안 잡히는 R4-01·02·06·08·09 확인에만 썼다.
