3줄 요약 — Spring Bean은 컨테이너에 등록되어 생성과 의존성 연결을 맡기는 객체다.
직접 작성한 클래스는 @Component 계열로 스캔하고, 외부 라이브러리 객체는 @Configuration의 @Bean으로 등록한다.
주입은 생성자 방식이 기본이며, private final 필드와 Lombok @RequiredArgsConstructor를 함께 쓰면 필수 의존성이 생성자로 전달된다.

011. 한 줄로 말하면열기 ↓

빈(Bean)은 Spring ApplicationContext가 정의를 읽어 생성하고 의존성을 연결해 관리하는 객체다. 객체가 필요한 구현체를 직접 new 하거나 전역에서 찾지 않아 구현 변경과 테스트 대체가 쉽다. 등록과 생성자 주입 규칙으로 연결 오류를 진단한다.

022. 당장 알아야 할 것열기 ↓

  1. 등록: 직접 작성한 클래스는 @Component 계열, 라이브러리 객체는 @Configuration + @Bean으로 등록한다. 기본 이름은 클래스명의 첫 글자 소문자 또는 메서드명이다. 자동 설정은 @ConditionalOnMissingBean으로 대체를 허용한다.

  2. 역할: @Component는 일반 클래스, @Service 서비스, @Repository 저장소(예외 변환 포함), @Controller MVC 계층이다. JSON API에는 @RestController를 쓴다.

  3. 스캔: 메인 @SpringBootApplication 패키지와 하위만 기본 탐색한다. 형제 패키지는 공통 상위 패키지에 메인 클래스를 두거나 스캔 범위를 명시한다.

  4. 생성자 주입: 필수 의존성을 생성 시 전달해 final로 둘 수 있고 단위 테스트도 간단하다. 생성자가 하나면 @Autowired는 생략한다.

  5. 필드·setter 주입: 필드는 의존성이 숨고 final을 쓸 수 없어 기본 선택으로 삼지 않는다. setter는 선택적이거나 재설정할 의존성에 한정한다.

    방식 주입 시점 실무 판단
    생성자 객체 생성 시 필수 의존성의 기본 선택. 불변성·테스트 용이성
    필드 @Autowired 생성 후 필드 설정 짧아 보여도 의존성 은닉, 단위 테스트 불편. 기존 코드 유지보수 외에는 피함
    setter @Autowired 생성 후 setter 호출 선택적이거나 재설정 가능한 의존성일 때 제한적으로 사용

  6. 동일 타입 빈 선택: 기본 구현은 @Primary, 특정 주입 인자는 @Qualifier, 전부 필요하면 List<T> 또는 Map<String,T>로 받는다. @Primary는 단일 값 주입에만 우선한다.

    Lombok 생성자와 @Qualifier를 함께 쓰면 직접 생성자 매개변수에 지정하는 편이 명확하다.

  7. 설정: 한 값은 @Value("${app.name:catalog}"), 묶음·타입 변환·검증은 @ConfigurationProperties로 받는다. Boot에서 scan 또는 @EnableConfigurationProperties로 등록한다.

  8. 확인: getBeanDefinitionNames()나 /actuator/beans로 빈을 찾는다. @SpringBootTest + @MockitoBean은 컨텍스트 테스트, 직접 new는 단위 테스트에 쓴다.

    확인 방법: 서비스가 GreetingRepository와 Clock을 받으면 등록 성공이다.

  4. 생성자 주입으로 서비스와 API 작성 — src/main/java/com/example/catalog/greeting/GreetingService.java

    package com.example.catalog.greeting;

import java.time.Clock;
import java.time.Instant;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;
import com.example.catalog.GreetingProperties;

@Service
@RequiredArgsConstructor
public class GreetingService {
    private final GreetingRepository repository;
    private final GreetingProperties properties;
    private final Clock applicationClock;

    public String greet() {
        return properties.prefix() + " " + repository.findMessage();
    }

    public Instant currentTime() {
        return applicationClock.instant();
    }
}

    Lombok이 단일 생성자를 만든다. src/main/java/com/example/catalog/greeting/GreetingController.java

    package com.example.catalog.greeting;

import java.time.Instant;
import java.util.Map;
import lombok.RequiredArgsConstructor;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api")
@RequiredArgsConstructor
public class GreetingController {
    private final GreetingService greetingService;

    @GetMapping("/greeting")
    public Map<String, String> greeting() {
        return Map.of("message", greetingService.greet());
    }

    @GetMapping("/time")
    public Instant time() {
        return greetingService.currentTime();
    }
}

    확인 방법: curl -i http://localhost:8080/api/greeting은 200과 {"message":"안녕하세요, Spring"}을 반환해야 한다(미실행, 예상값).

  5. Lombok이 만드는 코드 확인 — 실제 Lombok 1.18.46 delombok 출력이다. @RequiredArgsConstructor는 미초기화 final 필드를 인자로 만들고 일반 가변 필드는 제외한다.

    // delombok 출력의 생성 부분
public class GreetingService {
    private final Supplier<String> greetingRepository;
    private final Clock clock;
    private String mutableNote;

    @java.lang.SuppressWarnings("all")
    @lombok.Generated
    public GreetingService(final Supplier<String> greetingRepository, final Clock clock) {
        this.greetingRepository = greetingRepository;
        this.clock = clock;
    }
}

    프로젝트에서도 타입만 달라진다. 미초기화 @NonNull 필드에는 null 검사도 생성되며 단순 final에는 검사하지 않는다.

    확인 방법: ./gradlew clean compileJava 성공 여부를 본다. IDE만 실패 표시하면 Lombok processor 설정을 확인한다.

    package com.example.catalog.greeting;

import static org.assertj.core.api.Assertions.assertThat;

import java.time.Clock;
import java.time.Instant;

055. 자주 나는 에러와 해결열기 ↓

  1. No qualifying bean of type '...Repository' available / NoSuchBeanDefinitionException → 빈 미등록 또는 기본 스캔 범위 밖이다. → 구현에 등록 애노테이션을 붙이고 메인 패키지 아래인지, 조건·프로파일이 제외하지 않았는지 확인한다.

  2. NoUniqueBeanDefinitionException: expected single matching bean but found 2 → 같은 타입 구현이 둘 이상인데 단일 생성자 매개변수로 주입한다. → 기본 구현에 @Primary, 특정 인자에 @Qualifier("stripeGateway")를 지정한다. 여러 구현이 필요하면 List<T>·Map<String,T>를 받는다.

  3. UnsatisfiedDependencyException → 빈 생성 실패를 감싼 예외다. → Caused by의 첫 원인(누락·중복, 바인딩, 생성자 예외)을 해결한다.

  4. BeanCurrentlyInCreationException 또는 순환 참조 오류 → 생성자 A와 B가 서로 요구한다. → 책임을 나눠 의존 방향을 단방향으로 바꾼다.

  5. Lombok 생성자 누락 또는 variable ... might not have been initialized → Lombok processor가 실행되지 않았다. → Gradle compileOnly·annotationProcessor와 IDE annotation processing을 확인한다. 빈 미등록 오류라면 스캔 범위도 본다.

066. 한 단계 더열기 ↓

컨테이너는 등록 정의와 타입·qualifier 규칙으로 의존성을 연결한다. 생성자 주입은 필수값을 생성 시 확정하고 단일 생성자는 자동 선택된다. Lombok 생성자도 컴파일 뒤 일반 Java 코드다. 통합 검증은 @SpringBootTest, 로직 검증은 직접 생성하는 단위 테스트를 쓴다. 컨테이너 내부·생명주기 → S01, 프록시 → S02, 생성자·Builder → P04, 애노테이션 → P03.

077. 자가점검 Q&A (면접 대비)열기 ↓

  1. Bean과 new 객체는 어떻게 다른가? Bean은 컨테이너가 연결·관리하고, 직접 만든 객체는 호출 코드가 소유한다. 모두 Bean일 필요는 없다.
    꼬리질문: 구현체를 직접 new 하면? → 테스트 대역으로 바꾸기 어렵다.

  2. 생성자 주입이 기본인 이유는? 필수 의존성을 생성 때 확정해 final로 둔다. 직접 테스트하기 쉽고 의존성이 드러난다.
    꼬리질문: 선택 의존성은? → setter나 ObjectProvider<T>로 표현한다.

  3. 단일 생성자에 @Autowired가 필요한가? 아니다. Spring이 유일한 생성자를 쓴다. 여러 개면 선택을 명시한다. Lombok 생성자도 일반 생성자다.
    꼬리질문: @RequiredArgsConstructor에도 붙이나? → 보통 붙이지 않는다.

  4. 동일 타입 두 빈은 어떻게 선택하나? 기본은 @Primary, 특정 지점은 매개변수 @Qualifier다. 모두 필요하면 List<T> 또는 Map<String,T>로 받는다.
    꼬리질문: 컬렉션에서 @Primary는 하나만 남기나? → 아니다. 후보 전체를 받는다.

  5. 빈을 못 찾을 때 어디부터 보나? 등록 애노테이션·기본 스캔 범위·@Profile과 조건을 본다. getBeanDefinitionNames()나 /actuator/beans로 확인한다.
    꼬리질문: @Bean의 기본 이름은? → 메서드명이다.

  6. @Value와 @ConfigurationProperties는 언제 쓰나? 단일 값은 @Value, 여러 설정의 바인딩·검증은 @ConfigurationProperties가 적합하다.
    꼬리질문: 프로퍼티 record 등록은? → @ConfigurationPropertiesScan 또는 @EnableConfigurationProperties를 쓴다.
