#J23. 트리 자료구조와 순회 — 이진 트리·BST

트리는 부모·자식 관계로 자료를 계층화하며, 이진 트리는 자식 수만 최대 2개로 제한한다. BST는 왼쪽에 작은 키, 오른쪽에 큰 키를 두는 불변식으로 탐색 경로를 줄이지만 균형을 보장하지 않는다. 순회는 방문 순서의 차이다. 균형이 나쁘면 순회는 여전히 O(n)이지만 탐색·삽입은 O(n), 재귀 깊이도 O(n)이 된다.

#1. 왜 알아야 하나

BST에 정렬 입력 1, 2, 3, 4, 5를 넣으면 오른쪽 사슬이 된다. “트리 탐색은 O(log n)”이라 단정하면 오답이며, 재귀는 큰 입력에서 StackOverflowError가 날 수 있다. 이진 트리는 균형 트리가 아니다.

BST를 부모와 자식만 비교해 검증하는 것도 흔한 버그다. 루트 10, 왼쪽 자식 5, 그 오른쪽 자식 12는 부모보다 크지만 루트보다도 커 왼쪽 서브트리 규칙을 위반한다.

순회 순서를 착각하면 직렬화·트리 비교·계층형 응답 문제에서 틀린다. 전위·중위·후위는 노드 처리 위치가 다르고, 레벨 순회는 큐로 너비를 우선한다.

#2. 핵심 개념

용어 의미
노드(node) 값 또는 키와 자식 참조를 담는 단위. 아래 구현은 정수 키와 left, right 참조를 둔다.
루트(root) 부모가 없는 트리의 시작 노드. 빈 트리에는 루트가 없다.
간선(edge) 부모 노드와 자식 노드를 잇는 관계. 노드 n개인 비어 있지 않은 트리는 간선이 n−1개다.
부모·자식 직접 연결된 위·아래 노드. 한 노드는 루트를 제외하면 부모가 하나다.
잎(leaf) 자식이 하나도 없는 노드. 내부 노드는 자식이 하나 이상이다.
부분 트리(subtree) 임의 노드를 루트로 보고 그 아래 자손까지 포함한 트리. BST 규칙은 부분 트리 전체에 걸쳐 성립해야 한다.
깊이(depth) 루트에서 해당 노드까지 내려온 간선 수. 루트의 깊이는 0이다.
높이(height) 노드에서 가장 먼 잎까지의 간선 수. 여기서는 트리 높이를 루트 기준으로 정의하며 빈 트리 −1, 잎 하나짜리 트리 0으로 둔다. 노드 수 기준 높이는 각각 0, 1이므로 문제에서 정의를 확인한다.

트리, 이진 트리, BST는 다른 조건이다. 이진 트리는 자식이 최대 2개이고, BST(Binary Search Tree)는 키 순서 불변식까지 갖는다. 왼쪽·오른쪽은 키 비교를 뜻한다.

종류 각 노드의 자식 조건 키 순서 조건
일반 트리 0개 이상, 보통 구현·도메인에 따라 제한 없음
이진 트리 최대 2개 없음
BST 최대 2개 왼쪽 부분 트리의 모든 키 < 현재 키 < 오른쪽 부분 트리의 모든 키(엄격한 정책 예)

완전 이진 트리는 모양, BST는 키 순서 조건이며 서로 보장하지 않는다. 예제는 중복 키를 무시한다. 빈도 수 저장이나 한쪽 삽입도 가능하지만 검증 경계까지 같은 정책으로 맞춰야 한다.

#3. 내부 동작·원리

#BST 탐색과 삽입

탐색은 현재 키와 비교해 같으면 성공, 작으면 왼쪽, 크면 오른쪽으로 간다. null에 도착하면 실패다. 불변식으로 한쪽 부분 트리는 버리지만, 배열 이진 탐색과 달리 후보가 항상 절반으로 줄지는 않는다.

삽입도 같은 경로를 밟는다. 중복이면 거부하고, null 링크에 새 잎을 연결한다. 기존 노드 순서를 유지하지만 자가 균형 단계가 없어 입력 순서가 모양을 결정한다.

            8
          /   \
         3     10
        / \      \
       1   6      14
          / \    /
         4   7  13

7은 8 → 3 → 6 → 7, 9는 8 → 10 → null로 비교한다. 중위 순회가 오름차순인 것은 BST의 성질이다.

연산 BST에서의 비용 참고
탐색·삽입 O(h) h는 트리 높이. 균형이 좋을 때 O(log n), 편향되면 O(n).
전위·중위·후위·레벨 순회 O(n) 모든 노드를 한 번 방문한다.
재귀 순회의 호출 스택 O(h) 편향 트리에서는 O(n). 결과 목록을 따로 만들면 그 목록 공간은 O(n) 추가다.
레벨 순회 큐 O(w) w는 한 레벨의 최대 노드 수. 최악에는 O(n).

정렬되지 않은 배열은 탐색 O(n), 끝 추가 O(1)(동적 배열은 분할상환), 정렬 배열은 탐색 O(log n)이지만 중간 삽입 이동이 O(n)이다. BST 삽입은 O(h)여도 일반 BST는 O(log n)을 보장하지 않는다. 최악 시간 보장이 필요한 정렬 맵은 주요 연산이 O(log n)인 TreeMap을 쓴다. 내부 균형 연산은 J07 참조.

#순회는 방문 위치를 정한다

깊이 우선 순회(DFS)는 현재 노드에서 한쪽 자식의 더 깊은 노드를 먼저 처리한다. 노드 처리 시점으로 세 가지가 갈린다.

순회 처리 순서 흔한 용도
전위(preorder) 현재 → 왼쪽 → 오른쪽 루트부터 기록하는 직렬화·복사
중위(inorder) 왼쪽 → 현재 → 오른쪽 BST 키를 오름차순으로 출력
후위(postorder) 왼쪽 → 오른쪽 → 현재 자식을 먼저 계산한 뒤 삭제·집계

재귀는 node == null에서 멈추며, 노드 처리 줄의 위치가 순서를 정한다. 명시적 스택은 나중에 돌아올 노드를 직접 보관해 JVM 호출 깊이에 덜 의존한다. 둘 다 DFS 보조 공간은 O(h)다.

레벨 순회(BFS)는 FIFO 큐로 낮은 깊이부터 처리한다. 노드를 꺼내 왼쪽·오른쪽 자식을 뒤에 넣는다. ArrayDeque는 양끝 연산이 분할상환 상수 시간이고 null은 금지하므로 존재하는 자식만 추가한다.

DFS 재귀: node 호출 → 왼쪽 호출 → (복귀) 현재 처리 → 오른쪽 호출 → 복귀
DFS 스택: 스택에서 pop → 현재 처리 → 오른쪽 push → 왼쪽 push
BFS 큐:   큐에서 poll → 현재 처리 → 왼쪽 offer → 오른쪽 offer

#4. 코드로 확인

#예제 1: 삽입·탐색·세 DFS·스택 DFS·레벨 순회

JDK 21 단일 파일 실행으로 검증했다. 중복은 거부하고 높이는 간선 기준이다. 반환 결과 목록은 O(n) 공간을 추가로 쓴다.

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.List;

public class TreeTraversalDemo {
    static final class Node {
        final int key;
        Node left;
        Node right;

        Node(int key) {
            this.key = key;
        }
    }

    static final class Bst {
        private Node root;

        boolean insert(int key) {
            if (root == null) {
                root = new Node(key);
                return true;
            }
            Node current = root;
            while (true) {
                if (key == current.key) return false;
                if (key < current.key) {
                    if (current.left == null) {
                        current.left = new Node(key);
                        return true;
                    }
                    current = current.left;
                } else {
                    if (current.right == null) {
                        current.right = new Node(key);
                        return true;
                    }
                    current = current.right;
                }
            }
        }

        boolean contains(int key) {
            Node current = root;
            while (current != null) {
                if (key == current.key) return true;
                current = key < current.key ? current.left : current.right;
            }
            return false;
        }

        List<Integer> preorder() {
            List<Integer> out = new ArrayList<>();
            preorder(root, out);
            return out;
        }

        private void preorder(Node node, List<Integer> out) {
            if (node == null) return;
            out.add(node.key);
            preorder(node.left, out);
            preorder(node.right, out);
        }

        List<Integer> inorder() {
            List<Integer> out = new ArrayList<>();
            inorder(root, out);
            return out;
        }

        private void inorder(Node node, List<Integer> out) {
            if (node == null) return;
            inorder(node.left, out);
            out.add(node.key);
            inorder(node.right, out);
        }

        List<Integer> postorder() {
            List<Integer> out = new ArrayList<>();
            postorder(root, out);
            return out;
        }

        private void postorder(Node node, List<Integer> out) {
            if (node == null) return;
            postorder(node.left, out);
            postorder(node.right, out);
            out.add(node.key);
        }

        List<Integer> preorderIterative() {
            List<Integer> out = new ArrayList<>();
            if (root == null) return out;
            Deque<Node> stack = new ArrayDeque<>();
            stack.push(root);
            while (!stack.isEmpty()) {
                Node node = stack.pop();
                out.add(node.key);
                if (node.right != null) stack.push(node.right);
                if (node.left != null) stack.push(node.left);
            }
            return out;
        }

        List<Integer> levelOrder() {
            List<Integer> out = new ArrayList<>();
            if (root == null) return out;
            Deque<Node> queue = new ArrayDeque<>();
            queue.addLast(root);
            while (!queue.isEmpty()) {
                Node node = queue.removeFirst();
                out.add(node.key);
                if (node.left != null) queue.addLast(node.left);
                if (node.right != null) queue.addLast(node.right);
            }
            return out;
        }

        int heightEdges() {
            return heightEdges(root);
        }

        private int heightEdges(Node node) {
            if (node == null) return -1;
            return 1 + Math.max(heightEdges(node.left), heightEdges(node.right));
        }
    }

    public static void main(String[] args) {
        Bst tree = new Bst();
        for (int key : new int[]{8, 3, 10, 1, 6, 14, 4, 7, 13}) tree.insert(key);
        boolean duplicateInserted = tree.insert(6);

        System.out.println("preorder=" + tree.preorder());
        System.out.println("inorder=" + tree.inorder());
        System.out.println("postorder=" + tree.postorder());
        System.out.println("preorder(stack)=" + tree.preorderIterative());
        System.out.println("levelOrder=" + tree.levelOrder());
        System.out.println("contains(7)=" + tree.contains(7) + ", contains(9)=" + tree.contains(9));
        System.out.println("height(edges)=" + tree.heightEdges() + ", duplicateInserted=" + duplicateInserted);

        Bst empty = new Bst();
        Bst singleton = new Bst();
        singleton.insert(42);
        System.out.println("empty=" + empty.inorder() + ", height=" + empty.heightEdges());
        System.out.println("singleton=" + singleton.levelOrder() + ", height=" + singleton.heightEdges());

        Bst skewed = new Bst();
        for (int key : new int[]{1, 2, 3, 4, 5}) skewed.insert(key);
        System.out.println("skewedLevelOrder=" + skewed.levelOrder() + ", height=" + skewed.heightEdges());
    }
}

실행 명령: java _scratch/J23/TreeTraversalDemo.java

실제 출력:

preorder=[8, 3, 1, 6, 4, 7, 10, 14, 13]
inorder=[1, 3, 4, 6, 7, 8, 10, 13, 14]
postorder=[1, 4, 7, 6, 3, 13, 14, 10, 8]
preorder(stack)=[8, 3, 1, 6, 4, 7, 10, 14, 13]
levelOrder=[8, 3, 10, 1, 6, 14, 4, 7, 13]
contains(7)=true, contains(9)=false
height(edges)=3, duplicateInserted=false
empty=[], height=-1
singleton=[42], height=0
skewedLevelOrder=[1, 2, 3, 4, 5], height=4

전위 스택에 오른쪽을 먼저 넣어 LIFO에서 왼쪽이 먼저 나온다. 정렬된 중위 결과는 BST의 성질이다. 빈 트리 높이를 −1로 두면 잎 높이가 0이 된다.

#예제 2: 전역 범위 BST 검증과 BST의 LCA

검증은 각 노드에 전역 키 범위를 전달한다. LCA(Lowest Common Ancestor, 최저 공통 조상)는 두 키가 있는지 확인한 뒤 BST 순서로 내려간다. 일반 이진 트리의 LCA는 양쪽 자식 탐색 결과를 이용한다.

public class TreeQueriesDemo {
    static final class Node {
        final int key;
        Node left;
        Node right;

        Node(int key) {
            this.key = key;
        }
    }

    static boolean isValidBst(Node node, long lower, long upper) {
        if (node == null) return true;
        if (node.key <= lower || node.key >= upper) return false;
        return isValidBst(node.left, lower, node.key)
                && isValidBst(node.right, node.key, upper);
    }

    static boolean contains(Node root, int key) {
        Node current = root;
        while (current != null) {
            if (key == current.key) return true;
            current = key < current.key ? current.left : current.right;
        }
        return false;
    }

    static Node bstLca(Node root, int first, int second) {
        if (!contains(root, first) || !contains(root, second)) return null;
        Node current = root;
        while (current != null) {
            if (first < current.key && second < current.key) current = current.left;
            else if (first > current.key && second > current.key) current = current.right;
            else return current;
        }
        return null;
    }

    public static void main(String[] args) {
        Node root = new Node(8);
        root.left = new Node(3);
        root.right = new Node(10);
        root.left.left = new Node(1);
        root.left.right = new Node(6);
        root.left.right.left = new Node(4);
        root.left.right.right = new Node(7);
        root.right.right = new Node(14);
        root.right.right.left = new Node(13);

        Node invalid = new Node(10);
        invalid.left = new Node(5);
        invalid.left.right = new Node(12);

        Node lca = bstLca(root, 4, 7);
        System.out.println("validBST=" + isValidBst(root, Long.MIN_VALUE, Long.MAX_VALUE));
        System.out.println("invalidBST=" + isValidBst(invalid, Long.MIN_VALUE, Long.MAX_VALUE));
        System.out.println("LCA(4,7)=" + (lca == null ? "none" : lca.key));
        System.out.println("LCA(4,99)=" + bstLca(root, 4, 99));
    }
}

실행 명령: java _scratch/J23/TreeQueriesDemo.java

실제 출력:

validBST=true
invalidBST=false
LCA(4,7)=6
LCA(4,99)=null

입력이 존재한다고 보장되면 contains를 생략해 하향 탐색 O(h)로 풀 수 있다. 보장이 없다면 누락을 확인해야 한다.

#5. 버전별 변화 — 왜 바뀌었나

  • Java 21 — JEP 431, Sequenced Collections. 공통 타입에서 순서 있는 컬렉션의 첫·마지막 원소와 역순을 균일하게 표현하기 어려워 SequencedCollection, SequencedMap과 관련 API가 추가됐다. Java 25 API에서 ArrayDeque, TreeMap이 각 인터페이스 구현으로 표시된다. 컬렉션 API 변화이며 트리 알고리즘은 바꾸지 않는다. 근거: JEP 431, ArrayDeque Java SE 25, TreeMap Java SE 25.
  • 이진 트리·BST의 핵심 순회 알고리즘에서 이 자료 조사로 확인한 최근 Java 언어 차원의 큰 변화는 없다. 자료구조 알고리즘은 Java 문법 버전보다 문제의 트리 모양과 중복 정책에 좌우된다.

#6. 실무 가이드

  • 데이터가 부모·자식 계층이고 경로 단위 처리가 필요하면 트리 모델을 써라. 평탄 키 조회만 필요하면 해시 기반 조회를 고려한다.
  • 모든 노드를 부모부터 자식 순서로 출력하거나 직렬화하면 전위 순회를 써라. 자식 결과를 먼저 계산해 삭제·높이·크기를 합치면 후위 순회를 써라. BST 키를 오름차순 열거하면 중위 순회를 써라.
  • 최단 깊이 우선 탐색, 레벨별 출력, 너비 기준 처리가 필요하면 ArrayDeque를 큐로 사용해 레벨 순회를 하라. 최대 너비가 메모리 비용 O(w)라는 점도 함께 고려한다.
  • 입력 순서가 외부에서 통제되지 않거나 정렬된 키가 몰릴 수 있고, 탐색·삽입 시간 상한이 필요하면 직접 만든 일반 BST를 기본값으로 쓰지 말고 TreeMap을 기본값으로 선택하라. 공식 API는 주요 조회·삽입·삭제를 O(log n)으로 보장한다. 노드 참조와 특정 트리 모양을 직접 다루는 알고리즘 문제에서만 BST를 직접 구현한다.
  • 입력 높이가 제한돼 있으면 읽기 쉬운 재귀 DFS를 써라. 깊이 상한을 모르면 명시적 ArrayDeque 스택을 써라. 사슬에서 둘 다 O(n)이지만 명시적 스택은 JVM 호출 깊이를 쓰지 않는다.
  • 일반 이진 트리의 BST 여부를 검사하면 각 노드에 상한·하한을 전달하라. 부모와 자식만 비교하면 조상 규칙 위반을 놓친다.
  • 코딩테스트에서는 높이의 간선/노드 기준, LCA의 트리 종류, BST 검증의 전역 범위를 확인하라. J22 참조.

#7. 함정·안티패턴

  1. 증상: 잘못된 BST가 통과한다 → 원인: 부모-자식만 비교한다 → 대처: 전역 하한·상한을 전달한다.
  2. 증상: 같은 키를 넣은 뒤 검색 결과·검증 정책이 달라진다 → 원인: 중복을 한쪽에 넣는지, 거부하는지, 빈도로 셀지 정하지 않았다 → 대처: 삽입·검증·검색이 공유할 정책을 먼저 고정한다.
  3. 증상: 큐에 자식 null을 넣는 순간 예외가 난다 → 원인: ArrayDeque는 null 요소를 허용하지 않는다 → 대처: 존재하는 자식만 큐에 추가한다.
  4. 증상: 정렬 데이터에서 StackOverflowError가 난다 → 원인: 편향 트리의 재귀 깊이가 n이다 → 대처: 균형 보장 컬렉션 또는 반복·명시적 스택을 쓴다.
  5. 증상: 일반 이진 트리 중위 결과를 정렬로 본다 → 원인: BST의 성질을 일반화했다 → 대처: BST 불변식이 있을 때만 정렬로 해석한다.
  6. 증상: 높이 정답이 항상 1씩 어긋난다 → 원인: 문제의 높이 기준(간선 수/노드 수)과 빈 트리·잎 기준을 혼합했다 → 대처: 재귀 기저값과 문제 정의를 먼저 일치시킨다.
  7. 증상: equals로 다른 객체 키가 덮어써진다 → 원인: 비교자 또는 compareTo가 0이면 같은 정렬 키로 취급한다 → 대처: 비교 순서와 도메인 동등성·equals 계약을 맞춘다.

#8. 자가점검 Q&A (면접 대비)

Q1. 이진 트리의 탐색은 왜 항상 O(log n)이 아닌가?
자식 수 제한은 균형을 보장하지 않는다. 정렬 입력은 높이 n−1의 사슬이 되어 O(n)이다.
꼬리질문: 높이를 보장하려면? 답: 회전 등으로 균형을 유지하는 자료구조나 JDK TreeMap을 쓴다.

Q2. BST에서 중위 순회만 오름차순이 되는 이유는?
왼쪽 키 < 현재 키 < 오른쪽 키의 불변식에 따라 왼쪽·현재·오른쪽으로 방문하면 오름차순이다. 일반 이진 트리는 이 조건이 없다.
꼬리질문: 중복을 허용하면? 답: 중복을 한쪽에 두거나 개수를 저장하는 정책을 정하고 순서·검증 규칙을 함께 바꾼다.

Q3. 전위와 후위 중 어떤 순회가 자식 결과에 의존하는 계산에 맞나?
후위는 자식 결과가 필요한 높이·크기 계산에 맞고, 전위는 부모부터 기록하는 복사·직렬화에 편하다.
꼬리질문: BST 정렬 출력은? 답: 중위 순회다.

Q4. DFS 재귀를 명시적 스택으로 바꾸면 공간 복잡도가 줄어드나?
아니다. 둘 다 노드를 O(h) 보관한다. 명시적 스택은 JVM 메서드 호출 깊이를 소비하지 않는 차이가 있다.
꼬리질문: 레벨 순회는 무엇을 보관하나? 답: 아직 방문하지 않은 노드를 FIFO 큐에 두며 최악 O(w) 공간을 쓴다.

Q5. BST 검증에서 자식과 부모만 비교하면 왜 부족한가?
노드는 모든 조상 경계도 만족해야 한다. 전역 하한·상한을 재귀 전달하면 왼쪽 깊은 곳에 루트보다 큰 키도 검출된다.
꼬리질문: 정수 경계는 어떻게 표현하나? 답: long 범위처럼 키 범위를 감싸는 경계를 쓰거나, 값과 경계 존재 여부를 별도로 표현한다.

Q6. BST의 LCA 알고리즘이 일반 이진 트리에도 그대로 적용되나?
아니다. BST는 키 순서로 한쪽을 고르지만 일반 이진 트리는 양쪽을 탐색한다. 입력이 키인지 노드 참조인지도 정해야 한다.
꼬리질문: 입력 키가 없을 때 위 예제는? 답: 사전 포함 여부 검사로 null을 반환한다.

Q7. 정렬 배열과 BST 중 삽입이 더 빠른 쪽은?
정렬 배열 삽입은 원소 이동 O(n)이다. BST는 O(h)라 균형 시 유리하지만 편향되면 O(n)이다.
꼬리질문: 정적 데이터의 정렬 조회가 많다면? 답: 정렬 배열의 O(log n) 검색과 연속 저장 이점이 적합할 수 있다.

Q8. 높이 0인 트리는 어떤 경우이며 빈 트리는 어떻게 표현할 수 있나?
간선 기준 잎 높이는 0이며, 이 구현은 빈 부분 트리를 −1로 둔다. 노드 수 기준이면 잎 1, 빈 트리 0이므로 정의를 확인한다.
꼬리질문: 면접에서 먼저 확인할 점은? 답: 높이의 기준과 빈 트리 정의다.

다른 그래프 BFS/DFS·최단거리·Union-Find는 J22 참조. TreeMap 내부는 J07 참조. AVL·레드블랙 균형 연산 직접 구현은 다루지 않는다.
