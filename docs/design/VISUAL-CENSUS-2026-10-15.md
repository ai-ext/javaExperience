## 학습자의 “무엇을 하라는지 모르겠다” 피드백

`1-1`은 처음 읽을 때 한 API를 직접 만드는 단계인데, 실제 첫 요청 실행 버튼은 문서 시작에서 약 **6,099px 아래**에 있다(검사 뷰포트 높이 720px). 처음에는 요청 여정 4장면이 보이고, 그 뒤에 별도의 화면 미리보기·서버 흐름·API 경로·학습 절이 이어진다. 서로 비슷한 흐름 표현 세 종류가 경쟁해 “지금 할 일”이 늦게 나타난다. 사용자가 말한 “창 3개”는 고정 3열 레이아웃이라는 뜻으로 단정하지 않는다. 생성 HTML에서는 **서로 다른 세 가지 시각 모델이 한 페이지에 누적**된 것이 확인된다.

시나리오는 17장·101단계이며 난이도는 기초 26·중급 43·고급 32다. 단계당 `docs/knowledge` 링크는 평균 3.27개(총 330회, 고유 82개), 원문 `<details>`는 평균 8.6개다. 38단계는 원문 접기가 10개 이상이다. 이는 **새 개념 수의 측정값은 아니고** 화면 밀도의 지표다.

[101단계별 과제·밀도 표](scenario-learning-load.csv)에는 각 단계의 첫 API/과제, 기초·중급·고급, 원문 행 수, 지식 링크, 원문/생성 토글, 요청/채점 항목, 별도 확인 신호를 한 행씩 넣었다. 전체 구조화 요청은 1,383개, 구조화 확인은 664개다. 이 숫자에는 수동 SQL·DB 실습이 들어 있지 않으므로 전체 학습 과제 수로 쓰지 않는다. [집계](scenario-learning-load-summary.json)의 `flagged` 39개도 난도 판정이 아니라 후속 수동 검토 후보 수다.

과밀 유형은 네 가지다. (1) 하나의 단계에 여러 API가 들어감: 6-2·13-4·14-4. (2) 단일 성공 경로와 정책 예외를 한 번에 구현: 1-5·1-6·2-3. (3) 기능과 운영·테스트 기반을 묶음: 2-4·4-2·15-6. (4) 작은 API 과제 뒤에 실패 실험을 많이 붙임: 0-2의 `GET /api/start/ping`·404 관찰 뒤 여섯 종류의 고장 실험. `1-6`은 토큰 발급을 제외했지만 인증 상태·회원 상태·CORS까지 동시에 다뤄 학습 경계를 더 분명히 보여 줄 필요가 있다.

이 결과는 내용을 삭제하자는 뜻이 아니다. 첫 진입에는 **이번에 만들 API 한 개, 수정할 파일, 바로 해 볼 행동, 기대 결과**를 앞에 두고, 여러 API·예외·진단·깊은 개념은 이름이 분명한 다음 단계로 옮겨 찾아볼 수 있게 한다. 실습의 기술 범위와 채점 기준은 원문 그대로 보존한다.

## 화면을 나누는 기준

한 화면을 `페이지 → 장면/절 → 토글(닫힘·열림) → 내부 블록`으로 나눈다. 내부 블록은 `도입 산문`, `흐름/아키텍처`, `이미지`, `표/비교`, `코드/SQL`, `입력·실행 버튼`, `예상/실제 결과`, `힌트/오류`, `다음 단계`로 분류한다. 중첩 토글에는 부모 경로와 깊이를 기록한다. 시안이 여러 블록을 하나의 장면으로 합치면 각 원문 블록에서 그 장면으로 연결하는 참조를 남긴다.

조사 단위마다 원문 경로와 실제 HTML 위치, 시안 파일, 기술 문구 교정, 데스크톱·360px 화면 캡처, 상호작용 확인, 상태를 남긴다. 공통 CSS 한 곳의 수정은 그 CSS를 쓰는 모든 화면의 `verified`로 전파하지 않는다.

## 대비 문제: 먼저 고칠 곳

실제 1-1 `만들 것 → 클라이언트가 요청` 카드의 `/api/posts` 칩은 브라우저 계산값이 **글자 `#244d7a` / 배경 `#22262b` / 대비 1.75:1**이다. 밝은 카드 안에서도 공통 `code` 규칙의 어두운 배경이 남고, 별도 규칙이 글자색만 어둡게 바꿔 생겼다. 같은 페이지의 필드 칩 `boardSlug` 등도 2.13:1, 열린 DTO·채점·힌트 속 다른 칩도 약 1.8~2.6:1 사례가 확인됐다. `POST` 작은 주황 글자는 밝은 배경에서 약 3.6:1이다.

`first-request-visual.css`와 `p02-mvc-visual.css`에는 밝은 카드·짙은 글자·상태 색상이 고정된 규칙이 많다. 고정 색 선언의 개수 자체를 결함 수로 보지 않는다. 각 코드 칩·배지·본문의 **실제 계산된 글자/배경 조합**을 검증한다. 일반 텍스트는 최소 4.5:1, 큰 텍스트는 3:1을 목표로 하고, 그라디언트·이미지 위 텍스트는 데스크톱과 360px 캡처로 보완한다. 시스템 다크와 `data-theme="dark"`를 따로 확인한다.
