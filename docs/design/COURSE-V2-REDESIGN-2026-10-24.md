# 과정 v2 화면 재디자인 5개 영역 통합

확인일: 2026-10-24. 기준: `course/p1-spec-roadmap`, `421a6887`. A~E도 같은 기준 커밋임을 실제 Git에서 확인했다. 각 작업의 소스 diff를 통합한 뒤 생성물을 다시 만들었다. commit·push·merge·배포는 수행하지 않았다.

## 영역별 선택과 출처

아래 선택은 제공된 다섯 탐색 보고서의 기록을 대조한 것이다. 통합 단계에서 새로 탐색하거나 참고안을 재평가하지는 않았다. 외부 서비스 식별자는 제거하고 선택한 배치 원리를 남긴다. 점수는 학습 효과 실험 결과가 아니라 탐색 단계의 디자인 적합성 판단이다.

| 영역 | 적용한 1위 안 | 가져온 구성 원리 |
|---|---|---|
| A 일자 머리 | 학습 작업대: Java 레일 + 줄형 구현 체크리스트 | Java 진입과 구현 순서를 나란히 놓고 현재 순서·체크 진도·이어하기를 함께 표시 |
| B 순서 칸 | 번호 탭 작업 문서형 | 번호와 제목 분리, 파일 작업 행, 명세 다음 완료 조건, 도움 접기와 다음 순서 |
| C 데이터·SQL·채점 | 실습 노트형 | 기본·대량 데이터 분리, SQL 질문·확인 성질 공개, 말하기 질문과 답 기준 분리, 채점·다음 날 연결 |
| D 홈·지도 | 번호가 이어지는 학습 경로 | 오늘 할 일 옆 세 이정표, 단계별 45일 진도, 노드 목록 옆 선택 상세 |
| E 티켓·Java·전환 | 보고서형 작업 문서안 | 문서 종류·번호 경로·재현·제출물·일자 복귀, D10/D11 환경 전환과 D15 중간 점검 |

**디자인 참고 자료 이미지·폰트·아이콘·SVG 자산은 복사하지 않았다.** 선·표면·번호·문서 프레임은 CSS와 native 컨트롤로 재현하고, 관계 지도와 흐름은 저장소의 기존 SVG 렌더러를 유지했다. 디자인 참고 자료의 배치 관계를 참고했으며 원본 디자인 파일이나 자산을 삽입한 결과가 아니다. 새 imagegen 시안 제작이나 imagegen parity 완료로 표시하지 않는다.

## 제안 토큰 비교와 통일

다섯 보고서 모두 공통 색·글꼴 변경은 제안하지 않았다. A는 12px 모서리·24px 여백, B는 24px 여백·44px 번호·13px 라벨·48px 접기·12px 모서리, C는 48px 영역 간격·12px 라벨·20px 행 여백·44px 조작 높이를 제안했다. D는 280px 선택 상세·600px 목록·16px 경로 간격, E는 기존 토큰 유지와 지역 4~6px 문서 모서리를 사용했다.

색상 정본은 `tools/site/site.css`, 종류 색상 정본은 `tools/site/course.css`다. 추가 공통 치수·글꼴·모서리·그림자는 `tools/site/course-tokens.css`에서 관리한다. 과정 문서와 홈이 같은 파일을 로드하며, 기존 홈 도감·대화상자의 고정 라이트 색도 의미 토큰에 연결했다.

## 소스 병합과 판정

- 가져온 범위: `tools/`, `course/days/D10.json`, `D11.json`, `D15.json`, `course/map.md`. Java·티켓·출발 자료 Markdown은 입력 diff가 없어 보존했다. HTML·`course/spring/*`·합본 JSON·개별 작업의 시각 장부는 복사하지 않았다.
- `course.css`의 A/B 충돌: A의 작업대 스타일과 B의 새 순서 문서 스타일을 모두 보존하고, B가 교체한 옛 2열 사실 카드 규칙은 제거했다. C의 실습 후반부와 D의 홈·지도 규칙을 함께 병합했다.
- `course-pages.mjs`의 C/E 충돌: 복사 대상·페이지 이동을 만든 뒤 C의 실습 후반부를 구성하고, E의 인수인계·단계 전환을 적용한다. 한쪽 렌더러로 덮어쓰지 않았다.
- A/E 구조 충돌: A가 구현 목록을 `.day-overview`로 이동하면서 E의 D11 종료 경계 `.day-today`가 사라졌다. 인수인계 구획은 다음 제목·구분선·순서 칸·작업대·실습 패널에서 멈추도록 수정했다. 준비 체크 6개가 남고 구현 순서 4개가 별도 구획인지 회귀 검사한다.
- `course.js`: A의 체크·진행 막대·이어하기, C의 복사 실패 대체, D의 홈 작업 링크를 모두 보존했다. 준비·선택 티켓과 구현 진도는 기존 저장 모델에서 분리한다.
- `build.mjs`: E 전용 CSS와 공통 토큰을 함께 로드한다. Java·티켓·일자 목록도 종류 색을 공유한다. 캐시 해시는 최종 소스 기준으로 재생성했다.
- 홈 다크: 기존 라이트 고정과 하단 참고 도감·대화상자의 고정 색을 공통 테마에 연결했다. 파랑 이동 강조는 녹색으로, 종류별 Java 파랑·티켓 주황은 그대로 두었다. 일반 체크·준비 체크·radio의 accent도 통일했다.
- 일자 목록: 한 문장에 여러 `~`가 들어가 티켓 규칙 일부가 취소선이 되는 현상을 브라우저에서 발견했다. 생성기 `renderIndex`에서 범위 기호를 escape했다. 표시 내용은 유지하고, 일자 목록도 취소선 회귀 검사에 포함했다. 수정 전 실패를 실제 확인했다.
- 시각 장부는 통합 생성물에서 `inventory-visual-work.mjs`로 다시 만들었다. 새 항목은 미검토로 두고 기존 상태를 보존했다.

## 남은 문제와 검증 한계

- PC 1440만 확인했다. 모바일·다른 폭·다른 브라우저의 시각 QA와 학습자 이해도 실험은 하지 않았다.
- 실제 Spring·MySQL·Redis·PG 서버 실행과 백엔드 과제 채점은 이번 검증에 포함하지 않는다. 문서의 예상값과 clipboard 대조는 실제 DB 실험 성공을 뜻하지 않는다.
- D04-5 `GlobalExceptionHandler.java`, D07-1 `Member.java` 안내와 정답 커밋의 변경 범위 차이에 관한 기존 빌드 경고 2건은 남아 있다. 학습 요구사항이나 정답 커밋을 수정하지 않았다.
- D05의 `d05-seed-sql`에는 비어 있는 중복 `code` ID가 기준본에도 존재함을 DOM 대조로 확인했다. 이번 통합이 만든 중복은 아니다. 실제 복사는 첫 번째 원문 코드와 일치하며, 검증 스크립트는 `pre > code`를 대상으로 대조했다. 기존 HTML 파서의 빈 노드 정리는 후속 과제다.
- 빌드는 설치 시와 같은 Node 환경을 사용하는 `npm run build`로 실행했다. 별도 Node 경로에서 직접 `build.mjs`를 실행하면 esbuild의 x64/arm64 설치 차이 오류가 발생하는 환경 차이를 확인했다. 의존성 버전이나 시스템 설정을 임의로 바꾸지 않았다.
- 완료 기록은 수동 구현 체크다. Java·SQL·말하기·채점을 각각 자동 완료로 추적하는 새 모델은 추가하지 않았다. 기존 시각 장부의 `verified` 상태도 올리지 않았다.
