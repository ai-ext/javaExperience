# Task B 공통 진입·읽기 구조 검증

2026-10-24 착수, 2026-10-25 KST 최종 확인. PC 다크 범위다. 134개 개념 문서의 공통 읽기 구조를 적용했으며, 개별 문서 134개 전체의 교육 콘텐츠 개발 완료 판정은 아니다. Task C의 새로운 P09 9상태는 이 변경에 포함하지 않는다.

## 변경 결과

홈의 개념 진입에서 목록 검색을 거쳐 `설명 읽기`로 직접 들어가고, 기존 검색어·결과·초점을 유지해 돌아온다. 조작 가능한 문서는 장면/설명을 전환하며 기존 장면과 query를 유지한다. 일반 산문 문서는 바로 설명을 보여 준다. 설명은 220px 목차와 최대74ch 본문, 17px 본문 글씨로 배치한다. 핵심 장은 열어 두고 Q&A 907개의 답변은 각 질문에서 펼친다. 버전별 표 14개의 원본 summary도 실제로 펼칠 수 있다. 긴 표는 문서 전체를 넘치게 하지 않고 내부 가로 스크롤을 제공한다. 공통 UI에 새 모바일·라이트 분기를 만들지 않았다.

기존 Q&A가 문단 또는 순서 목록으로 작성된 191개 그룹은 보존 계약 안에서 개별 질문 details로 묶었다. 원문 제목이 toolbar 밖으로 이동하면서 기존 테스트 19개의 원문 H1 선택자만 승인 범위대로 바꿨다. 기존 원문 텍스트·코드·ID·Markdown 비교는 유지했다. Task A의 전체 main UI 문자열 해시는 새 toolbar 문구를 허용하는 명시 사양에 따라 원문 단위 보존 검사로 대체했다.

## 확인 근거

- Luna high 구현 뒤 별도 Sol high가 spec → quality 순서로 검토했다. 초기 실패와 수정 이력은 보존했고, 최종 polish·inventory·버전 본문 가독성 addendum까지 C/I/M 0건이다. `taskB-sol-review.json`과 `taskB-sol-logs/` 참조.
- 최신 24개 하네스 24/24 통과. 모든 결과의 실행 전후 코드 fingerprint가 현재 소스와 동일하다. `taskB-main-existing24-final-approved.log`와 각 task의 append-only run 참조.
- build, audit:visual, audit:version-cards 통과. 마지막 parity 감사는 734개, verified 0개다. 새 PC 전용 기록은 implemented로만 추가했다. `taskB-checks/` 참조.
- 메인 실제 Chrome에서 대표8문서와 1280/1440/1672px PC 화면을 확인했다. 홈→검색→설명→동일 결과 복귀, P09 장면→설명→같은 장면, 질문별 펼침, 원본 버전표 펼침, 키보드 표 가로 이동을 확인했다. 12개 추가 폭 사례에서 문서 overflow 0건. 실제 캡처 최종13개 JPG를 직접 확인했다. 기존 J03 캡처는 마지막 서체 변경 전 자료로 명시하고 새 최종 캡처를 추가했다.
- 대표8문서의 보이는 단색 텍스트 796개 표본에서 기준 미달0, 흰 UI0이었다. 이미지·그라데이션·opacity 합성의 픽셀 명암을 전수 검사했다는 뜻은 아니다.
- 134개 원문 root·코드·기존ID는 독립검수 및 공통 테스트에서 보존했다. 원문135파일·학습자 서버17파일, 기존 dirty2파일·역사proof1366파일·초기감사24JSON을 메인에서 SHA 재확인했다. `taskB-checks/preservation-final.json` 참조.
- inventory 47201항목. 새 공통 reader 수집1679행은 모두 unreviewed이고 기존 검증 상태를 임의로 올리지 않았다. P09 typed state는 아직 기존84다.

## 시각 자료와 한계

미리캔버스의 추가18검색·203신규후보·40신규grid·14참고 후보를 구조 설계에 활용했다. 참고 템플릿 이미지를 제품 자산으로 복사하지 않았다. 실제 imagegen으로 만든 PC 다크 reader 시안과 같은 1672×941 실제 P09 캡처를 장부에 연결했다. 시안은2.3 발췌이고 제품은2.1부터 원문 전체를 보존하므로 픽셀 동등을 주장하지 않는다. 개별 신규 수업 개발, Java/HTTP/DB 새 실행, 전체134 수동 화면 검증, 모바일·라이트 검증은 이 공통 UI 승인에 포함하지 않는다.

상세 수치는 `taskB-summary.json`, 브라우저 관측·캡처 manifest는 `taskB-browser/`에 있다. 과거 실패 화면과 로그를 최종 통과 자료로 덮어쓰지 않았다. push·PR·merge는 수행하지 않는다.
