## 실험 설계에 반영할 경계

- service `REQUIRED` 시나리오와 상위 경계가 없는 Repository A/B 시나리오를 분리한다. 같은 DataSource·manager·스레드에서 `JdbcTemplate`을 사용할 때의 단일 연결 참여와 독립 commit/rollback 결과를 비교한다.
- `RiskClient`는 제어 가능한 stub으로만 기록하고 외부 시스템 원자성 증거로 해석하지 않는다. sourceC의 제공된 `@TransactionalEventListener` 본문은 비어 있으므로 실제 알림 전송이라고 서술하지 않는다. 주변에 추가하는 observer가 기록한 것은 observer 호출 기록으로 한정한다.
- 제공된 sourceB/sourceC가 동명 `OrderUseCase` 대안 코드라는 사용자 설명을 기준으로, 이를 한 파일 묶음으로 컴파일하지 말고 독립 variant로 분리한다.
- 예정 환경은 H2/JDK 21/standalone Spring 7.0.9/BOM 4.1.1 및 schema(seed product 7, stock 5), 여러 JVM variant다. Controller는 실제 Spring proxy Java 호출이지만 HTTP/MVC/직렬화 실측은 아니다. RiskClient는 제어 stub이며 network/결제/broker/outbox/CDC/Java 25 실행이 아니다. 이들은 계획이며 실행 결과가 아니다.

이번 조사에서 코드 실행, 애플리케이션/H2 실행, 저장소 소스 수정 및 이미지 제작은 하지 않았다.
