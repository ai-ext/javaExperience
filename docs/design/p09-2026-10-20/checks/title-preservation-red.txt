Java는 숫자를 참·거짓으로 자동 변환하지 않으므로 if (count)는 컴파일되지 않고 if (count > 0)처럼 조건을 써야 한다. ==는 두 객체의 내용이 같은지 검사하지 않고 참조가 같은 객체를 가리키는지 검사한다. 문자열 내용 비교는 name.equals("Ada")처럼 equals를 사용한다. ==는 두 기본형 값이 같은지 비교할 때 알맞다. 정수 나눗셈은 소수 부분을 버린다. 따라서 7 / 3은 2이고, 나머지는 7 % 3으로 얻는다. 0으로 정수를 나누면 ArithmeticException이 난다. int 계산 결과가 표현 범위를 넘으면 예외 대신 값이 순환해 보이는 오버플로가 발생할 수 있다. 금액 계산에 double을 무심코 쓰면 이진 부동소수점의 근삿값이 드러날 수 있으므로, 실제 금액 모델에서는 보통 BigDecimal을 사용한다. 연산자 우선순위는 괄호가 없는 식을 어떤 묶음으로 해석할지 정한다. 자주 쓰는 순서는 높은 것부터 낮은 것으로 다음과 같다. 같은 묶음 안에서 결합 방향이 다를 수 있으므로, 복잡해지면 괄호를 써서 의도를 드러낸다. 우선순위 연산자 묶음 높음 후위 x++, x-- → 단항 ++x, --x, !, +, - 곱셈·나눗셈·나머지 *, /, % → 덧셈·뺄셈 +, - 관계 <, <=, >, >= → 동등 ==, != 비트 AND & → XOR ^ → OR ` 논리 AND && → 논리 OR ` 낮음 삼항 ?: → 대입 =, += 등 예를 들어 2 + 3 * 4는 곱셈을 먼저 해 14가 된다. 10 + 6 / 2 * 3은 곱셈·나눗셈이 덧셈보다 먼저이고, 같은 우선순위의 이항 산술 연산이 왼쪽부터 결합하므로 10 + ((6 / 2) * 3), 즉 19다. a || b && c는 a || (b && c)로 묶인다. 반면 수학 기호처럼 0 < age < 100이라고 연쇄 비교할 수 없다. 첫 비교의 결과가 boolean이기 때문에 age > 0 && age < 100으로 써야 한다. 우선순위에 익숙해져도 조건이 길면 괄호나 중간 boolean 변수를 써서 읽는 사람이 계산을 머릿속으로 추적하지 않게 한다. &&와 ||는 단락 평가(short-circuit)를 한다. &&의 왼쪽이 false면 전체 결과가 이미 false라 오른쪽을 실행하지 않는다. ||의 왼쪽이 true면 전체 결과가 이미 true라 오른쪽을 건너뛴다. 그래서 denominator != 0 && total / denominator > 3은 분모가 0일 때 나눗셈을 피한다. user != null && user.isActive()도 null 객체의 메서드 호출을 막는 전형적인 가드다. 다만 오른쪽 식을 건너뛸 수 있으므로, 그 안에 필수 대입이나 부수 효과를 넣으면 조건에 따라 동작이 달라진다. &와 |는 boolean 두 값을 받을 수 있지만 양쪽을 모두 평가한다. 정수에 쓰면 비트 연산이 되므로 논리 조건에는 보통 &&, ||를 쓴다. 다음 순수 Java 예제는 산술·비교·논리식과 우선순위, 단락 평가를 한 번에 보여 준다. public class OperatorsDemo { public static void main(String[] args) { int quantity = 3;
