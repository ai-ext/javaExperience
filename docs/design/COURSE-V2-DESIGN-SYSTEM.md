# 과정 v2 디자인 시스템

확인일: 2026-10-24.

## 결정과 범위

디자인 참고 템플릿의 표지, 목차, 단계, 체크리스트, 주의 박스를 과정 전체의 공통 언어로 사용한다. 넓은 왼쪽 레일, 위쪽 번호 태그, 본문 제목 아래 선, 같은 폭의 독립 패널, 패널 위 검정 말풍선 라벨, 청색 강조와 넉넉한 간격을 유지한다.

**다크 단일 테마, PC 가로 1440 기준**이다. 시스템 테마 감지, 테마 선택과 라이트 분기는 과정 화면에서 제거한다. 모바일용 신규 설계나 검증은 이번 범위에 포함하지 않는다.

디자인 참고 템플릿에서 확인한 값은 원본 캔버스 비율, 노드 좌표, 글자 크기와 청색 강조다. 글꼴명·굵기·정확한 모서리 반경은 구조 자료를 다시 조회해도 제공되지 않았다. 아래 글꼴·굵기·반경은 미리보기의 형태를 맞춘 웹 구현값이며 원본에서 추출한 값으로 표시하지 않는다. 사원증과 말풍선은 CSS로 형태를 구현했다.

청색 면은 디자인 참고 템플릿의 강조색을 유지한다. 어두운 면에 쓰는 청색 글자에는 더 밝은 별도 토큰을 적용해 대비를 확보한다. 코드 구문 색도 다크 전용 토큰이며 주석·문자열·타입을 포함해 본문 대비 4.5:1 이상을 목표로 한다.

본문 글꼴은 Apple SD Gothic Neo, Noto Sans KR, Segoe UI 순서의 시스템 sans-serif다. 코드는 SF Mono, Menlo, Consolas 순서다. 표지 48, 페이지 제목 32, 절 제목 24, 본문 16, 라벨 14, 보조 12, 코드 14를 기본 크기로 쓴다. 굵기는 400·600·700, 본문 줄 간격은 1.75다.

기본 간격은 4·8·12·16·20·24·32·40·48이다. 화면 최대 폭 1360, 좌측 레일 260, 레일과 본문 사이 48, 두 작업 패널 사이 24를 쓴다. 패널 반경 12, 일반 컨트롤 6, 번호 태그 3, 말풍선·주 행동은 캡슐 형태다. 일반 선 1, 강조 선 2이며 그림자는 사용하지 않는다. 기존 구성의 세부 치수도 공통 치수 토큰에 모아 화면별 CSS가 직접 색·글꼴·픽셀 치수를 선언하지 않도록 한다.

## 컴포넌트 매핑

| 디자인 참고 템플릿 유형 | 과정 컴포넌트 | 적용 방식 |
|---|---|---|
| 표지 | 홈 소개 | 굵은 첫 줄과 가는 둘째 줄, 오른쪽 기울어진 사원증, 하단 구분선 |
| 목차 | 과정 안내·일자 목록·출발 자료 | 왼쪽 번호 태그와 목차, 오른쪽 절별 패널·일자 흐름 |
| 단계 | Spring 일자 | 왼쪽 오늘 순서와 지금 순서 한 개, 상단 제목과 구분선 |
| 두 패널 | 만들 것·완료 조건 | 같은 폭, 같은 간격, 위쪽 말풍선 라벨 |
| 체크리스트 | 설명 세션·Java·티켓 제출물 | 독립 패널과 순번·확인 항목. 만들 파일이 없는 순서는 완료 조건을 전체 폭으로 표시 |
| 주의 박스 | 명세·힌트·관찰·원인·정답 | 제목을 구분하고 필요한 내용만 접어 열기 |
| 연결 흐름 | 과정 지도·과정 일정 | 캡슐 열 제목, 청색 선택, 연결선·일자별 흐름 |

탭은 같은 선·면·글자·컨트롤 높이를 쓴다. 선택 탭은 청색 글자와 선택 면으로 구분한다. 설정 형식 탭, 코드 블록, 접기는 내용이나 형식 이름에 종속되지 않는 일반 컴포넌트 규칙을 쓴다. 숨겨진 탭의 패널은 표시하지 않는다.

## 화면별 적용

- 홈: 표지, 오늘 할 일, Java → Spring → 채점 진입, 세 단계 안내, 전체 진도, 선택 티켓 기록과 기존 참고 도감.
- 과정 안내: 약속·진행 방법·준비물·완료 기준을 절별 패널로 배치하고 일정을 흐름으로 변환.
- 일자 목록: D00~D45를 순번과 일자·단계·마일스톤·Java·카드·상태를 묶은 흐름으로 배치.
- 과정 지도: Java·일자·티켓·결함 영역의 열과 선택 상세, 관계 필터·범례·연결 흐름 유지.
- D00~D45: 기본은 현재 순서 하나. 만들 것·완료 조건·층을 노출하고 명세·힌트·구현 예시·관찰은 접기. 준비 자료, 데이터 넣기, SQL·말하기·채점은 순서 안에서 이동.
- J00~J45: 목차 레일, 작업·연습·실행·완료 확인 패널, 일자 복귀와 이전·다음 연습 유지.
- B01~B16·E01·drill: 받은 요청, 환경·재현, 제출물과 훈련 순서 패널. 원인·정답은 닫힌 접기 안에 보존하고 그 안의 제목을 목차에 노출하지 않음.
- 출발 자료·서버 명세: 같은 목차·독립 패널·주의 박스. 준비 파일과 일정은 흐름으로, HTTP·설정·SQL 같은 정확한 비교가 필요한 기술 표는 유지.

## 보존과 검증

단계 이동은 해시와 브라우저 뒤로가기를 지원한다. 모두 펼쳐 보기와 한 순서씩 보기를 전환할 수 있다. 구현 진도, 별도 준비 확인, 선택 티켓 기록은 기존 저장 형식과 판정 기준을 유지한다. SQL·채점 복사, 파일 받기, Java·티켓 복귀 링크를 보존한다. 코드와 원문 앵커를 이동해 보존하며 텍스트 노드 사이의 공백도 유지한다.

PC 1440 다크에서 홈·과정 안내·지도·일자 목록, D00·D01·D05·D11·D15·D26·D45, J05·J16·J45, B01·E01·drill·출발 자료를 캡처하고 디자인 참고 템플릿 미리보기와 나란히 비교한다. 비교에서 찾은 일정 순번 겹침, 불필요한 빈 열, 작업 문서의 패널·라벨 차이를 교정한다. 색은 다크로 옮기며 웹의 탐색과 실제 학습 원문 길이에 따른 차이는 남는다. 원본 자산의 픽셀 복제를 주장하지 않는다.

브라우저에서 순서 넘기기, 뒤로가기, 체크 저장, 모두 보기, 선택 티켓 저장과 홈 동기화, SQL의 실제 clipboard 복사와 다운로드, 지도 선택, 원인 접기 상태를 확인한다. 본문 대비를 실제 계산된 글자·배경색으로 측정한다. 과정 원본·생성 화면·공통 탐색·홈 상호작용·시각화·버전 카드·시안 장부를 각 검사로 대조한다. 이 검증은 학습 UI에 관한 것이며 학습자의 서버 구현·DB 실행 결과를 대신 판정하지 않는다.
