# 과정 v2 디자인 시스템

확인일: 2026-10-25. 다크 단일 테마, PC 1440×900 전용이다.

## 정보 우선순위

현재 단계와 다음 단계, 만들 파일, 실행할 요청, 확인할 결과를 먼저 보여 준다. 전체 탐색·다른 선택 과제·긴 예시·원시 로그는 필요할 때 접근한다. 원인·정답은 기존 접기 안에 보존한다. 정적 확인 조건은 완료 체크와 다른 모양을 쓴다.

바탕은 `#141619`, 패널은 `#1d2025`, 레일은 `#282c33`, 상단은 `#07090c`다. 본문은 `#f3f4f6`, 보조 본문은 `#b6beca`, 구획 경계는 `#707b8b`, 조작 경계는 `#8591a2`다. 주 행동은 `#005eff` 위 `#ffffff`를 쓴다. 코드 면은 `#171a1f`다.

모든 의미색 글자는 해당 보조 면과 공통 표면에서 4.5:1 이상, 식별 가능한 경계는 인접 면에서 3:1 이상이어야 한다. 장식만으로 상태를 전달하지 않는다. 종류는 라벨·도형과 함께 표시한다. 실제 계산값과 조작 상태를 브라우저 대비 검사로 재확인한다.

| 상태·단계 | 색 | 추가 표식 |

Java·일자·티켓·결함 영역은 황토·청록·보라·살구로 구분한다. 콘텐츠 종류와 선택 상태를 같은 역할로 취급하지 않는다. 선택 노드는 별도 경계와 선택 문구를 쓴다.

## 글자와 치수

시스템 sans-serif와 기존 monospace를 유지한다. 페이지 제목 32px, 단계 제목 26px, 절 제목 20~24px, 본문 16px, 조작·표 라벨 14px를 쓴다. 본문 굵기는 400·600·700, 행간은 1.65~1.75다. 긴 산문만 76ch 안에 두고 코드·표·관계도는 작업 폭을 활용한다.

PC 공통 시작선은 80px다. 패널 반경 12px, 일반 조작 6px, 작은 태그 3px, 클릭 높이 44px를 기준으로 한다. 일반 경계 1px, 선택·집중 표시 2px, 의미 강조선 3px를 사용한다. 그림자와 반복 말풍선 장식은 추가하지 않는다. 반경·굵기처럼 원자료에서 확인할 수 없었던 값은 웹 구현값이다.

## 내용에 따른 배치

- 과정 안내: 진행 방식과 준비를 앞에, 일정은 단계별 비교 그리드로 배치한다.
- 일자 목록: 일자·목표·진도와 상세 필드를 비교 가능한 열로 모은다.
- 지도: 열 제목과 첫 노드 사이 간격을 확보하고 관계 목록을 다단으로 배치한다.
- 일자: 현재 단계 목록을 위에 둔다. 기본은 한 단계, 전체 보기는 비교 가능한 병렬 영역을 사용한다.
- Java: 만들 것·실행·완료를 앞에 둔다. 긴 표는 열 너비를 명시하고 식별자를 보존한다.
- SQL: 질문과 검증 조건을 구분한다. 코드 복사·파일 받기를 유지한다.
- 티켓: 받은 증상·재현·제출물을 우선한다. 원인과 정답을 목차나 새 요약에 복제하지 않는다.
- 출발 자료·더미 안내: 실행 순서·일자별 범위·선행 조건을 비교표와 타임라인으로 분리한다.

원문의 링크·앵커·코드·요청 계약·데이터 값은 유지한다. 예시와 실제 측정을 구분하며 학습자 서버·DB의 결과를 UI 검증으로 대신 판정하지 않는다.

## 보존과 검증

단계 이동·해시·브라우저 뒤로가기·전체 보기·완료 체크·진도·선택 티켓·복사·다운로드·설정 형식 탭을 검증한다. 일자 첫 화면 조작은 전역 메뉴를 포함해 12개 이하를 목표로 한다. 긴 대상 화면은 같은 상태의 스크롤 길이를 전후 비교해 30% 이상 축소를 목표로 한다.

부품마다 실제 DOM 계산값과 참고 요소의 크기·간격·모서리·선·색 관계·상태를 대조한다. 웹에 맞춰 바꾼 배치와 확인할 수 없었던 원본 수치는 차이로 남기며 픽셀 복제를 주장하지 않는다. 학습 UI 검증을 교육 효과나 학습자 서버의 완성 판정으로 확대하지 않는다.
