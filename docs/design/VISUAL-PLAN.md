## 현황과 완료 판단

`node tools/site/inventory-visual-work.mjs`가 원문과 생성 HTML이 함께 있는 **323개 화면**을 [화면별 체크리스트](VISUAL-PAGES.md)에 나열한다. 원문의 절·산문·표·코드·목록과 생성 HTML의 토글, 화면 JSON의 위젯·흐름을 [개별 항목 목록](visual-inventory.jsonl)에 기록한다. 첫 목록 생성 시 **42,631개 항목**이었고, 생성 화면이 바뀌면 수가 변한다. 이는 같은 콘텐츠의 원문 블록과 생성 UI를 모두 포함한 검사 단위 수이지, 서로 다른 개념 수가 아니다. [집계](visual-inventory-summary.json)에 현재 상태를 남긴다.

한 항목의 상태는 `unreviewed → mockup_ready → implemented → verified` 순서로만 올린다. 시안을 만들었어도 실제 화면에 반영하지 않았으면 `mockup_ready`에 둔다. 공통 컴포넌트가 적용돼도 개별 화면의 콘텐츠·모바일·상호작용을 확인하지 않았으면 해당 페이지 체크박스를 완료로 바꾸지 않는다. `--mark <id> <상태> <근거>`로 상태를 바꾸고, 목록 재생성은 기존 상태를 보존한다.

### 1. JPA 세로 사례: 실제 DB 값까지 따라가기

출처: `docs/knowledge/S09-jpa-hibernate.md`, `P20-jpa-entity-mapping.md`, `lessons/E3-what-is-jpa.md`, `E7-jpa-update-delete.md`. 구현 후보: `tools/site/knowledge-page-visual.mjs`, 별도 `tools/site/jpa-journey.{css,js}`. 전체 문장을 한 장에 밀어 넣지 않고 첫 장면을 누르면 상세 레인이 열리게 한다.

기술 동작은 [Jakarta Persistence 3.2 명세](https://jakarta.ee/specifications/persistence/3.2/jakarta-persistence-spec-3.2)와 [EntityManager API](https://jakarta.ee/specifications/persistence/3.2/apidocs/jakarta.persistence/jakarta/persistence/entitymanager)의 `find`·`flush` 설명에 대조한다. 별도 연결의 관찰은 실습 MySQL의 트랜잭션 격리와 조회 시작 시점을 함께 적는다.

- [x] 실제 `imagegen`으로 [JPA 데이터 여정 시안](jpa-entity-db-journey-v1.png)을 생성한다. 예제는 게시글 `id=42`, 제목 `첫 글 → 수정된 글`이다.
- [x] 시안의 오해 가능성 식별: commit/rollback은 순차 3·4단계가 아니라 **동일한 flush 뒤 갈림길**이다. 이미지 속 SQL/문구는 기술 근거가 아니다.
- [x] S09에 조회 전 DB 행, `find()` 이후 Entity 인스턴스와 스냅샷, setter 이후 메모리 값, flush 뒤 트랜잭션 내부 행을 단계 선택으로 구현한다. commit/rollback 뒤 결과는 같은 flush의 두 분기 카드로 둔다.
- [x] S09에서 `EntityManager`를 컨텍스트 조작 창구로, Hibernate를 SQL 생성·실행 구현체로 표시한다. Entity와 DB 행의 `id | title`을 별도 표로 비교한다.
- [ ] SELECT가 생략되는 같은 컨텍스트의 재조회, IDENTITY 식별자 때문에 INSERT가 앞당겨질 수 있는 예외, 트랜잭션 경계가 없는 경우는 기본 경로 아래 확장편으로 둔다.
- [x] S09의 별도 DBeaver 관찰 레인을 앱 요청 경로 밖에 두고, 새 autocommit SELECT 기준 commit 전·후 값과 rollback 결과를 표시한다. 열린 REPEATABLE READ 스냅샷의 예외도 명시한다.
- [ ] S09와 P20의 실제 문장·코드·근거 링크를 보존하고, `npm run build`와 개념 상태 검사 및 데스크톱·360px 브라우저로 확인한다.
- [x] S09의 원문 ASCII 흐름 항목을 시안 → 구현 → 검증으로 차례로 기록한다. 이는 S09 전체 문서 완료를 뜻하지 않는다.

## 2026-10-15 · 새 브랜치 첫 화면 이관

`docs/visual-learning-next`에서 이미 생성된 imagegen 시안 01·02·04를 세 개의 실제 첫 화면에 적용했다.
