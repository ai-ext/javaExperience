이 대화에서 만들었던 javaExperience v5~v7과 첨부한 javaExperience-all-in-one(1).html을 기준으로, 이제 홈을 제외한 화면을 실제 구현할 수 있는 수준으로 설계해 주세요. 설명만 제안하거나 가능하다고 답하지 말고, 원본 분석 → 실제 이미지 생성 → 상태별 상세 명세를 이번 응답에서 수행해 주세요.

[현재 상황]
- 상위 공간은 홈 / 서비스 만들기 / 실전 미션 / 개념 학습 4개로 합의했습니다. 홈은 별도 개발자가 로컬에서 구현 중이므로 이번에 홈을 다시 설계하지 마세요.
- 로컬에는 홈의 첫 방문/이어하기/완료, 시작점 선택, 환경 안내, 최종 게시판 예시, new 객체/참조 그림이 추가됐습니다. 이 변경을 원격 GitHub에서 확인했다고 주장하지 마세요. 공개 저장소 https://github.com/ai-ext/javaExperience 의 문서와 이 대화의 첨부가 원본 근거이며 최신 로컬과는 구분합니다.
- 개발은 학습자의 IDE, 학습 화면은 요구사항·설명·실제 요청·결과 대조를 담당합니다. 코드 자동 감지나 자동 채점 통과를 근거 없이 표시하지 않습니다.

[전체 작업 방식]
서비스 만들기, 실전 미션, 개념 학습의 상위 목록과 상세 화면을 하나씩 분석해야 합니다. 특히 개념 학습은 공통 템플릿만 붙여 완료했다고 하지 말고, 원문 문서/개념별로 고유한 질문·같은 예시 값·변화 단계·학습 시안·구현 동작을 목록으로 만들어 순차 진행해야 합니다. 원본에 접근할 수 없거나 읽지 못한 항목은 미확인으로 남기세요. 개념 문서, 시나리오, 미션의 본문·정답·출처·기존 앵커는 보존하고 복잡한 바깥 UI와 중복 분류를 줄여 주세요.

[이번 응답의 우선 범위: 개념 학습 탭]
먼저 나머지 공간 전체의 작업 순서와 개념별 분석 대기표를 정리하되, 이번에는 개념 학습의 탐색·검색·상세 연결부터 완성된 한 묶음으로 설계해 주세요. 이후 서비스 만들기, 실전 미션, 개념별 상세를 같은 방식으로 이어갑니다.
아래 6개 상태를 각각 별도의 크고 읽을 수 있는 이미지로 실제 생성해 주세요. 여러 화면을 한 장의 작은 보드에 우겨넣지 마세요.
K01: 개념 학습 첫 화면. 무엇을 하는 공간인지, 질문/기술명으로 찾기, 처음 보는 학습자의 시작점, 지금 과제와 관련된 개념이 무엇인지 분명하게.
K02: 아래로 스크롤한 화면. 분야별 탐색·학습 순서·기존 전체 문서로 들어가는 방법. 분류·카드·목차를 여러 겹 중복하지 않기.
K03: 실제 검색 결과 상태. 예를 들어 DTO/객체/트랜잭션을 검색했을 때 결과의 제목·배울 질문·관련 과제·선택 이유를 보여주기. 검색어만 바뀐 가짜 빈 카드 금지.
K04: 검색 결과 없음/필터 해제 상태. 다음 행동이 명확하고 입력한 검색어를 보존해야 합니다.
K05: 개념 상세의 첫 화면 및 학습 장면. 대표로 DTO와 Entity 또는 원본에서 근거를 확인한 개념 한 건을 선택해, 단순 표지가 아닌 큰 실제 값 비교·짧은 설명·코드의 현재 줄·관련 과제로 돌아가기를 보여주기.
K06: 모바일. 목록→검색→개념 상세의 핵심이 360~390px에서도 읽히고 조작되게 설계. 필요하면 모바일 상태를 추가 이미지로 분리하세요.

[각 이미지의 개발자 인계 명세]
각 시안에 화면 ID/상태/핵심 사용자 질문/영역별 목적/표시할 실제 원문 데이터/기본 노출과 접기 구분/클릭·키보드 동작/검색·선택·진도 저장 범위/뒤로가기와 스크롤·포커스 복원/좁은 화면 배치/완료를 판정할 검사 항목을 연결해 주세요. 시안의 버튼이 어디로 가고 무엇을 바꾸는지 빠짐없이 적고, 구현 우선순위를 함께 주세요. 실제 이미지와 문서가 서로 모순되지 않게 해 주세요.

[시각·기술 기준]
기존 밝은 흰색·아주 연한 회청색·절제된 파란 강조와 이어지는 정교한 실제 서비스 UI를 원합니다. 본문 약 16px, 넉넉한 여백, 한 화면의 주 행동 1개, 겹겹의 카드와 큰 닫힌 토글 최소화. 파일명보다 학습자의 질문과 바뀌는 값을 먼저 보여 주세요. 장식만 추가하거나 작은 상자와 화살표로 끝내지 마세요. UI 시안의 버튼/메뉴와 학습 본문용 이미지 자산은 구분하세요.
Java 객체/참조/DTO/Entity/SQL/DB는 같은 한 데이터로 비교하고, new와 DB 저장을 섞지 마세요. flush/commit/rollback과 별도 DB 연결에서의 관찰은 구분합니다. 0-1은 작은 Java API, 1-1은 200 success와 DB 미저장, 1-2부터 201 및 DB 행 확인입니다. 원본과 다른 임의 경로·필드·실측값을 발명하지 마세요.

이제 원본을 확인하고 위 개념 학습 묶음의 이미지를 실제 생성한 뒤, 바로 개발할 수 있는 상세 설계와 다음 개념별 진행 목록을 제시해 주세요.
