# 대주제 메뉴와 고정 화면 틀

2026-10-25 r27c 사용자 최종 결정. 서비스 만들기 기능·데이터를 디자인 브랜치에 흡수한다. 이번 1/2단계는 병합·내비게이션·회귀 검사이며, 서비스 화면 전체를 공통 부품으로 다시 입히는 일은 다음 단계다. 다크 단일 테마, PC 1440 × 900 기준이다. 360px 신규 구현·검증 조건은 사용자 결정으로 제외하고 기존 모바일 동작은 보존한다.

## 서비스 만들기 첫 화면

대표 진입 주소는 `scenario/README.html`이다. 기능 이름·사용자에게 생기는 결과·핵심 범위·선행 기능을 먼저 표시하고 일자·파일명은 뒤로 둔다. 같은 기능을 두 번 나열하지 않는다. 단계별 시안의 검색·난이도 필터·기능 펼치기와 API EXPLORER를 유지한다. 기능 목록·세부기획서·질문형 힌트·요청 도구·원본 대응표·프로젝트별 수동 진도는 통합 입력의 기능을 보존하고, 바깥 틀·내비게이션·색·부품·첫 렌더링은 디자인 브랜치 기준을 따른다. 요청 성공을 과정 체크나 자동 채점으로 연결하지 않는다.

서비스 사이드바는 기능 목록(`scenario/README.html`) / 단계별 시안(`scenario/README.html#visual-catalog`) / API EXPLORER(`scenario/README.html#journey-all-apis`) / 참고 구분 / 일자 목록(`course/spring/README.html`) / Java(`course/java/README.html`) / 티켓(`course/tickets/README.html`) / 출발 자료(`course/start/README.html`과 하위 `dummy/README.html`·`ops/README.html`) / 과정 안내(`course/README.html`) 순서다. 목록에 있던 큰 학습 경로·게시글 여정·오른쪽 요청 흐름 패널은 복원하지 않는다.

## 공통 화면 틀

모든 생성 문서가 site-frame.css의 공통 틀을 사용한다. 헤더 64px, 본문 바깥 여백 40px, 왼쪽 열 208px, 열 간격 32px, 본문 최대 1080px이다. 전역 메뉴는 고정 폭 브랜드 다음에 배치한다. 문서의 실제 시작은 x=280px, y=96px이며 스크롤바 공간도 고정한다. 홈·목록·상세·출발 자료·개념에 서로 다른 바깥 컨테이너를 두지 않는다.

기존 페이지 탐색과 일자 단계 탐색을 공통 왼쪽 열로 옮기며, 원문·기존 앵커·키보드 전환·진도·선택 티켓·복사·설정 탭은 유지한다.

## 첫 페인트

서버 생성 단계에서 사이드바와 기본 단계·탭을 렌더링한다. head에서 html.js·저장된 설정 형식과 해시 단계의 CSS 상태를 적용하고, 본문 초기 controller가 같은 상태를 인계받는다. html 배경을 다크로 고정한다. 시스템 글꼴을 사용하며 외부 폰트 교체를 추가하지 않는다.

## 홈

오늘 할 일(오늘 일자·Java → Spring → 채점·구현 순서·D00 안내), 과정 전체 설명(직접 만들기 → 티켓 → 설계·운영·독립 수행과 매일 흐름), 대주제 안내 네 곳만 둔다. 서비스 만들기에 편입된 일자·Java·티켓·출발 자료와 독립 과정 지도는 짧은 용도와 링크로 안내한다. 전체 진도·미리보기·개념 예제를 홈에서 복제하지 않는다.

측정 원자료와 캡처는 검사 실행 시 출력되는 저장소 밖 임시 결과 폴더에 저장한다. `--out`으로 보관 위치를 지정할 수 있다.

`check:frame`·`check:reload`와 공통 Playwright 실행기는 저장소 루트를 빈 포트에 직접 제공하고 검사 종료 시 자체 서버만 닫는다. `--base-url` 또는 `SITE_BASE_URL`로 외부 서버를 지정할 수도 있다. Playwright는 `PLAYWRIGHT_MODULE`을 우선하고, 없으면 node_modules의 `playwright`를 찾는다. 둘 다 사용할 수 없으면 설치·지정 방법을 출력하고 종료 코드 2를 반환한다. Git 스테이징·커밋·stash·reset과 패키지 설치는 하지 않는다. check:generated의 HEAD 대조 실패는 미커밋 변경이 있는 이번 작업에서 재빌드 일치 여부와 구분한다.

## 과거 검증 기록의 경로 정규화

main에서 유입된 과거 검증 기록 1,692개 텍스트 파일의 개인 홈 경로와 임시 폴더 접두사를 각각 `LOCAL_HOME/`, `LOCAL_TMP/` placeholder로 정규화했다. 원본 전체는 r27 외부 보관소의 tar와 SHA-256 manifest로 보존했다. 이 처리는 경로 표기만 바꾼 것으로, 과거 실행을 재현하거나 기존 관찰값·검증 판정을 새로 확인한 것이 아니다. 기록 속 기존 해시는 당시 원본 바이트의 증거로 유지하며, 현재 파일 무결성을 검사하는 D08 runner와 JPG provenance의 현재 무결성 지문은 정규화된 바이트에 맞췄다. placeholder가 들어간 과거 스크립트를 재실행할 때는 해당 환경의 실제 경로를 지정해야 한다. 생성 HTML은 원본에서 다시 빌드한다.

P13의 충돌 구분선 교육 예시 2개는 fenced code를 들여쓰기 code block으로 표현했다. 표시되는 예시·전체 코드 문자열·본문 텍스트는 `marked` 렌더 전후 동일하며, 실제 병합 잔재와 소스 형태를 구분하기 위한 변경이다. 과거 baseline 원문은 유지하고 현재 승인 기준의 P13 원본 지문과 해당 파일의 해시 연결만 갱신했다.

## r27c 검증 범위

이번 흡수 후 결과는 별도 최종 보고에 명령별로 기록한다. 위 표의 수치는 이전 디자인 검증의 역사 기록이며 이번 서비스 94기능 화면까지 검증했다는 뜻이 아니다. 이번에는 공통 틀의 좌표 차이 0px·떠다니는 바 0·새로고침·다크 대비와 지정 기능 회귀를 확인한다. 개별 서비스 화면의 여백·자체 스킨·한 열 늘어짐과 실제 API 도구 조작·기획 품질 검토는 다음 단계에서 확인한다. 새 시각 장부 항목은 근거 없이 verified로 올리지 않는다.

r27c로 유입된 개인 경로가 있는 문서·증거 원본은 저장소 밖 보관소에 tar와 SHA-256 manifest로 보존한 뒤 경로만 정규화했다. 저장소 안 자료는 상대 경로, 외부 보관 기록은 LOCAL_HOME/·LOCAL_TMP/ placeholder를 사용한다. 원래 해시는 당시 바이트의 역사 증거이며, 경로 정규화 자체는 당시 실행을 재검증한 것이 아니다.

## 개념 학습 흡수 (r27b)

개념 영역도 64px 헤더·208px 왼쪽 레일·본문 x=280px의 기존 틀을 유지한다. 레일은 개념 목록, 접을 수 있는 필수 기초 6단원과 분야별 개념, 레슨으로 구성한다. 단원에서는 6단원 묶음, 문서에서는 분야 묶음을 초기 HTML부터 펼친다. 문서의 절 목차와 단원의 선수 조건은 같은 레일에 둔다.

- 카탈로그: 분야 6개는 3열 파일 타일, 결과는 2열 파일 카드, 학습 순서는 3열 단원 카드다. 일자 연결은 일자 원본 JSON의 실제 개념 링크에서 추출한다. 검색·분류·필수/선택·깊이·정렬·history 복귀 계약을 유지한다.
- 필수 기초: 단계 탭 아래 코드/설명용 상태 비교를 2열 파일 패널로, 실제 관찰/출처를 별도 2열 패널로 놓는다. 설명 재생과 과거 최소 예제 실행 근거를 구별한다.
- 개념 리더: 원문에서 뽑은 요약 타일을 먼저 보여 주고, 절 선택·이전/다음 절·전체 원문으로 내용을 전환한다. 절 안의 주제는 2열 카드로 놓고 넓은 표·코드는 전체 폭을 사용한다. 원문 Markdown·텍스트·코드·앵커는 보존한다. 장면·리더 모드와 기존 다이어그램·복사 기능도 유지한다.
- 레슨: 기존 3열 목록을 유지하면서 중복 패널을 줄인다. 상세는 H2부터 다음 H2까지 H3·코드·표를 같은 절로 묶어 기본 절을 미리 렌더한다. 절 선택은 내용을 바꾸며 추가 바를 띄우지 않는다.
- 의미색은 Java/DB/요청/Spring/테스트/운영과 코드/비교/관찰/출처를 구분하며 기존 course 토큰을 사용한다. 개념 페이지는 전용 다크 팔레트를 로드하지 않는다. 이전 다크 파일은 홈의 기존 참조가 남아 있어 보존하며, 개념의 원문 호환 규칙만 공통 토큰에 연결한다.

기존 원문 전체의 사실 재검증이나 신규 시안 검증을 완료한 것으로 해석하지 않는다. 새 시각화 장부 항목은 미검토 상태를 유지한다. 서비스 만들기·과정 페이지와 그 사이드바의 구현은 이 변경에 포함하지 않는다.

직접 목록 패널 주소는 기본 fragment 스크롤과 분리해 첫 페인트의 선택을 인계한다. P09는 기존 controller로 기본 장면의 단계 버튼·관찰값·코드를 빌드 시 채워 지연 스크립트가 빈 슬롯을 확장하지 않게 한다.

D12 원문 도식은 절 선택으로 바뀌는 hidden도 관찰해 실제로 보인 뒤 렌더한다. 읽기 전환과 접기 상태의 기존 감시도 유지한다.
