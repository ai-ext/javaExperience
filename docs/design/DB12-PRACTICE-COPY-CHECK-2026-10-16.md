# DB-12 JOIN·EXISTS SQL 확인 기록

2026-10-16. `docker/mysql/init/02-practice.sql`을 **일회용 MySQL 8.4 컨테이너**에 복사해 실행했다. 기존 compose의 `practice` DB와 seed는 변경하지 않았다. 검증 뒤 일회용 컨테이너를 제거했다.

| 비교 | JOIN | EXISTS | 결과 |
|---|---:|---:|---|
| M3 회원 12의 공개·발행·미삭제 글 좋아요, `LIMIT 21` | 21행 | 21행 | 열 값과 순서가 일치 |
| M1 확장: dev 게시판의 spring 태그 공개 글 ID | 16행 | 16행 | ID와 순서가 일치 |

DB-12 원문의 네 SELECT 모두 `EXPLAIN FORMAT=TREE`를 성공적으로 실행했다. 대표 태그 EXISTS에는 `EXPLAIN ANALYZE`를 실행해 TREE 출력 5행을 얻었다. 이 명령은 SELECT를 실제로 실행한다. 테스트는 SQL 문법·두 쿼리 쌍의 결과 동일성 확인이며, 특정 문법이 더 빠르다는 근거로 쓰지 않는다.

M3 공개 조건의 첫 세 `(like_id, post_id, liked_at)` 행은 `565/145/2026-10-03 22:13:37`, `527/143/2026-10-02 09:43:56`, `521/140/2026-09-29 21:56:58`이었다. 이 값은 이 seed의 실행 결과이며 전체 R1 권한을 적용한 M3 API 응답은 아니다. 태그 비교의 첫 세 글 ID는 `138, 133, 118`이었다. 학습 화면에는 실행 전에 이 값을 정답처럼 채우지 않았다.

실제 Spring Boot M3/M1 HTTP 구현, 권한 R1 전체 분기, 동일 뷰포트 이미지·DOM 대조, 브라우저/모바일 조작은 이 검증으로 확인되지 않았다.
