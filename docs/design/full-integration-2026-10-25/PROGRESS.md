서비스 만들기의 기능 단위 목록·세부기획서·힌트·요청 도구·원본 대응·별도 수동 진도를 가져온다. 상단 메뉴는 **홈 · 과정 지도 · 서비스 만들기 · 실전 미션 · 개념 학습**이다. 45일 과정 대주제는 없애고 일자·Java·티켓·출발 자료·과정 안내를 서비스 만들기 안의 참고 영역으로 옮긴다. 기존 주소와 일자 진도 저장 키·값은 유지한다. 지도는 독립 메뉴다.

서비스 사이드바는 **기능 목록 / 단계별 시안 / API EXPLORER / 참고 구분 / 일자 목록(D00~D45, 기존 3열 타일) / Java / 티켓 / 출발 자료(더미 데이터·운영 실습 포함) / 과정 안내**다. 모든 하위 페이지에서 같은 위치·폭의 공통 부품을 쓴다. 첫 화면은 기능 이름·사용자 결과·핵심 범위·선행 기능을 우선하고 같은 기능을 중복 나열하지 않는다.

## 요구사항의 일곱 공통 조건은 어떻게 관리하는가

1. 기능 단위 구성 → 기능/variant/stage와 원본 대응을 편집 가능한 JSON으로 관리한다.
2. 쉬운 할 일·결과 우선 → 각 stage의 purpose/task/scenario가 첫 내용이다.
3. 세부기획 → brief의 시작 조건·정책·입력·성공/실패·사례·완료 조건을 작성한다.
4. 학습자 설계 여지 → 확정 업무 규칙과 선택할 내부 구현을 구분한다.
5. 순차 질문 힌트 → stage별 hints를 이전/다음으로 열며 별도 진도로 세지 않는다.
6. 실제 확인 → recipeIds 또는 executionChecks를 연결하고 예상과 실측을 분리한다.
7. 보존과 확인 기록 → source-map/coverage-review/검사 로그에 원본·현재 상태·미실행을 남긴다.

위 조건 전부를 만족시키는 것이 목표다. 필드 존재 검사나 authored 표시를 전체 수락 조건 통과로 해석하지 않는다. 최종 리뷰에서 모호한 요구·반복된 질문·부족한 사례가 발견되면 해당 기능을 다시 수정한다.

## 화면 흡수 단계 PC 화면 흡수와 실제 확인 (2026-10-25)

- 서비스 목록과 94개 상세는 공통 토큰·타일·단계 카드·기획서 2열·의미색·요청/응답 좌우 비교로 재생성했다. 목록/시안/API는 같은 카드 집합의 내용 전환이며 같은 기능을 중복 나열하지 않는다. 다른 프로젝트 단계와 삭제된 내부 좌우 열이 본문 폭을 차지하지 않는다.
- 순차 힌트·기존 URL·원본 계약과 일자 진도 키를 보존했다. 요청 도구의 준비 조건·DB 확인 SQL 누락과 입력 전/행동/결과 사례 누락을 복구했다. SQL은 안내이며 실행하지 않는다.
- 실제 브라우저에서 재현한 빈 본문 생성 계약의 ID 연결 결함을 수정했다. `201 + empty body + Location`은 JSON 필드를 요구하지 않고 선언된 Location에서 ID를 얻는다. 외부 Origin·잘못된 경로·입력 변경 뒤 응답의 ID 연결은 기존 보호 조건을 유지한다.
- 지정 사이트 검사 26개 묶음과 루트 course 162개가 통과했다. 빌드는 설치 변경 없이 arm64 Node로 실행했다. 빈 공간 회귀는 기존 check:frame에 연결해 대표 서비스 4쪽의 전체 빈 면적 40% 미만·연속 빈 높이 160px 이하·상세 본문 폭 90% 이상을 검사한다. 패널 면적 기반 DOM 측정이며 이해도나 문자 밀도의 자동 판정은 아니다.
- 저장소 밖 검증 증거의 `before/`, `after/`, `interaction.json`, `visual-metrics.json`, `verification.json`, `report.md`, `final.md`에 전후·명령별 결과와 한계를 기록했다. 저장소에는 캡처를 추가하지 않는다.
- **360px은 사용자 결정으로 제외**했다. 94개 기획서 전체의 사용자 관점 최종 품질, 선정 시안의 개별 동등성, 전체 학습자 API/DB와 D30 학습자 서버 자동 호환 검사는 미실행이다. 기존 parity를 verified로 올리지 않는다. 다음 통합 재검증 단계의 직관성 평가·사용자 판단도 남아 있다.

선정 JPG 4장을 직접 열어 현재 목록·상세·요청 도구·API 보기와 구성 차이를 확인했다. 원본은 1536×1024이고 이번 실제 캡처는 사용자 결정인 1440×900이므로 동일 캔버스 parity 완료로 표시하지 않는다. 현재 공통 틀에 맞춘 의도적 차이와 확인한 API 사실은 증거 묶음 화면 흡수 단계의 report.md에 기록했다.
