## API 도구와 프로젝트 경계

실제 fetch 요청을 명시적으로 보내며 서버·method·경로 변수·query·header·본문·파일·인증을 편집할 수 있다. 예상 결과와 실제 HTTP 상태·본문·headers·본문 수신까지의 시간을 구분한다. 전송 후 입력이 바뀌면 이전 snapshot 응답으로 표시한다. 원본 요청의 미해결 변수는 직접 입력해야 하며 미입력 값을 그대로 보내지 않는다. 토큰·쿠키·본문·실제 응답을 진도 저장소에 저장하지 않는다.

원본 요청 사례 1,472개를 보존했고, 명시된 정규 경로는 162개다. 요청 사례 수를 구현 완료 API 수로 부르지 않는다. JSONPath의 복잡한 원문 assertion은 보존하지만 지원하지 않는 부분을 자동 통과로 표시하지 않는다. 원문이 상태를 정하지 않은 준비 요청에는 임의 상태를 넣지 않았다.

`board`, `community`, `project-v1`, `practice`를 구분한다. 예를 들어 board 작성은 201 빈 본문·Location, community 작성은 201 JSON이다. 좋아요도 board 204와 community 200 JSON이 다르다. 세션 실습은 브라우저 credentials를 사용하고 Cookie 값을 수동 헤더로 만들지 않는다. DB SELECT는 사람이 별도 클라이언트에서 실행하는 확인이며 브라우저가 DB를 읽었다고 표시하지 않는다.

D23~D30은 학습자가 결정하는 예약 URI·필드가 원본에 고정돼 있지 않다. 가짜 `/api/reservations`를 만들지 않고 확정한 계약을 등록한다. D30은 목록/count 별도 측정, 예약 접수와 실제 지급 구분, 구/신 요청·자동 호환 테스트를 각각 안내한다. **미완성 학습자 예약 서버의 호환 테스트를 실행·통과했다고 표시하지 않았다.**
