2026-10-25 KST. D11의 질문 12개·상태 38개를 PC 다크 화면에 구현했다. 이 승인은 추가 학습 화면과 아래 증거의 범위이며, 원문 전체의 실습 실행이나 전체134개 고유 콘텐츠 개발 완료 판정은 아니다.

## 무엇을 배우는 화면인가

기본 진입은 현재 주체7이 자신의 주문1002를 조회하는 장면이다. 다른 사용자8의 주문1003을 ID만으로 조회한 결과와, 현재 소유자를 조건에 넣은 빈 결과를 비교한다. UUID 식별자에도 같은 권한 조건이 필요함을 같은 두 행으로 확인한다. 브라우저 CORS에서는 요청 전송, API 수신, JavaScript 응답 읽기를 따로 표시한다. SQL 값과 문법, DOM 텍스트와 태그 파싱, CSRF 자격 증명, 원문의 SecurityFilterChain 전제와 endpoint 존재, HSTS·비밀번호·키·의존성 운영 경계를 질문별로 나눴다.

상태를 바꾸면 시안의 현재 구간, 값과 bind, 코드·강조, 짧은 이유가 함께 바뀐다. 정확한 코드와 관측은 선택·복사 가능한 DOM이다. 추가 실행, 원문 분석, 설명 모델을 구분하며 단계 선택을 실제 요청 재실행처럼 표현하지 않는다. 긴 원자료와 출처는 details에서 확인한다. 원문은 전체 reader와 기존 앵커·Q&A7개로 보존한다.

PC 진입을 실제로 확인해 이미지 시작 위치를 약855px에서529px로 줄였다. 중복 단계 selector와 중첩 카드·장식을 제거했고, 코드14px·값17px를 유지했다. 좁은 세로 구간도 최대540px 높이로 확대해 잘리지 않게 했다. 새 모바일·라이트 분기는 만들지 않았다.

## 어떤 실행 증거인가

- 임시 SQLite의 합성 주문 두 행으로 객체 조건, UUID, 문자열 연결과 바인딩, 정렬 allow-list를 실행했다. 별도 addendum 두 비교를 포함해 원래 source와 raw를 수정하지 않고 독립 Sol이 새 DB에서 재실행했다. Python int 예시는 Java Authentication 실행과 구분한다.
- 메인이 실제 Chrome에서 두 임시 loopback 출처의 CORS4경우를 버튼으로 실행했다. OPTIONS/POST/JS읽기는 각각0/1/거부,1/0/거부,1/1/허용,0/1/거부였다. 성공한 추가 fixture만200/body를 관측했고, 실패 fetch의 status/body를 지어내지 않았다. 관측API와 원래 응답을 분리했고 API 이벤트5개를 실제 JSONL과 대조했다. 쿠키는 합성 이름 존재 boolean만 기록했다. 실제 창 캡처는1668×832이며 제품 시안의1672×941과 구분한다. 소유 process를 종료했고 두 포트 닫힘도 확인했다.
- 같은 Chrome에서 공격 코드 없는 `<b>주문1002</b>`를 textContent로 넣었을 때 B0, innerHTML로 파싱했을 때 B1을 실제 DOM에서 읽었다.
- 위 추가 fixture는 Spring Security/Java25/MySQL/JPA 실행이 아니다. 원문의 Boot4.1.1 설정, 실제 HSTS·password hash 성능·키 회전·CVE스캔은 실행하지 않은 모델·원문 분석으로 표시했다. 실제 환경변수·운영 키·기존 DB·학습자 서버는 조회·변경하지 않았다.
