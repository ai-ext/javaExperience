# I18 관계 업무 확장: 북마크 폴더 한도·이동·소유권

우선순위: **P1** / 판정: **실제 구현 있음 · 좋아요/댓글에서 규칙 확장 연습 부족**

검토일: 2026-10-21 KST. 읽기 전용 정적 감사이며 이 담당자는 원본 수정·빌드·테스트·DB 실행을 하지 않았다. 현재 작업 중인 worktree의 파일을 읽었으므로 아래 SHA256 manifest 시점의 판단이다. 기존 문서의 실행 성공 기록은 과거 기록이며 이번 실행으로 표시하지 않는다. 학습자 미구현은 의도된 실습 상태다. 아래 기존 학습자 상태는 main 및 기존 두 worktree의 확보 시점 기준이다. 감사 중 별도로 발견한 common-learning-foundation의 새 학습자 소스는 해당 항목의 추가 확인 단락으로 구분한다.

## 학습 계약

같은 관계형 기능이라도 좋아요와 북마크의 보존 정책이 다르고, 폴더 소유권·한도·중복 이름·삭제 시 이동을 여러 행의 불변식으로 설계한다.

## 실제 학습자 코드·정답·문서·UI의 상태

6-2 정답은 회원 행 잠금 뒤 폴더10개한도확인, 회원 내 중복 이름, saveAndFlush의 충돌번역, 폴더 삭제 전 북마크folder_id=NULL 이동을 구현한다. practice M4는 볼수없는글도 available:false로 남기며 M3좋아요목록과 다르다고 명시한다. 고급동시성/다중행규칙 자료가 없는 것은 아니다.

## 빠진 설명·직접 연습·합격 판정

좋아요의 유일성 규칙과 폴더의 최대10개 규칙은 다른데 @Transactional만 추가하면 둘 다 안전하다고 오해할 수 있다. 회원행을 왜 잠그는지, 빈폴더/없는폴더를 잠그는 방식과 어떤 차이가 있는지 직접 상태표를 작성하는 전이 과제가 필요하다. Service에서 DB 예외를 전부중복 이름으로 번역하는 범위도 검토해야 한다.

## 보완할 과제: 입력·전후 상태·SQL·실패

전: 회원2 폴더9개. 서로 다른 이름 폴더2개 동시 생성→최종11개 이상 금지. 같은 이름 생성→하나만 저장. 폴더F에 북마크2개를 넣고 DELETE F→북마크2개 유지/folder_id=NULL/폴더0. 남의 폴더 이동·삭제는404. 실패 주입으로 이동 후 삭제 실패 시 두 상태 원복을 확인한다.

## 관찰 가능한 합격 기준

10개한도/회원내이름유니크/소유권/북마크 보존을 각각 검증한다. count 조회와 INSERT 사이의 경쟁을 설명한다. 관계없는 회원 요청끼리는 과도하게 직렬화하지 않는 범위도 설명한다. unavailable 과제에서 원글 제목 등 비공개 정보를 노출하지 않는다.

## 한계와 정확성 확인

댓글/좋아요 기본을 마친 후에 적합하다. 모든 연관관계를 부모 cascade로 처리하는 일반 해법을 주지 않는다. 폴더명 정규화·DB collation은 실제 스키마와 대조해야 한다.
