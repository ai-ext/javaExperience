# I10 댓글 작성으로 1:N 연관관계 직접 구현

우선순위: **P0** / 판정: **매핑·정답 있음 · FK에서 객체 코드 도출 연습 부족**

검토일: 2026-10-21 KST. 읽기 전용 정적 감사이며 이 담당자는 원본 수정·빌드·테스트·DB 실행을 하지 않았다. 현재 작업 중인 worktree의 파일을 읽었으므로 아래 SHA256 manifest 시점의 판단이다. 기존 문서의 실행 성공 기록은 과거 기록이며 이번 실행으로 표시하지 않는다. 학습자 미구현은 의도된 실습 상태다. 아래 기존 학습자 상태는 main 및 기존 두 worktree의 확보 시점 기준이다. 감사 중 별도로 발견한 common-learning-foundation의 새 학습자 소스는 해당 항목의 추가 확인 단락으로 구분한다.

## 학습 계약

게시글 하나에 댓글 여러 개라는 요구에서 comment.post_id FK 위치를 결정하고 Comment→Post @ManyToOne로 저장한다. 부모 컬렉션이 없어도 자식 저장/조회가 가능함을 이해한다.

## 실제 학습자 코드·정답·문서·UI의 상태

5-0 읽기→5-1 작성 순서가 있고 5-1은 Comment의 Post·Member LAZY 연결, 댓글 저장+원자 count증가의 서비스 tx 및 SQL 검산을 제공한다. 개념 P20에는 mappedBy와 주인, 부모컬렉션만 변경 실패, addLine/removeLine 관찰이 있다.

## 빠진 설명·직접 연습·합격 판정

P20의 Order/OrderLine 양방향 예제에서 Comment/Post의 단방향으로 내려오는 선택 기준이 직접 과제로 연결되지 않는다. “1:N이면 부모 List와 @OneToMany부터 추가”하는 오해를 꺾는 두 버전 비교가 필요하다. 제공된 Comment 생성자를 사용하는 것만으로 FK 주인을 설계한 역량이 확인되지 않는다.

## 보완할 과제: 입력·전후 상태·SQL·실패

입력 postId=3, 토큰회원2, content=댓글A. 먼저 종이에 post3·comment행2개를 그리고 FK열을 자식에 둔다. Post에 List<Comment>가 없는 버전으로 댓글 저장·postId조회부터 구현한다. 후: comment(post_id=3,member_id=2,parent_id=NULL)1행/count c+1. SELECT post/권한→INSERT comment→UPDATE post count를 따라간다. 없는글·비공개·공백·1001자를 거절한다.

## 관찰 가능한 합격 기준

새 댓글FK와 인증회원 일치, 실패 시 comment/count 둘 다 불변, 응답DTO author 로딩의 추가SQL 이해. 부모컬렉션을 추가하는 선택 과제에서는 어느 쪽이 FK를 쓰는지와 객체 양쪽 동기화 이유를 설명한다.

## 한계와 정확성 확인

글 엔티티에 댓글 컬렉션을 강제로 추가할 필요가 없다. 현재 채점 R2도 컬렉션을 두었다면 이유가 있어야 한다고 명시한다. 학습자 src 미구현을 소스 결함으로 대신 고치지 않는다.

## 추가 common worktree 확인

common에는 PostEntity.tags의 단방향 @OneToMany+@JoinColumn(post_id)가 이미 추가되었다. 이것은 학습자의 1:N 시도다. 댓글 단방향 ManyToOne와 같은 FK를 어느 객체 쪽에서 쓰는지 비교하는 과제가 이제 더 직접적이다. 1:N 미경험/미구현이라고 단정하지 않는다.
