# I11 답글 2단계와 평평한 행에서 트리 응답 조립

우선순위: **P1** / 판정: **검증·조립 정답 있음 · 자료구조 전이 연습 부족**

검토일: 2026-10-21 KST. 읽기 전용 정적 감사이며 이 담당자는 원본 수정·빌드·테스트·DB 실행을 하지 않았다. 현재 작업 중인 worktree의 파일을 읽었으므로 아래 SHA256 manifest 시점의 판단이다. 기존 문서의 실행 성공 기록은 과거 기록이며 이번 실행으로 표시하지 않는다. 학습자 미구현은 의도된 실습 상태다. 아래 기존 학습자 상태는 main 및 기존 두 worktree의 확보 시점 기준이다. 감사 중 별도로 발견한 common-learning-foundation의 새 학습자 소스는 해당 항목의 추가 확인 단락으로 구분한다.

## 학습 계약

parent_id 자기참조와 같은글·최상위·미삭제 부모 조건을 분리한다. DB 행목록과 JSON 트리는 다른 모양이며 삭제/차단에 따른 출력 정책을 직접 구현한다.

## 실제 학습자 코드·정답·문서·UI의 상태

5-2는 resolveParent의 세 분기 및 null→최상위, 없는부모404와 규칙위반400을 설명한다. 5-3은 Map<Long,List<Comment>> 그룹, 삭제부모 placeholder, 차단부모 하위 제거, 보이는답글 기준을 정답에 구현한다. 5-3 삭제는 조건부 soft delete와 count 감소가 같은 tx다.

## 빠진 설명·직접 연습·합격 판정

완성 stream/groupingBy 코드를 읽는 것과 6개 행을 손으로 그룹화하는 능력 사이 발판이 부족하다. FK는 부모 존재만 보장하고 같은글·최대깊이를 보장하지 않는다는 경계를 직접 위반 사례로 보여 줄 필요가 있다. 요청 parentId=1.5가 정답에서1로 변환되는 관찰이 채점 제외로 남아 있어 엄격한 ID 계약과 실제 역직렬화의 차이를 놓칠 수 있다.

## 보완할 과제: 입력·전후 상태·SQL·실패

시드 comment1~6을 id,parent_id,deleted,blocked 표로 옮긴다. 먼저 for문으로 부모맵과 결과리스트를 만들고 stream은 나중 비교한다. 입력 parent1→201, parent2(답글)→400, 다른글부모→400, 삭제부모→400, 없는부모→404. 삭제4+살아있는5는 placeholder4+reply5, 삭제6은 제외한다. DB 원본행수와 DTO 노드수가 왜 다른지 기록한다.

## 관찰 가능한 합격 기준

기대 트리 id순서와 차단전후 결과, c+1 증가 및 실패불변, 동률created_at의 id정렬, 댓글마다 별도쿼리 없음. 세자리이상 깊이와 다른글 부모를 단순 FK만으로 막을 수 있다고 답하면 불합격이다.

## 한계와 정확성 확인

ID 소수 허용은 현재 관찰로 명시된 한계이며 사용자 학습자료에서 정책 결정 과제로 승격할 수 있다. 이번 감사에서 새로운 HTTP 재현은 하지 않았다.
