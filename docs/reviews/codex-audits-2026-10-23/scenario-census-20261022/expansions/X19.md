## 시작 상태

먼저 한 앱 안의 게시글·알림 모듈을 나누고 각 모듈이 소유하는 테이블과 호출 계약을 기록한다. 이후 알림만 별도 프로세스로 분리하는 선택 과제를 수행한다.

## 학습자가 할 일

1. 다른 모듈의 Repository 직접 호출을 인터페이스·이벤트 경계로 바꾼다.
2. 분리 전후 같은 글쓰기 명세와 알림의 최종 상태를 검사한다.
3. 알림 장애·네트워크 단절·중복·역순 전달의 업무 정책을 정한다.
4. 분리로 얻은 독립성과 추가 운영 비용을 명세·실측으로 평가한다.

## 정상 입력과 기대 결과

- 모놀리스에서도 모듈 경계를 지키며 단위·통합 검사가 가능하다.
- 분리 후 글 저장과 알림의 최종 처리가 합의한 계약을 유지한다.

## 실패·경계·반례

- 공유 DB 직접 쓰기·동기 호출의 연쇄 장애·분산 transaction 가정으로 생긴 부분 성공을 찾는다.
- 다른 서비스의 장애가 허용 범위 밖으로 확산하면 실패한다.

## 동시성·측정·DB 관찰과 정리
