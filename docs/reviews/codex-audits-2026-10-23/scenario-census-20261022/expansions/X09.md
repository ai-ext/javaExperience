# X09. RR/RC 비교와 빈 범위의 동시 삽입·범위 잠금

상태: **개발 명세 — 미구현·미실행**. 우선순위: P1. 확인일: 2026-10-22. 기존 학습자 코드와 시나리오 원문에 자동 반영하지 않았다.

## 현재 근거와 확장 이유

T-026은 RR snapshot 때문에 방금 커밋된 키가 일반 SELECT에 안 보이는 경우와 FOR SHARE 순서를 이미 직접 다룬다. 이를 선수로 연결하고, 새 과제는 READ COMMITTED와 REPEATABLE READ의 비교, 빈 범위의 동시 삽입, gap/range lock과 업무 불변식에 집중한다.

## 시작 상태

계좌 A/B 각각 100, 인덱스가 있는 예약 범위와 없는 범위의 별도 테이블을 준비한다. 세션 A/B를 barrier로 제어하고 초기 격리 수준을 기록한다.

## 학습자가 할 일

1. T-026의 일반 읽기·잠금 읽기 차이를 선수 검사로 확인하고 RC/RR에서 비교한다.
2. 두 세션이 같은 빈 예약 범위를 읽고 서로 다른 행을 추가하게 한다. 허용 가능한 예약 수나 중복 금지라는 업무 불변식을 검사한다.
3. 인덱스와 범위 조건에 따라 막힌 SQL·대기 대상을 기록한 뒤 각 transaction을 종료한다.

## 정상 입력과 기대 결과

- 격리 수준별 예측표와 실제 조회 값·대기가 일치한다.
- 업무 불변식이 DB 제약이나 적절한 잠금 설계로 유지된다.

## 실패·경계·반례

- transaction만 붙이면 한도 초과나 중복 예약이 사라진다는 가정을 반증한다.
- 대기 timeout과 deadlock을 같은 오류로 취급하지 않는다.

## 동시성·측정·DB 관찰과 정리

잠금·대기 정보와 세션별 BEGIN/COMMIT 시각을 함께 남긴다. 실험 후 열린 transaction이 남지 않았는지 확인한다.

## 합격 기준

SQL 순서·격리 수준·인덱스 정의로 재현할 수 있어야 한다. 불변식이 깨지는 실패판과 수정판을 모두 검증한다.

## 제작 완료 판정

위 계약을 실행할 fixture/시작 코드/검사기를 작성하고, 정상 구현 통과와 대표 오답 실패를 둘 다 확인한 뒤에만 학습 화면에 완료 상태로 공개한다. 실행 로그·버전·원문 링크·복구 결과를 함께 보존한다.
