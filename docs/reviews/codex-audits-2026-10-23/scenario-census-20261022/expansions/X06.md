# X06. flush·bulk DML·rollback·낙관적 락의 교차 실험

## 시작 상태

E7과 10-12를 완료한 별도 DB에서 글 P에 version과 updated_at을 둔다. 다른 게시판 B와 두 개의 동시 writer를 준비한다. 두 저장 기술의 DataSource와 트랜잭션 관리자 설정을 기록한다.

## 학습자가 할 일

1. 기존 flush 전후 관찰을 짧은 사전 검사로 재사용한다. 이를 새 학습 공백으로 다시 세지 않는다.
2. P를 읽은 두 writer 중 한쪽은 엔티티 변경, 다른 쪽은 bulk DML을 수행한다. version과 감사 필드의 갱신 계약을 먼저 정한다.
3. 보유 객체·재조회 결과·DB version·updated_at을 각각 기록한다.
4. 마지막 예외로 rollback하고 DB 원복과 Java 객체의 값이 자동으로 되돌아가는지는 별도로 확인한다.

## 정상 입력과 기대 결과

- 선수 실습의 flush/commit 가시성 계약이 유지된다.
- 정한 version·감사 필드 계약이 실제 bulk SQL과 일치한다.

## 실패·경계·반례

- 미전송 변경의 clear 소실, stale 객체 재사용, version 검사 없는 갱신을 구분한다.
- 동시 수정의 충돌 처리와 예외를 삼킨 경로·rollback-only 경로를 검증한다.

## 동시성·측정·DB 관찰과 정리

외부 연결의 새 autocommit SELECT와 이미 열린 RR snapshot을 구분한다. REQUIRED/REQUIRES_NEW는 G4의 기존 실험을 재사용한다.

## 합격 기준

객체 값·SQL 발행·트랜잭션 종료·다른 연결의 값에 더해 version과 감사 필드까지 독립 기대값으로 검증해야 한다.
