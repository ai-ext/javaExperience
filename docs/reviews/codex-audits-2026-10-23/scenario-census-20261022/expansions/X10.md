## 시작 상태

T-026의 회원별 키·fingerprint·유니크 제약을 유지한다. DB commit 직후 HTTP 응답 전에 연결을 종료할 수 있는 별도 앱 복사본을 둔다.

## 학습자가 할 일

1. commit 전 실패와 commit 후 응답 유실을 실제로 주입하고 같은 키로 재요청한다.
2. deadlock 재시도가 새 transaction에서 전체 업무를 다시 수행하는지 확인하고 한도·지연·시도 수를 기록한다.
3. R3의 키 보관·만료 정책을 구체 계약으로 선택하고 정리 작업과 늦은 재요청을 경합시킨다.

## 정상 입력과 기대 결과

- 같은 회원·키·payload는 같은 결과와 업무행 1개를 유지한다.
- 다른 회원의 같은 키는 독립적으로 처리된다.

## 실패·경계·반례

- 같은 키·다른 payload를 거부하고 재시도 한도 초과를 숨기지 않는다.
- DB는 commit됐지만 클라이언트가 실패를 본 경우에도 중복 업무가 생기지 않는다.

## 동시성·측정·DB 관찰과 정리

최종 성공률과 함께 실제 시도 수·rollback 수·유니크 충돌·대기 시간을 기록한다. 외부 부수효과는 X15로 분리한다.

## 합격 기준
