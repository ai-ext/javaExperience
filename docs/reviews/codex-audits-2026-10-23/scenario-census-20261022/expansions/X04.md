## 시작 상태

작성자 A·타인 B·운영자 M, PUBLIC/PRIVATE/DRAFT/HIDDEN/삭제 상태 글을 갖춘 격리 DB. 상태별 기존 원문의 403/404 우선순위를 계약으로 고정한다.

## 학습자가 할 일

1. 정답 메서드를 먼저 보지 않고 게시글 발행·숨김·복구의 상태 전이 표를 작성한다.
2. 회원 ID는 토큰, 대상 ID는 경로, 수정 값은 본문에서 얻는 과정을 추적한다.
3. 실패할 때 메모리 객체의 값과 커밋된 DB의 값이 어떻게 다른지 관찰한다.
4. HTTP와 배치 진입점에서 같은 업무를 호출해 정책 우회를 검사한다.

## 정상 입력과 기대 결과

- 허용된 전이만 실행되고 응답의 ID·상태가 DB와 일치한다.
- 서로 다른 진입점이 같은 업무 정책을 지킨다.

## 실패·경계·반례

- 본문의 authorId를 변조해도 실제 작성자는 토큰 주인이다. B의 수정·삭제 상태의 발행·중복 발행은 각 원문의 거부 계약을 따른다.
- 관계 저장 후 예외를 주입하면 글·새 태그·새 연결행이 함께 취소된다.

## 동시성·측정·DB 관찰과 정리

두 운영자가 같은 상태를 동시에 바꾸는 경우 선행 조건과 응답 계약을 먼저 정한 뒤 barrier로 확인한다. 새 과제에서 선택한 409/404를 기존 코드의 결함으로 소급하지 않는다.

## 합격 기준

학습자의 책임표와 실제 메서드·SQL이 일치하고, 정답을 복사하지 않은 상태에서 새로운 입력 조합을 통과해야 한다.
