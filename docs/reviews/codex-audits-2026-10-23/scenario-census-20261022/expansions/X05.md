## 시작 상태

글 A/B가 java 태그를 공유하고 A는 spring도 가진다. 부모 댓글 C와 답글 D를 준비한다. 14-4의 연결행 속성과 유일성 검사 결과를 선수 자료로 사용한다.

## 학습자가 할 일

1. 객체 관계, FK 소유자, ORM cascade, DB 삭제 제약의 역할을 먼저 표로 작성한다.
2. A에서 java 연결을 빼도 B의 연결과 java 태그가 남는지 검증한다.
3. post_tag에 속성이 필요하다는 추가 요구가 있을 때만 연결 엔티티로 전환하고, 기존 14-4와 공유 태그 모델의 차이를 설명한다.
4. 자식 제거·부모 삭제·연결 교체·중간 실패의 SQL과 행 수를 비교한다.

## 정상 입력과 기대 결과

- 공유 태그와 B의 연결은 보존되고 A의 대상 연결행만 사라진다.
- 추가 속성을 도입한 경우 UNIQUE(post_id,tag_id)와 조회·변경 계약을 지킨다.

## 실패·경계·반례

- 비주인 쪽만 변경한 경우와 공유 태그까지 cascade로 지운 경우를 구별한다.
- 관계 변경 도중 실패하면 원래 행과 연결이 보존된다.
- 부모 댓글이 있는 답글 삭제와 중복 연결의 제약을 확인한다.

## 동시성·측정·DB 관찰과 정리

ORM cascade와 DB ON DELETE를 같은 기능으로 취급하지 않고 SQL을 발생시킨 주체와 순서를 기록한다. 파괴 실험은 기존 practice seed와 분리한다.
