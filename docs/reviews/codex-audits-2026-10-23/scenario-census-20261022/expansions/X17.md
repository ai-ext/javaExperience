## 시작 상태

같은 DB를 쓰는 앱 A/B의 로컬 캐시와 PUBLIC 글 P를 준비한다. 양쪽 캐시가 warm한 상태와 같은 키로 50개 요청하는 상태를 구분한다. 사용자별 개인화는 추가하지 않는다.

## 학습자가 할 일

1. A의 캐시를 채운 뒤 B에서 P를 숨기고 A의 다음 공개 응답을 확인한다.
2. 선택한 무효화 전파에 지연·중복·유실을 주입하고 복구·재시작 동작을 검사한다.
3. 동시 만료 시 single-flight가 각 프로세스 안에서만 적용되는지 전체 집계 수로 측정한다.
4. T-028의 공개 결과·정렬·키(days,limit) 계약과 오류 결과의 캐시 삽입 정책을 유지한다.

## 정상 입력과 기대 결과

- 두 인스턴스 모두 합의한 최신성 범위 안에서 같은 공개 결과를 반환한다.
- 기존 단일 인스턴스 single-flight 검사는 계속 통과한다.

## 실패·경계·반례

- 숨김·삭제·공개 범위 변경 뒤 금지된 행이 남는 경우를 검출한다.
- 전파 유실이나 재시작 후에도 정한 복구 시간 안에 최신 상태로 돌아온다.
- DB 오류를 정상 데이터로 캐시하지 않는다.

## 동시성·측정·DB 관찰과 정리

응답·DB 집계 수·전파 시각·복구 시간을 양쪽에서 기록한다. TTL까지 기다리는 정책과 즉시 무효화 계약을 구분한다.

## 합격 기준

두 프로세스에서 전파 실패를 재현하고 최신성·집계 부하·복구의 대가를 설명해야 한다. 개인별 권한 캐시는 별도 API 요구로 분리한다.
