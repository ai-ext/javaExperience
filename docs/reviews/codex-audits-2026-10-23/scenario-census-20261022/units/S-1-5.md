## 판정

이전 단계에서 의도적으로 드러낸 500/잘못된 저장을 DTO 검증과 업무 규칙으로 닫고, ProblemDetail 및 DB 무변경까지 채점하는 탄탄한 통합 단계다. 12개 HTTP 입력에는 boundary, null tag, 대소문자 저장 lookup까지 들어간다. 핵심 부족은 실제 새 계약을 자동 JUnit으로 고정하지 않는 점이며, 주요 DB 상태는 수동 SELECT로 요구한다.

## 목표·선수 지식·학습자 작업

1-2~1-4에서 관찰한 DB 제약 유발 500, 저장되는 공백 입력, 없는 게시판 500을 DB 쓰기 전 명시적 DTO/서비스 규칙으로 바꾼다. 실패 응답을 RFC 9457 ProblemDetail 한 형식으로 맞춰 화면이 field 오류와 화면 전체 권한/대상 오류를 구별하게 한다.

요청 record에 Bean Validation 제약과 @Valid, visibility 생략 기본값, 게시판 미존재/ADMIN 전용 게시판 예외를 구현한다. 전역 @RestControllerAdvice에서 검증·본문 해석·업무 예외를 ProblemDetail로 응답한다. 저장 전 검증/권한을 완료한다.
