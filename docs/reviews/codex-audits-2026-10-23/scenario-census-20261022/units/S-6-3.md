## 판정

4-3과 달리 unavailable bookmark를 제거하지 않고 내용을 감춰 available=false로 돌려주는 설계가 구현되어 있다. 폴더·cursor query가 DB에서 제한되고 JUnit query-count 근거만 부족하다.

## 목표·선수 지식·학습자 작업

커서 기반 목록에 현재 못 보는 글도 북마크 관계는 보존하되 available=false로 표시하고 제목·작성자는 감춘다. 4-3 cursor utilities reused, 6-5 composes marked conditions.

폴더별 cursor keyset, unavailable 항목 redaction, author/folder/memo, size+1/nextCursor, 인증 및 잘못된 cursor 응답을 확인한다.

## 요구·구현·검사 대조

### 1. Strong HTTP 행렬을 원문 C1-C8이 제공한다. snapshot에는 Bookmark 목록 전용 test가 없고 MarkedPost/MemoPatch test만 보인다. 쿼리 수 및 cursor consistency는 코드 리뷰 항목이다.

구현 대조: BookmarkService.myBookmarks는 ALL/DEFAULT/own-folder ID 조건을 정하고 size+1 keyset 결과를 읽는다. 쿼리에서는 visibility filter를 빼 관계가 사라지지 않게 하고, accessPolicy로 각 item을 평가해 available=false면 title/author를 null로 변환한다. BookmarkRepository는 내 member만, folder mode 및 (createdAt,id) cursor를 쿼리에서 처리하고 글·작성자를 fetch한다.

검사 대조: 원문 C1-C8은 목록/폴더 필터/available·비공개 데이터/size+1/cursor/401·404를 지정한다. JUnit snapshot에 MyBookmarks 전용 테스트는 없다. JUnit 및 snapshot 테스트 존재 여부로 checker 채점 성공을 대신하지 않는다.

공백 또는 한계: 내부에서 여러 게시글의 accessPolicy를 평가할 때 팔로우/차단 정보를 한번만 읽는지, 댓글/관계 수와 무관한 쿼리인지 R3 review 요구이며 전용 query-count assertion이 없다.
