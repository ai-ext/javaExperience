## 판정

이 단계는 entity column mapping과 실제 DDL 행을 비교하고, server-side default/counter 값 및 LAZY 응답 데이터를 transaction 내에서 읽는다. HTTP/수동 SQL 확인이 있으나 schema mismatch 및 query-count 보장은 자동화되지 않았다.

## 목표·선수 지식·학습자 작업

1-3에서 저장한 post row의 누락 컬럼을 직접 확인하고, post의 모든 테이블 컬럼과 Entity 필드를 맞춘다. status/count/published_at은 앱 서버가 정하고 author_id는 Member 관계로 매핑하며 응답에 nickname을 포함한다. 1-3 JPA/태그 저장과 DDL 읽기가 선수다.

Post Entity를 post DDL 13개 컬럼과 맞추고 Member/Board 연관관계를 매핑한다. PostService에서 현재 시각/상태/카운트/삭제 시각을 결정하고 response author 정보를 트랜잭션 내에 읽어 제공한다. `ddl-auto: validate`와 SQL/bind logs를 확인한다.
