원문은 단계별 코드 제공/미완성 구간을 구별해 적고, 학습자는 해당 쿼리 요구와 경계 케이스를 실행 결과로 확인한다. exists 결과가 공개 상세 조회와 일관되고 숨김/삭제 글은 false인지 확인한다.

## 요구·구현·검사 대조

### 1. exists는 행이 실제 공개 detail query 조건(deletedAt/hiddenAt null, PUBLISHED, PUBLIC)을 모두 만족할 때만 true다.

구현 대조: Derived existsById...와 MyBatis SELECT EXISTS가 deleted/hidden/status/visibility 동일 조건을 쓴다. ID 양수 검증 뒤 존재성 조회를 수행한다.

검사 대조: 자동 흐름은 생성한 P에 대해 exists 결과 true를 확인한다. 없는 ID 및 hidden/deleted/non-PUBLIC 반례의 false는 별도 요청하지 않는다.

공백 또는 한계: 성공 true 한 사례만 검사한다. 같은 ID를 숨기거나 삭제한 뒤 false가 되는지, 존재하지 않는 양수 ID가 false인지 확인하는 음성 경계가 없다.

## 확장 개발 명세

### Q06 구체 데이터 결과와 경계 검사

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

exists는 행이 실제 공개 detail query 조건(deletedAt/hiddenAt null, PUBLISHED, PUBLIC)을 모두 만족할 때만 true다.

**시작 상태**

L12 practice profile. Request P creates dev/PUBLISHED/PUBLIC post `[쿼리연습] JPA 연결` with content `본문 JPA 검색` by member5. Use dynamic id/author from P response.

**학습자가 할 일**

- F에 P.body.id를 넣어 JPA exists와 MyBatis exists를 각각 호출한다.
- P를 HIDDEN으로 바꾼 뒤 false를 확인하고 원상복구한다.
- seed deleted ID42 및 없는 양수 ID를 조회해 false를 확인한다.
- 반환된 true/false가 detail의 네 공개 조건과 일치하는지 대조한다.

**정상 사례**

- 삭제·숨김이 없고 PUBLISHED/PUBLIC인 P는 exists=true다.

**실패·경계 사례**

- F는 P ID, C6은 status200 및 exists=true만 검사한다. false 상태는 자동 검사 범위 밖이다.

**동시성·성능**

L12 query 정확성만 다룬다. plan/성능 측정은 DB-08~14에서 수행한다.

**DB 관찰**

- 실제 응답 ID/total/status와 실행 SQL을 기록한다. items type만 확인하지 않는다.
- 동적 P로 seed count가 달라질 수 있으므로 reset하거나 직접 SQL과 대조한다.

**합격 기준**

- 공개 P는 true이고 HIDDEN/deleted/없는 ID는 false다.
- JPA와 MyBatis가 각 입력에서 같은 Boolean을 반환한다.

**기존 과제와 중복·연결**

Q02는 hidden/deleted 조건, DB-01은 field mapping, DB-07은 query 방식 비교를 다룬다.
