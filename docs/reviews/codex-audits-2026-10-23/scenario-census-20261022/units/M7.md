## 확장 개발 명세

### M7 댓글 트리·삭제 자리·답글 제한·카운터 확인

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

중첩·삭제 댓글 응답과 트랜잭션 카운터 변경을 함께 검증한다.

**시작 상태**

MISSION 예시는 practice post4/comment12다. 5-3 snapshot 테스트는 별도 post11/comment4 seed를 쓰므로 mission seed에서 재현하거나 동등 행 대응을 기록한다.

**학습자가 할 일**

- post4 댓글을 작성자/조회자 조건으로 불러와 root와 답글의 createdAt/id 순서를 확인한다.
- 삭제된 comment12는 노출 가능한 live 답글이 있을 때만 placeholder로 남고 없으면 빠지는지 확인한다.
- 답글의 답글, 삭제 부모, 다른 게시글 부모에 각각 답글을 시도한다.
- 댓글 생성 전후 comment_count를 기록하고 한 번 삭제 및 반복/동시 삭제 뒤 live 댓글 행 수와 비교한다.
- 댓글 작성자를 차단한 조회자로 root 하위 트리 또는 답글 필터 결과를 확인한다.

**정상 사례**

- root 댓글은 createdAt/id 오름차순, 답글도 같은 순서로 부모 아래 배치한다.
- 삭제 comment12는 노출 가능한 live 답글이 있을 때만 placeholder를 보인다.

**실패·경계 사례**

- 없는 댓글/이미 삭제된 댓글 삭제는 404, 다른 사람 댓글 삭제는 403이어야 한다.
- 차단된 root와 그 하위 답글은 숨기고, 차단된 답글만 걸린 경우 해당 답글만 필터링한다.

**동시성·성능**

snapshot 동시 삭제 테스트는 요청 8개 중 실제 삭제 1개, not_found 7개 및 카운터 1회 감소를 기대한다. 이는 MISSION post4/comment12 값 직접 검사와 구별한다.

**DB 관찰**

- 응답 트리 ID·부모 ID·deleted flag와 placeholder 내용.
- comment 테이블 live 행 수 및 post.comment_count 전후 값.

**합격 기준**

- 댓글 추가/삭제 뒤 counter가 답글을 포함한 미삭제 댓글 수와 일치한다.
- 반복 동시 삭제는 단 한 번만 상태 전이하고 counter를 한 번 감소한다.

**기존 과제와 중복·연결**

5-2는 1단계 답글, 5-3은 삭제/트리, 5-1/5-3은 counter 변경을 다룬다. M7은 이 동작을 묶은 mission이다.

**우선순위**

medium
