## 목표·선수 지식·학습자 작업

팔로잉 피드는 내 글과 내가 팔로우한 회원의 PUBLISHED 글을 keyset으로 보여 준다. 팔로워 공개 글은 포함하고, 양방향 차단과 내가 건 뮤트는 제외한다. 뮤트는 피드에만 영향 주고 글 상세 접근을 바꾸지 않는다. 선수는 12-4 follow, 2-3 access policy, 6-3 cursor pagination.

직접 구현: V32 member_mute unique/self check, idempotent PUT/DELETE, active target checks, 피드 작성자 OR follow, 양방향 block NOT EXISTS, muter-only mute NOT EXISTS, publishedAt/id cursor와 size+1 응답. 리스트 아이템 태그 fetch 전략도 책임진다.

## 확장 개발 명세

### Feed filter and mute boundary integration test

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

feed repository 한 쿼리에서 follow/block/mute 필터를 함께 적용하므로 차단 결과를 너무 많이 빼거나 차단 사용자를 노출하는 회귀가 생길 수 있다.

**시작 상태**

viewer 회원 6, 자기 공개 글 145, followee 공개 글 101과 FOLLOWERS 글 91, 무관 public 44, DRAFT 83, 차단 작성자 글, mute 대상 회원 7을 준비한다.

**학습자가 할 일**

- size=2로 feed를 호출하고 cursor로 끝까지 이어 받아 ID/order를 기록한다.
- 작성자 7을 mute한 뒤 feed를 다시 부르고, muted 글 상세는 직접 조회한다. unmute 후 feed를 다시 비교한다.
- feed ID를 follow/block/mute 조건을 포함한 SQL 결과와 비교한다.

**정상 사례**

- Before mute: 145,101,91,44 in publishedAt/id order; 83 absent.
- mute 후 해당 작성자의 글만 feed에서 빠진다. 상세는 200이며 unmute 후 다시 보인다.

**실패·경계 사례**

- 어느 방향의 차단도 feed에서 작성자 글을 제외한다. mute는 직접 상세나 전역 공개정책을 바꾸지 않는다.
- 탈퇴/없는 대상, 자기 mute, 잘못된 cursor는 지정된 404/400 status를 반환한다.

**동시성·성능**

seed와 실제 muted relation cardinality에서 mute NOT EXISTS 조건의 EXPLAIN을 수행하되 빈 테이블 plan만으로 결론 내리지 않는다.

**DB 관찰**

SELECT feed candidate ids, follow/block/mute rows and compare API page/cursor.

**합격 기준**

모든 page를 이어 받은 id/order가 기대 집합과 같고 mute는 본인 feed만 바꾸며, EXPLAIN 결과는 실제 조건/fixture와 함께 기록한다.

**기존 과제와 중복·연결**

T-012는 별도 feed API 구현 ticket이다. 이 실험은 기존 feed의 mute lifecycle/visibility 회귀만 보며 route를 재구현하지 않는다.
