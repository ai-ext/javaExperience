## 판정

## 목표·선수 지식·학습자 작업

북마크·폴더 수명, 소유권과 한도, 접근할 수 없는 게시글을 목록에 보존하는 응답을 다룬다. 고정 시각 2026-10-05의 practice DB를 사용하고 R1~R5 공통 규칙을 적용한다.

업무 규칙·시작 데이터·기대 개수는 문서에 있다. 학습자가 구현, SQL, 테스트를 작성하고 실패 원인과 DB 전후 상태를 설명한다. 북마크와 폴더의 생성·삭제·이동, unavailable 게시글 응답을 각각 검증한다.

## 확장 개발 명세

### 폴더 소유권·한도와 unavailable 북마크 검증

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

폴더 상태, 소유권, 삭제 시 bookmark 이동, 접근 불가 bookmark 보존은 서로 다른 불변조건이다.

**시작 상태**

practice seed에서 member6은 폴더 10개, member8은 기본 폴더와 2·10번 폴더를 보유한다. member8 북마크에는 현재 접근 불가인 post108이 있다. 원본 seed에서 요청 전후 폴더/북마크 행을 기록한다.

**학습자가 할 일**

- member6으로 11번째 폴더 생성을 요청해 거절 상태와 DB 폴더 수=10을 확인한다. member8로 생성 요청을 보내 성공하며 폴더 수가 4가 되는지 대조한다.
- member8 소유 폴더2·10번을 확인한 뒤 타 회원이 폴더10을 수정/삭제할 때 거절되고 DB 상태가 바뀌지 않는지 확인한다.
- member8 소유 폴더2를 삭제하고 연결된 7개 북마크가 기본 폴더로 옮겨지는지 확인한다. 삭제 전/후 전체 북마크 행 수를 비교한다.
- post108 북마크 행은 남고 available=false이며 title/author가 비노출인지 확인한다. 접근 가능한 북마크 행의 available=true와 title/author도 확인한다.
- 요청 입력 이름은 과제 문서와 snapshot API를 각각 읽어 해당 계약에 맞게 보낸다. 이름 차이만으로 구현 오류라고 판정하지 않는다.

**정상 사례**

- member8 seed의 기본 폴더 북마크 6개, folder2 7개(post108 포함), folder10 5개.
- member6의 11번째 폴더 생성은 거절되어 10개를 유지한다.
- 폴더2 삭제 뒤 7개 북마크가 기본 폴더로 옮겨져 전체 북마크 수가 보존된다.

**실패·경계 사례**

- 10개 초과가 허용되거나 타 회원이 남의 폴더를 변경할 수 있으면 해당 업무 규칙의 실패다.
- 삭제 폴더의 북마크가 유실되거나 post108의 숨겨진 title/author가 노출되면 이동/응답 검증 실패다.

**동시성·성능**

Service는 동시 11번째 폴더 생성을 막으려고 count 전에 member 행을 잠근다. 기존 동시성 test는 중복 bookmark set만 검사하며 폴더 한도는 다루지 않는다.

**DB 관찰**

- folder/member 소유권 ID, 삭제 전후 bookmark.folder_id, available flag와 folder별 count.

**합격 기준**

- member6/member8 한도 경계를 각각 10/11개와 3/4개로 확인한다.
- 삭제 전후 member8 북마크 총수가 동일하고 folder2의 7개가 기본으로 이전된다.
- post108은 목록에 남되 available=false, title/author 비노출이고 접근 가능한 행은 available=true다.
- 타 회원의 폴더 변경 요청은 거절되고 DB 상태는 유지된다.

**기존 과제와 중복·연결**

6-2/6-3 시나리오는 폴더 생성/목록을 별도로 설명한다. 확인된 test 산출물은 bookmark set만 검사한다.
