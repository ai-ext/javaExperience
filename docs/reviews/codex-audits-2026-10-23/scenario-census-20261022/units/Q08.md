## 확장 개발 명세

### page/size 경계와 두 페이지 겹침 확인

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

Q08의 현재 요청은 offset paging이다. 안정 정렬 id DESC, size 상한과 total을 확인한다.

**시작 상태**

L12 practice profile에서 P 게시글이 생성된 뒤 요청 H `/api/query-practice/jpa/posts?page=1&size=2`가 실행된다. 정렬은 전체 공개 게시글 id DESC다.

**학습자가 할 일**

첫 페이지 page0,size2와 두 번째 page1,size2를 각각 실행한다.

**정상 사례**

모든 응답은 items 길이 2 이하이며 page/size/total 값이 요청과 맞는다. 같은 입력에서 페이지 간 id 중복이 없어야 한다.

**실패·경계 사례**

size=0 또는 51, page=-1 또는 10001은 400이어야 한다. total보다 먼 page는 빈 items와 원래 total을 유지한다.

**동시성·성능**

이 단위는 쿼리 정확성과 응답 계약을 확인한다. 실행 계획과 시간 측정은 DB-08~14에 연결한다.

**DB 관찰**

각 페이지의 id 배열, total, hasNext, 실행 SQL의 LIMIT/OFFSET.

**합격 기준**

page1,size2 응답은 page=1,size=2; page0/page1 결과를 합쳐 같은 입력의 전체 정렬 순서와 맞고 중복·누락이 없다. size 범위는 1..50, page는 0..10000.

**기존 과제와 중복·연결**

M1 cursor 계약은 DB-02가 다룬다. page/offset은 완전한 keyset cursor를 대체하지 않는다.

**우선순위**

medium
