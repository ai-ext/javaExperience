## 확장 개발 명세

### V1 checksum 오류를 격리 DB에서 재현

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

V1을 적용한 disposable project DB에서만 checksum 불일치를 재현하고 운영 데이터와 실습 볼륨은 수정하지 않는다.

**시작 상태**

V1 적용 후 복제한 disposable DB에서 file checksum을 기록한다.

**학습자가 할 일**

- 복제 DB에서만 migration 파일을 변경해 기동 오류와 history row를 비교한다.
- 복구할 새 disposable DB를 다시 만들고 원래 V1의 불변 원칙과 V2 작성 흐름을 확인한다.

**정상 사례**

- 원문 checker가 지정한 정상 경계값과 정상 row/response를 유지한다.

**실패·경계 사례**

- 문서가 요구한 오류 코드와 오류 전후 DB state를 단언한다.

**동시성·성능**

동시성은 해당 실험에서만 barrier/별도 transaction으로 확인한다. 측정하지 않은 성능 개선은 주장하지 않는다.

**DB 관찰**

- 독립 disposable DB에서 핵심 relation/row/count의 전후값을 확인한다.

**합격 기준**

수정 전 기준 schema/version history를 기록하고 오류 뒤 test DB를 폐기한다.

**기존 과제와 중복·연결**

현재 단위의 원문 C/D/R 계약만 자동 검증한다. 기존 follow-up 단계의 책임을 이 단계에 복사하지 않는다.

**우선순위**

medium
