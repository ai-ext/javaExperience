## 판정

poll ownership/권한·검증·zero-count·DB unique 계약이 구체적이다. 병렬 첫 투표 JUnit은 없어 runtime race 재현은 확장으로 남긴다.

## 목표·선수 지식·학습자 작업

작성자는 게시글당 poll 하나와 2~5개 순서 옵션을 만든다. 로그인 회원당 한 번 투표하고 option은 그 poll에 속해야 한다. 공개 글 열람 권한이 있는 사람은 anonymous 포함 합계를 보며 zero vote option도 반환한다.

V51 poll/option/vote schema, 원시 JSON 타입 보존/요청 검증, 작성자 전용 poll 생성, option 소속 확인, poll/member UNIQUE, LEFT JOIN zero-fill 집계와 내 vote option 응답을 구현한다.

## 확장 개발 명세

### Concurrent first-vote uniqueness

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

Service 사전 조회는 동시 요청에서 보장하지 않는다. DB unique key 결과와 실제 수신 응답을 재현한다.

**시작 상태**

작성자 2가 공개 글 13에 Kimchi/rice/noodle poll을 만든다. 회원 3은 아직 투표하지 않았다.

**학습자가 할 일**

- 회원 3이 서로 다른 option id에 두 투표 POST를 barrier로 동시에 보낸다.
- 각 HTTP 결과와 완료 후 vote row/tally를 기록한다.
- 같은 option id 두 번도 시도해 choice와 1회 투표 규칙을 구분한다.

**정상 사례**

- poll/member당 한 행만 남고 한 요청 성공, 다른 요청 409다.
- GET 총계는 한 번만 증가하고 myVoteOptionId는 성공한 choice와 같다.

**실패·경계 사례**

- 다른 poll의 option 또는 poll 없는 요청은 vote row를 만들지 않는다.
- Any unexpected unique race maps to 409, not 500.

**동시성·성능**

Two independent transactions with synchronized start.

**DB 관찰**

SELECT poll_id,member_id,option_id and grouped counts; unique index definition.

**합격 기준**

row 한 개, total 증가 1, viewer 선택 일치, 500이 없어야 한다.

**기존 과제와 중복·연결**

C8은 순차 중복 투표를 확인한다. 확장은 동시 최초 INSERT만 추가한다.

**우선순위**
