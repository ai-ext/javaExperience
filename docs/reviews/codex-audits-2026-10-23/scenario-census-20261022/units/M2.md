## 확장 개발 명세

### 활성 회원 25명의 동시 PUT·멱등·권한 검사

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

MISSION 수치와 행 개수·비정규화 카운터의 최종 상태를 비교한다.

**시작 상태**

격리 Testcontainers practice seed에서 접근 가능한 공개 게시글을 고르고 요청 전 like_count와 관계 행을 기록한다.

**학습자가 할 일**

- 활성 비작성자 회원 25개 요청을 공통 시작 latch 뒤에서 같은 게시글에 PUT한다.
- 트랜잭션 커밋 후 성공 응답 수, 관계 행 수, post.like_count를 비교한다.
- 같은 회원 PUT을 반복해 행 1개를 확인하고 DELETE 두 번으로 상태 전이와 카운터 감소가 한 번만 일어나는지 확인한다.
- 자기 글, 정지 회원28, 접근 불가/숨김 글, 토큰 없는 요청의 상태 코드를 각각 기록한다.

**정상 사례**

- 서로 다른 활성 비작성자 25명이 같은 게시글에 좋아요를 넣고 commit한 뒤 관계 행 수와 like_count가 모두 25 증가한다.
- 같은 회원 PUT 반복은 관계 행을 추가하지 않고 DELETE 반복도 카운터를 두 번 감소시키지 않는다.

**실패·경계 사례**

- 자기 글, 정지 회원28, 접근 불가 글, 익명 요청 결과를 합쳐 보지 말고 개별 HTTP 상태와 DB 변경 0을 확인한다.
- 동시 요청 뒤 카운터와 관계 행 수가 다르면 원자성/멱등성 불변식이 깨진 것이다.

**동시성·성능**

공통 시작 latch 뒤 25개 요청을 보내고 성공/실패 응답, row count, counter를 함께 비교한다.

**DB 관찰**

- 요청 전후 post.like_count와 해당 post의 post_like 행 수.
- 동일 사용자 중복 PUT/DELETE 전후 관계 행 및 카운터 차이.

**합격 기준**

- 서로 다른 회원 25개 동시 PUT 뒤 행 25개와 like_count 증가 25가 일치한다.
- 중복 요청은 추가 행/추가 감소가 없고 접근 거절 요청은 DB를 바꾸지 않는다.

**기존 과제와 중복·연결**

S-4-2와 관련 동시성 테스트는 구현 비교 자료다. MISSION은 별도 지정 인원 25와 회원28 fixture를 확인해야 한다.

high
