## 목표·선수 지식·학습자 작업

댓글 작성은 발행됐고 현재 로그인 회원이 볼 수 있는 글에만 허용한다. 댓글 INSERT와 posts.comment_count 증가는 단일 서비스 트랜잭션으로 묶어 둘 중 하나만 저장되는 상태를 막는다. 5-0 목록과 10장 응답/인증 흐름이 선수이며 답글은 다음 5-2다.

인증 사용자·글 접근 정책·@Valid 본문 검증·댓글 저장·작성자 DTO 응답을 구현하고 Location, 실패 상태, DB count 변화를 확인한다.

## 확장 개발 명세

### 댓글 저장 후 count 갱신 실패 시 원자성 확인

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

두 DB 쓰기의 transaction 계약을 관찰 가능한 행으로 검증한다.

**시작 상태**

격리 test DB의 기존 comment 수와 post.comment_count를 기록하고 특정 post의 단일 요청을 준비한다.

**학습자가 할 일**

- 댓글 INSERT 뒤 count UPDATE가 실패하도록 테스트 전용 주입점을 만든다.
- 응답 실패 이후 comments와 posts.comment_count를 다시 조회한다.
- JPA와 MyBatis 구현이 같은 rollback 결과를 내는지 비교한다.

**정상 사례**

- 정상 POST는 201, 댓글행 1개와 count +1.

**실패·경계 사례**

- count 변경 실패 시 comment INSERT도 rollback되어 row/count가 모두 기존값.

**동시성·성능**

동시 댓글에서 카운터 lost update를 예방하는 원자 UPDATE는 코드 경로를 읽고 후속 실험 대상으로 검증한다.

**DB 관찰**

- 요청 전/후 comments row와 posts.comment_count
- 실패 시 transaction rollback 로그

**합격 기준**

- 정상·강제실패 모두 row와 count가 정확히 일치하고 JUnit assertion으로 검증된다.

**기존 과제와 중복·연결**

5-3에서 counter decrement와 delete 원자성을 다루므로 새 요구는 create 쪽 failure injection에 한정한다.

**우선순위**
