## 확장 개발 명세

### 삭제 댓글 PATCH 동작을 회귀 테스트로 고정

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

삭제 댓글 편집 guard는 snapshot에 있고 main agent runtime에서 create201/delete204/PATCH404와 DB 불변을 확인했다. 저장소 JUnit에 edit 전용 테스트는 없다.

**시작 상태**

소유자가 공개 댓글을 만들고 id/content/edited_at을 기록한 뒤 댓글을 soft delete한다.

**학습자가 할 일**

- 원래 소유자로 삭제된 댓글 id에 다른 content PATCH를 보낸다.
- 요청 전후 DB content/edited_at/deleted_at과 댓글 목록을 비교한다.

**정상 사례**

- 살아 있고 소유한 댓글을 변경하면 200/edited=true다.

**실패·경계 사례**

- 삭제 댓글은 404이고 content/edited_at은 바뀌지 않으며 목록 placeholder는 edited=false다.

**동시성·성능**

부하가 목적은 아니다. lock 정책을 바꾸는 경우 edit/delete race는 별도로 추가한다.

**DB 관찰**

SELECT content,deleted_at,edited_at for the same id before/after PATCH.

**합격 기준**

재현 가능한 테스트가 404와 row 불변을 증명해야 한다. 현재 runtime-targeted probe는 1회 확인 결과일 뿐이다.

**기존 과제와 중복·연결**

5-1 validation/create, S-12-2 mention, S-13-2 report/moderation, T-015 delete permission과 같은 기능을 중복 구현하지 않는다.

**우선순위**

low
