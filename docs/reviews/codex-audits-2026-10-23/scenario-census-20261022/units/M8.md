## 확장 개발 명세

### S-8-5 카운터 보정과 두 번째 실행의 no-op

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

MISSION의 고정 수치는 재집계 Service와 endpoint 검사에 대응한다. 추가 검증은 정확한 값과 멱등성을 보존한다.

**시작 상태**

의도적으로 틀린 practice seed에서 좋아요 93/119/120 값은 6/10/3이고 원본 행 기준은 4/5/4다. 댓글 22/75 값은 9/2이고 기준은 8/4다.

**학습자가 할 일**

- 관리자 재집계를 한 번 호출하고 likeFixed/commentFixed와 요청 전후 값을 기록한다.
- 같은 요청을 다시 보내 두 배열이 모두 비어 있는지 확인한다.
- D1/D2 원본 행 기준 불일치 건수를 별도 SQL로 확인한다.
- scheduler가 같은 method로 위임하는지 확인하고 여러 replica의 중복 실행은 운영 논점으로 구분한다.

**정상 사례**

- 첫 실행에서 지정된 like/comment 보정 tuple이 반환되고 두 번째 실행의 보정 배열은 빈 값이다.
- 보정 뒤 저장 counter는 실제 live source row 집계와 일치한다.

**실패·경계 사례**

- 원본 행이 재집계 중 바뀌면 snapshot/잠금의 일관성을 별도로 검토한다.

**동시성·성능**

batch SQL은 집합 연산이다. 다중 서버 분산 잠금과 재집계 중 원본 쓰기는 이 mission에서 테스트하지 않는다.

**DB 관찰**

- 응답 보정 목록, counter 값과 source row 기준 불일치 수.

**합격 기준**

- 첫 실행 tuple, 두 번째 빈 배열, D1/D2 불일치 0을 확인한다.

**기존 과제와 중복·연결**

S-8-5가 같은 시나리오의 상세 구현 및 검사 기준을 제공한다.

**우선순위**

low
