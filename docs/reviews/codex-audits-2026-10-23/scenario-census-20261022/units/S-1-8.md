## 판정

## 목표·선수 지식·학습자 작업

원본 글 ID는 path, 태그 복사는 query, 새 제목은 request DTO, 작성자는 인증 토큰에서 각각 가져오는 새 생성 경로를 만든다. 원본의 공개/발행/삭제 상태와 source board 쓰기 권한을 확인한 뒤 별도 Post entity로 저장한다. 1-6 인증, 1-3 tags transaction, 1-5 input validation이 선수다.

CopyPostRequest title만 받고 copyTags default false query를 해석한다. Service에서 원본을 조회해 PUBLISHED/PUBLIC/not-deleted 정책과 board role을 확인하고 source content/board를 복사해 새 작성자·새 제목·새 시각으로 저장한다. 옵션에 따라 원본 tag 연결을 복사한다.

### 복사 필드 불변/복제 assertions 강화

**이유**

게시판/본문 복사와 원본 불변이 핵심 계약이므로 DB 조회로 명시해 회귀를 보호한다.

**시작 상태**

seed post id 2와 @Transactional PostCopyControllerTest setup.

**학습자가 할 일**

tags=true/false로 복사 후 두 새 post의 board_id/content가 원본과 같고 title/author는 달라졌는지, 원본 행은 그대로인지, 관계 행은 선택된 경우만 있는지 검사한다.

**정상 사례**

- copyTags true preserves tag IDs/response names
- copyTags false yields no join rows
- new post retains original content and board

**실패·경계 사례**

- private/draft/deleted 원본은 404이고 신규 post/join row가 생기지 않는다.

**동시성·성능**

No concurrency/performance requirement

**DB 관찰**

테스트 rollback transaction/fixture를 사용해 post와 post_tag 행을 확인하고 community seed를 수정하지 않는다.

**합격 기준**

테스트가 원본과 두 신규 행의 board/content/title/author/status/visibility 및 tag join을 직접 비교한 뒤 원본 행 불변을 확인한다.

**기존 과제와 중복·연결**

1-7 직접 SQL과 7-3 통합테스트의 기법을 쓴다. 새 production behavior는 추가하지 않는다.
