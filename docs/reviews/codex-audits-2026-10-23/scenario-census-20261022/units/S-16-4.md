## 판정

정적 대조상 입력검증과 유효하지만 느린/열리지 않는 URL의 201/null 경계, transaction 밖 호출, timeout·64KB·title parser 구현은 명세와 맞는다. 실습은 localhost 접근을 허용한다고 명시하므로 SSRF는 의도된 교육 한계지만 운영 적용에는 그대로 사용할 수 없다. timeout/streaming 공격 회귀도 미포함이다.

## 목표·선수 지식·학습자 작업

새 글 입력에 URL 미리보기를 붙여 외부 HTTP 지연/실패를 글 저장·DB transaction과 분리한다. 선수는 1-5 JSON 입력 검증, 16-1/16-2 transaction·Server-Timing, HTTP connect/read timeout, HTML 최소 파싱과 SSRF 위험이다. 실습 fake site는 localhost라 내부 주소 차단을 의도적으로 풀어 두며 운영 서버 보안 구현과 분리한다.

V72 post.link_url/title nullable 컬럼 및 strict linkUrl 검증을 추가한다. Controller가 transaction 밖에서 RestClient fetch를 먼저 실행해 link metadata를 post create로 넘긴다. connect/read timeout은 각각 1초/2초, 2xx만 받아 앞 64KB에서 og:title→title, HTML entity unescape 및 200자 절단을 한다. URL 형식 오류 400과 유효하지만 접근 불가인 URL 201/null title을 구분한다.

## 요구·구현·검사 대조

### 1. linkUrl은 선택이다. null/필드 생략은 링크 없음이며 빈 문자열/공백·초과 500자·http/https가 아닌 scheme·공백 포함은 400, 여러 필드 오류를 모두 반환한다. 입력 형식이 맞지만 서버 응답이 실패해도 글을 201로 저장하고 title은 null이다.

구현 대조: 구현 일치: Service는 fetch 실패/비2xx/잘못된 URI 등을 catch해 url 유지·title null을 반환한다. 입력 형식 검증은 controller/DTO 단계에 있어야 fetch 전에 막히며 잘못된 여러 필드는 공통 error map에 누적된다.

검사 대조: C1은 다중 입력 오류 필드를 확인하고 C2는 no link/null·500자 상한·접속 불가, D2는 잘못된 URL이 link_url로 저장되지 않음을 확인한다.

## 확장 개발 명세

### 실서비스 SSRF 차단과 slow-stream/redirect/bytesize 검증

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

localhost fake exercise를 그대로 배포하면 내부 서비스로 요청할 수 있다. 배포 모드에서만 허용 목적지를 좁히고 timeout/읽기 상한을 실제 adversarial server로 검증한다.

**시작 상태**

별도 test network에 public fake host, redirect-to-127.0.0.1, private IPv4/IPv6, metadata IP mock, DNS rebinding mock, chunked slow stream, gzip huge body server를 둔다. local exercise mode와 production mode 설정을 분리한다.

**학습자가 할 일**

- scheme/host resolve 후 모든 A/AAAA 주소를 검사하고 loopback/private/link-local/reserved ranges를 차단
- redirect를 자동 추적하지 않거나 각 redirect hop에서 DNS/IP 정책을 재검증
- connect timeout, per-read timeout, 전체 wall-clock deadline 2초를 독립 설정/테스트
- 압축 해제 후 최대 bytes와 content type/charset을 검사
- 성공/차단/timeout 로그에서 credential/query secret을 가리고 fake site CORS 경로는 production에서 비활성화

**정상 사례**

- 공개 allowlist URL은 제한된 bytes/time 내 title을 추출한다.
- 형식 오류는 400, 유효 URL의 connect/read/total timeout은 201/null title이다.

**실패·경계 사례**

- redirect chain이 private IP에 도달하기 전에 차단된다.
- slow drip은 각 read timeout 아래라도 total deadline 안에 중단된다.
- gzip/무한 chunk stream이 decompressed byte cap을 넘으면 close하고 title null로 끝난다.

**동시성·성능**

동시 미리보기 1/20/100 요청에서 server thread 점유, pool/DB connection 사용, p95와 outbound sockets를 관찰하고 rate limit을 결정한다.

**DB 관찰**

실패 URL도 link_url은 유지되고 link_title NULL, 잘못된 scheme은 post row가 생성되지 않는다는 contract를 확인한다.

**합격 기준**

실습 localhost 경로는 profile상 유지하되 운영 profile에서는 private/metadata/redirect가 거절되고 total deadline·decoded size 상한·connection budget이 adversarial test로 통과한다.

**기존 과제와 중복·연결**

현 C1~C5/D1~D3/R1~R5를 보존하고 추가 SSRF/slow stream 조건은 production profile 확장으로 명시한다.
