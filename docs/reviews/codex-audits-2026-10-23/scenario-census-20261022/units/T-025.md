## 판정

version lifecycle와 stale API 결과, bulk update 영향이 구체적이다. 필수 자동 경쟁 검사는 선택이므로 요구의 @Version 경계를 테스트로 고정할 필요가 있고 legacy no-version의 overwrite 위험을 드러냈다.

## 목표·선수 지식·학습자 작업

상세 응답의 version을 PATCH precondition으로 사용해 stale client는 409/currentVersion으로 거부하고, 비교 이후의 race는 JPA @Version이 잡는다. 읽기나 counter 변경이 무관하게 버전을 올리지 않아야 한다.

V7 version column/엔티티 @Version, GET/PATCH DTO, optional version 입력과 stale 체크, commit-time ObjectOptimisticLockingFailureException→409 변환을 구현한다. 조회수는 bulk atomic update로 옮기고 좋아요/댓글 벌크 변경이 version을 건드리지 않는지 비교한다.
