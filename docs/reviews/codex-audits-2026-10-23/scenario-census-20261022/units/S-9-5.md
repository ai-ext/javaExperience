## 쿼리·DB 깊이와 다음 단계

문서의 운영 rollout은 단일 서버용 두 migration보다 긴 순서다. V5 열 추가/초기 복사 후 memo를 읽고 양쪽 쓰는 서버를 배포하고, memo→note 불일치를 별도로 보정한다. 모든 서버를 note 읽기/양쪽 쓰기로 바꾼 뒤 memo 사용이 끝나면 note만 쓰고 마지막에 V6로 memo를 제거한다. 최종 snapshot은 이 중간 서버 조합을 시험하지 않는다.

- 현재 난이도: 고급(해당 단계 기준)
- 판정 이유: old/new 이름을 함께 유지하면서 배포 버전 간 호환을 보존한 expand-contract migration을 수행한다.
- 다음 단계: 9-3 backfill, 16장 rollout과 맞물린다. 실제 무중단/lock-time guarantee는 운영 MySQL 버전·DDL 알고리즘에 따라 별도 측정해야 한다.

## 확장 개발 명세

### memo에서 note로 확장·복사·읽기 전환·제거 검증

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

열 이름 변경은 기존/신규 앱의 읽기·쓰기 호환성이 없을 수 있으므로 모든 서버가 계약 단계에 도달하기 전 열을 제거하면 안 된다.

**시작 상태**

practice schema에는 bookmark.memo와 51개 memo 값이 있고 note는 없다. API wire field는 memo다. destructive drop 전 backup/disposable DB를 사용한다.

**학습자가 할 일**

- Expand 단계에서 nullable note를 추가하고 memo를 복사한 뒤 D2/D3로 51개 값이 보존됐는지 확인한다.
- 기존 서버가 memo를 읽는 상태에서 전환 코드를 배포해 memo/note 양쪽 쓰기가 되는지 확인한다. 이전 버전 서버로 값을 바꾸고 reconciliation 뒤 두 열 값이 일치하는지 확인한다.
- 모든 서버의 read가 note로 전환된 뒤 note 읽기와 두 열 쓰기를 확인한다. 구버전 인스턴스가 남아 있는 동안 V6 drop을 실행하지 않는다.
- 서버가 note만 쓰고 memo를 더 이상 참조하지 않는지 확인한 다음 V6를 적용해 memo 제거와 최종 API memo wire 호환을 확인한다.
- D1~D5와 C/API 검사 결과, 서버 버전/단계를 시간순으로 기록한다. V6 실행 후 rollback을 즉석에서 시도하지 않는다.

**정상 사례**

- V5 뒤 기존 memo 값 51개가 note로 복사되고 API field memo는 유지된다.
- 모든 서버가 note 전환 뒤 V6 drop을 수행하면 DB에는 note만 남고 GET/PATCH API는 기존 memo 계약을 만족한다.

**실패·경계 사례**

- copy 전 note NOT NULL 추가는 기존 행에서 실패할 수 있다.
- dual-write 중 한 열만 갱신되면 reconciliation 뒤 값 불일치가 남는다.
- 구버전이 memo를 읽거나 쓰는 동안 V6로 memo를 제거하면 오류 또는 데이터 유실 위험이 있다.

**동시성·성능**

다중 서버 배포 단계의 실험이며 이 snapshot에는 혼합 버전 통합 테스트가 없다. reconciliation 처리량, 쓰기 경쟁, backup/restore 회복은 별도 실측이 필요하다.

**DB 관찰**

- memo/note nullability와 값 비교 개수, 두 열 불일치 수.
- V5/V6 version 및 성공 상태, 적용 전후 column 목록.
- API memo 입력/응답과 서버별 배포 버전.

**합격 기준**

- V5 후 51개 값이 모두 복사되고 D2/D3 일치가 확인된다.
- read 전환 후 모든 앱이 note를 읽으며 memo wire field를 보존한다.
- 모든 구버전 writer 제거 전에는 V6 drop하지 않는다. 최종 D5에 memo 열 없음과 API 회귀 응답을 기록한다.

**기존 과제와 중복·연결**

S9-1은 Flyway baseline, S9-3은 nullable-backfill-not-null 순서를 다룬다. J2는 expand-contract 원리를 설명한다.

**우선순위**

high
