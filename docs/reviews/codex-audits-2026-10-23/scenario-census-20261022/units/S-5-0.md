## 판정

댓글 목록 기본 응답·접근 차단·빈 결과 검증이 코드와 JUnit에서 일치한다. 조회 수의 확장성은 보장 주장 없이 R1 리뷰 조건으로 남아 있다.

## 목표·선수 지식·학습자 작업

게시글 댓글을 독립 DB 행에서 응답 DTO로 변환하고, 글 접근 정책을 통과한 뒤 최상위 댓글만 시간순으로 반환한다. 선수는 2-1 조회·2-3 공개 정책·1-2 DTO이며 다음은 5-1 댓글 추가다.

Controller, read-only QueryService, Repository query, response DTO를 작성한다. 댓글이 없는 글은 빈 배열, 없는/볼 수 없는 글은 404를 만들고 작성자·삭제 placeholder를 응답 계약에 맞춘다.

## 요구·구현·검사 대조

### 1. 게시글을 조회해 PostAccessPolicy로 접근을 확인하고 최상위 미삭제 댓글을 DTO로 반환한다.

구현 대조: 구현됨: read-only Service가 canView를 검사하고 Repository가 살아 있는 최상위 댓글을 응답 DTO로 바꿔 반환한다.

검사 대조: JUnit은 id [1,3], 작성자 nickname, deleted=false, 빈 목록, 없는/접근불가 글의 404를 확인한다. checker C1-C4도 같은 경로를 검사한다.

## 쿼리·DB 깊이와 다음 단계

조회 경로는 post policy 확인 후 top-level comment repository query로 분리된다. DTO로 작성자와 deleted marker를 노출한다. 작성자 fetch/query count는 별도 관찰 대상이나 현재 JUnit은 결과값만 검사한다.

- 현재 난이도: 기초-중급
- 판정 이유: 연관 객체를 응답에 직접 내보내지 않고 접근 정책·빈 결과·상태 placeholder를 적용한다.
- 다음 단계: - 2-3 글 visibility policy
  - 5-1 comment insert와 count 동기화
  - 5-2 parent self-reference
  - 5-3 tree와 soft delete
