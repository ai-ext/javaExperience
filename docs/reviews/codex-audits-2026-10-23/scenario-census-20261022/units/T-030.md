## 판정

행동 보존, transaction/lazy-loading 경계, 회귀 테스트, Service 응답 DTO 결합의 대가가 적혀 있다. 대표 field 비교 범위를 JSON fixture/구조 검사로 강화하면 완료 판정이 더 명확해진다.

## 목표·선수 지식·학습자 작업

Post/Comment entity-to-response mapping을 controller에서 service 또는 response factory로 옮기되 HTTP JSON/status/Location과 권한, transaction 내 lazy loading 동작을 보존하는 리팩터다.

공유 DTO mapper를 만들고 create/detail/update/comment Service가 entity 대신 response DTO를 돌려주게 한다. Controller에서 entity import/access와 연관 eager-loading을 위한 인위적 getter 호출을 제거한다. 기존 endpoint 응답 및 test suite를 보존한다.

## 요구·구현·검사 대조

### 1. Create/detail/update/comment/403/404/delete 응답의 fields/status/Location은 그대로다. lazy association은 transaction 범위 안에서 매핑하고 controller는 Post/Comment entity를 참조하지 않는다. 서비스/컨트롤러에서 임의 getter warm-up 코드는 모두 없앤다.

구현 대조: 정답 snapshot이 제공되지 않은 독립 과제다. 구현 상태를 미제공 정답 부재만으로 결함 처리하지 않는다.

검사 대조: C1-C6은 응답과 저장 결과, T1은 `./gradlew test` 전체 회귀를 필수로 한다. R1 grep과 controller entity import 부재, R2 단일 conversion location/unused DTO 제거, R3 구조와 동작 변경 분리를 검토한다.

공백 또는 한계: 대표 endpoint 결과는 보지만 모든 optional/null field, serialization shape, Problem Details error envelope를 snapshot 비교하는 항목은 없다. 서비스가 HTTP response 모양을 알게 되는 coupling은 R3에서 tradeoff로 요구된다.
