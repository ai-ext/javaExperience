## 판정

저장 전 단계라는 핵심 경계를 강하게 시각화하고, JSON 변환 실패와 CORS 차단을 별도로 보여 준다. 실제 snapshot은 작은 Controller와 전용 record로 계약과 맞는다. success만으로 payload 전체 mapping은 드러나지 않지만 R2 코드리뷰가 이를 보완한다.

## 목표·선수 지식·학습자 작업

DB에 쓰기 전 API 입구를 만들고 JSON→요청 record→Controller→HTTP 응답을 연결한다. 응답 success는 요청 수신 표시일 뿐 저장 성공이 아님을 설명한다. Java record와 0장 요청 바인딩을 선수로 둔다.

게시판 작성용 PostCreateRequest와 PostController를 직접 구현한다. 정상 JSON을 받고 제목을 SLF4J로 기록해 success를 반환한다. Service/Repository/DB 저장, 검증은 이 단계에서 구현하지 않는다. 브라우저 실행에는 기존 또는 새 CORS 설정이 필요하다.
