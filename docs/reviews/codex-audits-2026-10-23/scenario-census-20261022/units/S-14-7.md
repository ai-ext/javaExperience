## 목표·선수 지식·학습자 작업

2-2 목록의 공개 가능 조건을 공유해 월별 글 수와 월 단위 목록 건수를 일치시킨다. 연·월 집계와 달 목록의 반개구간, 경로/페이지 입력 검증, 서울 시각 경계, 인덱스 범위 조회를 직접 구현·비교한다. 선수는 2-2/8-4 조건 조립, W20 시간대, R05/J1 인덱스·EXPLAIN이며 다음은 14-8 공유 폴더다.

기존 board/published_at 복합 인덱스를 이용해 공개 글을 연·월별 집계하고, 접근 가능 글 목록을 해당 월 [첫날 00:00, 다음 달 첫날 00:00) 범위로 페이징한다. archive count와 월별 totalElements가 viewer마다 같은지 확인하고, 함수 기반 날짜 조건과 범위 조건의 EXPLAIN을 비교한다.

## 확장 개발 명세

### 월 경계·viewer 일치 및 인덱스 계획 자동 검증

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

달력/시간대 끝값과 집계/페이지 간 조건 차이를 실제 MySQL에서 고정하고 계획의 전제와 한계를 기록한다.

**시작 상태**

테스트 전용 MySQL에 게시판, 공개·팔로워 공개·숨김·삭제 글을 준비한다. 게시 시각은 2026-09-01 00:00:00, 2026-09-30 23:59:59.999999, 2026-10-01 00:00:00, 2000-01-01 00:00, 2101-01-01 00:00 값을 포함한다.

**학습자가 할 일**

- 비로그인과 팔로워 로그인 각각 archive count와 month totalElements를 비교
- 각 경계 시각 글의 포함/제외를 검증
- year/month/page/size의 0, 최대+1, 공백, 비숫자, int 초과 경로/쿼리를 MockMvc로 검증
- 같은 데이터에 range 조건과 MONTH/YEAR 함수 조건을 EXPLAIN ANALYZE로 비교하고 MySQL 버전·행 수·통계를 기록

**정상 사례**

- 9월 1일 포함, 9월 30일 마지막 microsecond 포함, 10월 1일 제외.
- viewer마다 archive의 9월 count와 9월 첫 페이지 응답 totalElements가 같다.

**실패·경계 사례**

- 팔로워 공개 글이 비로그인 집계에 들어오지 않고 팔로워에게만 포함된다.
- 잘못된 year/month는 400이며 DateTimeException/500이 발생하지 않는다.

**동시성·성능**

별도 disposable 데이터에서 동일 스키마의 1만/100만 행을 비교한다. 인덱스 계획과 rows examined를 기록하되 단일 실행시간으로 일반화하지 않는다.
