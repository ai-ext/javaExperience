## 판정

JPQL과 MyBatis는 같은 LEFT JOIN ON filters와 COUNT(p.id)로 구현되어 있다. C4는 전체 배열 동등성만 검사하고, seed에는 빈 board가 없어 zero case를 증명하지 않는다.

## 목표·선수 지식·학습자 작업

LEFT JOIN의 ON에 공개 조건을 두어 빈 게시판 count=0 행을 보존한다. 공통 준비 및 앞 단계 L12/L13/L14의 누적 SQL 실습을 선수로 한다.

원문은 단계별 코드 제공/미완성 구간을 구별해 적고, 학습자는 해당 쿼리 요구와 경계 케이스를 실행 결과로 확인한다. LEFT JOIN의 ON에 공개 조건을 두어 빈 게시판 count=0 행을 보존한다.

## 요구·구현·검사 대조

### 1. 모든 board를 반환하고 공개·PUBLISHED·미숨김·미삭제 게시글만 세며 count=0 board도 포함한다. 조건은 LEFT JOIN ON에 두고 COUNT(p.id)를 사용하며 COUNT(*)는 쓰지 않는다.

구현 대조: JPQL/MyBatis boardCounts는 게시글의 visibility/status/deleted 조건을 LEFT JOIN ON에 두고 board별 GROUP BY와 COUNT(p.id)를 수행해 글 없는 board도 남기도록 구현한다.

검사 대조: E/F는 두 엔진 boardCounts body를 비교한다. 기본 practice seed의 공개·게시·미삭제 수는 board1=5, board2=50, board3=27, board4=29로 모두 0보다 크다. P 요청 뒤 C4는 두 body 동등성만 검사한다.

공백 또는 한계: 기본 seed에 빈 board가 없으므로 empty-group 이름/합격 조건을 검사하지 않는다. 격리 test fixture에 빈 board를 추가하거나 0 count 기대값을 명시해야 한다.

## 확장 개발 명세

### 빈 게시판의 0 count와 실제 게시판 count 확인

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

LEFT JOIN ON 공개 조건 및 COUNT(p.id)가 게시판 행을 보존해 글 없는 게시판도 0을 내는지 검증한다.

**시작 상태**

기본 practice seed의 공개·발행·미삭제 글은 게시판1=5,2(dev)=50,3(qna)=27,4(free)=29여서 빈 게시판이 없다. Auto P 생성 후 dev count가 1 증가한다.

**학습자가 할 일**

default seed의 JPA/MyBatis board-counts 전체 배열을 비교한다. 별도 rollback 가능한 test fixture에 글이 없는 board를 만들어 두 방식의 count=0을 확인한다.

**정상 사례**

- LEFT JOIN ON 공개 조건 및 COUNT(p.id)가 게시판 행을 보존해 글 없는 게시판도 0을 내는지 검증한다.

**실패·경계 사례**

공개 글 filter를 WHERE에 두면 zero board 행이 사라질 수 있다. COUNT(*)는 LEFT JOIN null row를 1로 세므로 COUNT(p.id)와 비교한다.

**동시성·성능**

이 단위는 쿼리 정확성과 응답 계약을 확인한다. 실행 계획과 시간 측정은 DB-08~14에 연결한다.

**DB 관찰**

board 목록, board_id와 게시글 status/visibility/deleted 상태, QueryDSL의 (slug,count) 결과 배열을 기록한다.

**합격 기준**

seed baseline `[5,50,27,29]`; P 이후 dev=51. Empty-board fixture는 게시판 행을 유지한 `count=0`; JPA/MyBatis 전체 결과 배열이 동일.

**기존 과제와 중복·연결**

S-8-4/C12의 없는 게시판 검색은 게시글을 반환하지 않는 동작이다. Q12는 count=0인 게시판까지 모두 집계한다. 두 요구를 혼동하지 않는다.

**우선순위**

medium
