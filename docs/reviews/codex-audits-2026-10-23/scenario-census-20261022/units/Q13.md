## 판정

JPQL/MyBatis 코드의 exclusive 종료 조건은 일치한다. 기존 자동 요청은 엔진 비교만 하므로 정적 정확성은 확인했으나 날짜 경계 테스트를 추가해야 해당 학습 계약을 자동으로 증명한다.

## 목표·선수 지식·학습자 작업

제목 OR 본문을 필수 조건 AND 괄호로 묶고 기간 [from,to) 경계를 확인한다. 공통 준비 및 앞 단계 L12/L13/L14의 누적 SQL 실습을 선수로 한다.

원문은 단계별 코드 제공/미완성 구간을 구별해 적고, 학습자는 해당 쿼리 요구와 경계 케이스를 실행 결과로 확인한다. 제목 OR 본문을 필수 조건 AND 괄호로 묶고 기간 [from,to) 경계를 확인한다.

## 요구·구현·검사 대조

### 1. practice 시계 `2026-10-05T00:00:00`에서 공개 글 검색은 keyword를 title OR content에 적용하고 `created_at >= from AND created_at < to`로 기간을 반열린 구간 처리한다.

구현 대조: SearchFilter는 from/to를 LocalDateTime으로 파싱하고 from>=to, 잘못된 정렬, page/size 상한을 검증한다. JPQL은 공개 조건 AND (keyword 없음 OR title LIKE OR content LIKE) AND createdAt>=from AND createdAt<to를 적용한다. MyBatis XML도 같은 괄호와 half-open 기간을 사용한다.

검사 대조: Q13 자동 G/H 요청은 keyword=JPA, from=2026-10-01T00:00:00, to=2026-11-01T00:00:00이며 items 배열 동등성만 확인한다. README는 fixed Clock의 P 생성 시각 2026-10-05T00:00:00이 [00:00:00,00:00:01)에 포함되고 to=00:00:00 경계에선 제외되는 조건을 말하지만 자동 검사는 이 경계를 호출하지 않는다.

공백 또는 한계: 자동 동등성 요청은 새 P의 ID가 양쪽에 존재하는지, upper-bound 배타성, from>=to/잘못된 날짜 실패를 각각 확인하지 않는다. 경계 계약은 문서에 있지만 실행 검사는 별도다.

## 확장 개발 명세

### Q13의 고정시각 반열린 기간 경계 검사

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

원문이 고정 시각에 만들어진 글의 `from=now,to=now+1s` 포함과 `to=now` 제외를 직접 요구하지만 자동 check에는 해당 요청이 없다.

**시작 상태**

practice profile의 Clock `2026-10-05T00:00:00`; C request P가 `tok-p05`로 만드는 공개 post `[쿼리연습] JPA 연결`, content `본문 JPA 검색`.

**학습자가 할 일**

- P.body.id를 유지해 from/to 조건을 바꿔 JPA와 MyBatis에서 각각 조회한다.
- 제목만 `JPA`인 공개 fixture와 본문만 `JPA`인 공개 fixture가 결과에 포함되는지 확인한다.
- P 생성 시각과 같은 `to` 상한, 1초 뒤 상한, 동일 from/to, from>to를 각각 실행한다.

**정상 사례**

- `from=2026-10-05T00:00:00&to=2026-10-05T00:00:01`: P 포함.
- `from=2026-10-05T00:00:00&to=2026-10-05T00:00:00`: P 제외.
- G/H `from=2026-10-01T00:00:00&to=2026-11-01T00:00:00`의 JPA/MyBatis items 일치.

**실패·경계 사례**

- `from=2026-10-06T00:00:00&to=2026-10-05T00:00:00`와 동등한 from/to는 400.
- 본문만 일치하는 행이 없어지는 OR 괄호 누락 반례.
- HIDDEN 상태로 바뀐 같은 게시글이 검색 결과에 남는 공개 조건 누락 반례.

**동시성·성능**

기간 의미 검증 단계이므로 동시성/실행 시간 불요.

**DB 관찰**

- P의 실제 created_at을 조회해 경계에 놓였는지 확인한다.
- 두 엔진의 ID 배열과 total을 비교하고 to equality 케이스의 포함 여부를 확인한다.

**합격 기준**

- P가 from=now,to=now+1초에는 포함되고 to=now에는 제외.
- JPA/MyBatis 각 배열/total 동일.
- 동일/역전 날짜 범위는 status 400.

**기존 과제와 중복·연결**

Q16은 AND/OR grouping, Q14는 sort/count를 담당한다. Q13은 temporal boundary를 집중한다.
