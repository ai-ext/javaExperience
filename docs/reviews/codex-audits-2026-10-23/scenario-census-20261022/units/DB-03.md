## 확장 개발 명세

### 필수·선택 관계의 상세 row 재현

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

게시판·작성자 필수 FK는 JOIN, viewer likes/bookmarks optional은 LEFT JOIN이며 선택 row 부재가 post를 제거하면 안 된다.

**시작 상태**

practice seed post145, board2/dev, author6/밤샘개발자, viewer7; query-only learning.

**학습자가 할 일**

- post ID/title/dev/author/likedByMe/bookmarkedByMe를 확인하고 결과가 정확히 한 행인지 센다.
- viewer가 post_like 또는 bookmark 행을 갖지 않을 때 그 LEFT JOIN을 일반 JOIN으로 바꿔 게시글 행이 사라지는지 비교한다.
- viewerId 조건을 ON에서 WHERE로 옮기고 NULL 확장 행이 제거되는 이유를 설명한다.
- 조회 뒤 DTO를 만들기 전에 M1 service가 PostAccessPolicy를 적용해야 하는 이유를 설명한다.

**정상 사례**

- viewer 관계 행이 없어도 원 게시글 한 행은 남고 두 flag는 false다.

**실패·경계 사례**

- bookmark 내부 JOIN은 viewer7 bookmark가 없는 post145를 제거한다.
- LEFT JOIN 뒤 WHERE bm.member_id=7은 NULL 행을 걸러 내부 JOIN처럼 동작한다.
- visibility policy 전에 SQL 값을 응답하면 금지된 게시글을 노출할 수 있다.

**동시성·성능**

쓰기/동시성 측정은 하지 않는다. JOIN cardinality와 접근 정책 적용 순서를 본다.

**DB 관찰**

- 선택된 FK 행 및 viewer relation 행과 Boolean flags.

**합격 기준**

- 선택적 관계가 없어도 원 게시글 행을 보존한다.
- SQL JOIN 자체가 요청 권한을 부여하지 않는다고 설명한다.

**기존 과제와 중복·연결**

M1은 상세 API/PostAccessPolicy, DB-04는 일대다 관계의 결과 행 수를 다룬다.

**우선순위**

medium
