## 확장 개발 명세

### 예상 밖 500의 응답/로그 분리 검사

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

일반 Exception이 발생해도 응답 envelope에는 내부 세부정보가 빠지고 서버 로그에는 stacktrace가 남는지 확인한다.

**시작 상태**

격리 HTTP test에서만 고의 500 exception을 유발한다.

**학습자가 할 일**

- 응답 status/code/errors/data를 검사한다.
- 응답 본문에 예외 클래스/메시지가 없는지 확인하고 test log에서 원인이 남는지 본다.

**정상 사례**

- 원문 checker가 지정한 정상 경계값과 정상 row/response를 유지한다.

**실패·경계 사례**

- 문서가 요구한 오류 코드와 오류 전후 DB state를 단언한다.

**동시성·성능**

동시성은 해당 실험에서만 barrier/별도 transaction으로 확인한다. 측정하지 않은 성능 개선은 주장하지 않는다.

**DB 관찰**

- 독립 disposable DB에서 핵심 relation/row/count의 전후값을 확인한다.

**합격 기준**

사용자 본문에 내부 예외 정보가 없고 서버 로그에 원인이 남는다.

**기존 과제와 중복·연결**

현재 단위의 원문 C/D/R 계약만 자동 검증한다. 기존 follow-up 단계의 책임을 이 단계에 복사하지 않는다.

**우선순위**

medium
