## 판정

코드는 case-insensitive 제목 검색과 wildcard escape를 제공한다. 자동 검사는 items array만 확인하므로 매칭 ID와 특수문자 결과 확인이 필요하다.

## 목표·선수 지식·학습자 작업

제목 keyword의 대소문자·빈값·LIKE wildcard escaping과 parameter binding을 확인한다. 공통 준비 및 앞 단계 L12/L13/L14의 누적 SQL 실습을 선수로 한다.

원문은 단계별 코드 제공/미완성 구간을 구별해 적고, 학습자는 해당 쿼리 요구와 경계 케이스를 실행 결과로 확인한다. 제목 keyword의 대소문자·빈값·LIKE wildcard escaping과 parameter binding을 확인한다.

## 요구·구현·검사 대조

### 1. keyword=JPA를 제목에 대소문자 무시로 검색하고 `%`, `_`, `!`는 wildcard가 아닌 문자로 처리한다.

구현 대조: JPA는 TitleContainingIgnoreCase, MyBatis는 LOWER(title) LIKE와 ESCAPE !를 사용한다. QueryInputs.pattern은 LIKE wildcard를 escape한다. L12는 board/keyword/author 중 한 필터만 허용한다.

검사 대조: E는 keyword=JPA로 요청한다. C5는 status=200과 items 배열 type만 확인하며 동적 P 제목 매칭이나 %/_ 문자 literal 처리를 assertion하지 않는다.

공백 또는 한계: case-insensitive 검색식과 wildcard escape 구현은 있으나 P의 예상 ID/title 결과와 wildcard 반례가 자동 검사되지 않는다.

## 확장 개발 명세

### Q05 구체 데이터 결과와 경계 검사

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

keyword=JPA를 제목에 대소문자 무시로 검색하고 `%`, `_`, `!`는 wildcard가 아닌 문자로 처리한다.

**시작 상태**

L12 practice profile. Request P creates dev/PUBLISHED/PUBLIC post `[쿼리연습] JPA 연결` with content `본문 JPA 검색` by member5. Use dynamic id/author from P response.

**학습자가 할 일**

- E keyword=JPA 요청에서 P의 JPA 제목 매칭 여부와 반환 ID를 기록한다.
- jpa/JPA 대소문자 변형이 같은 검색 결과를 내는지 확인한다.
- %, _, !가 포함된 제목/검색어를 격리 행으로 만들어 wildcard escape 결과를 확인한다.
- Hibernate/MyBatis SQL과 ESCAPE 처리를 함께 확인한다.

**정상 사례**

- keyword=JPA는 대소문자를 무시해 제목을 찾고 %, _, !는 escape 규칙상 literal로 매칭된다.

**실패·경계 사례**

- E 요청의 C5는 200과 items array type만 확인하므로 P 제목 매칭이나 wildcard literal 결과를 검증하지 않는다.

**동시성·성능**

L12 query 정확성만 다룬다. plan/성능 측정은 DB-08~14에서 수행한다.

**DB 관찰**

- 실제 응답 ID/total/status와 실행 SQL을 기록한다. items type만 확인하지 않는다.
- 동적 P로 seed count가 달라질 수 있으므로 reset하거나 직접 SQL과 대조한다.

**합격 기준**

- P의 제목 매칭 및 대소문자 변형 ID 배열 일치.
- 격리 wildcard 반례가 문자 그대로 검색되고 예상 밖 다수 행으로 확장되지 않는다.

**기존 과제와 중복·연결**
