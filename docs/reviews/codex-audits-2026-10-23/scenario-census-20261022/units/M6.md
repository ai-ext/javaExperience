### 1. GET /api/posts/popular?days=7은 fixed now 2026-10-05, 기간 [2026-09-28,2026-10-05), 점수 기간 좋아요×3+삭제되지 않은 기간 댓글 수로 계산한다. 익명에게 보이는 게시·미삭제 글 중 점수>0을 published_at DESC 동률 순으로 반환한다.

구현 대조: 같은 인기글 endpoint는 S-8-2 snapshot에 구현되어 있다. injected fixed Clock, 좋아요/댓글 사전 집계, 점수 계산, DB 내 필터·정렬·limit이 있으며 누적 post.like_count에 의존하지 않는다.

검사 대조: S-8-2 H1은 7일 첫 5 ID/점수, H2는 30일 결과, H3는 16개 제한, H4~H6은 days31·빈 days·빈 limit의 400을 확인한다. MISSION 별도 테스트가 아니라 같은 기능을 다룬 시나리오 검사다.

## 확장 개발 명세

### S-8-2 응답을 M6의 SQL-first 학습에 연결

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

M6는 repository 표현을 고르기 전에 점수 SQL을 직접 유도해야 한다. S-8-2에 같은 endpoint, 구현, 검사 기준이 있다.

**시작 상태**

practice 데이터와 고정 시각 2026-10-05 00:00 Asia/Seoul을 사용하고 H1의 7일 조회부터 확인한다.

**학습자가 할 일**

- from=2026-09-28, to=2026-10-05 조건의 읽기 전용 SQL을 작성하고 좋아요/댓글을 게시물별로 각각 집계한다.
- 첫 5개 결과를 고정 합격값과 비교한다.
- 누적 post.like_count가 왜 잘못됐는지, 원시 좋아요와 댓글을 JOIN하면 왜 fanout이 생기는지 설명한다.
- SQL을 지원 repository 방식 하나로 옮기고 from/to/limit parameter binding 위치를 기록한다.

**정상 사례**

- 동률 점수는 published_at DESC 순으로 정렬하며 게시글 145가 143보다 먼저 온다.

**실패·경계 사례**

- 누적 좋아요 수가 22인 게시글 18/55/103은 7일 인기 순위와 같다고 볼 수 없다.

**동시성·성능**

벤치마크는 요구하지 않는다. M6 합격은 기간별 집계와 순위 정확성이다.

**DB 관찰**

- 게시글별 기간 안 좋아요/댓글 행 수, 점수 구성요소, 최종 정렬 순서.

**합격 기준**

- 선택한 query route가 SQL 결과와 같은 첫 페이지 및 DB 필터·정렬·limit을 반환한다.

**기존 과제와 중복·연결**

S-8-2가 같은 endpoint와 코드/검사를 담당하고 M6는 SQL-first 학습 요구를 추가로 명시한다.

**우선순위**

low
