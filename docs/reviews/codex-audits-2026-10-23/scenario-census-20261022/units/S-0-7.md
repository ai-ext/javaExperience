## 판정

record 방식과 Lombok DTO를 같은 HTTP 계약으로 비교하면서 생성 코드와 validation 책임을 설명한다. 정상/주요 validation 케이스는 checker와 자동 테스트가 확인하지만, 문서에 계약으로 쓴 비숫자 age 400은 두 검사 층위 모두 빠져 있다.

## 목표·선수 지식·학습자 작업

0-4의 record API 계약을 유지하면서 Lombok 요청·응답 클래스가 컴파일 시 생성하는 getter/constructor와 Bean Validation을 확인한다. 0-4 DTO와 JSON 이해가 선수이며 이 연습을 모든 DTO에 Lombok을 적용하라는 권고로 해석하지 않는다.

Gradle에 Lombok compileOnly와 annotationProcessor를 추가하고 record DTO를 static Lombok 요청/응답 클래스로 바꾼다. @Valid를 적용하고 빌드·javap·HTTP 요청으로 generated code 및 결과를 확인한다.
