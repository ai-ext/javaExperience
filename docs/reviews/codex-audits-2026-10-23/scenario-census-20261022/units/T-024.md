## 목표·선수 지식·학습자 작업

동기 AFTER_COMMIT listener는 요청 connection을 보유한 상태에서 REQUIRES_NEW가 추가 DB connection을 요청할 수 있다. connection pool 크기만큼 동시 요청이 겹치면 모두 두 번째 connection을 기다린다. 선수는 Spring propagation, physical connection pool, AFTER_COMMIT callback이다.

40개 동시 like를 두 글에 수행하며 pool 크기와 요청 worker를 고정하고 thread dump/Hikari metrics로 대기를 재현한다. listener를 bounded async executor 또는 transaction/outbox 대안으로 옮기고 notification 결과·shutdown·queue saturation 정책을 선택한다.
