## 목표·선수 지식·학습자 작업

2-3의 기준 글·후보 글 공개 판정을 적용하면서 태그 교집합 수로 추천 순위를 만든다. 원문은 post_tag PK와 ix_post_tag_tag 재사용, API·입력 검증, D1 SQL 결과, D2 EXPLAIN을 직접 수행하게 한다. 선수는 2-3 접근 정책·R04 JOIN·R05 인덱스·J1 실행계획·S10 projection이며 다음은 14-7 월별 아카이브다.

post_tag를 기준 글(base)과 후보(other)로 자기 JOIN하고 기준 글 자신을 제외해 겹친 태그 수를 집계한다. 전체 후보를 순위화한 뒤 후보 글을 일괄 조회하고 PostAccessPolicy로 사용자별 공개/팔로워/차단 규칙을 적용해 size만큼 자른다. 기준 글의 404, 태그 없음, size/id 오류와 SQL/EXPLAIN 관찰이 요구된다.

## 확장 개발 명세

### 접근 불가 상위 후보와 대량 키셋 탐색 비교

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

현재 전체 후보 로드가 정확성은 보존하지만 데이터가 커지면 메모리·조회 비용이 커질 수 있다. 접근 필터 뒤 결과를 자르며 순위가 바뀌지 않는 전략을 직접 비교한다.

**시작 상태**

태그가 1개 겹치는 공개 기준 글 A에 대해 상위 공유 태그 점수를 가진 비공개/차단 후보 12개와 공개 후보 B,C를 만들고, 동일 태그를 가진 후보 수를 1천/1만으로 늘린 별도 disposable DB를 준비한다.

**학습자가 할 일**

- 현재 전체 후보 방식으로 API 결과와 EXPLAIN ANALYZE/응답 후보 수를 기록
- 후보 조회를 (shared DESC, published_at DESC, id DESC) 커서로 이어가는 페이지 방식 설계
- 접근 불가 후보를 건너뛰며 size개가 모일 때까지 페이지를 반복하고, 한 페이지 내 전체가 불가할 때 계속 읽는 테스트 작성
- SQL에서 접근 정책을 재구현하지 않는지 PostAccessPolicy와 결과를 비교

**정상 사례**

- 상위 12개가 접근 불가여도 결과는 다음 공개 B,C이며 순위는 기존 전체 후보 정렬과 같다.
- 후보가 적을 때 기존 응답과 완전히 일치한다.

**실패·경계 사례**

- 페이지 경계에서 shared/published_at/id 동점인 후보가 중복/누락되지 않는다.
- 후보가 모두 비공개면 빈 결과를 반환하며 무한 루프 없이 끝난다.

**동시성·성능**

동일 데이터와 DB 통계에서 기존 전체 로드와 키셋 반복의 후보 행 수, DB 실행시간, 애플리케이션 메모리 상한을 측정한다. 결과를 추정치와 실측치로 나눈다.

**DB 관찰**
