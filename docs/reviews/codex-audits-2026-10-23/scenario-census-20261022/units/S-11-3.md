## 목표·선수 지식·학습자 작업

GET /api/posts/{id}에서 이미 있던 조회수 필드를 올바른 업무 단위(글×회원×업무일)로 정의한다. 로그인 비작성자의 첫 조회만 오늘 한 번 올리고, 비로그인은 매번, 작성자는 제외한다. 선행은 인증 회원 정보, PostAccessPolicy 404 규칙, 4-2 원자적 카운터 UPDATE, 8-2 Clock/시간대다.

직접 설계: post_view PK/FK/DATE, `INSERT IGNORE` 결과로 신규 열람 여부 판단, 상세 조회 트랜잭션/잠금 순서, DB 원자적 +1 및 현재 카운터 재조회, Clock과 목록·상세 응답 연결. migration과 JPQL/native SQL을 직접 작성한다.

## 쿼리·DB 깊이와 다음 단계

- content: post_view는 방문자 이력의 집계 원천이 아니라 하루 dedupe marker다. 카운터는 post에 비정규화 저장되고 atomic increment로 바뀐다. 날짜 결정은 injected Clock으로 앱에서 만들고 DB에는 DATE로 저장한다. 상세 조회 트랜잭션은 post row → post_view unique insert → 카운터 update → current counter locking read 순서를 가진다.
- current_scope: C1-C8과 D1-D3, R1-R5는 actor별 증가, 당일 중복, 작성자/anonymous 정책, 목록 반영, 같은 회원 동시 요청, 원자 SQL, Clock까지 명시. 구현도 쿼리/잠금/엔티티 삭제가 계약에 대응한다.
- missing_scope: D3의 information_schema 쿼리는 index_name을 묶지 않아 복합 키의 실제 column set/order를 엄격히 검증하지 않는다. 업무일 자정 경계는 Clock 설계는 있으나 고정 Clock 검사가 없다.
- existing_connections: T-017 카운터 누락·동시성 디버깅, L-H1 원자적 counter update, S-15-1/2 기간 집계·snapshot은 이어지는 별도 운영 주제다. 조회수 첫 열람 dedupe를 중복 과제로 추가하지 않는다.

- 현재 난이도: 고급 실전 동시성·기간 경계
- 판정 이유: 회원별 날짜 uniqueness와 비로그인 정책을 분리하고 PK가 멱등성 판단을 맡도록 한다. `INSERT IGNORE`, post row 잠금, atomic UPDATE, 최신 카운터 locking read, Clock을 함께 사용해 lost update와 snapshot stale read를 피하도록 선택 근거가 들어 있다.

## 확장 개발 명세

### 고정 Clock으로 일 경계와 DB unique key 검증

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

일 단위 규칙은 Clock 주입 코드와 D3 존재로 끝나지 않고 경계 초와 정확한 unique index 구성까지 확인해야 한다.

**시작 상태**

테스트 Clock을 Asia/Seoul로 설정한다. 글 하나와 작성자 회원 2, 비작성 회원 3을 준비하고 view_count=0 및 post_view 행 0개로 만든다.

**학습자가 할 일**

- Clock을 2026-10-22 23:59:59 Asia/Seoul에 고정하고 회원 3이 GET /api/posts/{id}를 보낸다.
- Clock을 2026-10-23 00:00:00으로 바꿔 같은 회원이 다시 GET한다.
- information_schema 결과를 `table_name,index_name,non_unique,seq_in_index,column_name`으로 조회해 단일 PK/UNIQUE index를 확인한다.

**정상 사례**

- 첫 GET은 1, 같은 날 두 번째는 1, 자정 이후 첫 GET은 2를 반환한다.
- post_view에는 같은 회원·post로 날짜 2026-10-22/23 각각 한 행이 생긴다.

**실패·경계 사례**

- 작성자가 두 날짜에 각각 조회해도 조회수/행은 늘지 않는다.
- 잘못 설정한 Clock zone 또는 DB CURDATE zone으로 기대일이 어긋나면 어느 계층의 날짜가 기록됐는지 비교한다.

**동시성·성능**

자정 경계 직전/직후를 순차 고정 Clock으로 먼저 확인하고, 별도 두 회원의 동시 GET으로 최종 view_count가 요청별 dedupe 합과 일치하는지 검증한다.

**DB 관찰**

post_view의 composite PK/UNIQUE 구성, viewed_on별 row 수, 최종 post.view_count를 SELECT로 비교한다.

**합격 기준**

동일 날짜 같은 회원 1행·1증가, 다른 날짜는 새 1행·1증가; 작성자 0행/0증가; 조회된 composite index가 (post_id,member_id,viewed_on) 한 index; 모두 실패 없이 200.

**기존 과제와 중복·연결**

T-017은 counter lost update 유발 방법을 다루고, 여기서는 회원×날짜 정책과 boundary를 검사한다. S-15-2 주간 snapshot의 날짜 정의와 혼합하지 않는다.

**우선순위**

medium
