## 판정

권한 행렬과 HTTP·DB counter 합격 기준이 구체적이며 잘못된 대상 관계도 구분한다. concurrent duplicate delete/reply lifecycle는 추가 검증 후보이고 답안 미제공은 결함이 아니다.

## 목표·선수 지식·학습자 작업

댓글 삭제 권한을 댓글 작성자·해당 글 작성자·운영자로 확장하며 권한과 삭제 상태를 구분하고 comment_count를 한 번만 감소시킨다. 선수는 comment/post owner 관계, soft-delete, reply 생명주기, moderation role.

DELETE 서비스에서 대상/삭제상태를 먼저 판정하고 허용 주체를 정책으로 모은다. transactional comment soft delete와 게시글 counter 감소를 atomic하게 수행한다. comment owner, post owner, moderator, unrelated user의 API 결과를 구분한다.

## 요구·구현·검사 대조

### 1. 관련 없는 user 403, comment 작성자와 같은 글 작성자 및 운영자는 204, 이미 삭제/없음 404. 다른 글 작성자 권한은 없어야 한다. soft delete는 comment_count를 딱 한 번 줄이고 deleted row를 목록에서 제외한다.

구현 대조: 정답 snapshot은 지정되지 않았다. 이 독립 과제의 요구로 확인했으며 미제공 정답을 구현 결함으로 판정하지 않는다.

검사 대조: C1/C3/C4는 관계별 204/403/404, C2/D1은 실제 comment row count와 denormalized comment_count equality를 검증, C5 목록 미노출, D2 fixture 데이터 정리를 확인한다. R1~R3는 권한 정책 재사용, 상태 선검사, lazy relationship query 관찰.

공백 또는 한계: 요구와 검사 근거를 적었으며 정답 구현 결과는 본 감사 범위에서 미확인이다.
