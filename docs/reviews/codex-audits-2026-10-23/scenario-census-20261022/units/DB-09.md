## 확장 개발 명세

### TREE actual 관측과 SELECT 결과 분리

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

EXPLAIN ANALYZE executes query and reports iterator measures, while ordinary SELECT is needed to record returned ID sequence.

**시작 상태**

DB-10 전용 MySQL 8.4 javaexperience_perf에서 member12 LIMIT11 query를 사용한다. DB-08과 같은 데이터 및 필터여야 한다.

**학습자가 할 일**

- 대상 schema와 읽기 전용 SELECT를 확인한 뒤 EXPLAIN ANALYZE를 실행한다.
- TREE iterator별 estimated/actual rows, loops, actual time을 기록한다.
- 같은 SELECT를 따로 실행해 반환 ID/순서를 기록한다.
- loop당 rows를 누적 작업량과 혼동하지 않는다. 시간 비교 시 cache 상태와 반복 번호도 적는다.

**정상 사례**

- DB-08과 동일한 post_like 11행 SELECT를 사용한다.
- 고정 출력값을 정답으로 삼지 않고 현재 TREE 관찰을 근거로 쓴다.

**실패·경계 사례**

- 비용과 영향이 확인되지 않은 운영 query나 write query에 실행하지 않는다.
- 단일 actual-time 숫자는 API latency나 개선 증거가 아니다.
- iterator actual rows는 loops와 함께 읽고 전체 scan 수로 오해하지 않는다.

**동시성·성능**

SELECT를 실제 실행하므로 DB 자원을 사용한다. 반복 비교는 같은 fixture에서 한다. index 전후는 DB-10에서 다룬다.

**DB 관찰**

- fixture 행 수/data 버전, cache/warm 상태와 반복 번호.
- TREE의 actual rows/loops/time 및 별도 SELECT의 ID 배열.

**합격 기준**

- 실제 TREE에서 actual rows/loops/time을 보존한다.
- estimate와 actual 차이를 설명하고 모든 비교 조건을 같게 유지한다.

**기존 과제와 중복·연결**

DB-08은 estimates, DB-10은 index 전후, DB-11은 visibility 상태를 비교한다.

**우선순위**

medium
