## 요구·구현·검사 대조

### 1. 독립 1:N likes=2,comments=3를 post_id만으로 raw join하면 6 pair rows가 생겨 COUNT(like)=6,COUNT(comment)=6으로 잘못 센다. 별도 group-by post_id CTE/derived count 후 LEFT JOIN, COALESCE 0이 안전한 방법. Actual M6은 period filter를 각 source에 넣고 score=likes*3+nondeleted comments, public/published/not-deleted, tie ordering을 유지한다.

구현 대조: 2x3는 labeled synthetic CTE IDs 41,42 and 71,72,73이며 production/community seed 행 아님. 정확한 6 pair list는 SQL 구조에서 기대되나 확인되지 않은 SQL 실행 결과로 표시하지 말라고 명시한다. Safe example preaggregates each relationship by post_id, uses COALESCE. M6 skeleton has separate period-bounded aggregates and score formula.

검사 대조: test-db05-focused-journey.mjs는 9개 panel, 합성 데이터 6칸, 잘못된 COUNT 6/6과 기대 2/3, 원문 CTE, M6/M9 설명 query/COALESCE 및 자산을 검사한다. MySQL/SQLite에서 SQL 결과를 실행하지 않는다.

공백 또는 한계: 자동 검사는 교육 markup만 확인한다. 안전한 사전 집계 및 기간 점수 SQL은 적절한 DB/fixture에서 직접 실행해야 하며 synthetic ID를 practice 정답으로 보고하면 안 된다.

## 확장 개발 명세

### 합성 2x3 SELECT로 aggregate 오류 재현

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

두 관계 테이블의 raw 행 단위는 결합 뒤 likes/comments pair 단위가 된다.

**시작 상태**

원문의 synthetic CTE만 사용한다. like ID41/42와 comment ID71/72/73은 모두 post_key=synthetic다. 실제 DB table은 변경하지 않는다.

**학습자가 할 일**

- 읽기 전용 CTE를 실행해 모든 (like_id,comment_id) 조합을 출력한다.
- 잘못된 원시 LEFT JOIN count를 실행해 한 synthetic post의 수가 왜 곱해지는지 설명한다.
- 안전한 사전 집계 CTE를 실행해 count를 비교하고 좋아요 0개/댓글 0개에서 COALESCE를 확인한다.
- M6 방식으로 from/to 및 deleted_at IS NULL을 각 관계 집계 안에 따로 적용한다.

**정상 사례**

- 각 관계를 먼저 집계한 뒤 LEFT JOIN하면 좋아요 2, 댓글 3이며 관계가 없으면 COALESCE로 0이다.

**실패·경계 사례**

- COUNT(DISTINCT like.id)는 count를 보정해도 별도 SUM/가중값 중복을 막지 못할 수 있다.
- 집계한 likes와 원시 comments를 결합하면 likes 값이 다시 반복된다.
- 기간 조건을 post에만 적용하면 event 행 기간을 제한하지 못한다. 각 aggregate마다 시간 조건이 필요하다.

**동시성·성능**

동시성/benchmark 주장은 없다. query 모양과 합성 행 수만 확인한다. M6 endpoint 결과는 S-8-2/M6에서 다루며 synthetic 값과 다르다.

**DB 관찰**

- CTE 실행 여부와 조합 행 수.
- 원시/안전 결과 행, count 및 관계 없는 0 결과.

**합격 기준**

- 원시 JOIN count는 6/6, 안전 사전 집계는 2/3이다.
- 합성 ID를 실제 DB 행으로 보고하지 않는다.

**기존 과제와 중복·연결**

M6/S-8-2 기간 순위, M9-1 회원 집계, M9-5 tag 집계와 연결한다. DB-05는 fanout 원리이지 endpoint 결과가 아니다.

**우선순위**

medium
