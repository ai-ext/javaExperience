## 판정

integration test는 매 실행 새 post를 생성해 응답 ID를 다음 요청에 전달하고 committed like/comment count를 다시 읽는다. @Transactional이 commit 관찰을 가리지 않는다고 명시한다. test profile의 실제 실행 결과는 corpus test run evidence와 분리해 기록한다.

## 목표·선수 지식·학습자 작업

실제 disposable MySQL과 여러 HTTP 요청으로 CRUD 흐름과 seed 상태를 확인한다. Test에 @Transactional을 둘 때 commit 뒤 동작이나 동시성을 가릴 수 있는 함정을 포함한다.

7단계 end-to-end 요청에서 생성 id를 다음 요청에 이어 전달하고 response/DB를 단언한다. Service/Repository mock 금지, cleanup/반복 실행 독립성 확인.

## 요구·구현·검사 대조

### 1. 통합테스트는 real Testcontainers MySQL에서 실제 요청 경로를 실행하고 생성 id를 다음 요청에 전달하며, class @Transactional이 commit 이후 동작/동시성을 숨길 수 있음을 다룬다.

구현 대조: 실제 auth token·DB·Service/Repository 경로를 순서대로 실행하고 각 단계 status/body를 assert한다.

검사 대조: 첫 테스트는 create에서 응답 id를 꺼내 detail→다른 사용자 like→comment→detail count→owner soft delete→detail/like 404까지 7단계를 잇는다. 두 번째는 seed id 목록과 total=13을 확인한다.

공백 또는 한계: 첫 flow는 생성된 ID를 사용해 다른 테스트의 생성 row에 기대지 않는다. 요청 흐름과 응답 count를 확인하지만 독립 실행/재실행 결과는 별도 실행 로그로 확인해야 한다.
