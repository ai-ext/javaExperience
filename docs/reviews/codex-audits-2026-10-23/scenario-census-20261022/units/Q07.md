## 확장 개발 명세

### Q07 구체 데이터 결과와 경계 검사

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

boardSlug=dev의 공개 글 개수를 반환하고 게시판 글 목록의 같은 filter와 일치한다.

**시작 상태**

L12 practice profile. Request P creates dev/PUBLISHED/PUBLIC post `[쿼리연습] JPA 연결` with content `본문 JPA 검색` by member5. Use dynamic id/author from P response.

**학습자가 할 일**

- G boardSlug=dev count를 요청하고 같은 시점의 JPA/MyBatis count를 비교한다.
- 동일 dev filter의 목록 total 및 직접 COUNT SQL과 수치를 대조한다.
- P 생성 전후 count 차이가 P 1건만큼인지 확인한다.
- 없는 slug와 빈/공백 slug를 각각 요청해 빈 결과와 validation 오류를 구분한다.

**정상 사례**

- boardSlug=dev 공개 글 count는 같은 filter의 목록 total 및 직접 COUNT(*)와 같다. P가 한 건 추가되면 다른 변경이 없을 때 count도 1 증가한다.

**실패·경계 사례**

- G의 C7은 status200/count>=1만 검사하므로 정확한 count나 JPA 목록 total parity는 확인하지 않는다.

**동시성·성능**

L12 query 정확성을 다루며 계획/성능 측정은 DB-08~14에서 수행한다.

**DB 관찰**

- 실제 응답 ID/total/status와 실행 SQL. items 배열 type만 기록하지 않는다.
- 동적 P가 seed count를 바꾸므로 초기화하거나 SQL 결과와 대조하고 고정값을 가정하지 않는다.

**합격 기준**

- 요청 시점의 정확한 count를 직접 SQL/JPA/MyBatis와 대조한다.
- P 생성 전후 차이가 1이고 같은 공개 조건이 사용된다.
- 잘못된 slug는 명시된 validation status를 따른다.

**기존 과제와 중복·연결**

Q02는 hidden/deleted 조건, DB-01은 field mapping, DB-07은 방식 비교다.
