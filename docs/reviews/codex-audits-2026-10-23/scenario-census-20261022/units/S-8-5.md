## 요구·구현·검사 대조

### 1. POST `/api/admin/recount`(admin tok-p01)는 원본행 수로 like_count/comment_count mismatch를 집합 UPDATE 한다. 첫 실행은 likes #93 6→4,#119 10→5,#120 3→4; comments #22 9→8,#75 2→4. 다음 실행은 양쪽 빈 배열이어야 한다. 비-admin=403, 무인증=401. D1,D2 mismatch count=0.

구현 대조: snapshot code mismatch SELECT는 원본 post_like/comment 집계 LEFT JOIN과 COALESCE로 0을 보존한다. UPDATE도 set-based, deleted post 제외, deleted comment 제외. Service는 mismatch를 먼저 저장해 응답+로그하고 변경 있을 때만 fix 호출. `@Scheduled(cron=0 0 4...)`는 같은 recount service를 호출한다.

검사 대조: X1은 first-run mismatch-set 또는 already-fixed-empty를 위한 anyOf 두 분기를 제공한다; X2는 양 배열 빈 값, X3 403, X4 401. D1/D2는 원본행 기준 mismatch가 각각 0인지 수동 SELECT. R1-R4 집합 UPDATE, 같은 method, multi-server lock, 예방적 원자 count update는 리뷰 기준.

공백 또는 한계: 실패 중간 재시도/동시 user write와 04:00 여러 인스턴스 동시 실행을 실제로 시험하지 않는다. R3은 다중 서버 시각 실행 위험과 ShedLock 같은 대책을 말로 검토하게 한다.

## 확장 개발 명세

### 재집계 멱등성과 다중 replica 운영 조건

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

단일 실행 후 mismatch 0과 같은 입력에 대한 재실행 빈 결과를 확인한다. 서버 replica가 여럿이면 매일 04:00에 동시에 수행될 수 있다.

**시작 상태**

practice seed의 알려진 count 불일치 93/119/120 likes, 22/75 comments; admin token tok-p01.

**학습자가 할 일**

- admin POST 한번, response list를 expected before/after와 대조한다.
- 그 다음 동일 API를 다시 보내 empty arrays를 확인하고 D1/D2 SELECT를 실행한다.
- 실제 2 replica 동시 scheduling은 메인 런타임 검증에서 별도 격리로 재현 후보로 남기고, 필요하면 분산락/idempotent partition strategy를 제안한다.
- 좋아요/댓글 원본이 보정과 동시에 추가되면 기존 count snapshot과 새 row가 어떻게 경합하는지 설명한다.

**정상 사례**

- likes: 93 6→4,119 10→5,120 3→4; comments:22 9→8,75 2→4.
- 두 번째 실행과 D1/D2 이후 mismatch count는 0.

**실패·경계 사례**

- tok-p02 요청 403; token 없는 요청 401.
- 이미 정합한 DB에서 첫 실행 expected는 빈 배열로 처리. source anyOf는 fresh state vs already-fixed state만 대안.

**동시성·성능**

고정된 04:00 동시 실행, multi-replica lock/retry, update during recount는 review/별도 isolated experiment이며 테스트되지 않았다.

**DB 관찰**

- API response likeFixed/commentFixed before/after.
- D1/D2 SQL mismatches=0 after fix.
- Asia/Seoul 기준 cron과 같은 service transaction 경계.

**합격 기준**

- C1 first-run or previously-fixed branch accurate.
- C2 second POST both arrays length0.
- C3=403,C4=401.
- D1/D2 count=0.

**기존 과제와 중복·연결**

4-2/5-1은 원자 증가/감소로 mismatch를 예방하는 역할, M8은 배치 안전망; 15장 retry/job run에서 batch operations 심화.
