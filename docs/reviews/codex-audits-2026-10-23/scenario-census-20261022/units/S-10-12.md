## 확장 개발 명세

### JPA flush 전후 MyBatis 가시성 비교

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

explicit flush와 동일 transaction에서 JPA→MyBatis 값을 안정적으로 비교한다.

**시작 상태**

IDENTITY id generation, JPA save 후 mapper SELECT가 있는 격리 통합 test.

**학습자가 할 일**

- flush를 넣은 경우와 생략한 경우를 각각 실행해 INSERT/SELECT 순서를 SQL 로그로 확인한다.
- 동일 ListItem response를 JPA/Mapper 결과와 비교한다.

**정상 사례**

- 원문 checker가 지정한 정상 경계값과 정상 row/response를 유지한다.

**실패·경계 사례**

- 문서가 요구한 오류 코드와 오류 전후 DB state를 단언한다.

**동시성·성능**

동시성은 해당 실험에서만 barrier/별도 transaction으로 확인한다. 측정하지 않은 성능 개선은 주장하지 않는다.

**DB 관찰**

- 독립 disposable DB에서 핵심 relation/row/count의 전후값을 확인한다.

**합격 기준**

flush 후 두 경로가 같은 행을 보며 본문 검증·목록 DTO contract도 유지된다.

**기존 과제와 중복·연결**

현재 단위의 원문 C/D/R 계약만 자동 검증한다. 기존 follow-up 단계의 책임을 이 단계에 복사하지 않는다.

**우선순위**

medium
