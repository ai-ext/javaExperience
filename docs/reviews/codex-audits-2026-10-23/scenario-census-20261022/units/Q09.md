## 확장 개발 명세

### DTO projection 필드와 관계값 확인

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

Entity 전체 대신 응답에 필요한 네 열을 DTO로 투영하고 JPA/MyBatis 결과를 비교한다.

**시작 상태**

자동 요청 P는 board=dev, author=member5, title [쿼리연습] JPA 연결, spring tag인 public 게시글을 만든다. A/B는 동적 author ID로 조회한다.

**학습자가 할 일**

A JPA와 B MyBatis의 items를 비교하고 동적 P.id가 결과에 있는지 확인한다. 각 item의 id,title,boardSlug,authorId를 P 응답의 대응 필드와 대조한다.

**정상 사례**

- Entity 전체 대신 응답에 필요한 네 열을 DTO로 투영하고 JPA/MyBatis 결과를 비교한다.

**실패·경계 사례**

잘못된 alias/생성자 열 순서, DTO에 없는 content가 노출되거나 P가 필터 결과에서 빠지는 경우를 확인한다.

**동시성·성능**

이 단위는 쿼리 정확성과 응답 계약을 확인한다. 실행 계획과 시간 측정은 DB-08~14에 연결한다.

**DB 관찰**

API JSON의 네 projection 필드, 두 엔진 결과 ID 집합, projection SQL의 선택 열.

**합격 기준**

JPA와 MyBatis items·total이 같고 P.id가 포함된다. 각 항목에는 id,title,boardSlug,authorId만 있으며 content가 없다.

**기존 과제와 중복·연결**

DB-07은 여러 쿼리 접근 방식의 공통 M1 계약, Q09는 DTO field mapping을 집중 확인한다.

**우선순위**

medium
