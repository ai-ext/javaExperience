## 판정

단건 조회, 비인증 GET, 404, lazy 관계 매핑과 조회수 반영을 sequential checker/SQL 기준으로 대조한다. 동시 갱신 손실은 T-017에서 명시적으로 심화하므로 이 단계 gap이 아니다.

## 목표·선수 지식·학습자 작업

게시글 단건 상세 GET을 만든다. 로그인을 요구하지 않고, 매 호출마다 post.view_count를 1 올린 뒤 갱신된 수치와 작성자/태그/게시판 정보를 DTO에 담는다. missing ID는 404, 숫자 아닌 path id는 바인딩 400이다. 1-6 interceptor와 JPA lazy/transaction 경계가 선수다.

PostQueryService에 @Transactional getDetail을 만들고 조회수 증가, lazy 관계를 DTO로 변환한다. Controller는 GET path id를 service에 전달한다. 인증 인터셉터가 no-token GET을 허용해야 한다.

## 쿼리·DB 깊이와 다음 단계

- content: JPA SELECT로 post와 lazy associations를 읽고 entity viewCount를 1 증가시킨 뒤 dirty-check UPDATE를 transaction commit에서 수행한다. D1/D2가 DB 값을 함께 확인한다.
- current_scope: 단일 post lookup, 읽기로 인한 상태 변경, lazy relation DTO mapping, 존재를 감추는 404.
- missing_scope: 동시 조회의 조회수 lost update는 이 단위에서 테스트하지 않지만 T-017 티켓이 정확한 후속 과제로 다룬다. 공개/숨김/삭제 정책은 2-3에서 다룬다.
- existing_links: 1-4 transaction/lazy 원칙, 2-3 access policy, 2-4 N+1, 4-2 concurrency, 11-3 회원별/일별 조회수 중복방지를 연결한다.

- 현재 난이도: 기초-중급
- 판정 이유: 단일 조회에 상태 변경을 함께 넣어 응답 값과 DB 값을 두 번 읽기로 대조한다. 인증 없는 GET과 POST 인증 정책을 구분하고 lazy-loading transaction boundary를 적용한다.
