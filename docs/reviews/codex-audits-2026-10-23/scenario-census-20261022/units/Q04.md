## 목표·선수 지식·학습자 작업

원문은 단계별 코드 제공/미완성 구간을 구별해 적고, 학습자는 해당 쿼리 요구와 경계 케이스를 실행 결과로 확인한다. 작성자 필터를 적용하고 글 없는 회원과 비공개 글을 확인한다.

## 요구·구현·검사 대조

### 1. authorId=P.body.author.id로 글을 찾되 공개 상태 필터를 유지한다.

구현 대조: JPA의 Author_Id 파생 메서드와 MyBatis author_id 조건을 사용한다. author ID 입력은 service에서 검증하며 L12는 한 번에 필터 하나만 허용한다.

검사 대조: D는 동적 P의 authorId를 요청한다. C4는 200과 items 배열만 검사하고 P의 ID/작성자 각 행 일치를 검사하지 않는다.

공백 또는 한계: 배열 유무만 확인하므로 작성자 필터가 누락되거나 다른 작성자 글이 섞여도 검사 통과 가능하다. authorId=0/없음의 빈 목록 경계도 확인하지 않는다.

## 확장 개발 명세

### Q04 구체 데이터 결과와 경계 검사

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

authorId=P.body.author.id로 글을 찾되 공개 상태 필터를 유지한다.

**시작 상태**

L12 practice profile. Request P creates dev/PUBLISHED/PUBLIC post `[쿼리연습] JPA 연결` with content `본문 JPA 검색` by member5. Use dynamic id/author from P response.

**학습자가 할 일**

- D 요청 authorId에 P.body.author.id를 넣어 JPA와 MyBatis를 호출한다.
- 각 결과 행의 authorId가 그 값과 일치하는지 확인하고 P가 반환되는지 확인한다.
- 다른 author ID와 존재하지 않는 양수 ID로 결과 경계를 비교한다.
- SQL/JPQL 파라미터 binding 및 공통 공개 조건을 확인한다.

**정상 사례**

- authorId=P.body.author.id인 공개 글을 찾고 숨김/삭제/비공개 글은 제외한다.

**실패·경계 사례**

- D는 동적 author ID 요청이다. C4는 200과 items 배열 type만 확인하므로 작성자 scope나 P 포함을 보장하지 않는다.

**동시성·성능**

L12 query 정확성만 다룬다. plan/성능 측정은 DB-08~14에서 수행한다.

**DB 관찰**

- 실제 응답 ID/total/status와 실행 SQL을 기록한다. items type만 확인하지 않는다.
- 동적 P로 seed count가 달라질 수 있으므로 reset하거나 직접 SQL과 대조한다.

**합격 기준**

- P 포함 및 모든 응답 행 authorId 일치.
- 다른 작성자 ID 응답에는 지정 authorId의 행이 없다.
- 각 엔진의 공개 상태 조건이 동일하다.

**기존 과제와 중복·연결**

Q02는 hidden/deleted 조건, DB-01은 field mapping, DB-07은 query 방식 비교를 다룬다.

**우선순위**

medium
