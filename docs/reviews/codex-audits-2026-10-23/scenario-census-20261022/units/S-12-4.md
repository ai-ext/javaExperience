## 확장 개발 명세

### 동시 PUT과 DELETE 최종 상태 결정

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

각 메서드는 멱등이지만 서로 반대되는 요청이 겹쳤을 때 우선순위가 정해져 있지 않다.

**시작 상태**

member 2와 active target 6 사이 관계가 없는 상태와 이미 있는 상태를 각각 준비한다.

**학습자가 할 일**

독립 트랜잭션 두 개를 barrier로 시작해 PUT/DELETE 응답과 최종 관계를 비교한다.

**정상 사례**

선택한 직렬화/DB commit 순서 정책에 맞는 하나의 최종 관계와 followerCount.

**실패·경계 사례**

block이면 PUT 403, DELETE 200; self/withdrawn 정책 유지.

**동시성·성능**

해당되는 경우 격리 데이터에서 동시성이나 실행계획을 확인하고 측정하지 않은 수치는 주장하지 않는다.

**DB 관찰**

pair row와 follower count를 SELECT하고 응답 시점의 기준을 기록한다.

**합격 기준**

정책 문서화, duplicate row 없음, 응답 count semantics가 명확.

**기존 과제와 중복·연결**
