## 목표·선수 지식·학습자 작업

PUT은 수정 폼 전체를 보내 새 상태로 교체하고 게시판/작성자/ID는 그대로 둔다. 3-1 PATCH의 생략/null 구분과 대비해 선택 필드가 생략되면 tags=[] 및 visibility=PUBLIC 기본을 적용한다. 1-5 validation, 1-6 token principal, 2-3 접근 정책이 선수다.

PostReplaceRequest를 새 DTO로 만들고 @Valid full replacement endpoint를 구현한다. Service에서 visibility policy와 owner를 확인한 뒤 Post.replace로 title/content/visibility/tags를 함께 바꾸고 2-1 상세 DTO를 반환한다. JPA join rows와 트랜잭션을 검증한다.

## 확장 개발 명세

### PUT 불변 identity와 생략 필드 assertion 보강

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

전체 교체 계약은 board/author/id 불변과 tags 생략의 기본값을 PATCH와 분명히 나눠야 한다.

**시작 상태**

integration test가 작성자 소유 post를 만들고 title/content/tags/visibility PUT을 수행하는 상태.

**학습자가 할 일**

요청 전 id/author_id/board_id/tags를 기록하고 tags를 생략한 PUT 뒤 동일 identity, PUBLIC 기본값, empty response tags 및 post_tag 행을 확인한다.

**정상 사례**

- Title/content/new visibility replace old values
- tags 생략은 빈 관계, visibility 생략은 PUBLIC이 된다.
- author/board/id stay constant

**실패·경계 사례**

- 필수 title 누락 시 400이며 scalar 값과 join row가 모두 바뀌지 않는다.
- another author 403; inaccessible source 404

**동시성·성능**

이 단계는 동시 수정 계약이 없다. 동시 PUT 정책은 미정이며 성능 측정을 요구하지 않는다.

**DB 관찰**

SELECT post fields plus post_tag rows before/after

**합격 기준**

기존 업데이트/실패 assertion에 더해 id/board/author 불변과 tags 생략 동작을 실제 DB에서 단언한다.

**기존 과제와 중복·연결**

3-1에서 PATCH 필드 존재/null semantics를 다루므로 두 계약을 합치지 않는다.

**우선순위**

low
