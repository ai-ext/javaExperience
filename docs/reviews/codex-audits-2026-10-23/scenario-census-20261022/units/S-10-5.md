## 확장 개발 명세

### 글·태그 저장의 중간 실패 rollback

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

Post와 tag/post_tag 작업 중 실패해도 transaction 전체가 되돌아가는지 확인한다.

**시작 상태**

Disposable DB에서 정상 tag 존재와 신규 tag를 포함할 입력을 준비한다.

**학습자가 할 일**

- 글 저장 직전/태그 관계 저장 중 DB constraint failure를 test hook으로 유발한다.
- post, tags, post_tags의 전후 row를 비교한다.

**정상 사례**

- 원문 checker가 지정한 정상 경계값과 정상 row/response를 유지한다.

**실패·경계 사례**

- 문서가 요구한 오류 코드와 오류 전후 DB state를 단언한다.

**동시성·성능**

동시성은 해당 실험에서만 barrier/별도 transaction으로 확인한다. 측정하지 않은 성능 개선은 주장하지 않는다.

**DB 관찰**

- 독립 disposable DB에서 핵심 relation/row/count의 전후값을 확인한다.

**합격 기준**

오류 뒤 신규 글과 신규 tag/join row가 남지 않고 정상 요청은 201이다.

**기존 과제와 중복·연결**

현재 단위의 원문 C/D/R 계약만 자동 검증한다. 기존 follow-up 단계의 책임을 이 단계에 복사하지 않는다.

**우선순위**

medium
