## 확장 개발 명세

### 자정 직전 cutoff와 동시 실행·실패 재시도 검증

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

SQL cutoff 및 UNIQUE 멱등성을 실제 MySQL에서 동시 요청/실패 조건으로 확인하고 다음 15-6 실행이력으로 연결한다.

**시작 상태**

테스트 전용 MySQL에 PUBLISHED/PUBLIC 글 두 개와 각 19·20개 좋아요를 준비한다. 좋아요 시각은 cutoff 직전, cutoff와 정확히 같은 시각, cutoff 직후를 각각 둔다. hall_of_fame은 비운다.

**학습자가 할 일**

- 고정 Clock으로 같은 date 수동 run을 두 스레드에서 동시에 호출
- 삽입 결과와 added를 비교하고 후속 같은 date 실행 결과를 비교
- 후보 수가 많을 때 EXPLAIN/행 수를 기록하고, 강제 오류 시 트랜잭션 전체가 롤백되는지 확인
- 운영자/일반회원/무토큰 요청을 HTTP로 확인하고 scheduler zone과 injected Clock을 대조

**정상 사례**

- cutoff 직전 20개 글만 한 행 삽입되고 경계 동일 시각의 좋아요는 제외된다.
- 동시/반복 실행 뒤 post_id별 행은 최대 1개이고 added에는 insert 성공 건만 포함된다.

**실패·경계 사례**

- DB 삽입 실패를 주입했을 때 일부 글만 남는지 또는 전체 rollback인지 계약대로 확인하고 15-6 복구 방식을 명세한다.
- 미래 날짜, 잘못된 형식, 일반 사용자/무토큰은 각각 400/403/401이다.

**동시성·성능**

같은 date run을 barrier로 두 개 동시에 시작하고 잠금/중복 제약 결과, 처리 건수와 트랜잭션 시간을 반복 기록한다. 대량 후보에서는 행 수를 키워 전체 결과 메모리와 실행 계획도 비교한다.

**DB 관찰**

**합격 기준**
