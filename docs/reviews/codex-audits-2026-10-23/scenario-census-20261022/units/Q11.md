## 판정

Declared JPQL과 MyBatis XML은 correlated EXISTS를 사용한다. Auto C3는 engine arrays equality only; P 포함과 id uniqueness independent assertion은 없다. 실제 스키마는 tag.name과 post_tag의 pair를 unique하게 제한한다.

## 확장 개발 명세

### 태그 EXISTS와 결과 행 단위 확인

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

tag=spring 관계가 있는 게시글을 필터하되 응답의 한 item은 게시글 한 건이어야 한다.

**시작 상태**

P는 tag spring으로 생성된다. E/F는 같은 practice DB에서 QueryDSL/JPA와 MyBatis에 tag=spring을 요청한다.

**학습자가 할 일**

두 결과의 id 목록에서 P.id를 찾고 item id 중복이 없는지 센다. 같은 post의 tag 관계 행과 API 결과 게시글 행을 따로 비교한다.

**정상 사례**

- tag=spring 관계가 있는 게시글을 필터하되 응답의 한 item은 게시글 한 건이어야 한다.

**실패·경계 사례**

tag가 없는 글이 포함되면 안 된다. 두 engine이 똑같이 빈 배열을 내거나 똑같이 중복 ID를 내도 통과 처리하지 않는다.

**동시성·성능**

이 단위는 쿼리 정확성과 응답 계약을 확인한다. 실행 계획과 시간 측정은 DB-08~14에 연결한다.

**DB 관찰**

post_tag/tag `spring` 매핑, P.id, 반환 items id 목록/중복 수, total.

**합격 기준**

P.id 포함, 모든 결과가 spring tag 보유, 각 post id 1회, QueryDSL/JPA와 MyBatis 결과가 같음.

**기존 과제와 중복·연결**

DB-04는 여러 조건 태그 JOIN의 중복 위험을 설명한다. Q11 현재 요청은 단일 tag라 schema unique pair를 같이 고려한다.

**우선순위**

medium
