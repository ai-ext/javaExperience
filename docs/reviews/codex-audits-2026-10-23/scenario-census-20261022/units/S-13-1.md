## 판정

정적 권한/상태 코드와 checker 요구가 맞는다. interceptor 순서와 양 DB migration은 runtime 확인이 필요하며 기능 불일치는 정적으로 발견하지 않았다.

## 목표·선수 지식·학습자 작업

회원 role을 USER/MODERATOR/ADMIN으로 확장하고 MODERATE_POST/MANAGE_ROLE/RUN_BATCH 권한을 한 enum에 둔다. 숨김 상태는 기존 status=HIDDEN에 hidden_at/hidden_by 기록을 더한다. 선수는 AuthInterceptor, PostAccessPolicy, 8-5 recount, post status lifecycle이다.

직접 구현: V40/V41 migrations, Role/Permission table, 권한 interceptor ordering, recount 권한 전환, role/status DTO validation, member role endpoint, post hide/unhide transition, hidden post read/list privacy. 운영자는 API로 ADMIN 승급/강등할 수 없다.

## 확장 개발 명세

### 역할 행렬·interceptor 순서·양 DB migration 검증

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

권한은 controller annotation뿐 아니라 요청 interceptor 순서와 각 profile의 DB role/migration에도 의존한다.

**시작 상태**

격리 community/practice DB에 member 1 ADMIN, member 7 USER를 준비하고 role API로 member 7을 MODERATOR로 바꾼다.

**학습자가 할 일**

- token 없음/USER/MODERATOR/ADMIN으로 protected GET, HIDDEN 상세, 상태 변경 API를 호출한다.
- member 7을 강등하고 새 인증 요청으로 다음 요청부터 거부되는지 확인한다.
- 양 profile에서 Flyway를 적용하고 role CHECK/hidden 컬럼/history를 조회한다.

**정상 사례**

- token 없음 401, USER moderation 403, MODERATOR는 hide/unhide 가능하나 role 관리/배치는 불가, ADMIN은 모두 허용된다.
- 반복 hide는 최초 actor/time을 유지하고 unhide는 metadata를 지운다. 일반 목록에는 HIDDEN row가 없다.

**실패·경계 사례**

- ADMIN role 변경 409, API의 role=ADMIN 400, DRAFT hide 409, 삭제 글 404.
- interceptor 순서 회귀가 인증 없는 요청을 null dereference/500으로 바꾸지 않는다.

**동시성·성능**

두 moderator가 같은 글을 동시에 hide한다. 최초 행위자/시각이 유지되고 응답이 일관되는지 확인한다.

**DB 관찰**

양 schema에서 role/status/hidden_at/hidden_by와 Flyway history를 조회한다.

**합격 기준**

권한 행렬/상태가 요구와 맞고 양 DB에 V40/V41이 한 번씩 적용되며 목록에는 hidden row가 없다.

**기존 과제와 중복·연결**

S-11-5 복구는 작성자 권한이며 deleted metadata를 비운다. moderator hide 권한과 혼합하지 않는다.

**우선순위**

medium
