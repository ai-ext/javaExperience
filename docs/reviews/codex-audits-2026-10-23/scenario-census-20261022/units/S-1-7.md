## 판정

DML로 앱 없이 직접 관계 행을 추가·변경·삭제하면서 FK/transaction/rollback을 관찰한다. D1-D4는 수동 SQL 과제로 지정됐으며 자동화 test가 없는 것은 이 단위의 학습 설계와 일치한다.

## 목표·선수 지식·학습자 작업

API로 만든 자기 글 ID를 사용해 community DB에서 JOIN·UPDATE/ROLLBACK·INSERT/연결/DELETE를 직접 관찰한다. post/board/member/tag/post_tag FK 경로와 트랜잭션 세션 경계를 알아야 한다.

새 API를 만들지 않는다. 1-6 POST로 새 글을 만들고 응답 ID/작성자 ID를 확인한 뒤 D1 JOIN, D2 태그 JOIN, D3 자기 행 UPDATE 후 rollback, D4 표식 post 및 post_tag 직접 작성/자식 먼저 삭제/rollback을 실행한다. seed id 1~21은 변경 금지.
