## 확장 개발 명세

### Two moderators resolving one report group

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

조건부 신고 처리가 report 상태와 target side effect 둘 다 한 번만 적용하는지 검증한다.

**시작 상태**

동일 public post target을 서로 다른 reporter가 PENDING 신고 두 개 만들고, 활성 MODERATOR token 두 개를 준비한다.

**학습자가 할 일**

- targetType=POST,targetId,action=HIDE인 resolve POST 두 개를 barrier로 동시에 시작한다.
- 두 응답 status/resolvedCount와 최종 report/post row를 비교한다.
- REJECT action 및 COMMENT target에서도 반복한다.

**정상 사례**

- 하나의 요청이 pending 신고 둘과 target을 처리하고 경합 loser는 409이며 두 번째 부수효과가 없다.

**실패·경계 사례**

- target 신고가 없으면 404, 이미 처리한 group은 409, 잘못된 권한은 403이다.
- target이 이미 삭제된 경우 report 상태 일부만 ACCEPTED로 남지 않도록 rollback 또는 targetStatus 정책을 확인한다.

**동시성·성능**

동일 group에 두 독립 transaction을 겹쳐 row lock/deadlock을 관찰한다. 순차 요청만으로 경쟁 주장을 하지 않는다.

**DB 관찰**

SELECT report status/handled_by/handled_at, post hidden fields or comment.deleted_at and post.comment_count before/after.

**합격 기준**

resolver 하나만 승리하고 pending report 상태가 일관되며 target effect와 comment_count가 한 번만 변경된다.

**기존 과제와 중복·연결**

CommentConcurrentDeleteTest는 중복 삭제 카운터를, S-13-1은 hide metadata 경쟁을 다룬다. 여기서는 report claim과 target effect를 결합한다.

**우선순위**

low
