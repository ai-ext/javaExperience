## 판정

PUT 전체 교체와 다르게 PATCH의 생략/null/빈 목록을 구분하고 일반 수정·태그 비우기·경계·접근 404/403·인증 실패를 검사한다. 유효 필드 뒤의 검증 오류 rollback 및 여러 오류 수집은 제한으로 명시한다.

## 목표·선수 지식·학습자 작업

PATCH는 제공한 non-null 필드만 바꾸고 absent/null은 그대로 둔다. 빈 값은 입력 오류, 빈 tags list는 태그 전부 제거다. 작성자 확인과 2-3 접근정책을 서버에서 적용해 본인 외 수정을 막는다. 3-0의 전체 교체/1-5 검증과 비교가 선수다.

수정 전용 PostUpdateRequest를 만들되 Bean Validation annotation을 쓰지 않는다(null이 합법적인 no-op 표시이므로). Service에서 source visibility→작성자 순으로 검사하고 제공 필드별 값 검증 후 Entity 변경 감지와 tags 관계 교체를 트랜잭션 안에서 수행한다.

## 쿼리·DB 깊이와 다음 단계

- content: Service는 managed Post의 field를 수정하고 tags는 기존 ManyToMany relation을 바꾼다. @Transactional은 DB commit까지 원자 경계를 제공한다. 검증은 필드별 순서대로 수행되므로 뒤 필드가 실패할 때 먼저 바꾼 메모리 상태가 transaction rollback되는지 확인해야 한다.
- current_scope: 누락/null/빈 목록 PATCH 의미, 작성자 및 privacy 검사, 수동 field validation, JPA dirty checking, tag join row 교체.
- missing_scope: 낙관적 잠금/동시 편집 정책은 정의되지 않는다. 여러 validation error를 모두 모으는 기능은 이번 답안에서 의도적으로 제공하지 않고 첫 오류를 반환한다. 유효 필드 뒤 invalid 필드 조합의 rollback 확인이 없다.
- existing_links: 3-0 PUT 전체 교체, 1-5 create validation 집계, 3-2 soft delete, 7-3 통합 테스트를 연결한다.

- 현재 난이도: 중급
- 판정 이유: PATCH는 필드 생략/null/빈 값 구분, field-by-field 검증, 접근 정책, JPA dirty checking, 관계 목록 의미를 함께 결정하게 한다. PUT 전체 교체와 대조한다.

## 확장 개발 명세

### 혼합 PATCH 오류 뒤 상태 rollback 검증

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

서비스는 non-null field를 순서대로 바꾼 뒤 뒤쪽 필드를 검증하므로 원자성은 transaction에 달려 있다.

**시작 상태**

기존 title/content와 태그가 채워진 소유자 글, 현재 @Transactional PATCH Service.

**학습자가 할 일**

- 유효한 새 title 다음에 잘못된 visibility 또는 과도한 tag 목록을 보내 400을 받는다.
- 요청 뒤 GET과 SELECT로 title/content/visibility/post_tag가 요청 전 상태와 동일한지 확인한다.
- 오류 수집이 첫 오류만인지 모든 필드인지 명세를 정하고 checker를 맞춘다.

**정상 사례**

- title only changes title
- tags=[] clears tag links
- null or omitted field remains same

**실패·경계 사례**

- title이 유효하고 visibility=SECRET이면 400이며 이전 title은 rollback된다.
- title이 유효하고 tag 개수가 초과하면 400이며 기존 post_tag 행이 유지된다.

**동시성·성능**

No concurrency requirement in this task

**DB 관찰**

같은 격리 test transaction 또는 Testcontainers에서 요청 전후 title/content/visibility/tag relation을 비교한다. community volume reset은 하지 않는다.

**합격 기준**

나중 필드 검증 실패 뒤 앞선 변경이 rollback되고 DB row/post_tag가 요청 전과 같음을 assertion한다.

**기존 과제와 중복·연결**

3-0 PostReplaceControllerTest는 PUT validation 한 건을 다루며 7-3은 통합 트랜잭션 테스트 방법을 제공한다. 현재 PATCH 전용 rollback test는 없다.

**우선순위**

medium
