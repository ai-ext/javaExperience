## 확장 개발 명세

### member7 feed cursor와 M5 R1 범위 확인

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

M5는 본인+팔로우 글을 R1 조건 아래 안정적으로 나열한다. 후속 구현에는 mute 및 size cursor가 추가되어 있으므로 구분한다.

**시작 상태**

M5 practice seed의 member7로 시작한다. 과제 기대 total=41 및 첫 ID는 mission 문서에서 읽는다. 12-5 snapshot은 mute가 추가된 비교 자료다.

**학습자가 할 일**

- 빈 cursor로 feed를 요청하고 nextCursor가 없어질 때까지 순회해 첫 페이지와 고유 ID 집합을 기록한다.
- 현재 practice 결과가 기대 total 41 및 첫 ID [145,144,139,138,137]와 일치하는지 대조한다.
- member7의 팔로우 대상 및 본인 글을 원본 행에서 확인한 뒤 status/deleted 및 현재 차단 관계를 적용한다.
- member_mute 상태를 확인하고 후속 mute 조건이 M5 기대 41을 바꾸는지 별도 기록한다.
- DDL에서 허용 visibility를 확인한다. PUBLIC/FOLLOWERS와 알 수 없는/private 값이 저장소 query에서 통과 가능한지 검토한다.
- 격리 데이터에 publishedAt 동률을 넣고 id DESC cursor에서 페이지 중복/누락이 없는지 확인한다.

**정상 사례**

- 마지막 페이지의 nextCursor는 null이며 전체 페이지 사이에 중복 ID가 없다.

**실패·경계 사례**

- PUBLISHED가 아니거나 deleted된 글은 feed에서 제외한다.
- 저장 가능한 비공개/미지 visibility가 팔로우만을 이유로 노출되면 접근 정책 누출이다.

**동시성·성능**

cursor 순회 검증이며 지연/처리량 목표는 없다.

**DB 관찰**

- 첫 ID와 전체 cursor 순회 개수, follow 경로, 차단/mute 관계, visibility/status/deleted 값.

**합격 기준**

- R1 visibility와 양방향 차단 규칙이 실제 repository 조건과 일치한다.
- 후속 mute 확장은 별도 확인해 M5 기준 동작과 혼동하지 않는다.

**기존 과제와 중복·연결**

DB-02는 2키 cursor, 12-5 Feed는 mute가 추가된 후속 변형, M1/PostAccessPolicy는 R1 정책을 다룬다.

**우선순위**

high
