## 확장 개발 명세

### 동적 생성 ID로 JPA/MyBatis 상세 대조

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

생성 응답 ID를 다음 요청에 연결하고 같은 저장 행을 두 query 방식이 반환해야 한다.

**시작 상태**

practice profile; POST /api/posts tok-p05 creates dev title [쿼리연습] JPA 연결, body 본문 JPA 검색, spring tag. P.body.id is dynamic.

**학습자가 할 일**

- P.body.id를 A JPA detail과 B MyBatis detail 경로에 각각 넣어 요청한다.
- 양쪽 응답의 id/title/boardSlug/authorId를 비교하고 저장된 P 응답의 값과 대조한다.
- Hibernate/MyBatis SQL과 바인딩 id 및 visibility 조건을 기록한다.
- 두 detail 성공 결과를 확인한 뒤 Q02 상태 변경으로 넘어간다.

**정상 사례**

- A와 B는 status=200이며 두 ID가 P.body.id와 같고 네 projection 필드도 일치한다.

**실패·경계 사례**

- 잘못된 형식/0 ID는 400, 없는 ID 또는 공개되지 않은 행은 404가 기대된다. Q01 자동 검사는 이 경계를 다루지 않는다.

**동시성·성능**

No performance/concurrency criterion for detail mapping.

**DB 관찰**

- P로 생성된 DB 행과 두 detail 응답 tuple.
- 실행 SQL 및 동적 id/visibility 조건.

**합격 기준**

- A/B status=200 및 id/title/boardSlug/authorId 동일.
- 양쪽 ID가 P 생성 응답의 동적 ID와 일치한다.

**기존 과제와 중복·연결**

Q02는 visibility/status 제외, DB-03은 상세 조회 JOIN 구성을 다룬다.

**우선순위**

medium
