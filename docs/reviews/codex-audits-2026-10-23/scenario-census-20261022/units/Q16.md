## 쿼리·DB 깊이와 다음 단계

실제 QueryDSL은 공통 공개 predicate에 keyword OR를 AND로 추가한다. JPA 선언 쿼리도 FILTER에서 같은 논리(공개 predicate AND (title OR content))를 사용하고, MyBatis XML도 괄호로 묶는다. fixture에는 title JPA가 포함된 HIDDEN post 105가 있어 누출 반례가 이미 있으나 check는 두 엔진 동등성뿐이다. 이 Q의 성공은 실제 숨김 ID 제외를 확인해야 하며 plan 비교는 DB-08~14 범위다.

- 현재 난이도: 기초~중급
- 판정 이유: 필수 공개 predicate AND (title OR content)의 grouping 및 숨김 글 누출을 확인한다.
- 다음 단계: 선행 Q 및 후속 Q, DB-01~14 데이터·쿼리 경로.

## 확장 개발 명세

### JPA·QueryDSL·MyBatis 검색의 HIDDEN 누출 검사

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

Q16의 요구는 공개 조건 AND 제목/본문 OR이고 HIDDEN 상태는 결과에서 제외해야 한다. 실제 seed post 105는 HIDDEN/PUBLIC이며 제목이 `JPA N+1 문제 초보 가이드`라 keyword 반례를 제공한다.

**시작 상태**

L13/L14 공통 준비의 practice 프로필, 기존 seed post 105, 그리고 C/D로 생성한 공개 post P(`[쿼리연습] JPA 연결`, 본문 `본문 JPA 검색`)를 사용한다. post 105를 수정하거나 reset하지 않는다.

**학습자가 할 일**

- `keyword=JPA` 요청을 JPA·QueryDSL·MyBatis 각각 실행하고 post 105가 세 결과의 id 목록에 없는지 확인한다.
- 키워드를 제목에만 둔 공개 글과 본문에만 둔 공개 글을 각각 생성해 두 글이 모두 검색 결과에 있는지 확인한다.
- 생성 글의 status를 HIDDEN으로 변경한 후 같은 세 요청에서 동적 ID가 제외되는지 확인한다.
- 공개 없는 글을 검색했을 때 status 200과 빈 items/total=0 계약을 확인한다.

**정상 사례**

- `GET /api/query-practice/querydsl/search?keyword=JPA`의 QueryDSL items와 같은 요청의 JPA/MyBatis items가 동일하다. 공개 P는 포함되고 ID 105는 제외된다.

**실패·경계 사례**

- HIDDEN post 105 제목 매칭 시 누출 금지.
- 공개 글의 content만 `JPA`에 매칭되는 경우도 반환해야 한다.
- keyword에 `%`, `_`, `!`를 넣을 경우 SearchFilter.pattern의 escape와 세 구현의 결과가 같아야 한다.

**동시성·성능**

Q16은 query semantics 단계이므로 동시성·실행시간을 요구하지 않는다.

**DB 관찰**

- 세 엔진 결과의 `id` 배열과 `total`을 비교한다.
- fixture post 105의 `status=HIDDEN`, title match를 SQL seed에서 확인한다.

**합격 기준**

- Q16 C2 동등성 통과.
- 세 결과 모두 ID 105 없음.
- 제목 전용·본문 전용 공개 게시글 각각 포함.
- 공개 같은 조건을 유지하고 HIDDEN으로 바꾼 두 게시글 각각 제외.

**기존 과제와 중복·연결**

Q02 공개상태 제외는 공통 선행 Q지만 Q16에서 OR 괄호가 누출 방지하는 실제 조합을 재검증해야 한다. DB-12 실행계획은 다른 단계다.

**우선순위**

high
