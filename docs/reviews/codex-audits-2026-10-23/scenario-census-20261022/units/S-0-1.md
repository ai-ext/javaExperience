## 판정

입문 목적에 맞게 API 계약·문법 학습·의도적 실패 진단을 함께 제공한다. 코드 정답은 계약을 구현하지만 기존 자동 테스트는 이 경로를 보호하지 않는다. 시작 준비에서 DB 포트 불일치 위험을 별도 문제로 정확히 드러내므로 학습자에게 남는 실행 마찰은 자동 검사로 닫히지 않는다.

## 목표·선수 지식·학습자 작업

Java 문법을 처음 API와 연결하는 입문 단계다. 쿼리 매개변수를 받아 문자열·정수를 계산하고 record 응답을 JSON으로 돌려주는 흐름을 따라 친다. 사전 조건은 레포 실행 환경 준비와 패키지·파일 생성이며, 문서는 datasource와 CORS까지 준비 항목으로 둔다.

학습자가 Greeting record와 GreetingController를 직접 작성한다. CORS 설정은 그대로 제공·복사하고 DB 컨테이너 상태는 준비한다. 코드 전문과 생성자 기반 대안은 비교 자료다. DB 저장은 학습자 작업에 포함되지 않는다.

## 확장 개발 명세

### 응답 회귀 검사를 저장소 테스트로 고정

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

현재 기존 테스트는 /hello만 검사하고 시나리오 endpoint의 기본값·JSON 필드를 보호하지 않는다.

**시작 상태**

스냅샷 코드와 현재 HelloControllerTest; API 응답은 브라우저 검사 패널로 확인 가능

**학습자가 할 일**

MockMvc 요청 두 개를 추가해 전달된 이름과 생략된 이름의 상태·Content-Type·JSON 필드 및 글자 수를 검증한다.

**정상 사례**

- name=김자바면 JSON 200, nameLength=3
- name 생략이면 익명과 nameLength=2

**실패·경계 사례**

- 기본값 annotation 제거 시 생략 요청이 400으로 바뀌어 검사가 실패
- nameLength 계산 또는 응답 키 변경 시 해당 JSON assertion 실패

**동시성·성능**

해당 없음: 순수 계산 API

**DB 관찰**

테스트 컨텍스트 시작은 datasource 의존성이 있으므로 활성 프로필과 DB 구성을 명시하고, 연결 실패와 endpoint 실패를 구분한다.

**합격 기준**

새 테스트가 두 입력 경로의 상태·응답 헤더·모든 응답 필드를 검증하고, 기존 /hello 테스트와 구별되는 endpoint를 실제로 호출한다.

**기존 과제와 중복·연결**

7-1의 Controller slice testing 및 7-3의 통합 검증으로 이어질 수 있으나 이 단계에 테스트 작성은 요구되지 않는다.

**우선순위**

medium
