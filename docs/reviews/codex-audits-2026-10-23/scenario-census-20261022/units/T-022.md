## 판정

기존 상태/오류 모양 보존, malformed body, 알 수 없는 500 응답 보호가 명확하다. 예외 subtype 전수 매핑은 추가 검사 후보이며 정답 snapshot이 없는 것은 독립 과제의 정상 범위다.

## 목표·선수 지식·학습자 작업

application-wide exception handling을 ErrorCode enum/shared handler로 정리하면서 기존 status/code/detail contract를 유지하고 Spring binding/validation/body parse errors도 같은 Problem Details 모양으로 반환한다. 선수는 @ControllerAdvice, MVC exception types, domain errors.

ErrorCode enum, 공통 domain exception, 단일 공통 handler를 구성하고 ResponseEntityExceptionHandler의 Spring MVC 예외 변환을 적용한다. 인증 인터셉터 예외와 알 수 없는 500도 같은 Problem Details 규약으로 처리하며 내부 예외 메시지는 응답에서 감춘다.

## 요구·구현·검사 대조

### 1. 존재/권한/state conflicts/input/body parse/unsupported method/binding errors는 상태와 code를 보존한 Problem Details. 잘못된 JSON 400 MALFORMED_BODY, auth 401 header 유지, inactive member 403, unknown exception fixed 500 no class/message leak; existing domain messages remain.

구현 대조: 정답 snapshot이 제공되지 않은 독립 과제다. 구현 상태를 미제공 정답 부재만으로 결함 처리하지 않는다.

검사 대조: C1~C6은 기존 404/400/401/403/409 의미, 본문 파싱 오류, 500 응답 비노출을 확인한다. D1은 실패 요청의 post 미생성, D2는 중복 bookmark가 409로 막히는 부수효과를 본다. R1~R3는 단일 오류 매핑, Spring 표준 오류, 리팩터 전후 회귀 확인을 다룬다.

공백 또는 한계: 표본 오류 유형은 확인하지만 기존 모든 도메인/보안/MVC 예외를 빠짐없이 열거해 상태·code가 정확히 한 번 매핑되는 표는 없다. ResponseEntityExceptionHandler 적용은 기존 override와 충돌할 수 있다고 R2가 밝힌다.
