## 요구·구현·검사 대조

### 1. V4는 수신자/행위자/게시글 FK, LIKE|COMMENT type 제약, nullable comment_id/read_at, 미읽음 목록용 index를 추가한다. 타인 글에 새 좋아요/댓글이 발생한 같은 transaction에서만 알림을 생성하며 중복/자기 행위는 제외한다.

구현 대조: V4 DDL에는 FK, type CHECK, index가 있다. LikeService는 INSERT IGNORE가 새 행을 만들었을 때만 event를 발행한다. CommentService는 저장과 counter 변경 뒤 같은 transaction에서 event를 보낸다. listener는 동기 EventListener다.

검사 대조: NotificationRollbackIntegrationTest는 새 좋아요 중 알림 저장 실패를 주입해 post_like 및 like_count가 0으로 rollback되는지 확인한다. 화면 검사 Y0~Y4는 좋아요 삭제/생성/중복, 댓글, 알림 목록을 확인하지만 Y4는 상위 2행과 unreadCount>=2만 본다.

공백 또는 한계: 자동 Y4는 상위 두 알림과 unreadCount 하한만 검사하므로 목록 뒤쪽에 중복 LIKE가 있어도 통과할 수 있다. rollback 테스트는 LIKE 저장 실패만 다루고 COMMENT listener 실패는 검사하지 않는다.

## 확장 개발 명세

### 좋아요·댓글 알림의 같은 트랜잭션과 멱등성 확인

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

알림은 원본 변경과 함께 커밋되고, 중복 좋아요나 자기 댓글처럼 실제 상태 변화가 없으면 중복 side effect를 만들지 않아야 한다.

**시작 상태**

practice fixture의 post12는 member2 작성, actor는 member3이다. 요청 전 member2 알림 수를 SELECT COUNT(*) FROM notification WHERE member_id=2로 기록한다.

**학습자가 할 일**

- Y0에서 actor3의 기존 좋아요를 지우고 Y1로 새 좋아요, Y2로 같은 PUT을 반복한다. 전후 알림 수를 세어 actor3/post12 LIKE 행이 하나인지 확인한다.
- Y3에서 actor3이 member2 post12에 댓글을 남기고 comment_id가 있는 COMMENT 행 하나를 확인한다.
- member2가 자기 글에 댓글을 남길 때 댓글 처리와 자기 알림 생략을 따로 확인한다.
- member2 알림 size2를 조회해 최신 COMMENT 후 LIKE 순서, unreadCount, 실제 행 수를 비교한다.
- Y5 타 회원 member5가 member2 알림을 읽을 때 404, Y6 소유자 read는 204인지 확인한다. unreadOnly=true에서 읽은 ID가 빠지는지 확인한다.
- 격리 테스트에서 LIKE와 COMMENT 알림 삽입 실패를 각각 유도해 원본 관계/카운터와 알림 행이 함께 rollback되는지 비교한다.

**정상 사례**

- Y1/Y2/Y3 뒤 member2에게 새 LIKE 1건과 COMMENT 1건만 생기며 중복 LIKE는 없다.
- 최신 두 알림은 COMMENT actor3/post12 후 LIKE이고 unreadCount는 실제 미읽음 행 수와 같다.

**실패·경계 사례**

- 숫자가 아닌 알림 ID는 400, 없는 ID/다른 소유자는 404, 소유자의 read 요청은 204다.
- 알림 저장 listener가 실패하면 원본 좋아요 행과 post.like_count도 0으로 rollback된다.
- 댓글 알림 실패도 별도 검사해야 한다. 현재 integration test는 해당 분기를 덮지 않는다.

**동시성·성능**

비동기/outbox 보장은 이 범위에 없다. listener는 같은 트랜잭션 동기 실행이며 commit 이후 delivery/retry는 구현되지 않았다.

**DB 관찰**

- member/type/post/actor별 notification 행 수 전후.
- 실패 유도 전후 post_like 행과 like_count.

**합격 기준**

- 중복 PUT 후 좋아요 알림은 1행이고 comment 이벤트는 COMMENT 1행이다.
- 소유자/비소유자 read 상태와 unreadCount가 각 규칙에 맞는다.
- LIKE/COMMENT 삽입 실패 시 원본 변경과 알림이 함께 rollback된다.

**기존 과제와 중복·연결**

16-1은 게시글 알림을 after-commit으로 이동하는 후속 주제다. M2 좋아요 멱등성, M7 댓글 transaction/counter와 연결되며 9-4는 동기 transaction을 다룬다.

**우선순위**

medium
