## 판정

교착 원인 및 응답/카운터/DB deadlock 관찰 기준이 구체적이다. 자동 동시 회귀는 선택사항이라 수동 재현 재현성 및 comment/like lock order를 보강할 여지가 있다.

## 목표·선수 지식·학습자 작업

FK 검사에서 부모 post 공유 잠금을 먼저 얻고 같은 트랜잭션의 counter UPDATE가 배타 잠금 승격을 기다려 댓글 동시 작성이 교착할 수 있다. 이를 재현하고 부모 행 잠금 순서를 바꾼다. 선수는 InnoDB/FK/트랜잭션/row lock이다.

같은 post에 댓글 요청 8개를 barrier로 겹쳐 SHOW ENGINE INNODB STATUS 또는 DB 로그에서 lock cycle을 확인한다. 댓글 INSERT보다 먼저 parent post 행을 UPDATE 또는 FOR UPDATE해 잠금 순서를 고친 뒤 응답/카운터를 보존하고, 같은 글의 직렬화와 다른 글 독립성을 비교한다.

## 요구·구현·검사 대조

### 1. 동시 요청 8개가 모두 201이고 comment id가 서로 다르며 post.comment_count가 8 증가한다. 실제 살아 있는 댓글 행 수도 같아야 한다. 원인은 FK 검사 S 잠금 뒤 counter UPDATE X 승격이 서로 기다리는 구조로 진단하며, parent lock을 먼저 획득한 후 댓글을 INSERT한다.

구현 대조: 정답 snapshot이 제공되지 않은 독립 과제다. 구현 상태를 미제공 정답 부재만으로 결함 처리하지 않는다.

검사 대조: C1~C3은 성공 응답·고유 id·카운터 증가, D1은 카운터와 실제 행 수, D2는 재현된 InnoDB deadlock 상태를 확인한다. T1 자동 동시성 회귀는 선택사항이다. R1~R3는 잠금 고리, 순서 조정과 단순 재시도 차이, 처리량 대가를 본다.

## 쿼리·DB 깊이와 다음 단계

- content: post.comment_count 갱신과 comment INSERT는 한 트랜잭션이어야 한다. 부모 post X lock을 FK 검사/자식 삽입 전에 획득하면 같은 행에 대한 잠금 순서를 맞춘다. atomic counter UPDATE를 먼저 하거나 SELECT FOR UPDATE를 쓸 수 있다.
- current_scope: 티켓 원문 전체의 시작조건, 직접 구현 업무, 채점·실험 방법을 대조했다. 정답 코드 snapshot 없음.
- missing_scope: 동시 JUnit은 선택이라 핵심 교착 완료 기준이 수동 CLI 재현에 의존하고 시점 차이로 안정적으로 재현되지 않을 수 있다. 좋아요 writer도 parent 행을 갱신하므로 댓글/좋아요 상호 잠금 순서 조합은 별도 검사되지 않는다.
- existing_connections: 선수/후속/겹치는 영역: H1 concurrency; S08 locks/transactions; MySQL FK/innodb status. 기존 단위와 겹치면 신규 기능을 발명하지 않고 reuse/regression으로 연결한다.

- 현재 난이도: 상 — 교착 진단을 위해 lock trace와 FK engine 동작, 안전한 공통 잠금 순서, 처리량 대가를 함께 이해해야 한다.
- 판정 이유: 댓글 삽입과 parent counter 갱신 사이의 교착을 InnoDB 상태에서 확인한 뒤 요청 순서를 조정하고 다른 writer와의 영향도 판단해야 한다.
