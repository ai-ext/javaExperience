## 판정

정적 구현은 커밋 뒤 REQUIRES_NEW로 수신자별 INSERT SELECT를 수행하고 즉시/임시저장/예약발행/복사 경로의 event 조건을 명세와 맞춘다. 실패 시 글 응답은 보호되지만 log-only listener는 알림 전달을 보장하지 않는 tradeoff다. 원문 검사 흐름은 구체적이나 새 글 경로의 자동 통합검사 및 durable retry는 부족하다.

## 목표·선수 지식·학습자 작업

새 공개 글이 커밋된 뒤에만 팔로워 알림을 생성한다. 저장 transaction 안에서 알림 row를 바로 만들 경우 rollback과 외부 비가역 부수효과가 섞이는 이유를 실습하고, AFTER_COMMIT→REQUIRES_NEW, 활성/차단 필터, INSERT SELECT를 확인한다. 선수는 9-4 notification과 11-1 draft, 13-5 copy, 15-3 scheduled publish이며 다음 16-2는 비동기 푸시 실패/스레드 처리다.

V70에서 NEW_POST type을 보존성 있게 CHECK에 추가한다. PostCreatedEvent는 즉시 PUBLIC create·draft publish·scheduled transition 실제 변경·copy의 트랜잭션 안에서 발행하고 listener는 AFTER_COMMIT에 notifyNewPost를 호출한다. 알림은 REQUIRES_NEW와 단일 INSERT SELECT로 작성자 팔로워 중 ACTIVE·미삭제·양방향 차단 없음만 생성한다. 실패 장치로 글 저장 후 rollback시 알림 0을 관찰한다.

- outbox 선택 시 event id+unique recipient key+상태/attempt count를 설계해 재시도 중 중복을 방지

**정상 사례**

- 각 공개 전이 1회당 허용 수신자에게 한 notification, 작성자/정지/탈퇴/non-follower/양방향 block은 0.
- 롤백된 글은 event가 commit listener에 도달하지 않고 알림도 0.

**실패·경계 사례**

- listener insert failure 이후 글은 성공/커밋되어도 알림이 남지 않는 현재 tradeoff를 관찰한다.
- outbox 채택 시 listener 중단 후 재시작/중복 전달에도 수신자별 DB 알림 하나만 남는다.

**동시성·성능**

같은 event handler 중복 호출 및 팔로우/차단 변경과 commit race를 테스트하고 fanout 수신자 수별 query/lock/시간을 측정한다. 시점 규칙(커밋 당시 follower vs listener 실행 당시 follower)을 정한다.

**DB 관찰**

글/알림 row, author/recipient/type/post_id, Flyway V70 check constraint, follower/block fixture, INSERT SELECT 처리량을 확인한다.

**합격 기준**
