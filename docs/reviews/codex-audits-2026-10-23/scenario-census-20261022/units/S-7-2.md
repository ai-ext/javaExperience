## 판정

엄격한 mock 단위 테스트가 좋아요 정책, 영향 행 수에 따른 counter, 저장 인자 ArgumentCaptor와 실제 visibility policy 호출을 분리한다. DB 무결성 및 transaction 동작을 증명하는 테스트는 아니다.

## 목표·선수 지식·학습자 작업

Repository mock을 사용하는 순수 service unit test를 만든다. 저장 값은 ArgumentCaptor로 보고 실제 policy 동작과 호출을 함께 확인해야 할 때만 spy를 쓴다.

성공 저장, 잘못된 owner/권한 거부, 호출 없어야 할 경우를 테스트한다. 시간 주입 등 결정적 test seam도 검토한다.

## 요구·구현·검사 대조

### 1. unit-test 기준은 순수 Service, repo mocks, 필요한 interaction만 stubbing, spy의 이유, never 검증과 ArgumentCaptor다.

구현 대조: service는 mock Repository/Policy와 mock TransactionManager를 사용한다. 5번만 PostAccessPolicy 실제 구현을 spy로 감싸 호출 횟수도 확인한다.

검사 대조: LikeServiceTest는 내 글 like 거부와 저장/증가 없음, 새 like insert/counter, duplicate insert 0행 시 counter 미증가, 미누른 상태 unlike에서 counter 미감소, spy 실제 policy로 비공개 글 거부/저장 없음까지 다룬다.

공백 또는 한계: 테스트는 Spring transaction/실제 MySQL을 실행하지 않으므로 DB unique, atomic update와 deadlock 동작의 검증은 7-3/4-2에 맡긴다.
