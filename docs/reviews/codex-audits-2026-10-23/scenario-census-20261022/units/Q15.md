## 확장 개발 명세

### QueryDSL Q 타입과 게시판 필터 확인

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

`QPost.post.board.slug.eq(boardSlug)`가 공통 visible predicate와 AND 결합되고 같은 dev 게시판 글을 반환해야 한다.

**시작 상태**

L14 practice overlay에서 author5가 board dev에 동적 P를 생성한다. A QueryDSL과 B JPA에 boardSlug=dev를 요청한다.

**학습자가 할 일**

- QPost 타입은 L14 build.gradle annotationProcessor가 생성한다. compile 확인은 runtime 후속 실행에 맡긴다.
- A/B에 boardSlug=dev를 보내 ID와 total을 기록한다.
- 동적 P.id 포함 여부와 모든 행의 boardSlug=dev, PUBLISHED/미삭제/미숨김/PUBLIC을 확인한다.
- 문서가 세 방식을 요구하므로 L13 MyBatis dev filter도 비교한다. 현재 자동 요청은 MyBatis를 호출하지 않는다.

**정상 사례**

- A/B는 dev 공개 글의 같은 결과를 반환하고 P를 포함한다. 생성 P 이전 M1 seed ID는 [145,144,143,140,138]이다.

**실패·경계 사례**

- QPost 생성 또는 annotation processor가 없으면 compile 실패를 데이터 query 실패와 구분해 기록한다.

**동시성·성능**

이 단위는 query contract를 검증하며, 실행계획·성능 측정은 DB-08~14로 연결한다.

**DB 관찰**

- QPost 생성 산출물/build profile, 엔진별 ID/count, boardSlug와 SQL predicate.

**합격 기준**

- 세 방식 기대를 유지하면 QueryDSL/JPA/MyBatis 모두 같은 ID 결과와 count를 반환한다.

**기존 과제와 중복·연결**

Q10은 authorId 결합을 추가하고 Q15는 board slug 및 QueryDSL 타입 생성을 다룬다.

**우선순위**

medium
