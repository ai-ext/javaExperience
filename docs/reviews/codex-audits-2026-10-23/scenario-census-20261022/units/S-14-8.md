## 목표·선수 지식·학습자 작업

기존 북마크 폴더를 비밀번호 없는 읽기 전용 링크로 공유하되 토큰 회전·만료·주인 권한·열람자 기준 공개 정책을 명확히 구현한다. V55 컬럼/UNIQUE, 소유자 전용 POST/DELETE, 공개 GET, 1~30일/null 입력과 Clock 만료 경계를 다룬다. 선수는 6-2 소유권, 2-3 PostAccessPolicy, 8-2 Clock이며 다음은 ch15 배치·스케줄링이다.

폴더 owner가 요청할 때마다 SecureRandom 32바이트 Base64url 토큰을 생성해 기존 값을 교체하고, 선택 만료일을 저장한다. 링크를 연 viewer 기준으로 북마크 글을 필터링하며 memo/note와 bookmark id는 응답에서 제외한다. 옛 토큰·만료·공유 해제를 404로 통일하고, 쓰기는 소유자 확인·행 잠금, 읽기는 공개 토큰 경로에서 수행한다.

### 공유 링크 회전·해제 동시 API 검사와 로그 비밀값 점검

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

row lock의 효과를 실제 MySQL에서 확인하고, 회전 이후 옛 링크가 살아남거나 unshare와 경합하는 경우를 재현한다.

**시작 상태**

Testcontainers MySQL에 소유자 A의 폴더와 공개 글·팔로워 공개 글을 넣고 A의 공유 token T0를 생성한다.

**학습자가 할 일**

- barrier를 둔 두 POST share를 동시 실행하고 응답 token 중 최종 DB token만 200으로 열리는지 확인
- share와 DELETE unshare를 동시에 실행해 최종 컬럼 및 각 응답 후 token 상태를 확인
- 타 회원의 share/unshare는 404이며 행·token을 변경하지 않는지 검사
- HTTP access log와 애플리케이션 로그에서 token 원문이 남지 않는지 설정과 테스트 로그로 검사

**정상 사례**

- 연속 회전 뒤 이전 token은 404, 마지막 token만 200이다.
- unshare 완료 뒤 token/expiry가 NULL이고 기존 링크는 404다.
- 비로그인과 로그인 사용자 각각의 공개/팔로워/차단 글이 viewer 정책대로 필터링된다.

**실패·경계 사례**

- 동시 해제/회전 이후 token과 expiry가 모순된 조합으로 남지 않는다.
- 입력 JSON 배열/null, expiresInDays 경계 밖, 비소유자가 500으로 번지지 않는다.

**동시성·성능**

두 스레드의 POST/DELETE를 같은 folder id에 장벽으로 동시 시작하고 교착/잠금 대기 시간과 결과를 기록한다. 다른 폴더 작업은 서로 불필요하게 막지 않는지 확인한다.

**DB 관찰**

최종 bookmark_folder token/expiry를 SELECT하고 token 유니크 인덱스를 확인한다. 응답상 token과 실제 저장값을 비교하되 비밀값은 보고서/로그에서 마스킹한다.

**합격 기준**

DB에는 token/expiry 상태 조합이 일관되고 최종 token 하나만 열리며, 비소유자 변화 없음, viewer별 데이터 최소화, 로그 원문 비노출이 확인된다.

**기존 과제와 중복·연결**

C1~C11/D1/D2/T1/R5를 통합·동시성 검사로 강화한다. 기존 만료 엔티티 테스트를 대체하지 않는다.
