## 확장 개발 명세

### method parameter 검증 오류도 공통 ProblemDetail로 맞추기

상태: **제안·미구현**. 이 문서 작성만으로 학습 실습이 구현됐다고 표시하지 않는다.

**이유**

모든 400/403/404에 공통 오류 형식을 둔다고 설명하지만 query parameter @Min/@Max는 다른 MVC 예외 경로를 탄다.

**시작 상태**

BoardPostController의 @Min/@Max 및 공통 ApiExceptionHandler

**학습자가 할 일**

전역 Advice에서 HandlerMethodValidationException을 다루고 파라미터 검증 오류를 지정한 ProblemDetail 구조로 바꾼 뒤 query parameter의 media type/detail을 검사한다.

**정상 사례**

- page 생략→0, size 생략→10
- size 1/50 및 page 0 허용

**실패·경계 사례**

- page -1과 size 0/51은 application/problem+json의 400
- 예외 클래스명/stack trace가 응답에 노출되지 않음

**동시성·성능**

해당 없음

**DB 관찰**

잘못된 query parameter는 DB query 실행 전에 거절한다.

**합격 기준**

request parameter 검증과 DTO body 검증이 동일하게 지정된 ProblemDetail 계약을 따르고 잘못된 경계값은 저장소 조회 전 거절된다.

**기존 과제와 중복·연결**

S-1-5에서 공통 ProblemDetail을 도입한다. Spring MVC 6.1 이상 method validation의 별도 예외 처리를 보강한다.

**우선순위**

medium
