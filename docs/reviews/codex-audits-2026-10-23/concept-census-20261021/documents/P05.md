## JAR/WAR와 클래스패스

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** JAR/WAR는 ZIP 기반 아카이브이며, 클래스패스는 JVM이 클래스·리소스를 찾는 위치 목록입니다.

**언제 사용하는가:** plain JAR은 classpath로, Boot executable JAR은 `java -jar`로 실행하고 내부 manifest를 점검합니다.

**대안과 경계:** 확장자만으로 실행 가능성을 알 수 없습니다. `-jar` 실행은 외부 `-cp`를 무시하고 중첩 JAR을 일반 클래스패스가 자동 탐색하지 않습니다.

**예시·실행 근거:** plain Java JAR manifest의 Main-Class와 Boot JAR의 JarLauncher/Start-Class 구조를 `jar`, `unzip`, `javap`로 확인합니다.

**선수개념:** 패키지·클래스 이름; JVM 런처

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- classpath 구분자와 라이브러리 동봉 방식은 OS/패키징에 따라 확인해야 합니다.

**초보자가 시작할 질문:**

- `java -jar app.jar`가 `-cp` 옵션을 무시하면 의존 라이브러리는 어디서 찾아야 하나요?
- plain JAR과 실행 JAR 중 어느 쪽 manifest를 먼저 확인해야 하나요?

## Boot executable JAR/Gradle 태스크

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** Gradle `jar`는 일반 아카이브, `bootJar`는 Boot launcher와 앱 의존성을 포함한 실행 산출물입니다.

**언제 사용하는가:** Spring Boot를 단독 실행 서비스로 배포할 때 `bootJar`와 `java -jar`를 사용합니다.

**대안과 경계:** `-D` JVM 옵션은 `-jar` 앞, Spring 인자는 뒤에 둡니다. -plain 산출물을 실행 파일로 오해하지 않습니다.

**예시·실행 근거:** 실제 Boot 4.1.1 프로젝트에서 manifest와 실행 로그/curl 출력이 기록되어 있습니다.

**선수개념:** Gradle/Maven; 클래스패스; Boot launcher

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 환경별 파일명/classifier는 빌드 설정으로 확인해야 합니다.

**초보자가 시작할 질문:**

- 배포 폴더에 JAR이 두 개 생겼다면 어느 것이 서버 실행 산출물인지 어떻게 판별하나요?
- 프로파일 `-D`와 `--server.port`를 명령행 어디에 두나요?

## WAR와 외부 서블릿 컨테이너

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** WAR는 WEB-INF 구조로 웹앱과 라이브러리를 두며 Boot는 SpringBootServletInitializer/WarLauncher로 실행 가능한 WAR도 만들 수 있습니다.

**언제 사용하는가:** 외부 컨테이너가 배포 요구사항일 때 WAR와 providedRuntime을 선택합니다.

**대안과 경계:** plain WAR와 executable WAR는 launcher/포함 라이브러리가 다릅니다. 컨테이너 호환성은 별도입니다.

**예시·실행 근거:** bootWar와 plain war 내부 경로·manifest·직접 java -jar 실행을 비교한 실제 결과가 있습니다.

**선수개념:** Servlet container; Gradle war plugin

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 외부 Tomcat 환경 배포 자체는 실행 확인 범위와 다릅니다.

**초보자가 시작할 질문:**

- 외부 Tomcat에 배포하는 WAR와 `java -jar` 가능한 WAR의 내부는 어떻게 다른가요?
- 컨테이너에 포함된 Tomcat과 앱의 제공 런타임이 충돌하면 무엇을 보나요?

## Dependency provenance and troubleshooting

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 의존성 좌표는 전이 의존성을 따라 해석되고 BOM은 관련 라이브러리 버전을 정렬합니다. dependencyInsight/tree로 실제 선택 경로를 조사할 수 있습니다.

**언제 사용하는가:** 클래스가 없거나 메서드 링크 오류가 날 때 컴파일·실행 classpath와 선택된 버전을 추적합니다.

**대안과 경계:** NoClassDefFoundError는 실행 시 필요한 클래스가 없을 때, NoSuchMethodError는 컴파일 당시와 실행 시 라이브러리 API가 맞지 않을 때 흔합니다.

**예시·실행 근거:** BOM, 전이 의존성 확인 명령과 두 대표 오류의 원인·진단 방향을 기록합니다.

**선수개념:** Gradle/Maven dependency graphs.

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- General dependency conflicts may be container-specific and require deployed-environment logs.
