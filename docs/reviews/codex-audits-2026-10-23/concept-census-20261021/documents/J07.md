## 컬렉션 계약·선택 기준

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** List/Set/Map/Queue 인터페이스는 순서·중복·key 의미를 정하고 구현체가 비용과 표현을 결정합니다.

**언제 사용하는가:** 접근 빈도·삭제 위치·순서 필요·데이터 크기를 먼저 정하고 구현을 고릅니다.

**대안과 경계:** Map은 Collection의 하위가 아니며 encounter order와 정렬 순서는 다릅니다.

**예시·실행 근거:** 구현별 연산비용 표와 interface map.

**선수개념:** Java interface/generics

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 복잡도 표는 측정 결과가 아니라 구현/API 특성 요약입니다.

## ArrayList·LinkedList 내부

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** ArrayList는 참조 배열을 확장 복사하고 중간 변경 때 이동하며 끝 추가는 상각 O(1). LinkedList는 node link로 위치를 찾아야 합니다.

**언제 사용하는가:** 인덱스 접근·순회는 ArrayList, iterator 위치를 이미 가진 주변 편집은 LinkedList를 검토합니다.

**대안과 경계:** LinkedList 삽입 O(1)은 노드 검색 비용을 빼야만 성립합니다. 1.5x 성장은 OpenJDK 구현 세부입니다.

**예시·실행 근거:** 동일한 키의 삽입·조회·삭제 결과를 비교해 해시 기반 구현의 계약을 확인합니다.

**선수개념:** 배열; node/iterator

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 특정 입력/장치에서 상수 비용 비교는 benchmark가 필요합니다.

**초보자가 시작할 질문:**

- 중간 삽입이 O(1)이라고 들었는데 `list.add(i,x)` 전체는 왜 O(n)일 수 있나요?
- 대량 순차 조회에서 LinkedList가 느려질 수 있는 메모리 경로는 무엇인가요?

## HashMap 해시·equals·resize

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** hashCode가 bucket을 고르고 같은 bucket 안에서 equals가 key를 구분합니다. 용량 임계값을 넘으면 table을 확장합니다.

**언제 사용하는가:** 키는 equals/hashCode에 쓰이는 상태가 변하지 않게 유지합니다. 예상 크기에 맞는 초기 용량을 정합니다.

**대안과 경계:** O(1)은 분산이 잘 된 기대치이고 oversized capacity는 순회 비용을 키웁니다. Treeify threshold는 API 계약이 아닙니다.

**예시·실행 근거:** HashCollisionDemo는 동일 hash 코드 키 12개를 보존하지만 실제 treeify 여부는 출력만으로 증명하지 않습니다.

**선수개념:** J02 equality/hashCode

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 충돌 bucket 수치/임계는 JDK 구현별입니다.

**초보자가 시작할 질문:**

- Set에 들어간 키의 hash 필드를 바꾼 뒤 contains가 실패할 수 있는 이유는 무엇인가요?
- 같은 해시를 반환하는 다른 키가 왜 HashMap에 함께 들어갈 수 있나요?

## 순서 맵·정렬 맵·LRU

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** LinkedHashMap은 insertion/access order 링크를 더하고 TreeMap은 comparator로 정렬해 범위 뷰를 제공합니다.

**언제 사용하는가:** 삽입 순서는 LinkedHashMap, 범위/이웃 검색은 TreeMap, 단순 LRU는 access-order map을 검토합니다.

**대안과 경계:** access-order get은 순서를 바꿀 수 있고 Tree comparator 0은 같은 key로 처리합니다.

**예시·실행 근거:** LRU Demo에서 key2가 제거되고 TreeMap 범위 출력이 나옵니다.

**선수개념:** HashMap; Comparator

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 동시성·TTL·분산 캐시 기능은 구현되지 않았습니다.

**초보자가 시작할 질문:**

- LinkedHashMap에서 get한 항목이 순회 순서에 영향을 주는 설정은 무엇인가요?
- TreeMap comparator가 0을 반환하면 equals가 false여도 키가 하나로 보일 수 있는 이유는?

## fail-fast와 unmodifiable view

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** iterator는 구조 변경을 best-effort로 감지하고 unmodifiableList wrapper는 원본을 비추는 뷰입니다.

**언제 사용하는가:** 반복 중 삭제는 iterator.remove; 방어 복사로 구조 변화를 차단하면 List.copyOf를 씁니다.

**대안과 경계:** Fail-fast는 thread-safe가 아니며 복사/불변 컬렉션도 원소 객체까지 재귀 불변으로 만들지 않습니다.

**예시·실행 근거:** CollectionContractsDemo에서 view는 원본 변경을 반영하고 copy는 고정됩니다.

**선수개념:** iterator; collection mutation

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 동시 변경 안전성은 J11의 concurrent collection/lock이 필요합니다.

**초보자가 시작할 질문:**

- unmodifiable view를 받은 뒤 원본 List에 값을 추가하면 view에는 무엇이 보이나요?
- ConcurrentModificationException이 동시성 잠금을 대신하지 못하는 이유는 무엇인가요?
