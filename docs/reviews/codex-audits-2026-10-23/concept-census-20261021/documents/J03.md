## 제네릭과 불공변성

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 제네릭 타입 인자는 컴파일 시 조합을 검사하며 `List<Integer>`는 `List<Number>`의 하위 타입이 아닙니다.

**언제 사용하는가:** 동일 타입 입력/출력을 연결하려면 `<T>`, 한 방향 입력·출력은 와일드카드로 표현합니다.

**대안과 경계:** extends는 생산자에서 읽고, super는 소비자로 넣는 PECS 경계입니다.

**예시·실행 근거:** copyAll(List<? extends T>, List<? super T>)로 Integer를 Number 목적지에 복사합니다.

**선수개념:** Java 기본 문법과 값/객체 참조

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 컴파일 실패 코드는 일부 사례만 설명되어 있습니다.

**초보자가 시작할 질문:**

- List<Integer>를 List<Number>로 대입할 수 있게 하면 호출자가 어떤 잘못된 값을 넣을 수 있나요?
- 값을 읽기만 할 리스트와 T를 쓰기만 할 리스트에는 extends/super 중 무엇을 둘까요?

## 소거·브리지·힙 오염

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 타입 인자는 대부분 실행 전 소거되고 컴파일러가 캐스트와 bridge method로 관계를 보존합니다.

**언제 사용하는가:** raw legacy 경계를 격리하고 리플렉션에서 bridge/synthetic을 구분합니다.

**대안과 경계:** 소거는 런타임 비용 0을 뜻하지 않으며 raw/배열 별칭은 예외를 늦출 수 있습니다.

**예시·실행 근거:** J03GenericsDemo에서 브리지 메서드와 raw call ClassCastException을 출력합니다.

**선수개념:** Java 기본 문법과 값/객체 참조

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- unchecked 배열 예제는 위험 재현용이지 복사할 구현이 아닙니다.

**초보자가 시작할 질문:**

- Node<Integer> override 뒤 raw Node로 문자열을 넣으면 캐스트 실패는 어느 메서드에서 드러날까요?
- 컴파일러가 bridge 메서드를 생성해야 하는 이유는 무엇일까요?

## 배열·varargs·타입 토큰

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 배열은 공변/reified, 제네릭은 불공변/소거라 parameterized type 배열을 직접 만들 수 없습니다.

**언제 사용하는가:** 제네릭 컬렉션을 우선하고 Type 토큰이 실제 요구일 때 사용합니다.

**대안과 경계:** @SafeVarargs는 구현 안전성 약속이며, Type token은 소거된 T 정보를 되살리지 못합니다.

**예시·실행 근거:** ArrayStoreException, generic array read CCE, TypeRef 결과를 실행합니다.

**선수개념:** Java 기본 문법과 값/객체 참조

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 프레임워크별 TypeToken 구현은 적용 대상과 문서가 다릅니다.

**초보자가 시작할 질문:**

- List<Integer>[]를 직접 만들 수 없는 이유와 List<?>[]가 허용되는 차이는 무엇일까요?
- List<String> 정보를 Class 토큰으로 전달할 수 없다면 어떤 Type 표현을 써야 할까요?

## Arrays, varargs and type tokens

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 배열은 공변이며 실행 시 원소 타입을 기억하고, 제네릭은 불공변이며 대부분 타입 인자를 지웁니다. Class<T>는 raw class 토큰만 담고 TypeRef는 parameterized type 서명을 보존할 수 있습니다.

**언제 사용하는가:** 배열에 하위 타입 원소를 저장하거나 generic type 정보를 reflection/Jackson 등에 전달할 때 두 규칙을 확인합니다.

**대안과 경계:** 배열은 실행 중 ArrayStoreException이 날 수 있지만 제네릭은 컴파일 시 불공변성을 검사합니다. 타입 토큰은 임의의 객체를 안전하게 복구해 주지는 않습니다.

**예시·실행 근거:** ArrayStoreException, heap pollution과 TypeRef<List<String>> 출력으로 배열·varargs·타입 토큰의 차이를 실행해 봅니다.

**선수개념:** Java 타입·메서드 호출 기초

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- No arbitrary framework integration test of Type token.

**초보자가 시작할 질문:**

- `List<Integer>`를 `List<Number>` 변수에 대입하려 할 때 컴파일러가 막는 이유는 무엇인가요?
- `List<String>[]` 배열을 직접 만들 수 없는데 배열과 제네릭의 차이가 무엇인가요?

## 실제 캡처 관찰

- 데스크톱 첫 화면에는 PECS/erasure/heap pollution 요약과 접힌 섹션이 보인다.
- 모바일 요약은 가로 넘침 없이 줄바꿈되어 읽을 수 있다. 후속 예제는 캡처 화면 아래에 있다.
- core에는 type parameter/argument, bound, wildcard, raw, erasure, bridge, type token의 조밀한 용어표와 접힌 소주제가 보인다. bridge/heap pollution의 런타임 흐름은 시각화되지 않는다.

**관찰 범위:** 캡처는 표로 용어를 전달하지만 unsafe cast 예제를 열지 않았고 compile-time에서 runtime으로 이어지는 변화도 보여 주지 않는다.
