## Entity·스키마 매핑

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** Entity와 테이블/열/제약의 지속 상태 연결

**보완·검증 필요 사항:**

## JPA Entity 클래스의 무인자 생성자 계약

현재 판정: **부정확** / 우선순위: P0

**정의와 실제 역할:** Jakarta Persistence Entity에는 public 또는 protected 무인자 생성자가 필요하다. 원문 앞부분은 이를 설명하지만 치트시트는 반대로 금지라고 적어 내부 모순이 있다.

**언제 사용하는가:** JPA가 생성할 영속 클래스의 생성자·접근 수준을 선언하고, 애플리케이션 생성 메서드와 구분할 때 확인한다.

**대안과 경계:** 무인자 생성자가 불필요한 일반 DTO/record의 설계와 JPA Entity의 생성 계약은 다르다. final 클래스 금지와 무인자 생성자 필요를 한 금지 목록으로 묶으면 안 된다.

**예시·실행 근거:** 원문9/15행의 public/protected 무인자 생성자 요구와318행의 final·무인자 생성자 금지 문장을 직접 대조했다. 이번에 새로운 JPA 코드를 실행한 증거가 아니라 원문 내부 모순 및 명세 대조다.

**선수개념:** 클래스 생성자; 접근 제어자; JPA Entity와 일반 객체의 역할

**관련 표기·별칭:** no-arg constructor; 무인자 생성자; protected constructor; @Entity

**판정 이유:** 동일 문서 안에 서로 반대인 생성자 계약이 존재한다. Jakarta Persistence3.2 Entity Class 요구사항으로 판정 가능하다.

**보완·검증 필요 사항:**

- 318행 치트시트를 final 클래스 금지·public/protected 무인자 생성자 필요로 구분해 교정해야 한다.
- 원문과 진행 중 보강의 교정 코드가 갈리는 경우 학습자가 복사할 기준을 한 곳으로 연결해야 한다.

**초보자가 시작할 질문:**

- 객체를 DB에서 읽어 올 때 내가 인자를 넣어 만들지 않았는데 생성자는 무엇을 써야 하나요?
- Entity에 기본 생성자가 필요하다는데 치트시트는 왜 금지라고 하나요?

**공개본과의 차이:** 공개본은 Entity/관계 매핑, owner/mappedBy, cascade, fetch와 DTO 설명을 제공하고 일부 순수 Java 관계 helper 출력만 근거로 둔다. compile 오류를 원문 접근성 문제와 연결하고 수정 한 줄을 대조하는 장면은 보강 HTML에서만 확인되며 공개 HTML에는 통합되지 않았다. 보강 compile 통과는 JPA schema, INSERT/flush, HTTP response 또는 MySQL mapping 검증을 뜻하지 않는다.
