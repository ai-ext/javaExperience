## JVM 논리 메모리와 HotSpot 영역

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** JVMS heap/stack/method area는 명세상 실행 영역이고 Metaspace/code cache/direct memory는 HotSpot/native 구현·프로세스 메모리로 설명됩니다.

**언제 사용하는가:** OOM 원인을 힙/비힙/OS 영역으로 나누고 RSS와 `-Xmx` 차이를 설명할 때 씁니다.

**대안과 경계:** 메서드 영역=Metaspace가 아니며 direct buffer 내용도 힙 객체와 다릅니다.

**예시·실행 근거:** Memory layout chart와 heap/direct buffer `isDirect()` 실행 예시.

**선수개념:** JVM runtime areas; OS RSS

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- HotSpot 객체 크기·물리 배치는 옵션/빌드별로 달라집니다.

**초보자가 시작할 질문:**

## GC 도달성·생존량·외부 자원

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** GC는 roots에서 도달 가능한 객체를 보존하고 나머지를 회수 후보로 둡니다. GC가 file/socket/native resource를 자동 닫는 것은 아닙니다.

**언제 사용하는가:** GC 로그와 heap dump에서 allocation·survivor·retained path를 나눠 봅니다.

**대안과 경계:** 회수 가능성과 서비스 자원 해제는 별개의 lifecycle입니다.

**예시·실행 근거:** 서로 참조하는 객체와 외부 파일 자원을 함께 두고 객체 회수와 자원 종료가 별개임을 설명합니다.

**선수개념:** references/GC roots; AutoCloseable

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- Object retain root path is not heap-dump reproduced.

**초보자가 시작할 질문:**

- Young GC 후에도 사용량이 계속 늘면 무엇이 살아남는지 어느 경로를 확인하나요?
- 객체가 GC 대상이 되면 열린 파일이 즉시 닫힌다고 할 수 없는 이유는?

## G1·ZGC·Shenandoah 선택

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** G1은 region/young+mixed collection, ZGC/Shenandoah는 낮은 지연시간을 위한 concurrent 작업의 비용 균형을 둡니다.

**언제 사용하는가:** 평소 G1 및 GC 로그부터 보고 pause/throughput/headroom 목표에 따라 collector를 비교합니다.

**대안과 경계:** G1 MaxGCPauseMillis는 보장 SLA가 아니고 concurrent collector도 CPU와 여유 메모리가 필요합니다.

**예시·실행 근거:** G1의 region 수집 흐름과 collector별 지연·처리량 선택표를 제시합니다.

**선수개념:** heap/live set; GC logs

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- collector 성능은 실제 workload benchmark가 필요합니다.

**초보자가 시작할 질문:**

- G1 pause target을 10ms로 설정하면 모든 pause가 10ms 이하가 된다고 볼 수 없는 이유는?
- ZGC로 바꾸면 CPU·heap 여유가 필요하지 않게 되나요?

## GC 로그와 버전별 옵션

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** Unified logging `-Xlog:gc`는 수집 전후 점유/용량/pause를 기록하고 세대형 collector 옵션은 JDK별로 달라집니다.

**언제 사용하는가:** after-GC 생존량 추세를 보고 OOME/GC overhead/할당률을 분류합니다.

**대안과 경계:** Allocation Failure는 GC 시작 원인이며 OOME와 같은 이벤트가 아닙니다. feature availability/version defaults drift.

**예시·실행 근거:** JDK21 SerialGC 16MiB example, log 43 lines 실제 관찰.

**선수개념:** GC event logging; JDK version

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- time/value/format JDK나 collector에 따라 다릅니다.

**초보자가 시작할 질문:**

- `5M->2M(15M)` 로그에서 전·후·capacity·pause는 각각 무엇을 뜻하나요?
- Java 25 기본 collector를 믿더라도 왜 배포 JVM 옵션을 확인해야 하나요?

## Versioned collector features

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** ZGC의 세대형 동작 기본값, Shenandoah의 제품 지원 상태, compact header는 JDK 버전에 따라 달라집니다.

**언제 사용하는가:** 실행 중인 JDK 버전과 해당 배포판의 문서에서 collector 기본값과 지원 상태를 확인합니다.

**대안과 경계:** 옵션과 기본값을 모든 JDK 버전에 일반화하면 안 됩니다. Shenandoah와 ZGC도 버전별 제공·기능 차이가 있습니다.

**예시·실행 근거:** JDK 21·23·24·25별 collector 기본값과 지원 상태 차이를 표로 비교합니다.

**선수개념:** JVM/OS process basics
