## @Scheduled와 JVM 작업 생명주기

현재 판정: **미검증** / 우선순위: high

**정의와 실제 역할:** Spring은 살아 있는 애플리케이션 JVM 내부 scheduler에 @Scheduled 작업을 등록한다.

**언제 사용하는가:** 영속 실행 이력이나 분산 보장이 필요 없는 단순 반복 작업에 사용한다.

**대안과 경계:** 애플리케이션 인스턴스마다 작업이 등록되며 서버가 꺼진 동안의 실행을 저장하거나 나중에 재생하지 않는다.

**예시·실행 근거:** 10초 지연 작업과 cron 작업을 등록한 뒤 앱 종료 시 중단되는 것을 확인한다.

**선수개념:** Spring Bean

**관련 표기·별칭:** @Scheduled JVM lifecycle; fixedRate; fixedDelay

**보완·검증 필요 사항:**

- Spring 코드 예제는 실행하지 않았다.

**초보자가 시작할 질문:**

- 서버가 꺼져 있는 동안 예약 작업도 실행되나?

## 주기·timezone·scheduler thread pool

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** fixedRate, fixedDelay, cron은 다음 실행 시점을 계산하는 기준이 다르며 scheduler thread pool은 동시에 실행 가능한 작업 수를 정한다.

**언제 사용하는가:** 일정 주기 polling, 작업 종료 후 대기, 특정 시각 실행 중 필요한 기준을 고를 때 사용한다.

**대안과 경계:** 기본 scheduler thread 수는 설정과 버전에 따라 확인해야 한다. Spring cron은 초를 포함하는 6개 필드여서 Linux cron 5개 필드와 다르다.

**예시·실행 근거:** 12초 걸리는 작업과 5초 간격 실행을 타임라인으로 비교한다.

**선수개념:** 시간 개념; thread와 동시성

**관련 표기·별칭:** Cadence/timezone/thread pool; cron; zone; TaskScheduler

**보완·검증 필요 사항:**

- virtual thread와 현재 기본값은 공식 설정 문서에서 버전별 확인이 필요하다.

**초보자가 시작할 질문:**

- 작업이 오래 걸리면 다른 예약 작업은 기다리나?

## 중복 실행·재시도·분산 scheduler

현재 판정: **미검증** / 우선순위: high

**정의와 실제 역할:** 예약된 시각에 실행된다는 사실은 한 번만 실행됨을 보장하지 않는다. 상태 저장, 멱등성, 분산 조정과 복구가 필요하다.

**언제 사용하는가:** 여러 서버에서 실행되거나 실행 이력과 누락 회차 복구가 필요한 작업에서 사용한다.

**대안과 경계:** ShedLock은 중복 실행을 건너뛰게 할 수 있고 Quartz는 지속 trigger를 저장하며 Kubernetes CronJob은 제한된 조정을 제공한다. 어느 쪽도 업무 멱등성을 대신하지 않는다.

**예시·실행 근거:** 잠금 행, 실행 상태, 재시도와 진행 key를 확인한다.

**선수개념:** DB transaction; 분산 lock

**관련 표기·별칭:** Duplicates, retries, distributed scheduler; ShedLock; Quartz; CronJob; idempotency

**보완·검증 필요 사항:**

- ShedLock 의존성 버전은 확인되지 않았고 예제는 실행되지 않았다.

**초보자가 시작할 질문:**

- 서버 세 대에서 같은 작업이 중복되거나 회차가 빠질 수 있나?
