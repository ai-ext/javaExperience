## characterization과 regression test

현재 판정: **미검증** / 우선순위: high

**정의와 실제 역할:** characterization test는 현재 관찰되는 legacy 동작을 기록하고 regression test는 수정으로 다시 문제가 생기지 않도록 한다.

**언제 사용하는가:** legacy 변경이나 bug fix 전에 현재 동작과 요구사항을 분리할 때 사용한다.

**대안과 경계:** 현재 동작 자체가 잘못됐을 수 있으므로 characterization 결과를 요구사항으로 확정하면 안 된다.

**예시·실행 근거:** soft-delete 상품 80개 예시를 수정 전후 비교한다.

**선수개념:** 테스트 assertion; 요구사항

**관련 표기·별칭:** characterization and regression test; golden master; bug reproduction

**보완·검증 필요 사항:**

- 예제 테스트는 실행되지 않았고 기존 파일과 중복될 수 있다.

## CI 보고서와 flaky test

현재 판정: **미검증** / 우선순위: high

**정의와 실제 역할:** CI에서 테스트와 결과 보고서를 보존하고 불안정한 테스트는 재시도로 숨기지 말고 원인을 조사한다.

**언제 사용하는가:** 팀 공유 자동화에서 반복 가능한 품질 증거를 남길 때 사용한다.

**대안과 경계:** Testcontainers 사용 시 CI runner의 Docker 필요 여부를 확인한다. 산출물은 어떤 테스트가 실패했는지 보여준다.

**예시·실행 근거:** 항상 실행되는 report upload 단계로 HTML/XML 결과를 보존한다.

**선수개념:** CI; Docker

**관련 표기·별칭:** CI reporting and flaky tests; JUnit XML; Gradle HTML report

**보완·검증 필요 사항:**

- workflow YAML은 실행되지 않았다.

## coverage 해석

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** line/branch coverage는 실행되지 않은 코드 위치를 찾는 계측이지 assertion의 정확성을 측정하는 점수는 아니다.

**언제 사용하는가:** 위험한 분기 중 테스트가 닿지 않은 곳을 찾을 때 사용한다.

**대안과 경계:** coverage가 높아도 요구사항 전체나 결과의 정확성을 보장하지 않는다.

**예시·실행 근거:** test와 JaCoCo를 실행해 놓친 branch를 확인한다.

**선수개념:** 테스트; Gradle

**관련 표기·별칭:** coverage interpretation; JaCoCo; branch coverage

**보완·검증 필요 사항:**

- coverage는 실행하지 않았다.

**초보자가 시작할 질문:**

- coverage 90%면 요구사항이 올바르게 구현된 건가?
