## Stream pipeline 생명주기

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 중간 연산은 지연 실행 pipeline을 구성하고 terminal operation에서 실행된다. pipeline은 한 번 소비하면 재사용할 수 없다.

**언제 사용하는가:** collection을 filter/map/aggregate로 변환할 때 사용한다.

**대안과 경계:** 분기·조기 종료·복구처럼 제어 흐름이 복잡하면 for문이 더 명확할 수 있다.

**예시·실행 근거:** 35개 짝 예제의 결과와 이미 소비한 Stream 재사용 시 IllegalStateException을 확인한다.

**선수개념:** Java collection; lambda

**관련 표기·별칭:** Stream pipeline lifecycle; lazy intermediate operations; single-use stream

**보완·검증 필요 사항:**

- 한 파일에 여러 패턴이 함께 있어 원하는 예제를 찾기 어렵다.

## 변환·선택·그룹·집계 연산

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** map은 요소를 대응 변환하고 flatMap은 내부 collection을 평탄화한다. collector는 grouping·merge·정렬 결과를 만든다.

**언제 사용하는가:** 중첩 목록, 검색 색인이나 보고서 변환에 사용한다.

**대안과 경계:** distinct는 equals로 중복을 판단한다. 중복 key를 toMap에 넣으면 merge 규칙을 지정하지 않은 경우 예외가 발생한다. Comparator에는 null 처리 정책이 필요하다.

**예시·실행 근거:** 예제 01–35의 입력과 출력 행을 확인한다.

**선수개념:** lambda; equals/hashCode; Optional

**관련 표기·별칭:** transform/select/group/aggregate; map; flatMap; collect; toMap

**보완·검증 필요 사항:**

- Collectors.toList의 변경 가능 여부는 보장되지 않는다. JDK 데모 결과와 API 계약을 구분한다.

## side effect와 결과 계약

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** Stream 연산은 외부 상태 변경을 피하고 결과 계약을 명확히 한다. Stream.toList 결과는 변경 불가이며 복잡한 복구 흐름에는 반복문이 더 읽기 쉬울 수 있다.

**언제 사용하는가:** 분기나 오류 복구가 많은 여러 단계 처리에서 Stream과 반복문 중 읽기 쉬운 방식을 고를 때 사용한다.

**대안과 경계:** Collectors.toList의 변경 가능성은 보장되지 않는다. peek은 terminal operation 전에는 실행되지 않고 short-circuit로 일부 요소만 처리될 수 있다.

**예시·실행 근거:** findFirst, page, reduce와 teeing 예제에서 연산 전후 결과를 비교한다.

**선수개념:** collection mutability

**관련 표기·별칭:** side effects/result contract; peek; toList; for loop

**보완·검증 필요 사항:**

- side effect 오류 사례는 실제 실행보다 규칙 설명 비중이 크다.

**초보자가 시작할 질문:**

- 오류 복구나 조기 종료가 필요하면 언제 for문이 더 나은가?
