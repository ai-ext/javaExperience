## 배포 모델과 공동 책임

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** on-prem, IDC와 cloud는 server 위치와 운영 책임을 다르게 나눈다. IaaS/PaaS/SaaS는 physical host·OS·runtime·app·data 운영 책임의 분배 모델이다.

**언제 사용하는가:** 어떤 환경을 직접 patch·운영하고 어느 부분을 provider에 맡기는지 결정할 때 사용한다.

**대안과 경계:** PaaS를 써도 애플리케이션·계정·data 책임은 남는다. cloud라고 모든 운영이 provider 몫은 아니다.

**예시·실행 근거:** 서비스 모델별로 고객/provider의 운영 책임을 layer 표로 비교한다.

**선수개념:** server; 운영 책임

**관련 표기·별칭:** Deployment model/shared responsibility

**보완·검증 필요 사항:**

- 실제 cloud account나 provider 서비스는 검증하지 않았다.

**초보자가 시작할 질문:**

- 관리형 서비스를 쓰면 내가 직접 책임져야 하는 것은 무엇인가?

## 가상화와 availability zone

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** VM은 가상 하드웨어와 guest OS를 제공하고 container는 host kernel을 공유한다. region/AZ는 cloud의 서로 다른 장애·위치 범위다.

**언제 사용하는가:** VM/container 배치나 고가용성 배치를 검토할 때 사용한다.

**대안과 경계:** multi-AZ만으로 app, network, DB, DNS까지 포함한 end-to-end 가용성이 되지는 않는다.

**예시·실행 근거:** VM/container와 region/AZ 경계를 각각 그려보고 한 AZ 장애의 영향 범위를 확인한다.

**선수개념:** OS; network

**관련 표기·별칭:** Virtualization and availability zones

**보완·검증 필요 사항:**

- 실제 provider별 AZ 장애 격리 수준은 서비스 문서 확인이 필요하다.

**초보자가 시작할 질문:**

- AZ를 여러 개 사용하면 왜 서비스 전체가 자동으로 고가용성이 되지 않나?

## 비용과 migration 전략

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 7R migration 선택과 주요 cloud 비용 항목을 비교한다.

**언제 사용하는가:** 기존 시스템을 옮길 방법과 운영 비용 항목을 정리할 때 사용한다.

**대안과 경계:** 구체 가격은 region·시간·사용량·할인에 따라 바뀌므로 현재 계산 없이 숫자를 고정하지 않는다.

**예시·실행 근거:** 현재 구조를 rehost/refactor 등 migration 후보와 compute·storage·network 항목으로 나눈다.

**선수개념:** 현재 시스템 구성; 운영 비용

**관련 표기·별칭:** Cost and migration strategy

**보완·검증 필요 사항:**

- 현재 live pricing과 실제 workload별 계산은 없다.

**초보자가 시작할 질문:**

- 서버를 cloud로 옮기면 어떤 비용이 새로 발생할 수 있나?

## 시각 구조와 보완 장면

**기존 표현**

- 환경 선택 흐름, 공동 책임 map, VM/container 및 region/AZ 도식을 제공한다.

**정적 구조의 한계**

- 실제 cloud provider와 가격은 확인하거나 시험하지 않았다.

**추가할 의미 장면**

- service model에 따라 책임이 provider/customer 사이에서 어떻게 이동하는지와 DB state 위험을 따로 표시한다.
