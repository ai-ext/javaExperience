현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** OpenAPI는 HTTP API 계약의 JSON/YAML 명세이고 Swagger UI는 명세를 렌더링하고 요청을 보내는 화면 도구다.

**언제 사용하는가:** 서버·클라이언트·여러 팀이 경로·요청·응답·인증에 합의하고 테스트할 때 계약으로 유지한다.

**대안과 경계:** UI를 끄는 것은 `/v3/api-docs`를 비활성화하는 것과 다르며 UI 자체가 API를 구현하지 않는다.

**예시·실행 근거:** 세 도구의 관계와 기본 docs/UI 경로를 설명한다.

**선수개념:** Java/Spring 기본 실행 흐름; HTTP·DB·프로세스 중 해당 개념의 접점

## springdoc 코드 우선·명세 우선

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** springdoc은 Spring mapping·DTO를 읽어 OpenAPI를 생성하고 애너테이션으로 설명·오류·보안을 보완한다. 명세 우선은 계약부터 합의한다.

**언제 사용하는가:** 기존 앱과 함께 발전하면 코드 우선, 여러 팀 외부 계약·client generation이 중요하면 명세 우선을 검토한다.

**대안과 경계:** 자동 생성이 인증·오류 상태·업무 의미까지 자동으로 맞추지는 않는다.

**예시·실행 근거:** `@Operation`, `@ApiResponse`, `@Schema` 예제가 있으나 Boot 4.1 조합은 미실행·지원표 일부 미기재다.

**선수개념:** Java/Spring 기본 실행 흐름; HTTP·DB·프로세스 중 해당 개념의 접점

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 문서의 핵심 선택과 실패 경계는 정리되어 있으나 제시된 Spring/infra 예제의 실제 실행은 별도 검증하지 않았다.

**초보자가 시작할 질문:**

- 문서에 201만 적혀 있는데 실제 서버는 400/401 ProblemDetail도 반환하면 어떤 애너테이션과 테스트가 빠졌나요?
- Boot 4.1에 Boot 3용 springdoc starter를 넣었더니 class not found가 나면 어떤 호환 세대를 맞춰야 하나요?

## servers와 Try it out·CORS

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** servers는 UI 요청의 기본 host/base URL이고 Try it out은 operation 경로를 붙여 브라우저가 실제 HTTP 요청을 보낸다.

**언제 사용하는가:** 실제 포트·환경 주소를 맞추고 UI/API가 다른 origin이면 허용 출처를 확인한다.

**대안과 경계:** 포트가 달라도 origin은 다르다. servers 변경은 서버 listener port나 API path를 바꾸지 않는다.

**예시·실행 근거:** localhost:8080과 `/api/posts/42` 예 및 CORS 조건을 설명한다.

**선수개념:** Java/Spring 기본 실행 흐름; HTTP·DB·프로세스 중 해당 개념의 접점

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 문서의 핵심 선택과 실패 경계는 정리되어 있으나 제시된 Spring/infra 예제의 실제 실행은 별도 검증하지 않았다.

**초보자가 시작할 질문:**

- Swagger UI에서 Try it out이 엉뚱한 포트로 요청한다면 경로가 아니라 어떤 기본 서버 주소를 고쳐야 하나요?
- 다른 포트의 UI에서만 CORS 오류가 발생하면 브라우저의 출처를 이루는 값은 무엇인가요?

## SecurityScheme과 API 응답 계약

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** SecurityScheme은 인증 방식 설명, SecurityRequirement는 operation에 적용, 서버 인증은 Spring Security 등이 수행한다.

**언제 사용하는가:** 인증 성공·실패, validation 오류, 404 등 실제 상태·Content-Type·ProblemDetail 스키마를 문서화한다.

**대안과 경계:** bearer schema만으로 보호가 생기지 않으며 문서와 실제 처리 결과가 다를 수 있다.

**예시·실행 근거:** 게시글 API의 bearer·ProblemDetail 응답 예시와 CI 계약 확인 절차가 있다.

**선수개념:** Java/Spring 기본 실행 흐름; HTTP·DB·프로세스 중 해당 개념의 접점

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 문서의 핵심 선택과 실패 경계는 정리되어 있으나 제시된 Spring/infra 예제의 실제 실행은 별도 검증하지 않았다.

**초보자가 시작할 질문:**
