## HTTP API 의미와 재시도

현재 판정: **부분** / 우선순위: P0

**정의와 실제 역할:** REST 계약은 URI 리소스와 HTTP 메서드·상태·표현의 의미를 일관되게 정한다. 안전성은 의도된 상태 변경 없음, 멱등성은 반복 요청의 상태 효과가 같다는 성질이다.

**언제 사용하는가:** 외부 API/CRUD에서 생성·전체교체·부분수정·삭제 의도를 구분하고, timeout 뒤 재시도를 설계한다. 목록에는 크기 상한과 안정 정렬을 둔다.

**대안과 경계:** POST는 기본 멱등을 보장하지 않는다. PUT은 전체 표현, PATCH는 정의한 일부 연산을 다룬다. offset은 임의 페이지 이동, cursor는 깊은 순차 읽기에 적합할 수 있다.

**예시·실행 근거:** 결제 POST timeout 뒤 무조건 재시도하지 않고 idempotency key와 서버측 결과 재생 계약을 둔다. If-Match 불일치는 412로 응답한다.

**선수개념:** HTTP semantics; API contracts; pagination sorting

**관련 표기·별칭:** HTTP methods; idempotency; PUT; PATCH; cursor

**판정 이유:** 개념 정의와 선택 기준은 다루지만 실습/실행이나 학습 과제의 검증 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- 예제 API/외부 서비스 호출은 실행 검증하지 않았다.

## HTTP 클라이언트·버전·캐시·timeout

현재 판정: **부분** / 우선순위: P1

**정의와 실제 역할:** RestClient는 동기 호출, WebClient는 reactive/streaming, HTTP Interface는 전송 어댑터에 연결되는 선언 계약이다. 버전 전략은 요청 버전을 추출해 handler와 비교한다.

**언제 사용하는가:** 새 동기 호출은 RestClient, 실제 reactive/streaming 요구는 WebClient, 반복되는 선언 계약은 HTTP Interface. 연결·읽기·전체 제한을 구별한다.

**대안과 경계:** timeout은 서버가 작업을 취소했다는 뜻이 아니며 retry 포함 전체 시간을 제한한다. ETag/304는 조건부 검증이고 사용자 응답은 private/no-store, public 공유는 공개 표현에만 적용한다.

**예시·실행 근거:** RestClient connect 2s/read 3s; API-Version 헤더로 v1/v2 매핑; 사용자 ETag는 인증된 표현 버전에 결합한다.

**선수개념:** HTTP cache; HTTP client timeout; authentication

**관련 표기·별칭:** RestClient; WebClient; HTTP Interface; ETag; API-Version

**판정 이유:** 개념 정의와 선택 기준은 다루지만 실습/실행이나 학습 과제의 검증 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- 예제는 미실행; 외부 HTTP 및 CDN 동작은 검증하지 않았다.

**초보자가 시작할 질문:**

- RestClient와 WebClient는 언제 다른가?
- 304면 서버에 요청이 가지 않나?
- 사용자별 응답을 CDN public으로 둬도 되나?
