## 인증·인가·object 소유권

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 사용자가 누구인지 확인하는 authentication과 특정 object/tenant에 접근할 권한을 확인하는 authorization은 다르다. UUID를 안다는 사실만으로 권한이 생기지 않는다.

**언제 사용하는가:** 계정 인증 뒤 요청한 주문·파일이 해당 사용자 소유인지 확인할 때 사용한다.

**대안과 경계:** 로그인 여부만 검사하면 다른 사람의 object ID를 바꿔 접근하는 IDOR 문제가 남을 수 있다.

**예시·실행 근거:** 같은 user가 자기 주문과 타인 주문 ID를 조회할 때 각각의 응답을 비교한다.

**선수개념:** identity; resource ownership

**관련 표기·별칭:** Auth, authorization and object ownership

**보완·검증 필요 사항:**

- 현재 사례 설명은 있으나 실제 제품 endpoint의 권한을 테스트하지 않았다.

**초보자가 시작할 질문:**

- 로그인한 사용자가 다른 사람 주문 ID를 넣으면 무엇을 검사해야 하나?

## CORS·CSRF·TLS·입출력 경계

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** CORS는 브라우저가 다른 origin의 응답을 읽게 할지 제어한다. CSRF는 browser가 자동 첨부하는 credential을 악용할 수 있고 TLS는 전송 경계를 보호한다.

**언제 사용하는가:** browser API 호출, 상태 변경 요청, 사용자 입력과 출력 인코딩 경계를 나눌 때 사용한다.

**대안과 경계:** CORS는 서버 인가나 CSRF 방어가 아니다. TLS도 안전한 입력 검증과 출력 escaping을 대신하지 않는다.

**예시·실행 근거:** TLS 연결, CORS 차단, CSRF cookie 요청, DB parameter와 HTML escaping을 다른 단계로 구분한다.

**선수개념:** HTTP origin; cookie; 입력 검증

**관련 표기·별칭:** CORS, CSRF, TLS and output/input boundary

**보완·검증 필요 사항:**

- 각 보안 경계의 같은 요청을 실제 브라우저에서 전체 검증하지 않았다.

**초보자가 시작할 질문:**

- CORS를 허용하면 로그인된 사용자 권한 검사도 끝난 것인가?

## password·secret·dependency·log 보안

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 비밀번호는 느린 password hashing으로 저장하고 secret은 rotation하며 dependency 취약성과 log 개인정보 노출을 관리한다.

**언제 사용하는가:** 인증정보 보관, 운영 key 교체, dependency 점검과 민감 로그를 다룰 때 사용한다.

**대안과 경계:** 암호화나 단순 hash는 password hashing과 다르다. credential을 log에 남기지 않으며 운영 정책은 조직/제품에 맞춰야 한다.

**예시·실행 근거:** password hash, secret 교체, SBOM/SCA 보고서와 log redaction 예를 비교한다.

**선수개념:** 인증; secret 관리

**관련 표기·별칭:** Passwords, secrets, dependencies and logs

**보완·검증 필요 사항:**

- 현재 정책의 구체 설정과 제품 운영은 별도 기준 확인이 필요하다.

**초보자가 시작할 질문:**

- 비밀번호를 DB에 그대로 저장하지 않고 어떤 방식으로 보호하나?

## 시각 구조와 보완 장면

**기존 표현**

- 보안 요청 pipeline, CORS와 authentication 흐름을 보여준다.

**정적 구조의 한계**

- 핵심 보안 경계가 core 앵커에서 접힌 카드 안에 있어 실제 요청 상태가 바로 드러나지 않는다.

**추가할 의미 장면**

- 하나의 요청에서 TLS→CORS→authentication→object ownership→DB parameter binding이 각각 무엇을 판단하는지 표시한다.

## 실제 캡처 관찰

- desktop/mobile 요약은 authentication과 authorization 및 CORS/CSRF를 구분한다. core 앵커의 첫 절과 용어집은 접혀 security flow가 보이지 않는다. 익명 401, 권한 부족 403, CORS의 브라우저 응답 읽기, CSRF cookie 요청을 첫 화면의 하나의 비교 장면으로 보여줄 필요가 있다.
