## static 상태와 instance 상태

현재 판정: **미검증** / 우선순위: high

**정의와 실제 역할:** static 필드는 classloader가 정의한 클래스에 속하고 instance 필드는 객체별로 존재한다.

**언제 사용하는가:** 공유 상수나 인스턴스 상태가 필요 없는 동작을 둘 때 선택한다.

**대안과 경계:** Spring singleton은 컨테이너 안 Bean 인스턴스 범위이고 static은 클래스 상태이므로 같은 뜻이 아니다. 요청별 변경값을 static에 두면 요청 간 값이 섞일 수 있다.

**예시·실행 근거:** 두 객체의 instance counter와 static counter를 비교하고 동시 요청의 값 섞임을 확인한다.

**선수개념:** 클래스와 객체; JVM

**관련 표기·별칭:** static vs instance state; class variable; instance field; shared mutable state

**보완·검증 필요 사항:**

- Spring 실행 예제는 미실행이며 중첩 클래스 범위 비교는 없다.

## static dispatch와 class 초기화

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** static 메서드는 컴파일 시 참조 타입으로 선택되고 클래스 초기화는 능동 사용 시 실행된다.

**언제 사용하는가:** static 메서드 선택이나 초기화 순서가 결과에 영향을 주는 코드를 읽을 때 사용한다.

**대안과 경계:** static 메서드는 override가 아니라 hiding이다. class loading과 initialization은 다르며 constant variable 접근은 초기화를 유발하지 않을 수 있다.

**예시·실행 근거:** 부모 타입 참조의 static/instance 호출 결과와 초기화 로그를 비교한다.

**선수개념:** 상속; JVM class loading

**관련 표기·별칭:** static dispatch and initialization; method hiding; class initialization

**보완·검증 필요 사항:**

- static nested와 inner class의 객체 생명주기 차이는 설명만 있다.

## static final과 의존성 주입

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** final은 변수 재할당을 막지만 참조 객체 내부 변경까지 막지는 않는다. Spring 설정값은 관리 대상 인스턴스의 생성자 의존성으로 전달한다.

**언제 사용하는가:** 변하지 않는 상수와 서비스 의존성을 구분할 때 사용한다.

**대안과 경계:** List 참조가 final이어도 내용은 변경 가능하다. static 필드에 @Value를 붙인 주입은 지원되지 않으며 일부 infrastructure BeanFactoryPostProcessor는 별도 예외다.

**예시·실행 근거:** TextRules의 static 상수와 WelcomeService 생성자 @Value 주입을 비교한다.

**선수개념:** Spring DI; final

**관련 표기·별칭:** static final and DI; deep immutability; constructor injection

**보완·검증 필요 사항:**

- Boot 애플리케이션 예제는 실행되지 않았다.
