**정의와 실제 역할:** 가입, 연락처 인증, password recovery와 login 실패를 상태 전이로 표현한다. 미인증 계정은 만료/정리 기준이 필요하다.

**언제 사용하는가:** 회원가입, 인증코드 재전송, 계정 잠금과 password reset API를 설계할 때 사용한다.

**대안과 경계:** 존재 여부를 응답에서 노출하면 계정 열거 위험이 생긴다. 만료/재사용/잠금 상태는 각기 다르다.

**선수개념:** 인증; HTTP response

**관련 표기·별칭:** Account state machine

**보완·검증 필요 사항:**

## 짧은 인증 코드와 reset token 저장

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 6자리 code는 HMAC 등 검증 가능한 형태와 시도 제한·짧은 TTL이 필요하고 reset token은 원문 대신 digest 저장을 고려한다.

**언제 사용하는가:** 이메일/전화 인증과 password reset token을 저장하고 검증할 때 사용한다.

**대안과 경계:** 짧은 code는 추측 공간이 좁아 제한이 필요하다. reset token 원문을 DB/log에 남기면 탈취 영향이 커진다.

**예시·실행 근거:** 같은 code의 1회 사용·만료·재사용 거부와 digest 저장을 확인한다.

**선수개념:** HMAC; TTL; token digest

**관련 표기·별칭:** Short code and reset-token storage

**보완·검증 필요 사항:**

- 원문은 설명 중심이며 token 저장·소비를 실행하지 않았다.

**초보자가 시작할 질문:**

- 코드가 만료되거나 이미 한 번 사용됐다면 서버는 무엇을 확인해야 하나?

## 분산 시도 제한과 session 무효화

현재 판정: **미검증** / 우선순위: high

**정의와 실제 역할:** 계정과 IP별 시도 제한, Redis Lua의 INCR와 최초 EXPIRE 결합, password 변경 뒤 refresh/session 폐기를 제안한다.

**언제 사용하는가:** 여러 instance에 걸친 무차별 시도 제한과 계정 보안 상태 변경을 설계할 때 사용한다.

**대안과 경계:** 각 명령을 따로 보내면 경쟁 조건이나 만료 설정 누락이 생길 수 있다. 비밀번호 변경 뒤 기존 session을 유지할지 폐기할지 정책이 필요하다.

**예시·실행 근거:** 동시 요청의 시도 횟수, TTL과 비밀번호 변경 전후 session 상태를 확인한다.

**선수개념:** Redis atomic command; session/token

**관련 표기·별칭:** Distributed attempt limit and session invalidation

**보완·검증 필요 사항:**

- 실행되지 않은 예제이며 경쟁 요청 결과를 실제 Redis에서 확인하지 않았다.

**초보자가 시작할 질문:**

**추가된 내용:** 원문 Markdown은 공개본과 byte 동일하며 SHA-256도 동일하다. 공개 HTML과 보강 HTML은 다르다(공개 7055ac262e8c2a287f857595b215dc473f659f4f2d4c7f3f605f132be766bad0, 보강 c483fac9fc34d94aeee592a14865a50562a72fb0ed1d4e5a9dd655044335a30b). 보강 화면은 외부 연습 schema copy에 migration을 적용하고 MySQL 8.4.11/Redis 10.2/Java21 환경의 관측 범위를 표시한다. private MySQL test에서는 동일 email로 두 독립 connection의 동시 가입을 시도해 사전 count check를 둘 다 통과한 뒤 UNIQUE constraint가 단 한 INSERT만 허용하는 상황을 보여준다. `PENDING` 기본 상태 및 credential version 컬럼은 추가했으나 기존 password hash backfill과 NOT NULL 전환은 실행하지 않았다. 로그인 JWT filter/API proxy는 관찰했으나 email/SMS/Java25는 미실행이다.

**공개본과의 차이:** 공개 원문은 가입/인증/비밀번호 복구, 계정·IP 시도 제한과 session 폐기 정책을 설명한다. 보강은 사전 중복 조회를 통과하는 경쟁 요청도 DB UNIQUE가 최종 차단한다는 실제 결과, migration 컬럼/동시 INSERT 시나리오를 보탰으나 공개 HTML에는 미통합이다. MySQL 경합 관찰을 email/SMS·운영 로그인 API 전체가 실행됐다고 해석하지 않는다.

**비교 범위:** desktop은 initial DDL과 두 connection의 race를 표시하고, 결과 순서가 어느 connection이 성공했는지 고정하지 않는다고 안내한다. mobile 첫 화면에서는 disclaimer와 첫 장면만 보여 나머지는 스크롤해야 한다. MySQL 8.4.11/Redis 10.2/Java21의 별도 환경이며 외부 schema copy에 한정된다. user/practice DB를 바꾸지 않았고 Java25·메일/SMS·전체 API/HTTP 시나리오를 실행하지 않았다.
