## DTO as external API contract and mass-assignment boundary

현재 판정: **부분** / 우선순위: P0

**정의와 실제 역할:** DTO는 외부 API 계약이며 Entity와 모양/생명주기가 다르다.

**언제 사용하는가:** 요청은 허용할 입력, 응답은 공개할 필드만 담고 엔티티와 분리한다.

**대안과 경계:** Entity 직접 직렬화는 내부 필드 노출·연관관계 cycle·lazy SQL·API 계약 결합 위험이 있다.

**예시·실행 근거:** 요청 DTO에서 id/role 등 수정 금지 필드를 받지 않고 응답 DTO allowlist를 둔다.

**선수개념:** DTO vs Entity; request/response contract

**관련 표기·별칭:** request DTO; response DTO; Entity direct response; command DTO

**판정 이유:** 개념 정의와 적용 기준은 확인되나 실제 실행/학습자 수행 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- base example 미실행; 보강 실험은 H2 standalone이지 Boot HTTP/OSIV/MySQL 증거가 아니다.

## Entity serialization, lazy loading, OSIV and cycles

현재 판정: **부분** / 우선순위: P0

**정의와 실제 역할:** Entity 응답은 직렬화 과정에서 LAZY 연관 조회를 추가로 실행하거나 양방향 참조 순환, 내부 필드 노출을 만들 수 있다.

**언제 사용하는가:** 응답 직렬화 도중 getter가 LAZY 관계를 초기화하면 SQL이 추가될 수 있고 양방향 연관은 순환 참조를 만든다.

**대안과 경계:** Service tx 안에서 필요한 fetch plan으로 조회한 뒤 DTO로 변환한다.

**예시·실행 근거:** OSIV는 요청 내 EntityManager 수명을 늘려 문제를 가릴 뿐 DTO/query plan을 대체하지 않는다. Jackson cycle exception을 실제 stack overflow와 혼동하지 않는다. 추가 예: close/open session 조회와 DTO projection 결과를 비교하고 SQL 수를 기록한다.

**선수개념:** Jackson serialization; lazy association; OSIV

**관련 표기·별칭:** LazyInitializationException; open-in-view; Jackson getter traversal; N+1 serialization

**판정 이유:** 개념 정의와 적용 기준은 확인되나 실제 실행/학습자 수행 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- Hibernate proxy
- Jackson object graph
- transaction boundary

**초보자가 시작할 질문:**

- 추가 H2 experiment는 원문처럼 standalone 범위; MySQL/HTTP/Boot OSIV로 확대하지 않는다.

## Entity-to-DTO mapping methods

현재 판정: **부분** / 우선순위: P1

**정의와 실제 역할:** Entity-to-DTO 변환 방식

**언제 사용하는가:** 수동 매핑, MapStruct, service 조립, repository projection은 변환 책임과 DB 조회 범위가 다르다.

**대안과 경계:** 단순 조립은 controller/service, 반복 필드 mapping은 mapper, 조회 전용 축소는 projection을 사용한다.

**예시·실행 근거:** Mapper가 Entity getter를 부르면 LAZY SQL/N+1이 날 수 있고 MapStruct가 fetch 계획을 대신하지 않는다. 추가 예: 단건 getName 접근과 목록 매핑의 SELECT 수를 비교한다.

**선수개념:** mapping layer; entity getter behavior

**관련 표기·별칭:** manual mapper; MapStruct; ModelMapper; projection

**판정 이유:** 개념 정의와 적용 기준은 확인되나 실제 실행/학습자 수행 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- mapping layer
- lazy association

- MapStruct example 미실행; progress evidence는 H2 only.

## DTO projection and query cost

현재 판정: **부분** / 우선순위: P1

**정의와 실제 역할:** DTO projection과 query 비용

**언제 사용하는가:** Projection은 반환 구조를 좁히고 query에서 필요한 칼럼만 읽도록 설계할 수 있다.

**대안과 경계:** 큰 목록/검색에서 일부 정보만 필요하고 entity behavior가 필요하지 않을 때.

**예시·실행 근거:** DTO를 도입해도 N+1은 자동 해결되지 않으며 fetch/join/projection을 SQL 로그로 확인한다. 추가 예: repository projection 한 쿼리와 entity list mapper의 추가 SELECT를 비교한다.

**선수개념:** SQL projection; N+1 query

**관련 표기·별칭:** constructor projection; interface projection; select only required columns

**판정 이유:** 개념 정의와 적용 기준은 확인되나 실제 실행/학습자 수행 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- SQL projection
- query plan

**초보자가 시작할 질문:**

- actual DB/SQL output은 본문 실험 외 추가 확인 필요.

## Record and nested mutability

현재 판정: **부분** / 우선순위: P2

**정의와 실제 역할:** Record는 얕은 불변 데이터 타입

**언제 사용하는가:** record component 참조는 final이지만 그 안의 mutable collection이 자동 복사/불변화되지는 않는다.

**대안과 경계:** 값 운반 DTO/event에 record를 쓰고 collection은 필요 시 방어적 복사한다.

**예시·실행 근거:** record는 JPA entity proxy/가변 lifecycle 객체를 대체하는 만능 annotation이 아니다. 추가 예: Record(List) 생성 뒤 원본 list 변경을 관찰하고 defensive copy와 비교한다.

**선수개념:** record; mutable collection

**관련 표기·별칭:** record DTO; shallow immutability

**판정 이유:** 개념 정의와 적용 기준은 확인되나 실제 실행/학습자 수행 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- Java records
- mutable collections
