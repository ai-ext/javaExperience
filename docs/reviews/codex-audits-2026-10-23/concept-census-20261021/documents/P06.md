## CRUD HTTP 상태 계약

현재 판정: **부분** / 우선순위: critical

**정의와 실제 역할:** 게시글 생성·조회·수정·삭제가 HTTP method와 status code로 드러납니다. POST 생성은 201+Location, 단건/PUT은 200, DELETE는 204, 없는 id는 404, 입력 오류는 400입니다.

**언제 사용하는가:** 클라이언트가 결과를 분기하고 생성 자원을 다시 찾을 수 있도록 상태와 Location을 명시합니다.

**대안과 경계:** 204는 본문이 없는 응답입니다. H2 성공은 MySQL 호환성을 보장하지 않습니다.

**예시·실행 근거:** 예제는 curl로 POST→GET→PUT→DELETE→404 흐름을 제시하지만 Spring 실행은 미실행이라고 표시합니다.

**선수개념:** HTTP request/response; JSON

**보완·검증 필요 사항:**

- 예제 실행은 미실행으로 표시되어 있어 코드를 동작 근거로 단정할 수 없습니다.

## 요청 DTO 검증과 Entity 매핑

현재 판정: **부분** / 우선순위: critical

**정의와 실제 역할:** PostRequest가 허용 입력을 제한하고 @Valid가 제약을 실행합니다. Service가 요청 필드로 Post Entity를 만들고 저장한 뒤 PostResponse로 공개 값을 매핑합니다.

**언제 사용하는가:** 외부가 바꿀 수 있는 필드와 내부 저장 필드를 분리하고, 변환 위치를 Service/Mapper에 둡니다.

**대안과 경계:** 요청 DTO·JPA Entity·응답 DTO는 같은 값이어도 역할이 다릅니다. Entity를 직접 요청/응답으로 쓰면 대량 할당과 계약 유출 위험이 있습니다.

**예시·실행 근거:** `PostRequest → new Post → repository.save → PostResponse`; 코드 예제는 미실행입니다.

**선수개념:** record/DTO; JPA Entity; Jackson

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 예제 실행은 미실행으로 표시되어 있어 코드를 동작 근거로 단정할 수 없습니다.

## 쓰기 트랜잭션·readOnly·변경 감지

현재 판정: **부분** / 우선순위: critical

**정의와 실제 역할:** Service 클래스는 readOnly=true, 쓰기 메서드는 @Transactional로 덮습니다. 관리 상태 Entity의 필드 변경은 커밋 시 변경감지로 UPDATE될 수 있습니다.

**언제 사용하는가:** 여러 DB 변경을 한 유스케이스 경계에서 묶고 조회 메서드는 읽기 목적을 표시합니다.

**대안과 경계:** readOnly는 DB 권한 제한이 아닙니다. 벌크 UPDATE와 영속성 컨텍스트의 객체 상태도 따로 관리해야 합니다.

**예시·실행 근거:** update에서 `get(id)` 후 `change(...)`하며 save를 다시 부르지 않는 이유를 S09로 연결합니다. Spring SQL 출력은 미실행입니다.

**선수개념:** Transaction; 영속성 컨텍스트

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 예제 실행은 미실행으로 표시되어 있어 코드를 동작 근거로 단정할 수 없습니다.

**초보자가 시작할 질문:**

## Web slice vs integration testing

현재 판정: **부분** / 우선순위: critical

**정의와 실제 역할:** WebMvcTest는 MVC와 Controller 계약을 분리해 확인하고, SpringBootTest와 MockMvc는 요청부터 H2 저장·조회까지 연결합니다.

**언제 사용하는가:** Controller HTTP 계약만 검증하면 slice 테스트, 애플리케이션 경로와 저장 결과까지 확인하면 통합 테스트를 선택합니다.

**대안과 경계:** slice 테스트는 전체 애플리케이션 구성을 시작하지 않습니다. 통합 테스트는 범위가 넓어 설정과 실행 비용이 더 큽니다.

**예시·실행 근거:** 생성 요청의 Location을 받고 그 주소로 GET해 저장된 결과를 확인하는 흐름을 설명합니다. 테스트 코드는 미실행입니다.

**선수개념:** JUnit, MockMvc, Spring context.

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- Examples not run; test isolation/data cleanup/concurrency absent.

## 실제 캡처 관찰

- 데스크톱 첫 화면에는 CRUD 상태 코드(201/200/204/400/404)와 섹션 목차가 보인다. 이 화면에는 요청→Entity→DB 행→응답 상태 흐름이 시각화되지 않았다.
- 모바일 요약은 세로 배치에서 읽을 수 있고 가로 넘침은 보이지 않는다. API 흐름은 모바일 이미지의 화면 아래에 있다.
- core 캡처에는 번호형 CRUD 규칙과 접힌 후속 섹션이 보인다. 요청 payload, Entity 상태, SQL, DB 관찰이 이 화면에서 시각적으로 연결되지는 않는다.

**관찰 범위:** 캡처에는 실제 curl 요청이나 DB 상태가 보이지 않는다. 시각 관찰은 해당 화면에 한정하며 런타임 동작을 주장하지 않는다.
