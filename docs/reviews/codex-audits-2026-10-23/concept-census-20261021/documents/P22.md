## DataSource/EMF/transaction manager 경계

현재 판정: **미검증** / 우선순위: high

**정의와 실제 역할:** 각각 연결 입구, JPA 단위, 자원 트랜잭션 경계다.

**언제 사용하는가:** 여러 DB별 persistence unit을 구성할 때

**대안과 경계:** @Primary는 기본 주입 후보이지 분산 commit이 아니다.

**예시·실행 근거:** users/orders에 각 DS, EMF, 매니저, repo package를 연결한다.

**선수개념:** Spring Bean 주입; JDBC 연결; JPA 영속성 단위

**관련 표기·별칭:** DataSource; EntityManagerFactory; PlatformTransactionManager

**보완·검증 필요 사항:**

- 실제 코드 미실행. 다중 EMF는 표면이 복잡해 먼저 topology 그림이 필요하다.

## 별도 DB와 primary/replica 구분

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 도메인별 독립 DB는 DS/EMF 두 세트, 같은 스키마 replica 라우팅은 router 뒤에 풀 두 개와 EMF 하나다.

**언제 사용하는가:** 별도 DB 소유권 또는 read scaling을 설계할 때

**대안과 경계:** 독립 DB는 자동 replication 아님. 실습 컨테이너 두 개 역시 replication을 설정하지 않는다.

**예시·실행 근거:** users/orders 분리와 routing 토폴로지 비교

**선수개념:** Repository와 EntityManagerFactory 연결

**관련 표기·별칭:** domain DB; read replica

**보완·검증 필요 사항:**

- 초보 도식과 데이터 양쪽 DB 비교 화면은 필요하다.

## readOnly 기반 routing·lazy connection

현재 판정: **미검증** / 우선순위: high

**정의와 실제 역할:** 새 connection 요청 때 transaction readonly 상태를 lookup key로 읽는다.

**언제 사용하는가:** primary/replica 읽기 분기 시

**대안과 경계:** readOnly는 힌트이며 쓰기 권한은 아님. 커넥션 조기 획득 시 default write를 고를 수 있어 지연 proxy 필요.

**예시·실행 근거:** GET은 read, POST는 write pool 로그를 확인한다.

**선수개념:** 트랜잭션 프록시; JDBC 커넥션 생명주기

**관련 표기·별칭:** AbstractRoutingDataSource; LazyConnectionDataSourceProxy

**보완·검증 필요 사항:**

- 미실행이며 실제 pool trace 필요.

**초보자가 시작할 질문:**

- 왜 @Transactional(readOnly=true)가 어느 풀을 고르나?

## 복제 지연·다중 DB atomicity

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 비동기 복제 지연과 두 로컬 transaction의 부분 commit을 구별한다.

**언제 사용하는가:** read-after-write 최신성이 필요하거나 cross DB 갱신 시

**대안과 경계:** 최신 값은 primary. 두 local transaction은 원자 단위 아님; outbox는 업무 행과 동일 DB commit.

**예시·실행 근거:** replica에 이전 값, primary 최신 값을 관찰하고 outbox로 전달한다.

**선수개념:** 복제 지연; 트랜잭션

**관련 표기·별칭:** replica lag; outbox

**보완·검증 필요 사항:**

- outbox 처리 과정/멱등성 실행 실습은 생략.

**초보자가 시작할 질문:**
