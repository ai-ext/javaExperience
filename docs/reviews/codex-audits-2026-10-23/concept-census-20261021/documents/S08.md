## 트랜잭션 관리자와 rollback proxy

현재 판정: **부분** / 우선순위: P0

**정의와 실제 역할:** PlatformTransactionManager는 자원 경계를 시작·커밋·롤백하고 Transactional은 프록시가 읽는 메타데이터다. REQUIRED는 참여하거나 없으면 시작한다. 기본 롤백은 RuntimeException/Error이며 checked 예외는 보통 commit된다.

**언제 사용하는가:** 같은 DB의 여러 변경을 서비스 유스케이스로 묶고 업무 실패 checked exception에는 rollbackFor를 선언한다.

**대안과 경계:** flush는 commit이 아니다; readOnly는 힌트다. self invocation은 proxy를 우회한다. DB transaction은 broker/HTTP를 포함하지 않는다.

**예시·실행 근거:** 이체 서비스가 debit/credit을 REQUIRED 트랜잭션으로 묶고 checked InsufficientFunds에는 rollbackFor를 둔다.

**선수개념:** AOP proxy; SQL transaction; exception hierarchy

**관련 표기·별칭:** PlatformTransactionManager; REQUIRED; rollbackFor; readOnly

**판정 이유:** 개념 정의와 선택 기준은 다루지만 실습/실행이나 학습 과제의 검증 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- 예제 미실행; 실제 DB 격리/자원 동작은 검증하지 않았다.

**초보자가 시작할 질문:**

- checked exception에서 데이터가 commit될 수 있는 이유?
- readOnly는 DB 쓰기를 차단하나?
- @Transactional은 broker 전송도 rollback하나?

## 전파·격리·after commit·outbox

현재 판정: **부분** / 우선순위: P1

**정의와 실제 역할:** 전파는 논리 호출을 물리 자원 경계에 참여시키거나 새로 만든다. 격리는 DB가 동시 읽기/쓰기 결과를 제어한다. after-commit listener는 프로세스 내 시점이며 outbox는 전달 의도를 DB와 함께 저장한다.

**언제 사용하는가:** 기본 REQUIRED, 독립 커밋만 REQUIRES_NEW, savepoint 지원 시 NESTED. 외부 이벤트 반드시 전달돼야 하면 outbox를 둔다.

**대안과 경계:** REQUIRES_NEW는 별도 연결/독립 커밋; NESTED는 같은 물리 tx savepoint. 격리 동작은 DB별이며 serializable도 실패·재시도 가능.

**예시·실행 근거:** order row와 outbox event를 함께 커밋하고 relay가 발행, consumer는 event ID로 중복 처리한다.

**선수개념:** DB isolation; connection pool; message delivery

**관련 표기·별칭:** rollback-only; UnexpectedRollbackException; savepoint; TransactionalEventListener; outbox

**판정 이유:** 개념 정의와 선택 기준은 다루지만 실습/실행이나 학습 과제의 검증 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- DB별 isolation과 savepoint 동작은 대상 DB 통합 검증이 필요.

**초보자가 시작할 질문:**

- REQUIRED 내부 rollback-only가 바깥 commit에 미치는 영향?
- commit 뒤 프로세스가 종료되면 이벤트는?
- SERIALIZABLE이면 재시도 불필요한가?
