## JVM runtime areas와 frame

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** JVMS는 heap, stack, method area 등 논리 영역을 정합니다. 메서드 호출마다 frame의 local variable array/operand stack이 만들어집니다.

**언제 사용하는가:** GC/Thread dump/JVM 영역을 설명할 때 spec model과 HotSpot 물리 구현을 나눕니다.

**대안과 경계:** 프레임이 반드시 OS stack에 있고 객체가 반드시 특정 물리 공간에 있다는 의미는 아닙니다.

**예시·실행 근거:** 메모리 영역도와 aload/invoke 바이트코드 설명.

**선수개념:** JVM process; method invocation

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 실제 메모리 layout은 VM implementation에 따릅니다.

**초보자가 시작할 질문:**

## Class loading/linking/initialization

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** Loading은 bytes를 정의하고 linking은 verify/prepare/resolve, initialization은 <clinit>을 실행합니다. 해석 시점은 지연될 수 있습니다.

**언제 사용하는가:** 특정 API 호출에서 늦게 난 LinkageError 원인을 단계로 나눠 조사합니다.

**대안과 경계:** 준비 시 static field 기본값과 초기화 시 명시 대입은 다릅니다.

**예시·실행 근거:** 반복 처리 중 예외가 발생한 위치와 finally 실행 결과를 보여 줍니다.

**선수개념:** class file; static initialization

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- JVM implementation can defer linking stages.

**초보자가 시작할 질문:**

- `static int size=10`에서 prepare와 initialize 단계에 값이 각각 어떻게 되나요?
- NoSuchMethodError가 서버 시작 뒤 특정 요청에서 처음 보일 수 있는 이유는?

## 클래스로더와 type identity

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 클래스 타입 정체성은 바이너리 이름과 defining ClassLoader 조합입니다.

**언제 사용하는가:** plugin/app server에서 공유 인터페이스는 공통 parent loader가 정의하도록 경계를 둡니다.

**대안과 경계:** load 요청자(start loader)와 define한 loader는 다를 수 있습니다. 이름 같은 클래스도 대입되지 않을 수 있습니다.

**예시·실행 근거:** 예외의 cause와 suppressed 목록을 출력해 원인·정리 실패를 구분합니다.

**선수개념:** ClassLoader API; interface API

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 실제 application server delegation은 컨테이너 정책별로 확인.

**초보자가 시작할 질문:**

- 로그에 X cannot be cast to X가 보이면 두 X에서 어떤 기준을 비교해야 하나요?
- plugin이 공유 interface까지 따로 define하면 어떤 경계가 갈라지나요?

## invoke opcodes와 Module/JPMS

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** invokevirtual/interface/runtime receiver dispatch와 invokestatic/special/indy 호출 경로는 다릅니다. JPMS는 requires/exports/opens 모듈 경계로 classloader와는 별개입니다.

**언제 사용하는가:** javap -c -v로 컴파일 결과를 확인하고 일반 API/깊은 reflection에 맞는 exports/opens를 둡니다.

**대안과 경계:** invokedynamic은 bootstrap으로 CallSite를 연결하며 reflection이 아닙니다.

**예시·실행 근거:** CallSitesDemo 출력 및 javap opcode; JPMS diagram.

**선수개념:** javap; JPMS

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 컴파일/JDK21에서 실행한 예와 Java25 module behaviors를 구분.

**초보자가 시작할 질문:**

- Java 메서드 호출에서 static, virtual, interface, constructor는 어떤 opcode 차이를 보이나요?
- 모듈에서 공개 method 사용과 private field reflection은 모두 exports 하나로 해결되나요?

**근거:**

## 클래스로더 누수와 재배포

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** GC root에서 application class/ThreadLocal/TCCL/Listener를 거쳐 loader까지 참조가 이어지면 해당 클래스 메타데이터 회수가 막힙니다.

**언제 사용하는가:** 서버 stop/redeploy 시 ThreadLocal.remove, Executor 종료, listener 해제, TCCL 복구를 합니다.

**대안과 경계:** 개별 class unload API는 없고 마지막 강한 참조 해제 후 reclaim 시점은 구현/GC에 달립니다.

**예시·실행 근거:** 반환값과 예외를 각각 assertion으로 확인하는 테스트 예시입니다.

**선수개념:** ThreadLocal; GC roots; app lifecycle

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- Actual heap dump not captured in tutorial.

**초보자가 시작할 질문:**

- redeploy마다 Metaspace가 늘면 어떤 shared root 경로를 먼저 살펴볼까요?
- 새 ClassLoader 변수를 null로 대입했다고 즉시 unload된다고 볼 수 없는 이유는?
