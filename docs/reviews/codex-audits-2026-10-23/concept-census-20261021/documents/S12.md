## Security filter chain·authentication

현재 판정: **부분** / 우선순위: P0

**정의와 실제 역할:** DelegatingFilterProxy는 Servlet 컨테이너를 Spring Security 빈에 연결한다. FilterChainProxy가 처음 일치하는 SecurityFilterChain을 고른다. AuthenticationManager는 provider에 위임하고 SecurityContext는 인증 주체/권한을 담는다.

**언제 사용하는가:** URL chain 순서와 인증 공급자를 구성하고 브라우저 요청 간 인증을 유지하려면 SecurityContextRepository/session을 사용한다.

**대안과 경계:** permitAll은 인가 허용이지만 filter chain을 계속 돈다. chain 제외는 보안 처리 자체를 건너뛸 수 있다. ThreadLocal holder는 현재 실행 접근, repository는 다음 요청 persistence.

**예시·실행 근거:** 필터에서 ID/password 인증을 수행하고 SecurityContextRepository에 저장해 다음 요청에서 복원한다. URL chain은 앞의 first match가 적용된다.

**선수개념:** Servlet filters; authentication vs authorization; thread local

**관련 표기·별칭:** DelegatingFilterProxy; FilterChainProxy; SecurityFilterChain; AuthenticationManager; SecurityContextRepository

**판정 이유:** 개념 정의와 선택 기준은 다루지만 실습/실행이나 학습 과제의 검증 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- 예제 미실행; Security chain matcher ordering not tested.

**초보자가 시작할 질문:**

## Session·CSRF/CORS·method security·password

현재 판정: **부분** / 우선순위: P0

**정의와 실제 역할:** Session cookie는 요청간 context를 복원하고 fixation defense는 인증 후 session ID를 바꾼다. CSRF는 쿠키 자동 첨부를 악용한 위조 요청 방어, CORS는 브라우저 cross-origin 응답 정책이다. Method security는 service method proxy authorization.

**언제 사용하는가:** 브라우저 session 앱에서 CSRF 유지, Secure/HttpOnly/SameSite 설정, @EnableMethodSecurity 활성화, adaptive password hash 사용.

**대안과 경계:** CORS는 CSRF/auth가 아님. HttpOnly는 cookie 읽기를 줄이나 XSS의 인증 요청을 막지 않는다. async context 자동 전파되지 않는다. hasRole은 ROLE_ prefix, hasAuthority exact string.

**예시·실행 근거:** POST logout에 CSRF token; URL+method authorization; DelegatingPasswordEncoder 해시.

**선수개념:** browser cookie model; principal/authority; AOP proxy

**관련 표기·별칭:** CSRF; CORS; SameSite; @EnableMethodSecurity; ROLE_; PasswordEncoder

**판정 이유:** 개념 정의와 선택 기준은 다루지만 실습/실행이나 학습 과제의 검증 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- 실제 browser login/cookie/CSRF POST는 실행하지 않았다.

**초보자가 시작할 질문:**

- CORS가 CSRF를 막나?
- HttpOnly면 XSS가 없어지나?
- async worker가 security context를 이어받나?
- hasRole이 검사하는 문자는?

## 실제 캡처 관찰

- 첫 화면에는 인증 성공과 관리자 권한 부족의 차이를 사용자 상태별 카드로 시각화하고 실제 경로·코드는 건드리지 않는 설명용이라고 표시한다.
- 모바일에서 익명/일반/관리자 선택 버튼과 인증 상태가 보여 정책 차이 탐색은 가능하지만 실제 filter chain 검증은 아니다.
- 이미지에 선택된 일반 사용자와 관리자 거부 결과가 보이지만 직접 클릭/action 이후 캡처는 하지 않았다.
