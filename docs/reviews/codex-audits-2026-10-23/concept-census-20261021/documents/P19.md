## Spring Boot DataSource/JPA 연결 경로

현재 판정: **미검증** / 우선순위: high

**정의와 실제 역할:** Boot starter/driver에서 DataSource·Hikari·Hibernate가 연결되고 EntityManager SQL이 JDBC를 통해 MySQL에 도달하는 구성

**언제 사용하는가:** JPA 앱에서 연결 수명과 트랜잭션을 프레임워크에 맡길 때

**대안과 경계:** JDBC 직접 관리는 자원 수명을 직접 책임진다. PostgreSQL 교체도 드라이버·URL·DDL 차이를 동반한다

**예시·실행 근거:** Customer save 후 POST/GET JSON과 MySQL 행을 비교한다

**선수개념:** Java classpath와 dependency; HTTP 요청; SQL 행; JDBC 연결 URL

**관련 표기·별칭:** DataSource; HikariCP; Hibernate; JDBC

**보완·검증 필요 사항:**

- 요청부터 INSERT까지 코드 경로 장면이 없다. Spring 예제는 미실행.

## 프로파일·환경변수·컨테이너 주소

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 환경별 접속값을 profile/env로 나누고 실행 네트워크에 맞는 주소를 정한다

**언제 사용하는가:** 로컬·테스트·운영 DB 분리 및 컨테이너 통신 시

**선수개념:** 환경변수; 포트 매핑; 호스트명

**관련 표기·별칭:** application.yml; JDBC URL; port mapping

**보완·검증 필요 사항:**

- 비밀/TLS 로컬 전용 설정은 더 눈에 띄는 경고가 필요하다.

## ddl-auto와 migration

현재 판정: **부분** / 우선순위: high

**보완·검증 필요 사항:**

## Pool·SQL 진단·OSIV

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** Hikari는 제한 커넥션을 재사용하고 OSIV는 영속성 컨텍스트 유지범위를 정한다

**언제 사용하는가:** pool 고갈/로그 진단 및 응답 전 연관조회 경계 설정

**대안과 경계:** 풀 증가는 느린 SQL·누수·긴 트랜잭션 원인 제거와 다르다. bind 로그는 민감값을 노출할 수 있다

**예시·실행 근거:** connection timeout을 원인별로 좁히고 service transaction에서 연관데이터 준비

**선수개념:** 트랜잭션; 지연 로딩; 로그 보안

**관련 표기·별칭:** connection timeout; open-in-view

**보완·검증 필요 사항:**

- 실제 메트릭·대여/반납 관찰이 없다.

**초보자가 시작할 질문:**

- timeout 때 풀만 키우면 되나?

## Actuator health와 Testcontainers DB 검증

현재 판정: **미검증** / 우선순위: medium

**정의와 실제 역할:** Actuator는 DB health를 노출하고 Testcontainers는 MySQL을 테스트 중 기동한다

**언제 사용하는가:** DB 상태 확인 및 MySQL 특성 검증

**대안과 경계:** H2 MODE=MySQL은 대체 증거가 아니며 Testcontainers에는 Docker 필요

**예시·실행 근거:** health HTTP 결과와 repository 저장 assertion

**선수개념:** HTTP 요청과 응답; 테스트 실행; Docker 컨테이너

**관련 표기·별칭:** Actuator·Testcontainers; health; real DB test

**보완·검증 필요 사항:**

- 원문 예제는 실행되지 않았다. 운영 환경에서 health endpoint를 외부에 노출할 때의 접근 제한 설명도 짧다.

**초보자가 시작할 질문:**
