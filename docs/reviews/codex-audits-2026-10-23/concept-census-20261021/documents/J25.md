## ArrayList·LinkedList·ArrayDeque·PriorityQueue

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** ArrayList는 인덱스 접근이 빠른 연속 참조 배열, LinkedList는 노드 연결, ArrayDeque는 양끝 원형 배열, PriorityQueue는 우선순위가 높은 원소를 앞에 두는 heap입니다.

**언제 사용하는가:** 인덱스 목록은 ArrayList, FIFO/LIFO는 ArrayDeque, 매번 우선순위가 가장 높은 항목을 꺼내면 PriorityQueue를 검토합니다.

**대안과 경계:** LinkedList에서 O(1) 삽입은 위치 노드를 이미 알고 있을 때만입니다. PriorityQueue 반복자는 전체 정렬 순서를 보장하지 않습니다.

**예시·실행 근거:** DataStructuresMapDemo에서 목록·양끝 큐·우선순위 큐의 삽입과 꺼내기 순서를 비교합니다. LRU 동작은 별도 예제로 다룹니다.

**선수개념:** array; queue/heap

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- No measured constant-factor comparison.

**초보자가 시작할 질문:**

- LinkedList의 node를 모르고 index 500을 삭제할 때 위치 찾기 비용은 얼마인가요?
- PriorityQueue에서 가장 작은 값만 유지하는 것이 전체 정렬을 의미하나요?

## 해시·정렬 tree·동등성

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** HashMap·HashSet은 해시가 고르게 분산된다는 전제에서 평균적으로 빠른 조회를 하고, TreeMap·TreeSet은 비교 순서와 범위 조회를 O(log n)으로 지원합니다.

**언제 사용하는가:** 단순 membership은 HashSet, 삽입 순서는 LinkedHashSet, 정렬·범위 조회는 TreeSet/TreeMap을 선택합니다.

**대안과 경계:** 해시 키를 넣은 뒤 동등성 관련 값을 바꾸면 조회가 실패할 수 있습니다. TreeSet은 comparator 결과가 0이면 같은 원소로 취급합니다.

**예시·실행 근거:** 해시 기반과 정렬 트리 기반 map/set에서 조회·순회 순서를 비교합니다.

**선수개념:** J02 equals/hashCode; Comparator

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- Hash collision worst case implementation/JDK details separated.

**초보자가 시작할 질문:**

- HashSet에 넣은 객체의 hash 필드를 바꾸면 왜 contains가 실패할 수 있나요?
- TreeSet comparator가 서로 다른 객체를 0으로 비교할 때 실제 어떤 원소가 남나요?

## 그래프 표현 선택

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 인접 리스트는 정점과 간선을 합쳐 O(V+E) 공간을 쓰고, 인접 행렬은 O(V²) 공간 대신 간선 존재 확인을 O(1)에 할 수 있습니다.

**언제 사용하는가:** 간선이 적은 그래프 탐색에는 보통 인접 리스트, 간선 확인이 잦고 조밀한 그래프에는 행렬을 검토합니다.

**대안과 경계:** 표현 방식 선택이 BFS·DFS·Dijkstra 같은 탐색 알고리즘의 의미를 정해 주지는 않습니다.

**예시·실행 근거:** 정점에서 인접 정점 목록을 따라가는 그래프 표현 그림입니다.

**선수개념:** node/edge; space complexity

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- Algorithm implementation deferred J22.

**초보자가 시작할 질문:**

- 정점은 많고 간선은 적은 그래프에서 V×V 행렬의 대부분 칸은 어떻게 되나요?
- 간선 존재 확인이 매우 잦고 V가 작은 조밀 그래프면 matrix가 가능한 이유는?

## LRU와 순서 계약

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** LinkedHashMap의 access-order는 오래 접근하지 않은 항목에서 최근 접근 항목 순으로 유지하며 removeEldestEntry로 용량 초과 항목을 제거할 수 있습니다.

**언제 사용하는가:** 동시성·만료 정책을 별도로 정한 단일 프로세스의 제한 용량 캐시에 활용할 수 있습니다.

**대안과 경계:** get()이 반복 순서를 바꿀 수 있고 기본 구현은 thread-safe가 아니며 TTL이나 크기 기반 weight 제한도 제공하지 않습니다.

**예시·실행 근거:** key1을 다시 접근한 뒤 key3을 넣어 key2가 퇴출되는 LruCacheDemo를 제시합니다.

**선수개념:** Map ordering; concurrency

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- Not a production cache implementation.

**초보자가 시작할 질문:**

- 최근 사용한 항목을 마지막으로 옮기고 용량 초과 때 오래된 항목을 지우려면 어떤 map 설정이 필요한가요?
- LinkedHashMap이 만들어준다고 해서 cache TTL까지 자동으로 적용되나요?
