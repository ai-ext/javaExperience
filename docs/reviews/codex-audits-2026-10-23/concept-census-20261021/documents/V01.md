## 위험도에 따른 테스트 대상 선택

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 테스트 대상은 코드 줄 수가 아니라 실패 시 사용자 피해, 놓칠 위험과 재현 가능성을 기준으로 고른다.

**언제 사용하는가:** 기능 변경 전이나 중요한 외부 계약을 보호할 때 사용한다.

**대안과 경계:** getter 테스트나 framework 동작만 반복하는 테스트는 업무 규칙 검증보다 신호가 적을 수 있다.

**예시·실행 근거:** 없는 상품의 404, 삭제 상품 제외, 페이지 응답을 검증한다.

**선수개념:** 요구사항과 실패 조건

**관련 표기·별칭:** risk and test target selection; contract; regression

**보완·검증 필요 사항:**

- 실제 예제는 상품 조회 시나리오에 범위가 한정돼 있다.

## 검증 경계별 테스트 범위

현재 판정: **미검증** / 우선순위: high

**정의와 실제 역할:** Service, Controller, Repository, E2E와 외부 계약 테스트는 각각 확인하는 경계가 다르다.

**언제 사용하는가:** 요구사항에 맞춰 테스트 종류와 실행 범위를 정할 때 사용한다.

**대안과 경계:** mock HTTP는 HTTP 계약을 확인할 뿐 DB 동작을 입증하지 않는다. H2 결과는 MySQL 동작과 같다는 증거가 아니다.

**예시·실행 근거:** MockMvc의 404와 Testcontainers 기반 MySQL 흐름을 비교한다.

**선수개념:** HTTP; Service 계층; DB

**관련 표기·별칭:** scope by boundary; unit; MVC slice; DataJpaTest; SpringBootTest

**보완·검증 필요 사항:**

- 예제 실행 여부와 README에 적힌 과거 테스트 이력을 별개의 증거로 표시해야 한다.

## AAA·assertion·테스트 비용

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 테스트는 준비, 한 가지 동작, 의미 있는 assertion으로 구성하고 실행 비용과 실패 위험의 균형을 맞춘다.

**언제 사용하는가:** 회귀 방지와 유지 가능한 테스트 범위를 설계할 때 사용한다.

**대안과 경계:** 테스트 피라미드/트로피는 고정 비율 규칙이 아니며 coverage 수치만으로 완전성을 보장하지 않는다.

**예시·실행 근거:** 상품 결과와 HTTP 필드를 검증하고 독립 시나리오를 나눠 작성한다.

**선수개념:** JUnit; assertion

**관련 표기·별칭:** AAA/assertion/cost tradeoff; Arrange Act Assert; pyramid; trophy

**보완·검증 필요 사항:**

- 이번 대조에서 전체 테스트 재실행 증거는 없다.
