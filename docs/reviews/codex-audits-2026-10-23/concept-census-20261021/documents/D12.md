## shell·파일·환경 설정

현재 판정: **충분** / 우선순위: high

**정의와 실제 역할:** terminal은 명령 입력/출력 창이고 shell은 명령 해석기다. path, stdout/stderr, PATH/JAVA_HOME 및 파일 명령을 구분한다.

**언제 사용하는가:** 빌드 명령 실패, 환경 변수 미설정, 파일 경로 오류를 조사할 때 사용한다.

**대안과 경계:** 현재 작업 디렉터리 상대 path는 절대 path와 다르며 stdout과 stderr는 서로 다른 stream이다.

**예시·실행 근거:** pwd, echo, which java와 stderr redirect 결과를 확인한다.

**선수개념:** 파일·디렉터리; 명령 실행

**관련 표기·별칭:** Shell/files/environment

**보완·검증 필요 사항:**

- 명령은 안내 중심이며 사용자의 특정 OS 상태를 관측한 결과가 아니다.

**초보자가 시작할 질문:**

## 권한·process·socket

현재 판정: **충분** / 우선순위: high

**정의와 실제 역할:** rwx permission은 파일/디렉터리 접근을 제어하고 PID·signal은 process를 관리하며 listener socket은 port 연결을 받는다.

**언제 사용하는가:** permission denied, process 종료, port 충돌을 구분할 때 사용한다.

**대안과 경계:** HTTP는 애플리케이션 protocol, TCP는 transport, ICMP는 진단/네트워크 protocol이다. `LISTEN` process가 있어도 HTTP 요청 성공은 별도다.

**예시·실행 근거:** ls -l, ps, kill, ss -ltnp와 curl 결과를 연결한다.

**선수개념:** OS process; file permission; TCP socket

**관련 표기·별칭:** Permissions, process, socket

**보완·검증 필요 사항:**

- 실제 서비스 process를 종료하거나 운영 서버 상태를 확인한 것은 아니다.

**초보자가 시작할 질문:**

- 8080 port가 이미 사용 중일 때 누가 점유했는지 어떻게 찾나?

**근거:**

## systemd·SSH·log·자원

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** systemd service unit이 JVM을 띄우고 journal에 log를 남기며 종료 signal과 resource limit이 service 수명에 영향을 준다.

**언제 사용하는가:** Linux에서 background app 시작 실패나 종료·로그·resource 문제를 추적할 때 사용한다.

**대안과 경계:** systemctl active만으로 HTTP health를 보장하지 않는다. SSH는 원격 접속 경로이며 앱 listener 상태와 다르다.

**예시·실행 근거:** systemctl status→PID→listener→curl→journal 순서로 확인한다.

**선수개념:** process; socket; 로그

**관련 표기·별칭:** systemd/SSH/logs/resources

**보완·검증 필요 사항:**

- 실제 systemd service나 원격 SSH session은 실행하지 않았다.

**초보자가 시작할 질문:**

- service가 active인데 HTTP 응답이 없으면 다음으로 무엇을 확인하나?
