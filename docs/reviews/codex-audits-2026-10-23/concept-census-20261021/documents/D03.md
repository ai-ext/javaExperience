## API 계약과 동작 의미

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** API 계약은 method·path·status·header·body·오류 형식 및 consumer가 기대하는 동작을 정한다.

**언제 사용하는가:** client와 server가 독립 개발되거나 API의 생성/조회/오류 동작을 합의할 때 사용한다.

**대안과 경계:** HTTP 응답 body가 성공이어도 status 의미와 자원 상태가 맞지 않으면 계약이 깨진다. 멱등성은 요청 반복 효과를 따로 정의한다.

**예시·실행 근거:** OpenAPI 정의와 실제 POST 201/Location, GET 응답, 오류 응답을 대조한다.

**선수개념:** HTTP method/status; JSON

**관련 표기·별칭:** API contract and semantics

**보완·검증 필요 사항:**

- 설명은 있으나 tutorial 코드는 전체 실행하지 않았다.

## pagination과 하위 호환성

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** offset과 cursor는 목록 위치를 전달하는 다른 방식이며 API 변경은 기존 consumer parser와 호환되어야 한다.

**언제 사용하는가:** 큰 목록을 나눠 전달하거나 응답을 바꾸면서 기존 client를 유지할 때 사용한다.

**대안과 경계:** offset page는 앞 데이터가 바뀌면 중복/누락될 수 있다. 새 응답 field 추가도 strict parser를 깨뜨릴 수 있다.

**예시·실행 근거:** offset/cursor 응답과 기존/신규 schema consumer 결과를 비교한다.

**선수개념:** 정렬 기준; API schema

**관련 표기·별칭:** Pagination and compatibility

**보완·검증 필요 사항:**

- 하위 호환성은 consumer 구현에 따라 달라질 수 있고 실행 예제는 제한적이다.

**초보자가 시작할 질문:**

- 목록 중간에 데이터가 추가되면 다음 페이지에서 왜 중복되거나 빠지나?

## API test와 release 흐름

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** MVC slice·integration test·OpenAPI diff·staged smoke를 통해 계약과 배포 전후 동작을 점검한다.

**언제 사용하는가:** API 변경을 공개하거나 release하기 전에 요청/응답 및 consumer 영향 확인이 필요할 때 사용한다.

**대안과 경계:** MockMvc는 전체 DB/운영 통합을 입증하지 않는다. OpenAPI diff도 모든 실제 consumer 동작을 대신 검증하지 않는다.

**예시·실행 근거:** schema diff와 실제 HTTP smoke 결과를 비교한다.

**선수개념:** HTTP test; OpenAPI

**관련 표기·별칭:** Test and release flow

**보완·검증 필요 사항:**

- tutorial 코드와 배포 흐름은 실제 실행하지 않았다.

**초보자가 시작할 질문:**

- API 계약을 바꾸기 전에 기존 client가 깨지지 않는지 무엇으로 확인하나?
