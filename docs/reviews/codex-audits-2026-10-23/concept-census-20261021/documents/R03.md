## VARCHAR의 문자 수와 byte 한도

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** MySQL VARCHAR(n)의 n은 문자 수 제한이고 저장/인덱스 한도는 byte 기준이다.

**언제 사용하는가:** 문자열 최대 길이와 인덱스·row 크기를 정할 때 사용한다.

**대안과 경계:** utf8mb4의 한 문자는 최대 4 byte일 수 있다. 선언 길이가 최대 byte만큼 미리 할당되는 것은 아니다.

**예시·실행 근거:** VARCHAR(255), utf8mb4 최대 byte, prefix index 길이를 비교한다.

**선수개념:** 문자 집합; 문자와 byte

**관련 표기·별칭:** VARCHAR characters and bytes; utf8mb4; row size; index key limit

**보완·검증 필요 사항:**

- 문자 길이와 byte 한도를 혼동하기 쉬우므로 크기 예제를 그림으로 연결하면 좋다.

## PK·FK·UNIQUE·CHECK·NULL·DEFAULT 제약

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** DB constraint는 중복, 참조 관계, row 값 범위를 선언적으로 지켜 모든 쓰기 경로의 마지막 무결성 장벽이 된다.

**언제 사용하는가:** 애플리케이션 외 쓰기까지 포함해 DB에서 반드시 지켜야 할 규칙을 선언할 때 사용한다.

**대안과 경계:** MySQL nullable UNIQUE는 여러 NULL을 허용할 수 있다. CHECK 조건의 UNKNOWN은 통과할 수 있으므로 CHECK와 NOT NULL은 다르다.

**예시·실행 근거:** 의도적으로 잘못된 UPDATE를 실행한 뒤 rollback하고 오류와 기존 값을 확인한다.

**선수개념:** SQL DDL; NULL의 3값 논리

**관련 표기·별칭:** PK/FK/unique/check/null/default; NOT NULL; UNIQUE; CHECK; FOREIGN KEY

**보완·검증 필요 사항:**

- 실제 캡처가 없고 실패 예제는 예상 결과뿐이다.

**초보자가 시작할 질문:**

- UNIQUE 열에 NULL을 여러 개 넣을 수 있나? CHECK가 NULL을 거부하나?

## 정규화와 키 설계

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 각 사실을 정규화된 원본 table에 두면 갱신·삭제·삽입 anomaly를 줄일 수 있다. surrogate ID와 business unique key를 구분한다.

**언제 사용하는가:** 반복 수정 오류를 막되 업무상 보존해야 하는 snapshot은 의미를 정해 둘 때 사용한다.

**대안과 경계:** 중복 데이터가 모두 잘못된 것은 아니다. 주문 시점 상품명/가격 snapshot은 현재 상품 정보와 다른 의미를 가진다.

**예시·실행 근거:** 회원/주문 관계와 anomaly가 생기는 예를 비교한다.

**선수개념:** 관계형 model

**관련 표기·별칭:** normalization and key design; normalization; surrogate key; natural key

**보완·검증 필요 사항:**

- ER diagram은 정적이며 anomaly 전후 실제 row 비교는 없다.

**초보자가 시작할 질문:**

## 공개본과 진행 중 보강의 차이

**추가된 내용:** 원문 Markdown은 공개본과 byte 동일하며 SHA-256도 동일하다. 공개 HTML과 보강 HTML은 다르다(공개 245b1cf9626920bfc2181e1556e1b360374eac3939a823c3bfeb1962191c87e7, 보강 55a33dc4bc955c73e289aa17ccc3db41ee7183652a20cbad17392a89595613ec). 보강 화면은 별도 datadir/socket의 native MySQL 8.4.11과 PyMySQL 1.1.2에서 외부 학습 schema/seed copy를 사용해 `SHOW CREATE TABLE`, `CREATE TABLE LIKE`, `ALTER TABLE`을 실행한다. 원본 product와 변경된 복사본의 `name` 길이 및 FK metadata를 비교한 뒤 복사본만 drop하고 원본이 남았음을 보여준다. TCP/mysqlx 비활성화, 별도 disposable datadir, 공개 연습 DB와 분리했다고 표시한다.

**공개본과의 차이:** 공개 원문은 data type, VARCHAR 문자/byte, PK/FK/UNIQUE/CHECK/NULL과 normalization을 표·예상 SQL로 설명한다. 보강 HTML은 실제 catalog/DDL과 복사본 변경, 복사본 삭제 후 원본 유지라는 DB 상태 증거를 추가했으나 공개 HTML에 포함되지 않았다. 공개본의 설명을 실행 결과로 바꾸어 읽으면 안 된다.

**비교 범위:** 보강 화면은 MySQL DDL과 FK metadata를 보여주지만 전체 row-level normalization anomaly 실험은 아니다. 원문 Java/JPA/HTTP/Docker는 실행하지 않았고 performance 측정도 없다. 작업은 새 datadir/socket과 외부 연습 schema copy에 한정되며 javaExperience 학습 DB를 수정한 결과가 아니다.
