## 보안 identity·인가·CSRF 검증

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 보안 테스트에서 가상 principal을 넣고 인증/인가 상태별 응답 차이를 확인한다.

**언제 사용하는가:** Security filter와 상태 변경 endpoint를 검증할 때 사용한다.

**대안과 경계:** WithMockUser는 JWT 서명 검증을 대체하지 않는다. MockMvc는 filter chain을 명시적으로 구성해야 할 수 있다.

**예시·실행 근거:** GET의 401/403/200과 POST CSRF 검증 실패를 나눈다.

**선수개념:** HTTP; Spring Security

**관련 표기·별칭:** security identity/authorization/CSRF; 401; 403; csrf

**보완·검증 필요 사항:**

- 대부분의 인증 기능은 현재 제품 동작이 아니라 향후 테스트 템플릿이다.

## 비동기·예약 작업·AFTER_COMMIT 검증

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 비동기 proxy, background worker와 transaction event는 실제 실행 및 commit을 관찰해야 검증된다.

**언제 사용하는가:** 비동기 작업과 commit 뒤 side effect를 시험할 때 사용한다.

**대안과 경계:** 직접 메서드 호출은 업무 로직만 시험하고 trigger/proxy는 확인하지 않는다. rollback은 commit과 다르다.

**예시·실행 근거:** Awaitility와 TransactionTemplate으로 완료 및 commit 상태를 확인한다.

**선수개념:** proxy; transaction; concurrency

**관련 표기·별칭:** async/schedule/AFTER_COMMIT; Awaitility; TransactionalEventListener

**보완·검증 필요 사항:**

- 제안된 새 클래스는 현재 프로젝트에 없다.

**초보자가 시작할 질문:**

- 왜 sleep으로 비동기 완료를 확인할 수 없고 rollback 때 listener가 실행되지 않나?

## DB 경쟁 조건과 원자적 갱신

현재 판정: **미검증** / 우선순위: high

**정의와 실제 역할:** 동시에 실행되는 실제 DB transaction을 만들어 조건부 갱신을 통해 한 요청만 성공하는지 검사한다.

**언제 사용하는가:** DB 경계에서 재고·잔액 등 경쟁 상태를 확인할 때 사용한다.

**대안과 경계:** 기본 테스트 transaction은 경쟁 상황을 가릴 수 있다. latch는 동시 시작을 맞추지만 sleep은 동시 실행의 증거가 아니다.

**예시·실행 근거:** 두 worker가 마지막 재고를 동시에 구매하고 재고가 0 이하로 내려가지 않는지 본다.

**선수개념:** SQL; transaction; thread

**관련 표기·별칭:** database race and atomic update; CountDownLatch; conditional UPDATE

**보완·검증 필요 사항:**

- 간략 예제는 실행되지 않았다.

**초보자가 시작할 질문:**

- 마지막 재고 하나에 두 구매 요청이 동시에 들어오면 어떻게 검증하나?

## 파일·시간·원격 timeout 경계

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 앱 입력 검증과 servlet container의 multipart parsing/size 제한은 서로 다른 경계다.

**언제 사용하는가:** 파일 업로드, 만료 시각, 외부 응답 timeout을 시험할 때 사용한다.

**대안과 경계:** MockMvc는 실제 port 및 multipart parser 전체를 거치지 않을 수 있다. client가 보내는 MIME type은 신뢰할 수 없다.

**예시·실행 근거:** 실제 port 업로드와 고정 시각을 사용한다.

**선수개념:** HTTP multipart; 파일 보안; clock

**관련 표기·별칭:** file/time/remote timeout boundaries; MockMultipartFile; Clock.fixed; timeout

**보완·검증 필요 사항:**

- 새 기능은 구현이 아니라 테스트 템플릿이다.

**초보자가 시작할 질문:**

- MockMvc만으로 실제 413 upload limit까지 검증할 수 있나?
