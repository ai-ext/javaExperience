## 예외를 잡는 기준과 계층 책임

현재 판정: **부분** / 우선순위: P0

**정의와 실제 역할:** 예외를 복구하거나 의미를 변환할 경계

**언제 사용하는가:** 예외는 실제로 복구하거나 호출 계약에 맞는 의미로 바꿀 책임이 있는 계층에서 잡는다.

**대안과 경계:** Repository는 저장 오류를 숨기지 않고 Service는 업무 의미를 결정하며 Controller/Advice는 HTTP 표현을 만든다.

**예시·실행 근거:** 잡은 뒤 정상 반환하면 rollback/logging 관찰이 바뀔 수 있고 여러 계층에서 중복 기록하면 추적이 어려워진다. 추가 예: 기술 예외를 특정 도메인 오류로 매핑하는 위치를 한 번 정하고 원인 예외를 보존한다.

**선수개념:** exception hierarchy; domain error; HTTP response

**관련 표기·별칭:** catch boundary; exception translation; recovery

**판정 이유:** 개념 정의와 적용 기준은 확인되나 실제 실행/학습자 수행 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- exception hierarchy
- transaction rollback

**초보자가 시작할 질문:**

- 예시 예외 매핑 코드는 미실행.

## Spring rollback rules, checked/caught exceptions

현재 판정: **부분** / 우선순위: P0

**정의와 실제 역할:** Spring rollback과 checked/caught 예외

**언제 사용하는가:** Spring 기본 롤백은 RuntimeException/Error이며 checked exception은 기본 commit 가능. 프록시 경계 밖에서 예외가 삼켜지면 rollback 신호가 없어질 수 있다.

**대안과 경계:** checked 업무 실패에는 타입 기반 rollbackFor, 잡고 정상 결과를 반환하면 rollback-only 여부를 명시한다.

**예시·실행 근거:** 예외 타입/전파 위치와 transaction rule이 결과를 정한다. @Transactional default가 모든 예외 rollback인 것은 아니다. 추가 예: checked InsufficientFunds를 경계까지 던지고 rollbackFor를 지정한다.

**선수개념:** Spring transaction rollback; checked exception

**관련 표기·별칭:** rollbackFor; rollback-only; UnexpectedRollbackException

**판정 이유:** 개념 정의와 적용 기준은 확인되나 실제 실행/학습자 수행 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- Spring transaction proxy
- checked exception

**초보자가 시작할 질문:**

- 프로젝트 transaction manager에서 실행 재현하지 않았다.

## MVC local handler vs global Advice and ProblemDetail

현재 판정: **부분** / 우선순위: P1

**정의와 실제 역할:** MVC local handler와 전역 Advice/ProblemDetail

**언제 사용하는가:** Controller 내부 복구와 여러 endpoint 공통 오류 응답을 만드는 @RestControllerAdvice는 범위가 다르다. ProblemDetail은 RFC 오류 계약이다.

**대안과 경계:** 한 endpoint의 특수한 보정은 지역 처리, 전역 오류 표준은 Advice에서 구현한다.

**예시·실행 근거:** 필터 단계나 MVC 밖 예외는 ControllerAdvice가 잡지 못할 수 있고 내부 stack/DB 정보는 응답에 내보내지 않는다. 추가 예: 도메인 not found를 404 ProblemDetail로, 미처리 내부 예외를 안전한 500 계약으로 매핑한다.

**선수개념:** Spring MVC; HandlerExceptionResolver; ProblemDetail

**관련 표기·별칭:** @ExceptionHandler; @RestControllerAdvice; RFC 9457; ProblemDetail

**판정 이유:** 개념 정의와 적용 기준은 확인되나 실제 실행/학습자 수행 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- Spring MVC exception resolver
- RFC 9457

**초보자가 시작할 질문:**

- MVC runtime request/error response는 실행하지 않았다.

## 로그 경계, 개인정보, 중복 사건

현재 판정: **부분** / 우선순위: P1

**정의와 실제 역할:** 로그 경계와 민감정보 최소화

**언제 사용하는가:** 로그는 선택적으로 사건을 저장하는 운영 파이프라인이며 비밀번호·token·개인정보가 포함될 수 있다.

**대안과 경계:** 요청 ID와 안전한 오류 코드만 기록하고 원인 stack을 알맞은 한 경계에서 남긴다.

**예시·실행 근거:** 예외 message를 외부 응답에 그대로 복사하면 내부 정보가 유출되고 같은 오류를 여러 층에서 로그하면 중복 이벤트가 된다. 추가 예: 민감 필드를 마스킹하고 사용자 응답에는 안정적 오류 코드·문구를 쓴다.

**선수개념:** logging boundary; PII redaction

**관련 표기·별칭:** single error log; sensitive data; cause chain

**판정 이유:** 개념 정의와 적용 기준은 확인되나 실제 실행/학습자 수행 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- logging context
- data privacy
- error contract

**초보자가 시작할 질문:**

- 저장소의 실제 logging/redaction 설정 미확인.
