## `var`·switch 식·text block

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** `var`는 초기화식에서 지역 변수의 정적 타입을 추론하고, switch 식은 모든 입력에서 값을 반환하며, text block은 여러 줄 String 리터럴입니다.

**언제 사용하는가:** 지역 타입을 추론해도 선언 의미가 분명할 때 `var`, 값 선택은 switch 식, 줄바꿈 문자열은 text block을 씁니다.

**대안과 경계:** `var`는 동적 타입이 아니며 field/parameter/return에 못 씁니다. text block은 문자열 보간이나 SQL 바인딩이 아닙니다.

**예시·실행 근거:** Java21 `InvoiceSwitchDemo`는 PRO 30.000과 text block SQL 형태를 출력합니다.

**선수개념:** Java 변수·switch·String

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 모든 코드를 Java25 문법으로 실행한 것은 아니며 예제별 버전 표기를 따라야 합니다.

**초보자가 시작할 질문:**

- var 지역 변수의 타입을 다른 객체로 다시 바꿀 수 있나요?
- SQL을 text block으로 쓰더라도 사용자 입력을 연결하면 어떤 위험이 남나요?

## record·sealed·패턴 매칭

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** record는 컴포넌트 기반 얕은 불변 데이터 타입, sealed는 허용 하위 타입 제한, pattern matching은 타입/record 구조 검사와 변수 바인딩입니다.

**언제 사용하는가:** 호출 데이터는 record, 닫힌 결제 유형은 sealed+완전한 switch로 표현합니다.

**대안과 경계:** record는 deep immutable이 아니며 sealed는 final과 달리 지정된 범위에서 확장을 허용합니다.

**예시·실행 근거:** Payment record/sealed example에서 카드/현금/null 분기를 실행해 확인합니다.

**선수개념:** 상속·record·switch

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- record 컴포넌트와 public JSON schema 변경의 영향은 별도로 검토해야 합니다.

**초보자가 시작할 질문:**

- record 안에 mutable List가 있으면 컴포넌트 자체와 List 내용 중 무엇이 바뀔 수 있나요?
- 새 Payment 하위 타입이 생겼을 때 default 없는 sealed switch는 어떤 도움을 주나요?

## Java25 module import와 compact main

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** `import module`은 읽을 수 있는 모듈이 export한 public 타입을 import하고 compact source/instance main은 작은 파일의 진입 문법을 줄입니다.

**언제 사용하는가:** Java25 source baseline이 확정된 도구·작은 예제에서만 사용합니다.

**대안과 경계:** module import는 `requires` 선언을 대체하지 않으며 서비스의 package/module 설계도 대신하지 않습니다.

**예시·실행 근거:** J25 `import module java.base; void main()` 예제는 JDK21 호스트라 미실행입니다.

**선수개념:** Java module과 main method

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- Java25 컴파일/운영 런타임은 캡처 당시 직접 실행하지 않았습니다.

**초보자가 시작할 질문:**

- `import module java.base`가 module-info의 requires를 대신할 수 없는 이유는 무엇인가요?
- JDK만 25로 설치했는데 --release 21이면 compact source가 가능한가요?

## Flexible constructor와 preview/final

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 명시적 `super()`/`this()` 앞에 제한된 검증 문장을 허용하지만 생성 중인 인스턴스 참조는 금지합니다. Preview는 릴리스별 enable-preview가 필요한 시험 기능입니다.

**언제 사용하는가:** super 인자 검증을 부모 호출 전에 해야 할 때 Java25 source target을 확인합니다.

**대안과 경계:** Preview를 최종 API처럼 고정할 수 없고 실행 JDK와 compiler release를 맞춰야 합니다.

**예시·실행 근거:** PositiveBigInteger constructor 예시와 JEP513/version table.

**선수개념:** constructor/super call; source level

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- Java25 예시는 JDK21 환경이라 컴파일·실행되지 않았습니다.

**초보자가 시작할 질문:**

- super() 전에 검증할 수 있는 입력과 아직 사용할 수 없는 `this` 상태는 어떻게 다를까요?
- Preview 기능을 25에서 실행하고 26에서 옮길 때 옵션만 그대로 써도 되나요?
