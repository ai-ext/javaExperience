## 예외 계층과 체크 규칙

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** Throwable의 Error/Exception 구분과 checked/unckecked 예외는 선언·호출자 처리 책임을 다르게 둡니다.

**언제 사용하는가:** 호출자가 복구 대안을 고를 수 있는 실패라면 checked를 고려하고, 계약/불변식 위반은 의미 있는 unchecked로 표현합니다.

**대안과 경계:** 컴파일 시 checked 분석과 런타임 catch 선택은 별개입니다. catch(Throwable)는 복구 불가능한 오류도 삼킬 수 있습니다.

**예시·실행 근거:** ExceptionBoundaryDemo에서 IOException을 원인으로 StorageException에 보존합니다.

**선수개념:** Java 기본 문법과 값/객체 참조

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 실제 DB/HTTP 예외 응답 매핑은 프레임워크 경계에 따릅니다.

**초보자가 시작할 질문:**

- IOException을 호출자가 다른 파일로 재시도할 수 있다면 checked/unchecked 중 어떤 계약이 더 분명할까요?
- Error까지 catch해 계속 실행하면 어떤 복구 불가능한 상태를 숨길 수 있나요?

## try-with-resources와 suppressed

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** AutoCloseable 자원은 선언 역순으로 닫힙니다. 본문 예외가 주 예외로 남고 close 실패는 suppressed에 기록됩니다.

**언제 사용하는가:** 파일·소켓·DB cursor에는 TWR을 사용합니다.

**대안과 경계:** finally에서 return/throw하면 기존 반환/예외를 덮을 수 있습니다.

**예시·실행 근거:** SuppressedDemo에서 B→A 역순 close와 두 suppressed 오류를 확인합니다.

**선수개념:** Java 기본 문법과 값/객체 참조

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- JVM 강제 종료에서는 finally/close 보장을 기대할 수 없습니다.

**초보자가 시작할 질문:**

- 파일 쓰기 실패와 close 실패가 동시에 나면 try-with-resources는 어느 예외를 주 예외로 남기나요?
- finally에서 return하면 이미 준비된 예외나 반환값에 어떤 일이 생기나요?

## cause 체인·checked 예외와 람다

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 예외 추상화는 안정된 상위 유형을 제공하되 원인을 cause로 보존합니다. 함수형 인터페이스 signature가 checked 예외 전달 가능성을 결정합니다.

**언제 사용하는가:** catch는 복구/번역이 있을 때 사용하고, 한 경계에서 원인 기록을 소유합니다.

**대안과 경계:** Consumer는 checked 예외를 선언하지 않아 adapter 또는 사용자 SAM이 필요합니다.

**예시·실행 근거:** CheckedLambdaDemo가 UncheckedIOException과 IOException cause를 출력합니다.

**선수개념:** Java 기본 문법과 값/객체 참조

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 예외 비용 수치는 측정 없이 일반화하지 않습니다.

**초보자가 시작할 질문:**

- Consumer 람다에서 IOException을 그대로 던질 수 없는 이유는 무엇일까요?

## Checked exceptions in lambdas and cost

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 람다에서 허용되는 checked exception은 대상 함수형 인터페이스 메서드의 throws 선언에 따릅니다. Throwable은 생성 시점의 stack trace도 보유합니다.

**언제 사용하는가:** IOException을 던지는 작업을 Runnable 같은 인터페이스로 넘길 때 예외를 어떻게 변환·전달할지 계약을 정합니다.

**대안과 경계:** IOException을 선언한 사용자 함수형 인터페이스는 checked 예외를 전파할 수 있지만 Runnable은 선언하지 않아 직접 전파할 수 없습니다. wrapping은 호출자가 예외를 처리하는 경계를 바꿉니다.

**예시·실행 근거:** IOAction에 checked IOException을 선언하고 이를 Runnable로 연결할 때 UncheckedIOException으로 감싸는 예입니다.

**선수개념:** Java 타입·메서드 호출 기초

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- No performance measurement; explicitly labeled contextual.

**초보자가 시작할 질문:**

- 람다 안에서 IOException을 던지려 할 때 컴파일 오류가 나는 까닭은 무엇인가요?
- 파일을 닫는 중에도 예외가 나면 본문 예외와 close 예외는 어디서 볼 수 있나요?
