## Spring Framework와 Spring Boot

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** Framework는 DI·빈 생명주기·MVC·트랜잭션 등 기반 기능을 제공하고 Boot는 기본 구성·의존성 조합·실행·운영 기능을 얹는다.

**언제 사용하는가:** 신규 앱은 보통 Boot로 시작한다. 특수 구성이나 외부 컨테이너가 필요하면 Framework를 직접 조립할 수 있다.

**대안과 경계:** Boot는 Framework를 대체하지 않는다. Boot 없이도 Framework를 쓰지만 설정·버전·서버를 직접 조립한다.

**예시·실행 근거:** Initializr → @SpringBootApplication → ./gradlew bootRun → curl /hello의 순서를 제시하나 예제는 미실행이다.

**선수개념:** Java main/package; 의존성; HTTP

**관련 표기·별칭:** Spring; Boot

**보완·검증 필요 사항:**

- 버전 조합은 시점에 따라 공식 요구사항 재확인 필요.

**초보자가 시작할 질문:**

- Boot 없이 웹 서버를 띄울 수 있는가?

## 스타터·자동 구성·BOM

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** starter는 관련 의존성 묶음이며 자동 구성은 클래스패스와 설정 조건으로 기본 Bean 구성을 시도한다. BOM은 라이브러리 버전을 맞춘다.

**언제 사용하는가:** MVC 구성요소를 하나씩 고르지 않고 Boot 스타터로 넣고 기본값을 속성이나 사용자 Bean으로 조정한다.

**대안과 경계:** 스타터가 모든 설정/API를 고정하지 않는다. Spring MVC·Data·Security 각각의 개념과 설정은 별개다.

**예시·실행 근거:** Boot 4.1 기준 spring-boot-starter-webmvc 및 spring-boot-dependencies:4.1.1 예시.

**선수개념:** Gradle/Maven; classpath

**관련 표기·별칭:** starter; auto-configuration

**보완·검증 필요 사항:**

- 자동 구성 조건의 상세 분석은 S03으로 연결한다.

**초보자가 시작할 질문:**

- starter는 무슨 일을 하나?
- Boot가 Bean을 만든 조건은 어디서 찾나?

## 진입점·컴포넌트 검색

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** @SpringBootApplication은 설정·자동 구성·컴포넌트 검색을 묶는다. 기본 검색은 메인 클래스 패키지와 하위다.

**언제 사용하는가:** 진입 클래스를 구성요소의 공통 최상위 패키지에 둔다.

**대안과 경계:** 형제 패키지는 기본 스캔되지 않는다. 명시 검색 범위를 지정할 수 있으나 구조를 단순화하는 편이 초보자에게 추적하기 쉽다.

**예시·실행 근거:** com.example.demo 아래 하위 컨트롤러는 검색되지만 com.example.controller는 기본 범위 밖일 수 있다.

**선수개념:** Java package; 애노테이션

**관련 표기·별칭:** @SpringBootApplication; component scan

**보완·검증 필요 사항:**

- ApplicationContext와 서버가 시작되는 내부 시간 흐름은 요약 수준이다.

**초보자가 시작할 질문:**

- Controller가 404인 이유는?
- 메인 클래스 위치가 중요한가?

## 내장 서버·실행 패키징

현재 판정: **부분** / 우선순위: medium

**정의와 실제 역할:** 웹 starter가 내장 Servlet 컨테이너 구성을 가져와 앱이 서버를 함께 시작한다. bootRun은 개발 실행, bootJar는 실행 패키징이다.

**언제 사용하는가:** 개발 중 bootRun, 배포 파일 생성에 bootJar와 java -jar를 쓴다. 외부 컨테이너 필요 시 WAR를 검토한다.

**대안과 경계:** 앱 프로세스와 외부 컨테이너 배포는 다른 운영 모델이다.

**예시·실행 근거:** ./gradlew bootRun; ./gradlew bootJar; java -jar build/libs/...jar. 원문은 미실행.

**선수개념:** JDK; Wrapper; HTTP port

**관련 표기·별칭:** bootRun; bootJar

**보완·검증 필요 사항:**

- 서버별 실제 교체 및 운영 배포는 깊이 다루지 않는다.

**초보자가 시작할 질문:**

- Tomcat 없이 실행되는 이유는?
- bootRun과 bootJar 차이는?

## 외부 설정과 비밀정보

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 설정 파일과 환경변수·명령행 입력으로 환경별 값을 주입하며 높은 우선순위 값이 기본 설정을 덮는다.

**언제 사용하는가:** 동일 앱을 개발·배포 환경에서 다른 값으로 실행할 때 사용한다. 비밀은 저장소에 커밋하지 않는다.

**대안과 경계:** 명령행은 YAML보다 우선한다. 프로파일 등 상세는 S04로 연결한다.

**예시·실행 근거:** SERVER_PORT=9090 또는 --server.port=9090.

**선수개념:** 환경변수; 설정 파일

**관련 표기·별칭:** application.yml; PropertySource

**보완·검증 필요 사항:**

- 전체 PropertySource 순서·프로파일 활성화 상세는 다루지 않는다.

**초보자가 시작할 질문:**
