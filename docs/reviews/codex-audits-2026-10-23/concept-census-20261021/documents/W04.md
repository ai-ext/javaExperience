## MyBatis Mapper interface/XML statement registry

현재 판정: **부분** / 우선순위: P0

**정의와 실제 역할:** MyBatis Mapper 인터페이스의 메서드 이름과 XML statement id/namespace를 연결한다.

**언제 사용하는가:** SQL과 CRUD 순서를 직접 보면서 Java 호출부를 타입으로 관리할 때.

**대안과 경계:** Mapper는 SQL을 생성하지 않으며 등록된 XML id가 없으면 바인딩 실패가 난다.

**예시·실행 근거:** findById 메서드와 mapper namespace + id=findById를 맞춘다.

**선수개념:** MyBatis mapper 등록; SQL statement id/namespace

**관련 표기·별칭:** namespace; statement id; Mapper proxy; SqlSessionTemplate

**판정 이유:** 개념 정의와 적용 기준은 확인되나 실제 실행/학습자 수행 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- 예제는 애플리케이션 및 DB 실행 검증 안 됨.

**초보자가 시작할 질문:**

## SQL parameterization and SQL injection boundary

현재 판정: **부분** / 우선순위: P0

**정의와 실제 역할:** #{} 파라미터 바인딩과 ${} SQL 문자열 치환

**언제 사용하는가:** 사용자 값은 #{}로 prepared statement 파라미터로 바인딩한다.

**대안과 경계:** 검색어·ID 등 외부 입력을 SQL 값으로 전달할 때.

**예시·실행 근거:** ${}는 SQL 문법 조각을 문자열 치환하므로 injection 위험이 있고 컬럼명/정렬은 allowlist가 필요하다. 추가 예: 검색 값은 #{value}; 정렬 컬럼은 허용된 enum을 골라 SQL 조각을 선택한다.

**선수개념:** SQL parameter binding; SQL injection

**관련 표기·별칭:** #{}; ${}; PreparedStatement; allow-list dynamic identifier

**판정 이유:** 개념 정의와 적용 기준은 확인되나 실제 실행/학습자 수행 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- SQL injection
- prepared statement

**초보자가 시작할 질문:**

- 실제 악성 입력 테스트는 수행하지 않았다.

## MyBatis dynamic SQL safety and empty predicates

현재 판정: **부분** / 우선순위: P0

**정의와 실제 역할:** 동적 SQL과 빈 조건 안전성

**언제 사용하는가:** if/choose/where/foreach 등으로 조건이 있는 SQL을 조립한다.

**대안과 경계:** 필터 조합이 선택적일 때 단일 mapper statement에 조건을 구성한다.

**예시·실행 근거:** 조건 없는 DELETE/UPDATE나 IN 빈 목록은 결과를 과도하게 넓힐 수 있어 기본 차단 정책이 필요하다. 추가 예: 삭제 조건이 비면 SQL 실행을 거부하고 foreach에 빈 목록의 동작을 테스트한다.

**선수개념:** MyBatis dynamic SQL; WHERE/IN predicates

**관련 표기·별칭:** <if>; <where>; <set>; <foreach>; full-table update risk

**판정 이유:** 개념 정의와 적용 기준은 확인되나 실제 실행/학습자 수행 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- SQL predicate
- dynamic statement

**초보자가 시작할 질문:**

- 동적 SQL 통합 테스트 및 실제 DB 동작 미실행.

## resultType vs resultMap and joined cardinality

현재 판정: **부분** / 우선순위: P1

**정의와 실제 역할:** resultType과 resultMap, 조인 행 cardinality

**언제 사용하는가:** resultType은 단순 행-객체 매핑, resultMap은 관계/중첩 매핑을 세밀히 정의한다.

**대안과 경계:** 조인 결과에서 부모·자식 구조로 변환하거나 컬럼명이 다를 때 resultMap을 쓴다.

**예시·실행 근거:** JOIN은 부모별 자식 수만큼 행을 늘릴 수 있어 id/collection mapping으로 중복 부모를 합쳐야 한다. 추가 예: order와 order_line 조인을 resultMap의 id/collection으로 매핑한다.

**선수개념:** resultMap; JDBC row mapping

**관련 표기·별칭:** <association>; <collection>; nested result mapping; identity IDs

**판정 이유:** 개념 정의와 적용 기준은 확인되나 실제 실행/학습자 수행 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- JDBC row
- nested association

**초보자가 시작할 질문:**

- 실제 mapper SQL 결과 비교는 미실행.
