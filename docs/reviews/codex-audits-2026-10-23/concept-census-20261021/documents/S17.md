## Tomcat worker·연결·대기열

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** worker는 servlet 요청을 처리하는 스레드, max-connections는 연결 상한, accept-count는 연결 포화 때 대기 영역이다.

**언제 사용하는가:** worker 포화에 DB와 CPU 여유가 있는지 확인하고 가장 좁은 실행 자원을 찾는다.

**대안과 경계:** 세 값은 처리량·연결·대기 허용이라는 서로 다른 한도이며 queue를 늘려도 처리량은 늘지 않는다.

**예시·실행 근거:** Boot 속성 예제와 한계값 표가 있으나 운영 부하에서 미실행이다.

**선수개념:** Java/Spring 기본 실행 흐름; HTTP·DB·프로세스 중 해당 개념의 접점

**관련 표기·별칭:**

**정의와 실제 역할:** Hikari pool은 애플리케이션이 재사용하는 DB 연결 수를 제한한다.

**언제 사용하는가:** pending이 지속될 때 DB CPU·락·쿼리 시간과 replica 수를 함께 보고 작은 풀부터 시험한다.

## timeout과 deadline 전파

**정의와 실제 역할:** Tomcat connection timeout, Hikari 획득 timeout, SQL timeout, 앱 요청 deadline, proxy timeout은 서로 다른 단계 제한이다.

**언제 사용하는가:** 요청 예산을 계층별로 나누고 안쪽 작업 제한을 바깥 요청보다 짧게 두어 오류 응답 여유를 확보한다.

**대안과 경계:** 클라이언트가 끊겨도 JDBC가 즉시 취소된다고 단정할 수 없다. 겹친 retry는 중복 부하를 만든다.

**예시·실행 근거:** Boot 설정 예제와 하위·상위 제한 관계를 설명하며 미실행이다.

**선수개념:** Java/Spring 기본 실행 흐름; HTTP·DB·프로세스 중 해당 개념의 접점

**언제 사용하는가:** 시작이 느리면 단계별 기록 후 비싼 초기화를 특정한다. lazy를 쓸 때 첫 요청의 cold path도 측정한다.

**대안과 경계:** lazy는 비용과 구성 오류 발견을 첫 요청에 옮길 수 있고 eager singleton 의존성은 빈을 시작 중 만들 수 있다.
