## 캡슐화·추상화·상속·조합

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 객체는 상태/행위를 타입 경계 안에 두고 계약으로 협력합니다. 상속은 대체 가능성이 있을 때 쓰고, 구현 재사용만 필요하면 조합합니다.

**언제 사용하는가:** 상태 전이·불변식을 객체 내부에서 보호하고, 역할을 작은 인터페이스로 받습니다.

**대안과 경계:** 상속은 생성 순서와 override 훅까지 공유합니다. 조합은 협력자를 전달해 구현 의존을 줄입니다.

**예시·실행 근거:** Formatter 인터페이스를 ReportService에 주입한 데모와 중첩 타입을 실행합니다.

**선수개념:** Java 기본 문법과 값/객체 참조

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 모든 설계 사례에 조합이 우월한 것은 아니며 계약에 따라 선택합니다.

## 오버로딩과 오버라이딩

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 오버로드는 선언 타입/인자 타입으로 컴파일 시 메서드 시그니처를 고르고, 오버라이드는 런타임 receiver에 맞는 구현을 선택합니다.

**언제 사용하는가:** 같은 작업에 인자 형태가 다르면 오버로드, subtype 구현을 바꾸면 동일 signature override를 씁니다.

**대안과 경계:** runtime argument subtype이 overload를 다시 고르지 않습니다. static method는 hiding입니다.

**예시·실행 근거:** DispatchDemo가 상위 참조·캐스팅·static 호출 결과를 출력합니다.

**선수개념:** Java 기본 문법과 값/객체 참조

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 컴파일/실행 단계 분리를 놓치면 “왜 String overload가 아닌가”를 오판합니다.

**초보자가 시작할 질문:**

- Base 변수에 Child를 넣고 `describe("x")`를 부르면 overload와 override 중 어느 단계가 먼저일까요?
- Child에 String overload만 있고 Base 시그니처 override가 없다면 어떤 구현이 호출될까요?

## equals/hashCode/compareTo 규약

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** equals로 같은 객체는 hashCode도 같아야 하며, compareTo==0은 TreeSet/TreeMap의 동일 키 판정에 영향을 줍니다.

**언제 사용하는가:** 비교 상태를 불변으로 유지하고 equals/hashCode/자연 순서를 같은 값 경계로 설계합니다.

**대안과 경계:** 해시 충돌은 허용되지만 가변 HashMap 키는 조회 실패가 날 수 있습니다.

**예시·실행 근거:** AccountId value class로 equals/hashCode/compareTo와 TreeSet 중복 제거를 확인합니다.

**선수개념:** Java 기본 문법과 값/객체 참조

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 상속 계층에서 대칭성·추이성 검토가 더 복잡합니다.

**초보자가 시작할 질문:**

- equals만 바꾼 객체를 HashSet에 두 번 넣으면 왜 중복이 남을 수 있나요?
- HashMap 키의 비교 필드를 넣은 뒤 바꾸면 get이 왜 실패할까요?

## 불변 객체·접근·중첩 타입

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** private 상태와 생성 검증은 객체 불변식을 보호합니다. final 참조는 대상 객체까지 동결하지 않습니다.

**언제 사용하는가:** 외부 API를 최소화하고 입력/반환 가변 참조를 방어 복사합니다. 바깥 인스턴스가 필요 없으면 static nested class가 단순합니다.

**대안과 경계:** 인터페이스는 역할, 추상 클래스는 상태/구현 골격을 공유합니다.

**예시·실행 근거:** J02 중첩 클래스/조합 예시와 Q&A.

**선수개념:** Java 기본 문법과 값/객체 참조

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 필드 접근·패키지 경계가 실제 모듈 정책과 어떻게 연결되는지 별도 학습 가능합니다.

**초보자가 시작할 질문:**

## 실제 캡처 관찰

- 데스크톱 요약은 캡슐화, overload/override, equals/hashCode, comparator를 강조하고 소주제는 접혀 있다.
- 모바일 제목과 요약은 한 열에서 읽을 수 있고 가로 넘침은 보이지 않는다.
- core에는 OOP/계약 비교표와 접힌 소주제 행이 보인다. 정의는 전달하지만 equality/hash bucket이나 dispatch 상태 전이를 보여 주지는 않는다.

**관찰 범위:** 캡처에는 코드 출력이나 상호작용이 보이지 않는다. 렌더링된 비교표와 접힌 소주제 목록만 평가했다.
