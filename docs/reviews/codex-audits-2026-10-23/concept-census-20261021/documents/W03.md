## DB 접근 추상화 선택축

현재 판정: **부분** / 우선순위: P1

**정의와 실제 역할:** 접근 도구는 객체 상태 추적, SQL 직접 제어, 매핑 반복 감소라는 서로 다른 축을 제공한다.

**언제 사용하는가:** 도메인 CRUD는 JPA, SQL 중심 화면은 JDBC/MyBatis, 타입 안전 DSL이 필요하면 QueryDSL/jOOQ를 검토한다.

**대안과 경계:** 도구 이름만으로 빠르다고 단정할 수 없고 쿼리·매핑·상태 관리 부담을 비교한다.

**예시·실행 근거:** 같은 고객 조회를 JPA, MyBatis, JdbcClient로 표현해 팀의 SQL 소유권을 비교한다.

**선수개념:** SQL; ORM; mapping

**관련 표기·별칭:** JDBC; JdbcTemplate; JdbcClient; MyBatis; JPA; Spring Data JPA; QueryDSL; jOOQ

**판정 이유:** 핵심 개념은 설명하지만 대상 환경 실행·학습자 수행 근거가 충분하지 않아 부분 판정.

**보완·검증 필요 사항:**

- 모든 코드 경로는 미실행이며 성능 비교 측정은 없다.

## JPA 영속성 컨텍스트, 변경 감지와 flush

현재 판정: **부분** / 우선순위: P0

**언제 사용하는가:** 같은 트랜잭션 안에서 엔티티 상태 변경을 추적해야 할 때 JPA를 쓴다.

**대안과 경계:** flush는 commit이 아니며 1차 캐시는 앱 간 공유 캐시가 아니다.

**예시·실행 근거:** 조회 엔티티를 변경하고 flush 전후 SQL 시점을 살핀다.

**선수개념:** EntityManager; transaction

**관련 표기·별칭:** EntityManager; persistence context; managed entity; dirty checking; flush

**판정 이유:** 핵심 개념은 설명하지만 대상 환경 실행·학습자 수행 근거가 충분하지 않아 부분 판정.

**보완·검증 필요 사항:**

- SQL 로그/DB 실행 확인은 하지 않았다.

**판정 이유:** 핵심 개념은 설명하지만 대상 환경 실행·학습자 수행 근거가 충분하지 않아 부분 판정.

## JPA와 MyBatis 혼용 시 transaction과 cache 동기화

현재 판정: **부분** / 우선순위: P0

**정의와 실제 역할:** JPA와 MyBatis를 한 DB에 같이 쓸 때도 각각의 상태 추적·캐시·flush가 따로 있다.

**언제 사용하는가:** 도메인 변경은 JPA, 정밀 SQL은 MyBatis처럼 기능 단위로 나눌 때.

**대안과 경계:** 같은 DataSource/트랜잭션에 연결될 수 있어도 영속성 컨텍스트가 MyBatis 조회 결과를 자동 갱신하지 않는다.

**예시·실행 근거:** JPA 변경 후 MyBatis SELECT 전 flush/clear 또는 별도 SQL 경계를 확인한다.

**선수개념:** DataSource; transaction manager; first-level cache

**관련 표기·별칭:** same DataSource; flush before mapper read; refresh/clear; single write owner

**판정 이유:** 핵심 개념은 설명하지만 대상 환경 실행·학습자 수행 근거가 충분하지 않아 부분 판정.

**보완·검증 필요 사항:**

- 실제 SQL 순서 및 cache stale 재현은 하지 않았다.

## 읽기 모델 SQL/도구 선택과 점진 마이그레이션

**보완·검증 필요 사항:**

- 화면 첫 노출과 모바일 가독성은 아래 실제 캡처 판독에서 별도로 기록했다.

**추가할 의미 장면**

- 같은 고객 조회를 JPA, MyBatis, JdbcClient로 표현해 팀의 SQL 소유권을 비교한다.
- 조회 엔티티를 변경하고 flush 전후 SQL 시점을 살핀다.
- 이름 있는 파라미터로 SELECT 후 RowMapper/람다로 DTO를 만든다.
- Mapper 인터페이스 메서드와 XML의 namespace/id 및 #{} 파라미터를 맞춘다.
