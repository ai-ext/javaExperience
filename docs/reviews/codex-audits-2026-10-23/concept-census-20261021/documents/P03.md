## 애노테이션과 소비 주체

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** `@Override`는 컴파일러, Lombok은 annotation processor, `@Service`는 Spring component scan이 읽습니다. 읽는 주체가 없으면 애노테이션만 붙여도 동작하지 않습니다.

**언제 사용하는가:** 새 애노테이션을 보면 대상·보존기간·소비자·실행 시점을 먼저 확인합니다. Spring 기능은 컨테이너가 관리하는 객체 경계에서 사용합니다.

**대안과 경계:** 소스 주석과 달리 애노테이션은 구조화된 메타데이터지만, 실행 로직 자체는 아닙니다.

**예시·실행 근거:** `@Service`만 붙이고 직접 `new`하면 Spring Bean 등록·프록시가 생기지 않는다는 Q&A를 안내합니다.

**선수개념:** Java 타입과 클래스; 컴파일 단계; Spring Bean

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 리플렉션/Retension과 processor 내부는 J06에 위임합니다.

## Bean 등록·의존 주입·설정 바인딩

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** `@Component` 계열은 scan 후보, `@Bean`은 메서드가 만든 객체 등록, 생성자 인자는 필수 협력 객체 연결을 표현합니다. `@Primary`·`@Qualifier`는 중복 후보를 고릅니다.

**언제 사용하는가:** 직접 작성한 클래스는 stereotype, 외부 라이브러리 객체는 `@Bean`으로 등록하고 필수 의존성은 생성자로 받습니다. 설정 한 값은 `@Value`, 설정 묶음은 `@ConfigurationProperties`가 맞습니다.

**대안과 경계:** `@Service`가 자동으로 트랜잭션을 만들지 않습니다. `@Bean`은 클래스를 스캔해 생성하는 방식과 다릅니다.

**예시·실행 근거:** `Clock`은 JDK 타입이라 `@Configuration`의 `@Bean`으로 등록하고 GreetingService 생성자에 전달하는 예를 제시합니다.

**선수개념:** 생성자·인터페이스; 컴포넌트 스캔; 환경 설정

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 동일 타입 후보/조건·프로파일별 빈 선택과 생명주기는 P11/S01에서 더 다룹니다.

**초보자가 시작할 질문:**

- `Clock`처럼 내 코드가 아닌 클래스를 Spring에 맡기려면 어디에 빈을 선언하나요?
- 같은 `PaymentGateway`가 두 개 등록되면 Spring은 무엇을 기준으로 고르나요?

## HTTP 입력 바인딩과 검증

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** `@PathVariable`은 URL 경로, `@RequestParam`은 query, `@RequestBody`는 JSON 본문에서 DTO를 만듭니다. `@Valid`가 DTO 제약을 실행하고 Validation 구현 의존성도 필요합니다.

**언제 사용하는가:** 요청 위치와 자원 의미에 따라 경로/쿼리/본문을 나누고, 외부 입력은 Controller 경계에서 검증합니다.

**대안과 경계:** `@Valid`는 제약 선언만으로 실행되지 않습니다. `@Validated`는 그룹·메서드 검증 등 Spring 기능을 추가합니다.

**예시·실행 근거:** 빈 customer에 `@NotBlank`, 잘못된 이메일에 `@Email`을 적용한 CreateOrder 예제를 제시합니다. Spring HTTP 예제는 미실행입니다.

**선수개념:** HTTP 경로·쿼리·본문; JSON/DTO; 제약 검증

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 메서드 검증의 proxy/self-invocation 조건은 상세 실행되지 않습니다.

**초보자가 시작할 질문:**

- `/orders/17?view=brief`에서 17과 brief는 각각 어떤 매개변수로 받아야 할까요?
- DTO에 `@NotBlank`만 붙였는데 빈 값이 통과한다면 빠진 실행 지점은 무엇일까요?

## JPA 매핑과 트랜잭션 애노테이션

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** `@Entity`·`@Id`·`@Column`은 객체와 테이블 매핑을 선언하고 `@Transactional`은 호출 작업의 트랜잭션 경계를 뜻합니다.

**언제 사용하는가:** 영속 모델과 데이터 관계를 매핑할 때 persistence annotations를 쓰고, 여러 DB 변경을 묶을 때 transaction boundary를 둡니다.

**대안과 경계:** `@Entity`가 붙었다고 트랜잭션이 시작되는 것은 아닙니다. 관계 소유자와 lazy loading도 별도 정책입니다.

**예시·실행 근거:** 치트시트에 Entity·ID·관계 애노테이션과 `@Transactional`을 각각 나열하지만 실제 저장 예제는 없습니다.

**선수개념:** JPA Entity; Spring proxy; DB 관계

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 관계/지연로딩은 S09, 트랜잭션 의미는 S08로 넘깁니다.

**초보자가 시작할 질문:**

- `@Entity`와 `@Transactional`은 각각 누구에게 무엇을 요청하는 표시인가요?
- 양방향 연관관계에서 관계를 실제 저장할 주인은 어떤 규칙으로 정하나요?

## 프로파일·테스트 범위·Lombok

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** `@Profile`은 활성 환경에 따라 Bean 등록을 제한합니다. `@SpringBootTest`, `@WebMvcTest`, `@DataJpaTest`는 올리는 컨텍스트 범위가 다르고 Lombok은 컴파일 중 멤버를 생성합니다.

**언제 사용하는가:** 앱 전체 배선은 통합 테스트, MVC/DB 경계는 slice, 순수 로직은 일반 단위 테스트로 나눕니다.

**대안과 경계:** `application-local.yml`이라는 파일명만으로 프로파일이 켜지지 않습니다. `@Data`는 equals/hashCode/toString까지 만들 수 있어 JPA 관계에 무심코 쓰지 않습니다.

**예시·실행 근거:** Boot 4.1 테스트 import를 표기하고 Lombok 생성 코드·processor 설정을 설명합니다. Spring 예제는 미실행으로 표기됩니다.

**선수개념:** 프로파일; JUnit·Mockito; annotation processor

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- Boot 4 패키지 경로·JUnit 버전은 고정된 예시 버전으로 다시 확인해야 합니다.

**초보자가 시작할 질문:**

- `application-local.yml`이 있는데도 local 값이 안 들어오면 어떤 로그부터 볼까요?
- IDE에서는 Lombok getter가 보이는데 Gradle 컴파일은 실패한다면 무엇을 분리해 확인해야 할까요?
