## test double 역할 구분

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** test double은 placeholder, 고정 결과 제공, 실제 객체 일부 사용, 상호작용 검증, 단순 대체 구현 등 테스트에서 맡는 역할로 구분한다.

**언제 사용하는가:** 외부 효과나 비결정적 조건을 통제할 때 사용한다.

**대안과 경계:** fake는 메모리 구현을 사용할 수 있지만 실제 운영 DB의 SQL·제약 동작을 증명하지 않는다.

**예시·실행 근거:** ProductStore를 Map으로 흉내 낸 fake와 실제 DB 테스트의 경계를 비교한다.

**선수개념:** interface; Repository

**관련 표기·별칭:** test double role taxonomy; dummy; stub; spy; mock; fake

**보완·검증 필요 사항:**

- 증상으로 테스트 종류를 찾는 입문 경로가 더 필요하다.

## spy side effect와 객체 상태

현재 판정: **미검증** / 우선순위: high

**정의와 실제 역할:** spy는 별도 설정이 없으면 실제 메서드를 실행한다. when(spy.method())은 stubbing 설정 중 실제 호출을 먼저 할 수 있고 doReturn은 이를 피한다.

**언제 사용하는가:** 기존 동작을 일부 유지하면서 제한된 호출 결과만 바꾸려는 legacy test에 사용한다.

**대안과 경계:** spy는 원본 객체와 복사한 상태가 달라질 수 있다. private 메서드를 직접 검사하는 방식은 피한다.

**예시·실행 근거:** 예외, 상태와 원본 객체가 각각 어떻게 달라지는지 JUnit 예제를 확인한다.

**선수개념:** Mockito 기본 동작

**관련 표기·별칭:** spy side effect and state; when; doReturn; Mockito spy

**보완·검증 필요 사항:**

- 원문 예제는 복사된 사례로 소개됐으며 이번 감사에서 실행하지 않았다.

**초보자가 시작할 질문:**

- spy stubbing을 설정하는 중 원래 메서드가 먼저 실행되나?

## mock 경계와 상호작용 assertion

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 업무 Service는 실제 실행하고 의존 collaborator를 대체해 공개 계약에 필요한 상호작용을 검증한다.

**언제 사용하는가:** Spring context 일부나 외부 시스템을 대체해야 하는 테스트에서 사용한다.

**대안과 경계:** mock 호출 검증은 SQL 실행의 증거가 아니다. 내부 호출을 과도하게 검증하면 리팩터링에 취약해진다.

**예시·실행 근거:** 실제 Controller와 mock Service를 둔 MVC test 및 생성자 주입 Service test를 비교한다.

**선수개념:** Spring context; Mockito

**관련 표기·별칭:** mock boundary and interaction assertions; @MockitoBean; ArgumentCaptor; STRICT_STUBS

**보완·검증 필요 사항:**

- 상호작용 검증은 외부 계약에 필요한 범위로 제한해야 한다.

**초보자가 시작할 질문:**

- Service 테스트에서 실제 실행할 코드와 대체할 경계는 어디인가?

## 제어 가능한 clock과 외부 HTTP 테스트 경계

현재 판정: **미검증** / 우선순위: high

**정의와 실제 역할:** 제어 가능한 시각과 HTTP 응답기를 주입해 경계 시간 및 외부 응답을 재현한다.

**언제 사용하는가:** 시간 민감 정책이나 외부 응답 decoding을 검증할 때 사용한다.

**대안과 경계:** mock server는 HTTP 요청/응답 mapping을 시험하고 WireMock은 네트워크 경계를 별도로 시험할 수 있다.

**예시·실행 근거:** 고정 시각과 partner JSON 응답을 사용한다.

**선수개념:** HTTP; 시각/시간

**관련 표기·별칭:** clock and external HTTP test boundary; Clock.fixed; MockRestServiceServer; WireMock

**보완·검증 필요 사항:**

- 새 예제는 실행되지 않았다.

## 시각 구조와 보완 장면

**기존 표현**

- 표, test code와 stubbing 설정으로 mock/stub/spy/fake 역할을 설명한다.

**정적 구조의 한계**

- 실제 render와 테스트 실행은 하지 않았다.

**추가할 의미 장면**

- 같은 호출에 mock·stub·spy·fake를 적용해 side effect와 실제 DB 증거가 어떻게 달라지는지 비교한다.
