## DI 구성과 인터페이스 계약은 서로 다른 선택

현재 판정: **부분** / 우선순위: P1

**정의와 실제 역할:** DI는 객체 생성/구성 책임을 컨테이너에 맡기는 방식이고, 인터페이스는 호출자와 구현 사이의 계약이다. 구체 클래스도 생성자 주입할 수 있다.

**언제 사용하는가:** 외부 업체/복수 정책/모듈 소유권처럼 변경 경계가 있을 때 최소 포트를 만든다. 내부 단일 구현은 구체 주입으로 시작 가능.

**대안과 경계:** 인터페이스를 만들어도 구현이 호출자에게 새거나 모든 사용처가 Impl에 결합되면 교체 경계가 아니다. 추상 클래스는 상태/공통 구현 재사용 시 별도 선택.

**예시·실행 근거:** CheckoutService는 ShippingQuotePort만 알고 DomesticAdapter가 구현; 내부 OrderService는 TaxPolicy 구체 빈을 주입 가능.

**선수개념:** 생성자 주입; Spring bean 후보 선택; 의존성 방향; adapter 역할

**관련 표기·별칭:** Dependency Injection; concrete-class injection; port/adapter

**판정 이유:** 개념 정의와 선택 기준은 다루지만 실습/실행이나 학습 과제의 검증 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- Spring 예제는 미실행; 순수 Java 전략 예시만 소스가 실행했다고 표기.
- 외부 포트가 SDK 타입을 그대로 노출하면 결합 격리가 약해진다.
- 다중 구현 시 빈 선택 모호성과 @Primary/@Qualifier 비용을 다룬다.

## JDK/CGLIB AOP 프록시와 테스트 더블 선택

현재 판정: **부분** / 우선순위: P1

**정의와 실제 역할:** Spring AOP 프록시는 구현 인터페이스가 있으면 JDK 프록시 또는 클래스 기반 CGLIB를 쓸 수 있으며 실제 기본은 구성에 의존한다. Mockito는 구체 타입도 목으로 만들 수 있다.

**언제 사용하는가:** 프록시되는 bean의 주입 타입/메서드 가시성 문제를 디버깅하거나, 외부 협력자 대체 테스트 경계를 선택할 때.

**대안과 경계:** JDK proxy는 interface API로 노출; CGLIB는 subclass라 final 제약. 목은 SQL/HTTP 실동작 증명이 아니며 통합 테스트를 대체하지 않는다.

**예시·실행 근거:** 단위 테스트에서 CheckoutService에 Mockito class/interface mock 직접 전달; Spring test는 @MockitoBean으로 컨텍스트 bean override.

**선수개념:** Java proxy/subclass; bean 후보; unit vs context vs integration test

**관련 표기·별칭:** JDK dynamic proxy; CGLIB; Mockito; @MockitoBean

**판정 이유:** 개념 정의와 선택 기준은 다루지만 실습/실행이나 학습 과제의 검증 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- 실제 Spring 컨텍스트의 proxy 선택/주입은 실행 확인하지 않았다.
- framework7 문서상 @Proxyable 언급과 Boot 전역 설정의 조합은 프로젝트 설정 확인 필요.
- mockito dependency/version을 실제 build로 해결·테스트하지 않았다.
