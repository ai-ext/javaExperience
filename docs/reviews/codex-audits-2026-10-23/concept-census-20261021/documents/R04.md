## JOIN 결과 행 수와 NULL

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** JOIN은 조건에 맞는 행 쌍을 만들고 join 종류에 따라 왼쪽 또는 오른쪽 행 보존을 결정한다.

**언제 사용하는가:** 관련 table을 함께 읽거나 집계할 때 사용한다.

**대안과 경계:** 1:N join은 parent 값을 여러 행으로 늘릴 수 있다. nullable side에 WHERE 조건을 걸면 unmatched 행이 없어질 수 있다. COUNT(*)와 COUNT(column)도 NULL 처리에서 다르다.

**예시·실행 근거:** 주문이 없는 회원과 join 후 합계가 부풀어 오르는 예를 확인한다.

**선수개념:** PK/FK; 집계

**관련 표기·별칭:** join cardinality and NULL; INNER; LEFT; RIGHT; CROSS; SELF JOIN

**보완·검증 필요 사항:**

- 예제 결과는 기대값이며 DB에서 실행하지 않았다.

**초보자가 시작할 질문:**

## EXISTS와 NULL이 포함된 하위 질의

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** EXISTS는 자식 행 존재 여부를 검사해 parent 행 중복을 만들지 않는다. NOT IN 목록에 NULL이 있으면 결과가 UNKNOWN이 될 수 있다.

**언제 사용하는가:** semi-join/anti-join 형태의 존재 여부를 판단할 때 사용한다.

**대안과 경계:** 실제 query plan은 optimizer와 통계에 따라 달라진다.

**예시·실행 근거:** 결제 주문이 한 건 이상 있는 회원을 EXISTS로 찾는다.

**선수개념:** subquery; NULL

**관련 표기·별칭:** EXISTS and NULL subquery; EXISTS; NOT EXISTS; NOT IN

**보완·검증 필요 사항:**

- 실제 EXPLAIN 결과가 없다.

**초보자가 시작할 질문:**

- 자식 행이 있는지 여부만 확인하면서 회원 중복을 피하려면?

## 안전한 CRUD와 transaction

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** DML은 행을 변경하고 transaction은 여러 statement를 한 단위로 묶는다. bound parameter는 값 입력을 안전하게 전달한다.

**언제 사용하는가:** 변경 query를 실행하기 전에 대상 행과 변경 결과를 확인할 때 사용한다.

**대안과 경계:** autocommit은 statement마다 commit할 수 있고 DDL은 implicit commit할 수 있다. table/column identifier는 일반 bound parameter로 치환되지 않는다.

**예시·실행 근거:** 재고 UPDATE 후 affected rows와 SELECT 결과를 확인하고 rollback한다.

**선수개념:** transaction; prepared statement

**관련 표기·별칭:** safe CRUD and transactions; INSERT; UPDATE; DELETE; autocommit; bind parameters

**보완·검증 필요 사항:**

- 예상 결과 중심이며 DB 실행 기록이 없다.

**초보자가 시작할 질문:**

- 조건 없는 UPDATE를 실행하기 전에 무엇을 확인해야 하나?

## SQL UNION과 UNION ALL 누락

현재 판정: **누락** / 우선순위: high

**정의와 실제 역할:** SQL UNION은 호환되는 열 구조의 조회 결과를 하나의 결과 집합으로 합친다.

**언제 사용하는가:** 두 SELECT 결과를 합치되 중복 행을 제거할지 보존할지 정할 때 사용한다.

**대안과 경계:** UNION은 기본적으로 중복을 제거하고 UNION ALL은 중복을 그대로 남긴다.

**예시·실행 근거:** 백업 검산 query의 UNION ALL 사용은 원문에 있으나 의미 설명/결과 예제로 다루지 않는다. 학습 보강 예는 동일 행이 두 SELECT에 있을 때 UNION은 1행, UNION ALL은 2행이 되는 비교다.

**선수개념:** SELECT 결과; 열 개수와 타입 호환성

**관련 표기·별칭:** UNION and multiset gap; UNION; UNION ALL; bag semantics

**보완·검증 필요 사항:**

- 원문에 백업 복원 검산 SQL에서 UNION ALL 문자열이 등장할 수 있으나, UNION과 UNION ALL의 독립 정의·결과 중복 차이·선택 기준·입문자 실습은 없다. 문자열/코드 검색 적중만으로 개념 설명 coverage라고 판정하지 않는다.

**초보자가 시작할 질문:**

- 같은 결과 행을 합칠 때 중복을 없애거나 남기려면 무엇을 선택하나?
