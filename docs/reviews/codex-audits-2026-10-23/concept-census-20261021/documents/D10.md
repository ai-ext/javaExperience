## 데이터 model·schema·constraint·normalization

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** relational model은 table, key, relationship로 데이터를 표현한다. schema와 constraints가 값·참조 범위를 지키며 normalization은 중복 사실로 생기는 이상을 줄인다.

**언제 사용하는가:** 회원/수강 데이터처럼 사실의 소유 위치와 DB 무결성을 설계할 때 사용한다.

**대안과 경계:** PK/FK/UNIQUE/CHECK는 서로 다른 규칙을 보장한다. normalization이 모든 업무상 snapshot 복제를 금지하는 것은 아니다.

**예시·실행 근거:** 등록 사례로 회원, 강좌, enrollment 관계와 key/constraint를 연결한다.

**선수개념:** table/row; PK/FK

**관련 표기·별칭:** model/schema/constraints/normalization

**보완·검증 필요 사항:**

- worked example은 있으나 사용자 기존 데이터의 실제 anomaly 실행은 하지 않았다.

## query plan과 index

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 옵티마이저는 index를 포함한 실행계획을 선택하고 예상 행 수·비용을 계산한다. 실제 실행 관측은 estimate와 다를 수 있다.

**언제 사용하는가:** 어떤 조건에서 index가 선택되는지와 추정/실제 행 수 차이를 조사할 때 사용한다.

**대안과 경계:** index는 read를 도울 수 있지만 쓰기 비용과 저장공간을 더한다. 계획의 추정값은 실제 시간이나 실제 행 수와 같지 않다.

**예시·실행 근거:** 같은 query에서 EXPLAIN 계획과 실제 실행 결과를 구분해 읽는다.

**선수개념:** SQL query; index; 통계

**관련 표기·별칭:** query plans and indexes

**보완·검증 필요 사항:**

- 예제는 현재 애플리케이션 workload를 측정하지 않는다.

## transaction·lock·운영 경계

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** transaction isolation, lock, deadlock, connection pool, replica lag, sharding과 backup은 서로 다른 DB 운영 경계다.

**언제 사용하는가:** 동시 쓰기, connection 대기, replica 최신성, 백업 복구 위험을 설계할 때 사용한다.

**대안과 경계:** 앱 transaction과 여러 DB 간 원자성은 다르다. replica read와 primary write 사이에 복제 지연이 있을 수 있다.

**예시·실행 근거:** 주문 변경이 commit된 뒤 replica에 언제 보이는지와 백업 restore 경계를 따라간다.

**선수개념:** transaction; DB connection; replication

**관련 표기·별칭:** transactions/locks/operations

**보완·검증 필요 사항:**

- 원문은 개요를 모으지만 각 운영 방법의 실제 실행/복구 검증은 하지 않았다.

**초보자가 시작할 질문:**

- 주문을 저장했는데 replica에는 예전 값이 보이면 무엇을 확인하나?

## NoSQL 모델과 저장소 선택

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 저장소는 유행이나 JSON 형식만으로 선택하지 않고 query/access pattern과 무결성·운영 요구로 비교한다. 구현 세부는 R02/P23에 연결한다.

**언제 사용하는가:** 실제 조회 형태와 consistency/durability 요구에 맞춰 storage를 비교할 때 사용한다.

**대안과 경계:** NoSQL은 schema와 운영 비용이 없는 저장소가 아니며 RDB와 같은 ACID 동작이라고 가정하면 안 된다.

**예시·실행 근거:** 같은 요구를 RDB·document·Redis 선택표와 R02/P23 사례로 비교한다.

**선수개념:** query pattern; 무결성 요구

**관련 표기·별칭:** NoSQL and product choice

**보완·검증 필요 사항:**

- 제품별 query/복구 동작을 이 문서만으로 검증할 수 없다.

## 실제 캡처 관찰

- 데스크톱·모바일 첫 화면은 DB를 표 이상으로 설명하는 요약을 보여준다. core는 RDBMS/PK/FK/UK/index/transaction 등 사전 표가 길게 열려 있어 사용자는 원하는 용어를 볼 수 있으나 정보량이 크다. 모델링부터 plan·transaction으로 이어지는 본문 그림은 별도 절이다. 실제 한 order row를 Entity→SQL→plan→commit 후 DB 행으로 이어 보여 주면 용어가 의미와 연결된다.
