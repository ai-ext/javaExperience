## Spring AOP 프록시·advice·pointcut

현재 판정: **부분** / 우선순위: P0

**정의와 실제 역할:** Aspect는 횡단 관심사를 모으고 pointcut은 Spring bean 메서드 실행을 선택하며 advice가 프록시 호출에서 target 앞뒤로 동작한다. 자동 프록시는 BeanPostProcessor 기반으로 만들어질 수 있다.

**언제 사용하는가:** 트랜잭션·메트릭·로그·보안처럼 bean 메서드 호출 경계에서 공통 처리가 필요할 때.

**대안과 경계:** Spring AOP는 proxied bean method만 대상으로 하며 AspectJ weaving은 생성자·필드 접근 등 넓은 bytecode point를 다룰 수 있다. 직접 new된 객체와 내부 호출은 경계를 지나지 않는다.

**예시·실행 근거:** @Around에서 timer를 시작하고 try/finally로 메서드 시간을 재며 proceed를 한 번 호출하고 결과/예외를 그대로 전달한다.

**선수개념:** IoC bean refs; method invocation

**관련 표기·별칭:** Aspect; Advice; Pointcut; Join point; Advisor; target; proxy

**판정 이유:** 개념 정의와 선택 기준은 다루지만 실습/실행이나 학습 과제의 검증 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- Spring AOP runtime 예제 및 generated proxies는 실행하지 않았다.

**초보자가 시작할 질문:**

- @Aspect는 weaving인가?
- Spring AOP가 가로채는 지점은?
- advice가 실행되려면?

## JDK/CGLIB, self-invocation, @Order

현재 판정: **부분** / 우선순위: P0

**정의와 실제 역할:** JDK proxy는 인터페이스 구현체, CGLIB는 target 하위 클래스를 만든다. Boot는 CGLIB 기본, Framework 일반 규칙은 인터페이스가 있으면 JDK를 선택할 수 있다. target의 this 호출은 양쪽 proxy를 우회한다.

**언제 사용하는가:** 서비스 호출 계약을 interface에 노출하고, advice 대상 메서드는 proxy를 통과하도록 별도 bean으로 분리한다.

**대안과 경계:** CGLIB는 final class를 상속하지 못하고 final/private 메서드를 override 못한다. JDK proxy 타입은 interface 계약이다. @Order는 advice ordering이지 bean 생성 순서가 아니다.

**예시·실행 근거:** 외부 bean → proxy → advice → target 흐름. 내부 this.method 호출은 proxy를 통과하지 않으므로 advice 미적용.

**선수개념:** Java inheritance/interface; Spring bean proxy

**관련 표기·별칭:** JDK dynamic proxy; CGLIB; self-invocation; @Order; final/private

**판정 이유:** 개념 정의와 선택 기준은 다루지만 실습/실행이나 학습 과제의 검증 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- Framework7 @Proxyable과 Boot 설정 조합은 정확한 dependency context에서 검증 필요.

**초보자가 시작할 질문:**

- Interface bean이 왜 CGLIB일까?
- final method advice가 빠지는 이유?
- this.other()에서 @Transactional이 빠지는 이유?
- @Order 작은 값이 먼저인가?
