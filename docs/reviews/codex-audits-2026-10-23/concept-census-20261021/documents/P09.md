## class·field·object·scope

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 클래스는 필드/생성자/메서드를 선언하고 new 객체는 인스턴스 필드 상태를 가집니다. static 필드는 클래스 소속, local 변수는 선언 블록 안에서 읽기 전 초기화가 필요합니다.

**언제 사용하는가:** 필드에 객체 상태, 메서드 local에 일시 계산을 두고 요청별 상태를 static으로 공유하지 않습니다.

**대안과 경계:** 필드 기본값과 local 변수 definite assignment는 다릅니다. static 메서드에는 this가 없습니다.

**예시·실행 근거:** Invoice 예제와 지역/인스턴스/static 변수 표.

**선수개념:** Java 기본 문법과 해당 API의 연산 의미

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 실제 객체 수명과 JMM 물리 배치는 이 문서 깊이를 넘어갑니다.

**초보자가 시작할 질문:**

- 클래스 필드가 0으로 보이는데 같은 값을 local로 선언하면 왜 컴파일 오류가 날까요?
- Spring Controller에서 요청별 값을 static 필드에 두면 어떤 요청 간 간섭이 생길까요?

## method call·return·overload·varargs

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 메서드의 이름/매개변수/반환 타입/throws/body를 읽고 인자 표현식으로 호출 대상을 정합니다.

**언제 사용하는가:** 같은 작업의 입력 signature가 달라 overload하며 여러 인자는 마지막 varargs로 받습니다.

**대안과 경계:** 반환 타입만 다른 선언은 overload가 아니며 `static` 호출에는 특정 객체의 this가 없습니다.

**예시·실행 근거:** MethodsDemo 실제 실행 출력으로 overload/static/varargs를 확인합니다.

**선수개념:** Java 기본 문법과 해당 API의 연산 의미

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 제네릭 overload resolution은 J03에서 보강 필요

## 캡슐화·접근 제어·final

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** private 필드와 검증 메서드로 외부 변경 경로를 제한하며 access와 name scope를 구분합니다.

**언제 사용하는가:** 상태 변경이 필요할 때 허용된 operation만 노출하고 필드 전체에 setter를 만들지 않습니다.

**대안과 경계:** private와 지역 변수 scope는 다른 개념이며 final 참조가 가리키는 객체는 여전히 변경 가능할 수 있습니다.

**예시·실행 근거:** 수량 setter가 음수를 거부하는 예시.

**선수개념:** Java 기본 문법과 해당 API의 연산 의미

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- immutable collection 깊은 복사와 domain 설계는 추가 사례 필요

**초보자가 시작할 질문:**

- setter가 아무 숫자나 받으면 private 필드가 있어도 캡슐화가 약해지는 이유는 무엇인가요?
- final List의 reference와 list contents 중 무엇이 고정되나요?

## Java 값 전달과 참조 별칭

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 기본값도 참조값도 값으로 전달됩니다. 같은 객체를 가리키는 참조 복사본으로 필드를 수정하면 보이지만 매개변수 재할당은 caller 변수에 반영되지 않습니다.

**언제 사용하는가:** 새 객체를 caller에게 돌려주려면 return해 caller가 대입합니다.

**대안과 경계:** `pass-by-reference` 설명은 정확하지 않으며 mutable aliasing은 동시성 안전을 보장하지 않습니다.

**예시·실행 근거:** PassByValueDemo 실제 출력: field mutation 보임, parameter reassignment/primitive reassignment는 caller 값 유지.

**선수개념:** Java 기본 문법과 해당 API의 연산 의미

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 별칭이 여러 스레드에서 공유되면 J10/J11 규칙 추가

**초보자가 시작할 질문:**

- 메서드에 `Profile p`를 넣은 뒤 p.nickname을 바꾸면 보이는데 p=new Profile(...)은 안 보이는 이유는 무엇인가요?
- 입력 int를 99로 바꿔도 호출자 int가 그대로인 이유는 무엇인가요?

## 연산자·우선순위·short circuit

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 연산은 중간 타입·우선순위·좌결합과 단락 평가로 결과를 만듭니다. int overflow와 binary float 근사도 포함됩니다.

**언제 사용하는가:** 복잡 조건은 괄호/중간 boolean으로 풀고 0 분모 guard는 &&로 보호합니다. 금액은 BigDecimal을 검토합니다.

**대안과 경계:** `&`/`|` boolean 연산은 양쪽을 평가하고 `&&`/`||`는 결과가 정해지면 건너뜁니다.

**예시·실행 근거:** OperatorsDemo가 calls=1과 산술/우선순위 출력을 보여줍니다.

**선수개념:** Java 기본 문법과 해당 API의 연산 의미

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 정밀한 BigDecimal 정책은 J01

**초보자가 시작할 질문:**

- `denominator != 0 && total/denominator > 3`이 0 나누기를 막는 단계는 무엇인가요?
- false && (++calls > 0)에서 오른쪽 식은 왜 실행되지 않나요?
