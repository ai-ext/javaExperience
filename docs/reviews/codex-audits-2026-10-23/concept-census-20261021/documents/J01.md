## 기본형과 참조형·박싱

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 기본형 변수는 값을, 참조형은 객체 참조 또는 null을 저장합니다. wrapper는 nullable·제네릭 경계에서 기본 값을 감쌉니다.

**언제 사용하는가:** nullable이 필요하지 않으면 primitive, 외부 데이터에 값 없음이 가능하면 wrapper로 받아 먼저 검증합니다.

**대안과 경계:** wrapper끼리 `==`는 참조 동일성이고 혼합 비교는 unboxing될 수 있습니다. null wrapper의 unboxing은 NPE입니다.

**예시·실행 근거:** BoxingDemo가 127/128 참조 비교와 null unboxing 실패를 출력합니다.

**선수개념:** Java 기본 문법과 값/객체 참조

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 숫자 승격/narrowing 규칙은 표현식별로 추적해야 합니다.

**초보자가 시작할 질문:**

- nullable Integer가 null인 채 `x + 1`에 들어가면 어디서 실패할까요?
- 왜 Integer 127과 128의 `==` 결과를 값 비교로 믿으면 안 될까요?

## 오버플로와 BigDecimal

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** int/long은 범위를 넘으면 예외 대신 오버플로하고 double은 십진 소수를 정확히 표현하지 못합니다. BigDecimal은 unscaled value와 scale로 표현합니다.

**언제 사용하는가:** 금액 등 정확한 십진 계약은 문자열 기반 BigDecimal과 반올림 규칙을 정합니다.

**대안과 경계:** BigDecimal compareTo는 수치, equals는 scale 표현도 비교합니다.

**예시·실행 근거:** NumericDemo가 0.1+0.2, int overflow, BigDecimal 1.0/1.00 차이를 실행합니다.

**선수개념:** Java 기본 문법과 값/객체 참조

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 각 업무 도메인의 scale/rounding 정책은 별도로 정해야 합니다.

**초보자가 시작할 질문:**

- double 0.1을 BigDecimal 생성자에 넣으면 왜 예상보다 긴 소수가 나오나요?
- 1.0과 1.00을 같은 금액으로 볼 때 equals와 compareTo 중 무엇이 맞을까요?

## String 불변성과 연결

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** String 객체 내용은 바뀌지 않지만 변수는 다른 객체를 가리키도록 재할당할 수 있습니다. 리터럴 pooling은 일부 `==` 결과에 영향 줍니다.

**언제 사용하는가:** 문자 내용 비교는 equals, 짧은 연결은 +, 반복 누적은 StringBuilder로 표현합니다.

**대안과 경계:** JEP 280의 연결 전략은 런타임 구현이며 소스에서 임시 객체 수를 가정하면 안 됩니다.

**예시·실행 근거:** StringDemo와 `javap`가 literal identity와 invokedynamic 출력 증거를 제시합니다.

**선수개념:** Java 기본 문법과 값/객체 참조

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- 반복 연결 성능은 정량 측정 없이 단정하지 않습니다.

**초보자가 시작할 질문:**

- new String("java")와 리터럴의 `==`가 다른데 내용을 비교하려면 무엇을 쓰나요?
- 긴 루프에서 result += part를 반복하면 어떤 비용이 생기나요?

## Equality and conversion pitfalls

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** Java는 피연산자의 선언 타입을 기준으로 숫자 승격·축소 변환을 정하고, `==`와 `equals`는 기본형과 참조형에서 서로 다른 비교를 합니다.

**언제 사용하는가:** 산술 결과의 범위와 객체 동등성 조건을 검토해 버그가 없는지 확인합니다.

**대안과 경계:** 기본형 `==`는 값을 비교하고 참조형 `==`는 같은 객체인지 비교합니다. `equals`는 클래스가 정의한 논리적 동등성을 확인합니다.

**예시·실행 근거:** 숫자 변환·`==`·`equals`의 차이와 대소문자·null 상황을 예제 및 Q&A에서 확인합니다.

**선수개념:** Java 타입·메서드 호출 기초

**관련 표기·별칭:** 

**보완·검증 필요 사항:**

- Not a full numeric type-conversion exercise.

**초보자가 시작할 질문:**

- 서로 다른 wrapper 객체에 같은 숫자를 넣었는데 `==`와 `equals` 결과가 다른 이유는 무엇인가요?
- 정수에 실수를 대입하거나 큰 값을 작은 정수형에 넣으면 어떤 값이 남나요?
