## Controller slice 테스트 경계

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 실제 MVC와 Controller를 실행하고 Service 이후 경계는 mock으로 대체한다.

**언제 사용하는가:** HTTP routing, JSON 직렬화, status와 ProblemDetail 응답을 확인할 때 사용한다.

**대안과 경계:** 이 테스트는 실제 Service나 DB query를 실행하지 않는다.

**예시·실행 근거:** 상품 API의 200/404 응답 계약을 확인한다.

**선수개념:** HTTP 요청; test double

**관련 표기·별칭:** Controller slice boundary; @WebMvcTest; MockMvc; @MockitoBean

**보완·검증 필요 사항:**

- 한 테스트 메서드의 성공/실패 시나리오를 독립 테스트로 나누는 편이 원인 파악에 좋다.

## container 생명주기와 fixture

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** Spring Boot가 테스트 container를 연결하고 schema/seed fixture가 DB 상태를 준비한다.

**언제 사용하는가:** 반복 가능한 DB 통합 테스트 환경을 구성할 때 사용한다.

**대안과 경계:** transaction rollback은 해당 transaction에 참여한 변경만 되돌린다. JUnit container와 Spring context의 생명주기가 다르면 DB 수명도 어긋날 수 있다.

**예시·실행 근거:** 정해진 schema와 seed를 가진 static container를 사용한다.

**선수개념:** SQL fixture

**관련 표기·별칭:** Container lifecycle and fixtures; ServiceConnection; schema.sql; seed.sql

**보완·검증 필요 사항:**

- 수동 commit이나 HTTP 경로의 정리 절차는 제한적으로 다뤄진다.

**초보자가 시작할 질문:**
