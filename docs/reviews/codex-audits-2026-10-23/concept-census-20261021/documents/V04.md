## 테스트 DB 엔진 선택

현재 판정: **미검증** / 우선순위: high

**정의와 실제 역할:** 테스트 목적에 따라 DB를 고른다. Service 단위 테스트는 DB 없이 실행할 수 있지만 SQL 방언·제약·lock을 보려면 실제 엔진이 필요하다.

**언제 사용하는가:** Repository나 DB 동작 중 MySQL 고유 계약을 확인할 때 사용한다.

**대안과 경계:** H2 호환 모드는 별도 서버 구현이며 collation과 lock 의미가 MySQL과 다를 수 있다.

**예시·실행 근거:** MySQL 8.4 Testcontainers 실행 결과를 사용한다.

**선수개념:** SQL; DB 엔진

**관련 표기·별칭:** DB engine selection; H2; Testcontainers MySQL

**보완·검증 필요 사항:**

- Spring 코드 예제는 실행하지 않았다.

**초보자가 시작할 질문:**

## DataJpaTest의 datasource 대체

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** JPA slice test는 embedded DB로 datasource를 대체할 수 있다. 실제 container 연결을 위해 ServiceConnection과 replacement 비활성화를 설정한다.

**언제 사용하는가:** 실제 DB 엔진으로 JPA slice를 시험할 때 사용한다.

**대안과 경계:** 테스트 transaction rollback은 참여 transaction의 변경에 적용된다. 테스트가 실제 연결한 datasource를 확인해야 한다.

**예시·실행 근거:** MySQL에서 ProductRepository count와 페이지를 조회한다.

**선수개념:** Spring test context; Docker

**관련 표기·별칭:** DataJpaTest and replacement; Replace.NONE; ServiceConnection

**보완·검증 필요 사항:**

- Spring Boot 4 import API는 공식 문서에서 확인할 필요가 있다.

**초보자가 시작할 질문:**

## fixture와 SQL 생명주기

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** context 초기화용 schema/seed와 각 테스트 메서드의 SQL fixture를 분리해 준비한다.

**언제 사용하는가:** DB 테스트마다 재현 가능한 초기 데이터가 필요할 때 사용한다.

**대안과 경계:** rollback은 테스트 transaction 범위에 적용된다. 별도 connection이나 commit된 행은 별도 정리가 필요할 수 있다.

**예시·실행 근거:** 부모 FK 데이터를 먼저 넣고 그 뒤 상품 fixture를 넣는다.

**선수개념:** SQL foreign key; transaction

**관련 표기·별칭:** fixture and SQL lifecycle; @Sql; schema.sql; seed.sql

**보완·검증 필요 사항:**

- 공유 seed fixture는 테스트 간 결합을 만들 수 있다.

**초보자가 시작할 질문:**

## flush·commit·transaction 경계

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 테스트 transaction과 HTTP server thread의 경계에 따라 SQL 실행 시점, lazy access와 commit event가 달라진다.

**언제 사용하는가:** SQL 제약, commit callback과 실제 서버 write를 확인할 때 사용한다.

**대안과 경계:** flush는 commit 전 SQL을 보낼 수 있다. 별도 HTTP server thread는 별도 transaction을 쓸 수 있으며 rollback되면 AFTER_COMMIT listener는 실행되지 않는다.

**예시·실행 근거:** TestTransaction으로 명시 commit한 뒤 데이터와 cleanup을 확인한다.

**선수개념:** JPA transaction; Spring event

**관련 표기·별칭:** flush/commit/transaction boundaries; flush; AFTER_COMMIT; RANDOM_PORT

**보완·검증 필요 사항:**

- 주문 관련 예제는 저장소에 없으며 템플릿으로만 제시된다.

**초보자가 시작할 질문:**

- flush가 commit과 같은가? 테스트에선 되는데 운영에선 lazy 오류가 왜 나나?

**근거:**
