## 컴파일러와 annotation processor

현재 판정: **미검증** / 우선순위: high

**정의와 실제 역할:** 애노테이션은 그 자체로 실행하지 않으며, 컴파일러나 annotation processor가 읽거나 코드를 생성할 수 있다.

**언제 사용하는가:** Lombok, MapStruct, QueryDSL처럼 컴파일 시점에 코드를 검사하거나 생성하는 도구를 사용할 때 구분한다.

**대안과 경계:** 일반 runtime dependency와 annotation processor 설정은 역할이 다르다.

**예시·실행 근거:** clean compile 후 generated source가 생성됐는지 확인한다.

**선수개념:** Java compiler

**관련 표기·별칭:** @Override; APT

**보완·검증 필요 사항:**

- 버전별 동작과 전체 Spring 앱 예제는 실행되지 않았다.

**초보자가 시작할 질문:**

- 애노테이션을 붙였는데 코드가 생성되지 않는 이유는 무엇인가?

## Bean 등록과 자동 구성

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** component scan, configuration parser와 조건 평가가 Spring context의 Bean definition을 등록한다.

**언제 사용하는가:** Spring component와 설정 클래스가 애플리케이션 context에 들어오는 경로를 확인할 때 사용한다.

**대안과 경계:** scan 범위나 조건이 맞지 않으면 애노테이션을 붙여도 Bean으로 등록되지 않을 수 있다.

**예시·실행 근거:** Bean 목록과 조건 평가 결과를 확인한다.

**선수개념:** IoC; classpath

**관련 표기·별칭:** Bean registration / autoconfig; @Component; @Bean; @Conditional

**보완·검증 필요 사항:**

- 전체 흐름은 설명 모델이며 실행 결과로 확인하지 않았다.

**초보자가 시작할 질문:**

- Bean 애노테이션을 붙였는데 왜 주입되지 않을까?

## MVC resolver와 validation

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** MVC의 argument resolver와 converter가 요청 값을 handler 인자에 바인딩하고 validation을 수행한다.

**언제 사용하는가:** Controller method의 경로 변수, 요청 본문과 유효성 검증 동작을 이해할 때 사용한다.

**대안과 경계:** @Valid만으로 규칙이 생기지 않는다. 제약 애노테이션과 validation provider가 필요하다.

**예시·실행 근거:** curl 요청 본문과 path 값이 정상/오류 응답으로 바뀌는지 확인한다.

**선수개념:** HTTP; DTO; validation

**관련 표기·별칭:** MVC resolver·validation; @RequestBody; @PathVariable; @Valid

**보완·검증 필요 사항:**

- 실제 예외 종류는 Framework 버전에 따라 달라질 수 있으므로 공식 문서 확인이 필요하다.

**초보자가 시작할 질문:**

- 잘못된 요청 값은 Controller method에 들어가기 전에 어떻게 거부되나?

## AOP proxy 경계

현재 판정: **미검증** / 우선순위: high

**정의와 실제 역할:** Spring AOP proxy는 관리 대상 Bean 호출을 감싸 transaction·cache·security 등의 advice를 적용한다.

**언제 사용하는가:** Bean proxy를 통과하는 호출에 공통 동작을 적용할 때 사용한다.

**대안과 경계:** 같은 객체 내부 호출, private/final 제한 또는 직접 생성한 객체는 기대한 proxy interception을 거치지 않을 수 있다.

**예시·실행 근거:** 같은 클래스 내부 호출과 다른 Bean 경유 호출을 비교한다.

**선수개념:** Spring Bean; proxy

**관련 표기·별칭:** AOP proxy; @Transactional; @Async; @Cacheable; @PreAuthorize

**보완·검증 필요 사항:**

- 예제는 실행되지 않았다.

**초보자가 시작할 질문:**

- @Transactional이 같은 클래스 안에서 호출될 때 왜 적용되지 않을까?

## 테스트 bootstrap 범위

현재 판정: **부분** / 우선순위: high

**정의와 실제 역할:** 테스트 bootstrap은 전체 Spring context 또는 MVC slice 등 필요한 구성 범위를 선택한다.

**언제 사용하는가:** Controller 계층만 확인할지 실제 통합 경계를 확인할지 정할 때 사용한다.

**대안과 경계:** slice test에는 업무 Bean이 모두 포함되지 않을 수 있다. 통합 테스트는 더 넓은 경계를 검증한다.

**예시·실행 근거:** MockMvc에서 실제 Controller와 대역 Service를 연결한다.

**선수개념:** Spring test

**관련 표기·별칭:** testing bootstrap; @SpringBootTest; @WebMvcTest; @MockitoBean

**보완·검증 필요 사항:**

- 외부 경로의 샘플을 참조하므로 이 결과만으로 프로젝트 자체 검증을 주장하지 않는다.

**초보자가 시작할 질문:**

- MockMvc 테스트에서 어떤 Bean이 실제로 실행되고 무엇을 대역 처리하나?
