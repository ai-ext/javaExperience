## Java naming conventions, semantic method names and role suffixes

현재 판정: **부분** / 우선순위: P1

**정의와 실제 역할:** Java 식별자 표기 대부분은 style convention이며 역할 접미사는 사람이 검색/책임을 읽는 표지다. Impl 자체가 Spring 동작을 켜지 않는다.

**언제 사용하는가:** 기존 코드의 일관성을 우선하고 의미 있는 구현 차이가 있으면 Jpa/Remote/Kakao 같은 이름을 쓴다.

**대안과 경계:** find/get/fetch는 Java 언어 표준 의미 차이가 아니다. 계약상 부재/필수/원격 비용 구분을 팀이 합의할 수 있다.

**예시·실행 근거:** 구현 하나는 OrderService, 외부 결제 adapter는 KakaoPaymentClient로 표현한다.

**선수개념:** Java identifiers; Spring bean registration; domain vocabulary

**관련 표기·별칭:** camelCase; PascalCase; UPPER_SNAKE_CASE; Impl; find/get/fetch

**판정 이유:** 핵심 설명과 선택 기준은 있으나 실행/학습 과제 근거가 부분적이므로 부분 판정.

**보완·검증 필요 사항:**

- 국내 naming 사용빈도 통계는 확인하지 않았다.

**초보자가 시작할 질문:**

- camelCase는 컴파일러가 강제하나?
- OrderServiceImpl이 없으면 Spring 주입이 안 되나?

## Cross-boundary naming transformations are executable contract

현재 판정: **부분** / 우선순위: P0

**정의와 실제 역할:** Java camelCase, DB snake_case, JSON/API 계약, Boot kebab-case는 서로 다른 경계 이름이다. MyBatis/Spring Data는 특정 이름을 파싱하거나 mapping에 활용해 실행 동작이 바뀔 수 있다.

**언제 사용하는가:** 외부 DB/API 이름은 계약을 유지하고 내부 Java 이름과 explicit mapping/naming strategy로 연결한다. derived query는 속성 이름 parser 규칙을 따른다.

**대안과 경계:** MyBatis underscore→camel 자동 변환은 기본 꺼짐으로 기술돼 있다. JSON naming strategy는 외부 contract, Boot env spelling은 relaxed binding 규칙이다.

**예시·실행 근거:** created_at 컬럼을 Java createdAt으로 매핑하고 API JSON 표기는 Jackson/계약에 명시한다.

**선수개념:** ORM mapping; JSON schema compatibility; property binding

**관련 표기·별칭:** Java camelCase; DB snake_case; JSON naming; Boot kebab-case/env vars; MyBatis mapper; Spring Data derived query

**판정 이유:** 핵심 설명과 선택 기준은 있으나 실행/학습 과제 근거가 부분적이므로 부분 판정.

**보완·검증 필요 사항:**

- 예제 parser/mapping을 실제 Spring/MyBatis app에서 실행하지 않았다.

**초보자가 시작할 질문:**

- created_at이 createdAt으로 자동 연결되는가?
- JSON 키를 바꾸면 내부 필드명만 바뀐 것인가?
- findByStatus 이름이 실제 SQL에 영향을 주나?
