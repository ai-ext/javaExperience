## Servlet/Tomcat–DispatcherServlet MVC 요청 파이프라인

현재 판정: **부분** / 우선순위: P0

**정의와 실제 역할:** 서블릿 컨테이너는 worker/request/response와 Filter chain을 제공하고 DispatcherServlet은 MVC strategy를 조율한다. HandlerMapping은 handler/interceptor chain을 찾고 HandlerAdapter는 handler를 실행한다.

**언제 사용하는가:** 404/405/415와 예외가 어디서 발생하는지 추적하고 적용 경계에 맞는 필터, 인터셉터, AOP를 고른다.

**대안과 경계:** Filter는 MVC 외 정적/다른 서블릿도 처리 가능; interceptor는 MVC handler 필요; MVC resolver는 MVC 내부 예외만 처리한다.

**예시·실행 근거:** Tomcat→filter→DispatcherServlet→mapping/interceptor→adapter→controller; MVC 예외는 resolver가 HTTP 응답으로 바꾼다.

**선수개념:** Servlet API; MVC handler lifecycle; HTTP request/response

**관련 표기·별칭:** Servlet container; DispatcherServlet; HandlerMapping; HandlerAdapter; HandlerExecutionChain

**판정 이유:** 개념 정의와 선택 기준은 다루지만 실습/실행이나 학습 과제의 검증 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- Flow는 정적이며 Boot code examples는 미실행.

**초보자가 시작할 질문:**

- HandlerMapping과 Adapter 역할 차이?

## Resolver·converter·validation·response·CORS·multipart

현재 판정: **부분** / 우선순위: P0

**정의와 실제 역할:** ArgumentResolver는 컨트롤러 인자를 만들고 HttpMessageConverter는 HTTP body 바이트를 DTO로 읽거나 응답으로 쓴다. 검증은 바인딩 뒤 수행된다. 반환값/예외/CORS/multipart는 별도 처리 경계를 갖는다.

**언제 사용하는가:** 명시적 DTO와 제약 검증, ProblemDetail advice, 제한 origin/method/header, Servlet·앱·proxy 전체 업로드 상한을 설정한다.

**대안과 경계:** 415는 request media/body mismatch, 406은 response negotiation. Argument validation과 method validation은 다른 예외가 가능하다. postHandle 전에 본문이 commit될 수 있고 CORS는 인증이 아니다.

**예시·실행 근거:** @RequestBody DTO→@Valid→controller; ProblemDetail 오류, multipart metadata converter+MultipartFile.

**선수개념:** HTTP media types; Bean Validation; ControllerAdvice

**관련 표기·별칭:** HandlerMethodArgumentResolver; HttpMessageConverter; @RequestBody; @Valid; ProblemDetail; CORS; MultipartResolver

**판정 이유:** 개념 정의와 선택 기준은 다루지만 실습/실행이나 학습 과제의 검증 근거가 부족해 부분 판정.

**보완·검증 필요 사항:**

- 서버 요청 trace와 Spring code는 실행하지 않았다.

**초보자가 시작할 질문:**

- 415와 406의 차이는?
- CORS가 권한 검사를 하나?
- postHandle에서 JSON을 바꿀 수 있나?

## 실제 캡처 관찰

- 첫 화면 요약은 DispatcherServlet이 MVC 구성요소에 위임하고 매핑/인자/converter/검증/예외 단계를 구분한다고 명시한다.
- 모바일에는 요약만 보여 full lifecycle chain과 415/406/Advice 경계의 조작 예는 섹션을 열어야 한다.
- core는 MVC 구성요소 표에서 역할과 경계를 비교하지만 실제 HTTP 요청 trace나 status별 실행 캡처가 아니다.
- core는 현재 전달된 anchor 화면 범위만 판정; 모든 nested details·조작까지 확인했다는 뜻은 아니다.
