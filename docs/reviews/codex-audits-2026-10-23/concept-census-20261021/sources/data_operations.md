## 해석 메모

- `UNIQUE`와 `NOT NULL`은 별도 제약이다. MySQL 8.4에서 nullable unique column은 여러 NULL을 허용하므로 애플리케이션의 “한 계정당 하나” 규칙이 nullable 상태라면 키 모델까지 확인해야 한다.
- “인덱스를 만들었다”는 “optimizer가 이를 쓴다”, “쿼리가 빨라졌다”, “실제 읽은 행이 적다”와 같지 않다. 계획과 실제 지표를 나눠 관찰한다.
- InnoDB 공식 페이지는 일반 index를 B-tree라고 표기하고 leaf pages에 index records가 있다고 설명한다. 입문 화면에서 B-tree/B+tree를 같은 이름처럼 쓰지 말고, 교재 용어와 제품 문서 명칭을 분리한다.
- 모든 example version strings와 release claims를 현재 패키지 metadata/official release source와 재검증하기 전 최신 사실로 일반화하지 않는다.
