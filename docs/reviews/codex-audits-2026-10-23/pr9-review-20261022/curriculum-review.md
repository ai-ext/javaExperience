# PR9 커리큘럼 총체평가 — 교육 문서·검증기 범위

확인 기준: PR9 작업 트리 HEAD `c9786af3b97c48ec118cade5777bc015fe282a88`, 기준 커밋 `1f443faae406324f8c5a3c87b2741ad0b74913a6`, 2026-10-22. 대상은 `course/README.md`, `spec-v2.md`, `roadmap.json`, `talk-cards.md`, `docs/course-redesign/`의 조사·계획, `tools/course/` 검증기다. 결과는 이 파일 범위의 정독에 기반하며, 전체 PR 217개 파일에 대한 판정이나 정답 서버 기능 검수로 확대하지 않는다.

## 판정

**PR9은 커리큘럼 설계·API 계약·일자별 작업 명세와 구조 검사기를 갖춘 계획 산출물로는 탄탄하다. 하지만 현재 상태를 초보자가 그대로 발견하고 끝까지 따라갈 수 있는 완성 학습 과정이라고 부르기는 어렵다.** README는 과정의 목표·15일 일정·도구를 소개하지만, 학습자용 오늘 페이지는 P5에, Java 학습 자료와 실습은 P3에, 결함을 재현하는 티켓은 P4에, 기존 문서와의 접합은 P6에, 최종 학습자 전 과정 검증은 P7에 남아 있다. 계획 문서는 이 상태를 숨기지 않는다. 따라서 P3~P7 미착수를 이번 PR의 숨은 구현 버그로 세지 않는다. 다만 계획이 완료되기 전까지 “완성된 15일 온보딩 교재”로 배포·약속할 수 없다는 것은 제품 준비도의 핵심 판정이다.

커리큘럼의 내용 골격은 업무 판단을 연습시키려는 방향이 분명하다. 예를 들어 D06의 검색과 커서 페이징은 실제 조회 요구와 EXPLAIN 전후를 연결하고, D07은 포인트 원장·조건부 재고 차감·중복 요청을 DB 제약 및 동시성 테스트로 판정한다. D08은 PG 호출을 트랜잭션 밖에 두고 타임아웃 시 `UNKNOWN`과 잔액 불변을 관찰하게 한다. D13~D14는 metadata lock, deadlock, 브라우저 preflight, 캐시 경합, Redis 지연을 증상에서 진단으로 이어 붙인다. 명세서도 공개/USER/ADMIN 권한, 오류 형식, 커서 목록, 멱등 키, 서명 콜백 같은 계약을 구체화한다. 이 예들은 제목 수가 아니라 명세와 `roadmap.json`의 `done` 항목에 적힌 학습자 행동·기대 결과의 근거다.

## 검증기 평가

`tools/course/validate.mjs`는 엔드포인트 표와 카드 ID를 파싱하고, 일수·순서·phase·Java ID 짝·카드 수/참조·단계별 파일 수·`specRefs` 존재·엔드포인트 커버리지·B01~B16 존재·금지 문구를 검사한다(`validate.mjs:8-99`). README 일정표와 roadmap 일치도 테스트로 고정했다(`validate.test.mjs:179-187`). 이는 P1의 연결 오류를 조기에 잡는 데 유용한 구조 검사다.

다만 통과 메시지의 `30 endpoints, 15 days, 68 cards`는 형식·참조 개수의 통과이지 교육적 완결성이나 실행 성공을 의미하지 않는다. 검증기는 Java 항목과 실제 학습 테스트의 존재·내용, prerequisites, 일별 예상 소요, `done`이 요구하는 결과의 재현성, 명세의 필드/상태 코드와 카드 답안의 의미 정합, 티켓의 실행 환경/증상 재현, HTML에 노출된 학습 경로를 검사하지 않는다. `specRefs`는 경로 문자열 존재를 검사하고 한 엔드포인트가 관련 학습을 제공하는지 또는 테스트 기대값이 계약과 맞는지 검증하지 않는다. `tickets`는 식별자 B01~B16의 등장만 보장한다. 따라서 이 검증기는 “교육과정 검증기”라기보다 “커리큘럼 산출물 간 기본 참조 무결성 검사기”로 설명하는 것이 정확하다. 이 한계는 P7의 사람이 직접 전 과정 정독·실행·브라우저 확인을 대체하지 않는다.

## 우선 조치

1. **배포 상태와 약속을 일치시킨다.** P1 설계 산출물과 P2 일부 정답 서버가 존재하는 상태를 전면에 표시하고, Java 초보까지 포함한 완성 15일 과정이라는 약속은 P3~P7 및 P7 학습자 실행 확인이 끝날 때까지 확정 표현으로 사용하지 않는다. 이는 새 기능 범위를 늘리는 제안이 아니라 현재 상태의 오해를 막는 조치다.
2. **초보 진입 경로를 P5의 필수 완료 조건으로 만든다.** 첫 화면에서 준비물 사전 확인 → D0 선택 기준/필수 선행 지식 → D01 실행 → 예상 결과/실패 시 복구 → 다음 개념·실습 링크로 이동하게 하고, JSON roadmap을 찾아가라고 전제하지 않는다. 증상 기반 진입은 보조 경로로 두되, D01부터 시작하는 기본 경로도 제공한다.
3. **Java 준비도에 따라 두 경로를 정의한다.** J00의 “반나절~1일”을 근거 없이 초보에게 충분하다고 가정하지 않는다. J00 학습 테스트의 통과 기준과 D01 필수 사전 점검을 만들고, 실패자는 선행 학습으로 보내며, 통과자는 선택 심화/압축 경로를 제공한다. P3가 구현되기 전에는 현재 자료만으로 Java 초보 수용 가능하다고 판정하지 않는다.
4. **15일을 관찰 가능한 학습량으로 재산정한다.** 적어도 Java 입문자와 Java 경험자를 나눠 대표 일자(D01, D06, D08, D14)를 실제 처음 수행하는 학습자에게 따라가게 하고, 준비·구현·실패 분석·카드 답변 시간을 기록한다. 이 결과로 하루 범위와 15일 약속을 조정한다. 계획 파일의 “15일” 숫자 자체로 현실성을 입증하지 않는다.
5. **상위 DB 주제는 문제-데이터-기대값-실행 관측으로 완성한다.** 이미 있는 커서·EXPLAIN·경합·장애 시나리오를 재사용하고, 추가할 경우 윈도 함수/CTE 또는 분포·쓰기비용 판단처럼 별도 업무 질문이 있는 주제를 선택한다. 기존 감사의 미구현 확장 목록을 이미 제공되는 기능처럼 세지 않는다.
6. **검증기의 주장 범위를 이름과 보고에 반영한다.** 현재 구조검사를 유지하되, 후속 교재가 생기면 prerequisite/링크/페이지 존재 및 ID 연결을 검사하고, 대표 `done` 항목은 실제 서버 요청·DB 조회·테스트 결과와 맞추는 자동/수동 증거를 둔다. 검증기 통과만으로 시나리오가 실행 가능하다고 쓰지 않는다.

## 근거 사용 범위와 한계

기존 시나리오 감사 자료 `$USER_HOME/research/javaexperience-scenario-census-20261022/README.md`, `DEPTH-MAP.md`, `EXPANSION-INDEX.md`는 PR9의 새 교육 설계와 구별해 비교 배경으로만 사용했다. 해당 감사는 기존 main 기반 시나리오의 실행·누락을 조사한 별도 산출물이다. 그 안의 기존 과제나 X01~X20 개발 명세는 이번 PR9에서 구현·제공된 학습 경로로 계산하지 않았다. 특히 DEPTH-MAP은 고급 주제의 보강 방향을 구체화하지만, PR9 roadmap의 해당 단계가 실행되었다는 증거가 아니다.

이번 평가는 교육 범위 자료의 문서 검토다. 보고서 작성 시 새 테스트·빌드·브라우저 검증을 실행하지 않았고, PR 전체 217개 파일 중 교육 문서·검증기 외 범위의 변경, 실제 초보 학습자 수행 시간, P2 서버의 모든 기능과 `done` 항목의 실동작은 판정하지 않는다. 완료 판단은 P7에 명시된 전체 실행·화면 확인과 실제 학습자 관찰 뒤 갱신해야 한다.
