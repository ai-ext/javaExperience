#7-3. 통합 테스트 — Testcontainers

#상황

슬라이스·단위 테스트는 빠르지만 "진짜로 붙였을 때"는 확인하지 못한다. 엔티티 매핑, 실제 SQL, 트랜잭션, 인증 부품이 함께 돌 때만 보이는 문제가 있다. 마지막으로 진짜 MySQL(Testcontainers) 위에서 사용자 흐름 하나를 처음부터 끝까지 돌린다.

#화면 시나리오

사용자가 화면에서 무엇을 하면 어떤 요청이 서버로 가고, 서버·DB에서 무슨 일이 일어나 어떤 응답이 돌아와 화면이 어떻게 바뀌는지다. 흐름을 펼치면 사용자 행동부터 응답까지 차례대로 볼 수 있다.

통합 테스트 — 사용자 흐름 한 바퀴

진짜 MySQL(Testcontainers) 위에서 글쓰기 → 조회 → 좋아요 → 댓글 → 삭제를 처음부터 끝까지 돌린다.

#만들 것

테스트 클래스 PostFlowIntegrationTest (이름 그대로) — @SpringBootTest + @AutoConfigureMockMvc

흐름(한 테스트 메서드 또는 단계별 메서드):

  1. 김자바(tok-kimjava)가 dev 게시판에 글을 쓴다 → 201
  2. 비로그인으로 그 글 상세 → 200
  3. 이스프링(tok-lee)이 좋아요 → likeCount 1
  4. 이스프링이 댓글 → 201
  5. 상세에서 likeCount=1, commentCount=1
  6. 김자바가 글을 지운다 → 204
  7. 상세 → 404, 이스프링이 다시 좋아요 → 404

추가로 하나 더: 시드 데이터 규칙 확인 — 비로그인으로 GET /api/boards/free/posts?size=20의 id 순서가 21~12, 9, 5, 4인지(2-3).

  • 테스트 프로파일은 이미 Testcontainers MySQL에 시나리오 dump를 넣는다(application-test.yml). 따로 설정할 것은 없다.
  • 테스트끼리 순서에 기대지 않는다. 각 테스트가 자기 데이터를 만들어 쓴다.

#구현 가이드

GET /api/boards/free/posts?size=20 계약을 기준으로 아래 순서대로 구현한다. 먼저 직접 작성하고, 막힌 역할만 펼쳐 아래의 전체 구현 코드와 비교한다.

테스트 / 계약 검증

PostFlowIntegrationTest.java는 @SpringBootTest와 실제 MySQL Testcontainers를 사용한다. 서비스와 리포지토리를 mock으로 바꾸지 않고, 같은 테스트에서 만든 글 ID를 다음 요청에 이어 쓴다. @Transactional을 테스트 클래스에 붙이지 않아 요청별 커밋 뒤의 결과도 확인한다.

@SpringBootTest
@AutoConfigureMockMvc
class PostFlowIntegrationTest {
    @Autowired MockMvc mockMvc;

    @Test
    void 글쓰기_조회_좋아요_댓글_삭제까지_한_흐름() throws Exception {
        String created = mockMvc.perform(post("/api/posts")
                .header("Authorization", "Bearer tok-kimjava")
                .contentType(MediaType.APPLICATION_JSON)
                .content("{\"boardSlug\":\"dev\",\"title\":\"[통합] 흐름 확인\",\"content\":\"본문\",\"tags\":[],\"visibility\":\"PUBLIC\"}"))
                .andExpect(status().isCreated())
                .andReturn().getResponse().getContentAsString();
        Integer postId = JsonPath.read(created, "$.id");
        // postId로 상세 → 좋아요 → 댓글 → 다시 상세 → 삭제 → 404를 검증한다.
    }
}

각 요청·응답 단언의 실행 가능한 전문은 아래 테스트 코드 접기에서 확인한다. 두 번째 테스트는 비로그인 자유 게시판 목록의 시드 ID와 totalElements를 확인한다.

테스트 — src/test/java/org/example/post/PostFlowIntegrationTest.java
package org.example.post;


import com.jayway.jsonpath.JsonPath;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.boot.webmvc.test.autoconfigure.AutoConfigureMockMvc;
import org.springframework.http.MediaType;
import org.springframework.test.web.servlet.MockMvc;


import java.util.List;


import static org.assertj.core.api.Assertions.assertThat;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.delete;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.post;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.put;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;


// 7-3: 진짜 MySQL(Testcontainers, application-test.yml이 시나리오 dump를 넣는다) 위에서 사용자 흐름을 끝까지 돌린다.
// 서비스·리포지토리를 mock으로 바꾸지 않는다.
//
// @Transactional을 붙이지 않는다 — 붙이면 테스트가 끝날 때 롤백돼 깔끔하지만, 요청마다 커밋되는 실제
// 동작(원자적 UPDATE, 커밋 뒤 다른 트랜잭션에서 보이는 값)이 가려진다. 대신 테스트마다 자기 글을 새로 만들어 쓴다.
// 애노테이션 조합(@SpringBootTest + @AutoConfigureMockMvc)을 다른 통합 테스트와 같게 둬 컨텍스트·컨테이너를 공유한다.
@SpringBootTest
@AutoConfigureMockMvc
class PostFlowIntegrationTest {


private static final String KIMJAVA = &quot;Bearer tok-kimjava&quot;;
private static final String LEE = &quot;Bearer tok-lee&quot;;

@Autowired
MockMvc mockMvc;

@Test
void 글쓰기_조회_좋아요_댓글_삭제까지_한_흐름() throws Exception {
    // 1. 김자바가 dev 게시판에 글을 쓴다
    String created = mockMvc.perform(post(&quot;/api/posts&quot;)
                    .header(&quot;Authorization&quot;, KIMJAVA)
                    .contentType(MediaType.APPLICATION_JSON)
                    .content(&quot;&quot;&quot;
                            {&quot;boardSlug&quot;:&quot;dev&quot;,&quot;title&quot;:&quot;[통합] 흐름 확인&quot;,&quot;content&quot;:&quot;통합 테스트 본문&quot;,&quot;tags&quot;:[&quot;spring&quot;],&quot;visibility&quot;:&quot;PUBLIC&quot;}
                            &quot;&quot;&quot;))
            .andExpect(status().isCreated())
            .andReturn().getResponse().getContentAsString();
    Integer postId = JsonPath.read(created, &quot;$.id&quot;);

    // 2. 비로그인 상세
    mockMvc.perform(get(&quot;/api/posts/{id}&quot;, postId))
            .andExpect(status().isOk())
            .andExpect(jsonPath(&quot;$.author.id&quot;).value(2));

    // 3. 이스프링이 좋아요
    mockMvc.perform(put(&quot;/api/posts/{id}/like&quot;, postId).header(&quot;Authorization&quot;, LEE))
            .andExpect(status().isOk())
            .andExpect(jsonPath(&quot;$.liked&quot;).value(true))
            .andExpect(jsonPath(&quot;$.likeCount&quot;).value(1));

    // 4. 이스프링이 댓글
    mockMvc.perform(post(&quot;/api/posts/{id}/comments&quot;, postId)
                    .header(&quot;Authorization&quot;, LEE)
                    .contentType(MediaType.APPLICATION_JSON)
                    .content(&quot;&quot;&quot;
                            {&quot;content&quot;:&quot;[통합] 댓글&quot;}
                            &quot;&quot;&quot;))
            .andExpect(status().isCreated())
            .andExpect(jsonPath(&quot;$.postId&quot;).value(postId));

    // 5. 상세에서 숫자 확인(커밋된 값을 다시 읽는다)
    mockMvc.perform(get(&quot;/api/posts/{id}&quot;, postId))
            .andExpect(status().isOk())
            .andExpect(jsonPath(&quot;$.likeCount&quot;).value(1))
            .andExpect(jsonPath(&quot;$.commentCount&quot;).value(1));

    // 6. 김자바가 글을 지운다
    mockMvc.perform(delete(&quot;/api/posts/{id}&quot;, postId).header(&quot;Authorization&quot;, KIMJAVA))
            .andExpect(status().isNoContent());

    // 7. 지운 글은 상세 404, 좋아요도 404
    mockMvc.perform(get(&quot;/api/posts/{id}&quot;, postId))
            .andExpect(status().isNotFound());
    mockMvc.perform(put(&quot;/api/posts/{id}/like&quot;, postId).header(&quot;Authorization&quot;, LEE))
            .andExpect(status().isNotFound());
}

// 시드 데이터 규칙(2-3) — 비로그인이면 PUBLISHED·PUBLIC·미삭제만, 최신순
@Test
void 비로그인_자유게시판_목록은_시드_규칙대로다() throws Exception {
    String body = mockMvc.perform(get(&quot;/api/boards/free/posts&quot;).param(&quot;size&quot;, &quot;20&quot;))
            .andExpect(status().isOk())
            .andReturn().getResponse().getContentAsString();

    List&lt;Integer&gt; ids = JsonPath.read(body, &quot;$.items[*].id&quot;);
    assertThat(ids).containsExactly(21, 20, 19, 18, 17, 16, 15, 14, 13, 12, 9, 5, 4);
    Integer total = JsonPath.read(body, &quot;$.totalElements&quot;);
    assertThat(total).isEqualTo(13);
}


}

#채점 기준

T = 테스트 실행(필수), R = 코드 리뷰(피드백용).

# 확인 방법 기대
T1 ./gradlew test --tests org.example.post.PostFlowIntegrationTest 통과
T2 ./gradlew test 전체 통과(2-4·4-2·7-1·7-2 테스트 포함)
R1 흐름 위 1~7과 시드 데이터 확인이 모두 있다. 앞 단계 응답의 id를 다음 단계에 이어 쓴다
R2 진짜로 붙였나 서비스·리포지토리를 mock으로 바꾸지 않았다. 실제 MySQL에서 돈다
R3 트랜잭션 함정 테스트 클래스에 @Transactional을 붙였다면, 그것 때문에 커밋 후에만 생기는 문제(동시성·커밋 뒤 동작)가 가려진다는 것을 알고 선택했다
R4 독립성 다른 테스트가 만든 데이터에 기대지 않는다. 같은 테스트를 두 번 돌려도 통과한다
R5 속도 컨텍스트가 테스트 클래스마다 새로 뜨지 않게 설정을 맞췄다(@MockitoBean 남발·서로 다른 프로퍼티 조합은 컨텍스트 캐시를 깨뜨린다)
