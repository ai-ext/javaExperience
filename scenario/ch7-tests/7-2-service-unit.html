업무 규칙은 서비스에 모여 있다. "내 글엔 좋아요 금지", "이미 좋아요면 아무것도 안 함", "볼 수 없는 글은 404" 같은 것들이다. 이 규칙들을 Spring도 DB도 없이 순수 자바 단위 테스트로 빠르게 고정한다.

이때 협력 객체를 다루는 두 방법을 구분해 쓴다.

  • mock: 전부 가짜. 리포지토리처럼 "이번 테스트에서 이런 값을 돌려줘"만 정한다.
  • spy: 실물을 감싼다. 진짜 로직은 그대로 돌리면서 "몇 번, 무엇으로 불렸나"를 확인한다.
02◇무엇을 만들까만들 것테스트 클래스 LikeServiceTest (이름 그대로) — 4장의 좋아요 서비스를 대상으로열기 ↓

테스트 클래스 LikeServiceTest (이름 그대로) — 4장의 좋아요 서비스를 대상으로

# 시나리오 확인
1 내 글에 좋아요 정해 둔 예외가 난다. 저장·숫자 증가가 호출되지 않았다
2 아직 안 누른 글에 좋아요 insertIgnore가 1행을 반환하고 숫자 증가 1번. 전달한 글·회원 ID를 ArgumentCaptor로 꺼내 확인
3 이미 누른 글에 또 좋아요 INSERT IGNORE는 0행을 반환하고 좋아요 숫자 증가는 없다(멱등)
4 안 누른 글에 취소 DELETE는 0행을 반환하고 좋아요 숫자 감소는 없다
5 볼 수 없는 글 "볼 수 있나" 규칙(2-3의 규칙 클래스 등)을 spy로 감싸 실제 판정을 쓰게 하고, 한 번 호출됐는지와 결과(404 예외)를 확인한다

4-2에서 INSERT IGNORE로 바꿨으므로 PostLike 엔티티 저장은 없다. 2번에서는 insert 메서드에 넘어간 글·회원 ID를 캡처하고, 3번에서는 insert가 0행을 돌려주면 숫자 증가가 없다는 것을 확인한다.

  • @ExtendWith(MockitoExtension.class) — Spring 컨텍스트를 띄우지 않는다.
  • 리포지토리는 @Mock, 테스트 대상 서비스는 생성자로 직접 만들거나 @InjectMocks.
  • 시간이 필요하면 Clock.fixed(...)를 넣는다.
03⌘어떻게 만들까구현 가이드화면 시나리오의 서버·DB 흐름을 이 단계에서 바뀐 파일에 연결한다. 먼저 만들 것 의 계약대로 직접 작성하고, 필요한 역할만 펼쳐 파일 전문과 비교한다.2개 코드 · 열기 ↓

화면 시나리오의 서버·DB 흐름을 이 단계에서 바뀐 파일에 연결한다. 먼저 만들 것의 계약대로 직접 작성하고, 필요한 역할만 펼쳐 파일 전문과 비교한다.

이 단계의 처리 흐름:

  • 테스트에서는 HTTP 없이 likeService.like(12, me)를 직접 부른다. postRepository는 @Mock — '12번 글의 작성자는 me'를 돌려주게 정한다
  • 예외가 났는지 + verify(postLikeRepository, never()).insertIgnore(anyLong(), anyLong()) — INSERT 시도도 없었는지 본다
  • PostAccessPolicy를 spy로 감싸 진짜 규칙대로 판정하게 하고, verify(policy).canView(...)로 한 번 불렸는지 확인한다
테스트 — 계약 확인

LikeServiceTest.java에서 Spring 컨텍스트 없이 Mockito가 리포지토리를 만들고, 서비스는 생성자로 직접 만든다. @Spy를 모든 테스트에 넣지 않는다. 다섯 번째 테스트에서만 실제 PostAccessPolicy를 spy(...)로 감싼다.

@ExtendWith(MockitoExtension.class)
class LikeServiceTest {
    @Mock PostRepository postRepository;
    @Mock PostLikeRepository postLikeRepository;
    @Mock PostAccessPolicy accessPolicy;
    @Mock PlatformTransactionManager transactionManager;

    LikeService likeService;

    @BeforeEach
    void setUp() {
        likeService = new LikeService(postRepository, postLikeRepository,
                accessPolicy, transactionManager);
    }
}

4-2의 실제 저장은 INSERT IGNORE다. 성공 시 넘어간 두 ID와 숫자 증가를 확인하고, 이미 있으면 0행·숫자 증가 없음으로 검증한다.

given(postLikeRepository.insertIgnore(POST_ID, KIMJAVA.id())).willReturn(1);
LikeResponse response = likeService.like(POST_ID, KIMJAVA);
ArgumentCaptor<Long> postId = ArgumentCaptor.forClass(Long.class);
ArgumentCaptor<Long> memberId = ArgumentCaptor.forClass(Long.class);
verify(postLikeRepository).insertIgnore(postId.capture(), memberId.capture());
assertThat(postId.getValue()).isEqualTo(POST_ID);
assertThat(memberId.getValue()).isEqualTo(KIMJAVA.id());
verify(postRepository).incrementLikeCount(POST_ID);

이 코드는 각 테스트의 사전 설정을 생략한 핵심 부분이다. 예외·멱등·취소·spy 설정까지 실행 가능한 전문은 아래 테스트 코드 접기에서 확인한다.

package org.example.like;

import org.example.auth.AuthenticatedMember;
import org.example.member.Member;
import org.example.post.Post;
import org.example.post.PostAccessPolicy;
import org.example.post.PostNotFoundException;
import org.example.post.PostRepository;
import org.example.social.BlockPolicy;
import org.example.social.FollowRepository;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.extension.ExtendWith;
import org.mockito.ArgumentCaptor;
import org.mockito.Mock;
import org.mockito.junit.jupiter.MockitoExtension;
import org.springframework.transaction.PlatformTransactionManager;

import java.util.Optional;

import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.assertThatThrownBy;
import static org.mockito.ArgumentMatchers.anyLong;
import static org.mockito.BDDMockito.given;
import static org.mockito.Mockito.mock;
import static org.mockito.Mockito.never;
import static org.mockito.Mockito.spy;

// 7-2: 좋아요 규칙을 Spring·DB 없이 순수 단위 테스트로 고정한다(MockitoExtension — strict stubs).
// 리포지토리·"볼 수 있나" 정책은 mock, 5번만 정책을 spy로 감싸 실제 판정을 돌린다.
//
// 참고(설계 피드백): 4-2에서 좋아요 저장을 save(PostLike)가 아니라 INSERT IGNORE(insertIgnore)로 바꿨기
// 때문에 "저장된 PostLike"라는 객체가 없다 — 2번은 insertIgnore에 넘어간 (글 id, 회원 id)를 캡처하고,
// 3번 "저장 없음"은 "insert 시도는 하되 0행이라 숫자를 올리지 않음"으로 확인한다.
// TransactionTemplate은 mock PlatformTransactionManager로 돌린다(getTransaction/commit이 아무것도 안 함).
@ExtendWith(MockitoExtension.class)
class LikeServiceTest {

    private static final Long POST_ID = 3L;
    private static final AuthenticatedMember KIMJAVA = new AuthenticatedMember(2L, "김자바", "USER");

    @Mock
    PostRepository postRepository;

    @Mock
    PostLikeRepository postLikeRepository;

    @Mock
    PostAccessPolicy accessPolicy;

    @Mock
    PlatformTransactionManager transactionManager;

    LikeService likeService;

    @BeforeEach
    void setUp() {
        likeService = new LikeService(postRepository, postLikeRepository, accessPolicy, transactionManager);
    }

    @Test
    void 내_글에_좋아요하면_예외이고_저장도_증가도_하지_않는다() {
        Post myPost = publishedPostBy(KIMJAVA.id());
        given(postRepository.findById(POST_ID)).willReturn(Optional.of(myPost));
        given(accessPolicy.canView(KIMJAVA, myPost)).willReturn(true);

        assertThatThrownBy(() -> likeService.like(POST_ID, KIMJAVA))
                .isInstanceOf(SelfLikeNotAllowedException.class);

        verify(postLikeRepository, never()).insertIgnore(anyLong(), anyLong());
        verify(postRepository, never()).incrementLikeCount(anyLong());
    }

    @Test
    void 안_누른_글에_좋아요하면_한_번_저장하고_숫자를_한_번_올린다() {
        Post post = publishedPostBy(4L);
        given(postRepository.findById(POST_ID)).willReturn(Optional.of(post));
        given(accessPolicy.canView(KIMJAVA, post)).willReturn(true);
        given(postLikeRepository.insertIgnore(POST_ID, KIMJAVA.id())).willReturn(1);
        given(postRepository.findLikeCountById(POST_ID)).willReturn(1);

        LikeResponse response = likeService.like(POST_ID, KIMJAVA);

        ArgumentCaptor<Long> postId = ArgumentCaptor.forClass(Long.class);
        ArgumentCaptor<Long> memberId = ArgumentCaptor.forClass(Long.class);
        verify(postLikeRepository, times(1)).insertIgnore(postId.capture(), memberId.capture());
        assertThat(postId.getValue()).isEqualTo(POST_ID);
        assertThat(memberId.getValue()).isEqualTo(KIMJAVA.id());
        verify(postRepository, times(1)).incrementLikeCount(POST_ID);
        assertThat(response).isEqualTo(new LikeResponse(POST_ID, true, 1));
    }

    @Test
    void 이미_누른_글에_또_좋아요하면_숫자를_올리지_않는다() {
        Post post = publishedPostBy(4L);
        given(postRepository.findById(POST_ID)).willReturn(Optional.of(post));
        given(accessPolicy.canView(KIMJAVA, post)).willReturn(true);
        given(postLikeRepository.insertIgnore(POST_ID, KIMJAVA.id())).willReturn(0); // UNIQUE 때문에 0행
        given(postRepository.findLikeCountById(POST_ID)).willReturn(1);

        LikeResponse response = likeService.like(POST_ID, KIMJAVA);

        verify(postRepository, never()).incrementLikeCount(anyLong());
        assertThat(response).isEqualTo(new LikeResponse(POST_ID, true, 1));
    }

    @Test
    void 안_누른_글에_취소하면_숫자를_내리지_않는다() {
        Post post = mock(Post.class);
        given(post.getStatus()).willReturn("PUBLISHED");
        given(postRepository.findById(POST_ID)).willReturn(Optional.of(post));
        given(accessPolicy.canView(KIMJAVA, post)).willReturn(true);
        given(postLikeRepository.deleteByPost_IdAndMember_Id(POST_ID, KIMJAVA.id())).willReturn(0L);
        given(postRepository.findLikeCountById(POST_ID)).willReturn(0);

        LikeResponse response = likeService.unlike(POST_ID, KIMJAVA);

        verify(postRepository, never()).decrementLikeCount(anyLong());
        assertThat(response).isEqualTo(new LikeResponse(POST_ID, false, 0));
    }

    // spy를 쓰는 이유: "볼 수 있나"는 결과를 지어내지(mock) 않고 2-3의 실제 규칙으로 판정하게 하면서,
    // 서비스가 그 규칙을 정말 한 번 물어봤는지도 확인하고 싶어서다.
    @Test
    void 볼_수_없는_글이면_실제_규칙으로_판정해_404이고_저장하지_않는다() {
        PostAccessPolicy realPolicy = spy(new PostAccessPolicy(mock(FollowRepository.class), mock(BlockPolicy.class)));
        LikeService service = new LikeService(postRepository, postLikeRepository, realPolicy, transactionManager);

        Post othersDraft = mock(Post.class); // 남(99번)의 임시저장 글 — 작성자만 볼 수 있다
        Member author = mock(Member.class);
        given(author.getId()).willReturn(99L);
        given(othersDraft.getAuthor()).willReturn(author);
        given(othersDraft.getStatus()).willReturn("DRAFT");
        given(postRepository.findById(POST_ID)).willReturn(Optional.of(othersDraft));

        assertThatThrownBy(() -> service.like(POST_ID, KIMJAVA))
                .isInstanceOf(PostNotFoundException.class);

        verify(realPolicy, times(1)).canView(KIMJAVA, othersDraft);
        verify(postLikeRepository, never()).insertIgnore(anyLong(), anyLong());
    }

    private Post publishedPostBy(Long authorId) {
        Member author = mock(Member.class);
        given(author.getId()).willReturn(authorId);
        Post post = mock(Post.class);
        given(post.getAuthor()).willReturn(author);
        given(post.getStatus()).willReturn("PUBLISHED");
        return post;
    }
}

힌트 — spy 만들기

PostAccessPolicy policy = spy(new PostAccessPolicy(followRepository, blockPolicy));처럼 실물을 만든 뒤 감싼다(그 안의 협력 객체는 mock). 그러면 policy.canView(...)는 진짜 규칙대로 판정하고, 테스트 끝에 verify(policy).canView(viewer, post)로 호출을 확인할 수 있다.

spy의 메서드를 바꾸고 싶으면 doReturn(...).when(policy).canView(...) 형태를 쓴다(when(policy.canView(...))는 진짜 메서드를 한 번 실행한다).
