#7-1. 컨트롤러 슬라이스 테스트

#화면 시나리오

사용자가 화면에서 무엇을 하면 어떤 요청이 서버로 가고, 서버·DB에서 무슨 일이 일어나 어떤 응답이 돌아와 화면이 어떻게 바뀌는지다. 흐름을 펼치면 사용자 행동부터 응답까지 차례대로 볼 수 있다.

이 단계의 작업 위치

Controller 테스트가 기존 HTTP 요청·응답 계약을 확인하는 단계입니다.

전체 API 구조도 보기

#상황

지금까지 확인은 서버를 띄우고 curl을 보내는 식이었다. 코드를 고칠 때마다 사람이 다시 해야 한다. 이제 자동으로 도는 테스트로 계약을 고정한다.

첫 번째는 컨트롤러만 시험하는 테스트다. DB도 서비스도 띄우지 않고(가짜로 바꾸고), "이 요청이 오면 이 상태 코드·헤더·JSON이 나간다"는 HTTP 계약만 빠르게 확인한다.

#만들 것

테스트 클래스 PostControllerTest (이름 그대로) — @WebMvcTest(PostController.class)

# 시나리오 단언
1 올바른 토큰 + 올바른 본문으로 POST /api/posts 201, Location 헤더, $.author.id
2 빈 제목으로 POST /api/posts 400, Content-Type: application/problem+json, errors에 title
3 토큰 없이 POST /api/posts 401
4 서비스가 "글 없음" 예외를 던질 때 GET /api/posts/{id} 404
  • 서비스는 @MockitoBean으로 가짜로 바꾸고, 각 테스트에서 돌려줄 값을 정한다(given(...).willReturn(...)).
  • 1-6의 토큰 확인 부품(인터셉터·ArgumentResolver 등)이 리포지토리를 쓴다면 그 리포지토리도 @MockitoBean으로 바꾸고 "토큰 → 회원"을 정해 준다.
  • 그 부품이 Clock 같은 설정 빈(@Configuration)을 주입받는다면 @WebMvcTest는 일반 @Configuration을 읽지 않으므로 @Import(ClockConfig.class)처럼 직접 가져온다.
  • 서비스가 엔티티를 돌려주고 컨트롤러가 DTO로 바꾸는 구조(1-3)라면, 테스트에서 id·게시판이 채워진 엔티티를 mock으로 꾸며야 한다. 서비스가 응답 DTO(또는 결과 객체)를 돌려주면 슬라이스 테스트가 훨씬 쉬워진다 — 구조를 고를 때의 트레이드오프다.
  • DB 없이 돌아야 한다. 이 테스트만 돌리면 Testcontainers MySQL이 뜨지 않는다.

#구현 가이드

화면 시나리오의 서버·DB 흐름을 이 단계에서 바뀐 파일에 연결한다. 먼저 만들 것의 계약대로 직접 작성하고, 필요한 역할만 펼쳐 파일 전문과 비교한다.

이 단계의 처리 흐름:

  • @WebMvcTest: 컨트롤러·검증·Advice는 진짜, PostService는 @MockitoBean 가짜 — given(postService.create(...)).willReturn(응답)
  • 검증에서 막혀 서비스가 불리지 않는다 — then(postService).shouldHaveNoInteractions()로 확인
테스트 — 계약 확인

PostControllerTest.java는 실제 PostController와 MVC 검증·예외 처리·인증 부품을 띄운다. 서비스와 토큰 저장소만 mock으로 바꾼다.

@WebMvcTest(PostController.class)
@Import(ClockConfig.class)
class PostControllerTest {
    @Autowired MockMvc mockMvc;
    @MockitoBean PostService postService;
    @MockitoBean PostQueryService postQueryService;
    @MockitoBean ApiTokenRepository apiTokenRepository;
}

201은 Location과 작성자 ID까지, 400은 Problem JSON의 title 오류와 서비스 무호출까지 확인한다. 토큰이 없으면 401과 WWW-Authenticate를 확인하고, 조회 서비스가 PostNotFoundException을 던지면 404를 확인한다.

mockMvc.perform(post("/api/posts")
        .header("Authorization", "Bearer tok-kimjava")
        .contentType(MediaType.APPLICATION_JSON).content(VALID_BODY))
        .andExpect(status().isCreated())
        .andExpect(header().string("Location", endsWith("/api/posts/22")))
        .andExpect(jsonPath("$.author.id").value(2));

mockMvc.perform(post("/api/posts")
        .header("Authorization", "Bearer tok-kimjava")
        .contentType(MediaType.APPLICATION_JSON)
        .content("{\"boardSlug\":\"dev\",\"title\":\"\",\"content\":\"본문\",\"tags\":[],\"visibility\":\"PUBLIC\"}"))
        .andExpect(status().isBadRequest())
        .andExpect(content().contentTypeCompatibleWith(MediaType.APPLICATION_PROBLEM_JSON))
        .andExpect(jsonPath("$.errors[*].field", hasItem("title")));
then(postService).shouldHaveNoInteractions();

VALID_BODY와 givenToken 준비 코드를 포함한 실행 가능한 전문은 아래 테스트 코드 접기에서 확인한다.

// 7-1: 컨트롤러만 띄워 HTTP 계약(상태 코드·헤더·JSON)을 고정한다. DB·서비스는 띄우지 않는다.
// 실물: PostController, ApiExceptionHandler(Advice), Bean Validation, AuthInterceptor·LoginMemberArgumentResolver
// 가짜: 컨트롤러가 쓰는 서비스 두 개 + 인터셉터가 쓰는 ApiTokenRepository("토큰 → 회원"을 정해 준다)
// Clock은 리포지토리가 아니라 설정 빈이라 실물(ClockConfig)을 가져온다 — @WebMvcTest는 일반 @Configuration을 읽지 않는다.
@WebMvcTest(PostController.class)
@Import(ClockConfig.class)
class PostControllerTest {


private static final String VALID_BODY = &quot;&quot;&quot;
        {&quot;boardSlug&quot;:&quot;dev&quot;,&quot;title&quot;:&quot;[테스트] 제목&quot;,&quot;content&quot;:&quot;본문&quot;,&quot;tags&quot;:[],&quot;visibility&quot;:&quot;PUBLIC&quot;}
        &quot;&quot;&quot;;

@Autowired
MockMvc mockMvc;

@MockitoBean
PostService postService;

@MockitoBean
PostQueryService postQueryService;

@MockitoBean
ApiTokenRepository apiTokenRepository;

@Test
void 올바른_토큰과_본문이면_201과_Location과_작성자를_돌려준다() throws Exception {
    Member kimjava = givenToken(&quot;tok-kimjava&quot;, 2L, &quot;김자바&quot;);
    Post created = fakePost(22L, kimjava);
    given(postService.create(eq(2L), any(PostCreateRequest.class))).willReturn(created);

    mockMvc.perform(post(&quot;/api/posts&quot;)
                    .header(&quot;Authorization&quot;, &quot;Bearer tok-kimjava&quot;)
                    .contentType(MediaType.APPLICATION_JSON)
                    .content(VALID_BODY))
            .andExpect(status().isCreated())
            .andExpect(header().string(&quot;Location&quot;, endsWith(&quot;/api/posts/22&quot;)))
            .andExpect(jsonPath(&quot;$.id&quot;).value(22))
            .andExpect(jsonPath(&quot;$.author.id&quot;).value(2))
            .andExpect(jsonPath(&quot;$.author.nickname&quot;).value(&quot;김자바&quot;));
}

@Test
void 빈_제목이면_400_problem_json에_title_오류가_있고_서비스를_부르지_않는다() throws Exception {
    givenToken(&quot;tok-kimjava&quot;, 2L, &quot;김자바&quot;);

    mockMvc.perform(post(&quot;/api/posts&quot;)
                    .header(&quot;Authorization&quot;, &quot;Bearer tok-kimjava&quot;)
                    .contentType(MediaType.APPLICATION_JSON)
                    .content(&quot;&quot;&quot;
                            {&quot;boardSlug&quot;:&quot;dev&quot;,&quot;title&quot;:&quot;&quot;,&quot;content&quot;:&quot;본문&quot;,&quot;tags&quot;:[],&quot;visibility&quot;:&quot;PUBLIC&quot;}
                            &quot;&quot;&quot;))
            .andExpect(status().isBadRequest())
            .andExpect(content().contentTypeCompatibleWith(MediaType.APPLICATION_PROBLEM_JSON))
            .andExpect(jsonPath(&quot;$.status&quot;).value(400))
            .andExpect(jsonPath(&quot;$.errors[*].field&quot;, hasItem(&quot;title&quot;)));

    then(postService).shouldHaveNoInteractions();
}

@Test
void 토큰이_없으면_401이고_서비스도_토큰_조회도_하지_않는다() throws Exception {
    mockMvc.perform(post(&quot;/api/posts&quot;)
                    .contentType(MediaType.APPLICATION_JSON)
                    .content(VALID_BODY))
            .andExpect(status().isUnauthorized())
            .andExpect(header().string(&quot;WWW-Authenticate&quot;, &quot;Bearer&quot;))
            .andExpect(content().contentTypeCompatibleWith(MediaType.APPLICATION_PROBLEM_JSON));

    then(postService).shouldHaveNoInteractions();
    then(apiTokenRepository).shouldHaveNoInteractions();
}

@Test
void 서비스가_글_없음_예외를_던지면_404_problem_json이다() throws Exception {
    given(postQueryService.getDetail(eq(999L), any())).willThrow(new PostNotFoundException());

    mockMvc.perform(get(&quot;/api/posts/999&quot;))
            .andExpect(status().isNotFound())
            .andExpect(content().contentTypeCompatibleWith(MediaType.APPLICATION_PROBLEM_JSON))
            .andExpect(jsonPath(&quot;$.status&quot;).value(404));
}

// 인터셉터가 쓰는 &quot;토큰 → 회원&quot;을 정해 준다(만료 2099년, 폐기 없음, ACTIVE)
private Member givenToken(String token, Long memberId, String nickname) {
    Member member = mock(Member.class);
    given(member.getId()).willReturn(memberId);
    given(member.getNickname()).willReturn(nickname);
    given(member.getRole()).willReturn(&quot;USER&quot;);
    given(member.getMemberStatus()).willReturn(&quot;ACTIVE&quot;);

    ApiToken apiToken = mock(ApiToken.class);
    given(apiToken.getExpiresAt()).willReturn(LocalDateTime.of(2099, 12, 31, 23, 59, 59));
    given(apiToken.getMember()).willReturn(member);
    given(apiTokenRepository.findByTokenFetchMember(token)).willReturn(Optional.of(apiToken));
    return member;
}

// PostService.create가 돌려주는 것은 엔티티라(1-3: DTO 변환은 컨트롤러 몫) id·게시판이 채워진 가짜 엔티티를 만든다
private Post fakePost(Long id, Member author) {
    Board board = mock(Board.class);
    given(board.getSlug()).willReturn(&quot;dev&quot;);

    Post post = mock(Post.class);
    given(post.getId()).willReturn(id);
    given(post.getBoard()).willReturn(board);
    given(post.getAuthor()).willReturn(author);
    given(post.getTitle()).willReturn(&quot;[테스트] 제목&quot;);
    given(post.getContent()).willReturn(&quot;본문&quot;);
    given(post.getTags()).willReturn(new LinkedHashSet&lt;&gt;());
    given(post.getVisibility()).willReturn(&quot;PUBLIC&quot;);
    given(post.getCreatedAt()).willReturn(LocalDateTime.of(2026, 10, 9, 12, 0));
    return post;
}


}

#채점 기준

T = 테스트 실행(필수), R = 코드 리뷰(피드백용).

# 확인 방법 기대
T1 ./gradlew test --tests org.example.post.PostControllerTest 통과, 테스트 4개 이상
R1 범위 @SpringBootTest가 아니라 @WebMvcTest(PostController.class)다. 실행 로그에 Testcontainers·HikariPool 시작이 없다(DB를 띄우지 않는다)
R2 가짜 범위 컨트롤러가 쓰는 서비스와 인증 인터셉터가 쓰는 토큰 저장소만 @MockitoBean이다. 컨트롤러·Advice·검증은 실물이다
R3 단언 상태 코드만 보지 않고 헤더(Location, Content-Type)와 JSON 경로(jsonPath)까지 확인한다
R4 위 1~4 표의 네 시나리오가 모두 있다. 테스트 이름에서 입력과 기대 결과가 읽힌다
R5 서비스 호출 2·3번(400·401)에서 서비스가 호출되지 않았음을 verify(..., never()) 또는 then(...).shouldHaveNoInteractions()로 확인한다
