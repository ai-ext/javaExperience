0-4 · 한 파일·두 record02 / 20

ProfileController.java 안에 두 record를 만듭니다

이번 실습은 요청·응답 DTO를 별도 파일로 빼지 않습니다.

파일 위치src/main/java/org/example/start/ProfileController.java
요청 모양ProfileRequest(String name, int age)
응답 모양ProfileResponse(String name, int age, boolean adult)
원문 ProfileController.java 전체직접 작성할 한 파일
package org.example.start;

import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class ProfileController {

    // 요청 본문 DTO. 클래스 안에 둔 record는 저절로 static이다
    public record ProfileRequest(String name, int age) {
    }

    // 응답 DTO. record는 name()·age()·adult()를 만들어 주고, Jackson이 그걸로 JSON을 만든다
    public record ProfileResponse(String name, int age, boolean adult) {
    }

    @PostMapping("/api/start/profile")
    public ProfileResponse create(@RequestBody ProfileRequest request) {
        boolean adult = request.age() >= 19;
        return new ProfileResponse(request.name(), request.age(), adult);
    }
}

Jackson이 JSON을 요청 객체로 만듭니다

컨트롤러 메서드가 실행되기 전에 JSON 키를 record 구성 요소와 맞춥니다.

2record 생성자

3Java 객체

Controller 매개변수

ProfileRequest는 ProfileController 안의 중첩 record입니다.

0-4 · 성인 계산04 / 20

나이 19 이상인지 계산합니다

이번 실습의 성인 기준은 19세입니다.

원문 계산식
boolean adult = request.age() >= 19;
요청 A · 20세request.age() = 2020 >= 19 → true
요청 B · 15세request.age() = 1515 >= 19 → false

record의 값은 age()처럼 괄호를 붙여 꺼냅니다. getAge()가 아닙니다.

0-4 · DTO 세 규칙09 / 20

DTO 변환에는 세 규칙이 있습니다

요청은 만들 수 있어야 하고, 응답은 값을 꺼낼 수 있어야 합니다.

1바깥 객체 없이 만들기

중첩 record는 자동 static입니다. 일반 중첩 클래스라면 static을 붙입니다.

2만드는 방법 알기

record 생성자를 쓰거나 기본 생성자와 setter를 둡니다.

3응답 값 읽기

record 접근자 또는 getter를 둡니다.

이 과정의 record는 세 규칙을 한 번에 만족합니다.

0-4 · 안쪽 클래스11 / 20

안쪽 클래스와 static 중첩 클래스는 다릅니다

겉으로 보이지 않는 바깥 객체 참조가 생성 방식의 차이입니다.

원문 Java 비교선택 개념 · 실습 파일에 추가하지 않음
public class ProfileController {
    public class Inner { }          // 안쪽(비정적) 클래스 — "ProfileController 객체 하나에 딸린" 클래스
    public static class Nested { }  // static 클래스 — 바깥 클래스 이름만 빌려 쓰는 독립 클래스
}

ProfileController controller = new ProfileController();
ProfileController.Inner a = controller.new Inner();         // 바깥 객체가 반드시 있어야 만든다
ProfileController.Nested b = new ProfileController.Nested(); // 바깥 객체 없이 만든다
비정적 Innercontroller.new Inner()

바깥 객체가 반드시 필요합니다.

static Nestednew ProfileController.Nested()

바깥 객체 없이 만듭니다.

0-4 · static 클래스 대안14 / 20

record 대신 static 클래스로도 받을 수 있습니다

기본 생성자와 setter로 요청 객체를 만들고 getter로 값을 꺼냅니다.

원문 static ProfileRequest 비교 코드선택 대안 · record를 대체할 때만
    public static class ProfileRequest {
        private String name;
        private int age;

        public String getName() {
            return name;
        }

        public void setName(String name) {
            this.name = name;
        }

        public int getAge() {
            return age;
        }

        public void setAge(int age) {
            this.age = age;
        }
    }
Jackson 생성new ProfileRequest()

생성자를 직접 선언하지 않아 Java가 빈 생성자를 제공합니다.

값 채우기setName(...) · setAge(...)

컨트롤러에서는 getName()·getAge()로 읽습니다.

0-4 · getter 없는 응답17 / 20

getter 없는 응답 클래스는 200인데 {}입니다

원문 getterless ProfileResponse고장 실험 · 응답 DTO만 바꾸기

        private final String name;
        private final int age;
        private final boolean adult;

        public ProfileResponse(String name, int age, boolean adult) {
            this.name = name;
            this.age = age;
            this.adult = adult;
        }
    }

0-4 · 생성자 이름 보존18 / 20

생성자만 있는 static class도 이 프로젝트에서 됩니다

기본 생성자가 없다는 문구만 보고 원인을 단정하지 마세요.

이 Gradle/Spring Boot 프로젝트-parameters

생성자 매개변수 name·age가 남아 Jackson 3가 매핑할 수 있습니다.

Jackson 3.1.5 별도 실험-parameters 없음

이름을 알 수 없으면 적절한 Creator를 찾지 못해 실패할 수 있습니다.

오른쪽은 Boot 3 앱의 실행 결과가 아닙니다. 500의 진짜 원인은 앞 장면의 비정적 안쪽 클래스였습니다.

첫 수업에서 가장 오래 막힌 곳이 여기다. 요청을 받을 DTO 클래스를 컨트롤러 안에 만들었더니 이런 에러가 났다. "기본 생성자가 없다." 그런데 생성자는 분명히 있었다. 진짜 원인은 static이 빠진 것이었다.

DTO(Data Transfer Object)는 JSON과 Java 객체 사이를 오가는 그릇이다. 그릇을 만드는 규칙은 세 가지뿐이다. 이 단계에서는 프로필 하나를 받아 "성인인지"를 붙여 돌려주는 API를 만든다. 그다음 DTO를 일부러 규칙에 어긋나게 만들어 실제 에러를 보고 고친다.

package org.example.start;

import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class ProfileController {

    // 요청 본문 DTO. 클래스 안에 둔 record는 저절로 static이다
    public record ProfileRequest(String name, int age) {
    }

    // 응답 DTO. record는 name()·age()·adult()를 만들어 주고, Jackson이 그걸로 JSON을 만든다
    public record ProfileResponse(String name, int age, boolean adult) {
    }

    @PostMapping("/api/start/profile")
    public ProfileResponse create(@RequestBody ProfileRequest request) {
        boolean adult = request.age() >= 19;
        return new ProfileResponse(request.name(), request.age(), adult);
    }
}

#DTO 규칙 세 가지

Jackson(JSON ↔ 객체 변환기)이 DTO를 다룰 때 필요한 것은 둘이다. 만들 수 있어야 하고(요청), 값을 꺼낼 수 있어야 한다(응답).

규칙 왜 지키는 법
① 바깥 객체 없이 만들 수 있어야 한다 Jackson은 new 바깥객체.new 안쪽클래스()를 할 수 없다 record(자동 static), 또는 static 클래스, 또는 별도 파일의 클래스
② 만드는 방법을 알아야 한다 빈 객체를 만든 뒤 setter로 채우거나, 생성자 매개변수 이름을 보고 넣는다 record(생성자 자동), 또는 기본 생성자 + setter
③ 값을 꺼낼 수 있어야 한다 응답 JSON을 만들 때 getXxx()(또는 record의 xxx())를 부른다 record, 또는 getter

record를 쓰면 세 규칙이 한 번에 지켜진다. 그래서 이 과정에서는 DTO를 record로 만든다.

#static이 뭐길래

public class ProfileController {
    public class Inner { }          // 안쪽(비정적) 클래스 — "ProfileController 객체 하나에 딸린" 클래스
    public static class Nested { }  // static 클래스 — 바깥 클래스 이름만 빌려 쓰는 독립 클래스
}

ProfileController controller = new ProfileController();
ProfileController.Inner a = controller.new Inner();         // 바깥 객체가 반드시 있어야 만든다
ProfileController.Nested b = new ProfileController.Nested(); // 바깥 객체 없이 만든다
  • static은 "객체가 아니라 클래스에 붙어 있다"는 뜻이다. 필드에 붙이면 객체마다가 아니라 클래스에 하나만 있다(예: private static final Logger log). 메서드에 붙이면 객체 없이 부른다(Main.main, Long.parseLong).
  • 비정적 안쪽 클래스의 생성자는 겉으로는 빈 괄호 ()처럼 보인다. 하지만 컴파일러가 바깥 객체를 받는 숨은 매개변수를 넣는다. 그래서 "기본 생성자가 없다"는 에러가 난다. 눈에 보이는 생성자가 있어도 난다.

#record 대신 static 클래스로 쓴다면

record를 쓸 수 없는 경우(예: 값을 나중에 바꿔야 하는 객체)에는 이렇게 쓴다. 기본 생성자 + getter + setter 모양이다.

    public static class ProfileRequest {
        private String name;
        private int age;

        public String getName() {
            return name;
        }

        public void setName(String name) {
            this.name = name;
        }

        public int getAge() {
            return age;
        }

        public void setAge(int age) {
            this.age = age;
        }
    }
  • 생성자를 하나도 쓰지 않으면 Java가 **빈 생성자(기본 생성자)**를 만들어 준다. Jackson은 그 생성자로 빈 객체를 만든 뒤 setName·setAge로 채운다.
  • 이 모양으로 바꾸면 컨트롤러에서는 request.getAge(), request.getName()으로 꺼낸다.
  • 이 코드도 실측으로 같은 응답이 나왔다. 다만 나이를 빠뜨리면 차이가 난다. record는 400이고, 이 클래스는 age가 0인 채로 200이 나온다({"name":"김자바","age":0,"adult":false}). setter가 불리지 않아 int의 초깃값 0이 남기 때문이다. 조용히 틀린 값이 들어가는 쪽이 더 위험하다.

#record는 실행 중에도 모양을 지킨다

record는 컴파일된 뒤에도 클래스로 남는다. Jackson은 실행 중에 그 구성 요소(name·age)를 보고 본문 JSON을 객체로 만든다. 그래서 모양이 안 맞으면(예: int age에 넣을 값이 없으면) 메서드에 들어가기 전에 400으로 거절된다.

#③ 나이를 빠뜨림(record의 int) → 400


본문을 {"name":"김자바"}로 보낸다.


WARN ... Resolved [org.springframework.http.converter.HttpMessageNotReadableException: JSON parse error: Cannot map `null` into type `int` (set `DeserializationFeature.FAIL_ON_NULL_FOR_PRIMITIVES` to 'false' to allow)]


"age": null로 보내도 같은 줄이 나온다.


    

  • Jackson 3에서 달라진 점: Jackson 2는 같은 record에 age를 0으로 채우고 넘어갔다(2.18.2 단독 실측: Rec[name=김자바, age=0]). Jackson 3는 기본값으로 거절한다.
없어도 되는 값이면 Integer age(null 가능)로 선언하고 코드에서 null을 처리한다. 위 static 클래스 + setter 모양은 Jackson 3에서도 setter가 안 불려 0이 된다.
    • 



#④ 나이에 글자 → 400 (요청 C)


WARN ... Resolved [org.springframework.http.converter.HttpMessageNotReadableException: JSON parse error: Cannot deserialize value of type `int` from String "스무살": not a valid `int` value]


"age": "20"처럼 숫자로 읽히는 글자는 400이 아니다. 20으로 바꿔 받는다(실측).


#⑤ (참고) 생성자만 있고 기본 생성자가 없는 static 클래스


public static class ProfileRequest에 public ProfileRequest(String name, int age) 생성자와 getter만 두고 setter와 빈 생성자는 없앤다. 이 레포에서는 에러 없이 동작한다(실측).


Gradle(Spring Boot 플러그인)이 생성자 매개변수 이름을 클래스 파일에 남기기 때문이다(-parameters). Jackson 3는 그 이름(name, age)을 JSON 키와 맞춰 생성자를 부른다.


매개변수 이름이 남지 않게 컴파일되면(-parameters 없이) 이렇게 실패한다(Jackson 3.1.5 단독 실측).


tools.jackson.databind.exc.InvalidDefinitionException: Cannot construct instance of `K$Req` (no Creators, like default constructor, exist): cannot deserialize from Object value (no delegate- or property-based Creator)


"기본 생성자 없음"이라는 말이 나오는 진짜 경우가 이것이다. ①과는 원인이 다르다.
