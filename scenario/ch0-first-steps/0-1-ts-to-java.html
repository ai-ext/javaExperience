#준비

① DB가 떠 있는지 본다. 실습 레포에는 DB를 쓰는 라이브러리(JPA)가 이미 들어 있다. 그래서 0장처럼 DB를 안 쓰는 코드만 있어도, DB가 꺼져 있으면 앱이 아예 뜨지 않는다.

실습 DB는 javaExperience MySQL(localhost:13308) 안에 있다(시작하기에서 application.yml을 이 DB로 맞췄다). javaExperience DB 컨테이너가 떠 있으면 된다.

docker compose ps mysql   # STATUS가 Up … (healthy)면 준비 끝

이걸 빼먹고 Main을 실행하면 로그 맨 아래에 이런 줄이 나오고 앱이 꺼진다(실측, Boot 4.1.1). 왜 그런지는 0-6에서 본다.

Caused by: org.hibernate.HibernateException: Unable to determine Dialect without JDBC metadata (please set 'jakarta.persistence.jdbc.url' for common cases or 'hibernate.dialect' when a custom Dialect implementation must be provided)

그보다 위쪽 WARN 줄에는 Communications link failure, Caused by: java.net.ConnectException: Connection refused가 보인다. "DB에 연결하지 못했다"는 뜻이다.

② CORS 설정을 넣는다. 이 페이지 아래쪽의 실행 칸(버튼)은 브라우저가 내 서버로 요청을 보낸다. 브라우저 화면과 내 서버는 출처(포트)가 다르다.

그래서 서버가 허락해 주지 않으면 브라우저가 응답을 막는다. 아래 파일을 그대로 붙여 넣는다.

어떻게 동작하는지는 1-1의 CORS 열기에서 자세히 본다. 0-3에서 쓸 X-Client 헤더도 미리 허락해 둔다. 1-1에 갔을 때 이 파일이 있으면 그대로 둔다.

src/main/java/org/example/config/CorsConfig.java

package org.example.config;

import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.CorsRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

// 브라우저 화면가 다른 출처인 이 서버의 응답을 읽도록 허락한다. 자세한 이유는 1-1
@Configuration
public class CorsConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
                .allowedOriginPatterns("http://localhost:[*]", "http://127.0.0.1:[*]")
                .allowedMethods("GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS")
                .allowedHeaders("Content-Type", "Authorization", "X-Client")
                .exposedHeaders("Location", "WWW-Authenticate");
    }
}

// 응답 JSON의 모양. 구성 요소 이름(name·message·nameLength)이 그대로 JSON 키가 된다

줄 코드 처음 보는 사람용 설명
1 package org.example.start; 이 파일이 사는 폴더 이름. 폴더 org/example/start ↔ 패키지 org.example.start. 다르면 컴파일 에러가 난다
3 // ... 한 줄 주석. /* */도 된다
4 public record Greeting(...) record는 "값을 담기만 하는 클래스"를 한 줄로 만드는 문법이다(Java 16+). 괄호 안이 구성 요소다
4 String name 타입이 먼저, 이름이 뒤. String은 대문자로 시작하는 클래스다
4 int nameLength int는 정수(소수점 없음). 소문자로 시작하는 기본 타입이다
4~5 { } record 본문. 지금은 비어 있다
— 파일 이름 public 클래스·record 이름과 파일 이름이 같아야 한다(Greeting ↔ Greeting.java)

record Greeting(String name, String message, int nameLength) 한 줄로 Java가 아래를 저절로 만든다.

  • 필드 세 개: private final String name; 등. final은 "한 번 넣으면 못 바꾼다"는 뜻이다.
  • 생성자 하나: new Greeting("김자바", "...", 3)로 객체를 만들 때 불리는 특별한 메서드다. 필드에 값을 채운다.
  • 꺼내는 메서드: name(), message(), nameLength(). 이름 앞에 get이 붙지 않는다.
  • equals·hashCode·toString.

같은 것을 보통 클래스로 쓰면 이렇다. 생성자를 직접 쓰는 연습용이다. 만들지 않아도 된다.

public class Greeting {
    private final String name;        // 필드: 타입 이름;
    private final String message;
    private final int nameLength;

    // 생성자 — 클래스와 이름이 같고, 반환 타입을 쓰지 않는다
    public Greeting(String name, String message, int nameLength) {
        this.name = name;             // this.name = 이 객체의 필드, name = 매개변수
        this.message = message;
        this.nameLength = nameLength;
    }

    // getter — Jackson(JSON 변환기)은 getXxx()를 보고 JSON 키 xxx를 만든다
    public String getName() { return name; }
    public String getMessage() { return message; }
    public int getNameLength() { return nameLength; }
}

Java는 클래스 이름을 생성자 이름으로 쓴다. 생성자에는 반환 타입을 쓰지 않는다(void도 안 쓴다).

#파일 2 — 요청을 받는 GreetingController.java

src/main/java/org/example/start/GreetingController.java

package org.example.start;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class GreetingController {

    @GetMapping("/api/start/hello")
    public Greeting hello(@RequestParam(defaultValue = "익명") String name) {
        String message = name + "님, 반가워요";
        int nameLength = name.length();
        return new Greeting(name, message, nameLength);
    }
}
줄 코드 처음 보는 사람용 설명
3~5 import org.springframework...GetMapping; 다른 패키지의 클래스를 이 파일에서 쓰겠다는 선언. 패키지 전체 이름.클래스 이름 순서다. IntelliJ에서 빨간 글자에 Alt+Enter(맥 ⌥↩)를 누르면 자동으로 넣어 준다
7 @RestController 어노테이션. Spring에게 "이 클래스는 HTTP 요청을 받는 곳이고, 반환값을 그대로 응답 본문으로 쓴다"고 알려 주는 표시다. 0-2에서 떼어 본다
8 public class GreetingController { 클래스 선언. public은 "다른 패키지에서도 보인다"
10 @GetMapping("/api/start/hello") 이 메서드가 GET /api/start/hello를 맡는다
11 public Greeting hello(...) 반환 타입 Greeting이 메서드 이름 앞에 온다.
11 @RequestParam(defaultValue = "익명") String name 쿼리스트링의 name을 이 매개변수에 넣는다. 없으면 "익명". 매개변수도 타입 이름 순서다
12 String message = name + "님, 반가워요"; 지역 변수 선언: 타입 이름 = 값; 문자열은 +로 잇는다. 문장 끝 ;는 빼면 안 된다
13 int nameLength = name.length(); 문자열 길이. length는 메서드라 괄호 ()를 붙인다
14 return new Greeting(name, message, nameLength); new로 생성자를 불러 객체를 만들고 돌려준다. 인자의 순서와 개수가 record 선언과 같아야 한다

#자주 헷갈리는 것

  • var도 있다. var message = name + "님";처럼 쓰면 타입을 추론한다. 하지만 처음에는 타입을 직접 쓰는 연습을 한다.
  • String(대문자, 클래스)과 int(소문자, 기본 타입)는 종류가 다르다. 기본 타입은 null이 될 수 없다. null이 필요하면 Integer를 쓴다. 0-4에서 이 차이 때문에 에러가 난다.
  • static은 "객체 없이 클래스에 붙어 있는 것"이다. Main.main이 static이라 객체를 만들지 않고도 앱이 시작된다. 0-4에서 자세히 본다.
  • Java 문자열은 큰따옴표 "만 된다. 작은따옴표 'a'는 글자 하나(char)다.

이 단계의 처리 흐름:

  • GreetingController.hello가 쿼리의 name을 String name 매개변수로 받는다 — @RequestParam
  • 인사말(String)과 글자 수(int)를 만들어 new Greeting(name, message, nameLength)로 응답 객체를 만든다
  • Spring이 Greeting record를 JSON으로 바꾼다 — 구성 요소 이름이 그대로 JSON 키가 된다
  • name이 없으니 @RequestParam(defaultValue = "익명")의 기본값 '익명'이 들어간다

        int nameLength = name.length();
        return new Greeting(name, message, nameLength);
    }
