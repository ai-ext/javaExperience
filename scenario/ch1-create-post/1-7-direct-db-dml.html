#만들 것

새 API를 만들지 않는다. 1-6의 POST /api/posts로 만든 본인 글 한 행을 SQL로 검산한다. SQL은 javaExperience CloudBeaver의 community 연결 또는 MySQL CLI에서 실행한다. 처음에는 아래의 완성 예시를 실행하고, 그다음 WHERE와 JOIN을 직접 바꿔 본다.

테이블 연결 열 이 단계에서 읽거나 바꿀 것
post id, board_id, author_id API가 만든 글, 제목 변경·롤백, 표식 글 INSERT·DELETE
board id post.board_id가 가리키는 slug='dev'
member id post.author_id가 가리키는 토큰 주인(김자바 id 2)
tag·post_tag tag.id, post_tag.post_id·tag_id 표식 글에 java 태그 연결, 자식 행부터 삭제

post는 board_id와 author_id가 필수 외래키다. post_tag는 (post_id, tag_id) 복합 기본키라 같은 태그를 같은 글에 두 번 연결하면 오류가 난다. 1-3에서 JPA가 저장한 두 테이블의 행도 아래 SELECT로 볼 수 있다.

#구현 가이드

이번 단계의 구현 위치는 Java 파일이 아니라 community DB의 내가 만든 행이다. 먼저 post.id와 토큰 회원 ID를 기록한다.

SQL — 외래키를 따라 요청 결과 찾기

post.board_id → board.id, post.author_id → member.id를 연결한다. 아래 22는 API 응답에서 받은 실제 글 ID로 바꾼다.

SELECT p.id, p.title, b.slug, m.nickname
FROM post p
JOIN board b ON b.id = p.board_id
JOIN member m ON m.id = p.author_id
WHERE p.id = 22 AND p.author_id = 2;

태그는 post_tag.post_id로 한 번 더 연결한다. JOIN을 하나씩 추가하면서 행 수가 어떻게 바뀌는지 확인한다.

롤백 — 직접 바꾼 행을 남기지 않기

같은 SQL 탭/연결에서 START TRANSACTION부터 ROLLBACK까지 실행한다. WHERE에는 글 ID와 내 회원 ID 둘 다 넣는다.

START TRANSACTION;
UPDATE post SET title = '[DB실습] 임시 제목', updated_at = NOW()
WHERE id = 22 AND author_id = 2;
SELECT id, title FROM post WHERE id = 22;
ROLLBACK;
SELECT id, title FROM post WHERE id = 22;

두 번째 SELECT가 원래 제목인지 확인한다. ROLLBACK은 AUTO_INCREMENT 번호를 되감지 않는다.

-- 별도 표식 글의 생성, 태그 연결, 자식 행 우선 삭제를 한 트랜잭션에서 확인한다.
START TRANSACTION;
INSERT INTO post (board_id, author_id, title, content, status, visibility,
                  published_at, created_at, updated_at)
VALUES (2, 2, '[DB실습] SQL 표식 글', '직접 INSERT한 글입니다.',
        'PUBLISHED', 'PUBLIC', NOW(), NOW(), NOW());
SET @sql_post_id = LAST_INSERT_ID();
INSERT INTO post_tag (post_id, tag_id)
SELECT @sql_post_id, id FROM tag WHERE name = 'java';
SELECT p.id, p.title, t.name
FROM post p JOIN post_tag pt ON pt.post_id = p.id
JOIN tag t ON t.id = pt.tag_id
WHERE p.id = @sql_post_id;
DELETE FROM post_tag WHERE post_id = @sql_post_id;
DELETE FROM post WHERE id = @sql_post_id AND author_id = 2;
SELECT COUNT(*) AS remaining FROM post WHERE id = @sql_post_id;
ROLLBACK;

#직접 확인

먼저 API로 글을 하나 만든다. 1-5의 제목·본문 길이 규칙에 맞춰 내용을 조정하고, 응답의 id를 기록한다. SQL 예시의 22는 내 응답 id로 바꿔야 한다. 시드에 글 21개가 있어 초기 상태에서는 22 이상이지만 채점 뒤에는 달라진다.

터미널 명령어 참고
BASE=http://localhost:8080
curl -i -X POST "$BASE/api/posts" -H 'Authorization: Bearer tok-kimjava' \
  -H 'Content-Type: application/json' \
  -d '{"boardSlug":"dev","title":"[DB실습] 처음 제목","content":"SQL로 행을 확인하고 트랜잭션을 연습합니다.","tags":["java"],"visibility":"PUBLIC"}'

CloudBeaver에서 community 연결을 열거나 MySQL CLI로 접속한다. 아래는 완성된 3테이블 JOIN 예시다. 먼저 실행해 nickname='김자바', slug='dev', 응답의 제목을 확인한다.

SELECT p.id, p.title, b.slug, m.nickname
FROM post p
JOIN board b ON b.id = p.board_id
JOIN member m ON m.id = p.author_id
WHERE p.id = 22 AND p.author_id = 2;

이제 post_tag와 tag를 JOIN해서 이 글의 태그 이름을 조회하는 SQL을 직접 작성한다. 시작 모양은 FROM post_tag pt JOIN tag t ON t.id = pt.tag_id WHERE pt.post_id = 22다. 기대 결과는 java 한 행이다.

#트랜잭션 안에서 UPDATE 후 되돌리기

다음 SQL은 같은 DB 세션에서 차례로 실행한다. SET @my_post_id = 22의 22를 실제 내 글 id로 바꾼다. UPDATE 결과가 1행인지 보고, ROLLBACK 뒤 첫 제목으로 돌아왔는지 확인한다. DB 클라이언트가 문장마다 새 연결을 쓰면 같은 세션의 @my_post_id와 트랜잭션이 이어지지 않으므로 한 SQL 탭/연결에서 실행한다.

SET @my_post_id = 22;
START TRANSACTION;
SELECT title FROM post WHERE id = @my_post_id AND author_id = 2;
UPDATE post SET title = '[DB실습] SQL로 수정', updated_at = NOW()
WHERE id = @my_post_id AND author_id = 2;
SELECT title FROM post WHERE id = @my_post_id AND author_id = 2;
ROLLBACK;
SELECT title FROM post WHERE id = @my_post_id AND author_id = 2;

#표식 글 INSERT·연결·DELETE

아래는 새로운 행의 필수 열을 채우는 동작하는 예시다. board_id=2는 dev, author_id=2는 김자바다. 시작 전 SELECT id, slug FROM board와 SELECT id, nickname FROM member WHERE id=2로 확인한다. 트랜잭션을 열고 표식 글을 넣은 뒤 LAST_INSERT_ID()를 변수에 담는다. 기존 글·태그를 건드리지 않는다.

START TRANSACTION;
INSERT INTO post (board_id, author_id, title, content, status, visibility,
                  published_at, created_at, updated_at)
VALUES (2, 2, '[DB실습] SQL 표식 글', '직접 INSERT한 글입니다.',
        'PUBLISHED', 'PUBLIC', NOW(), NOW(), NOW());
SET @sql_post_id = LAST_INSERT_ID();
INSERT INTO post_tag (post_id, tag_id)
SELECT @sql_post_id, id FROM tag WHERE name = 'java';
SELECT p.id, p.title, t.name
FROM post p JOIN post_tag pt ON pt.post_id = p.id
JOIN tag t ON t.id = pt.tag_id
WHERE p.id = @sql_post_id;
DELETE FROM post_tag WHERE post_id = @sql_post_id;
DELETE FROM post WHERE id = @sql_post_id AND author_id = 2;
SELECT COUNT(*) AS remaining FROM post WHERE id = @sql_post_id;
ROLLBACK;

remaining은 0이어야 한다. post를 먼저 DELETE하면 아직 post_tag가 가리켜 외래키 오류가 난다. 일부러 순서를 바꿔 오류를 본 경우에도 같은 세션에서 ROLLBACK을 실행해 실습 행을 정리한다. ROLLBACK은 행과 연결을 되돌리지만 AUTO_INCREMENT 번호를 되감지는 않는다. 다음 글 id가 건너뛰어도 정상이다.
