"태그도 저장해 주세요. 없는 태그면 새로 만들고요. 같은 태그가 두 번 오면 한 번만 붙여 주세요."

1-2에서는 컨트롤러가 저장소 둘(BoardRepository·PostRepository)을 바로 불렀다. 태그까지 저장하려면 일이 늘어난다.

  1. slug로 게시판을 찾는다.
  2. 태그 이름마다 tag에서 찾고, 없으면 INSERT한다.
  3. post에 글을 INSERT한다.
  4. post_tag에 (글, 태그) 연결을 태그 수만큼 INSERT한다.

DB에 쓰는 일이 여러 번이다. 3번에서 실패하면 2번에서 새로 만든 태그만 덩그러니 남는다. 이 묶음을 "전부 되거나, 전부 안 되거나"로 만들어야 한다. 그 경계가 트랜잭션이고, 트랜잭션은 서비스 메서드 하나에 건다.

그래서 이 단계에서 컨트롤러에서 서비스를 떼어 낸다. 저장소는 1-2의 JPA 저장소 그대로 쓴다.

태그 규칙

  • 이미 있는 이름(예: spring)은 그 태그를 연결한다.
  • 없는 이름은 tag에 새로 만든 뒤 연결한다.
  • 같은 이름이 요청에 두 번 와도 한 번만 연결한다.
  • 연결 테이블은 post_tag(복합 기본키 post_id, tag_id)다.

트랜잭션 규칙 — 게시판 찾기부터 post_tag 연결까지가 한 트랜잭션이다. 중간에 실패하면 새로 만든 태그도 남지 않는다.

필드 규칙 — 1-2의 표 그대로다. 아직 검증하지 않는다. 이 단계 정답 코드에서도 제목 null은 500이다(관찰 O1). 달라진 점은 실패할 때 반쪽이 남지 않는다는 것이다(관찰 O2와 D3). 검증은 1-5에서 한다.

② Post.java — 태그 연결 추가

1-2의 Post에 아래를 더한다(import는 jakarta.persistence.JoinTable·ManyToMany, org.example.tag.Tag, java.util.LinkedHashSet·Set).

    @ManyToMany(fetch = FetchType.LAZY)
    @JoinTable(
            name = "post_tag",
            joinColumns = @JoinColumn(name = "post_id"),
            inverseJoinColumns = @JoinColumn(name = "tag_id")
    )
    private Set<Tag> tags = new LinkedHashSet<>();

    public void addTag(Tag tag) {
        tags.add(tag);
    }

    public Set<Tag> getTags() {
        return tags;
    }
줄 뜻
@ManyToMany + @JoinTable(name = "post_tag", …) 글 하나에 태그 여럿, 태그 하나에 글 여럿. 그 사이를 post_tag 테이블이 잇는다. joinColumns는 "이 엔티티(글) 쪽 컬럼", inverseJoinColumns는 "상대(태그) 쪽 컬럼"이다.
Set<Tag> · LinkedHashSet 같은 태그를 두 번 넣어도 하나만 남는다. LinkedHashSet은 넣은 순서를 지킨다.
addTag(tag) 글을 저장할 때 Hibernate가 이 집합을 보고 post_tag에 행을 넣는다. 연결 행을 내가 INSERT하지 않는다.

③ PostService.java — 글 만들기 규칙과 트랜잭션(org.example.post)

package org.example.post;

import org.example.board.Board;
import org.example.board.BoardRepository;
import org.example.tag.Tag;
import org.example.tag.TagRepository;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.time.LocalDateTime;
import java.util.LinkedHashSet;
import java.util.List;
import java.util.Set;

// 글 만들기 규칙. HTTP(ResponseEntity, 헤더 등)는 알지 않는다.
@Service
public class PostService {

    // 로그인 기능이 없는 동안 작성자를 고정한다 — 1-6에서 토큰 기반으로 바꾼다
    private static final long FIXED_AUTHOR_ID = 2L;

    private final PostRepository postRepository;
    private final BoardRepository boardRepository;
    private final TagRepository tagRepository;

    public PostService(PostRepository postRepository, BoardRepository boardRepository,
                        TagRepository tagRepository) {
        this.postRepository = postRepository;
        this.boardRepository = boardRepository;
        this.tagRepository = tagRepository;
    }

    // 글 한 행 + 새 태그 + post_tag 연결을 한 트랜잭션으로 — 중간에 실패하면 전부 되돌린다
    @Transactional
    public Post create(PostCreateRequest request) {
        Board board = boardRepository.findBySlug(request.boardSlug())
                .orElseThrow(() -> new IllegalArgumentException("게시판을 찾을 수 없습니다: " + request.boardSlug()));

        LocalDateTime now = LocalDateTime.now();
        Post post = new Post(board, FIXED_AUTHOR_ID, request.title(), request.content(),
                request.visibility(), now);

        for (String tagName : distinctTagNames(request.tags())) {
            Tag tag = tagRepository.findByName(tagName)
                    .orElseGet(() -> tagRepository.save(new Tag(tagName, now)));
            post.addTag(tag);
        }

        return postRepository.save(post);
    }

    private List<String> distinctTagNames(List<String> tags) {
        if (tags == null) {
            return List.of();
        }
        Set<String> seen = new LinkedHashSet<>(tags);
        return List.copyOf(seen);
    }
}
줄 뜻
@Service 이 클래스로 객체(빈)를 하나 만들어 두라는 표시. Spring은 서버를 켤 때 이 표시가 붙은 클래스를 찾아 딱 하나 만든다. 이게 없으면 컨트롤러가 받을 PostService가 없어서 서버가 안 뜬다(아래 "일부러 망가뜨리기" 1번).
private final …Repository 셋 + 생성자 생성자 주입. Spring이 서비스를 만들 때 생성자 인자를 보고, 보관 중인 저장소 빈을 넣어 준다. 생성자가 하나면 @Autowired를 안 붙여도 된다.
@Transactional 메서드가 시작할 때 트랜잭션을 열고, 정상으로 끝나면 COMMIT, 예외가 밖으로 나가면 ROLLBACK한다. 안에서 부른 저장소들은 모두 같은 트랜잭션(같은 DB 연결)을 쓴다.
findByName(...).orElseGet(() -> tagRepository.save(...)) 있으면 그 태그, 없을 때만 만든다. 이미 있는 이름을 또 INSERT하면 tag.name의 UNIQUE에 걸린다.
distinctTagNames 요청 안의 중복을 미리 지운다. LinkedHashSet에 넣었다 빼면 중복 없이 순서가 유지된다.
new Post(...), new Tag(...) 값을 담는 엔티티는 new 해도 된다. new 하지 말라는 건 다른 빈(서비스·저장소) 이야기다.

왜 final + 생성자인가.

  • 빠뜨릴 수 없다 — 생성자 인자라서 저장소 없이는 PostService를 만들 수가 없다. 컴파일러와 Spring이 둘 다 막아 준다. 필드 주입(@Autowired private PostRepository postRepository;)은 빠져도 일단 만들어지고, 쓰는 순간 null이 터진다.
  • 바뀌지 않는다 — final이라 한 번 들어온 저장소를 중간에 다른 걸로 바꿀 수 없다. 빈은 서버 전체에서 하나를 여러 요청이 같이 쓰므로, 안 바뀌는 게 안전하다.
  • 테스트하기 쉽다 — Spring 없이도 생성자에 가짜 저장소를 넣어 시험할 수 있다(7-2).

서버를 켜면 Spring이 이 순서로 조립한다. 저장소(Spring Data JPA가 만든 구현)를 먼저 만들고, 그걸 넣어 서비스를 만들고, 그 서비스를 넣어 컨트롤러를 만든다. 어느 하나라도 만들 수 없으면 서버가 뜨지 않는다.

import org.example.board.Board;
import org.example.board.BoardRepository;
import org.example.tag.Tag;
import org.example.tag.TagRepository;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;


import java.time.LocalDateTime;
import java.util.LinkedHashSet;
import java.util.List;
import java.util.Set;


// 글 만들기 규칙. HTTP(ResponseEntity, 헤더 등)는 알지 않는다.
@Service
public class PostService {


// 로그인 기능이 없는 동안 작성자를 고정한다 — 1-6에서 토큰 기반으로 바꾼다
private static final long FIXED_AUTHOR_ID = 2L;

private final PostRepository postRepository;
private final BoardRepository boardRepository;
private final TagRepository tagRepository;

public PostService(PostRepository postRepository, BoardRepository boardRepository,
                    TagRepository tagRepository) {
    this.postRepository = postRepository;
    this.boardRepository = boardRepository;
    this.tagRepository = tagRepository;
}

// 글 한 행 + 새 태그 + post_tag 연결을 한 트랜잭션으로 — 중간에 실패하면 전부 되돌린다
@Transactional
public Post create(PostCreateRequest request) {
    Board board = boardRepository.findBySlug(request.boardSlug())
            .orElseThrow(() -&gt; new IllegalArgumentException(&quot;게시판을 찾을 수 없습니다: &quot; + request.boardSlug()));

    LocalDateTime now = LocalDateTime.now();
    Post post = new Post(board, FIXED_AUTHOR_ID, request.title(), request.content(),
            request.visibility(), now);

    for (String tagName : distinctTagNames(request.tags())) {
        Tag tag = tagRepository.findByName(tagName)
                .orElseGet(() -&gt; tagRepository.save(new Tag(tagName, now)));
        post.addTag(tag);
    }

    return postRepository.save(post);
}

private List&lt;String&gt; distinctTagNames(List&lt;String&gt; tags) {
    if (tags == null) {
        return List.of();
    }
    Set&lt;String&gt; seen = new LinkedHashSet&lt;&gt;(tags);
    return List.copyOf(seen);
}


}

package org.example.post;


import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import java.net.URI;


@RestController
@RequestMapping("/api/posts")
public class PostController {
    private static final Logger log = LoggerFactory.getLogger(PostController.class);
    private final PostService postService;


public PostController(PostService postService) {
    this.postService = postService;
}

@PostMapping
public ResponseEntity&lt;PostResponse&gt; create(@RequestBody PostCreateRequest request) {
    log.info(&quot;게시글 작성 요청 제목: {}&quot;, request.title());
    PostResponse response = postService.create(request);
    return ResponseEntity.created(URI.create(&quot;/api/posts/&quot; + response.id())).body(response);
}


}

Service / 규칙 — src/main/java/org/example/post/PostService.java
package org.example.post;


import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import java.time.LocalDateTime;
import java.util.LinkedHashMap;
import java.util.LinkedHashSet;
import java.util.List;
import java.util.Map;


// 태그·글·연결 행을 하나의 트랜잭션에서 Mapper SQL로 저장한다.
@Service
public class PostService {
    private static final long FIXED_AUTHOR_ID = 2L;
    private final PostCreationMapper mapper;


public PostService(PostCreationMapper mapper) {
    this.mapper = mapper;
}

@Transactional
public PostResponse create(PostCreateRequest request) {
    BoardWriteRow board = mapper.findBoardBySlug(request.boardSlug());
    if (board == null) {
        throw new IllegalArgumentException(&quot;게시판을 찾을 수 없습니다: &quot; + request.boardSlug());
    }
    PostInsert post = new PostInsert();
    post.boardId = board.id;
    post.authorId = FIXED_AUTHOR_ID;
    post.title = request.title();
    post.content = request.content();
    post.visibility = request.visibility();
    post.now = LocalDateTime.now();

    Map&lt;Long, String&gt; storedTags = new LinkedHashMap&lt;&gt;();
    for (String tagName : new LinkedHashSet&lt;&gt;(request.tags() == null ? List.&lt;String&gt;of() : request.tags())) {
        mapper.insertTagIfAbsent(tagName, post.now);
        TagWriteRow tag = mapper.findTagByName(tagName);
        storedTags.putIfAbsent(tag.id, tag.name);
    }
    // 앞선 태그 INSERT가 끝난 뒤 글 INSERT가 실패해도 @Transactional이 함께 되돌린다.
    mapper.insertPost(post);
    for (Long tagId : storedTags.keySet()) {
        mapper.linkTag(post.id, tagId);
    }
    return new PostResponse(post.id, board.slug, post.title, post.content,
            List.copyOf(storedTags.values()), post.visibility, post.now);
}


}

MyBatis / Mapper — src/main/java/org/example/post/PostCreationMapper.java
package org.example.post;


import java.time.LocalDateTime;
import org.apache.ibatis.annotations.Mapper;
import org.apache.ibatis.annotations.Param;


@Mapper
public interface PostCreationMapper {
    BoardWriteRow findBoardBySlug(@Param("slug") String slug);
    int insertPost(PostInsert post);
    int insertTagIfAbsent(@Param("name") String name, @Param("now") LocalDateTime now);
    TagWriteRow findTagByName(@Param("name") String name);
    int linkTag(@Param("postId") Long postId, @Param("tagId") Long tagId);
}

C = HTTP 확인(필수), D = DB 확인(필수, SELECT만), R = 코드 리뷰(피드백용). C4·C5는 관찰이다(채점 안 함 — 필수 N/M에 세지 않는다). {id}는 C1 응답의 id다. 이 단계는 구조를 바꾸는 단계라 R 항목이 핵심 피드백이다.

힌트 1 — 서비스 뼈대


@Service 클래스에 저장소 셋을 private final로 두고, 셋을 받는 생성자 하나. public Post create(PostCreateRequest request)에 @Transactional(org.springframework.transaction.annotation). 컨트롤러에 있던 게시판 찾기·new Post(...)·save를 그대로 옮긴다.






힌트 2 — 태그


post_tag는 컬럼이 두 개뿐인 연결 테이블이라 @ManyToMany + @JoinTable(name = "post_tag", ...)로 매핑할 수 있다. 태그는 TagRepository.findByName으로 찾고 없으면 save한다. 요청 목록은 new LinkedHashSet<>(tags)로 중복을 지운다.






힌트 3 — 응답의 tags


post.getTags().stream().map(Tag::getName).toList(). 서비스가 돌려준 Post의 태그는 서비스 안에서 찾거나 만든 객체라, 컨트롤러에서 이름을 읽어도 DB에 다시 가지 않는다.
