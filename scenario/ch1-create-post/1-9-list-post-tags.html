#1-9. 글의 태그 목록 조회 — 제네릭과 Stream

#상황

"글 상세 화면에서 태그를 따로 새로고침하고 싶어요. 글 ID로 태그 이름 목록을 주세요."

1-8까지 글을 만들고 복사했다. 이제 기존 글의 태그 목록을 읽는 작은 GET API를 추가한다. Post의 태그 Set<Tag>를 API 응답 List<TagResponse>로 바꾸면서 제네릭 타입과 Stream의 map을 함께 연습한다.

이 단계는 JPA 경로에서 컬렉션과 Stream 변환을 익히는 실습이다. 같은 계약의 MyBatis Mapper 대안은 아직 제공하지 않으며, MyBatis 평가는 별도 구현 전까지 보류한다.

#먼저 읽기: 꺾쇠 괄호의 타입

List<Tag>는 Tag 여러 개를 담는 목록이다. 여기서 <Tag>의 Tag가 목록 안에 들어갈 타입이다. List<String>은 문자열 목록이다. 이처럼 컨테이너가 안에 들어갈 타입을 받아 여러 타입에 재사용되는 방식이 제네릭이다.

기존 코드에도 이미 같은 문법이 있다.

JpaRepository<Post, Long> // Post 행을 다루며 ID 타입은 Long
Optional<Post>            // Post가 있거나 없을 수 있음
List<String>              // 문자열 여러 개

이번 응답은 ResponseEntity<List<TagResponse>>다. 바깥 ResponseEntity는 HTTP 응답을, 안쪽 List<TagResponse>는 JSON 배열의 원소 타입을 나타낸다. TagResponse를 명시하므로 Tag 엔티티 전체나 내부 DB 필드를 API에 그대로 내보내지 않는다.

#구현 가이드

먼저 이름 하나를 DTO로 바꾸는 함수를 읽고, 그다음 목록의 각 원소에 같은 변환을 적용한다.

응답 DTO — 엔티티 대신 이름만 내보내기 
package org.example.post;

public record TagResponse(String name) {
}
PostTagService — Stream map으로 타입 변환하기 
@Transactional(readOnly = true)
public List<TagResponse> listTags(Long postId) {
    Post post = postRepository.findById(postId)
            .filter(found -> found.getDeletedAt() == null
                    && "PUBLISHED".equals(found.getStatus())
                    && "PUBLIC".equals(found.getVisibility()))
            .orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND));

    return post.getTags().stream()
            .map(tag -> new TagResponse(tag.getName()))
            .toList();
}

stream()은 컬렉션의 원소들을 차례로 처리할 흐름을 만든다. map은 원소 하나를 다른 값으로 바꾸므로 Tag가 TagResponse가 된다. 마지막 toList()가 변환 결과를 List<TagResponse>로 모은다. 빈 Set이면 자연스럽게 빈 목록이 나온다. 트랜잭션 안에서 지연 로딩되는 태그도 읽는다.

map(TagResponse::new)로 줄여 쓸 수도 있지만, 첫 학습에서는 tag.getName()이 DTO 생성자에 들어가는 모습을 보이도록 람다를 쓴다.

PostTagController — 반환 타입에서 제네릭 읽기 
@GetMapping("/{postId}/tags")
public ResponseEntity<List<TagResponse>> listTags(@PathVariable Long postId) {
    return ResponseEntity.ok(postTagService.listTags(postId));
}

List와 TagResponse, GetMapping, PathVariable을 import한다. 컨트롤러는 DB나 태그 변환을 직접 처리하지 않는다.

package org.example.post;


import java.util.List;


import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;


@RestController
@RequestMapping("/api/posts")
public class PostTagController {


private final PostTagService postTagService;

public PostTagController(PostTagService postTagService) {
    this.postTagService = postTagService;
}

@GetMapping(&quot;/{postId}/tags&quot;)
public ResponseEntity&lt;List&lt;TagResponse&gt;&gt; listTags(@PathVariable Long postId) {
    return ResponseEntity.ok(postTagService.listTags(postId));
}


}

Service / 규칙 — src/main/java/org/example/post/PostTagService.java
package org.example.post;


import java.util.List;


import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import org.springframework.web.server.ResponseStatusException;


@Service
public class PostTagService {


private final PostRepository postRepository;

public PostTagService(PostRepository postRepository) {
    this.postRepository = postRepository;
}

@Transactional(readOnly = true)
public List&lt;TagResponse&gt; listTags(Long postId) {
    Post post = postRepository.findById(postId)
            .filter(found -&gt; found.getDeletedAt() == null
                    &amp;&amp; &quot;PUBLISHED&quot;.equals(found.getStatus())
                    &amp;&amp; &quot;PUBLIC&quot;.equals(found.getVisibility()))
            .orElseThrow(() -&gt; new ResponseStatusException(HttpStatus.NOT_FOUND));

    return post.getTags().stream()
            .map(tag -&gt; new TagResponse(tag.getName()))
            .toList();
}


}

#직접 확인

먼저 기존 공개 글(기본 데이터의 ID 2)에 태그가 있는지 화면과 DB에서 확인한다. 빈 목록 응답도 확인하려면 1-3의 글 생성 API로 공개 글을 하나 만들 때 tags: []를 보내고, 응답의 id를 아래 실행 요청의 {{taglessPostId}} 자리에 바꿔 넣은 뒤 전체 실행한다.

터미널 명령어 참고
BASE=http://localhost:8080
curl -i "$BASE/api/posts/2/tags"
curl -i "$BASE/api/posts/{{taglessPostId}}/tags"
curl -i "$BASE/api/posts/999999/tags"

실제 DB에서 글 ID 2의 태그는 post_tag와 tag를 JOIN해 확인한다. 태그 없는 공개 글을 하나 만들고 그 글의 ID로 다시 요청하면 []가 나와야 한다.

SELECT t.name
FROM post_tag pt
JOIN tag t ON t.id = pt.tag_id
WHERE pt.post_id = 2
ORDER BY t.name;
