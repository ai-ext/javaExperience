package org.example.post;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class PostController {
    private static final Logger log = LoggerFactory.getLogger(PostController.class);

    @PostMapping("/api/posts")
    public String create(@RequestBody PostCreateRequest request) {
        log.info("게시글 작성 요청: {}", request.title());
        return "success";
    }
}

DTO — JSON의 필드와 record 구성 요소

JSON 키와 record 구성 요소 이름을 맞추면 Spring이 요청 본문을 객체로 변환합니다.

content→String content본문

PostCreateRequest.java요청 DTO · record
import java.util.List;

public record PostCreateRequest(
    String boardSlug,
    String title,
    String content,
    List<String> tags,
    String visibility
) { }
Controller에서 꺼내기request.title()record 접근자는 getTitle()이 아니라 title()입니다.
변환과 검증은 다른 단계예요이 단계에는 Bean Validation을 붙이지 않습니다. JSON 문법 오류나 대상 타입으로 변환할 수 없는 값은 변환 실패로 400이 될 수 있습니다. 필드 이름이 어긋났다고 매번 400이라고 단정하지 말고, JSON 키와 record 이름을 맞춰 필요한 값을 받으세요.

출처(origin)는 프로토콜·호스트·포트의 조합입니다. localhost:3000과 localhost:8080은 포트가 달라 다른 출처예요.
JSON 요청은 먼저 허락을 확인해요
  1. 01
    브라우저가 OPTIONS preflight를 보냄OPTIONS /api/postsOrigin: http://localhost:3000 · Access-Control-Request-Method: POST · Access-Control-Request-Headers: content-type
  2. 02
    서버가 허용 헤더로 답함Access-Control-Allow-Origin: http://localhost:3000Access-Control-Allow-Methods: GET, POST, PUT, PATCH, DELETE, OPTIONS이 요청의 Access-Control-Allow-Headers: content-type
  3. 03
    허락을 확인한 뒤 실제 POST 전송POST /api/posts이 1-1 요청의 헤더는 Content-Type: application/json 입니다.
허락 헤더가 없으면?preflight 응답에 Access-Control-Allow-Origin이 없으면 브라우저는 실제 POST를 보내지 않고 차단합니다. 서버가 OPTIONS에 200으로 답해도 허락 헤더가 빠지면 같은 결과입니다.
CORS는 로그인이나 권한 검사가 아니에요
브라우저가 다른 출처 응답을 페이지 코드에 보여 줄지 정하는 규칙입니다. 실제 인증·권한 처리는 서버가 따로 해야 합니다.
Postman은 브라우저 CORS를 검사하지 않아요
서버 응답 헤더를 직접 확인할 수 있어도, 브라우저가 응답을 읽을 수 있는지는 브라우저에서 확인해야 합니다.
서버에서 허용할 범위
경로/api/**API만 열고 /hello 같은 경로는 그대로 둡니다.
allowedOriginPatternshttp://localhost:[*]http://127.0.0.1:[*]로컬 화면의 포트가 달라도 허용합니다. 배포 뒤에는 배포한 화면 주소를 추가합니다.
allowedMethodsGET · POST · PUT · PATCH · DELETE · OPTIONS기본은 GET·HEAD·POST뿐이라 이후 PATCH·DELETE 단계가 preflight에서 막힐 수 있습니다.
allowedHeadersContent-Type · Authorization · X-ClientX-Client는 0-3 설정을 유지하고, Authorization은 1-6부터 사용합니다.
exposedHeadersLocation · WWW-Authenticate브라우저 코드에서 읽을 응답 헤더입니다. 1-2와 1-6의 헤더 확인에 필요합니다. Postman은 이 제한을 받지 않습니다.
0장에서 CorsConfig를 만들었다면 기존 설정을 유지하고 필요한 값을 합치세요. 구현은 org.example 아래 설정 클래스에서 WebMvcConfigurer의 addCorsMappings를 재정의합니다. Spring Framework 7.0(Spring Boot 4.1)의 addMapping 기본값을 기준으로 설명합니다.
1-6 토큰 인터셉터 주의OPTIONS preflight에는 토큰이 없습니다. 인터셉터가 이를 차단하면 브라우저는 CORS 실패처럼 보입니다. 인터셉터 맨 앞에서 CorsUtils.isPreFlightRequest(request)가 true이면 통과시키세요.

import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.CorsRegistry;

// 브라우저 화면(브라우저)이 다른 출처에서 /api/**를 부를 수 있게 CORS를 연다(1-1 "CORS 열기").
@Configuration
public class CorsConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
                .allowedOriginPatterns("http://localhost:[*]", "http://127.0.0.1:[*]")
                .allowedMethods("GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS")
                .allowedHeaders("Content-Type", "Authorization", "X-Client")
                .exposedHeaders("Location", "WWW-Authenticate");
    }
}

힌트 4 — CORS 설정 코드

브라우저가 학습 화면에서 API 서버를 호출할 수 있도록 org.example 아래 설정 클래스를 둡니다.
org.example.config.CorsConfigSpring MVC 설정
package org.example.config;

import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.CorsRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class CorsConfig implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
            .allowedOriginPatterns("http://localhost:[*]", "http://127.0.0.1:[*]")
            .allowedMethods("GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS")
            .allowedHeaders("Content-Type", "Authorization", "X-Client")
            .exposedHeaders("Location", "WWW-Authenticate");
    }
}
경로/api/**
허용 출처 패턴http://localhost:[*]http://127.0.0.1:[*]
허용 메서드GET · POST · PUT · PATCH · DELETE · OPTIONS
허용 요청 헤더Content-Type · Authorization · X-Client
브라우저에 노출할 응답 헤더Location · WWW-Authenticate
적용할 때 확인하세요allowedOrigins("*")로 모두 열지 않습니다. 0장에서 만든 설정이 있다면 X-Client 허용을 포함해 유지하세요. 코드를 수정한 뒤에는 앱을 다시 띄워 반영합니다.
