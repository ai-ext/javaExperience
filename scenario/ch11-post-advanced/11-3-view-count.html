#상황

"인기글 순위를 조회수로 매기려는데, 글쓴이가 새로고침을 연타하면 조회수가 수십씩 올라가요. 같은 사람이 하루에 여러 번 봐도 한 번으로 쳐 주세요. 자기 글은 아예 세지 말고요."

지금 상세 조회(GET /api/posts/{id})는 열 때마다 view_count를 1 올린다(2-1). "누가 봤는지"를 기억하지 않으니 같은 사람의 새로고침도 전부 1씩이다.

"누가 언제 봤나"를 기록하는 표를 하나 만들고, 그 표에 오늘 처음 행이 생길 때만 조회수를 올린다. 같은 회원·같은 글·같은 날짜는 한 행만 있을 수 있게 키를 걸어 두면, "처음인가?"는 그 행이 새로 생겼는지로 판단할 수 있다.

#화면 시나리오

사용자가 화면에서 무엇을 하면 어떤 요청이 서버로 가고, 서버·DB에서 무슨 일이 일어나 어떤 응답이 돌아와 화면이 어떻게 바뀌는지다. 흐름을 펼치면 사용자 행동부터 응답까지 차례대로 볼 수 있다.

#구현 가이드

화면 시나리오의 서버·DB 흐름을 이 단계에서 바뀐 파일에 연결한다. 먼저 만들 것의 계약대로 직접 작성하고, 필요한 역할만 펼쳐 파일 전문과 비교한다.

이 단계의 처리 흐름:

  • 볼 수 있나(2-3) → 작성자 본인인가(아니다) → 오늘 본 기록을 넣어 본다
  • 기록이 새로 생겼으니 +1
  • 새로 생긴 행이 없으니 UPDATE를 하지 않는다
  • 보는 사람 = 작성자 → 기록도, +1도 하지 않는다

Service — 처리 순서

PostQueryService.java. 위 서버 처리 순서가 어디에서 검증·조회·상태 변경으로 이어지는지 따라간다. 트랜잭션 경계는 아래 코드의 @Transactional 위치에서 확인한다.

@Transactional
public PostDetailResponse getDetail(Long id, AuthenticatedMember viewer) {
    Post post = postRepository.findByIdForUpdate(id).orElseThrow(PostNotFoundException::new);
    if (!accessPolicy.canView(viewer, post)) throw new PostNotFoundException();
    if (shouldCountView(viewer, post)) {
        postRepository.incrementViewCount(id);
    }
    int viewCount = postRepository.findViewCountById(id); // 벌크 UPDATE는 관리 엔티티 값을 갱신하지 않는다
    return toDetailResponse(post, viewCount);
}

private boolean shouldCountView(AuthenticatedMember viewer, Post post) {
    if (viewer == null) return true;
    if (viewer.id().equals(post.getAuthor().getId())) return false;
    LocalDateTime now = LocalDateTime.now(clock);
    return postViewRepository.insertIfAbsent(post.getId(), viewer.id(), now.toLocalDate(), now) == 1;
}
JPA / Repository — DB 조건

PostRepository.java, PostViewRepository.java. 쿼리·파생 메서드의 조건을 화면 시나리오의 DB 단계 및 직접 확인 SQL과 대조한다. 직접 작성한 JPQL·SQL과 아래 파일의 @Query를 비교한다.

PostRepository.findByIdForUpdate(11-1에서 추가)를 접근 권한 검사와 조회 기록 INSERT 전에 사용한다. 글 행을 먼저 잠그지 않으면, 같은 회원의 동시 첫 조회에서 FK가 잡은 글의 공유 잠금과 조회 기록 PK 잠금이 서로 맞물려 교착이 날 수 있다. 삭제나 공개 범위 변경과 경합해도 잠금 이후의 상태로 404 여부를 결정한다.

MyBatis 대체 코드는 글 행 잠금, post_view 조건부 INSERT, 글의 view_count 원자적 증가, 증가 후 조회를 Mapper로 수행한다. 선행 글 조회·권한·DTO는 JPA 경로를 유지하며, SQL은 같은 트랜잭션 안에서 실행된다. 잠금을 먼저 잡아 동시 첫 조회 때 InnoDB의 글 FK 잠금과 조회 기록 PK 잠금이 서로 기다리는 교착을 막는다.

    if (!accessPolicy.canView(viewer, post)) {

@Transactional(readOnly = true)
public List&lt;PostHeadlineResponse&gt; listPublicByAuthor(Long memberId, String boardSlug) {
    if (!memberRepository.existsById(memberId)) {
        throw new ResponseStatusException(HttpStatus.NOT_FOUND, &quot;회원을 찾을 수 없습니다.&quot;);
    }
    boardRepository.findBySlug(boardSlug)
            .orElseThrow(() -&gt; new BoardNotFoundException(boardSlug));
    return postRepository.findPublicPostsByAuthorAndBoard(memberId, boardSlug).stream()
            .map(post -&gt; new PostHeadlineResponse(
                    post.getId(), post.getTitle(),
                    post.getAuthor().getNickname(), boardSlug))
            .toList();

@Transactional
public PostDetailResponse getDetail(Long id, AuthenticatedMember viewer) {
    // 접근 권한도 잠금 이후의 최신 상태로 판단한다(삭제·공개 범위 변경과의 경합).
    if (myPostViewMapper.lockPost(id) == null) {
        throw new PostNotFoundException();
    }
    Post post = postRepository.findById(id)
            .orElseThrow(PostNotFoundException::new);

    // 볼 수 없으면 403이 아니라 404 — 글이 있다는 사실도 숨긴다. 조회수도 올리지 않는다.
    if (!accessPolicy.canView(viewer, post)) {
        throw new PostNotFoundException();
    }

    // post_view INSERT와 post 카운터 UPDATE의 잠금 순서는 위 글 행 잠금으로 고정된다.
    if (shouldCountView(viewer, post)) {
        myPostViewMapper.incrementViewCount(id);
    }
    int viewCount = myPostViewMapper.findViewCountById(id);
    return toDetailResponse(post, viewCount);
}

// 로그인 회원은 그 글을 오늘 처음 볼 때만(post_view에 오늘 행이 새로 생겼을 때만) 센다.
private boolean shouldCountView(AuthenticatedMember viewer, Post post) {
    if (viewer == null) {
        return true;
    }
    if (viewer.id().equals(post.getAuthor().getId())) {
        return false;
    }
    LocalDateTime now = LocalDateTime.now(clock);
    return myPostViewMapper.insertIfAbsent(post.getId(), viewer.id(), now.toLocalDate(), now) == 1;
}

@Transactional(readOnly = true)
public PostListResponse search(String boardSlug, String tag, Long authorId, LocalDate from, LocalDate to,
                               String q, int page, int size, AuthenticatedMember viewer) {
    if (from != null &amp;&amp; to != null &amp;&amp; from.isAfter(to)) {
        throw new InvalidSearchConditionException(&quot;from이 to보다 늦을 수 없습니다.&quot;);
    }
    PageRequest pageRequest = PageRequest.of(page, size);
    Long boardId = null;
    if (boardSlug != null &amp;&amp; !boardSlug.isBlank()) {
        Board board = boardRepository.findBySlug(boardSlug).orElse(null);
        if (board == null) {
            return toListResponse(Page.empty(pageRequest));
        }
        boardId = board.getId();
    }
    PostSearchCondition condition = new PostSearchCondition(boardId, tag, authorId, from, to, q);
    return toListResponse(postSearchRepository.search(condition, viewerIdOf(viewer), pageRequest));
}

private PostListResponse toListResponse(Page&lt;PostListRow&gt; result) {
    List&lt;Long&gt; ids = result.getContent().stream().map(PostListRow::id).toList();
    Map&lt;Long, List&lt;String&gt;&gt; tags = postSearchRepository.findTagsByPostIds(ids).stream()
            .collect(Collectors.groupingBy(PostTagRow::postId,
                    Collectors.mapping(PostTagRow::name, Collectors.toList())));
    List&lt;PostListItemResponse&gt; items = result.getContent().stream()
            .map(row -&gt; toListItem(row, tags.getOrDefault(row.id(), List.of())))
            .toList();
    return new PostListResponse(
            items,
            result.getNumber(),
            result.getSize(),
            result.getTotalElements(),
            result.getTotalPages(),
            (long) result.getNumber() * result.getSize() + items.size() &lt; result.getTotalElements()
    );
}

private Long viewerIdOf(AuthenticatedMember viewer) {
    return viewer == null ? null : viewer.id();
}

R2
올린 뒤의 값
UPDATE … SET view_count = view_count + 1(벌크 UPDATE)은 이미 읽어 둔 엔티티를 바꾸지 않는다. REPEATABLE READ의 오래된 읽기 스냅샷도 피하려고 SELECT view_count ... FOR UPDATE로 현재 값을 읽는다




R3
옛 방식 정리

R4
날짜 기준

R5
