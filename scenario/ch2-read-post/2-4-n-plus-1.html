#상황

목록 API를 호출하고 SQL 로그(org.hibernate.SQL: debug)를 보면 글 목록을 한 번 가져온 뒤 글마다 작성자 조회·태그 조회가 따로 나간다. 20개를 보여 주면 40번 넘게 DB에 다녀온다. 사용자가 늘면 DB가 먼저 버티지 못한다.

응답은 그대로 두고, 한 번 호출에 나가는 SQL 수를 페이지 크기와 상관없이 일정하게 만든다. 그리고 그 사실을 테스트로 고정한다(다시 늘어나면 테스트가 깨지게).

#화면 시나리오

사용자가 화면에서 무엇을 하면 어떤 요청이 서버로 가고, 서버·DB에서 무슨 일이 일어나 어떤 응답이 돌아와 화면이 어떻게 바뀌는지다. 흐름을 펼치면 사용자 행동부터 응답까지 차례대로 볼 수 있다.

목록 화면 뒤의 SQL

화면은 같아도 서버 로그를 보면 글마다 쿼리가 따로 나간다. 사용자가 늘면 DB가 먼저 지친다.

자유 게시판
list자유글 10 · 자유글 09 · 자유글 08 · 자유글 07 · 자유글 06

#만들 것

  1. 2-3의 게시판 목록 API를 고쳐 SQL 문장 수를 줄인다.
    • 기준: size=20의 문장 수가 size=5보다 많지 않고(글 수에 비례해 늘지 않는다), 둘 다 5개 이하다(목록·건수·태그 등).
    • 참고: Spring Data의 Page는 가져온 글이 size보다 적으면(마지막 페이지) 건수 쿼리를 생략한다. 자유 게시판은 13개라 size=20이 한 문장 적게 나올 수 있다 — 정상이다.
    • 보는 사람 확인용 서브쿼리는 목록 쿼리 안에 들어가므로 따로 세지 않는다.
  2. 테스트 클래스 PostListQueryCountTest 를 만든다(이름 그대로 — 채점에서 이 이름으로 실행한다).
    • @SpringBootTest + MockMvc로 GET /api/boards/free/posts?size=5와 size=20을 호출한다.
    • Hibernate가 실행한 SQL 문장 수를 세서 위 기준을 단언한다.
    • 테스트 DB에는 시나리오 데이터(free 게시판 글 13~14개)가 이미 들어 있다.

응답 JSON은 2-3과 완전히 같아야 한다.

MyBatis — 페이지 크기가 늘어도 SELECT 수를 고정하기

아래 MyBatis 대체 구현 코드의 11개 파일을 이 단계 전체 소스에 적용한다. 2-3의 조회 권한 조건은 PostVisibilityMapper.xml의 목록·COUNT 공통 조건으로 유지한다. 목록 SQL에서 작성자를 JOIN해 한 번에 읽고, 페이지에 나온 글 ID를 모아 post_tag·tag를 IN 쿼리 한 번으로 읽는다. Mapper 실행 순서는 게시판 ID, 목록, COUNT, 태그로 페이지 크기와 관계없이 SELECT 4개다. 글마다 작성자·태그를 다시 읽는 N+1 루프는 없다.

기본 JPA 테스트의 Hibernate Statistics는 MyBatis SQL을 세지 못한다. 대체 코드의 MyBatisStatementCounter는 MyBatis Executor.query를 가로채 요청 스레드의 SELECT 호출 수를 세고, PostListQueryCountTest가 size=5와 size=20에서 실제로 0보다 큰 수인지, 두 수가 같은지, 5개 이하인지 검사한다. 격리 테스트 DB에서는 두 크기 모두 4개였다. JPA·MyBatis 양쪽의 C1 응답과 2-3 접근 조건도 대조한다.

package org.example.post;


import org.example.auth.AuthenticatedMember;
import org.example.board.Board;
import org.example.board.BoardNotFoundException;
import org.example.board.BoardRepository;
import org.example.tag.Tag;
import org.springframework.data.domain.Page;
import org.springframework.data.domain.PageImpl;
import org.springframework.data.domain.PageRequest;
import org.springframework.data.domain.Sort;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;


import java.util.List;


// 글 조회 전용 서비스 — 1-3/1-4의 PostService(쓰기)와 책임을 나눈다
@Service
public class PostQueryService {


private final PostRepository postRepository;
private final BoardRepository boardRepository;
private final PostAccessPolicy accessPolicy;

public PostQueryService(PostRepository postRepository, BoardRepository boardRepository,
                         PostAccessPolicy accessPolicy) {
    this.postRepository = postRepository;
    this.boardRepository = boardRepository;
    this.accessPolicy = accessPolicy;
}

@Transactional
public PostDetailResponse getDetail(Long id, AuthenticatedMember viewer) {
    Post post = postRepository.findById(id)
            .orElseThrow(PostNotFoundException::new);

    // 볼 수 없으면 403이 아니라 404 — 글이 있다는 사실도 숨긴다. 조회수도 올리지 않는다.
    if (!accessPolicy.canView(viewer, post)) {
        throw new PostNotFoundException();
    }

    post.increaseViewCount();
    return toDetailResponse(post);
}

@Transactional(readOnly = true)
public PostListResponse list(String boardSlug, int page, int size, AuthenticatedMember viewer) {
    Board board = boardRepository.findBySlug(boardSlug)
            .orElseThrow(() -&gt; new BoardNotFoundException(boardSlug));

    Long viewerId = viewer == null ? null : viewer.id();

    PageRequest pageRequest = PageRequest.of(page, size,
            Sort.by(Sort.Order.desc(&quot;publishedAt&quot;), Sort.Order.desc(&quot;id&quot;)));
    List&lt;Post&gt; content = postRepository.findViewableByBoard(board, viewerId, pageRequest);
    long total = postRepository.countViewableByBoard(board, viewerId);
    Page&lt;Post&gt; result = new PageImpl&lt;&gt;(content, pageRequest, total);

    List&lt;PostListItemResponse&gt; items = result.getContent().stream()
            .map(this::toListItem)
            .toList();

    return new PostListResponse(
            items,
            result.getNumber(),
            result.getSize(),
            result.getTotalElements(),
            result.getTotalPages(),
            result.hasNext()
    );
}

private PostListItemResponse toListItem(Post post) {
    return new PostListItemResponse(
            post.getId(),
            post.getTitle(),
            new AuthorResponse(post.getAuthor().getId(), post.getAuthor().getNickname()),
            post.getTags().stream().map(Tag::getName).toList(),
            post.getLikeCount(),
            post.getCommentCount(),
            post.getViewCount(),
            post.getPublishedAt()
    );
}

private PostDetailResponse toDetailResponse(Post post) {
    // 트랜잭션 안에서 지연 로딩 연관을 읽어 DTO로 옮긴다(open-in-view: false)
    return new PostDetailResponse(
            post.getId(),
            post.getBoard().getSlug(),
            post.getTitle(),
            post.getContent(),
            post.getTags().stream().map(Tag::getName).toList(),
            post.getVisibility(),
            new AuthorResponse(post.getAuthor().getId(), post.getAuthor().getNickname()),
            post.getViewCount(),
            post.getLikeCount(),
            post.getCommentCount(),
            post.getCreatedAt()
    );
}


}

package org.example.post;


import org.example.board.Board;
import org.springframework.data.domain.Pageable;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;


import java.util.List;


// Spring Data JPA가 구현을 만들어 준다(1-3의 메모리 구현을 대체)
public interface PostRepository extends JpaRepository<Post, Long> {


// 2-3의 &quot;볼 수 있나&quot; 규칙 중 목록에 해당하는 부분을 쿼리로 옮긴 것 — PostAccessPolicy.canView와
// 같은 규칙이지만, 목록은 PUBLISHED 글만 대상이다(자기 임시저장·운영자 숨김 글도 목록에는 넣지 않는다).
// 메모리에서 거르지 않고 쿼리에서 걸러야 페이지 크기·totalElements가 맞는다.
//
// Page&lt;Post&gt; 대신 List&lt;Post&gt; + 아래 countViewableByBoard를 따로 둔다: Page&lt;&gt;로 받으면
// Spring Data가 &quot;content 개수 &lt; size면 count 쿼리를 생략&quot;하는 최적화를 적용해서, size=5(꽉 찬
// 페이지, count 쿼리 나감)와 size=20(13개뿐이라 마지막 페이지, count 쿼리 생략)의 SQL 문장 수가
// 13과1씩 달라졌다(2-4의 PostListQueryCountTest가 요구하는 &quot;size와 무관하게 문장 수 동일&quot;이 깨짐).
// count를 항상 명시적으로 실행해 문장 수를 size와 무관하게 고정한다(R2와도 맞다).
@Query(&quot;&quot;&quot;
        SELECT p FROM Post p
        JOIN FETCH p.author
        WHERE p.board = :board
          AND p.deletedAt IS NULL
          AND p.status = 'PUBLISHED'
          AND (
               p.visibility = 'PUBLIC'
               OR (:viewerId IS NOT NULL AND p.author.id = :viewerId)
               OR (:viewerId IS NOT NULL AND EXISTS (
                       SELECT 1 FROM Follow f
                       WHERE f.follower.id = :viewerId AND f.followee = p.author))
          )
          AND (
               :viewerId IS NULL OR NOT EXISTS (
                   SELECT 1 FROM MemberBlock b
                   WHERE (b.blocker.id = :viewerId AND b.blocked = p.author)
                      OR (b.blocked.id = :viewerId AND b.blocker = p.author)
               )
          )
        &quot;&quot;&quot;)
List&lt;Post&gt; findViewableByBoard(@Param(&quot;board&quot;) Board board,
                                @Param(&quot;viewerId&quot;) Long viewerId,
                                Pageable pageable);

// findViewableByBoard와 같은 조건의 건수 — 반드시 같이 고친다
@Query(&quot;&quot;&quot;
        SELECT COUNT(p) FROM Post p
        WHERE p.board = :board
          AND p.deletedAt IS NULL
          AND p.status = 'PUBLISHED'
          AND (
               p.visibility = 'PUBLIC'
               OR (:viewerId IS NOT NULL AND p.author.id = :viewerId)
               OR (:viewerId IS NOT NULL AND EXISTS (
                       SELECT 1 FROM Follow f
                       WHERE f.follower.id = :viewerId AND f.followee = p.author))
          )
          AND (
               :viewerId IS NULL OR NOT EXISTS (
                   SELECT 1 FROM MemberBlock b
                   WHERE (b.blocker.id = :viewerId AND b.blocked = p.author)
                      OR (b.blocked.id = :viewerId AND b.blocker = p.author)
               )
          )
        &quot;&quot;&quot;)
long countViewableByBoard(@Param(&quot;board&quot;) Board board, @Param(&quot;viewerId&quot;) Long viewerId);


}

package org.example.post;


import jakarta.persistence.EntityManagerFactory;
import org.hibernate.SessionFactory;
import org.hibernate.stat.Statistics;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.boot.webmvc.test.autoconfigure.AutoConfigureMockMvc;
import org.springframework.test.web.servlet.MockMvc;


import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertTrue;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;


// 2-4: 페이지 크기와 상관없이 목록 조회의 SQL 문장 수가 일정한지(N+1이 없는지) 고정한다.
// generate_statistics=true는 application-test.yml(공용 설정)에 있다 — 테스트별로 따로 켜면
// Spring이 별도 컨텍스트를 만들어 같은 Testcontainers 컨테이너의 스키마를 두 번 초기화하려다 깨진다.
@SpringBootTest
@AutoConfigureMockMvc
class PostListQueryCountTest {


@Autowired
MockMvc mockMvc;

@Autowired
EntityManagerFactory entityManagerFactory;

@Test
void queryCountIsSameRegardlessOfPageSizeAndBounded() throws Exception {
    Statistics statistics = entityManagerFactory.unwrap(SessionFactory.class).getStatistics();

    statistics.clear();
    mockMvc.perform(get(&quot;/api/boards/free/posts&quot;).param(&quot;size&quot;, &quot;5&quot;))
            .andExpect(status().isOk());
    long countForSize5 = statistics.getPrepareStatementCount();

    statistics.clear();
    mockMvc.perform(get(&quot;/api/boards/free/posts&quot;).param(&quot;size&quot;, &quot;20&quot;))
            .andExpect(status().isOk());
    long countForSize20 = statistics.getPrepareStatementCount();

    assertTrue(countForSize5 &gt; 0, &quot;Hibernate SQL 계측이 실제로 켜져 있어야 한다&quot;);
    assertEquals(countForSize5, countForSize20,
            &quot;size=5와 size=20의 SQL 문장 수가 같아야 한다(N+1이면 글 수만큼 늘어난다)&quot;);
    assertTrue(countForSize5 &lt;= 5,
            &quot;SQL 문장 수는 5개 이하여야 한다(실제: &quot; + countForSize5 + &quot;)&quot;);
}


}

package org.example.post;


import org.example.auth.AuthenticatedMember;
import org.example.board.BoardNotFoundException;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;


import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;


// 글 조회 전용 서비스 — 1-3/1-4의 PostService(쓰기)와 책임을 나눈다
@Service
public class PostQueryService {


private final PostVisibilityMapper mapper;

public PostQueryService(PostVisibilityMapper mapper) {
    this.mapper = mapper;
}

@Transactional
public PostDetailResponse getDetail(Long id, AuthenticatedMember viewer) {
    Long viewerId = viewer == null ? null : viewer.id();
    String viewerRole = viewer == null ? null : viewer.role();
    // SQL에서 권한을 먼저 걸러 404일 때 조회수가 변하지 않게 한다.
    PostDetailRow row = mapper.findVisibleDetail(id, viewerId, viewerRole);
    if (row == null) {
        throw new PostNotFoundException();
    }
    mapper.increaseViewCount(id);
    List&lt;String&gt; tags = mapper.findTagsByPostIds(List.of(id)).stream()
            .map(PostTagRow::name).toList();
    return new PostDetailResponse(row.id, row.boardSlug, row.title, row.content,
            tags, row.visibility, new AuthorResponse(row.authorId, row.authorNickname),
            row.viewCount + 1, row.likeCount, row.commentCount, row.createdAt);
}

@Transactional(readOnly = true)
public PostListResponse list(String boardSlug, int page, int size, AuthenticatedMember viewer) {
    Long boardId = mapper.findBoardIdBySlug(boardSlug);
    if (boardId == null) throw new BoardNotFoundException(boardSlug);

    Long viewerId = viewer == null ? null : viewer.id();

    long offset = (long) page * size;
    List&lt;PostListRow&gt; rows = mapper.findViewableByBoard(boardId, viewerId, size, offset);
    long total = mapper.countViewableByBoard(boardId, viewerId);
    Map&lt;Long, List&lt;String&gt;&gt; tags = rows.isEmpty() ? Map.of()
            : mapper.findTagsByPostIds(rows.stream().map(row -&gt; row.id).toList()).stream()
                .collect(Collectors.groupingBy(PostTagRow::postId,
                        Collectors.mapping(PostTagRow::name, Collectors.toList())));
    List&lt;PostListItemResponse&gt; items = rows.stream()
            .map(row -&gt; toListItem(row, tags.getOrDefault(row.id, List.of()))).toList();

    return new PostListResponse(
            items,
            page,
            size,
            total,
            (int) ((total + size - 1) / size),
            offset + rows.size() &lt; total
    );
}

private PostListItemResponse toListItem(PostListRow row, List&lt;String&gt; tags) {
    return new PostListItemResponse(
            row.id,
            row.title,
            new AuthorResponse(row.authorId, row.authorNickname),
            tags,
            row.likeCount,
            row.commentCount,
            row.viewCount,
            row.publishedAt
    );
}


}

package org.example.post;


import org.apache.ibatis.executor.Executor;
import org.apache.ibatis.mapping.MappedStatement;
import org.apache.ibatis.plugin.Interceptor;
import org.apache.ibatis.plugin.Intercepts;
import org.apache.ibatis.plugin.Invocation;
import org.apache.ibatis.plugin.Signature;
import org.apache.ibatis.session.ResultHandler;
import org.apache.ibatis.session.RowBounds;
import org.springframework.stereotype.Component;


// 테스트 중 Mapper가 실행한 SELECT 문장 수를 요청 스레드별로 센다.
@Component
@Intercepts(@Signature(type = Executor.class, method = "query",
        args = {MappedStatement.class, Object.class, RowBounds.class, ResultHandler.class}))
public class MyBatisStatementCounter implements Interceptor {
    private final ThreadLocal<Long> count = ThreadLocal.withInitial(() -> 0L);


@Override
public Object intercept(Invocation invocation) throws Throwable {
    count.set(count.get() + 1);
    return invocation.proceed();
}

public void clear() { count.set(0L); }
public long getCount() { return count.get(); }


}

#힌트 (막힐 때만)



힌트 1 — SQL 세기


src/test/resources/application-test.yml에 spring.jpa.properties.hibernate.generate_statistics: true를 켠다. 테스트 클래스에 @TestPropertySource로 따로 켜면 스프링 컨텍스트가 하나 더 생기고, 같은 테스트 DB에 스키마 초기화가 다시 돌아 "Table already exists"로 실패한다. 그다음 EntityManagerFactory를 주입받아 emf.unwrap(SessionFactory.class).getStatistics()를 얻는다. 호출 직전 statistics.clear(), 호출 뒤 statistics.getPrepareStatementCount().






힌트 2 — 가장 쉬운 해결


작성자(@ManyToOne)는 목록 쿼리에 join fetch로 붙이고, 태그(컬렉션)는 spring.jpa.properties.hibernate.default_batch_fetch_size: 100으로 IN 쿼리 한 번에 가져오게 한다. 태그를 fetch join하면 페이징이 메모리에서 일어난다.
