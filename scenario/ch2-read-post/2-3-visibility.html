#만들 것

누가 보는가 — 조회 API는 토큰이 없어도 된다.

요청 보는 사람
Authorization 헤더 없음 비로그인
올바른 토큰 그 토큰의 회원
헤더는 있는데 잘못된·만료·폐기 토큰 401(비로그인으로 취급하지 않는다)

볼 수 있나 (보는 사람 v, 글 p) — 아래를 모두 만족해야 볼 수 있다.

  1. 삭제된 글(deleted_at 있음)이 아니다 — 작성자 본인도 못 본다.
  2. status가 PUBLISHED이다. 단, DRAFT(임시저장)는 작성자만, HIDDEN(운영자 숨김)은 운영자(ADMIN)만 볼 수 있다.
  3. visibility가 FOLLOWERS면 작성자 본인이거나 작성자를 팔로우하는 회원이어야 한다.
  4. v와 작성자 사이에 차단이 없다(어느 쪽이 차단했든).
  5. 비로그인은 PUBLISHED + PUBLIC만 볼 수 있다.
화면 적용
상세 GET /api/posts/{id} 볼 수 없으면 404. 403이 아니다 — 글이 있다는 사실도 숨긴다. 404일 때 조회수는 오르지 않는다
목록 GET /api/boards/{slug}/posts 볼 수 있는 PUBLISHED 글만. 자기 임시저장 글도 목록에는 넣지 않는다. totalElements도 이 기준

사진에서 말한 isHide는 이 실습 DB에서는 별도 boolean이 아니라 post.status = 'HIDDEN'이다. deleted_at은 삭제 시각이고, 숨김은 운영 조치다. 둘은 같은 조건으로 다루지 않는다.

글 일반 사용자 상세 운영자 상세 게시판 목록

#구현 가이드

먼저 id 조회가 어떤 행을 돌려주는지 확인하고, 상세와 목록에서 필요한 조건을 각각 적용한다. 접기를 열어 한 역할씩 구현한다.

Controller — 비로그인 조회와 선택적 회원 
@GetMapping("/api/posts/{id}")
public PostDetailResponse detail(@PathVariable Long id,
                                 @RequestAttribute(required = false) AuthenticatedMember viewer) {
    return postQueryService.getDetail(id, viewer);

토큰이 없으면 viewer == null이다. 잘못된 토큰은 인증 인터셉터에서 401로 끝내고 이 메서드까지 보내지 않는다. 상세 DTO에는 deletedAt이나 숨김 기록을 일반 사용자에게 노출하지 않는다.

Service — 상세 조회 뒤 접근 규칙 적용 
@Transactional
public PostDetailResponse getDetail(Long id, AuthenticatedMember viewer) {
    Post post = postRepository.findById(id)
            .orElseThrow(PostNotFoundException::new);
    if (!postAccessPolicy.canView(viewer, post)) {
        throw new PostNotFoundException(); // 존재 여부도 숨긴다
    }
    post.increaseViewCount(); // 404일 때는 실행하지 않는다
    return toDetailResponse(post);
}

findById 다음에 정책을 적용하는 방식은 상세에 쓸 수 있다. 목록에서는 페이지를 읽고 Java에서 거르면 items 개수와 totalElements가 틀어지므로 DB 쿼리에 조건을 넣는다.

JPA / Repository — findById와 조건 조회의 차이

JpaRepository.findById(id)는 삭제·숨김 필터를 자동으로 넣지 않는다. 삭제된 행을 일반 경로에서 아예 가져오지 않으려면 파생 메서드로 시작할 수 있다.

Optional<Post> findByIdAndDeletedAtIsNull(Long id);

하지만 findByIdAndDeletedAtIsNullAndStatusNot(id, "HIDDEN")만으로 전체 접근 규칙이 되지는 않는다. 임시저장 작성자, 팔로워, 상호 차단, 운영자의 숨김 글 열람이 남는다. 상세는 위 Service처럼 정책을 적용하고, 게시판 목록 쿼리는 다음 공통 조건에서 시작한다.

@Query("""
    SELECT p FROM Post p JOIN FETCH p.author
    WHERE p.board = :board AND p.deletedAt IS NULL
      AND p.status = 'PUBLISHED'
      AND (p.visibility = 'PUBLIC'
           OR (:viewerId IS NOT NULL AND p.author.id = :viewerId)
           OR (:viewerId IS NOT NULL AND EXISTS (
               SELECT 1 FROM Follow f
               WHERE f.follower.id = :viewerId AND f.followee = p.author)))
      AND (:viewerId IS NULL OR NOT EXISTS (
          SELECT 1 FROM MemberBlock b
          WHERE (b.blocker.id = :viewerId AND b.blocked = p.author)
             OR (b.blocked.id = :viewerId AND b.blocker = p.author)))
    ORDER BY p.publishedAt DESC, p.id DESC
    """)
List<Post> findViewableByBoard(@Param("board") Board board,
                               @Param("viewerId") Long viewerId, Pageable pageable);

@Query("""
    SELECT COUNT(p) FROM Post p
    WHERE p.board = :board AND p.deletedAt IS NULL
      AND p.status = 'PUBLISHED'
      AND (p.visibility = 'PUBLIC'
           OR (:viewerId IS NOT NULL AND p.author.id = :viewerId)
           OR (:viewerId IS NOT NULL AND EXISTS (
               SELECT 1 FROM Follow f
               WHERE f.follower.id = :viewerId AND f.followee = p.author)))
      AND (:viewerId IS NULL OR NOT EXISTS (
          SELECT 1 FROM MemberBlock b
          WHERE (b.blocker.id = :viewerId AND b.blocked = p.author)
             OR (b.blocked.id = :viewerId AND b.blocker = p.author)))
    """)
long countViewableByBoard(@Param("board") Board board, @Param("viewerId") Long viewerId);

목록과 COUNT의 WHERE가 한 글자라도 다르게 진화하면 화면의 totalElements가 어긋난다. 차단 조건은 양방향이고, :viewerId IS NULL일 때는 비로그인 공개 글을 통과시킨다. Pageable의 정렬을 쓰거나 JPQL의 ORDER BY를 쓰되, 최종 순서는 publishedAt DESC, id DESC다. 접근 규칙 강의와 채점 R1·R2를 대조한다.

SQL / MyBatis — 조건을 WHERE에 놓기

먼저 DB에서 두 조건의 차이를 직접 본다. id=8은 삭제, id=10은 운영자 숨김 시드다.

SELECT id, status, deleted_at FROM post WHERE id IN (8, 10);
SELECT id FROM post WHERE id IN (8, 10) AND deleted_at IS NULL;
SELECT id FROM post WHERE id IN (8, 10)
  AND deleted_at IS NULL AND status = 'PUBLISHED';

첫 쿼리는 둘 다, 둘째는 숨김 10번만, 셋째는 둘 다 제외한다. MyBatis에서도 공개 목록의 WHERE에 p.deleted_at IS NULL AND p.status = 'PUBLISHED'를 넣는다. 이것만으로는 팔로워·차단 조건이 완성되지 않으므로 JPA 목록과 동일한 규칙을 추가하고, COUNT 쿼리에도 복사한다.

비로그인 상세의 첫 MyBatis 메서드는 이처럼 작성할 수 있다. 이 메서드는 익명 공개 글 전용이므로 로그인 회원의 임시저장·팔로워·숨김 권한 판정까지 대신하지 않는다.

@Mapper
public interface PublicPostMapper {
    Long findAnonymousVisibleId(@Param("id") Long id);
}
<mapper namespace="org.example.post.PublicPostMapper">
  <select id="findAnonymousVisibleId" resultType="long">

위 코드는 익명 조회의 첫 예시다. 아래 MyBatis 대체 구현 코드 접기에는 로그인·팔로우·양방향 차단·운영자 숨김·목록 COUNT까지 적용한 Mapper·XML·Service·조회 DTO의 파일 전문이 있다.

package org.example.post;


import org.example.auth.AuthenticatedMember;
import org.example.social.FollowRepository;
import org.example.social.MemberBlockRepository;
import org.springframework.stereotype.Component;


// "이 사람이 이 글을 볼 수 있나" 규칙을 한 곳에 모은다.
// 상세(GET /api/posts/{id})는 이 자바 코드로 판정하고, 목록(게시판 목록)은
// 같은 다섯 조건을 PostRepository의 JPQL(findViewableByBoard)로 옮겨 건다.
// 규칙을 바꿀 때는 두 곳을 같이 고쳐야 한다.
@Component
public class PostAccessPolicy {


private static final String PUBLISHED = &quot;PUBLISHED&quot;;
private static final String DRAFT = &quot;DRAFT&quot;;
private static final String HIDDEN = &quot;HIDDEN&quot;;
private static final String PUBLIC = &quot;PUBLIC&quot;;
private static final String FOLLOWERS = &quot;FOLLOWERS&quot;;
private static final String ADMIN_ROLE = &quot;ADMIN&quot;;

private final FollowRepository followRepository;
private final MemberBlockRepository memberBlockRepository;

public PostAccessPolicy(FollowRepository followRepository, MemberBlockRepository memberBlockRepository) {
    this.followRepository = followRepository;
    this.memberBlockRepository = memberBlockRepository;
}

public boolean canView(AuthenticatedMember viewer, Post post) {
    // 1. 삭제된 글은 작성자 본인도 못 본다
    if (post.getDeletedAt() != null) {
        return false;
    }

    Long viewerId = viewer == null ? null : viewer.id();
    Long authorId = post.getAuthor().getId();
    boolean isAuthor = viewerId != null &amp;&amp; viewerId.equals(authorId);
    boolean isAdmin = viewer != null &amp;&amp; ADMIN_ROLE.equals(viewer.role());

    // 2. 상태별 허용 — DRAFT는 작성자만, HIDDEN은 운영자만
    boolean statusOk = switch (post.getStatus()) {
        case PUBLISHED -&gt; true;
        case DRAFT -&gt; isAuthor;
        case HIDDEN -&gt; isAdmin;
        default -&gt; false;
    };
    if (!statusOk) {
        return false;
    }

    // 3. PUBLISHED + FOLLOWERS 공개는 작성자 본인이거나 팔로워만
    if (PUBLISHED.equals(post.getStatus()) &amp;&amp; FOLLOWERS.equals(post.getVisibility()) &amp;&amp; !isAuthor) {
        boolean follows = viewerId != null
                &amp;&amp; followRepository.existsByFollower_IdAndFollowee_Id(viewerId, authorId);
        if (!follows) {
            return false;
        }
    }

    // 4. 둘 사이에 차단이 있으면(어느 쪽이 차단했든) 못 본다
    if (viewerId != null &amp;&amp; !isAuthor &amp;&amp; isBlockedEitherWay(viewerId, authorId)) {
        return false;
    }

    // 5. 발행 글의 공개 범위가 알려진 값인지 검사한다.
    // 비로그인과 일반 열람자는 PUBLIC 또는 위에서 확인한 FOLLOWERS만 볼 수 있다.
    // DB에 PRIVATE/알 수 없는 값이 들어와도 공개로 취급하지 않는다.
    if (PUBLISHED.equals(post.getStatus()) &amp;&amp; !isAuthor
            &amp;&amp; !PUBLIC.equals(post.getVisibility())
            &amp;&amp; !FOLLOWERS.equals(post.getVisibility())) {
        return false;
    }
    return true;
}

private boolean isBlockedEitherWay(Long a, Long b) {
    return memberBlockRepository.existsByBlocker_IdAndBlocked_Id(a, b)
            || memberBlockRepository.existsByBlocker_IdAndBlocked_Id(b, a);
}


}

package org.example.post;


import jakarta.validation.Valid;
import org.example.auth.AuthenticatedMember;

import org.slf4j.Logger;

import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;

import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;


import java.net.URI;
import java.util.List;


@RestController
@RequestMapping("/api/posts")
public class PostController {


private static final Logger log = LoggerFactory.getLogger(PostController.class);

private final PostService postService;
private final PostQueryService postQueryService;

public PostController(PostService postService, PostQueryService postQueryService) {
    this.postService = postService;
    this.postQueryService = postQueryService;
}

@GetMapping(&quot;/{id}&quot;)
public PostDetailResponse getOne(@PathVariable Long id, @LoginMember AuthenticatedMember viewer) {
    return postQueryService.getDetail(id, viewer);
}

@PostMapping
public ResponseEntity&lt;PostResponse&gt; create(@LoginMember AuthenticatedMember loginMember,
                                            @Valid @RequestBody PostCreateRequest request) {
    log.info(&quot;게시글 작성 요청 제목: {}&quot;, request.title());

    Post post = postService.create(loginMember.id(), request);
    PostResponse response = toResponse(post);

    return ResponseEntity.created(URI.create(&quot;/api/posts/&quot; + post.getId())).body(response);
}

@PostMapping(&quot;/{sourceId}/copies&quot;)
public ResponseEntity&lt;PostResponse&gt; copy(@PathVariable Long sourceId,
                                         @RequestParam(defaultValue = &quot;false&quot;) boolean copyTags,
                                         @LoginMember AuthenticatedMember loginMember,
                                         @Valid @RequestBody CopyPostRequest request) {
    Post post = postService.copy(sourceId, loginMember.id(), copyTags, request);
    return ResponseEntity.created(URI.create(&quot;/api/posts/&quot; + post.getId()))
            .body(toResponse(post));
}

private PostResponse toResponse(Post post) {
    List&lt;String&gt; tagNames = post.getTags().stream().map(Tag::getName).toList();
    AuthorResponse author = new AuthorResponse(post.getAuthor().getId(), post.getAuthor().getNickname());
    return new PostResponse(
            post.getId(),
            post.getBoard().getSlug(),
            post.getTitle(),
            post.getContent(),
            tagNames,
            post.getVisibility(),
            author,
            post.getCreatedAt()
    );
}


}

@Service
public class PostQueryService {


private final PostRepository postRepository;
private final BoardRepository boardRepository;
private final PostAccessPolicy accessPolicy;

public PostQueryService(PostRepository postRepository, BoardRepository boardRepository,
                         PostAccessPolicy accessPolicy) {
    this.postRepository = postRepository;
    this.boardRepository = boardRepository;
    this.accessPolicy = accessPolicy;
}

@Transactional
public PostDetailResponse getDetail(Long id, AuthenticatedMember viewer) {
    Post post = postRepository.findById(id)
            .orElseThrow(PostNotFoundException::new);

    // 볼 수 없으면 403이 아니라 404 — 글이 있다는 사실도 숨긴다. 조회수도 올리지 않는다.
    if (!accessPolicy.canView(viewer, post)) {
        throw new PostNotFoundException();
    }

    post.increaseViewCount();
    return toDetailResponse(post);
}

@Transactional(readOnly = true)
public PostListResponse list(String boardSlug, int page, int size, AuthenticatedMember viewer) {
    Board board = boardRepository.findBySlug(boardSlug)
            .orElseThrow(() -&gt; new BoardNotFoundException(boardSlug));

    Long viewerId = viewer == null ? null : viewer.id();

    PageRequest pageRequest = PageRequest.of(page, size,
            Sort.by(Sort.Order.desc(&quot;publishedAt&quot;), Sort.Order.desc(&quot;id&quot;)));
    Page&lt;Post&gt; result = postRepository.findViewableByBoard(board, viewerId, pageRequest);

    List&lt;PostListItemResponse&gt; items = result.getContent().stream()
            .map(this::toListItem)
            .toList();

    return new PostListResponse(
            items,
            result.getNumber(),
            result.getSize(),
            result.getTotalElements(),
            result.getTotalPages(),
            result.hasNext()
    );
}

private PostListItemResponse toListItem(Post post) {
    return new PostListItemResponse(
            post.getId(),
            post.getTitle(),
            new AuthorResponse(post.getAuthor().getId(), post.getAuthor().getNickname()),
            post.getTags().stream().map(Tag::getName).toList(),
            post.getLikeCount(),
            post.getCommentCount(),
            post.getViewCount(),
            post.getPublishedAt()
    );
}

private PostDetailResponse toDetailResponse(Post post) {
    // 트랜잭션 안에서 지연 로딩 연관을 읽어 DTO로 옮긴다(open-in-view: false)

            post.getId(),
            post.getBoard().getSlug(),
            post.getTitle(),
            post.getContent(),
            post.getTags().stream().map(Tag::getName).toList(),
            post.getVisibility(),
            new AuthorResponse(post.getAuthor().getId(), post.getAuthor().getNickname()),
            post.getViewCount(),
            post.getLikeCount(),
            post.getCommentCount(),
            post.getCreatedAt()
    );
}

// 글 조회 전용 서비스 — 1-3/1-4의 PostService(쓰기)와 책임을 나눈다
@Service
public class PostQueryService {


private final PostVisibilityMapper mapper;

public PostQueryService(PostVisibilityMapper mapper) {
    this.mapper = mapper;
}

@Transactional
public PostDetailResponse getDetail(Long id, AuthenticatedMember viewer) {
    Long viewerId = viewer == null ? null : viewer.id();
    String viewerRole = viewer == null ? null : viewer.role();
    // SQL에서 권한을 먼저 걸러 404일 때 조회수가 변하지 않게 한다.
    PostDetailRow row = mapper.findVisibleDetail(id, viewerId, viewerRole);
    if (row == null) {
        throw new PostNotFoundException();
    }
    mapper.increaseViewCount(id);
    List&lt;String&gt; tags = mapper.findTagsByPostIds(List.of(id)).stream()
            .map(PostTagRow::name).toList();
    return new PostDetailResponse(row.id, row.boardSlug, row.title, row.content,
            tags, row.visibility, new AuthorResponse(row.authorId, row.authorNickname),
            row.viewCount + 1, row.likeCount, row.commentCount, row.createdAt);
}

@Transactional(readOnly = true)
public PostListResponse list(String boardSlug, int page, int size, AuthenticatedMember viewer) {
    Long boardId = mapper.findBoardIdBySlug(boardSlug);
    if (boardId == null) throw new BoardNotFoundException(boardSlug);

    Long viewerId = viewer == null ? null : viewer.id();

    long offset = (long) page * size;
    List&lt;PostListRow&gt; rows = mapper.findViewableByBoard(boardId, viewerId, size, offset);
    long total = mapper.countViewableByBoard(boardId, viewerId);
    Map&lt;Long, List&lt;String&gt;&gt; tags = rows.isEmpty() ? Map.of()
            : mapper.findTagsByPostIds(rows.stream().map(row -&gt; row.id).toList()).stream()
                .collect(Collectors.groupingBy(PostTagRow::postId,
                        Collectors.mapping(PostTagRow::name, Collectors.toList())));
    List&lt;PostListItemResponse&gt; items = rows.stream()
            .map(row -&gt; toListItem(row, tags.getOrDefault(row.id, List.of()))).toList();

    return new PostListResponse(
            items,
            page,
            size,
            total,
            (int) ((total + size - 1) / size),
            offset + rows.size() &lt; total
    );
}

private PostListItemResponse toListItem(PostListRow row, List&lt;String&gt; tags) {
    return new PostListItemResponse(
            row.id,
            row.title,
            new AuthorResponse(row.authorId, row.authorNickname),
            tags,
            row.likeCount,
            row.commentCount,
            row.viewCount,
            row.publishedAt
    );
}

#채점 기준


C = HTTP 확인(필수), D = DB 확인(필수, SELECT만), R = 코드 리뷰(피드백용).

404 / 404

값이 그대로 — 404면 조회수가 오르지 않는다




R1
규칙 한 곳
위 규칙이 한 클래스(예: PostAccessPolicy)에 모여 있다. 상세는 자바 코드로 판정하고 목록은 쿼리 조건으로 걸러야 하는데, 두 곳이 같은 규칙을 따르도록 관리한다




R2
404
볼 수 없을 때 403이 아니라 404를 주는 이유를 코드나 주석으로 알 수 있다




R3
목록 필터 위치
목록 필터링을 메모리(stream().filter)가 아니라 쿼리에서 한다 — 메모리에서 거르면 페이지 크기와 totalElements가 틀어진다




R4
선택적 인증
"헤더 없음 = 비로그인"과 "헤더가 잘못됨 = 401"을 구분한다

#힌트 (막힐 때만)



힌트 1 — 상세와 목록에 같은 규칙


상세: policy.canView(viewer, post)를 자바로 판정한다. 목록: 같은 규칙을 WHERE 조건으로 옮긴다 — status = PUBLISHED, (visibility = PUBLIC OR author = :viewer OR EXISTS(팔로우)), NOT EXISTS(차단). JPQL이면 EXISTS (SELECT 1 FROM Follow f WHERE ...), QueryDSL이면 JPAExpressions로 서브쿼리를 만든다. 규칙을 바꿀 때 두 곳을 같이 고치도록 같은 클래스 옆에 둔다.






힌트 2 — 비로그인


보는 사람을 null(또는 Viewer.anonymous())로 표현하고, 쿼리 조건에서는 비로그인일 때 "PUBLIC만"으로 분기한다.
