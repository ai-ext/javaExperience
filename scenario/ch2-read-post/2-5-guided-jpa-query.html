#2-5. JPA 쿼리 작성 — 예시에서 JOIN까지

#상황

"회원 프로필에 그 사람이 개발 게시판에 쓴 공개 글 목록을 보여주세요. 글 제목과 작성자 이름이 필요하고, 삭제하거나 비공개인 글은 빼주세요."

2-1~2-4에서 단건·게시판 목록·조회 권한·N+1을 다뤘다. 이번에는 같은 데이터를 SQL로 먼저 확인하고 PostRepository의 파생 쿼리와 JPQL @Query를 직접 작성해 새 조회 API를 만든다. 완성 예시를 보고 조건을 하나씩 늘린다. 답을 외우는 단계가 아니라 DB 열과 엔티티 필드가 어떻게 연결되는지 확인하는 단계다.

#만들 것

항목 계약
메서드·경로 GET /api/members/{memberId}/posts?board={slug}. board는 필수 쿼리 파라미터다.
인증 필요 없음. 누구나 볼 수 있는 PUBLISHED·PUBLIC·미삭제 글만 보여준다.
성공 200, [{ "id": 2, "title": "JPA 연관관계 매핑 정리", "authorNickname": "이스프링", "boardSlug": "dev" }]. 새 글이 없는 회원은 [].
정렬 published_at DESC, id DESC — 같은 시각이어도 순서가 정해진다.
실패 memberId가 숫자가 아니거나 board가 비면 400; 회원·게시판이 없으면 404.
구현 Controller는 경로/쿼리를 받아 응답 DTO로 변환, Service는 회원·게시판 확인, Repository는 DB 조건으로 필터링한다. 목록을 전부 읽어 Java에서 거르지 않는다.

시드에서 회원 3은 이스프링이고 개발 게시판(dev)의 글 2번을 썼다. 1-6을 풀며 이스프링으로 만든 공개 글이 있다면 함께 나온다. 회원 4는 존재하지만 dev에 공개 글이 없으므로 200 []다. 글 8은 삭제됐고 6은 팔로워 공개이므로 비로그인 응답에 넣지 않는다. 이미 가진 게시판 목록 API를 바꾸지 말고 새 API로 작성한다.

#구현 가이드

GET 요청을 받는 Controller, 회원·게시판을 확인하는 Service, DB 조건을 적용하는 Repository 순서로 만든다. 아래 JPA 코드와 MyBatis 대체 코드는 단계별 전체 코드 접기에서 파일별로 볼 수 있다.

Controller — 경로와 필수 쿼리 받기

board를 필수 @RequestParam으로 받으면 누락된 요청은 Controller 본문에 들어오기 전에 400이 된다.

@GetMapping("/api/members/{memberId}/posts")
public List<PostHeadlineResponse> list(@PathVariable Long memberId,
                                        @RequestParam @NotBlank String board) {
    return postQueryService.listPublicByAuthor(memberId, board);
}
DTO — 엔티티 대신 네 필드 반환

응답을 Post 엔티티로 바로 보내지 않는다. 목록에서 필요한 값만 고정한다.

public record PostHeadlineResponse(
        Long id, String title, String authorNickname, String boardSlug) {}

목록이 비면 List.of() 또는 빈 조회 결과를 그대로 반환한다. DTO의 필드 이름은 check의 JSON 경로와 같다.

Service — 없는 회원·게시판과 빈 목록 구분

존재 확인을 먼저 해야 "회원은 있지만 글이 없음"이 404가 아니라 200 []가 된다. BoardRepository.findBySlug를 사용한다.

@Transactional(readOnly = true)
public List<PostHeadlineResponse> listPublicByAuthor(Long memberId, String boardSlug) {
    if (!memberRepository.existsById(memberId)) {
        throw new ResponseStatusException(HttpStatus.NOT_FOUND, "회원을 찾을 수 없습니다.");
    }
    boardRepository.findBySlug(boardSlug)
            .orElseThrow(() -> new BoardNotFoundException(boardSlug));
    return postRepository.findPublicPostsByAuthorAndBoard(memberId, boardSlug)
            .stream().map(post -> new PostHeadlineResponse(
                    post.getId(), post.getTitle(),
                    post.getAuthor().getNickname(), boardSlug)).toList();
}

DTO의 boardSlug는 검증한 쿼리값을 사용하므로 각 글의 board를 다시 지연 로딩하지 않는다. @NotBlank가 붙은 Controller의 빈 board 요청은 400인지 확인한다.

JPA / Repository — SQL JOIN을 JPQL로 옮기기

#1. SQL로 기대 결과 보기

다음은 post·member·board의 외래키를 이용한 완성 예시다. community에서 그대로 실행한다. 먼저 WHERE를 빼고 세 테이블의 연결을 확인한 뒤, m.id·b.slug·공개 조건을 하나씩 붙여 결과가 어떻게 줄어드는지 본다.

SELECT p.id, p.title, m.nickname, b.slug
FROM post p
JOIN member m ON m.id = p.author_id
JOIN board b ON b.id = p.board_id
WHERE m.id = 3
  AND b.slug = 'dev'
  AND p.status = 'PUBLISHED'
  AND p.visibility = 'PUBLIC'
  AND p.deleted_at IS NULL
ORDER BY p.published_at DESC, p.id DESC;

m.id=3을 4로 바꾸면 빈 결과가 나온다. b.slug='free'로 바꾸면 다른 글이 나온다. post의 author_id와 board_id가 왜 두 JOIN 조건인지 1-7의 직접 DB 확인에서 본 행과 대조한다.

#2. Repository 쿼리로 옮기기

파생 메서드의 가장 작은 출발점은 다음과 같다. 엔티티의 author.id와 deletedAt 필드를 읽어 메서드 이름을 SQL 조건으로 바꾼다. 아래 코드를 먼저 실행하고 글 8처럼 삭제된 행이 빠지는지 확인한다.

List<Post> findByAuthor_IdAndDeletedAtIsNullOrderByIdDesc(Long memberId);

이번에는 작성자 ID와 게시판이라는 두 조건이 필요하다. 파생 메서드 이름에 Author_Id·Board_Slug를 붙이고 Status·Visibility 조건까지 늘리는 방법을 먼저 시도한다. 이름이 길어지면 아래처럼 JPQL @Query로 조건을 드러낸다. Post·Board·Member는 엔티티 이름과 연관 필드이고, post·board·member는 SQL의 테이블 이름이다.

@Query("""
    SELECT p FROM Post p
    JOIN FETCH p.author a
    JOIN p.board b
    WHERE a.id = :memberId
      AND b.slug = :boardSlug
      AND p.status = 'PUBLISHED'
      AND p.visibility = 'PUBLIC'
      AND p.deletedAt IS NULL
    ORDER BY p.publishedAt DESC, p.id DESC
    """)
List<Post> findPublicPostsByAuthorAndBoard(
    @Param("memberId") Long memberId,
    @Param("boardSlug") String boardSlug);

처음에는 위 JPQL을 그대로 써서 SQL 예시와 결과를 맞춘다. 다음에는 JOIN FETCH p.author를 JOIN p.author로 바꾸고 authorNickname DTO를 만들 때 SQL이 몇 번 나가는지 로그를 비교한다. 마지막으로 엔티티 전체 대신 필요한 네 필드만 선택하는 DTO projection을 직접 작성해 본다. 전체 행의 개수와 순서가 유지되어야 한다.

목록을 반환할 때 Post 엔티티를 JSON으로 바로 보내지 않는다. PostHeadlineResponse 같은 응답 DTO를 만들어 id·title·authorNickname·boardSlug만 내보낸다. 회원·게시판의 존재 확인은 Service에서 먼저 하므로, 없는 회원/게시판은 404, 존재하지만 글이 없으면 200 []가 된다.

MyBatis / SQL — 같은 조건을 Mapper에 쓰기

JPA 단계 코드에서 MyBatis로 바뀌는 12개 파일은 전체 코드 접기의 MyBatis 대체 구현에 있다. PostHeadlineRow는 조회 결과, PostVisibilityMapper는 회원 확인과 목록 SQL, PostQueryService는 404/빈 배열 구분을 담당한다. @Mapper 인터페이스의 메서드는 selectPublicByAuthorAndBoard(@Param("memberId") Long memberId, @Param("boardSlug") String boardSlug)처럼 두 입력을 받는다.

<select id="selectPublicByAuthorAndBoard" resultType="org.example.post.PostHeadlineRow">
  SELECT p.id, p.title, m.nickname AS author_nickname, b.slug AS board_slug
  FROM post p
  JOIN member m ON m.id = p.author_id
  JOIN board b ON b.id = p.board_id
  WHERE m.id = #{memberId} AND b.slug = #{boardSlug}
    AND p.status = 'PUBLISHED' AND p.visibility = 'PUBLIC'
    AND p.deleted_at IS NULL
  ORDER BY p.published_at DESC, p.id DESC
</select>

PostHeadlineRow에는 조회 열에 대응하는 public 필드를 두고, map-underscore-to-camel-case로 별칭을 연결한다. Mapper 결과를 위 응답 DTO로 변환한다. 회원·게시판 존재 확인과 404/빈 배열 구분은 JPA 방식과 동일하게 Service에서 처리한다. 이 단계의 MyBatis 대체 구현에는 build.gradle 의존성, application.yml 설정, Mapper XML이 모두 포함되어 있다.

public class PostHeadlineRow {
    public Long id;
    public String title;
    public String authorNickname;
    public String boardSlug;
}

이 클래스는 org.example.post 패키지에 둔다. application.yml의 map-underscore-to-camel-case: true가 SQL 별칭을 필드에 연결한다.

package org.example.post;


import org.example.auth.AuthenticatedMember;
import org.example.board.Board;
import org.example.board.BoardNotFoundException;
import org.example.board.BoardRepository;
import org.example.member.MemberRepository;
import org.example.tag.Tag;
import org.springframework.data.domain.Page;
import org.springframework.data.domain.PageImpl;
import org.springframework.data.domain.PageRequest;
import org.springframework.data.domain.Sort;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import org.springframework.http.HttpStatus;
import org.springframework.web.server.ResponseStatusException;


import java.util.List;


// 글 조회 전용 서비스 — 1-3/1-4의 PostService(쓰기)와 책임을 나눈다
@Service
public class PostQueryService {


private final PostRepository postRepository;
private final BoardRepository boardRepository;
private final MemberRepository memberRepository;
private final PostAccessPolicy accessPolicy;

public PostQueryService(PostRepository postRepository, BoardRepository boardRepository,
                         MemberRepository memberRepository,
                         PostAccessPolicy accessPolicy) {
    this.postRepository = postRepository;
    this.boardRepository = boardRepository;
    this.memberRepository = memberRepository;
    this.accessPolicy = accessPolicy;
}

@Transactional(readOnly = true)
public List&lt;PostHeadlineResponse&gt; listPublicByAuthor(Long memberId, String boardSlug) {
    if (!memberRepository.existsById(memberId)) {
        throw new ResponseStatusException(HttpStatus.NOT_FOUND, &quot;회원을 찾을 수 없습니다.&quot;);
    }
    boardRepository.findBySlug(boardSlug)
            .orElseThrow(() -&gt; new BoardNotFoundException(boardSlug));
    return postRepository.findPublicPostsByAuthorAndBoard(memberId, boardSlug).stream()
            .map(post -&gt; new PostHeadlineResponse(
                    post.getId(), post.getTitle(),
                    post.getAuthor().getNickname(), boardSlug))
            .toList();
}

@Transactional
public PostDetailResponse getDetail(Long id, AuthenticatedMember viewer) {
    Post post = postRepository.findById(id)
            .orElseThrow(PostNotFoundException::new);

    // 볼 수 없으면 403이 아니라 404 — 글이 있다는 사실도 숨긴다. 조회수도 올리지 않는다.
    if (!accessPolicy.canView(viewer, post)) {
        throw new PostNotFoundException();
    }

    post.increaseViewCount();
    return toDetailResponse(post);
}

@Transactional(readOnly = true)
public PostListResponse list(String boardSlug, int page, int size, AuthenticatedMember viewer) {
    Board board = boardRepository.findBySlug(boardSlug)
            .orElseThrow(() -&gt; new BoardNotFoundException(boardSlug));

    Long viewerId = viewer == null ? null : viewer.id();

    PageRequest pageRequest = PageRequest.of(page, size,
            Sort.by(Sort.Order.desc(&quot;publishedAt&quot;), Sort.Order.desc(&quot;id&quot;)));
    List&lt;Post&gt; content = postRepository.findViewableByBoard(board, viewerId, pageRequest);
    long total = postRepository.countViewableByBoard(board, viewerId);
    Page&lt;Post&gt; result = new PageImpl&lt;&gt;(content, pageRequest, total);

    List&lt;PostListItemResponse&gt; items = result.getContent().stream()
            .map(this::toListItem)
            .toList();

    return new PostListResponse(
            items,
            result.getNumber(),
            result.getSize(),
            result.getTotalElements(),
            result.getTotalPages(),
            result.hasNext()
    );
}

private PostListItemResponse toListItem(Post post) {
    return new PostListItemResponse(
            post.getId(),
            post.getTitle(),
            new AuthorResponse(post.getAuthor().getId(), post.getAuthor().getNickname()),
            post.getTags().stream().map(Tag::getName).toList(),
            post.getLikeCount(),
            post.getCommentCount(),
            post.getViewCount(),
            post.getPublishedAt()
    );
}

private PostDetailResponse toDetailResponse(Post post) {
    // 트랜잭션 안에서 지연 로딩 연관을 읽어 DTO로 옮긴다(open-in-view: false)
    return new PostDetailResponse(
            post.getId(),
            post.getBoard().getSlug(),
            post.getTitle(),
            post.getContent(),
            post.getTags().stream().map(Tag::getName).toList(),
            post.getVisibility(),
            new AuthorResponse(post.getAuthor().getId(), post.getAuthor().getNickname()),
            post.getViewCount(),
            post.getLikeCount(),
            post.getCommentCount(),
            post.getCreatedAt()
    );
}


}

import org.example.board.Board;

// Spring Data JPA가 구현을 만들어 준다(1-3의 메모리 구현을 대체)
public interface PostRepository extends JpaRepository<Post, Long> {


// 2-3의 &quot;볼 수 있나&quot; 규칙 중 목록에 해당하는 부분을 쿼리로 옮긴 것 — PostAccessPolicy.canView와

// 메모리에서 거르지 않고 쿼리에서 걸러야 페이지 크기·totalElements가 맞는다.
//

// Spring Data가 &quot;content 개수 &lt; size면 count 쿼리를 생략&quot;하는 최적화를 적용해서, size=5(꽉 찬
// 페이지, count 쿼리 나감)와 size=20(13개뿐이라 마지막 페이지, count 쿼리 생략)의 SQL 문장 수가
// 13과1씩 달라졌다(2-4의 PostListQueryCountTest가 요구하는 &quot;size와 무관하게 문장 수 동일&quot;이 깨짐).
// count를 항상 명시적으로 실행해 문장 수를 size와 무관하게 고정한다(R2와도 맞다).
@Query(&quot;&quot;&quot;
        SELECT p FROM Post p
        JOIN FETCH p.author
        WHERE p.board = :board
          AND p.deletedAt IS NULL
          AND p.status = 'PUBLISHED'
          AND (
               p.visibility = 'PUBLIC'
               OR (:viewerId IS NOT NULL AND p.author.id = :viewerId)
               OR (:viewerId IS NOT NULL AND EXISTS (
                       SELECT 1 FROM Follow f
                       WHERE f.follower.id = :viewerId AND f.followee = p.author))
          )
          AND (
               :viewerId IS NULL OR NOT EXISTS (
                   SELECT 1 FROM MemberBlock b
                   WHERE (b.blocker.id = :viewerId AND b.blocked = p.author)
                      OR (b.blocked.id = :viewerId AND b.blocker = p.author)
               )
          )
        &quot;&quot;&quot;)
List&lt;Post&gt; findViewableByBoard(@Param(&quot;board&quot;) Board board,
                                @Param(&quot;viewerId&quot;) Long viewerId,
                                Pageable pageable);

// findViewableByBoard와 같은 조건의 건수 — 반드시 같이 고친다
@Query(&quot;&quot;&quot;
        SELECT COUNT(p) FROM Post p
        WHERE p.board = :board
          AND p.deletedAt IS NULL
          AND p.status = 'PUBLISHED'
          AND (
               p.visibility = 'PUBLIC'
               OR (:viewerId IS NOT NULL AND p.author.id = :viewerId)
               OR (:viewerId IS NOT NULL AND EXISTS (
                       SELECT 1 FROM Follow f
                       WHERE f.follower.id = :viewerId AND f.followee = p.author))

                   WHERE (b.blocker.id = :viewerId AND b.blocked = p.author)

               )
          )
        &quot;&quot;&quot;)
long countViewableByBoard(@Param(&quot;board&quot;) Board board, @Param(&quot;viewerId&quot;) Long viewerId);

        SELECT p FROM Post p
        JOIN FETCH p.author a
        JOIN p.board b
        WHERE a.id = :memberId
          AND b.slug = :boardSlug
          AND p.status = 'PUBLISHED'
          AND p.visibility = 'PUBLIC'

import org.example.auth.AuthenticatedMember;
import org.example.board.BoardNotFoundException;
import org.springframework.stereotype.Service;

import org.springframework.web.server.ResponseStatusException;

// 글 조회 전용 서비스 — 1-3/1-4의 PostService(쓰기)와 책임을 나눈다
@Service
public class PostQueryService {


private final PostVisibilityMapper mapper;

public PostQueryService(PostVisibilityMapper mapper) {
    this.mapper = mapper;
}


@Transactional(readOnly = true)
public List&lt;PostHeadlineResponse&gt; listPublicByAuthor(Long memberId, String boardSlug) {
    if (boardSlug == null || boardSlug.isBlank()) {
        throw new ResponseStatusException(HttpStatus.BAD_REQUEST, &quot;게시판을 선택해 주세요.&quot;);
    }
    if (mapper.findMemberId(memberId) == null) {
        throw new ResponseStatusException(HttpStatus.NOT_FOUND, &quot;회원을 찾을 수 없습니다.&quot;);
    }
    if (mapper.findBoardIdBySlug(boardSlug) == null) {
        throw new BoardNotFoundException(boardSlug);
    }
    return mapper.selectPublicByAuthorAndBoard(memberId, boardSlug).stream()
            .map(row -&gt; new PostHeadlineResponse(row.id, row.title,
                    row.authorNickname, row.boardSlug)).toList();
}

@Transactional
public PostDetailResponse getDetail(Long id, AuthenticatedMember viewer) {
    Long viewerId = viewer == null ? null : viewer.id();
    String viewerRole = viewer == null ? null : viewer.role();
    // SQL에서 권한을 먼저 걸러 404일 때 조회수가 변하지 않게 한다.
    PostDetailRow row = mapper.findVisibleDetail(id, viewerId, viewerRole);
    if (row == null) {
        throw new PostNotFoundException();
    }
    mapper.increaseViewCount(id);
    List&lt;String&gt; tags = mapper.findTagsByPostIds(List.of(id)).stream()
            .map(PostTagRow::name).toList();
    return new PostDetailResponse(row.id, row.boardSlug, row.title, row.content,
            tags, row.visibility, new AuthorResponse(row.authorId, row.authorNickname),
            row.viewCount + 1, row.likeCount, row.commentCount, row.createdAt);
}

@Transactional(readOnly = true)
public PostListResponse list(String boardSlug, int page, int size, AuthenticatedMember viewer) {
    Long boardId = mapper.findBoardIdBySlug(boardSlug);
    if (boardId == null) throw new BoardNotFoundException(boardSlug);

    Long viewerId = viewer == null ? null : viewer.id();

    long offset = (long) page * size;
    List&lt;PostListRow&gt; rows = mapper.findViewableByBoard(boardId, viewerId, size, offset);
    long total = mapper.countViewableByBoard(boardId, viewerId);
    Map&lt;Long, List&lt;String&gt;&gt; tags = rows.isEmpty() ? Map.of()
            : mapper.findTagsByPostIds(rows.stream().map(row -&gt; row.id).toList()).stream()
                .collect(Collectors.groupingBy(PostTagRow::postId,
                        Collectors.mapping(PostTagRow::name, Collectors.toList())));
    List&lt;PostListItemResponse&gt; items = rows.stream()
            .map(row -&gt; toListItem(row, tags.getOrDefault(row.id, List.of()))).toList();

    return new PostListResponse(
            items,
            page,
            size,
            total,
            (int) ((total + size - 1) / size),
            offset + rows.size() &lt; total
    );
}

private PostListItemResponse toListItem(PostListRow row, List&lt;String&gt; tags) {
    return new PostListItemResponse(
            row.id,
            row.title,
            new AuthorResponse(row.authorId, row.authorNickname),
            tags,
            row.likeCount,
            row.commentCount,
            row.viewCount,
            row.publishedAt
    );
}


}

// 테스트 중 Mapper가 실행한 SELECT 문장 수를 요청 스레드별로 센다.
@Component
@Intercepts(@Signature(type = Executor.class, method = "query",
        args = {MappedStatement.class, Object.class, RowBounds.class, ResultHandler.class}))
public class MyBatisStatementCounter implements Interceptor {
    private final ThreadLocal<Long> count = ThreadLocal.withInitial(() -> 0L);


@Override
public Object intercept(Invocation invocation) throws Throwable {
    count.set(count.get() + 1);
    return invocation.proceed();
}

public void clear() { count.set(0L); }
public long getCount() { return count.get(); }


}
