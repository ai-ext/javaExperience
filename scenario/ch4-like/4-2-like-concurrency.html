화면 시나리오의 서버·DB 흐름을 이 단계에서 바뀐 파일에 연결한다. 먼저 만들 것의 계약대로 직접 작성하고, 필요한 역할만 펼쳐 파일 전문과 비교한다.

이 단계의 처리 흐름:

  • 고치기 전: 각 요청이 엔티티를 읽고 +1 해서 저장 → 서로 덮어써 숫자가 모자란다
  • 고친 뒤: DB가 한 번에 더한다 — 읽고 쓰기 사이에 끼어들 틈이 없다
  • 다섯 요청이 동시에 '아직 없음'을 확인하고 모두 INSERT를 시도 → UNIQUE(post_id, member_id)가 하나만 받아들인다
  • 중복 키 오류를 '이미 좋아요'로 처리해 500을 내지 않는다
Service — 처리 순서

LikeService.java. 위 서버 처리 순서가 어디에서 검증·조회·상태 변경으로 이어지는지 따라간다. 변경된 메서드: like, unlike.

like와 unlike 모두 새 트랜잭션에서 실행하고, 교착으로 롤백된 요청만 새 트랜잭션으로 재시도한다. 같은 트랜잭션 안에서 오류 뒤 SQL만 재실행하면 이미 롤백 전용이어서 실패한다.

public LikeResponse like(Long postId, AuthenticatedMember me) {
    return withDeadlockRetry(() ->
        transactionTemplate.execute(status -> doLike(postId, me)));
}

private LikeResponse doLike(Long postId, AuthenticatedMember me) {
    Post post = findLikeablePost(postId, me);
    if (post.getAuthor().getId().equals(me.id())) throw new SelfLikeNotAllowedException();
    int inserted = postLikeRepository.insertIgnore(postId, me.id());
    if (inserted > 0) postRepository.incrementLikeCount(postId);
    return new LikeResponse(postId, true, postRepository.findLikeCountById(postId));
}

DELETE도 실제 삭제 행 수가 1일 때만 decrementLikeCount를 호출한다. DB에서 다시 읽은 숫자로 DTO를 만든다.

JPA / Repository — DB 조건

PostLikeRepository.java, PostRepository.java. 쿼리·파생 메서드의 조건을 화면 시나리오의 DB 단계 및 직접 확인 SQL과 대조한다. 직접 작성한 JPQL·SQL과 아래 파일의 @Query를 비교한다.

@Modifying
@Query(value = "INSERT IGNORE INTO post_like (post_id, member_id, created_at) " +
               "VALUES (:postId, :memberId, NOW())", nativeQuery = true)
int insertIgnore(@Param("postId") Long postId, @Param("memberId") Long memberId);

@Modifying
@Query("UPDATE Post p SET p.likeCount = p.likeCount + 1 WHERE p.id = :id")
int incrementLikeCount(@Param("id") Long id);

INSERT IGNORE의 결과 0은 이미 관계가 있다는 뜻이다. 1일 때만 숫자를 증가시킨다. likeCount를 엔티티에서 읽어 +1 후 저장하면 갱신 손실이 다시 생긴다.

Post.java. 실제 테이블의 컬럼·외래키와 엔티티 매핑을 대조한다.

MyBatis / Mapper — 중복 삽입 방지와 원자적 숫자 갱신

MyBatisLikeService도 TransactionTemplate로 두 쓰기를 묶고 교착 시 새 트랜잭션에서 재시도한다. insertIgnoreLike가 1을 돌려준 요청만 increaseLikeCount를 실행한다. DELETE는 deleteLike가 1을 돌려준 요청만 decreaseLikeCount를 실행한다.

<insert id="insertIgnoreLike">
  INSERT IGNORE INTO post_like(post_id, member_id, created_at)
  VALUES (#{postId}, #{memberId}, CURRENT_TIMESTAMP)
</insert>
<update id="increaseLikeCount">
  UPDATE post SET like_count = like_count + 1 WHERE id = #{postId}
</update>

두 경로 모두 새 SELECT로 저장된 like_count를 응답한다. 실행 가능한 Mapper Java/XML·Service·Controller·동시성 테스트 파일 전문은 아래 MyBatis 역할별 코드 접기에 있다.

package org.example.like;


import org.example.auth.AuthenticatedMember;
import org.example.post.Post;
import org.example.post.PostAccessPolicy;
import org.example.post.PostNotFoundException;
import org.example.post.PostRepository;
import org.springframework.dao.ConcurrencyFailureException;
import org.springframework.stereotype.Service;
import org.springframework.transaction.PlatformTransactionManager;
import org.springframework.transaction.support.TransactionTemplate;


// 좋아요·취소 규칙. PUT·DELETE 모두 "현재 상태를 확인하고 필요할 때만 바꾼다"(멱등).
// 4-2: like_count는 DB에서 원자적으로 +1/-1 하고(읽고 계산해서 저장하지 않는다), 중복 INSERT는
// UNIQUE(post_id, member_id) + INSERT IGNORE로 막는다 — 동시 요청에도 숫자와 행 수가 어긋나지 않는다.
//
// 그래도 "서로 다른 회원 수십 명이 같은 글에 동시에" INSERT + UPDATE를 하면 MySQL/InnoDB가 교착
// 상태(Deadlock found when trying to get lock)로 한쪽을 강제로 롤백시키는 경우가 실제로 있다(값이
// 틀리는 게 아니라 그 요청만 실패한다). 그 요청은 처음부터 다시 하면 되므로 짧게 재시도한다.
@Service
public class LikeService {


private static final String PUBLISHED = &quot;PUBLISHED&quot;;
private static final int MAX_ATTEMPTS = 10;

private final PostRepository postRepository;
private final PostLikeRepository postLikeRepository;
private final PostAccessPolicy accessPolicy;
private final TransactionTemplate transactionTemplate;

public LikeService(PostRepository postRepository, PostLikeRepository postLikeRepository,
                    PostAccessPolicy accessPolicy, PlatformTransactionManager transactionManager) {
    this.postRepository = postRepository;
    this.postLikeRepository = postLikeRepository;
    this.accessPolicy = accessPolicy;
    this.transactionTemplate = new TransactionTemplate(transactionManager);
}

public LikeResponse like(Long postId, AuthenticatedMember loginMember) {
    return withDeadlockRetry(() -&gt; transactionTemplate.execute(status -&gt; doLike(postId, loginMember)));
}

public LikeResponse unlike(Long postId, AuthenticatedMember loginMember) {
    return withDeadlockRetry(() -&gt; transactionTemplate.execute(status -&gt; doUnlike(postId, loginMember)));
}

private LikeResponse doLike(Long postId, AuthenticatedMember loginMember) {
    Post post = findLikeablePost(postId, loginMember);
    if (post.getAuthor().getId().equals(loginMember.id())) {
        throw new SelfLikeNotAllowedException();
    }

    int inserted = postLikeRepository.insertIgnore(postId, loginMember.id());
    if (inserted &gt; 0) {
        postRepository.incrementLikeCount(postId);
    }
    return new LikeResponse(postId, true, postRepository.findLikeCountById(postId));
}

private LikeResponse doUnlike(Long postId, AuthenticatedMember loginMember) {
    findLikeablePost(postId, loginMember);

    long deleted = postLikeRepository.deleteByPost_IdAndMember_Id(postId, loginMember.id());
    if (deleted &gt; 0) {
        postRepository.decrementLikeCount(postId);
    }
    return new LikeResponse(postId, false, postRepository.findLikeCountById(postId));
}

// 볼 수 있는 글인가(2-3 규칙 재사용) + PUBLISHED인가 — 둘 다 아니면 404
private Post findLikeablePost(Long postId, AuthenticatedMember loginMember) {
    Post post = postRepository.findById(postId)
            .orElseThrow(PostNotFoundException::new);
    if (!accessPolicy.canView(loginMember, post) || !PUBLISHED.equals(post.getStatus())) {
        throw new PostNotFoundException();
    }
    return post;
}

private LikeResponse withDeadlockRetry(java.util.function.Supplier&lt;LikeResponse&gt; action) {
    for (int attempt = 1; ; attempt++) {
        try {
            return action.get();
        } catch (ConcurrencyFailureException e) {
            if (attempt &gt;= MAX_ATTEMPTS) {
                throw e;
            }
            // 이 트랜잭션은 이미 롤백됐다 — 처음부터(새 트랜잭션으로) 다시 시도한다.
            // 바로 재시도하면 같은 상대와 또 부딪히기 쉬우니 짧게, 무작위로 간격을 둔다.
            try {
                Thread.sleep((long) (Math.random() * 20 * attempt));
            } catch (InterruptedException interrupted) {
                Thread.currentThread().interrupt();
                throw e;
            }
        }
    }
}


}

import org.example.auth.AuthenticatedMember;

import org.springframework.dao.ConcurrencyFailureException;
import org.springframework.stereotype.Service;
import org.springframework.transaction.PlatformTransactionManager;
import org.springframework.transaction.support.TransactionTemplate;


// 관계 행 삽입과 개수 증감을 같은 트랜잭션에서 원자적으로 처리한다.
@Service
public class MyBatisLikeService {
    private static final int MAX_ATTEMPTS = 10;
    private final PostVisibilityMapper visiblePosts;
    private final MyBatisLikeMapper likes;
    private final TransactionTemplate transactions;


public MyBatisLikeService(PostVisibilityMapper visiblePosts, MyBatisLikeMapper likes,
                          PlatformTransactionManager manager) {
    this.visiblePosts = visiblePosts;
    this.likes = likes;
    this.transactions = new TransactionTemplate(manager);
}

public LikeResponse like(Long postId, AuthenticatedMember me) {
    return withDeadlockRetry(() -&gt; transactions.execute(status -&gt; doLike(postId, me)));
}

public LikeResponse unlike(Long postId, AuthenticatedMember me) {
    return withDeadlockRetry(() -&gt; transactions.execute(status -&gt; doUnlike(postId, me)));
}

private LikeResponse doLike(Long postId, AuthenticatedMember me) {
    PostDetailRow post = findLikeablePost(postId, me);
    if (post.authorId.equals(me.id())) throw new SelfLikeNotAllowedException();
    if (likes.insertIgnoreLike(postId, me.id()) == 1) likes.increaseLikeCount(postId);
    return new LikeResponse(postId, true, likes.findLikeCount(postId));
}

private LikeResponse doUnlike(Long postId, AuthenticatedMember me) {
    findLikeablePost(postId, me);
    if (likes.deleteLike(postId, me.id()) == 1) likes.decreaseLikeCount(postId);
    return new LikeResponse(postId, false, likes.findLikeCount(postId));
}

private PostDetailRow findLikeablePost(Long postId, AuthenticatedMember me) {
    PostDetailRow post = visiblePosts.findVisibleDetail(postId, me.id(), me.role());
    if (post == null || !&quot;PUBLISHED&quot;.equals(likes.findPostStatus(postId)))
        throw new PostNotFoundException();
    return post;
}

private LikeResponse withDeadlockRetry(java.util.function.Supplier&lt;LikeResponse&gt; action) {
    for (int attempt = 1; ; attempt++) {
        try {
            return action.get();
        } catch (ConcurrencyFailureException e) {
            if (attempt &gt;= MAX_ATTEMPTS) throw e;
            try {
                Thread.sleep((long) (Math.random() * 20 * attempt));
            } catch (InterruptedException interrupted) {
                Thread.currentThread().interrupt();
                throw e;
            }
        }
    }
}

@Service
public class PostPatchMyBatisService {
    private static final int TITLE_MAX_LENGTH = 200;
    private static final int TAGS_MAX_COUNT = 5;
    private static final int TAG_NAME_MAX_LENGTH = 30;


private final PostVisibilityMapper visibilityMapper;
private final PostReplaceMapper replaceMapper;

public PostPatchMyBatisService(PostVisibilityMapper visibilityMapper,
                               PostReplaceMapper replaceMapper) {
    this.visibilityMapper = visibilityMapper;
    this.replaceMapper = replaceMapper;
}

@Transactional
public PostDetailResponse patch(Long id, AuthenticatedMember me, PostUpdateRequest request) {
    PostDetailRow current = visibilityMapper.findVisibleDetail(id, me.id(), me.role());
    if (current == null) throw new PostNotFoundException();
    if (!current.authorId.equals(me.id())) throw new PostForbiddenException();

    // 모든 입력을 확인한 뒤 쓰기를 시작한다.
    if (request.title() != null) validateTitle(request.title());
    if (request.content() != null) validateContent(request.content());
    if (request.tags() != null) validateTags(request.tags());
    if (request.visibility() != null) validateVisibility(request.visibility());

    List&lt;String&gt; tags;
    if (request.tags() == null) {
        tags = visibilityMapper.findTagsByPostIds(List.of(id)).stream()
                .map(PostTagRow::name).toList();
    } else {
        List&lt;PostReplaceTagRow&gt; resolved = new ArrayList&lt;&gt;();
        Set&lt;Long&gt; seenIds = new HashSet&lt;&gt;();
        for (String name : request.tags()) {
            replaceMapper.insertTagIfMissing(name);
            PostReplaceTagRow tag = replaceMapper.findTagByName(name);
            if (seenIds.add(tag.id)) resolved.add(tag);
        }
        replaceMapper.deletePostTags(id);
        for (PostReplaceTagRow tag : resolved) replaceMapper.insertPostTag(id, tag.id);
        tags = resolved.stream().map(tag -&gt; tag.name).toList();
    }
    replaceMapper.patchPost(id, request.title(), request.content(), request.visibility());
    return new PostDetailResponse(id, current.boardSlug,
            request.title() == null ? current.title : request.title(),
            request.content() == null ? current.content : request.content(),
            tags,
            request.visibility() == null ? current.visibility : request.visibility(),
            new AuthorResponse(current.authorId, current.authorNickname),
            current.viewCount, current.likeCount, current.commentCount, current.createdAt);
}

private void validateTitle(String title) {
    if (title.isBlank()) throw new InvalidPostFieldException(&quot;title&quot;, &quot;제목을 입력해 주세요.&quot;);
    if (title.length() &gt; TITLE_MAX_LENGTH)
        throw new InvalidPostFieldException(&quot;title&quot;, &quot;제목은 &quot; + TITLE_MAX_LENGTH + &quot;자 이하여야 합니다.&quot;);
}

private void validateContent(String content) {
    if (content.isBlank()) throw new InvalidPostFieldException(&quot;content&quot;, &quot;본문을 입력해 주세요.&quot;);
}

private void validateTags(List&lt;String&gt; tags) {
    if (tags.size() &gt; TAGS_MAX_COUNT)
        throw new InvalidPostFieldException(&quot;tags&quot;, &quot;태그는 &quot; + TAGS_MAX_COUNT + &quot;개까지입니다.&quot;);
    for (String tag : tags) {
        if (tag == null || tag.isBlank() || tag.length() &gt; TAG_NAME_MAX_LENGTH)
            throw new InvalidPostFieldException(&quot;tags&quot;, &quot;태그 이름은 1~&quot; + TAG_NAME_MAX_LENGTH + &quot;자여야 합니다.&quot;);
    }
}

private void validateVisibility(String visibility) {
    if (!&quot;PUBLIC&quot;.equals(visibility) &amp;&amp; !&quot;FOLLOWERS&quot;.equals(visibility))
        throw new InvalidPostFieldException(&quot;visibility&quot;, &quot;공개 범위는 PUBLIC 또는 FOLLOWERS여야 합니다.&quot;);
}

private List&lt;Exception&gt; runConcurrently(int count, java.util.function.IntConsumer task) throws InterruptedException {
    ExecutorService pool = Executors.newFixedThreadPool(count);
    CountDownLatch ready = new CountDownLatch(count);
    CountDownLatch start = new CountDownLatch(1);
    CountDownLatch done = new CountDownLatch(count);
    List&lt;Exception&gt; errors = new CopyOnWriteArrayList&lt;&gt;();

    for (int i = 0; i &lt; count; i++) {
        int index = i;

            try {
                ready.countDown();
                start.await();
                task.accept(index);
            } catch (Exception e) {
                errors.add(e);
            } finally {
                done.countDown();
            }
        });
    }

    boolean allReady = ready.await(10, TimeUnit.SECONDS);
    start.countDown(); // 모든 스레드가 준비된 뒤 한꺼번에 출발시킨다

힌트 1 — 숫자


리포지토리에 @Modifying @Query("update Post p set p.likeCount = p.likeCount + 1 where p.id = :id"). 이 쿼리는 영속성 컨텍스트를 거치지 않으므로, 응답에 줄 최신 값은 다시 조회하거나 clearAutomatically = true를 쓴다.


서로 다른 회원 20명이 동시에 누르면 MySQL이 post_like 유니크 인덱스 삽입과 post 행 갱신 사이에서 교착 상태를 감지해 일부 트랜잭션을 되돌릴 수 있다(Deadlock found ... try restarting transaction → Spring의 ConcurrencyFailureException, 실측 20건 중 8건). 원자적 UPDATE만으로는 이걸 막지 못한다 — 트랜잭션 밖에서 짧게(예: 3번, 수십 ms 간격) 다시 시도한다.


재시도는 같은 트랜잭션 안에서 하면 안 된다(이미 롤백 표시가 붙었다). 



힌트 2 — 테스트 뼈대


ExecutorService pool = Executors.newFixedThreadPool(20); CountDownLatch ready = new CountDownLatch(1), done = new CountDownLatch(20); 각 작업은 ready.await() 후 서비스(또는 MockMvc)를 호출하고 done.countDown(). 모두 제출한 뒤 ready.countDown()으로 동시에 출발시키고 assertThat(done.await(10, SECONDS)).isTrue() — 시간 제한을 둔 await는 반환값을 꼭 단언한다(버리면 스레드가 다 안 끝났어도 테스트가 통과한다).


테스트 클래스에는 다른 통합 테스트(처음부터 있는 HelloControllerTest)와 같은 애너테이션(@SpringBootTest + @AutoConfigureMockMvc)을 붙인다 — MockMvc를 안 쓰더라도. 하나라도 다르면 스프링 컨텍스트가 따로 만들어지고, 같은 테스트 DB에 스키마 초기화가 다시 돌아 "Table already exists"로 실패한다.
