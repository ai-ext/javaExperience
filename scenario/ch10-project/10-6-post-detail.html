#10-6. 게시글 상세 — 조회수·작성자·태그·댓글을 한 번에, N+1 없이

#상황

API 규칙 성공 실패
GET /api/v1/posts/{postId} 조회수 +1(같은 요청의 응답에도 반영), 작성자 {id, nickname}, 태그, 좋아요 수, 내가 좋아요했나(로그인 시), 댓글 목록(시간순, 답글은 부모 아래) 200 404(없음·삭제·남의 PRIVATE)

상세 화면은 글 하나에 딸린 것을 모두 보여 준다. 작성자, 태그, 댓글(과 댓글마다의 작성자)이다. 엔티티를 하나씩 따라가며 읽으면 쿼리가 댓글 수만큼 늘어난다. 이것이 N+1 문제다. 이 단계의 목표는 기능과 함께 쿼리 수를 댓글 수와 상관없이 고정하는 것이다.

댓글은 10-9에서 쓰기를 만든다. 지금은 시드 데이터에 있는 댓글을 읽어서 트리로 만드는 것만 한다. 글 1에 모든 경우가 들어 있다.

댓글 상태 상세에서
1 "좋은 정리네요" 최상위, 답글 2·3 보인다, replies 2개
4 "지울 댓글" 최상위, 삭제됨, 답글 5(살아 있음) 내용·작성자를 숨기고 "삭제된 댓글입니다"로 자리만, replies에 5
6 "record는 불변이라 좋아요" 최상위, 답글 7(삭제됨) 보인다, replies 비어 있음
8 "아무 답글 없이 지운 댓글" 최상위, 삭제됨, 답글 없음 아예 빠진다

작성 응답 10-5의 작성 응답도 같은 모양으로(liked: false, comments: [])

#설계 포인트

  • N+1이 생기는 자리. 댓글 목록을 findByPostId로 읽고 응답을 만들며 comment.getAuthor().getNickname()을 부르면, 작성자가 LAZY라 댓글마다 SELECT ... FROM users가 나간다. 댓글 6개면 1 + 6번이다. 해결은 "필요한 것을 처음 쿼리에서 같이 가져오기"다. JPQL의 join fetch를 쓴다.
  • 컬렉션 두 개를 한 번에 fetch join하지 않는다. 글 + 태그 + 댓글을 한 JPQL에 모두 join fetch하면 행이 곱으로 불어난다(태그 2 × 댓글 6 = 12행). 컬렉션이 둘 이상이면 Hibernate가 거부하기도 한다(MultipleBagFetchException). 글·작성자·태그 한 쿼리, 댓글·작성자 한 쿼리로 나눈다.
  • 조회수는 "읽고 +1 해서 저장"하지 않는다. 엔티티의 viewCount를 +1 하고 변경 감지에 맡기면, 동시에 두 명이 열 때 둘 다 10을 읽고 11을 쓴다. UPDATE posts SET view_count = view_count + 1을 DB에서 바로 실행한다(@Modifying @Query). 응답에는 읽었던 값 + 1을 싣는다. 두 요청이 동시에 10을 읽으면 각 응답은 11일 수 있지만 DB의 최종 값은 12다. 응답 값은 이 요청의 증가를 반영한 값이며, 동시 요청까지 포함한 최신 합계를 보장하지 않는다.
  • 트리는 메모리에서. 댓글을 시간순 평평한 목록으로 한 번에 읽고, 자바에서 parent_id별로 묶어 트리를 만든다. 부모 댓글마다 답글을 다시 조회하면 그게 또 N+1이다.
  • 남의 비공개는 404. 403("권한 없음")은 "그 글이 있다"를 알려 준다. 접근 규칙은 G2처럼 한곳에 모아 두면 10-8·10-9에서 다시 쓴다.

@Transactional
public PostDetailResponse detail(Long postId, Long loginUserId) {
    Post post = postRepository.findDetailById(postId)
            .orElseThrow(() -> new ApiException(ErrorCode.NOT_FOUND, "게시글을 찾을 수 없습니다."));
    if (post.getVisibility() == Visibility.PRIVATE && !post.getAuthor().getId().equals(loginUserId)) {
        throw new ApiException(ErrorCode.NOT_FOUND, "게시글을 찾을 수 없습니다.");
    }
    postRepository.increaseViewCount(postId);
    boolean liked = loginUserId != null && postRepository.countLike(postId, loginUserId) > 0;
    return PostDetailResponse.of(post, post.getViewCount() + 1, liked,
            CommentTree.build(commentRepository.findAllWithAuthorByPostId(postId)));
}

없는 글·삭제된 글·남의 비공개 글은 조회수를 올리기 전에 404로 끝난다. 응답 조회수는 DB의 원자적 증가 결과와 맞춘다.

선택 경로는 PostMapper.xml의 findDetailRows가 posts·users·post_tags·tags를 한 번에 JOIN한다. 태그 수만큼 반복된 PostDetailRow를 Service에서 글 하나와 이름순 태그 목록으로 조립한다. findCommentRows는 comments와 작성자 users를 한 번에 JOIN하고 parentId로 답글 트리를 만든다.

<select id="findCommentRows" resultType="org.example.board.comment.CommentRow">
    SELECT c.id, c.parent_id AS parentId, c.content, c.created_at AS createdAt,
           c.deleted_at AS deletedAt, a.id AS authorId, a.nickname AS authorNickname
    FROM comments c JOIN users a ON a.id = c.author_id
    WHERE c.post_id = #{postId}
    ORDER BY c.created_at, c.id

package org.example.board.comment;


import java.time.LocalDateTime;
import java.util.List;


import com.fasterxml.jackson.annotation.JsonInclude;
import org.example.board.post.AuthorResponse;


// 최상위 댓글은 replies(답글 목록)를 가진다. 답글에는 replies가 없다
public record CommentResponse(
        Long id,
        String content,
        AuthorResponse author,
        boolean deleted,
        LocalDateTime createdAt,
        @JsonInclude(JsonInclude.Include.NON_NULL) List<CommentResponse> replies) {


static final String DELETED_CONTENT = &quot;삭제된 댓글입니다&quot;;

static CommentResponse reply(Comment c) {
    return new CommentResponse(c.getId(), c.getContent(), AuthorResponse.from(c.getAuthor()), false,
            c.getCreatedAt(), null);
}

public PostDetailResponse create(Long userId, PostCreateRequest request) {

            .orElseThrow(() -&gt; new ApiException(ErrorCode.UNAUTHORIZED));
    Post post = new Post(author, request.title(), request.content(),
            Visibility.valueOf(request.visibility()), findOrCreateTags(request.tags()));

    return PostDetailResponse.of(post, post.getViewCount(), false, List.of());

@Transactional
public PostDetailResponse detail(Long postId, Long loginUserId) {
    Post post = postRepository.findDetailById(postId)
            .orElseThrow(() -&gt; new ApiException(ErrorCode.NOT_FOUND, &quot;게시글을 찾을 수 없습니다.&quot;));
    boolean isAuthor = post.getAuthor().getId().equals(loginUserId);
    if (post.getVisibility() == Visibility.PRIVATE &amp;&amp; !isAuthor) {
        // 남의 비공개 글은 &quot;있지만 못 본다&quot;(403)가 아니라 &quot;없다&quot;(404) — 있다는 사실도 흘리지 않는다
        throw new ApiException(ErrorCode.NOT_FOUND, &quot;게시글을 찾을 수 없습니다.&quot;);
    }
    postRepository.increaseViewCount(postId);
    boolean liked = loginUserId != null &amp;&amp; postRepository.countLike(postId, loginUserId) &gt; 0;
    return PostDetailResponse.of(post, post.getViewCount() + 1, liked,
            CommentTree.build(commentRepository.findAllWithAuthorByPostId(postId)));
}

// 이름으로 찾고, 없으면 새로 만든다(tags.name은 UNIQUE)
private Set&lt;Tag&gt; findOrCreateTags(List&lt;String&gt; names) {
    Set&lt;Tag&gt; tags = new LinkedHashSet&lt;&gt;();
    for (String name : names) {
        tags.add(tagRepository.findByName(name).orElseGet(() -&gt; tagRepository.save(new Tag(name))));
    }
    return tags;
}

    Set&lt;Tag&gt; tags = findOrCreateTags(request.tags());
    Post post = new Post(author, request.title(), request.content(),

    PostDetailRow first = rows.get(0);
    if (&quot;PRIVATE&quot;.equals(first.visibility) &amp;&amp; !first.authorId.equals(loginUserId))
        throw new ApiException(ErrorCode.NOT_FOUND, &quot;게시글을 찾을 수 없습니다.&quot;);
    postMapper.increaseViewCount(postId);
    boolean liked = loginUserId != null &amp;&amp; postMapper.countLike(postId, loginUserId) &gt; 0;
    List&lt;String&gt; tags = new ArrayList&lt;&gt;();
    for (PostDetailRow row : rows) if (row.tagName != null) tags.add(row.tagName);
    return new PostDetailResponse(first.id, first.title, first.content,
            Visibility.valueOf(first.visibility), first.viewCount + 1, first.likeCount,
            liked, new AuthorResponse(first.authorId, first.authorNickname), tags,

}

import org.example.board.common.ErrorCode;
import org.springframework.dao.DuplicateKeyException;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;


@Service
public class UserService {


private final UserMapper userMapper;
private final PasswordEncoder passwordEncoder;

public UserService(UserMapper userMapper, PasswordEncoder passwordEncoder) {
    this.userMapper = userMapper;
    this.passwordEncoder = passwordEncoder;
}

@Transactional
public UserResponse signup(SignupRequest request) {
    if (userMapper.existsByEmail(request.email())) {
        throw new ApiException(ErrorCode.DUPLICATE, &quot;이미 가입된 이메일입니다.&quot;);
    }
    User user = new User(request.email(), passwordEncoder.encode(request.password()), request.nickname());
    try {
        userMapper.insert(user);
    } catch (DuplicateKeyException e) {
        // 확인과 저장 사이에 같은 이메일이 먼저 들어간 경우 — DB의 UNIQUE가 마지막 방어선이다
        throw new ApiException(ErrorCode.DUPLICATE, &quot;이미 가입된 이메일입니다.&quot;);
    }
    return UserResponse.from(user);
}

@Transactional(readOnly = true)
public UserResponse me(Long userId) {
    // 토큰은 맞는데 회원이 없다(DB를 되돌린 뒤 옛 토큰 등) — 로그인부터 다시
    User user = userMapper.findById(userId);
    if (user == null) throw new ApiException(ErrorCode.UNAUTHORIZED);
    return UserResponse.from(user);
}


}

#힌트 (막힐 때만)



힌트 1 — 글·작성자·태그를 한 번에


@Query("select distinct p from Post p join fetch p.author left join fetch p.tags "
        + "where p.id = :id and p.deletedAt is null")
Optional<Post> findDetailById(Long id);


태그가 없는 글도 나와야 하니 태그는 left join fetch다. distinct는 태그 수만큼 같은 글이 겹치는 것을 막는다.






힌트 2 — 댓글을 작성자와 함께


Comment 엔티티(comments)를 만든다. post·author·parent는 모두 @ManyToOne(fetch = LAZY)다. 저장소에서 이렇게 읽는다.


@Query("select c from Comment c join fetch c.author where c.post.id = :postId order by c.createdAt, c.id")
List<Comment> findAllWithAuthorByPostId(Long postId);


c.getParent().getId()는 부모를 따로 조회하지 않는다. 지연 로딩 프록시도 id는 이미 알고 있다.






힌트 3 — 평평한 목록 → 트리


    

  1. 한 바퀴 돌며 살아 있는 답글을 Map<부모 id, List<답글>>에 모은다.
    2. 

  2. 다시 돌며 최상위 댓글마다 replies = map.getOrDefault(id, List.of())를 붙인다.
    3. 

  3. 최상위가 삭제됐는데 replies가 비었으면 건너뛴다. 남기면 내용·작성자를 가린다.
    4. 



답글 항목에 replies를 아예 빼고 싶으면 그 필드에 @JsonInclude(JsonInclude.Include.NON_NULL)을 붙이고 답글은 null로 만든다.






힌트 4 — 조회수 +1과 응답 값


@Modifying
@Query("update Post p set p.viewCount = p.viewCount + 1 where p.id = :id")
int increaseViewCount(Long id);


서비스 메서드에 @Transactional이 있어야 한다(@Modifying 쿼리는 트랜잭션 안에서만). 벌크 UPDATE는 이미 읽어 둔 엔티티의 값을 바꾸지 않는다. 응답에는 post.getViewCount() + 1을 싣는다.


"내가 좋아요했나"는 아직 좋아요 엔티티가 없으니(10-10) 네이티브 쿼리로 센다. @Query(value = "select count(*) from post_likes where post_id = :postId and user_id = :userId", nativeQuery = true) long countLike(...)처럼 쓴다.
