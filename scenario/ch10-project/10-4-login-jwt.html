JWT는 숨기는 봉투가 아니라 위조를 막는 서명입니다.

1-6에서는 DB의 토큰 표를 찾아 확인했다. 이번에는 서버가 토큰을 저장하지 않는다. JWT는 서버가 비밀키로 서명한 문자열이다. 서명이 맞으면 서버가 발급한 것이고, 그 안의 sub를 믿는다. 토큰 확인은 1-6과 같은 방식으로 한다. 인터셉터가 한곳에서 확인하고, 컨트롤러는 @LoginUser Long userId 매개변수로 회원 id를 받는다.

실무에서는 이 일을 보통 Spring Security가 한다. 이 단계는 그 안에서 일어나는 일(헤더 읽기 → 서명 확인 → 회원 id 꺼내기 → 401)을 직접 만들어 보는 것이다. Security로 옮기는 법은 "더 깊이"에 있다.

03◇무엇을 만들까설계 포인트열기 ↓
  • JWT는 암호화가 아니라 서명이다. 점(.)으로 나뉜 세 덩어리 중 가운데(페이로드)는 Base64라 누구나 읽는다(jwt.io에 붙여 보라). 비밀번호 같은 비밀은 넣지 않는다. 비밀키는 "위조 방지"에만 쓰인다.
  • 인증은 컨트롤러보다 먼저. 인터셉터는 컨트롤러 메서드 매개변수를 만들기(본문 읽기·@Valid) 전에 돈다. 그래서 토큰 없는 POST는 본문이 깨져 있어도 401이다(10-5에서 확인한다).
  • GET은 비로그인 통과, 나머지는 막기. 목록·상세는 비로그인도 보지만, 로그인하면 결과가 달라진다(내 비공개 글, "내가 좋아요했나"). 그래서 GET에서 헤더가 없으면 그냥 통과시키고, @LoginUser(required = false)가 null을 받는다. GET /users/me처럼 로그인이 필수인 GET은 매개변수 해석기가 401을 던진다.
  • 헤더는 있는데 틀린 토큰은 GET이어도 401. "토큰을 보냈는데 무시당함"보다 "토큰이 틀렸다"를 알려 주는 편이 프론트가 고치기 쉽다.
  • 로그인 실패 문구를 하나로. "없는 이메일입니다"와 "비밀번호가 틀렸습니다"를 나누면 남의 가입 여부를 캐낼 수 있다.
  • 로그인에는 가입의 72바이트 규칙을 걸지 않는다. 10-3에서 막은 것은 encode가 72바이트를 넘으면 예외를 던지기 때문이다. 로그인의 matches는 예외 없이 앞 72바이트만 비교해 500이 나지 않는다(F4). 가입이 72바이트를 넘는 비밀번호를 받지 않으니, 그런 입력은 틀린 비밀번호와 똑같이 401로 답하면 된다. 규칙은 비밀번호를 정할 때(가입) 검사한다 — 규칙이 바뀌어도 예전 규칙으로 가입한 회원은 로그인할 수 있어야 한다. 단, 정확히 72바이트(한글 24자)로 가입한 회원은 뒤에 무엇을 붙여도 로그인된다. 앞 72바이트를 모두 알아야 하니 구멍은 아니다.

Service — 처리 순서

AuthService.java, UserService.java. 위 서버 처리 순서가 어디에서 검증·조회·상태 변경으로 이어지는지 따라간다. 변경된 메서드: login, me. 트랜잭션 경계는 아래 코드의 @Transactional 위치에서 확인한다.

@Transactional(readOnly = true)
public TokenResponse login(LoginRequest request) {
    User user = userRepository.findByEmail(request.email())
            .orElseThrow(() -> new ApiException(ErrorCode.UNAUTHORIZED, LOGIN_FAILED));
    if (!passwordEncoder.matches(request.password(), user.getPasswordHash())) {
        throw new ApiException(ErrorCode.UNAUTHORIZED, LOGIN_FAILED);
    }
    return new TokenResponse(jwtProvider.issue(user.getId()), jwtProvider.validitySeconds());
}

@Transactional(readOnly = true)
public UserResponse me(Long userId) {
    User user = userRepository.findById(userId)
            .orElseThrow(() -> new ApiException(ErrorCode.UNAUTHORIZED));
    return UserResponse.from(user);
}

없는 이메일과 틀린 비밀번호가 같은 LOGIN_FAILED 문구를 쓴다. me는 DB에서 회원을 다시 읽어 해시가 빠진 DTO로 돌려준다.

MyBatis / Mapper — 가입에서 로그인·내 정보까지 이어가기

10-3의 MyBatis 선택 경로를 계속 쓸 때는 findByEmail과 findById SQL을 추가한다. AuthService는 첫 조회 결과가 없으면 401, 있으면 같은 PasswordEncoder.matches를 쓴다. UserService.me도 조회 결과가 없으면 401이다. 인터셉터·JWT·Controller의 계약은 JPA 경로와 같다.

<select id="findByEmail" resultType="org.example.board.user.User">
    SELECT id, email, password_hash, nickname, created_at
    FROM users WHERE email = #{email}
</select>
<select id="findById" resultType="org.example.board.user.User">
    SELECT id, email, password_hash, nickname, created_at
    FROM users WHERE id = #{id}
</select>

MyBatis 설정의 map-underscore-to-camel-case: true가 password_hash를 passwordHash에 매핑한다. 아래 MyBatis 대체 구현 코드에는 JPA Repository 삭제, POJO·Mapper·Service·설정의 파일 전문이 있다. 기본 10-4 스냅샷에 적용하면 독립적으로 실행된다.

private ResponseEntity<ApiResponse<Void>> fail(ErrorCode code, String message, List<FieldErrorItem> errors) {
    ResponseEntity.BodyBuilder builder = ResponseEntity.status(code.status());
    if (code == ErrorCode.UNAUTHORIZED) {
        builder.header(HttpHeaders.WWW_AUTHENTICATE, "Bearer");
    }
    return builder.body(ApiResponse.fail(code, message, errors));
}

    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
        // 브라우저의 CORS 사전 요청(OPTIONS)은 토큰 없이 온다 — 막으면 실행 칸 전체가 CORS로 실패한다

            return true;

        if (header == null) {
            // 조회(GET)는 비로그인도 된다. 쓰기는 토큰이 있어야 한다
            if (HttpMethod.GET.matches(request.getMethod())) {
                return true;
            }
            throw new ApiException(ErrorCode.UNAUTHORIZED);
        }
        if (!header.startsWith(BEARER_PREFIX)) {
            throw new ApiException(ErrorCode.UNAUTHORIZED, "Authorization 헤더는 'Bearer <토큰>' 형식이어야 합니다.");
        }
        Long userId = jwtProvider.parseUserId(header.substring(BEARER_PREFIX.length()).trim());
        request.setAttribute(USER_ID_ATTRIBUTE, userId);
        return true;
    }

import org.example.board.common.ErrorCode;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

// 액세스 토큰 발급·검증 — HS256, sub = 회원 id, 유효 시간은 설정값(기본 1시간)
@Component
public class JwtProvider {

    private final SecretKey key;
    private final long validitySeconds;

    public JwtProvider(@Value("${app.jwt.secret}") String secret,
                       @Value("${app.jwt.validity-seconds}") long validitySeconds) {
        this.key = Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
        this.validitySeconds = validitySeconds;
    }

    public String issue(Long userId) {
        Instant now = Instant.now();
        return Jwts.builder()
                .subject(String.valueOf(userId))
                .issuedAt(Date.from(now))
                .expiration(Date.from(now.plusSeconds(validitySeconds)))
                .signWith(key, Jwts.SIG.HS256)
                .compact();
    }

    public long validitySeconds() {
        return validitySeconds;
    }

    // 서명이 틀리거나, 만료됐거나, 형식이 깨졌으면 모두 401 — 이유를 응답에 자세히 싣지 않는다
    public Long parseUserId(String token) {
        try {
            String subject = Jwts.parser().verifyWith(key).build()
                    .parseSignedClaims(token).getPayload().getSubject();
            return Long.valueOf(subject);
        } catch (JwtException | IllegalArgumentException e) {
            throw new ApiException(ErrorCode.UNAUTHORIZED, "토큰이 올바르지 않거나 만료되었습니다.");
        }
    }
}

@RestControllerAdvice
public class GlobalExceptionHandler {

    private static final Logger log = LoggerFactory.getLogger(GlobalExceptionHandler.class);

    // 서비스가 던진 실패(401·403·404·409 …)
    @ExceptionHandler(ApiException.class)
    public ResponseEntity<ApiResponse<Void>> handleApi(ApiException e) {
        return fail(e.code(), e.getMessage(), List.of());
    }

    // @Valid 검증 실패 — 필드별 이유를 errors에 담는다
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ApiResponse<Void>> handleInvalid(MethodArgumentNotValidException e) {
        List<FieldErrorItem> errors = e.getBindingResult().getFieldErrors().stream()
                .map(fe -> new FieldErrorItem(fe.getField(), fe.getDefaultMessage()))
                .sorted(Comparator.comparing(FieldErrorItem::field))
                .toList();
        return fail(ErrorCode.VALIDATION_FAILED, ErrorCode.VALIDATION_FAILED.defaultMessage(), errors);
    }

    // 쿼리·경로 값의 타입이 틀림(?page=abc, /posts/abc)
    @ExceptionHandler(MethodArgumentTypeMismatchException.class)
    public ResponseEntity<ApiResponse<Void>> handleTypeMismatch(MethodArgumentTypeMismatchException e) {
        return fail(ErrorCode.VALIDATION_FAILED, ErrorCode.VALIDATION_FAILED.defaultMessage(),
                List.of(new FieldErrorItem(e.getName(), "형식이 올바르지 않습니다.")));
    }

    // 필수 쿼리 파라미터 없음
    @ExceptionHandler(MissingServletRequestParameterException.class)
    public ResponseEntity<ApiResponse<Void>> handleMissingParam(MissingServletRequestParameterException e) {
        return fail(ErrorCode.VALIDATION_FAILED, ErrorCode.VALIDATION_FAILED.defaultMessage(),
                List.of(new FieldErrorItem(e.getParameterName(), "필수 값입니다.")));
    }

    // 본문이 JSON이 아니거나 깨짐
    @ExceptionHandler(HttpMessageNotReadableException.class)
    public ResponseEntity<ApiResponse<Void>> handleBadJson(HttpMessageNotReadableException e) {
        return fail(ErrorCode.BAD_JSON, ErrorCode.BAD_JSON.defaultMessage(), List.of());
    }

    // 없는 주소
    @ExceptionHandler(NoResourceFoundException.class)
    public ResponseEntity<ApiResponse<Void>> handleNoResource(NoResourceFoundException e) {
        return fail(ErrorCode.NOT_FOUND, "요청한 주소가 없습니다.", List.of());
    }

    // 주소는 있는데 메서드가 다름(DELETE /api/v1/health)
    @ExceptionHandler(HttpRequestMethodNotSupportedException.class)
    public ResponseEntity<ApiResponse<Void>> handleMethod(HttpRequestMethodNotSupportedException e) {
        return fail(ErrorCode.METHOD_NOT_ALLOWED, ErrorCode.METHOD_NOT_ALLOWED.defaultMessage(), List.of());
    }

    // 그 밖의 예상 못 한 예외 — 원인은 로그에만 남기고, 응답에는 내부 정보를 싣지 않는다
    @ExceptionHandler(Exception.class)

    // 없는 이메일과 틀린 비밀번호를 같은 문구로 — 어느 이메일이 가입돼 있는지 흘리지 않는다
    private static final String LOGIN_FAILED = "이메일 또는 비밀번호가 올바르지 않습니다.";

    private final UserMapper userMapper;
    private final PasswordEncoder passwordEncoder;
    private final JwtProvider jwtProvider;

    public AuthService(UserMapper userMapper, PasswordEncoder passwordEncoder, JwtProvider jwtProvider) {
        this.userMapper = userMapper;
        this.passwordEncoder = passwordEncoder;
        this.jwtProvider = jwtProvider;
    }

    @Transactional(readOnly = true)
    public TokenResponse login(LoginRequest request) {
        User user = userMapper.findByEmail(request.email());
        if (user == null) throw new ApiException(ErrorCode.UNAUTHORIZED, LOGIN_FAILED);
        if (!passwordEncoder.matches(request.password(), user.getPasswordHash())) {
            throw new ApiException(ErrorCode.UNAUTHORIZED, LOGIN_FAILED);
        }
        return new TokenResponse(jwtProvider.issue(user.getId()), jwtProvider.validitySeconds());
    }

public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
    if (CorsUtils.isPreFlightRequest(request)) return true;          // preflight 통과
    String header = request.getHeader(HttpHeaders.AUTHORIZATION);
    if (header == null) {
        if (HttpMethod.GET.matches(request.getMethod())) return true; // 비로그인 조회
        throw new ApiException(ErrorCode.UNAUTHORIZED);
    }
    if (!header.startsWith("Bearer ")) throw new ApiException(ErrorCode.UNAUTHORIZED);
    request.setAttribute("loginUserId", jwtProvider.parseUserId(header.substring(7).trim()));
    return true;
}
