작업 수용·거절·종료를 확인하기

작업을 무한히 쌓아 두지 않고 처리 가능한 수와 거절·종료 동작을 정합니다.

이번에 할 일

worker 2·대기열 2에서 작업 5개를 동시에 막아 수용·거절을 확인하고 종료 뒤 남은 작업을 식별하세요.

시작 조건

  • 실행 중 작업을 테스트 신호로 멈출 수 있는 격리 실행기를 준비합니다.
  • 작업별 가짜 id와 제출·시작·종료 시각을 기록합니다.

사용자 시나리오

  1. 시작
    worker 2개와 queue 2개를 모두 점유한 상태에서 다섯 번째 작업을 제출합니다.
    행동
    모든 작업을 막아 둔 채 수용 결과를 기록하고, 해제 후 종료 요청과 새 작업 제출을 시험합니다.
    결과
    처리 중 2개·대기 2개·수용 불가 1개를 구분하고 종료 뒤 신규 작업은 정한 방식으로 거절합니다.
    이후
    무한 대기가 없고 종료 제한 시간·미완료 id·문맥 정리 결과가 남아야 합니다.

데이터와 이유

작업 id와 상태
수용 실패와 처리 실패를 구분하고 미완료 대상을 찾습니다.
대기·실행 시각
줄을 선 시간과 실제 실행 시간을 나눕니다.

업무 정책

  • 포화 시 호출자 실행·거절 등 선택한 정책과 관찰 결과를 명시합니다.
  • 종료 제한 시간은 직접 정하고 실측과 구분합니다.
  • 이 결과를 이후 쿠폰 작업 설계의 입력으로 남깁니다.

입력과 출력

  • worker=2, queue=2, 차단 가능한 작업 5개, 종료 제한 시간

성공 기준

  • 처리 중 2개·대기 2개·수용 불가 1개를 구분하고 종료 뒤 신규 작업은 정한 방식으로 거절합니다.

실패와 데이터 보존

  • 실행기 포화 또는 종료 후 제출 → 선택한 거절 결과가 호출자에게 보입니다. · 유지: 수용하지 않은 작업을 완료했다고 기록하지 않습니다.

입력 사례

  • 같은 대상의 전후 비교

개발 과제

  • worker 2·대기열 2에서 작업 5개를 동시에 막아 수용·거절을 확인하고 종료 뒤 남은 작업을 식별하세요.

완료 확인

  • worker 2·queue 2에서 작업 5개를 막고 수용/거부·대기 시간·문맥 정리를 기록한다. 무한 대기를 금지한다.
  • shutdown 뒤 새 작업 거부, 제한 시간 내 종료와 미완료 작업 식별을 테스트한다. 이 결과를 D32 작업 설계의 입력으로 적는다.

직접 실행하고 기록하기

명령을 자동 실행하지 않습니다. 직접 실행한 뒤 결과를 기록하세요.
