태그 연결을 목록 응답으로 바꾸기

1-9 공개 글의 post_tag join 결과를 태그 이름 배열로 변환하고 글 상태별 접근 규칙을 확인한다.

이번에 할 일

post2 tag 목록, 태그 없는 공개 글, 없는 id를 조회해 `[name]` response와 글 정보 비노출을 확인한다.

시작 조건

  • 기본 post2의 tag java/jpa relation을 확인한다.
  • 1-3 POST로 tags=[]인 공개 글을 만들고 실제 response id를 캡처한다.

사용자 시나리오

  1. 시작
    post2와 tagless captured post의 post_tag/tag rows를 기록한다.
    행동
    GET /api/posts/2/tags, GET /api/posts/{taglessId}/tags, GET /api/posts/999999/tags.
    결과
    두 공개 글 모두 200 JSON array; post2 [java,jpa], tagless []. 없는 글은 404.
    이후
    삭제·private/unpublished source 글에도 태그 정보가 노출되지 않는지 404 확인.

데이터와 이유

post2 post_tag→tag(java,jpa)
응답 tag names and relation join 검증.
tagless post actual id with no relations
empty array vs null distinction.
post status/visibility/deleted_at
태그 조회가 글 visibility/access 정책을 우회하지 않음.
TagResponse name-only
응답에서 entity internals/IDs를 노출하지 않음.

업무 정책

  • GET /api/posts/{postId}/tags returns 200 array of `{name}` only.
  • public readable post with no tags returns 200 []; no null or fabricated empty tag object.
  • missing/deleted/private/unpublished source returns 404; do not disclose whether tags exist.
  • This stage assesses JPA collection/stream mapping; MyBatis alternative is not supplied and remains ungraded until authored.

입력과 출력

  • GET /api/posts/2/tags.
  • GET /api/posts/{captured tagless id}/tags.
  • GET /api/posts/999999/tags plus hidden/deleted id if fixture provides.

성공 기준

  • post2 returns 200 [{name:"java"},{name:"jpa"}] in stored/source order.
  • tagless public post returns 200 [].
  • Response item only contains name.

실패와 데이터 보존

  • post id missing/deleted/private → 404. · 유지: no post/tag state changes and no tag names exposed.
  • tagless route returns 404/null instead of empty array → contract assertion fails. · 유지: post remains tagless.

입력 사례

  • Tagged post
  • No tags
  • Missing post

개발 과제

  • Use response id for tagless fixture instead of hard-coded guessed id.
  • Join actual post_tag/tag rows and compare response name array.
  • Check hidden/deleted no-leak result separately.

완료 확인

  • tag names list matches relation rows.
  • tagless 200 [] distinguished from missing 404.
  • missing/deleted/private status does not disclose tag data.

선택한 API 계약

GET/api/posts/2/tags200

C1: HTTP 상태 200이어야 합니다. C1: JSON 경로 $ type "array", length 2이어야 합니다. C1: JSON 경로 $[0].name type "string"이어야 합니다. C1: JSON 경로 $[1].name type "string"이어야 합니다.
