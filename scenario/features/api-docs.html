명세와 실제 API의 입력·응답 맞추기

OpenAPI 문서가 실제 요청·응답 계약과 일치하고 사용자가 직접 실행할 수 있게 한다.

이번에 할 일

Swagger UI와 사용자용 API 그룹을 구성하고 명세와 검증 결과를 맞춘다.

시작 조건

  • 시나리오 DB(`community`) — 앱을 기본 프로파일로 띄운다.
  • community app 의존성 및 13-7에서 정한 springdoc 버전·접근 경로를 확인한다.

사용자 시나리오

  1. 시작
    사용자용 API와 운영자용 API가 실제 서버에 구현돼 있습니다.
    행동
    /v3/api-docs/public과 원본 문서 경로를 열어 실제 operation·입력·응답·Bearer 설정을 비교합니다.
    결과
    public 명세는 OpenAPI 3.1과 javaExperience 게시판 API 제목, HTTP bearerAuth 설정을 제공합니다.
    이후
    문서의 경로·필드·오류 예시와 실제 서버의 응답을 대조합니다. 명세 파일이 열린 것만으로 모든 API 실행 완료로 표시하지 않습니다.

데이터와 이유

실제 controller method/path/status와 OpenAPI operation
문서 정의와 실행 응답을 같은 endpoint로 비교한다.
public/admin group 설정
사용자용 그룹의 우선 노출과 운영용 API 분리를 확인한다.

업무 정책

  • API path/method/status/error schema와 bearer 인증 표시는 실제 controller/security 설정을 따른다. 원문에 없는 endpoint를 추가하지 않는다. 문서 그룹은 사용자용 먼저.
