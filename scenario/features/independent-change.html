이번에 할 일

진행자가 준 새 업무 한 개를 모델/API/SQL/정책으로 정리하고 실패 테스트→구현→불변식/권한/호환→배포/실패 대응까지 수행하세요.

시작 조건

  • D35~D37과 다른 요구를 진행자에게 받습니다. 예시는 보존 기간 뒤 쿠폰 지급 이력 익명 조회이며 강제 과제가 아닙니다.
  • 정확한 입력·기간·상태·오류는 새 요구에서 합의하고 아래 실제 계약에 등록합니다.
  • 힌트와 예시 해법을 쓰지 않은 독립 범위를 기록하며, 필요하면 힌트를 열 수 있지만 도움받은 범위를 남깁니다.

사용자 시나리오

  1. 시작
    기존 서비스는 정상이고 진행자가 새로운 작은 사용 결과를 요청합니다.
    행동
    대안/비용/범위를 정하고 미충족 계약 테스트를 실패시킨 뒤 최소 구현·반례·배포 순서·실패 중단/복귀를 확인합니다.
    결과
    새로 확정한 사용 시나리오가 동작하며 기존 권한·정합성·호환이 유지됩니다.
    이후
    설계·구현·SQL·설명 각 영역을 통과/실패/확인 불가로 증거와 함께 기록하고, 새 반론 하나로 결정을 갱신합니다.

데이터와 이유

새 업무 입력·상태·보관 정책
원래 과제의 제목만 바꾸지 않고 관찰 가능한 새 결과를 정합니다.
수행 증거·소요·도움
직접 구현 범위와 보류 영역을 구분합니다.

업무 정책

  • 개발 전에 존재하지 않는 API 경로·보존 기간을 기본 정답으로 만들지 않습니다.
  • 원래 정상 동작을 약화해 RED를 만들지 않습니다.
  • 배포/데이터 이행 불필요 판정에도 근거를 기록합니다.

입력과 출력

  • 진행자의 새 요구·확정 입력/성공/실패·선행 데이터·기존 회귀·배포/중단/복귀 조건

성공 기준

  • 새로 확정한 사용 시나리오가 동작하며 기존 권한·정합성·호환이 유지됩니다.

실패와 데이터 보존

  • 새 반례 또는 기존 회귀에서 실패 → 해당 영역을 실패/보류로 남기고 결정을 수정합니다. · 유지: 기존 사용자 데이터·권한·완료 이력을 무관하게 변경하지 않습니다.
