글 등록하기

로그인한 회원이 쓴 제목·본문·태그를 저장해 다음 요청에서도 같은 글을 읽을 수 있게 만듭니다.

이번에 할 일

작성자는 로그인한 회원으로 정하고 글과 태그 연결을 저장하세요. 생성한 글의 위치를 응답하고, 잘못된 요청은 저장하지 마세요.

시작 조건

  • 서버와 MySQL을 실행하고 회원 가입·로그인을 마칩니다. 이 단계는 board 프로젝트의 API 계약을 사용합니다.
  • 게시글 데이터 구조와 공유 태그 관계를 직접 설계합니다. 태그가 다른 글에서도 사용될 수 있다는 조건을 지켜야 합니다.

사용자 시나리오

  1. 시작
    로그인한 회원이 제목 ‘첫 기록’, 본문 ‘오늘 배운 내용’, 태그 ‘spring’을 입력합니다.
    행동
    정상 글 등록 요청을 보냅니다. 작성자 번호를 임의의 본문 값으로 바꾸어 신뢰하지 않습니다.
    결과
    생성된 글의 위치를 Location으로 받습니다. 응답 본문을 받은 것으로 가정하지 않습니다.
    이후
    확인한 실제 id로 다음 단계에서 조회했을 때 같은 제목·본문·태그가 보여야 합니다.

데이터와 이유

게시글
누가 어떤 제목과 본문을 언제 썼는지 보관하고 고유 id로 다시 찾습니다.
태그와 글별 연결
같은 이름의 태그를 여러 글에서 재사용하되 각 글의 연결을 구분합니다.

업무 정책

  • 작성자는 인증한 회원이며 본문의 authorId로 정하지 않습니다.
  • 이번 요청의 글·태그 변경은 같은 트랜잭션으로 확정되거나 취소되어야 합니다. 이전부터 있던 공유 태그를 요청 실패를 이유로 지우면 안 됩니다.
  • 테이블·키·제약을 직접 선택하되 글과 작성자, 글과 태그의 관계가 일관돼야 합니다. 요청 DTO와 저장 Entity의 역할을 구분합니다.

입력과 출력

  • 제목·본문은 실제 저장할 내용입니다. tags는 글에 붙일 이름 목록입니다. 정확한 필수 여부와 허용 범위는 아래 선택한 API 계약에 표시합니다.
  • 인증 정보는 Bearer 토큰 입력란에 넣습니다. 토큰을 학습 기록으로 저장하지 않습니다.

성공 기준

  • 새 글이 저장되고 생성 위치를 응답합니다. 실제 응답의 id를 사용해 조회와 DB 재확인을 이어갑니다.

실패와 데이터 보존

  • 제목이 공백이거나 본문 등 DTO 조건을 지키지 않은 요청 → 검증 오류와 해당 필드를 알려야 합니다. · 유지: 새 글과 요청에 따른 태그 연결이 남으면 안 됩니다.
  • 인증 토큰이 없는 쓰기 요청 → 인증되지 않았음을 응답합니다. · 유지: 요청자가 임의로 지정한 작성자의 글이 저장되면 안 됩니다.
  • 글 또는 태그를 저장하다 중간에 오류가 발생 → 요청을 실패로 처리합니다. · 유지: 일부 저장만 남지 않아야 하며 기존 공유 태그는 보존합니다.

입력 사례

  • 정상 등록
  • 공백 제목

개발 과제

  • 입력·인증·저장·응답이 하나의 글 등록 기능으로 이어지게 구현합니다. 클래스 생성 순서를 그대로 따라 치는 과제가 아닙니다.
  • 직접 설계한 저장 구조가 정상·실패·공유 태그 사례를 모두 만족하는지 확인합니다.

완료 확인

  • 정상 요청의 상태·Location을 확인하고 같은 id로 저장 결과를 다시 읽었습니다.
  • 제목 공백과 미인증 요청에서 새 글이 남지 않는 것을 확인했습니다.
  • 중간 저장 실패의 취소 범위와 기존 공유 태그 보존을 코드·격리 테스트 또는 DB 관찰로 설명할 수 있습니다.

같은 이름의 태그를 여러 글에서 재사용하되 각 글의 연결을 구분합니다.

    
업무 정책
  • 게시판을 찾고 작성 권한을 확인한 회원만 그 게시판에 글을 쓸 수 있습니다. 작성자는 인증된 회원입니다.
  • 공개 범위의 기본값은 PUBLIC이며 허용되지 않은 값은 검증 오류입니다. 생성된 글은 PUBLISHED이고 카운터는 0, 삭제 시각은 비어 있습니다.
  • 태그는 이름으로 재사용하거나 새로 만들고 이번 글과 연결합니다. 이번 글·새 태그·연결은 함께 확정되거나 취소되며 기존 공유 태그는 지우지 않습니다.
  • 생성 응답 JSON의 id와 Location은 같은 글이어야 합니다. 이전 요청 받기 연습의 success만 반환하는 버전과 구분합니다.
  • DB에 직접 쓰면 앱의 DTO 검증과 작성 권한 검사가 자동 실행되는 것이 아닙니다. 어떤 제약을 DB가 보장하고 앱이 보장하는지 구분합니다.
