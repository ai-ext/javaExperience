연·월 경계를 기준으로 목록 묶기

게시글 수를 연·월별로 묶고 해당 월 글은 동일한 시간 경계로 조회한다.

이번에 할 일

월 아카이브 집계와 월별 목록을 구현한다.

시작 조건

  • 시나리오 DB(`community`) — 앱을 기본 프로파일로 띄운다.
  • community Clock/timezone과 공개 게시글 기준을 확인한다.

사용자 시나리오

  1. 시작
    같은 게시판에 2026년 9월 30일 글과 10월 1일 글이 있습니다.
    행동
    월별 글 수와 2026년 9월 목록을 각각 요청합니다.
    결과
    월 집계는 글이 있는 달부터 최신순이며 9월 목록은 9월 1일 00:00 이상·10월 1일 00:00 미만입니다.
    이후
    0월은 400, 없는 게시판은 404이고 공개 범위·삭제·상태 조건은 기존 목록과 같습니다.

데이터와 이유

published_at 월 구간 [2026-09-01,2026-10-01)
9월 30일 포함과 10월 1일 제외를 동일 목록/count 조건으로 검증한다.
free board 비로그인/이스프링 visibility
비로그인 9월 count=9, 이스프링은 FOLLOWERS 게시글 6을 더해 10이 된다.

업무 정책

  • GET /api/boards/{slug}/archive는 글이 있는 달의 수를 최신 달부터 반환한다. GET /api/boards/{slug}/archive/{year}/{month}는 2-2 목록 필드를 그대로 쓴다.
  • 월 목록 범위는 [첫날 00:00, 다음 달 첫날 00:00); 2026년 9월 30일 글은 포함, 10월 1일 글은 제외한다. 사용자의 공개 권한과 삭제/status 조건은 2-2와 같다.
  • year 2000~2100, month 1~12, page>=0 기본 0, size 1~50 기본10. 빈 page/size 또는 int 초과 400, 없는 board 404.

성공 기준

  • 2026년 9월 비로그인 count=9, 목록 totalElements=9, id=[17,16,15,14,13,12,9,5,4].
  • 이스프링 기준 count=10, 9월 글 없음은 HTTP 200 + 빈 목록이다.

실패와 데이터 보존

  • GET /api/boards/free/archive/2026/0 입력이 원문 실패 check 조건에 해당 → HTTP 400 — 원문 check의 실패 응답 · 유지: GET 요청은 post 행/published_at을 변경하지 않는다.
  • GET /api/boards/free/archive/2026/0 · [교육용 fixture · legacy:14-7:A8] 잘못된 입력 — 0월 → HTTP 400 (A8) · 유지: GET은 post/published_at 행을 바꾸지 않는다.
  • GET /api/boards/nope/archive · [교육용 fixture · legacy:14-7:A9] 없는 게시판의 아카이브 → HTTP 404 (A9) · 유지: GET은 post/published_at 행을 바꾸지 않는다.

GET/api/boards/free/archive200
