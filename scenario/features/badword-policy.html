정해진 필드와 일치 규칙으로 금칙어 판단하기

글·댓글의 BLOCK 단어는 저장 전에 400으로 거절하고 MASK 단어는 별표로 바꿔 저장하세요. 공백을 끼운 BLOCK 단어도 막고 모든 관련 쓰기에서 같은 정책을 확인합니다.

1 · 이번에 할 일

검증 위치에 정책을 한 번 적용하고 정상/거절 요청 차이를 확인한다.

2 · 시작 조건

  • 시나리오 DB(`community`) — 앱을 기본 프로파일로 띄운다.
  • community 게시글 등록 및 원문 금칙어 사전/정책을 준비한다.

3 · 세부 요구사항

입력과 출력
  • legacy:13-4:FA: POST /api/admin/banned-words; body={"word":"임시금칙어","action":"BLOCK"}; case=기존 글 작성 후 금칙어 추가; source expected/status checks=[{"id":"C8","pointer":"/checks/7","request":"FA","expect":{"status":201}}]
  • legacy:13-4:P0: POST /api/posts; body={"boardSlug":"free","title":"[채점] 정상 글","content":"안전한 내용"}; case=글 수정 확인용 글; source expected/status checks=[{"id":"C6","pointer":"/checks/5","request":"P0","expect":{"status":201}}]

성공 기준
  • 정상 글은 기존 입력 검증/저장 규칙 그대로 통과.
개발 과제
  • 사전 로딩/갱신 경로와 서버 입력 검증을 연결하고 실제 규칙만 구현한다.

데이터와 이유

banned_word.word, action, active 상태
운영자가 등록한 실제 정책과 글 입력의 매치를 확인한다.
POST title/content와 post/tag 행
정상/차단 사례의 저장 결과를 비교한다.

업무 정책

  • 이미 등록된 금칙어를 추가하면 409이며 banned_word의 단어·action·행 수를 유지합니다. BLOCK이 들어 있는 글·댓글 저장은 400이며 오류가 난 모든 필드를 errors[]에 넣고 post/post_tag/tag/comment 저장을 남기지 않습니다.
  • BLOCK 단어는 저장 전 거절 400과 errors field 목록을 반환한다. 공백을 제거하고 대소문자 무시해 비교하므로 `도 박 사 이 트`도 `도박사이트`로 차단한다.
  • MASK 단어는 같은 길이의 별표로 저장한다(바보→**; 멍청이→***). 작성·복사·PUT/PATCH·발행·복구와 댓글 작성/수정의 8개 쓰기 경로를 같은 정책으로 검사한다.
  • banned word 2~30자, 공백 금지; action BLOCK|MASK. 목록/추가/삭제는 ADMIN MANAGE_BANNED_WORD만; 중복 추가 409, 없는 id 삭제 404.

입력 사례

  • 교육용 데이터로 전후 확인
    입력 전
    BLOCK 단어 도박 사이트와 MASK 단어 바보가 등록된 교육용 상태입니다.
    행동
    공백을 끼운 BLOCK 단어와 MASK 단어를 글·댓글의 관련 쓰기 경로로 보냅니다.
    결과
    작성·복사·전체/부분 수정·발행·복구·댓글 작성/수정의 8개 경로에 같은 정책을 적용합니다. 거절에는 글과 관계 변경이 없습니다.
  • 구체 값과 전후 비교 · 본문 최고의 도박사이트 안내 및 공백을 넣은 도 박 사 이 트는 400/content 오류입니다. 댓글 [채점] 너 정말 바보 같아는 201로 [채점] 너 정말 ** 같아를 저장합니다. 금칙어 삭제 204 뒤에는 같은 단어를 허용하는 원문 B5 사례를 확인합니다.
