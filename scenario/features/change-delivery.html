이번에 할 일

허용된 실제 이슈 하나를 고르거나 취소 사유 필수화를 선택합니다. 요구·대안·추정을 정하고, 수정 전 실패 확인부터 최소 구현·회귀·복귀까지 완료하세요.

시작 조건

  • D25 예약 취소와 D34 작업의 현재 계약/통과 증거를 준비합니다.
  • 실제 이슈가 없으면 취소 사유 누락·공백은 422, 같은 key와 같은 사유에는 같은 결과, 다른 사유에는 409를 반환하는 제공 변형을 사용합니다.
  • 이미 충족했다면 정상 코드를 약화하지 말고, 두 운영자 승인 또는 새 미충족 요구를 합의합니다.

사용자 시나리오

  1. 시작
    운영자가 기존 예약을 취소하면서 사유를 남겨야 합니다. 같은 멱등 키로 재요청할 수도 있습니다.
    행동
    새 요구를 테스트해 RED를 확인한 뒤, 사유를 성공 응답·감사 기록에 보존하고 같은 사유와 다른 사유로 재요청합니다.
    결과
    사유 누락/공백에는 422, 같은 키와 같은 사유에는 같은 결과, 다른 사유에는 409를 반환합니다. 시작 후 취소 거부와 기존 지급 보존은 유지됩니다.
    이후
    정상·권한·없음·중복·동시 반례와 기존 API 회귀를 확인합니다. 예상 범위와 실제 소요를 비교하고 배포/복귀 smoke를 기록합니다.

업무 정책

  • 두 운영자 승인 대안은 첫 승인 202, 같은 운영자의 반복 승인은 409, 다른 운영자의 최종 승인은 200입니다.
  • 선택조회대안은회원별최근지급1건또는예약별최근실패TOPN으로범위를제한하며MyBatis ROW_NUMBER/PARTITION BY를씁니다.
  • 마감이 하루 단축되거나 담당자가 부재한 경우에도 검증/배포/실패 대응의 유지선을 명시합니다.

완료 확인

  • 접근 허용된 실제 업무의 작은 계약 변경 1건을 고른다. 없으면 D25의 기존 예약 취소 API를 바꾼다: 취소 사유를 필수로 받아 누락·공백은 422, 성공 응답·감사 기록에 사유 보존, 동일 멱등 키·같은 사유 재요청은 같은 결과, 다른 사유는 409다. 시작 전 취소/시작 후 거부·기존 지급 보존은 유지한다.
  • 관찰 사실·가정·미확인·성공/실패 계약·대안 2개·제외 범위를 적고 요구·모델/SQL·구현·검증·이행으로 작업을 나눈다.
  • 이미 충족한 경우 현 계약과 통과 증거를 먼저 남긴다. 대체 새 계약은 서로 다른 운영자 2명의 취소 승인이다: 첫 승인 202·같은 운영자의 두 번째 승인 409·다른 운영자의 최종 승인 때만 취소 200으로 합의한다. 이것도 이미 충족하면 담당자/훈련 진행자와 기존 성공·실패 기대값을 실제로 바꾸는 작은 요구를 새로 합의한다. 정상 코드를 약화하지 않는다. D36 전 미충족 계약 한 줄과 현재 결과를 확정한다.
  • 선택 과제로 기존 개인 조회 요구 대신 회원별 최근 지급 1건 또는 예약별 최근 실패 TOP N을 합의할 수 있다. MyBatis의 MySQL ROW_NUMBER()·PARTITION BY를 쓰며 동률 정렬 키·빈 결과·대상 필터를 명세화한다. D36 구현 범위를 이 조회 하나로 제한한다.
  • 금요일 마감이라는 요청에 각 작업의 최소–최대 추정·근거·의존성·불확실성·버퍼·재산정 시점을 제시한다. 실측 일정이라고 부르지 않는다.
  • 마감이 하루 앞당겨지고 담당자가 없다는 반론에 범위 축소안·포기할 기능·검증/배포/실패 대응 유지선을 제시하고 결정권자에게 승인을 요청하는 합의문을 쓴다.
  • D35에서 합의한 새 성공/실패 계약을 테스트해 RED를 남기고 최소 변경으로 GREEN을 만든다. 이미 모든 새 테스트가 통과하면 D35로 돌아가 통과 증거를 남기고 미충족 새 계약을 합의한다. 정상 코드 약화·기대값 조작으로 RED를 만들지 않는다.
  • 실제 수정 파일·설계 선택·데이터 전후·도움받은 범위를 기록한다. 실제 이슈가 없으면 D35에서 합의한 취소 사유 또는 두 운영자 승인 계약의 실패·중복·동시 요청 반례를 구현한다.
  • D35에서 윈도 함수 조회를 골랐다면 MyBatis SQL을 구현하고 동일 시각 동률·빈 결과·예약 밖 행 반례를 RED→GREEN으로 확인한다. 다른 새 업무를 동시에 추가하지 않는다.
  • 정상·권한·대상 없음·중복·동시 요청 중 해당 이슈의 반례를 실행하고 기존 API 회귀를 확인한다.
  • D35 작업별 예상 범위와 실제 소요·원인·남은 불확실성을 비교하고 배포/롤백 smoke를 남긴다.
