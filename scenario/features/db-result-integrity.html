선택 정보·집계·존재 조건을 정확하게 조립하기

선택 정보가없는행도보존하고여러일대다관계의행곱셈이집계를왜곡하지않게합니다.

이번에 할 일

상세의 필수/선택 JOIN, 좋아요 2개·댓글 3개의 합성 집계, 좋아요를 눌렀지만 북마크하지 않은 글의 존재 조건을 직접 SELECT로 검증하세요.

시작 조건

  • 상세·합성 CTE는 원문 community 연결을, 좋아요/북마크 M9-6은 practice 연결을 사용합니다.
  • 원문 합성 id 41/42와 71/72/73은 실제 게시글 집계가 아닌 설명용 데이터입니다.

사용자 시나리오

  1. 시작
    글 한 개에 좋아요 2개·살아 있는 댓글 3개가 있고, 다른 글은 태그나 댓글이 없습니다.
    행동
    두관계를직접JOIN한6행을보고관계별선집계결과2/3과비교합니다. 회원12의좋아요-북마크조건을EXISTS/NOT EXISTS/LEFT JOIN으로비교합니다.
    결과
    선택 정보가 없는 글이 사라지지 않고 좋아요 수 2·댓글 수 3이 맞으며, 각 존재 조건의 글 id와 순서가 같습니다.
    이후
    NOT IN의NULL조건과실제NOT NULL제약을구분하고읽기전용결과를기록합니다.

데이터와 이유

필수 작성자와 선택 태그/댓글
JOIN 종류에 따른 행 보존을 판정합니다.
관계별 집계와 존재 여부
2×3 입력 행을 각각 2/3 결과와 구분합니다.

업무 정책

  • COUNT(DISTINCT)로 수를 고쳐도 SUM·가중치 합이 자동으로 수정되지는 않습니다.
  • practice seed/인덱스는수정하지않습니다.
  • 합성 6행을 실제 데이터 측정 결과라고 표시하지 않습니다.

입력과 출력

  • 합성 좋아요 2/댓글 3·태그 없는 글·회원 12·좋아요/북마크 관계·실제 NULL 제약

성공 기준

  • 선택 정보가 없는 글이 사라지지 않고 좋아요 수 2·댓글 수 3이 맞으며, 각 존재 조건의 글 id와 순서가 같습니다.

실패와 데이터 보존

  • 직접 JOIN 집계가 6/6이 되거나 태그 없는 글이 누락 → 관계별 행 수와 필터 위치를 분리해 정확한 결과로 수정합니다. · 유지: 실습 읽기는 기존 관계나 seed를 바꾸지 않습니다.

입력 사례

  • 같은 대상의 전후 비교

개발 과제

  • 상세의 필수/선택 JOIN, 좋아요 2개·댓글 3개의 합성 집계, 좋아요를 눌렀지만 북마크하지 않은 글의 존재 조건을 직접 SELECT로 검증하세요.

완료 확인
