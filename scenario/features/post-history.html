수정과 이력을 함께 남기고 조회하기

수정 전 스냅숏은 실제 변경 때만 남고 글 변경과 같은 트랜잭션으로 확정된다.

이번에 할 일

PATCH 수정과 이력 조회를 구현하고 권한·검증·변경 전 값을 보존한다.

시작 조건

  • 시나리오 DB(`community`). 이번 단계 마이그레이션은 `V23`이다.
  • community V23 및 3-1 PATCH 계약; 인증 회원/작성자 또는 운영자.

사용자 시나리오

  1. 시작
    내 글의 제목은 A, 본문은 C입니다. 아직 수정 이력이 없습니다.
    행동
    제목을 B로 부분 수정하고 같은 글의 수정 이력을 조회합니다.
    결과
    현재 글은 B이고 이력에는 변경 전 A가 남습니다. 같은 값으로 반복 수정하면 새 이력이 생기지 않습니다.
    이후
    잘못된 제목과 공개 범위를 함께 보내면 400과 모든 해당 필드 오류를 받으며, 글과 이력은 모두 그대로입니다.

데이터와 이유

post_revision의 직전 title/content/tags/visibility
실제로 바뀐 요청의 변경 전 스냅숏을 읽는다.
changed_fields, editor_id, created_at
변경한 필드와 누가 언제 수정했는지 확인한다.

업무 정책

  • 로그인 401→볼 수 있는 글 확인 404→작성자/운영자 확인 403. 모든 입력 검증을 먼저 모으고, 오류 하나라도 있으면 글·이력 모두 불변. 동일 값은 이력 생성 안 함. tags 문자열 escape 및 순서 규칙 원문 준수.

입력과 출력

  • legacy:11-6:H0: POST /api/posts; body={"boardSlug":"free","title":"[채점] 이력 원본","content":"처음 본문","tags":["java"]}; case=H0 김자바의 새 글; source expected/status checks=[]
  • legacy:11-6:H1: PATCH /api/posts/{{H0.body.id}}; body={"title":"[채점] 이력 제목 수정"}; case=H1 제목 수정; source expected/status checks=[{"id":"C1","pointer":"/checks/0","request":"H1","expect":{"status":200}}]
  • legacy:11-6:X1: PATCH /api/posts/{{H0.body.id}}; body={"title":"","visibility":"SECRET"}; case=X1 빈 제목 + 없는 공개 범위; source expected/status checks=[{"id":"C3","pointer":"/checks/2","request":"X1","expect":{"status":400,"json":[{"path":"$.errors[*].field","contains":"title"},{"path":"$.errors[*].field","contains":"visibility"}]}}]
  • legacy:11-6:L1: GET /api/posts/{{H0.body.id}}/revisions; case=L1 작성자가 이력 보기; source expected/status checks=[{"id":"C2","pointer":"/checks/1","request":"L1","expect":{"status":200,"json":[{"path":"$.items","length":2},{"path":"$.items[0].changedFields","equals":["content","tags"]},{"path":"$.items[0].before.content","equals":"처음 본문"},{"path":"$.items[0].before.tags","equals":["java"]},{"path":"$.items[0].editor.id","equals":2},{"path":"$.items[0].editedAt","type":"string"},{"path":"$.items[1].changedFields","equals":["title"]},{"path":"$.items[1].before.title","equals":"[채점] 이력 원본"},{"path":"$.items[1].before.visibility","equals":"PUBLIC"}]}}]
  • legacy:11-6:L2: GET /api/posts/{{H0.body.id}}/revisions; case=L2 이스프링이 이력 보기; source expected/status checks=[{"id":"C6","pointer":"/checks/5","request":"L2","expect":{"status":403}}]

성공 기준

  • GET 이력 API에서 해당 글의 변경 전 상태들을 id 순으로 확인.

실패와 데이터 보존

  • GET /api/posts/{{H0.body.id}}/revisions 입력이 원문 실패 check 조건에 해당 → HTTP 403 — 원문 check의 실패 응답 · 유지: post의 title/content/tags/visibility와 post_revision 행 수를 실패 전 그대로 보존한다.
  • PATCH /api/posts/{{H0.body.id}} · [교육용 fixture · legacy:11-6:X1] X1 빈 제목 + 없는 공개 범위 → HTTP 400 (X1); $.errors[*].field contains "title"; $.errors[*].field contains "visibility" · 유지: post title/content/tags/visibility와 post_revision 행 수는 실패 전 그대로다.
  • GET /api/posts/{{H0.body.id}}/revisions · [교육용 fixture · legacy:11-6:L2] L2 이스프링이 이력 보기 → HTTP 403 (L2) · 유지: post title/content/tags/visibility와 post_revision 행 수는 실패 전 그대로다.

입력 사례

  • 교육용 데이터로 전후 확인

개발 과제

  • 변경 전 값 수집 → 실제 변경 필드만 적용 → 이전 값과 변경 목록 저장을 원자적으로 수행한다.

완료 확인

  • 현재 글은 B이고 이력에는 변경 전 A가 남습니다. 같은 값으로 반복 수정하면 새 이력이 생기지 않습니다.
  • 잘못된 제목과 공개 범위를 함께 보내면 400과 모든 해당 필드 오류를 받으며, 글과 이력은 모두 그대로입니다.
  • GET /api/posts/{{H0.body.id}}/revisions 입력이 원문 실패 check 조건에 해당 → HTTP 403 — 원문 check의 실패 응답 post의 title/content/tags/visibility와 post_revision 행 수를 실패 전 그대로 보존한다.
  • PATCH /api/posts/{{H0.body.id}} · [교육용 fixture · legacy:11-6:X1] X1 빈 제목 + 없는 공개 범위 → HTTP 400 (X1); $.errors[*].field contains "title"; $.errors[*].field contains "visibility" post title/content/tags/visibility와 post_revision 행 수는 실패 전 그대로다.
