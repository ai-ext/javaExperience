앱 복귀와 별도 DB 복원을 나누어 실행하기

새 버전이 실패하면 호환되는 앱으로 되돌리고, 백업도 실제로 복원 가능한지 확인합니다.

이번에 할 일

실패하는 내 실험 이미지를 배포해 smoke 실패→배포 중단→호환되는 이전 이미지 복귀를 실행하고, 백업은 별도 새 DB에 복원하세요.

시작 조건

  • 앞선 백업과 앱/DB 호환 행렬·이전 이미지·실패 실험 이미지를 준비합니다.
  • 현재 원본 DB를 복원 대상으로 덮어쓰지 않습니다.

사용자 시나리오

  1. 시작
    새 이미지에서 예약 계약 smoke가 실패했지만 배포 이후에 새 예약 데이터도 생겼습니다.
    행동
    앱만 호환 버전으로 복귀한 뒤 새 데이터 보존을 확인합니다. 별도 DB에 D27 백업을 복원해 원본 시점과 대사합니다.
    결과
    요청 실패 구간과 복귀 후 성공률을 확인하고 앱 복귀가 새 데이터를 지우지 않았음을 증명합니다.
    이후
    복원 DB의 테이블 행 수·예약 대상·지급 식별 집합·금액 합계·제약이 백업 시점과 맞고 손실 구간·복원 시간을 구분합니다.

데이터와 이유

이미지 버전과 호환 경계
DB 제약 강화 뒤 돌아갈 수 없는 버전을 제외합니다.
백업 시점과 복원 대사 집합
앱 교체와 데이터 시점 복원을 구분합니다.

업무 정책

  • 앱 rollback과 DB restore는 다른 동작입니다.
  • 백업 뒤 발생한 데이터의 손실 구간은 미확인과 실측을 구분합니다.
  • 복원 검증은 새 disposable DB에서 합니다.

입력과 출력

  • 실패/이전 이미지, 백업 파일·시점, 원본 시점 행 수·대상·지급·금액·제약

성공 기준

  • 요청 실패 구간과 복귀 후 성공률을 확인하고 앱 복귀가 새 데이터를 지우지 않았음을 증명합니다.

실패와 데이터 보존

  • 이전 앱이 현재 DB와 비호환 → 해당 버전 복귀를 중단하고 forward fix 또는 명시한 복원 조건을 사용합니다. · 유지: 운영 중인 원본 DB를 임의로 덮어쓰지 않습니다.

입력 사례

  • 같은 대상의 전후 비교

개발 과제

  • 실패하는 내 실험 이미지를 배포해 smoke 실패→배포 중단→호환되는 이전 이미지 복귀를 실행하고, 백업은 별도 새 DB에 복원하세요.

완료 확인

  • 계약 오류가 있는 내 실험 이미지로 smoke 실패를 만들고 배포 중단→호환되는 이전 이미지로 복귀한다.
  • 롤백 전후 요청 성공률·실패 구간·신규 데이터 보존을 대조하고 contract 이후 되돌릴 수 없는 버전은 명시한다.
  • D27 백업을 새 disposable DB에 복원한다. 테이블별 행 수·예약 대상·지급 식별 집합·금액 합계·제약을 원본 시점과 대조한다.
  • 복원 소요와 백업 이후 손실 구간을 실측/미확인으로 구분한다. 복원은 앱 롤백과 다르며 현재 원본 DB를 덮어쓰지 않는다.
