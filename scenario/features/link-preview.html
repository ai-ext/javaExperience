외부 지연·오류를 제한하고 안전한 응답 만들기

링크 미리보기는 지정한 2초 안에 실패해도 링크가 달린 글 저장을 완료한다.

이번에 할 일

POST 글 생성 전에 제한 시간 내 외부 제목을 가져오고 안전 입력을 저장한다.

시작 조건

  • 학습용 DB(`practice`) — 앱을 `practice` 프로파일로 띄운다.
  • practice fake-site endpoint; RestClient connection 1초/read 2초, 최대 HTML 앞 64KB.

사용자 시나리오

  1. 시작
    글에 넣을 외부 주소는 가짜 사이트의 정상 페이지 또는 delay 3000ms 페이지입니다.
    행동
    정상 주소와 지연 주소로 각각 글을 등록하고 linkUrl/linkTitle을 비교합니다.
    결과
    정상 페이지는 og:title 우선, 없으면 title을 보관합니다. 읽기 2초 초과나 상대 오류에도 글은 201로 저장하고 link_title은 NULL입니다.
    이후
    연결 1초·읽기 2초 상한과 HTML 앞 64KB 조건을 지킵니다. ftp/javascript/공백 주소는 400이며 글/태그를 만들지 않습니다.

데이터와 이유

post.link_url, link_title
외부 응답 정상/timeout 뒤 저장된 URL과 nullable 제목을 비교한다.
delay=0ms / 3000ms, read timeout=2s, HTML cap=64KB
원문 fake-site에서 성공과 시간 초과 경계를 재현한다.

업무 정책

  • linkUrl은 선택, null/생략은 링크 없음, 빈 문자열 400, 최대 500자이며 `https?://[^\s/?#]+\S*` 형식만 허용한다. ftp/javascript/공백 포함 값은 400.
  • 외부 페이지 HTML 앞 64KB에서 og:title, 없으면 title을 찾는다. RestClient connect timeout 1초/read timeout 2초; 2초 초과/상대 사이트 오류는 한 줄 기록 후 link_title=NULL로 post는 201 저장한다.
  • Fake site delay=0은 title=hello를 돌려주고 delay=3000은 timeout 사례다. POST /api/posts 응답 본문에는 원문대로 linkUrl/linkTitle 저장 결과를 확인한다.
