8-4 검색 조건 조합을 SELECT와 COUNT에 똑같이 적용해 page metadata 및 날짜·게시판 오류를 확인한다.

이번에 할 일

board/tag/author/date/q를 단독·조합 검색하고 없는 slug/tag는 빈 결과, from>to와 invalid values는 400인지 확인한다.

시작 조건

  • dev board, tag jpa, author 3 이스프링, publishedAt 경계에 걸리는 글을 확인한다.
  • 기본 page=0,size=10 및 응답 total 필드 계약을 확인한다.

사용자 시나리오

  1. 시작
    dev/jpa/author3에 맞는 글과 제외될 글의 id 집합을 기록한다.
    행동
    GET /api/posts/search?board=dev&tag=jpa&author=3&from=2026-09-01&to=2026-09-30&q=JPA&page=0&size=5; 이후 없는 board/tag와 날짜 역전을 시험한다.
    결과
    200 목록과 total이 같은 filter에 맞고 publishedAt desc/id desc다. 없는 board/tag는 200 empty. from>to는 없는 board라도 400.
    이후
    날짜 종료일 전체 포함, size/page 오류, wildcard q escaping을 확인한다.

데이터와 이유

published_at calendar-day boundary
from/to both-inclusive 날짜 경계를 검증한다.
board slug dev/nope
검색 없는 board는 empty 200; normal list 404와 구별한다.
tag jpa, author 3, q JPA
단독 및 조합 조건 집합을 비교한다.
items/totalElements/totalPages/hasNext
SELECT와 COUNT가 같은 조건을 사용하는지 본다.

업무 정책

  • GET /api/posts/search filters board/tag/author/from/to/q; page default0,size default10.
  • 없는 board/tag는 200 zero results. board listing missing slug 404와 다르다.
  • from/to YYYY-MM-DD inclusive, DATETIME range 1000-01-01..9999-12-31; from>to 400; date validation precedes missing-board short-circuit.
  • 검색·visibility predicate와 parameter binding을 SELECT 및 COUNT 모두에서 공유한다.

입력과 출력

  • valid: board=dev,tag=jpa,author=3,from=2026-09-01,to=2026-09-30,q=JPA,page=0,size=5.
  • board=nope or tag=missing.
  • board=nope with from=2026-10-01&to=2026-09-01.

성공 기준

  • valid results ordered published_at desc/id desc; COUNT matches same conditions.
  • missing board/tag returns 200 items=[] and totalElements=0.
  • both calendar endpoints included.

실패와 데이터 보존

  • from>to, malformed/out-of-range date → 400, even with missing board. · 유지: post/tag rows unchanged.
  • page<0, invalid size/type → 400. · 유지: read-only search makes no DB changes.
  • COUNT omits tag/date/visibility condition → metadata no longer corresponds to result filter. · 유지: data unchanged.

입력 사례

  • Combined search
  • Missing slug
  • Invalid date precedence

개발 과제

  • Add one search predicate at a time and save returned id sets.
  • Compare list IDs and a SQL COUNT with the exact same where clauses.
  • Run inclusive date boundaries and invalid date plus missing board.

완료 확인

  • Empty search versus normal-list 404 is clear.
  • Inclusive date and validation precedence confirmed.
  • SELECT/count, visibility, page metadata align.

선택한 API 계약

GET/api/posts/search?tag=jpa&size=5상태 미정

C1: JSON 경로 $.totalElements equals 13이어야 합니다. C1: JSON 경로 $.items[*].id equals [123,118,98,87,79]이어야 합니다.
