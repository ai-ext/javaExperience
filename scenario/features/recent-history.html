회원별 최근 열람 순서와 보관량 지키기

회원별 최근 본 글을 중복 없이 최신 순으로 보관하되 최대 20개다.

이번에 할 일

상세 열람 기록을 갱신하고 내 최근 보기 목록을 관리한다.

시작 조건

  • 시나리오 DB(`community`) — 앱을 기본 프로파일로 띄운다.
  • community 또는 원문에서 지정한 DB/Clock, 회원별 접근 권한과 공개 글을 준비한다.

사용자 시나리오

  1. 시작
    회원이 서로 다른 글 20개를 읽은 상태에서 새 글과 전에 읽은 글을 엽니다.
    행동
    최근 목록을 읽고 스물한 번째 글 조회·기존 글 재조회를 차례로 수행합니다.
    결과
    목록은 회원별 최신 열람 순 최대 20개이며 기존 글 재조회는 중복 추가 대신 앞으로 옮깁니다.
    이후
    size 21은 400이고 실패한 목록 조회는 열람 기록과 순서를 바꾸지 않습니다.

데이터와 이유

recent_view(member_id, post_id, viewed_at)
회원별 최근 순서와 재방문 중복 행을 비교한다.
회원별 최신 20개 post id
보관 한도 후 오래된 열람 행 정리 여부를 확인한다.

업무 정책

  • 최근 본 글은 회원별 기록. 삭제/숨김·접근 불가 데이터 표시 규칙과 20개 보관 정책은 14-5 원문을 따름; 익명 처리는 만들어내지 않는다.

성공 기준

  • 최근 조회 순서와 제한량 확인, 다른 회원 목록은 분리.

실패와 데이터 보존

  • GET /api/me/recent-posts?size=0 입력이 원문 실패 check 조건에 해당 → HTTP 400 — 원문 check의 실패 응답 · 유지: 요청 회원의 recent_view 행/정렬 값을 실패 전 그대로 보존한다.

입력 사례

  • 교육용 데이터로 전후 확인

개발 과제

  • 회원-글 유니크성, 최근 시각 갱신, 보관량 제한을 구현하고 조회 권한과 함께 확인한다.

완료 확인

  • 목록은 회원별 최신 열람 순 최대 20개이며 기존 글 재조회는 중복 추가 대신 앞으로 옮깁니다.
  • size 21은 400이고 실패한 목록 조회는 열람 기록과 순서를 바꾸지 않습니다.
