예약 대상과 지급 사실을 구분해 모델 검증하기

운영자가 정한 회원들에게 미래 시각에 쿠폰을 지급하고 실패한 대상만 다시 찾을 수 있게 설계합니다.

이번에 할 일

승인 시 고정한 대상·예약 전 취소·실패 재처리·1인 1매 규칙을 명세화하고 두 모델을 최소 6행 반례로 비교하세요.

시작 조건

  • 기존 쿠폰과 회원별 쿠폰 기능을 완성합니다.
  • 별도 disposable DB를 쓰고 예약 두 개·대상 회원 세 명 이상을 준비합니다.

사용자 시나리오

  1. 시작
    운영자가 회원 집합을 선택해 미래 지급 예약을 승인합니다. 승인 뒤 회원 검색 결과가 달라질 수 있습니다.
    행동
    승인 당시 대상을 고정하고 중복 대상·없는 회원·이미 받은 회원·같은 시각·취소 상태를 넣은 fixture를 실행합니다.
    결과
    실행 시점에 재검색해 대상이 바뀌지 않으며 선택한 업무 키 범위에서 중복 지급을 거절할 수 있습니다.
    이후
    예약/대상/지급 이력의 관계와 상태를 실제 DDL·SQL 오류·조회로 검증하되 아직 지급 서버 구현은 하지 않습니다.

데이터와 이유

예약 의도와 고정 대상
누가 어떤 쿠폰을 누구에게 언제 주기로 승인했는지 보존합니다.
지급 사실과 실패 정보
실제로 받은 사람과 재처리 대상을 구분합니다.

업무 정책

  • 대상은 예약 승인 시 고정합니다.
  • 예약과 이력을 나눈 안·합친 안의 정합성·조회·이행 비용을 비교해 하나를 고릅니다.
  • 테이블·키·상태 이름은 학습자가 정하며 기존 member_coupon을 새 모델 정답으로 강제하지 않습니다.

입력과 출력

  • 운영자·쿠폰·대상 회원 집합·미래 시각, 취소와 재처리 상태, 선택한 업무 중복 키

성공 기준

  • 실행 시점에 재검색해 대상이 바뀌지 않으며 선택한 업무 키 범위에서 중복 지급을 거절할 수 있습니다.

실패와 데이터 보존

  • 중복 대상·없는 회원·이미 받은 회원 입력 → 명세에 적은 제약·실패 결과를 SQL로 확인합니다. · 유지: 기존 지급과 다른 예약의 대상이 지워지면 안 됩니다.

입력 사례

  • 같은 대상의 전후 비교

개발 과제

  • 승인 시 고정한 대상·예약 전 취소·실패 재처리·1인 1매 규칙을 명세화하고 두 모델을 최소 6행 반례로 비교하세요.

완료 확인

  • 운영자가 회원 집합에 쿠폰을 미래 시각에 지급하고 지급 이력을 조회한다. 대상은 예약 승인 시 고정하고 예약 전 취소·실패 대상 재처리·1인 1매 요구를 명세화한다.
  • 테이블·키·관계·UNIQUE·시각·상태를 직접 정한다. 예약과 지급 이력을 분리한 안/단일 안의 정합성·조회·이행 비용을 비교하고 선택한다.
  • 중복 대상·없는 회원·이미 지급된 회원·동일 시각·취소 상태를 포함한 최소 6행 fixture와 기대 불변식을 직접 만든다.
  • DDL을 disposable DB에 적용하고 중복·FK·상태 제약을 실제 SQL 오류/조회로 검증한다. 아직 서비스 구현은 하지 않는다.

명령을 자동 실행하지 않습니다. 직접 실행한 뒤 결과를 기록하세요.
