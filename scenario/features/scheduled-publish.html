실행 시각이 지난 대상을 한 번 발행하기

SCHEDULED 글은 기준 시각이 지나면 한 번 PUBLISHED로 바뀌고 목록에 나타난다.

이번에 할 일

예약 작성·상세 가시성·배치의 시점 전후 상태 전이를 구현한다.

시작 조건

  • 학습용 DB(`practice`) — 앱을 `practice` 프로파일로 띄운다. "지금" = 2026-10-05 00:00.
  • practice Clock에서 예약 시각=2026-10-05 09:00:00; app fixed-now 설정 확인.

사용자 시나리오

  1. 시작
    미래 publish_at이 있는 SCHEDULED 글은 작성자만 읽을 수 있습니다.
    행동
    고정 시각을 예약 직전·경계·직후로 옮기며 기존 예약 발행 배치를 실행합니다.
    결과
    기준 시각에 도달한 대상만 PUBLISHED로 전환돼 공개되고 이미 발행한 글을 중복 처리하지 않습니다.
    이후
    발행 전 비로그인 상세 404이며 게시 목록/검색에도 빠집니다. 잘못된 at 값 400에서는 기존 예약 시각과 상태를 유지합니다.

데이터와 이유

post.status, publish_at, published_at
직전·정각·재실행 시 상태 전이가 발생했는지 확인한다.
at=2026-10-05T08:59:59 / 09:00:00
원문 check의 경계 직전과 경계 시각을 그대로 재현한다.

업무 정책

  • SCHEDULED에는 publish_at 필수; DRAFT와 같이 작성자만 상세 접근, 목록/검색 제외. Clock 사용, 초 단위 정밀도. practice fixed clock에서는 13-5 rate limit bypass 예외 보존. 배치는 기존 endpoint 사용.

실패와 데이터 보존

  • POST /api/admin/jobs/scheduled-publish/run?at=abc 입력이 원문 실패 check 조건에 해당 → HTTP 400 — 원문 check의 실패 응답 · 유지: post가 SCHEDULED면 publish_at 유지, published_at=NULL을 보존한다.
  • GET /api/posts/{{P1.body.id}} · [교육용 fixture · legacy:15-3:P4] 예약 글 — 비로그인 상세 → HTTP 404 (P4) · 유지: 예약 post는 SCHEDULED, publish_at 원값, published_at=NULL이다.
