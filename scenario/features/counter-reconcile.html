8-5 ADMIN recount에서 실제 post_like 및 nondeleted comment 관계와 counter 불일치만 집합 갱신한다.

이번에 할 일

실행 전 mismatch SELECT 결과를 기록하고 tok-p01로 POST /api/admin/recount, 재검사해 D1/D2=0 및 두 번째 실행 무변화를 확인한다.

시작 조건

  • 학습용 practice DB에서만 작업하고 post별 like_count/comment_count와 relation aggregates를 먼저 읽는다.
  • ADMIN member1 tok-p01, ordinary member 및 no-token을 구분한다.

사용자 시나리오

  1. 시작
    deleted_at is null인 post 중 저장 count와 relation count가 다른 id 및 각 값을 기록한다.
    행동
    ADMIN token으로 POST /api/admin/recount 후 같은 SELECT를 재실행한다.
    결과
    불일치 active post만 실제 relation 수로 맞춰지고 D1/D2 mismatch 수가 0이 된다.
    이후
    두 번째 POST에서 값/affected rows가 더 바뀌지 않으며 deleted post는 대상에서 제외된다.

데이터와 이유

active post id/deleted_at/like_count/comment_count
대상 범위와 원래 counter를 기록한다.
post_like grouped count
likes counter의 실제 관계값이다.
comment grouped count where deleted_at is null
활성 댓글만 counter에 포함한다.
before/after mismatch id and affected rows
고친 범위가 사전 SELECT 후보와 일치하는지 검증한다.

업무 정책

  • POST /api/admin/recount는 ADMIN(member1 tok-p01) only; no token 401, ordinary member 403.
  • 진단 SELECT를 먼저 남기고 active posts만 처리한다. likes는 post_like 행수, comments는 미삭제 comment 행수의 합이다.
  • post를 한 개씩 entity load/save하지 않고 집합형 update로 대상 mismatch만 보정한다.
  • scheduled/background job이 아니라 명시적인 학습용 ADMIN request다.

입력과 출력

  • pre-recount mismatch SELECT for likes/comments.
  • POST /api/admin/recount with tok-p01.
  • repeat SELECT and endpoint; then ordinary member and no token.

성공 기준

  • D1 active like_count mismatch=0; D2 live comment_count mismatch=0.
  • repeated recount produces no further count changes.
  • deleted posts remain outside update.

실패와 데이터 보존

  • no Authorization → 401. · 유지: all counters unchanged.
  • non-ADMIN token → 403. · 유지: all counters unchanged.
  • deleted comments are included in aggregation → D2 source check exposes wrong count. · 유지: run in disposable fixture and restore only by documented fixture reset.

입력 사례

  • Repair one mismatch
  • Repeat repair
  • Ordinary member denied

개발 과제

  • Save diagnostic SELECT output before requesting the operation.
  • Compare changed IDs with SELECT candidates and affected-row count.
  • Read service log to confirm one grouped set update rather than per-post entity loop.

완료 확인

  • D1 and D2 are zero afterward.
  • Only mismatch active records changed; deleted records excluded.
  • 401/403 keep counts and second run is stable.

POST/api/admin/recount200
