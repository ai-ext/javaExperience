글을 폴더에 담고 메모·목록 관리하기

community 북마크 생성·upsert·폴더 CRUD·목록·메모 수정에서 회원 소유권과 북마크 행 수명을 보존한다.

이번에 할 일

Kim이 글 2에 memo와 folder를 지정해 저장하고 반복 PUT/upsert·메모 PATCH·폴더 삭제/이동·cursor 목록을 확인한다.

시작 조건

  • Kim token과 post 2(자기 글도 bookmark 가능), Park token 및 각 member 소유 folder를 분리해 준비한다.
  • Kim 폴더는 최대 10개; 폴더 이름은 trim 후 1~50자, member-post UNIQUE.

사용자 시나리오

  1. 시작
    post2 bookmark 없음; Kim folder "스프링 공부" id11에 2 bookmarks, folder12 "나중에 읽기"에도 2 bookmarks.
    행동
    PUT /api/posts/2/bookmark memo="[북마크실습] 복습"; 같은 PUT 반복; 6-2 folder rename/create/delete·move; 6-4 memo PATCH.
    결과
    첫 저장 200 bookmarkId 한 개, 반복 같은 ID. 폴더 생성 201/rename 200/delete 204; delete folder는 child bookmarks를 지우지 않고 folder_id=NULL 이동. memo PATCH는 200.
    이후
    다른 회원 folder ID, 중복 folder name, 11번째 folder, memo 201자, memo PATCH {}/null을 검사하고 영향 row를 비교.

데이터와 이유

bookmark(member_id=Kim,post_id=2,folder_id,memo)
한 회원·한 글 북마크와 folder/memo 상태 전후 비교.
bookmark_folder Kim: id11 스프링 공부, id12 나중에 읽기
목록/count/rename/delete 이관 규칙 검증.
Park 소유 folder
타 회원 folder id 거절 및 북마크 변경 없음 확인.
bookmarkedAt/id cursor
created_at DESC,id DESC stable ordering.

업무 정책

  • 6-0 PUT는 token member와 post, optional folderId/memo; 누락/null folder는 기본 폴더, memo는 null; memo max200. 반복 PUT은 같은 bookmarkId, 행은 한 개. 내 글 북마크 허용, like_count는 건드리지 않는다.
  • folderId 존재뿐 아니라 folder.member_id=token member인지 확인한다. invalid folder면 새 bookmark를 만들지 않는다. UNIQUE(member_id,post_id).
  • 6-1 upsert는 existing folder/memo를 요청값으로 갱신한다. 6-2 folder max10, duplicate normalized name 409, 빈/51자 400, 삭제 시 bookmark 유지하면서 folder_id=NULL.
  • 6-3 GET /api/me/bookmarks 생략=전체, folder=default/null-folder, numeric folder own only; size 1..100/default10; sort bookmarkedAt desc then bookmark id desc, cursor opaque. Unavailable row는 남기고 available=false,title=null,author=null.
  • 6-4 PATCH existing bookmark memo: {} means unchanged, {memo:null} clears; string incl empty allowed up to 200, >200/wrong type 400, missing bookmark 404, no new row; folderId ignored and folderId/bookmarkId/created_at stable.

입력과 출력

  • PUT /api/posts/2/bookmark {memo:"[북마크실습] 복습"}; repeat; folderId=Kim folder id11.
  • folder names " 스프링 공부 ", duplicate "스프링 공부", 50자/51자, 11th folder.
  • PATCH bookmark body {}, {memo:null}, {memo:"다시 읽기"}, {memo:""}, 201 chars, {memo:12}.
  • GET /api/me/bookmarks?folder=default&size=10 and next cursor.

성공 기준

  • PUT bookmark 200; repeated PUT same bookmarkId, one row; response bookmarked=true, folderId/memo actual.
  • folder list 200 created order/count; create 201 Location; rename 200; delete 204 with child bookmark retained at default (folder_id NULL).
  • memo PATCH 200; text change returns memo, null removes memo, empty string remains empty, {} keeps prior.
  • bookmark list 200; unavailable rows stay with available=false and title/author null.

실패와 데이터 보존

  • folder missing/owned by Park; invalid positive integer representation → 404 for foreign/nonexistent folder or 400 malformed folderId. · 유지: bookmark row is not created or moved.
  • same Kim folder name exists or folder count already 10 → 409 duplicate name or 400 max folders. · 유지: folder count/name and bookmarks stay unchanged.
  • memo 201 chars or numeric/array type; no token → 400 or 401. · 유지: existing bookmarkId, folderId, memo, created_at remain unchanged.
  • move/delete foreign bookmark/folder → 404. · 유지: Park/Kim folder contents not altered.

입력 사례

  • 반복 북마크 설정
  • 폴더 삭제와 북마크 보존
  • memo 생략과 null
  • 중복 폴더 생성

개발 과제

  • 6-0/6-1/6-2/6-3/6-4 source recipe를 기능별로 나눠 호출한다.
  • bookmarkId/folderId/memo/created_at before-after와 folder count를 기록한다.
  • 삭제 폴더가 비어 있지 않은 경우 연결 UPDATE 후 folder delete가 이뤄졌는지 확인한다.

완료 확인

  • 중복 PUT은 bookmarkId와 row 하나를 유지했다.
  • 폴더 소유/limit/name/delete 이관 규칙을 확인했다.
  • 6-3 unavailable 보존 및 6-4 absent/null/empty memo 의미를 구분했다.
  • 실패 후 bookmark/folder 관계가 unchanged다.

선택한 API 계약

PUT/api/posts/2/bookmark200

C1: HTTP 상태 200이어야 합니다. C1: JSON 경로 $.postId equals 2이어야 합니다. C1: JSON 경로 $.bookmarked equals true이어야 합니다. C1: JSON 경로 $.memo equals "[북마크실습] 복습"이어야 합니다. C1: JSON 경로 $.bookmarkId type "number"이어야 합니다.
