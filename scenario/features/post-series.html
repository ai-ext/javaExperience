시리즈 순서와 이전·다음 글 연결하기

연재 글을 순서에 따라 묶고 이전·다음 글 이동을 노출한다.

이번에 할 일

시리즈 생성과 글 연결/순서 변경 및 공개 가능한 이전·다음 링크를 구현한다.

시작 조건

  • 시나리오 DB(`community`) — 앱을 기본 프로파일로 띄운다.
  • community 게시글 3개를 준비하고 필요한 시리즈 권한을 확인한다.

사용자 시나리오

  1. 시작
    작성자가 자신의 여러 글을 한 시리즈로 묶고 순서를 정합니다.
    행동
    시리즈를 만들고 글을 넣은 뒤 가운데 글의 이전/다음 글을 조회합니다.
    결과
    정한 순서의 인접 글이 연결되고 글을 빼거나 순서를 바꾼 결과가 목록에 반영됩니다.
    이후
    권한 없는 글 추가·중복·잘못된 순서에서는 원래 시리즈 관계와 순서가 유지됩니다.

데이터와 이유

series와 series_post(position)
여러 게시글 묶음 및 이전/다음 순서를 만든다.
post 공개/삭제 상태
시리즈 탐색에서 노출해도 되는 글인지 적용한다.

업무 정책

  • 제목은 strip 후 2~100자 필수, 설명은 선택 500자 이하이며 빈 설명은 null입니다. 잘못된 필드 오류는 모두 400으로 알립니다.
  • 한 글은 시리즈 하나에만 속합니다. 내 다른 시리즈에서 옮기면 새 시리즈 끝에 넣고, 이미 같은 시리즈에 있으면 그대로 200입니다. 삭제 연결은 없어도 204입니다.
  • 시리즈 생성 201+Location, 조회 200입니다. 글의 시리즈/이전/다음 조회는 시리즈가 없으면 204이며, 보는 사람이 접근 가능한 글만 순서대로 연결합니다.

성공 기준

  • 시리즈 상세/글 상세에서 실제 순서와 이전/다음 대상 일치.

실패와 데이터 보존

  • POST /api/series 입력이 원문 실패 check 조건에 해당 → HTTP 400 — 원문 check의 실패 응답 · 유지: series와 series_post 행 및 순서를 실패 전 그대로 보존한다.
  • PUT /api/series/{{S1.body.id}}/posts/3 · [교육용 fixture · legacy:14-4:S5] 남의 시리즈에 넣기(김자바) → HTTP 403 (S5) · 유지: series/series_post 행과 순서를 보존한다.

입력 사례

  • 교육용 데이터로 전후 확인

개발 과제

  • series 및 series_post 관계를 일관되게 저장하고 이전·다음은 정렬 결과에서 계산한다.

완료 확인

  • 정한 순서의 인접 글이 연결되고 글을 빼거나 순서를 바꾼 결과가 목록에 반영됩니다.
  • 권한 없는 글 추가·중복·잘못된 순서에서는 원래 시리즈 관계와 순서가 유지됩니다.
  • POST /api/series 입력이 원문 실패 check 조건에 해당 → HTTP 400 — 원문 check의 실패 응답 series와 series_post 행 및 순서를 실패 전 그대로 보존한다.
  • PUT /api/series/{{S1.body.id}}/posts/3 · [교육용 fixture · legacy:14-4:S5] 남의 시리즈에 넣기(김자바) → HTTP 403 (S5) series/series_post 행과 순서를 보존한다.

선택한 API 계약

POST/api/series201

C1: HTTP 상태 201이어야 합니다. C1: JSON 경로 $.title equals "[채점] JPA 연재"이어야 합니다. C1: JSON 경로 $.description type "null"이어야 합니다. C1: JSON 경로 $.author.id equals 3이어야 합니다. C1: JSON 경로 $.posts length 0이어야 합니다. C1: 응답 헤더 Location {"endsWith":"/api/series/{{S1.body.id}}"}이어야 합니다.
