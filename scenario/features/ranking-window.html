고정한 기준 시각으로 기간 순위 계산하기

8-2 최근 N일 인기 점수를 고정 Clock과 Asia/Seoul의 반열린 시간 구간으로 재현한다.

이번에 할 일

2026-10-05 기준 7일 동안의 좋아요×3+삭제 제외 댓글 점수를 계산하고 0점 제외 및 top5 tie order를 확인한다.

시작 조건

  • practice fixed-now=2026-10-05T00:00:00, timezone Asia/Seoul.
  • 예시 post145 score61/likes20/comments1; lifetime leaders post18/55/103 각각 22 likes는 오래된 반응이 다수다.

사용자 시나리오

  1. 시작
    days=7, to=2026-10-05 00:00 Asia/Seoul, from=2026-09-28 00:00를 계산한다.
    행동
    popular endpoint에 days=7,limit=5를 보내고 from 직전/from exact/to 직전/to exact event 포함 여부를 비교한다.
    결과
    기간 [2026-09-28,2026-10-05), score=likes×3 + live comments, score 0 제외, score desc/publishedAt desc/id desc top5; post145 sample score61.
    이후
    days=30 및 0/31/abc/empty를 보내 range validation과 순위 변화를 확인한다.

데이터와 이유

fixed Clock now 2026-10-05T00:00 Asia/Seoul
매 실행 시 같은 query window.
event timestamps at 2026-09-28 and 2026-10-05
하한 포함·상한 제외 semantics.
post145 score61 / 20 likes / 1 comment; old posts18/55/103
최근 반응 대 누적 반응 정렬 비교.
published/public/nondeleted post
랭킹 대상 필터.

업무 정책

  • 기간 [now-days,now), days 1..30 default7; invalid numeric/empty/bounds 400.
  • score = in-window likes*3 + nondeleted comments; score 0 excluded. Order score desc, published_at desc, id desc, top five.
  • Clock bean, Asia/Seoul. Fixed app time은 SQL NOW()나 LocalDateTime.now()에 적용되지 않으므로 DB timestamps와 구분한다.

입력과 출력

  • popular endpoint with days=7 and limit=5.
  • boundary events: 2026-09-27 23:59:59; 2026-09-28 00:00:00; 2026-10-04 23:59:59; 2026-10-05 00:00:00.
  • days=30,0,31,abc,empty.

성공 기준

  • from exact and to-minus-one events count; before from and exact to do not.
  • post145 example scores 61 based on 20 likes and 1 comment.
  • old cumulative 22 likes alone does not decide current-period ranking.

실패와 데이터 보존

  • days outside 1..30, malformed or empty → 400. · 유지: events/posts unchanged.
  • from excluded or to exact included → boundary assertion fails. · 유지: timestamps unchanged.
  • system time or SQL NOW mixes with fixed Clock → repeat calls drift from fixed source fixture. · 유지: no data change.

입력 사례

  • Seven-day top list
  • Upper exclusive bound
  • Bad window

개발 과제

  • Read actual endpoint recipe and fixed Clock profile.
  • Independently count events by boundary and compare SQL CASE output.
  • Write measured results only; do not invent latency/index performance.

완료 확인

  • time window boundaries and timezone confirmed.
  • score formula, zero exclusion and tie break confirmed.
  • days range success/failure recorded.

선택한 API 계약

GET/api/posts/popular?days=7&limit=5상태 미정
