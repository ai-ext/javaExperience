재사용 기간과 무효화 시점 지키기

인기글 결과는 최대 60초 재사용하지만 숨김·삭제 성공 후 즉시 캐시에서 제거한다.

이번에 할 일

8-2 인기글 쿼리의 Caffeine cache, HIT/MISS 증거, mutation invalidation을 구현한다.

시작 조건

  • 학습용 DB(`practice`) — 앱을 `practice` 프로파일로 띄운다. 8-2의 `GET /api/posts/popular`를 그대로 쓴다.
  • practice profile에서 /api/posts/popular?days=7&limit=10; Caffeine 설정과 8-2 endpoint 사용.

사용자 시나리오

  1. 시작
    같은 기간/개수/버전으로 인기 글을 아직 읽지 않았습니다.
    행동
    첫 목록과 즉시 반복 목록을 비교한 뒤 공개 범위 변경이나 삭제를 성공시킵니다.
    결과
    처음 MISS·반복 HIT이며 60초 재사용합니다. 성공한 공개 범위 변경/삭제는 모든 인기 글 캐시를 즉시 비웁니다.
    이후
    실패한 변경과 발행 대상 0건 배치는 캐시를 지우지 않습니다. 캐시 중 좋아요 변화의 기존 순위 허용과 숨김 즉시 반영을 구분합니다.

데이터와 이유

popularPosts(days,limit,version), X-Cache
cache hit/miss와 mutation 직후 무효화를 같은 key로 본다.
days=7, limit=10, TTL=60s
원문 popular API 파라미터와 TTL을 확인한다.

업무 정책

  • popularPosts Caffeine cache: maximumSize=100, expireAfterWrite=60s; key=(days,limit,version), 반환 리스트는 불변이다.
  • 첫 GET은 MISS, 즉시 같은 key 재조회는 HIT; 60초 동안 좋아요 변화는 이전 순위를 보여 주는 것이 허용된다.
  • 성공한 visibility 변경/삭제는 모든 popularPosts key를 바로 비운다. 잘못된 요청·실패 변경에는 eviction 하지 않고 발행 대상 0건 배치도 cache를 유지한다.

성공 기준

  • 응답 본문은 8-2 배열, X-Cache만 진단 추가; MISS일 때 SQL 실행.

실패와 데이터 보존

  • PATCH /api/posts/144 입력이 원문 실패 check 조건에 해당 → HTTP 400 — 원문 check의 실패 응답 · 유지: 실패한 변경은 post visibility/deleted_at 및 cache generation을 바꾸지 않는다.
  • PATCH /api/posts/144 · [교육용 fixture · legacy:16-3:X5] 남의 글(회원 7) → HTTP 403 (X5) · 유지: 실패 mutation은 post visibility/deleted_at과 cache generation을 바꾸지 않는다.
