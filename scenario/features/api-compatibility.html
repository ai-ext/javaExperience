제품 담당자가 원하는 전체 개수와 목록 조회 비용을 비교해 새 화면에 필요한 정보를 제공합니다.

이번에 할 일

D25의 실제 목록 계약과 데이터로 목록 조회·정확 COUNT를 따로 측정하고, 정확 total 또는 다음 목록 유무를 선택해 응답에 반영하세요.

시작 조건

  • D25에서 내 프로젝트에 확정한 기존 경로·필드·커서·오류 fixture를 준비합니다.
  • D24의 같은 데이터·필터를 사용하며 실제 목록 경로가 아직 없다면 원본 설계에서 정한 조회 계약을 먼저 확정합니다.
  • 아래 이전/변경 후 계약 등록란에 실제 값과 기대 상태를 각각 저장합니다. 원문이 정하지 않은 URI를 기본값으로 넣지 않습니다.

사용자 시나리오

  1. 시작
    제품 담당자가 예약 목록의 정확한 전체 개수를 요청합니다. 같은 필터에 빈 목록·다음 묶음·집계 HAVING 조건이 있습니다.
    행동
    목록 일부 조회와 정확 count를 따로 실행·측정하고 선택 근거를 남긴 뒤 이전 요청과 새 요청을 각각 전송합니다.
    결과
    기존 앱의 응답은 유지되고 새 화면은 합의한 total 또는 다음 목록 유무를 정확하게 받습니다.
    이후
    목록과 COUNT의 시간·실행계획은 별도 기록이며 HAVING이 있으면 total이 원본 행 수인지 결과 그룹 수인지 명확합니다.

데이터와 이유

이전/새 요청·응답 fixture
업데이트할 수 없는 앱의 경로와 필드가 유지되는지 비교합니다.
동일 필터의 목록·count 측정
사용자 요구의 비용을 구분합니다.

업무 정책

  • 정확 count와 다음 목록 유무 중 선택·이유·비용·변경 방식을 명세에 확정합니다.
  • 이전 계약은 D25에서 정한 실제 값을 재사용합니다.
  • 측정하지 않은 성능이나 존재하지 않는 URI를 확정값으로 쓰지 않습니다.

입력과 출력

  • 실제 목록 경로·쿼리·커서·기존 응답 예시, 동일 fixture와 count SQL, 선택한 새 필드

성공 기준

  • 기존 앱의 응답은 유지되고 새 화면은 합의한 total 또는 다음 목록 유무를 정확하게 받습니다.

실패와 데이터 보존

  • 빈 목록·잘못된 커서·집계 그룹이 있는 요청 → 기존 오류와 새 total 의미가 확정 계약대로 동작해야 합니다. · 유지: 이전 앱의 경로·필드·다음 목록 조회를 깨뜨리지 않습니다.

입력 사례

  • 같은 대상의 전후 비교

개발 과제

  • D25의 실제 목록 계약과 데이터로 목록 조회·정확 COUNT를 따로 측정하고, 정확 total 또는 다음 목록 유무를 선택해 응답에 반영하세요.

완료 확인

  • 제품 담당자가 목록 전체 건수와 예약 즉시 지급 성공 표시를 요구한다. 동기/비동기·정확 count/다음 페이지의 비용·불확실 상태를 설명하고 합의 계약을 작성한다.
  • 기존 앱은 업데이트 불가라는 반론을 받은 뒤 필드 추가·새 경로·상태 표현 대안 중 추천안·결정 요청·폐기 조건을 적는다.
  • 같은 필터로 목록 쿼리와 정확 COUNT 쿼리를 따로 실행·측정한다. HAVING 집계라면 원본 행 수와 필터를 통과한 결과 그룹 수 중 API의 total이 무엇인지 합의한다.

    • 제품 담당자가 목록 전체 건수와 예약 즉시 지급 성공 표시를 요구한다. 동기/비동기·정확 count/다음 페이지의 비용·불확실 상태를 설명하고 합의 계약을 작성한다.
    • 기존 앱은 업데이트 불가라는 반론을 받은 뒤 필드 추가·새 경로·상태 표현 대안 중 추천안·결정 요청·폐기 조건을 적는다.
    • 같은 필터로 목록 쿼리와 정확 COUNT 쿼리를 따로 실행·측정한다. HAVING 집계라면 원본 행 수와 필터를 통과한 결과 그룹 수 중 API의 total이 무엇인지 합의한다.
    원문 질문 힌트
    • 응답 필드와 202/201 등의 의미를 먼저 협의한다. 실제 지급 전 성공을 약속하지 않는다. 말만 하지 말고 요청/응답 fixture를 남긴다.
    • 집계 목록의 total은 COUNT(*) 원본 행과 다를 수 있다. HAVING 적용 뒤 결과 그룹의 수를 별도 COUNT로 구하고 목록 비용과 분리한다.
