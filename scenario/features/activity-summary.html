활동이 없는 회원도 올바르게 집계하기

8-1 회원별 게시글·댓글·받은 좋아요·누른 좋아요를 집계하고 활동 없는 회원도 0으로 포함한다.

이번에 할 일

practice DB에 작성된 SQL 먼저 실행한 뒤 GET /api/stats/member-activity를 호출해 member별 네 집계를 비교한다.

시작 조건

  • CloudBeaver에서 `practice` Java 학습 DB를 선택한다.
  • 삭제된 글·댓글과 post_like row를 포함하는 8-1 fixture를 확인한다.

사용자 시나리오

  1. 시작
    member 전체 목록과 posts/comments/post_like rows를 독립 집계해 기록한다.
    행동
    sql/8-1-member-activity.sql을 먼저 실행하고 GET /api/stats/member-activity로 JSON을 읽는다.
    결과
    200 response에서 posts, comments, likesReceived, likesGiven은 SQL 기준과 같고 활동이 없는 member도 네 count 0으로 남는다.
    이후
    한 번에 여러 1:N 테이블을 join한 잘못된 곱집계와 대조하고 soft-delete 조건을 다시 검사한다.

데이터와 이유

member id/nickname 전체
0 activity member를 포함한 기준 집합.
post author/status/deleted_at
활성 게시글 수 filter.
comment author/post/deleted_at
comment 및 상위 글이 모두 미삭제인지 확인.
post_like.member_id와 post_like.post_id
누른 좋아요·받은 좋아요를 구분하고 cache count 오류 방지.

업무 정책

  • member를 기준으로 시작해 활동 없는 회원도 유지하고 집계 null을 0으로 나타낸다.
  • likesReceived는 deleted 아닌 회원 authored post에 연결된 post_like rows; `post.like_count` column은 source of truth가 아니다. likesGiven은 해당 member의 relation rows.
  • comment count는 comment 자체와 원글이 모두 미삭제여야 한다. posts는 PUBLISHED/nondeleted.
  • 여러 collection을 동시에 join해 row multiplication을 발생시키지 않는다.

입력과 출력

  • GET /api/stats/member-activity (no query).
  • SQL reference: sql/8-1-member-activity.sql.
  • member별 direct count를 각 relation에서 다시 계산.

성공 기준

  • 모든 member가 나타나며 activity 없는 member는 네 값이 0이다.
  • likesReceived/likesGiven/posts/comments는 원문 정의와 맞고 response와 SQL 결과가 동일하다.

실패와 데이터 보존

  • post×comment×like collection을 한번에 join하여 COUNT → 잘못된 곱집계와 source SQL 숫자가 어긋난다. · 유지: 조회이므로 데이터 변화 없음.
  • deleted comment 또는 deleted parent post 포함 → comment count가 source 기준보다 커진다. · 유지: 원본 rows unchanged.

입력 사례

  • 활동 회원
  • 활동 없는 회원
  • count cache 비교

개발 과제

  • SQL 먼저 실행해 member id별 결과를 기록한다.
  • HTTP JSON을 id로 join해 하나씩 비교한다.
  • multi-join alternative에서 중복 row가 생기는 이유를 fixture cardinality로 설명한다.

완료 확인

  • 0 activity 회원이 결과에 남았다.
  • 각 count의 soft-delete와 relation 기준을 확인했다.
  • 실제 post_like rows로 likesReceived를 계산했다.
