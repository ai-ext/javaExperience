운영 권한과 CSV 형식을 지켜 내보내기

운영자만 신고 데이터를 CSV로 받을 수 있고 셀 내용이 스프레드시트 수식으로 실행되지 않게 한다.

이번에 할 일

신고 조회 범위와 CSV 다운로드 헤더·인코딩·escaping 정책을 구현한다.

시작 조건

  • 시나리오 DB(`community`) — 앱을 기본 프로파일로 띄운다.
  • community 신고 기록과 운영자 인증을 준비한다.

사용자 시나리오

  1. 시작
    운영자가 특정 조건의 신고 내역을 외부 도구에서 검토하려 합니다.
    행동
    운영자 권한으로 CSV를 다운로드하고 일반 회원의 같은 요청을 비교합니다.
    결과
    허용된 신고 열과 정렬·문자 코드·CSV 이스케이프가 원본 다운로드 계약과 맞습니다.
    이후
    권한 없는 요청에서 파일 내용이 노출되지 않고 다운로드 조회가 신고 상태를 바꾸지 않습니다.

데이터와 이유

report.status, created_at, reporter_id
내보낼 실제 신고 행과 운영 범위를 확인한다.
CSV 셀 원문 및 응답 header
쉼표/따옴표/개행 등 원문 사례의 표현을 비교한다.

업무 정책

  • GET /api/admin/reports/export는 ADMIN의 EXPORT_DATA 권한만 허용합니다. 토큰 없음 401·권한 없음 403·잘못된 status 400입니다. status는 PENDING/ACCEPTED/REJECTED, 생략은 전체입니다.
  • 응답 200, text/csv;charset=UTF-8, UTF-8 BOM으로 시작하고 CRLF로 줄을 끝냅니다. 파일명은 고정 Clock의 신고내역-YYYYMMDD.csv이며 Content-Disposition을 노출합니다.
  • 열은 신고번호/대상/대상번호/사유/상세/신고자/신고시각/처리상태/처리자/처리시각, 신고 id 순입니다. 시각 형식 yyyy-MM-dd HH:mm:ss, 없는 값은 빈칸입니다.
  • 쉼표·따옴표·줄바꿈 셀은 따옴표로 감싸고 내부 따옴표를 두 번 씁니다. =,+,-,@,탭,개행과 전각 기호로 시작하면 앞에 작은따옴표를 붙여 수식 실행을 막습니다.

성공 기준

  • 응답은 CSV 바이트/Content-Disposition을 확인하고 데이터 수·열 순서를 신고 목록과 대조.

실패와 데이터 보존

  • POST /api/admin/reports/resolve 입력이 원문 실패 check 조건에 해당 → HTTP 409 — 원문 check의 실패 응답 · 유지: DB는 변경하지 않으며 실패 응답에 CSV 신고 데이터가 섞이지 않는다.
  • GET /api/admin/reports/export?status=DONE · [교육용 fixture · legacy:13-6:EX] status가 없는 값 → HTTP 400 (EX) · 유지: 신고 데이터는 바뀌지 않고 권한 실패 본문에 CSV가 없다.
  • GET /api/admin/reports/export · [교육용 fixture · legacy:13-6:P1] 일반 회원이 내려받기 → HTTP 403 (P1) · 유지: 신고 데이터는 바뀌지 않고 권한 실패 본문에 CSV가 없다.
