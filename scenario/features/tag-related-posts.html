공유 태그 수와 동률 규칙으로 추천하기

현재 글과 공유하는 태그 수로 추천하고 같은 점수는 결정적인 순서로 정렬한다.

이번에 할 일

같은 게시글 제외·접근 정책·공유 태그 개수 집계를 적용한다.

시작 조건

  • 시나리오 DB(`community`) — 앱을 기본 프로파일로 띄운다.
  • community 태그 연결과 게시판 공개 규칙이 있는 데이터 사용.

사용자 시나리오

  1. 시작
    현재 글에 태그가 붙어 있고 후보 글마다 공유하는 태그 수가 다릅니다.
    행동
    현재 글의 관련 글을 요청하고 태그 겹침 수·동률·공개 범위를 비교합니다.
    결과
    자기 글은 후보에서 빼고 볼 수 있는 후보만 원본의 공유 태그/동률 순서로 반환합니다.
    이후
    size 0은 400, 볼 수 없는 기준 글은 404입니다. 추천 조회는 태그 연결이나 후보 글을 수정하지 않습니다.

데이터와 이유

post_tag(post_id,tag_id)
기준 글과 후보 글의 공통 tag 행 수를 재현해 추천 순서를 검증한다.
GET /api/posts/{id}/related?size=1
size 1 결과와 기본 페이지 결과를 비교한다.

업무 정책

  • 기준 글과 태그가 1개 이상 겹치는 글만 후보로 하고 기준 글 자신은 제외합니다. 공유 태그 수 내림차순→published_at 최신→id 큰 순입니다.
  • size는 1~10, 기본 5이며 빈 값·숫자 아님·범위 밖은 400입니다. 기준 글 없음/접근 불가는 404, 태그 없음은 200과 items 빈 배열입니다.
  • 삭제·초안·숨김·팔로워 공개·차단 등 2-3의 모든 접근 규칙을 후보에도 적용합니다. 기존 post_tag 기본 키와 tag 역방향 인덱스를 사용하며 새 마이그레이션은 필요하지 않습니다.

성공 기준

  • 결과 순위는 공유 태그 수 내림차순 후 원문 tie-break.

실패와 데이터 보존

  • GET /api/posts/{{K1.body.id}}/related?size=0 · [교육용 fixture · legacy:14-6:K9] 잘못된 입력 — size=0 → HTTP 400 (K9) · 유지: 조회는 post_tag/추천 대상 데이터를 변경하지 않는다.
