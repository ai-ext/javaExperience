-- V6 — bookmark.memo → note 이름 변경의 3·4단계. 모든 서버가 "양쪽 쓰기" 코드(V5와 같은 커밋)가 된 뒤에 적용한다.
-- 실제 여러 대 배포라면 3(맞추기 + 읽기 전환)과 4(지우기)는 서로 다른 배포지만, 실습은 서버 한 대라 한 파일에 둔다.

-- 3. 맞추기 — V5 이후 옛 서버가 memo를 "고친" 행은 note가 null이 아니라 옛 값이다. note IS NULL로는 그 행을
--    못 잡으므로, 값이 다른 행 전부(지운 값 = null 포함, <=>는 null끼리도 같다고 본다)를 memo 기준으로 맞춘다.
UPDATE bookmark SET note = memo WHERE NOT (CAST(note AS BINARY) <=> CAST(memo AS BINARY));

-- 4. 좁히기 — 이 뒤로는 데이터 없이 되돌릴 수 없다(memo가 사라진다). 적용 전에 백업과 위 맞추기 결과를 확인한다.
ALTER TABLE bookmark DROP COLUMN memo;
