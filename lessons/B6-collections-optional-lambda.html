#B6. List·Map·Optional·람다 맛보기 — 목록 거르기·바꾸기와 없는 값

개념 레슨 · 30분

#이게 뭐냐

서비스 코드는 목록을 거르고, 바꾸고, 키로 찾고, 없을 수도 있는 값을 다룬다. 이 레슨은 맛보기다. 서비스 코드에서 자주 보는 모양만 익힌다.

#한눈에

하고 싶은 일 Java 메모
빈 리스트 만들기 List<String> titles = new ArrayList<>(); List는 약속(인터페이스, B5), ArrayList는 구현
넣기 titles.add("첫 글")
꺼내기 titles.get(0) titles[0]처럼 []로 꺼내지 않는다
개수 titles.size() 메서드다(괄호)
값을 정해 두고 만들기 List.of(70, 85, 90) 바꿀 수 없는 리스트
하나씩 돌기 for (String t : titles) : 뒤에 리스트
거르기 list.stream().filter(s -> s >= 80).toList() ->는 람다(아래)
바꾸기 list.stream().map(s -> s + 5).toList()
키 → 값 묶음 Map<String, Integer> likes = new HashMap<>();
키로 꺼내기 likes.get(key) 없으면 null
없으면 기본값 likes.getOrDefault(key, 0)
있을 수도 없을 수도 있는 값 하나 Optional<T> + map orElse 아래 설명

#<String> — 안에 무엇이 드나

List<String>은 "문자열이 든 리스트"다. 꺾쇠 안에는 참조형만 들어간다. List<int>는 안 되고 List<Integer>로 쓴다(B1의 기본형·참조형). 오른쪽 new ArrayList<>()의 빈 꺾쇠는 "왼쪽과 같은 타입"이라는 뜻이다.

#람다 — 이름 없는 짧은 함수

s -> s >= 80은 "s를 받아 s >= 80을 돌려주는 함수"다. 매개변수 하나면 괄호를 생략하고, 둘이면 (id, title) -> .... String::toUpperCase처럼 메서드 이름을 바로 넘기는 짧은 형태(메서드 참조)도 있다. 거르기·바꾸기는 list.stream()으로 흐름을 연 뒤 filter·map을 잇고, 마지막에 .toList()로 다시 리스트를 만든다.

#Optional — "없을 수도 있음"을 타입으로

저장소에서 글 하나를 찾으면 있을 수도, 없을 수도 있다. 이걸 null로 돌려주면 받는 쪽이 확인을 잊고 터진다. 그래서 "있거나 없는 값 하나"를 담는 상자 Optional<T>를 쓴다. 저장소의 findById가 Optional을 돌려주는 것이 대표적이다.

하고 싶은 일 Java
없으면 기본값 found.orElse("없음")
있으면 안의 값을 바꾸기 found.map(p -> p.title())
없으면 예외 found.orElseThrow(() -> new PostNotFoundException(id))
있는지 확인 found.isPresent()

백엔드에서 가장 많이 보는 줄은 마지막 orElseThrow다. "글이 없으면 예외 → 404 응답"으로 이어진다(B7).

  2. 새 jshell을 열고, 저장소의 findById를 흉내 낸다.
jshell> Map<Long, String> posts = Map.of(1L, "첫 글", 2L, "둘째 글");

Optional.ofNullable(값)은 값이 null이면 빈 상자, 아니면 값이 든 상자를 만든다. 마지막 줄의 예외가 B7에서 404 응답으로 바뀐다. 첫 줄의 {1=첫 글, 2=둘째 글} 순서는 실행마다 다를 수 있다(4번).

  1. 이어서 람다를 두 가지로 써 본다.
jshell> List<String> names = List.of("kim", "lee", "park");
names ==> [kim, lee, park]
jshell> names.stream().map(n -> n.toUpperCase()).toList()
$7 ==> [KIM, LEE, PARK]
jshell> names.stream().map(String::toUpperCase).toList()
$8 ==> [KIM, LEE, PARK]

두 줄은 같은 일을 한다. 실무 코드에서 String::toUpperCase, PostResponse::from 같은 모양을 보면 "그 메서드를 람다로 넘긴 것"이라고 읽는다.

  1. Map의 순서를 확인한다. jshell을 껐다 켜며 Map.of(1L, "a", 2L, "b", 3L, "c")를 여러 번 쳐 본다. 실측에서는 여섯 번에 {2=b, 1=a, 3=c}, {1=a, 3=c, 2=b}, {3=c, 2=b, 1=a}처럼 실행마다 순서가 달랐다. HashMap·Map.of는 순서를 약속하지 않는다. 순서가 필요하면 LinkedHashMap을 쓴다. 3번에 이어서 치면:
jshell> Map<String, Integer> ordered = new LinkedHashMap<>();
ordered ==> {}
jshell> ordered.put("다", 3);
$10 ==> null
jshell> ordered.put("가", 1);
$11 ==> null
jshell> ordered.put("나", 2);
$12 ==> null
jshell> ordered

#일부러 틀려 보기

새 jshell에서 ①~③을 순서대로 친 결과다. (#2:1) 같은 표시는 "2번째 입력의 1번째 줄"이라는 뜻이다. 다른 줄을 끼워 치면 번호가 달라진다.

#① List.of로 만든 리스트에 추가한다

jshell> List<Integer> scores = List.of(70, 85, 90, 55);
scores ==> [70, 85, 90, 55]
jshell> scores.add(100);

|        at ImmutableCollections.uoe (ImmutableCollections.java:142)

List.of·Map.of로 만든 것은 바꿀 수 없다(record처럼 불변). 컴파일은 되고 실행 중에 터진다. 고치기: 바꿔야 하면 new ArrayList<>(scores)로 복사해서 쓴다.

jshell> List<Integer> editable = new ArrayList<>(scores);
editable ==> [70, 85, 90, 55]
jshell> editable.add(100);
$4 ==> true

#② 꺾쇠 안에 기본형을 넣는다

jshell> List<int> nums = List.of(1, 2);
|  Error:
|  unexpected type
|    required: reference
|    found:    int
|  List<int> nums = List.of(1, 2);
|       ^-^

"참조형이 와야 하는데 int가 왔다". 고치기: List<Integer>.

#③ 빈 Optional에서 값을 꺼낸다

jshell> Optional<String> missing = Optional.empty();
missing ==> Optional.empty
jshell> missing.get()
|  Exception java.util.NoSuchElementException: No value present
|        at Optional.get (Optional.java:143)
|        at (#6:1)

get()은 "당연히 있다"고 믿고 꺼낸다. 없으면 No value present. 로그에서 이 문장을 보면 누군가 빈 Optional에 get()을 부른 것이다. 고치기: orElse(기본값)이나, 없을 때 의미 있는 예외를 던지는 orElseThrow(() -> new PostNotFoundException(id)).

#확인 문제

1. posts에서 좋아요가 10개보다 많은 글의 제목만 뽑아 리스트로 만들어라. posts는 List<Post>, Post는 record Post(String title, int likes).

정답

posts.stream().filter(p -> p.likes() > 10).map(p -> p.title()).toList(). filter로 거르고 map으로 제목만 남긴다. record 값은 likes()처럼 괄호로 꺼낸다. 앞에 stream(), 끝에 toList()가 붙는다. jshell 실측: 좋아요 5·20·11인 글 a·b·c에서 [b, c].

2. Map<String, Integer> likes에 없는 키로 likes.get("x")를 하면? 0을 받고 싶으면?

정답

null이 나온다(실측 $15 ==> null). 0을 원하면 likes.getOrDefault("x", 0). 주의: int n = likes.get("x");처럼 바로 int에 넣으면 실행 중에 터진다. 실측: NullPointerException: Cannot invoke "java.lang.Integer.intValue()" because the return value of "java.util.Map.get(Object)" is null(B1의 Integer → int).

3. List.of("a", "b").add("c")는 컴파일될까? 실행하면?

정답

컴파일은 된다(List에는 add 메서드가 있다). 실행하면 UnsupportedOperationException. List.of가 만든 리스트는 바꿀 수 없는 구현이다.

4. findById(id)가 Optional<Post>를 돌려준다. "없으면 PostNotFoundException을 던지고, 있으면 Post를 받는" 한 줄을 써라.

정답

Post post = repository.findById(id).orElseThrow(() -> new PostNotFoundException(id));. orElseThrow에는 "예외를 만드는 람다"를 넘긴다. 값이 있으면 그 값이 나오고, 없을 때만 람다가 실행되어 예외가 던져진다.

5. API 응답의 항목이 넣은 순서와 다르게 나오고, 서버를 다시 띄우면 순서가 또 바뀌기도 한다. 서버 코드에 HashMap·Map.of가 보인다. 무엇을 의심하나?

정답

HashMap(그리고 Map.of)은 순서를 약속하지 않는다. 넣은 순서를 지키지 않고, 실측에서 Map.of는 jshell을 새로 띄울 때마다 순서가 달랐다. 넣은 순서가 필요하면 LinkedHashMap, 정렬이 필요하면 리스트로 바꿔 sorted로 정렬한다.
