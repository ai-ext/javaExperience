#T-010. 태그별 글 수 통계 API

난이도 쉬움 · 유형 새 API · DB community · 예상 30분

#티켓

요청자 기획 · 배경 메인 화면 사이드바에 "인기 태그" 박스를 넣는다. 태그 이름 옆에 글 수를 붙여 많이 쓰인 순으로 보여 준다.

  • 태그별 글 수를 내려주는 API를 만들어 주세요. 로그인 없이 보는 박스라 누구나 볼 수 있는 글(게시됨·전체 공개·삭제 안 됨)만 셉니다. 팔로워 공개 글·임시저장·숨김·삭제된 글은 빼 주세요.
  • 글이 하나도 없는 태그는 안 보여 줍니다. 몇 개까지 받을지는 프론트가 정합니다(기본 10개, 최대 50개).
  • 완료 조건: 글 수가 많은 순, 같으면 태그 이름 순. 숫자는 DB에서 센다(목록을 다 읽어 자바에서 세지 않는다).

DB 시작 상태: community 처음 상태(이 저장소 루트에서 docker compose down -v && docker compose up -d — community·practice·project 세 DB를 모두 지우고 docker/mysql/init/의 처음 상태로 다시 만든다(project는 빈 DB, CloudBeaver 작업 공간도 초기화). 남길 데이터가 있으면 먼저 ./docker/mysql/dump.sh로 세 DB를 docker/mysql/backup/<시각>/에 SQL 파일로 떠 둔다. CloudBeaver에 저장한 SQL 스크립트·바꾼 설정은 이 백업에 들어가지 않으니 따로 복사해 둔다 — 미리 만든 연결 세 개는 다시 들어간다). 기준 코드로 앱을 켜면 Flyway가 V2~V6을 적용한다. 공개 글에 달린 태그는 mysql 6 · java 5 · spring 3 · 질문 2 · jpa 1 · 회고 1이고, docker·테스트는 글이 없다.

#지금 코드

  • 회원 활동 통계 API가 이미 있다 — 네이티브 SQL 한 번으로 집계하고 인터페이스 프로젝션으로 받는 방식이다. 같은 방식을 따른다.
  • 글과 태그는 연결 테이블로 이어져 있다(복합 PK). "누구나 볼 수 있는 글" 조건은 인기글 API의 SQL에도 같은 모양으로 들어 있다.

#채점 기준


C = HTTP(필수), D = DB(필수, SELECT만), R = 코드 리뷰(피드백)

확인 방법
기대





C1
요청 D
200, mysql 6 · java 5 · spring 3 · 질문 2 · jpa 1 · 회고 1 순서, 항목은 name·postCount 두 필드




C2
요청 D
200 배열이고, 팔로워 공개 글의 docker, 지운 글의 테스트가 세어지지 않았다




C3
요청 E
limit=2면 mysql, java 두 개




C4
요청 F
limit=0은 400




D1
SELECT t.name, COUNT(*) FROM tag t JOIN post_tag pt ON pt.tag_id = t.id JOIN post p ON p.id = pt.post_id WHERE p.status = 'PUBLISHED' AND p.visibility = 'PUBLIC' AND p.deleted_at IS NULL GROUP BY t.id, t.name ORDER BY COUNT(*) DESC, t.name
요청 D와 같은 6행




D2
SELECT t.name, COUNT(*) FROM tag t JOIN post_tag pt ON pt.tag_id = t.id GROUP BY t.id, t.name ORDER BY t.name
조건 없이 세면 docker·테스트도 나온다 — 조건이 왜 필요한지 비교




R1
집계 위치
GROUP BY·COUNT·ORDER BY·LIMIT을 DB에서 한다. 태그나 글을 모두 읽어 자바에서 세지 않는다




R2
공개 글 조건
세는 조건이 "비로그인이 볼 수 있는 글"과 같다. 같은 조건이 다른 SQL(인기글)에도 있다는 걸 알고, 규칙이 바뀌면 같이 고쳐야 할 곳으로 꼽을 수 있다




R3
응답 DTO
프로젝션(행)을 그대로 내보내지 않고 응답 record로 옮긴다(회원 활동 통계와 같은 방식). COUNT(*)가 Long으로 온다는 점을 처리했다




R4
정렬 끝까지
글 수가 같을 때 이름 순으로 정해서 결과가 매번 같다

#힌트 (막힐 때만)



힌트 1 — 저장소


통계 저장소에 @Query(nativeQuery = true, value = """ … """) 메서드를 하나 더 둔다. 별칭을 AS name, AS postCount로 주고 interface TagStatRow { String getName(); Long getPostCount(); }로 받는다. LIMIT :limit과 @Param("limit") int limit.






힌트 2 — 컨트롤러


@GetMapping("/api/stats/tags"), @RequestParam(defaultValue = "10") @Min(1) @Max(50) int limit — 범위를 벗어나면 다른 목록 API의 size처럼 400이 된다.
