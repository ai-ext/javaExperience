#T-008. 알림 목록에 글 제목 넣기

난이도 쉬움 · 유형 기존 API 변경 · DB community · 예상 25분

#티켓

요청자 프론트 팀 · 배경 알림 목록에 "박디비님이 댓글을 남겼어요"만 보여서 어느 글인지 모른다. 지금은 알림마다 글 상세 API를 한 번씩 더 불러 제목을 가져오는데, 알림 20개면 요청이 21번 나간다.

  • 내 알림 목록 응답의 각 항목에 글 제목을 넣어 주세요. "박디비님이 'JPA 연관관계 매핑 정리'에 댓글을 남겼어요"로 바꿉니다.
  • 서버에서도 알림마다 글을 따로 조회하지 않게 해 주세요(목록 한 번에 쿼리 수가 알림 수에 따라 늘면 안 됩니다).
  • 완료 조건: 기존 필드는 그대로, postTitle만 추가된다.

DB 시작 상태: community 처음 상태(이 저장소 루트에서 docker compose down -v && docker compose up -d — community·practice·project 세 DB를 모두 지우고 docker/mysql/init/의 처음 상태로 다시 만든다(project는 빈 DB, CloudBeaver 작업 공간도 초기화). 남길 데이터가 있으면 먼저 ./docker/mysql/dump.sh로 세 DB를 docker/mysql/backup/<시각>/에 SQL 파일로 떠 둔다. CloudBeaver에 저장한 SQL 스크립트·바꾼 설정은 이 백업에 들어가지 않으니 따로 복사해 둔다 — 미리 만든 연결 세 개는 다시 들어간다). 기준 코드로 앱을 켜면 Flyway가 V2~V6을 적용한다. 알림 테이블(V4)은 비어 있다 — 아래 요청 A·B가 회원 3(이스프링)의 글 2에 좋아요·댓글을 달아 알림을 만든다.

#지금 코드

  • 좋아요·댓글이 생기면 커밋 뒤에 알림을 만드는 리스너가 있다. 알림 행에는 글 id만 있고 제목은 글 테이블에 있다.
  • 내 알림 목록 쿼리가 이미 "보낸 사람"을 함께 읽고(fetch join) 있다. 같은 방법을 글에도 쓸 수 있다.
  • 쿼리 수는 앱 로그(org.hibernate.SQL)로 센다.

#힌트 (막힐 때만)



힌트 1 — 응답


알림 응답 record에 String postTitle을 추가하고, 서비스에서 n.getPost().getTitle()을 넣는다. 이것만 하면 동작은 하지만 알림마다 글 조회가 한 번씩 더 나간다(로그를 보라).






힌트 2 — 한 번에 읽기


내 알림 목록 JPQL에 JOIN FETCH n.actor가 있다. 그 아래 JOIN FETCH n.post를 더한다. Pageable과 fetch join을 같이 써도 되는 건 둘 다 "하나"(ManyToOne)라서다 — 컬렉션 fetch join이면 얘기가 다르다.
