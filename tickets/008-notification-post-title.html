#T-008. 알림 목록에 글 제목 넣기

난이도 쉬움 · 유형 기존 API 변경 · DB community · 예상 25분

#티켓

요청자 프론트 팀 · 배경 알림 목록에 "박디비님이 댓글을 남겼어요"만 보여서 어느 글인지 모른다. 지금은 알림마다 글 상세 API를 한 번씩 더 불러 제목을 가져오는데, 알림 20개면 요청이 21번 나간다.

  • 내 알림 목록 응답의 각 항목에 글 제목을 넣어 주세요. "박디비님이 'JPA 연관관계 매핑 정리'에 댓글을 남겼어요"로 바꿉니다.
  • 서버에서도 알림마다 글을 따로 조회하지 않게 해 주세요(목록 한 번에 쿼리 수가 알림 수에 따라 늘면 안 됩니다).
  • 완료 조건: 기존 필드는 그대로, postTitle만 추가된다.

DB 시작 상태: community 처음 상태(bash scripts/java-db.sh --reset). 기준 코드로 앱을 켜면 Flyway가 V2~V6을 적용한다. 알림 테이블(V4)은 비어 있다 — 아래 요청 A·B가 회원 3(이스프링)의 글 2에 좋아요·댓글을 달아 알림을 만든다.

#지금 코드

  • 좋아요·댓글이 생기면 커밋 뒤에 알림을 만드는 리스너가 있다. 알림 행에는 글 id만 있고 제목은 글 테이블에 있다.
  • 내 알림 목록 쿼리가 이미 "보낸 사람"을 함께 읽고(fetch join) 있다. 같은 방법을 글에도 쓸 수 있다.
  • 쿼리 수는 앱 로그(org.hibernate.SQL)로 센다.

알림 항목마다 글 제목을 함께 받아, 추가 요청 없이 문구를 만든다.

알림 목록 열기
  1. 사용자

    종 아이콘을 누른다

  2. HTTP 요청

    GET /api/me/notifications

    headers
    Authorization: Bearer tok-lee
  3. 서버

    내 알림을 최신순으로 읽을 때 보낸 사람과 글을 한 쿼리로 함께 읽고, 글 제목을 항목에 담는다

  4. DB

    sql
    SELECT n.*, a.*, p.* FROM notification n JOIN member a ON a.id = n.actor_id JOIN post p ON p.id = n.post_id WHERE n.member_id = 3 ORDER BY n.created_at DESC, n.id DESC LIMIT 20
    note
    알림이 몇 개든 목록 쿼리 1번 + 안 읽은 개수 1번
  5. HTTP 응답

    status
    200
    body

#만들 것

항목 내용
대상 GET /api/me/notifications
추가 필드 각 항목에 postTitle(문자열) — 알림이 가리키는 글의 지금 제목
쿼리 목록을 읽는 쿼리 한 번에 글까지 함께 읽는다(알림 수만큼 글 조회가 더 나가지 않는다)
그대로인 것 나머지 필드(id·type·actor·postId·commentId·read·createdAt), unreadCount, 정렬, 인증
  • DB 변화 없음.

#힌트 (막힐 때만)



힌트 1 — 응답


알림 응답 record에 String postTitle을 추가하고, 서비스에서 n.getPost().getTitle()을 넣는다. 이것만 하면 동작은 하지만 알림마다 글 조회가 한 번씩 더 나간다(로그를 보라).






힌트 2 — 한 번에 읽기


내 알림 목록 JPQL에 JOIN FETCH n.actor가 있다. 그 아래 JOIN FETCH n.post를 더한다. Pageable과 fetch join을 같이 써도 되는 건 둘 다 "하나"(ManyToOne)라서다 — 컬렉션 fetch join이면 얘기가 다르다.
