#T-015. 댓글 삭제 권한 — 글 작성자·운영자

난이도 중급 · 유형 기존 API 변경 · DB community · 예상 45분

#티켓

요청자 운영팀·기획 · 배경 광고 댓글이 달려도 운영자가 지울 수 없어서 DB로 처리하고 있다. 글쓴이들도 "내 글에 달린 악성 댓글을 내가 지우게 해 달라"고 요청한다. 글 삭제는 이미 운영자도 할 수 있는데 댓글만 작성자 전용이다.

  • 댓글 삭제를 댓글 작성자 · 그 댓글이 달린 글의 작성자 · 운영자가 할 수 있게 바꿔 주세요. 그 밖의 회원은 지금처럼 403입니다.
  • 다른 사람 글에 달린 댓글은 글 작성자 권한으로 지울 수 없습니다(내 글의 댓글만).
  • 누가 지우든 삭제 방식(soft delete)·댓글 수(comment_count) 감소·목록 표시 규칙은 지금과 같습니다.
  • 완료 조건: 세 경우 모두 204이고, 댓글 수가 정확히 한 번만 줄어든다.

DB 시작 상태: community 처음 상태(bash scripts/java-db.sh --reset). 기준 코드로 앱을 켜면 Flyway가 V2~V6을 적용한다. 글 11(질문 게시판)은 이스프링(회원 3)의 글, 글 3은 박디비(회원 4)의 글이다. 운영자 토큰은 tok-admin.

#지금 코드

  • 글 삭제와 댓글 삭제가 권한을 어떻게 다르게 확인하는지 나란히 놓고 본다.
  • 댓글에서 그 댓글이 달린 글의 작성자까지 가려면 어떤 연관을 따라가야 하는지, 그때 쿼리가 몇 번 나가는지 본다.

#화면 시나리오

내 글의 댓글 — 글쓴이가 삭제

글쓴이·운영자에게도 댓글 [삭제] 버튼이 보이고, 누르면 204 뒤 목록에서 사라진다.

toast댓글을 삭제했어요

글쓴이가 남의 댓글 삭제
  1. 사용자

    이스프링이 자기 글의 광고 댓글에서 [삭제]를 누른다

  2. HTTP 요청

    DELETE /api/comments/{광고 댓글 id}

    headers
    Authorization: Bearer tok-lee
  3. 서버

    댓글을 찾고(지운 댓글이면 404) → 댓글 작성자인가, 이 댓글이 달린 글의 작성자인가, 운영자인가 → 하나라도 맞으면 soft delete + comment_count - 1(한 트랜잭션)

  4. DB

    sql
    UPDATE comment SET deleted_at = NOW(), updated_at = NOW() WHERE id = ?; UPDATE post SET comment_count = comment_count - 1 WHERE id = 11 AND comment_count > 0
  5. HTTP 응답

    status
    204
  6. 화면

    광고 댓글이 사라지고 토스트

남의 글에 달린 댓글 — 거절
  1. 사용자

    이스프링이 박디비 글(글 3)에 달린 댓글을 지우려 한다

  2. HTTP 요청

    DELETE /api/comments/{그 댓글 id}

    headers
    Authorization: Bearer tok-lee
  3. HTTP 응답

    status
    403
    body
    {"status": 403, "detail": "댓글을 삭제할 권한이 없습니다."}
  4. 화면

    권한 없음 토스트

#만들 것

항목 내용
대상 DELETE /api/comments/{id}
204 요청자가 댓글 작성자 또는 그 댓글이 달린 글의 작성자 또는 운영자(ADMIN)
403 위 셋이 아님
404 없는 댓글, 이미 지운 댓글(누가 지웠든) — 권한 확인보다 먼저
그대로인 것 soft delete, comment_count 1 감소(같은 트랜잭션), 댓글 목록 표시 규칙

#채점 기준


C = HTTP(필수), D = DB(필수, SELECT만), R = 코드 리뷰(피드백)

확인 방법
기대





C1
요청 A·B·C
관계없는 회원 403, 글 작성자 204




C2
요청 P0·P1
댓글 하나 달고 지운 뒤 commentCount가 처음과 같다(한 번만 줄었다)




C3
요청 E·F·G
운영자 204, 이미 지운 댓글은 운영자에게도 404




C4
요청 H·I·J
남의 글에 달린 댓글은 글 작성자 권한이 없다(403), 그 글의 작성자는 204




C5
요청 L
지운 두 댓글이 목록에 없다(답글이 없는 최상위라 자리도 남지 않는다)




D1
SELECT p.comment_count, (SELECT COUNT(*) FROM comment c WHERE c.post_id = p.id AND c.deleted_at IS NULL) AS actual FROM post p WHERE p.id IN (3, 11) ORDER BY p.id
각 행의 두 값이 같다(글 3 0 0, 글 11 4 4) — 몇 번을 돌려도 어긋나지 않는다




D2
SELECT COUNT(*) FROM comment WHERE content LIKE '[T-015]%' AND deleted_at IS NULL
0 — 이 티켓으로 만든 댓글은 모두 지워졌다




R1
권한 판정 위치
"누가 지울 수 있나"를 한 메서드(또는 정책 클래스)에 모았다. 글 삭제의 "작성자 또는 운영자" 판정과 나란히 읽힌다




R2
순서
404(없음·이미 지움)를 403보다 먼저 본다. 반대면 지워진 댓글에 대해 권한 오류가 나와 상태가 드러난다




R3
쿼리
글 작성자 확인을 위해 댓글 → 글 → 작성자 id까지 따라갈 때 어떤 SELECT가 더 나가는지 로그로 확인했다(프록시의 id만 읽으면 로딩이 안 된다는 점 포함)

#힌트 (막힐 때만)



힌트 1 — 판정


boolean canDelete = 댓글 작성자 id == 내 id || 댓글.getPost().getAuthor().getId() == 내 id || "ADMIN".equals(내 role). 로그인 회원 정보에는 이미 역할(role)이 들어 있다. 글 삭제 쪽 코드가 같은 모양이다.






힌트 2 — 지연 로딩


comment.getPost()는 프록시라 getId()까지는 쿼리가 안 나가지만, getAuthor()를 부르면 글을 읽는 SELECT가 한 번 나간다. 서비스 메서드가 트랜잭션 안이라 문제는 없다. 거슬리면 댓글을 읽을 때 글을 함께 fetch하는 조회 메서드를 하나 더 둔다.
