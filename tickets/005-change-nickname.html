#T-005. 닉네임 변경 API

난이도 쉬움 · 유형 새 API · DB community · 예상 40분

#티켓

요청자 기획 · 배경 가입 때 정한 닉네임을 못 바꾼다는 문의가 계속 온다. 마이페이지에 "닉네임 변경"을 넣는다.

  • 로그인한 회원이 자기 닉네임을 바꾸는 API를 만들어 주세요. 앞뒤 공백은 잘라서 저장하고, 자른 뒤 2~20자여야 합니다.
  • 다른 회원이 쓰고 있는 닉네임이면 거절(409)합니다. 지금 내 닉네임을 그대로 다시 저장하는 건 성공이어야 합니다(프론트가 다른 항목과 같이 저장 버튼을 누르는 경우).
  • 완료 조건: 바꾼 뒤 내가 쓰는 글·댓글의 작성자 이름이 새 닉네임으로 나온다.

DB 시작 상태: community 처음 상태(이 저장소 루트에서 docker compose down -v && docker compose up -d — community·practice·project 세 DB를 모두 지우고 docker/mysql/init/의 처음 상태로 다시 만든다(project는 빈 DB, CloudBeaver 작업 공간도 초기화). 남길 데이터가 있으면 먼저 ./docker/mysql/dump.sh로 세 DB를 docker/mysql/backup/<시각>/에 SQL 파일로 떠 둔다. CloudBeaver에 저장한 SQL 스크립트·바꾼 설정은 이 백업에 들어가지 않으니 따로 복사해 둔다 — 미리 만든 연결 세 개는 다시 들어간다). 기준 코드로 앱을 켜면 Flyway가 V2~V6을 적용한다. 회원 2(tok-kimjava)의 닉네임은 김자바, 회원 3은 이스프링.

#지금 코드

  • 회원 엔티티는 조회만 하고 있어 값을 바꾸는 메서드가 없다. 회원 테이블에 닉네임 UNIQUE 제약이 있는지 확인한다.
  • "이름 앞뒤 공백 자르고 길이 검사 → 중복이면 409"와 거의 같은 규칙을 이미 쓰는 기능이 하나 있다(내 북마크 폴더 이름). 그 서비스를 참고한다.
  • 토큰으로 로그인한 회원을 컨트롤러 매개변수로 받는 방법은 다른 "내 것" API(/api/me/...)를 본다.

#만들 것

항목 내용
메서드·경로 PATCH /api/me
인증 필수(토큰 없으면 401 — 인터셉터가 이미 막는다)
요청 본문 {"nickname": "자바왕"}
규칙 앞뒤 공백을 자른 값을 저장. 자른 뒤 2~20자 아니면(없음·빈 값 포함) 400
중복 다른 회원이 쓰는 닉네임이면 409. 지금 내 닉네임과 같으면 200(바뀐 것 없음)
응답 200 {"id": 2, "email": "kimjava@example.invalid", "nickname": "자바왕"} — 이 세 필드
DB 변화 member.nickname, member.updated_at
  • 두 요청이 동시에 같은 닉네임을 노려도 결국 하나만 성공해야 한다 — 마지막 방어선은 DB의 UNIQUE 제약이고, 그때 나는 예외도 409로 바꾼다.

D1
SELECT id, nickname FROM member WHERE id IN (2, 3) ORDER BY id
2 자바왕 · 3 이스프링 — B가 실패했으니 회원 3은 그대로




D2
SELECT COUNT(*) FROM member WHERE nickname <> TRIM(nickname)
0 — 공백 붙은 닉네임이 저장되지 않았다




R1
계층
컨트롤러는 로그인 회원 id와 요청만 넘기고, 길이·중복 규칙은 서비스, 값 바꾸기는 엔티티 메서드(changeNickname 등 — setter를 열지 않는다)




R2
중복 확인
"나를 뺀" 중복 확인(...AndIdNot)이다. 그냥 existsByNickname이면 C4가 409가 된다




R3
동시 요청
확인과 저장 사이 경쟁은 UNIQUE 제약이 막고, 그 예외(DataIntegrityViolationException)를 409로 바꾼다(saveAndFlush로 그 자리에서 터지게)




R4
오류 응답
400·409가 다른 API와 같은 Problem Details 모양이다(전역 핸들러에 추가)

#힌트 (막힐 때만)



힌트 1 — 모양


record NicknameChangeRequest(String nickname), record MeResponse(Long id, String email, String nickname). 컨트롤러 @PatchMapping("/api/me")에서 @LoginMember AuthenticatedMember me와 @RequestBody를 받는다.






힌트 2 — 서비스


strip() → 길이 검사(아니면 400 예외) → memberRepository.existsByNicknameAndIdNot(nickname, me.id())면 409 예외 → member.changeNickname(nickname, now) → saveAndFlush를 try/catch (DataIntegrityViolationException)로 감싸 409. 북마크 폴더 이름 변경 서비스가 같은 순서다.
