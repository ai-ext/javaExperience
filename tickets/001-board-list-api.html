난이도 쉬움 · 유형 새 API · DB community · 예상 20분

#티켓

요청자 프론트 팀 · 배경 상단 게시판 탭과 글쓰기 화면의 "게시판" 드롭다운이 지금 프론트 코드에 하드코딩돼 있다. 게시판이 추가될 때마다 프론트를 다시 배포해야 한다.

  • 게시판 목록을 내려주는 API를 만들어 주세요. 탭 순서는 DB에 있는 순서(정렬 순서 컬럼)를 따릅니다.
  • 공지사항처럼 운영자만 글을 쓸 수 있는 게시판은 드롭다운에서 비활성으로 보여 줄 거라, 그걸 알 수 있는 값도 필요합니다.
  • 완료 조건: 로그인 없이 호출할 수 있고, 아래 "만들 것"의 모양과 순서로 내려온다.

DB 시작 상태: community 처음 상태(이 저장소 루트에서 docker compose down -v && docker compose up -d — community·practice·project 세 DB를 모두 지우고 docker/mysql/init/의 처음 상태로 다시 만든다(project는 빈 DB, CloudBeaver 작업 공간도 초기화). 남길 데이터가 있으면 먼저 ./docker/mysql/dump.sh로 세 DB를 docker/mysql/backup/<시각>/에 SQL 파일로 떠 둔다. CloudBeaver에 저장한 SQL 스크립트·바꾼 설정은 이 백업에 들어가지 않으니 따로 복사해 둔다 — 미리 만든 연결 세 개는 다시 들어간다). 기준 코드로 앱을 켜면 Flyway가 V1을 기준선으로 적고 V2~V6을 적용한다(다음 마이그레이션 번호는 V7).

#지금 코드

  • 게시판 엔티티와 저장소는 이미 있다(게시판 글 목록 API가 slug로 게시판을 찾을 때 쓴다). 컨트롤러·서비스는 없다.
  • "운영자만 글쓰기"는 글 작성 API가 이미 검사하고 있다 — 그 검사가 어떤 컬럼 값을 보는지 찾아서 같은 기준을 쓴다.

#채점 기준


C = HTTP(필수), D = DB(필수, SELECT만), R = 코드 리뷰(피드백)

기대





C1
요청 A
상태 200, JSON 배열, 4개




C2
요청 A
slug 순서가 notice, dev, qna, free — 정렬 순서 컬럼 기준

요청 A
항목이 slug·name·adminOnly 세 필드뿐이고, notice만 adminOnly: true




C4
요청 B
토큰이 있어도 200, 같은 순서




D1
SELECT slug, name, write_role FROM board ORDER BY sort_order
notice 공지사항 ADMIN · dev 개발 USER · qna 질문 USER · free 자유 USER — 응답과 같은 순서·같은 판정




R1
응답 모양
엔티티(Board)를 그대로 돌려주지 않고 응답 전용 DTO를 쓴다(id·createdAt·writeRole 원문이 새지 않는다)




R2
정렬
정렬을 DB(ORDER BY sort_order)에 맡긴다. 전부 읽어 자바에서 정렬하거나 순서를 코드에 박지 않는다




R3
운영자 전용 판정
글 작성 API의 "운영자만" 검사와 같은 기준(write_role)을 쓴다. 상수 문자열이 두 곳에 흩어지면 한 곳으로 모으는 방안을 말할 수 있다
