#T-007. 글 대표 이미지 주소 컬럼 추가

난이도 쉬움 · 유형 스키마 변경 · DB community · 예상 40분

#티켓

요청자 프론트 팀 · 배경 목록을 카드형으로 바꾸면서 글마다 대표 이미지(썸네일)를 보여 주려 한다. 이미지 업로드는 이미 외부 저장소로 되어 있고, 업로드하면 https:// 주소를 받는다. 서버는 그 주소만 저장하면 된다.

  • 글 작성 때 대표 이미지 주소를 선택으로 받아 저장하고, 상세와 게시판 목록 응답에 내려 주세요. 없으면 null.
  • 주소는 https://로 시작해야 하고 500자까지입니다.
  • 스키마는 Flyway 마이그레이션으로만 바꿉니다(운영 DB에 손으로 ALTER 금지).
  • 완료 조건: 기존 글은 그대로(null) 보이고, 앱을 다시 켜도 마이그레이션이 한 번만 적용된다.

DB 시작 상태: community 처음 상태(bash scripts/java-db.sh --reset). 기준 코드로 앱을 켜면 Flyway가 V1을 기준선으로 적고 V2~V6을 적용한다 — 다음 마이그레이션 번호는 V7이다.

#지금 코드

  • 마이그레이션 파일이 어디에 있고 이름 규칙이 어떤지(V<번호>__<설명>.sql) 본다. 이미 적용된 파일은 고치지 않는다.
  • JPA 설정이 "엔티티와 테이블이 다르면 기동 실패"(ddl-auto: validate)다. 엔티티에만 필드를 추가하고 마이그레이션을 빠뜨리면 앱이 안 뜬다 — 일부러 한 번 겪어 봐도 좋다.
  • 글 응답 DTO가 세 종류다(작성 응답·상세·목록 항목). 이번에 어느 것에 넣는지 "만들 것"을 본다.

대표 이미지와 함께 저장
  1. 사용자

    이미지를 올려 주소를 받은 뒤 [저장]을 누른다

  2. HTTP 요청

    POST /api/posts

    headers
    Authorization: Bearer tok-kimjava · Content-Type: application/json
    body
    {"boardSlug": "dev", "title": "[T-007] 썸네일 있는 글", "content": "대표 이미지 확인", "thumbnailUrl": "https://img.example.com/t-007.png"}
  3. 서버

    형식(https://, 500자)을 확인하고 글과 함께 thumbnail_url을 저장한다

  4. DB

    sql
    INSERT INTO post (…, thumbnail_url, …) VALUES (…, 'https://img.example.com/t-007.png', …)
  5. HTTP 응답

    status
    201
    body
    {"id": 22, ..., "thumbnailUrl": "https://img.example.com/t-007.png"}
  6. 화면

    목록 맨 위 카드에 이미지가 보인다

기존 글
  1. 사용자

    개발 게시판 목록을 연다

  2. HTTP 요청

    GET /api/boards/dev/posts?size=5

  3. 서버

    마이그레이션 전에 있던 글은 thumbnail_url이 NULL — 응답에 null로 나간다

  4. HTTP 응답

    status
    200
    body
    {"items": [{"id": 22, ..., "thumbnailUrl": "https://…"}, {"id": 2, ..., "thumbnailUrl": null}], ...}
  5. 화면

    이미지가 없는 카드는 기본 그림을 쓴다

#만들 것

항목 내용
마이그레이션 src/main/resources/db/migration/V7__add_post_thumbnail_url.sql — post.thumbnail_url VARCHAR(500) NULL 추가. 기존 행 백필 없음
작성 요청 POST /api/posts 본문에 선택 필드 thumbnailUrl. 보내면 https://로 시작하고 공백 없이 500자 이하, 아니면 400
응답 POST /api/posts(작성 응답)·GET /api/posts/{id}(상세)·GET /api/boards/{slug}/posts의 각 항목에 thumbnailUrl(문자열 또는 null)
그대로인 것 나머지 필드, thumbnailUrl을 안 보낸 작성 요청(→ null)
  • 수정 API로 대표 이미지를 바꾸는 것은 이번 범위가 아니다. 상세와 같은 DTO를 쓰는 수정 응답에 thumbnailUrl이 함께 나오는 것은 괜찮다.

H='Authorization: Bearer tok-kimjava'

  -d '{"boardSlug":"dev","title":"[T-007] 썸네일 있는 글","content":"대표 이미지 확인","thumbnailUrl":"https://img.example.com/t-007.png"}'
curl -s "$BASE/api/posts/{id}"                       # 요청 B — 상세
curl -s "$BASE/api/boards/dev/posts?size=5"           # 요청 C — 목록
curl -s "$BASE/api/posts/2"                           # 요청 D — 기존 글
# 요청 E — http 주소 / 요청 F — 이미지 없이 작성
curl -i -X POST "$BASE/api/posts" -H "$H" -H 'Content-Type: application/json' \
  -d '{"boardSlug":"dev","title":"[T-007] http","content":"x","thumbnailUrl":"http://img.example.com/a.png"}'
curl -s -X POST "$BASE/api/posts" -H "$H" -H 'Content-Type: application/json' -d '{"boardSlug":"dev","title":"[T-007] 이미지 없음","content":"x"}'

R1
마이그레이션
새 파일(V7)로 추가했다. 적용된 V1~V6을 고치지 않았다(체크섬 검증 실패)




R2
NULL 허용
선택 값이라 NULL 허용·백필 없음이 맞다. NOT NULL DEFAULT ''로 "없음"을 빈 문자열로 표현하지 않는다




R3
세 DTO
작성·상세·목록 DTO를 모두 고쳤고, 컴파일 에러를 따라 테스트 코드까지 맞췄다




R4
검증 위치
형식 검증이 요청 DTO(Bean Validation)에 있다. 주소의 이미지가 실제로 있는지는 서버가 확인하지 않는다는 한계를 말할 수 있다

#힌트 (막힐 때만)



힌트 1 — 마이그레이션


ALTER TABLE post ADD COLUMN thumbnail_url VARCHAR(500) NULL AFTER excerpt;


파일 이름의 밑줄은 두 개(V7__...)다. 앱을 켜면 로그에 Migrating schema ... to version "7 - add post thumbnail url"이 보인다.






힌트 2 — 엔티티와 요청


엔티티에 @Column(name = "thumbnail_url", length = 500) private String thumbnailUrl;. 요청 record에 @Size(max = 500) @Pattern(regexp = "https://\\S+") String thumbnailUrl — @Pattern은 null을 통과시키므로 선택 필드에 그대로 쓸 수 있다.
