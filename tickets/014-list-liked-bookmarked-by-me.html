#T-014. 글 목록에 내 좋아요·북마크 표시

난이도 중급 · 유형 기존 API 변경 · DB community · 예상 60분

#티켓

요청자 프론트 팀 · 배경 목록 카드의 하트·책갈피 아이콘을 "내가 눌렀는지"에 따라 채우고 싶다. 지금은 목록을 받은 뒤 카드마다 상세 API를 한 번씩 더 불러 확인하고 있어서, 목록 하나에 요청이 20번 넘게 나간다.

  • 게시판 글 목록과 조합 검색 응답의 각 항목에 "내가 좋아요했는지"·"내가 북마크했는지"를 넣어 주세요. 비로그인은 둘 다 false입니다.
  • 서버도 항목마다 따로 조회하면 같은 문제를 서버로 옮긴 것뿐입니다. 목록 크기(최대 50)와 상관없이 쿼리 수가 일정해야 합니다.
  • 완료 조건: 기존 필드·정렬·건수는 그대로이고 두 필드만 더해진다. 좋아요를 누르고 다시 목록을 받으면 바로 반영돼 있다.

DB 시작 상태: community 처음 상태(이 저장소 루트에서 docker compose down -v && docker compose up -d — community·practice·project 세 DB를 모두 지우고 docker/mysql/init/의 처음 상태로 다시 만든다(project는 빈 DB, CloudBeaver 작업 공간도 초기화). 남길 데이터가 있으면 먼저 ./docker/mysql/dump.sh로 세 DB를 docker/mysql/backup/<시각>/에 SQL 파일로 떠 둔다. CloudBeaver에 저장한 SQL 스크립트·바꾼 설정은 이 백업에 들어가지 않으니 따로 복사해 둔다 — 미리 만든 연결 세 개는 다시 들어간다). 기준 코드로 앱을 켜면 Flyway가 V2~V6을 적용한다. 박디비(회원 4)는 자유 게시판 글 4·9·12·14에 좋아요를 눌렀고, 이스프링(회원 3)은 글 5에 좋아요, 글 5·9·13(자유 게시판)과 2에 북마크를 해 두었다.

#지금 코드

  • 게시판 목록과 조합 검색은 같은 서비스 메서드에서 같은 항목 DTO로 바뀐다. 고칠 곳이 한 군데로 모이는지 확인한다.
  • 좋아요·북마크 저장소에는 "한 글"을 기준으로 한 메서드만 있다. 이번에는 "글 여러 개"를 한 번에 물어야 한다.

SELECT post_id FROM post_like WHERE member_id = 4 AND post_id IN (SELECT id FROM post WHERE board_id = 4) ORDER BY post_id
4 6 8 9 12 14 — 그중 목록에 보이는 4 9 12 14만 C1에서 true(6 팔로워 공개·8 삭제는 박디비 목록에 없다)




D2

T1
(선택) 목록 SQL 수 테스트
로그인 상태로 size=5와 size=20의 SQL 문장 수가 같다(기존 PostListQueryCountTest와 같은 방식)




R1
쿼리 수
항목마다 exists…를 부르지 않고, 목록의 글 id 묶음으로 IN 쿼리 한 번씩(좋아요·북마크) 읽어 Set으로 판정한다. 비로그인이면 그 두 쿼리도 보내지 않는다




R2
위치
게시판 목록·검색이 공유하는 응답 변환 한 곳에서 처리했다(두 API에 같은 코드를 복사하지 않음)




R3
대안
목록 쿼리에 LEFT JOIN post_like … ON member_id = ?를 붙이는 방법과 비교해, 페이지 COUNT 쿼리·행 중복·쿼리 재사용 측면에서 왜 "목록 뒤에 IN 한 번"을 골랐는지(또는 반대) 말할 수 있다

#힌트 (막힐 때만)



힌트 1 — 저장소


@Query("SELECT l.post.id FROM PostLike l WHERE l.member.id = :memberId AND l.post.id IN :postIds") List<Long> findLikedPostIds(...) — 북마크도 같은 모양. 반환값을 Set<Long>으로 바꿔 두고 항목을 만들 때 contains로 본다. 목록이 비었으면 IN ()을 보내지 않는다.






힌트 2 — 어디서 부르나


목록·검색 결과(Page<Post>)를 응답으로 바꾸는 private 메서드에 보는 사람 id를 넘기고, 거기서 글 id 목록을 뽑아 두 쿼리를 보낸 다음 항목을 만든다. 항목 DTO record에 필드 두 개를 더하면 컴파일 에러가 나는 곳(테스트 포함)을 따라가 맞춘다.
