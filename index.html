백엔드가 처음인데, 어디서 시작하나요?

기본 시작점인 0-1에서 작은 Java API를 먼저 만드세요. Java 문법이 익숙하면 ‘시작점 바꾸기’에서 게시글 API를 선택하고, SQL을 연습하려면 DB 경로를 고르면 됩니다.

여기서 코드를 작성하고 실행하나요?

#초기화 전 백업과 DB 복원

루트 compose의 down -v는 community·practice·project와 CloudBeaver 작업 공간(저장한 SQL·바꾼 연결 설정)을 함께 지운다. 먼저 ./docker/mysql/dump.sh로 DB를 백업하고, CloudBeaver 자료는 별도로 복사한다. DB 덤프에는 CloudBeaver 작업 공간이 들어 있지 않으며, 다시 띄우면 저장소 기본 계정·연결로 시작한다.

dump.sh의 --compact 덤프에는 기존 테이블을 지우는 DROP TABLE이 없다. 초기화로 시드가 다시 적재된 DB 위에 덮어 넣으면 테이블·키 중복이 나므로, 앱을 멈추고 아래 대상 DB를 지워도 되는지 확인한 뒤 빈 DB에 복원한다. 이 절차는 현재 DB 내용을 백업 시점으로 교체한다. --seed가 아닌 일반 백업 디렉터리를 지정한다(project가 없었던 백업은 그 DB를 건너뜀).

# javaExperience 레포 루트에서 실행. 실제 백업 디렉터리 이름으로 바꾼다.
backup_dir=docker/mysql/backup/20261024-120000
test -s "$backup_dir/01-community.sql" && test -s "$backup_dir/02-practice.sql" || exit 1
docker compose up -d mysql
# docker compose ps에서 mysql이 healthy가 된 다음 아래를 실행한다.
for db in community practice project; do
  case "$db" in
    community) file=01-community.sql ;;
    practice) file=02-practice.sql ;;
    project) file=03-project.sql ;;
  esac
  if [ ! -s "$backup_dir/$file" ]; then continue; fi
  docker compose exec -T mysql mysql -uroot -proot -e "DROP DATABASE IF EXISTS $db; CREATE DATABASE $db CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci; GRANT ALL PRIVILEGES ON $db.* TO 'community'@'%';" || exit 1
  docker compose exec -T mysql mysql -uroot -proot "$db" < "$backup_dir/$file" || exit 1
done

01-community.sql에는 USE가 없어 대상 DB를 인자로 준다. 나머지 덤프는 CREATE DATABASE·USE를 포함한다. 백업 시점에 각 DB의 테이블·정확한 행 수·대표 조회 결과를 따로 기록하고, 복원 뒤 같은 조회로 대조한다. project의 flyway_schema_history도 백업에 포함되므로 정상 복원한 뒤 앱을 시작한다. 파일 크기만으로 복원 성공을 판단하지 않는다.

#테스트

./gradlew test는 위 DB를 쓰지 않는다. Testcontainers가 일회용 MySQL 8.4 컨테이너를 띄우고, 시나리오용 dump(docker/mysql/init/01-community.sql)를 넣은 뒤 테스트한다(src/test/resources/application-test.yml). 그래서 테스트가 개발용 데이터를 망가뜨리지 않는다. Docker 런타임이 꺼져 있으면 실패한다. 먼저 docker info와 docker compose version이 성공하는지 확인하고, 호스트 JDK 21에서 테스트를 실행한다. 런타임 전용 환경 변수는 기본 실행에 필요하지 않다.

첫 실행 준비

IDE에서 서버를 켜고, 브라우저에서 응답을 확인해요.

  1. JDK 21로 프로젝트를 여세요

    IntelliJ IDEA에서 이 저장소를 Gradle 프로젝트로 열고, 프로젝트 JDK를 21로 설정하세요. Gradle 동기화가 끝나면 다음으로 넘어가요.

    JDK 버전 확인 명령

    프로젝트 폴더의 터미널에서 확인하세요.

    ./gradlew --version
  2. 앱과 DB의 연결 주소를 확인하세요

    현재 기본 설정은 MySQL의 localhost:3306에 연결합니다. Docker의 DB를 쓴다면 Docker 런타임을 켜고 연결 포트를 확인하세요.

    DB 포트가 서로 달라요앱은 localhost:3306, Compose 기본값은 localhost:13308입니다. 이 Docker DB를 사용하려면 앱의 연결 포트를 맞추세요. 실행 중인 포트는 docker compose ps로 확인할 수 있어요.

    Docker DB 실행·상태 확인 명령
    docker compose up -d
docker compose ps

    MySQL이 healthy인지 확인하세요. 기본 포트를 바꿔 실행했다면 실제 포트에 맞춰 연결해야 해요.

  3. Main을 실행하고 hello를 확인하세요

    IDE에서 org.example.Main을 실행하세요. 기본 주소 localhost:8080/hello를 열어 hello가 보이면 서버가 응답하는 거예요.

    터미널에서 서버 실행하기
    ./gradlew bootRun

    이미 IDE에서 실행했다면 다시 실행할 필요는 없어요.

  4. 학습 화면은 문서 서버로 여세요

    API 서버는 8080, 학습 화면은 8765 포트를 사용해요. 문서 서버 주소에서 학습 화면을 열면 요청 보내기와 이어하기를 이용할 수 있어요.

    문서 서버 실행 명령과 주소

    프로젝트 폴더에서 새 터미널을 열고 실행하세요.

    python3 -m http.server 8765 --bind 127.0.0.1

    브라우저에서 127.0.0.1:8765/index.html을 여세요.

위 단계는 직접 확인하는 안내입니다. 준비 전에도 과제는 열어볼 수 있어요.
