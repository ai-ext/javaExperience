시작 전에 궁금할 수 있어요

백엔드가 처음인데, 어디서 시작하나요?

기본 시작점인 0-1에서 작은 Java API를 먼저 만드세요. Java 문법이 익숙하면 ‘시작점 바꾸기’에서 게시글 API를 선택하고, SQL을 연습하려면 DB 경로를 고르면 됩니다.

여기서 코드를 작성하고 실행하나요?

코드는 내 IDE에서 작성하고 서버도 직접 실행합니다. 학습 화면에서 요구사항과 가이드를 확인하고, 과제의 요청 도구로 내 서버에 요청을 보냅니다. 홈의 미리보기는 예시 데이터로 동작합니다.

학습 기록과 완료 표시는 어떻게 남나요?

직접 시작한 과제의 마지막 학습 장면을 이 브라우저에 저장합니다. 현재 이어하기는 Java·게시글 API·DB 시작 경로와 각각의 다음 과제, 총 6개 과제에서 지원합니다. 과제를 구경하거나 개념 설명을 열어도 하던 작업은 바뀌지 않습니다. ‘직접 확인 완료’는 본인의 확인 기록이며 자동 채점 결과가 아닙니다. 브라우저 데이터를 지우면 기록도 사라집니다.

#javaExperience

Spring Boot 백엔드를 직접 만들면서 배우는 공개 실습 레포다. 게시판 API 101단계를 이어서 만들고, Codex 또는 Claude Code로 단계별 채점과 피드백을 받을 수 있다. 시나리오와 HTML은 GitHub 로그인 없이 읽거나 다운로드할 수 있다.

폴더 내용
scenario/ 따라 만들기 시나리오 — 101단계 요구사항·난이도·역할별 전체 코드 접기, 쿼리 연습 18개, JWT 이후 세션 인증과 interface/impl 선택 실습. 여기서 시작한다
practice/ 학습용 미션 — 함정이 섞인 많은 데이터(practice DB)로 조회·쿼리 연습
docs/knowledge/ 공부자료 134개 — 단계마다 "필요한 지식"으로 링크된다
docker/ 실습 DB(MySQL 8.4) 초기 데이터 dump(mysql/init/)와 CloudBeaver(웹 DBeaver) 설정
src/ 여러분이 개발할 Spring Boot 4.1 프로젝트(지금은 /hello만 있다)
tools/site/ .md → .html 빌드 도구(문서를 고칠 때만 쓴다)

#시작하기

준비물: Docker Desktop, IntelliJ IDEA, JDK 21(없으면 Gradle이 찾는다 — gradle/gradle-daemon-jvm.properties). AI 채점을 원하면 Codex 또는 Claude Code를 선택해 쓸 수 있다.

git clone https://github.com/ai-ext/javaExperience.git
cd javaExperience
git switch -c <내이름>/ch1          # 각자 자기 브랜치에서 개발한다
docker compose up -d        # DB와 CloudBeaver 띄우기(처음 한 번은 1~2분)
  1. IntelliJ로 폴더를 열고(Gradle 프로젝트로 가져오기), org.example.Main을 실행한다.
  2. 브라우저로 http://localhost:8080/hello → hello가 보이면 준비 끝.
  3. 아래 명령으로 문서 서버를 켜고 브라우저에서 http://127.0.0.1:8765/scenario/README.html을 연다. 백엔드가 처음이면 0-1, 이미 Java 기본기를 알면 1-1부터 시작한다. GitHub에서는 scenario/README.md를 바로 읽을 수 있다.
python3 -m http.server 8765 --bind 127.0.0.1

문서 서버는 정적 HTML과 단계별 전체 코드 파일을 제공한다. 페이지의 화면 흐름과 코드 토글을 본 뒤 서버 주소를 입력하고 요청 버튼으로 API를 호출할 수 있다. community·practice·10장 project DB는 서로 다른 데이터이므로 DB를 바꿀 때 이전 단계의 글 ID를 재사용하지 않는다.

#DB 접속 정보

항목 값
호스트·포트 localhost · 13308
계정 community / community
DB community — 본편 기본 DB · practice — 쿼리·배치용 학습 데이터 · project — 10장 별도 프로젝트(빈 DB)

느린 쿼리와 인덱스 실습은 별도 javaexperience_perf DB를 쓴다. DB-14 실제 스키마부터 느린 쿼리까지에서 DBeaver/CloudBeaver로 열·인덱스·FK를 직접 확인하고, 같은 목록 쿼리의 실행 계획을 인덱스 전후로 비교한다. 이 DB는 127.0.0.1:13319의 전용 임시 컨테이너이며 practice 데이터와 분리된다.

10장은 ./gradlew bootRun --args='--spring.profiles.active=project'로 실행한다. 기존 Docker 볼륨에는 새 project DB가 자동으로 생기지 않는다. 데이터를 지우지 않고 추가하려면 docker compose exec -T mysql mysql -uroot -proot -e "CREATE DATABASE IF NOT EXISTS project; GRANT ALL PRIVILEGES ON project.* TO 'community'@'%';"를 한 번 실행한다.

CloudBeaver(웹 DBeaver) — compose에 들어 있다

항목 값
주소 http://localhost:8978
로그인 cbadmin / Admin1234
연결 community (시나리오) · practice (학습용) · project (10장) — 새 CloudBeaver 작업 공간에 미리 들어 있다
  • 연결 설정은 docker/cloudbeaver/data-sources.json이고 처음 뜰 때 한 번 들어간다. 바꿨다면 docker compose rm -sf cloudbeaver && docker volume rm <폴더이름>_cloudbeaver-data && docker compose up -d.
  • 아이디가 admin이 아닌 이유: CloudBeaver에 같은 이름의 기본 팀이 있어 쓸 수 없다. 비밀번호는 CloudBeaver 규칙(8자 이상·대소문자·숫자)에 맞춘 것이다.
  • 데스크톱 DBeaver를 쓰면: 새 연결 → MySQL → 위 DB 값 입력 → Driver properties에서 allowPublicKeyRetrieval = true.
  • Docker 안에서 도는 다른 도구에서 붙을 때는 호스트를 localhost가 아니라 host.docker.internal로 넣는다(컨테이너 안의 localhost는 컨테이너 자신이다).
  • 13308·8978가 이미 쓰이고 있으면 DB_PORT=13318 CB_PORT=8989 docker compose up -d로 바꾼다. DB 포트를 바꾸면 application.yml의 포트도 같이 바꾼다.

#테스트

./gradlew test는 위 DB를 쓰지 않는다. Testcontainers가 일회용 MySQL 8.4 컨테이너를 띄우고, 시나리오용 dump(docker/mysql/init/01-community.sql)를 넣은 뒤 테스트한다(src/test/resources/application-test.yml). 그래서 테스트가 개발용 데이터를 망가뜨리지 않는다. Docker Desktop이 꺼져 있으면 실패한다.

#작업 방식

  • 각자 <이름>/<장> 브랜치(예: hyemin/ch1)에서 개발하고 push한다. 리뷰를 받고 싶으면 PR을 연다.
  • main에는 직접 push하지 않는다(무료 플랜이라 보호 규칙으로 막혀 있지는 않다 — 약속으로 지킨다).
  • 시나리오·문서를 고치면 cd tools/site && npm install && npm run build로 .html을 다시 만들어 함께 커밋한다(깨진 링크가 있으면 빌드가 실패한다). 누적 전체 코드를 제공하는 시나리오에는 canonical snapshots/<id>.json과 snapshots/blobs/*.txt를 scenario/snapshots/에 함께 둔다. canonical snapshot을 복사한 뒤 python3 tools/site/localize-snapshots.py를 실행해 공개 DB 포트 설정과 blob 참조를 갱신한다. HTML은 목록과 파일 코드를 사용자가 펼칠 때 각각 지연 로드한다.

IDE에서 서버를 켜고, 브라우저에서 응답을 확인해요.

  1. JDK 21로 프로젝트를 여세요

    IntelliJ IDEA에서 이 저장소를 Gradle 프로젝트로 열고, 프로젝트 JDK를 21로 설정하세요. Gradle 동기화가 끝나면 다음으로 넘어가요.

    JDK 버전 확인 명령

    프로젝트 폴더의 터미널에서 확인하세요.

    ./gradlew --version
  2. 앱과 DB의 연결 주소를 확인하세요

    현재 기본 설정은 MySQL의 localhost:3306에 연결합니다. Docker의 DB를 쓴다면 Docker Desktop을 켜고 연결 포트를 확인하세요.

    DB 포트가 서로 달라요앱은 localhost:3306, Compose 기본값은 localhost:13308입니다. 이 Docker DB를 사용하려면 앱의 연결 포트를 맞추세요. 실행 중인 포트는 docker compose ps로 확인할 수 있어요.

    Docker DB 실행·상태 확인 명령
    docker compose up -d
docker compose ps

    MySQL이 healthy인지 확인하세요. 기본 포트를 바꿔 실행했다면 실제 포트에 맞춰 연결해야 해요.

  3. Main을 실행하고 hello를 확인하세요

    IDE에서 org.example.Main을 실행하세요. 기본 주소 localhost:8080/hello를 열어 hello가 보이면 서버가 응답하는 거예요.

    터미널에서 서버 실행하기
    ./gradlew bootRun

    이미 IDE에서 실행했다면 다시 실행할 필요는 없어요.

  4. 학습 화면은 문서 서버로 여세요

    API 서버는 8080, 학습 화면은 8765 포트를 사용해요. 문서 서버 주소에서 학습 화면을 열면 요청 보내기와 이어하기를 이용할 수 있어요.

    문서 서버 실행 명령과 주소

    프로젝트 폴더에서 새 터미널을 열고 실행하세요.

    python3 -m http.server 8765 --bind 127.0.0.1

    브라우저에서 127.0.0.1:8765/index.html을 여세요.

위 단계는 직접 확인하는 안내입니다. 준비 전에도 과제는 열어볼 수 있어요.
