#힌트

1. 응답이 무엇으로 만들어지는지 본다

MemberController.me의 반환 타입을 본다. 컨트롤러가 돌려준 객체는 Jackson이 getter를 모두 읽어 JSON으로 만든다. Member에는 Lombok @Getter가 붙어 있으니 getPasswordHash()도 getter다.

2. spec과 비교한다

course/spec-v2.md 5-1절: GET /api/members/me 응답은 id, email, nickname, role, createdAt이고 비밀번호 해시는 절대 포함하지 않는다. jq 'keys'로 지금 필드 목록을 뽑아 나란히 놓으면 무엇이 더 나가는지 바로 보인다.

3. 테스트로 고정하기

MockMvc로 /api/members/me를 부르고 본문 문자열에 저장된 해시 값이 없는지, 필드 이름 집합이 다섯 개와 같은지 단언한다. @JsonIgnore 하나로 해시만 가리면 첫 단언은 통과해도 두 번째 단언이 남은 문제(잔액·수정 시각, 오프셋 없는 시각)를 잡는다.

#원인과 정답

펼치기

원인. MemberController.me가 JPA 엔티티 Member를 그대로 반환한다("필드가 같아 DTO를 따로 두지 않는다"). Jackson은 엔티티의 getter를 전부 직렬화하므로 passwordHash가 그대로 나가고, 화면이 안 쓰는 pointBalance·updatedAt도 함께 나간다. createdAt은 엔티티의 LocalDateTime이 그대로 찍혀 spec의 KST 오프셋(+09:00)이 빠진다. 더 큰 문제는 구조다. 엔티티에 컬럼을 하나 더하면 그 순간 API 응답이 바뀐다. 다음에 누가 주민번호나 탈퇴 사유 컬럼을 추가해도 아무도 모르게 밖으로 나간다.

정답 수정. 응답 전용 DTO MemberResponse(id, email, nickname, role, createdAt)를 두고 컨트롤러는 MemberResponse.from(member)를 돌려준다. @JsonIgnore로 해시만 가리는 것은 오답에 가깝다. 엔티티와 API 스펙이 계속 묶여 있어 다음 필드가 또 샌다. (tickets/B08/answer/fix.patch)

확인 테스트. tickets/B08/answer/B08ConfirmTest.java — 내_정보_응답에_비밀번호_해시가_없다, 내_정보_응답은_spec의_다섯_필드뿐이다

1단계 정답 서버는? board-server/src/main/java/com/example/board/member/MemberResponse.java로 응답을 따로 만들고, MemberApiTest가 필드 다섯 개와 passwordHash 없음을 확인했다. 이 서버에서는 DTO가 지워졌고 MemberApiTest는 id·email·nickname·role만 본다.
