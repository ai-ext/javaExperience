# B08. 회원 API 응답에 비밀번호 해시가 보인다

> 같은 날: D11 ②·③ · 선택(인수인계 리뷰 과제) · 진단 도구: 응답 확인(`curl … | jq`), 특성화 테스트

## 받은 티켓

> 외부 보안 점검 보고서에 "내 정보 조회 API 응답에 비밀번호 해시 노출"이 고위험으로 올라왔습니다.
> 앱 화면에는 안 보이는데, 개발자 도구로 응답을 열어 보면 `$2a$10$...`로 시작하는 값이 있다고 합니다.
> 언제부터 그랬는지, 다른 값도 새고 있는지 함께 확인 부탁드립니다. — 보안 담당

## 환경과 재현

1. `messy-server`에서 `docker compose up -d`
2. `./gradlew bootRun --args='--spring.profiles.active=local'`
3. `bash tickets/B08/repro.sh`
   - 새 회원으로 가입·로그인한 뒤 `GET /api/members/me` 응답을 그대로 찍는다.
   - 기대 증상: 응답에 `passwordHash`가 있고, spec에 없는 `pointBalance`·`updatedAt`도 보인다. `createdAt`에는 `+09:00`이 없다.

## 제출물

- 원인 서술: 어떤 값이 왜 응답에 실렸는가, 그리고 이 구조가 앞으로 어떤 사고를 더 부르는가
- 재현 테스트: 지금 응답을 그대로 고정하는 특성화 테스트(`MemberApiCharacterizationTest`)를 먼저 쓰고, 고친 뒤 새 기대값(spec-v2의 다섯 필드, 해시 없음)으로 갱신한다
- 수정 diff

## 힌트

<details>
<summary>1. 응답이 무엇으로 만들어지는지 본다</summary>

`MemberController.me`의 반환 타입을 본다. 컨트롤러가 돌려준 객체는 Jackson이 getter를 모두 읽어 JSON으로 만든다.
`Member`에는 Lombok `@Getter`가 붙어 있으니 `getPasswordHash()`도 getter다.
</details>

<details>
<summary>2. spec과 비교한다</summary>

`course/spec-v2.md` 5-1절: `GET /api/members/me` 응답은 `id`, `email`, `nickname`, `role`, `createdAt`이고 비밀번호 해시는 절대 포함하지 않는다.
`jq 'keys'`로 지금 필드 목록을 뽑아 나란히 놓으면 무엇이 더 나가는지 바로 보인다.
</details>

<details>
<summary>3. 테스트로 고정하기</summary>

MockMvc로 `/api/members/me`를 부르고 본문 문자열에 저장된 해시 값이 없는지, 필드 이름 집합이 다섯 개와 같은지 단언한다.
`@JsonIgnore` 하나로 해시만 가리면 첫 단언은 통과해도 두 번째 단언이 남은 문제(잔액·수정 시각, 오프셋 없는 시각)를 잡는다.
</details>

## 원인과 정답

<details>
<summary>펼치기</summary>

**원인.** `MemberController.me`가 JPA 엔티티 `Member`를 그대로 반환한다("필드가 같아 DTO를 따로 두지 않는다").
Jackson은 엔티티의 getter를 전부 직렬화하므로 `passwordHash`가 그대로 나가고, 화면이 안 쓰는 `pointBalance`·`updatedAt`도 함께 나간다.
`createdAt`은 엔티티의 `LocalDateTime`이 그대로 찍혀 spec의 KST 오프셋(`+09:00`)이 빠진다.
더 큰 문제는 구조다. 엔티티에 컬럼을 하나 더하면 그 순간 API 응답이 바뀐다. 다음에 누가 주민번호나 탈퇴 사유 컬럼을 추가해도 아무도 모르게 밖으로 나간다.

**정답 수정.** 응답 전용 DTO `MemberResponse(id, email, nickname, role, createdAt)`를 두고 컨트롤러는 `MemberResponse.from(member)`를 돌려준다.
`@JsonIgnore`로 해시만 가리는 것은 오답에 가깝다. 엔티티와 API 스펙이 계속 묶여 있어 다음 필드가 또 샌다. (`tickets/B08/answer/fix.patch`)

**확인 테스트.** `tickets/B08/answer/B08ConfirmTest.java` — `내_정보_응답에_비밀번호_해시가_없다`, `내_정보_응답은_spec의_다섯_필드뿐이다`

**1단계 정답 서버는?** `board-server/src/main/java/com/example/board/member/MemberResponse.java`로 응답을 따로 만들고,
`MemberApiTest`가 필드 다섯 개와 `passwordHash` 없음을 확인했다. 이 서버에서는 DTO가 지워졌고 `MemberApiTest`는 id·email·nickname·role만 본다.
</details>
