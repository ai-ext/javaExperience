#힌트

1. 규칙을 위에서부터 짚어 본다▸

SecurityConfig의 authorizeHttpRequests 규칙을 요청 하나(GET /actuator/env, 토큰 없음)를 들고 위에서부터 하나씩 대어 본다. 처음 매치되는 규칙에서 판정이 끝나고 아래 규칙은 보지 않는다. EndpointRequest.toAnyEndpoint()가 무엇을 포함하는지 생각한다(노출된 모든 엔드포인트).

2. 노출 설정도 함께 본다▸

application-prod.yml(또는 application-prod.properties)의 management.endpoints.web.exposure.include와 management.endpoint.env.show-values를 본다. Spring Boot의 기본은 env 값을 ******로 가린다(never). 노출 엔드포인트가 test 프로파일과 prod 프로파일에서 다르다는 것도 테스트가 놓친 이유다.

3. 테스트로 고정하기▸

@ActiveProfiles("prod")를 test 프로파일 위에 얹고, prod yml의 자리표시자(DB_PASSWORD, BOARD_JWT_SECRET, BOARD_PG_SECRET 등)만 @SpringBootTest(properties = …)로 채운다. 접속은 테스트 컨테이너가 그대로 맡는다. 그 컨텍스트에서 토큰 없음·USER·ADMIN 세 경우와 health를 함께 단언한다.

#원인과 구현 예시

펼치기▸

원인. 두 가지가 겹쳤다. ① SecurityConfig에서 "모니터링은 토큰 없이" 규칙 requestMatchers(EndpointRequest.toAnyEndpoint()).permitAll()이 "env는 관리자만" 규칙 requestMatchers(EndpointRequest.to("env")).hasRole("ADMIN")보다 위에 있다. toAnyEndpoint()는 노출된 모든 엔드포인트(env 포함)와 매치되므로 env 요청은 여기서 공개로 끝나고, 아래 관리자 규칙은 영원히 매치되지 않는다. metrics도 함께 공개된다. ② application-prod.yml(또는 application-prod.properties)이 env를 노출하면서 show-values: always로 값 가림을 껐다. 그래서 공개된 env에 비밀값이 평문으로 실린다. test 프로파일은 health만 노출하므로 /actuator/env가 아예 엔드포인트가 아니고, 마지막 anyRequest().authenticated()에 걸려 401이 난다. 기존 테스트가 통과한 이유다.

구현 예시 수정. health만 공개(EndpointRequest.to("health"))하고, 그다음에 나머지 노출 엔드포인트를 관리자 전용(EndpointRequest.toAnyEndpoint() → hasRole("ADMIN"))으로 둔다. 좁은 규칙을 먼저, 넓은 규칙을 나중에. show-values: always는 지운다(기본 never). 키와 출처 이름만으로도 설정 확인(B11)은 충분하다. 노출된 키는 교체해야 한다. (tickets/B14/answer/fix.patch)

확인 테스트. tickets/B14/answer/B14ConfirmTest.java — 토큰 없는 env·metrics 401, 일반 회원 env·metrics 403, 관리자 env·metrics 200, 관리자 env 응답에도 비밀값 평문 없음, 토큰 없는 health 200

1단계 구현 예시 서버는? board-server/src/main/resources/application.yml(또는 board-server/src/main/resources/application.properties)(학습자 구현에서는 board-server/src/main/resources/application.properties도 인정)은 HTTP로 health만 노출하고(exposure.include: health), SecurityConfig는 GET /actuator/health만 permitAll로 열어 나머지 /actuator/**는 anyRequest().authenticated()가 막는다(spec-v2 3절).
