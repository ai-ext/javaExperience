## 힌트

<details>
<summary>1. 요청마다 다른 값이 어디에 있는지 본다</summary>

`POST /api/posts` → `PostServiceImpl.create` → `ForbiddenWordChecker.contains`를 따라간다. 검사기는 `@Component`, 즉 애플리케이션에 하나뿐인 싱글톤 빈이다.
`contains`가 읽고 쓰는 값 가운데 메서드 지역 변수가 아니라 필드에 있는 것이 무엇인가?
</details>

<details>
<summary>2. 재현을 "가끔"에서 "거의 매번"으로 바꾼다</summary>

HTTP 부하는 타이밍이 매번 달라 재현이 들쭉날쭉하다. 검사기 객체 하나를 직접 만들고(`new ForbiddenWordChecker(new BoardProperties(new BoardProperties.ForbiddenWords(true), null, null))`)
두 스레드가 정해진 시간(예: 2초) 동안 한쪽은 깨끗한 글만, 다른 쪽은 금칙어 글만 계속 검사하게 한다. 틀린 결과가 한 번이라도 나오면 멈추고 센다.
섞이는 순간을 놓치지 않게 두 가지를 맞춘다.

- 금칙어 글에 금칙어를 **전부** 넣고, 깨끗한 글에는 하나도 넣지 않는다. 그러면 깨끗한 글이 금칙어 목록을 도는 도중 언제 다른 글의 값이 끼어들어도
  바로 다음 금칙어에서 결과가 뒤집힌다(불변 `Set`의 순회 순서는 실행마다 달라, 금칙어 하나만 넣으면 끼어든 시점에 따라 놓친다).
- 금칙어를 수천 개, 깨끗한 글을 길게 만들어 한 번 검사가 목록을 도는 시간(= 끼어들 창)을 늘린다.

스레드가 끼어드는 순서를 테스트가 직접 정할 수는 없다(검사기 안에 끼어들 지점이 없다). 그래서 "매번"은 반복 실행으로 확인한다: 결함 상태에서 100번 돌려 100번 실패하는지 본다.
</details>

<details>
<summary>3. 기존 테스트가 왜 통과했나</summary>

`ForbiddenWordCheckerTest.요청마다_바뀌는_상태_필드가_없다`는 `final`도 `volatile`도 아닌 필드만 찾는다. `volatile`은 다른 스레드가 쓴 값을 보이게 할 뿐, "읽고-쓰고-다시 읽는" 사이에 남이 끼어드는 것은 막지 못한다.
원인 서술에는 `volatile`이 왜 이 경쟁을 막지 못했는지도 함께 적는다.
</details>

## 원인과 정답

<details>
<summary>펼치기</summary>

**원인.** `ForbiddenWordChecker`가 "같은 글을 연달아 검사할 때 다시 정규화하지 않으려고" 마지막 검사 대상(`lastText`)과 정규화 결과(`lastFolded`)를 인스턴스 필드에 둔다.
싱글톤 빈의 필드는 모든 요청 스레드가 함께 쓰므로, A 요청이 `lastFolded`를 쓰고 금칙어 목록을 도는 사이 B 요청이 자기 글로 덮어쓰면 A는 B의 글을 검사한 결과를 돌려준다.
금칙어 목록이 길수록(도는 시간이 길수록) 섞이는 창이 넓다. 혼자 요청할 때는 끼어들 상대가 없어 재현되지 않는다. `volatile`은 가시성만 보장하고 이 경쟁은 막지 못한다.

**정답 수정.** 요청마다 다른 값은 지역 변수에 둔다(`String target = fold(text)`). 필드는 적재 때 통째로 바꾸는 불변 집합 `words`만 남긴다(`tickets/B05/answer/fix.patch`).
"캐시가 꼭 필요하다"면 요청 단위 값은 필드가 아니라 호출자가 들고 다니게 하고, 공유 캐시라면 스레드 안전한 자료구조에 키(원문)와 값(결과)을 함께 넣는다. `synchronized`는 모든 글쓰기를 한 줄로 세운다.

**확인 테스트.** `tickets/B05/answer/B05ConfirmTest.java` — `깨끗한_글과_금칙어_글을_동시에_검사해도_결과가_섞이지_않는다`
두 스레드가 2초 동안 깨끗한 글(금칙어 0개)과 금칙어 글(금칙어 3,000개 전부)을 계속 검사하고, 섞인 결과가 한 번이라도 나오면 실패한다.
스레드 교차 순서를 테스트가 직접 정하지는 못하므로 반복 실측으로 확인했다: 결함 상태 100회 중 100회 실패(CPU를 다른 프로세스와 나눠 쓸 때도 100회 중 100회), 지역 변수 수정과 `synchronized` 수정은 각각 100회 모두 통과.

**1단계 정답 서버는?** `board-server/src/main/java/com/example/board/common/ForbiddenWordChecker.java`는 정규화 결과를 지역 변수로 두고, 필드는 적재 때 통째로 바꾸는 불변 `Set`(`volatile`)뿐이다.
</details>
