<details class="step-observations" data-step="D07-1">
<summary>선택 관찰 실험 · 오늘은 하나만 골라도 됩니다</summary>

- 선택 관찰 A(15분, C16): 앞의 D05 실험을 확장해 MySQL InnoDB의 서로 다른 두 물리 연결 A/B를 쓴다. 테스트 자동 tx/OSIV와 2차 캐시를 끄고 각 실행의 @@transaction_isolation을 기록한다. A가 old를 일반 SELECT/find로 먼저 읽은 뒤 B에서 new로 UPDATE·commit한다(latch로 순서 고정). A에서 find 재호출(SQL 수), em.clear 후 find, 같은 A tx의 JDBC 일반 SELECT, A 종료 뒤 새 tx SELECT를 비교한다. clear 전 SQL 0회는 1차 캐시 증거다. REPEATABLE READ의 기존 consistent-read snapshot에서는 clear 후에도 old, READ COMMITTED는 새 SELECT에서 new, 새 tx는 두 수준 모두 new가 기대된다. DB snapshot과 Hibernate 변경 감지용 loaded state도 별개다. SELECT FOR UPDATE 같은 locking/current read는 이 예상표에서 제외한다. 두 격리 수준을 각각 새 tx로 실행하고 물리 연결을 바꾼 조회를 같은 tx의 JDBC 비교라고 적지 않는다.
- 선택 관찰 B(15분, I12): D04의 공유 태그를 서로 다른 회원 A/B가 동시에 생성하는 상황으로 반복한다. 학습자 src/test의 두 worker가 각자 새 tx에서 고유한 같은 태그 이름을 findByName하여 둘 다 없음임을 확인한 지점에서 latch로 모은 뒤 INSERT를 시도한다. 둘 다 조회를 마치기 전에 INSERT하지 않으며 INSERT 뒤 두 worker barrier는 두지 않는다(UNIQUE 잠금 대기와 교착될 수 있다). 모든 Future를 timeout과 함께 회수하고 worker별 SQL·UNIQUE 제약명·예외·commit/rollback을 기록한다. 기준 재현은 tag 1행과 한 tx의 충돌이며 회원별 락만으로 공유 이름을 보호할 수 있는지 질문한다. 복구안을 선택해 별도 fixture에서 검증한다면 실패 tx를 끝낸 후 새 tx 재조회·기존 태그 재사용 또는 DB 충돌 처리 정책을 설명한다. 최종 목표는 tag 1행·서로 다른 글의 연결 2행이며 다른 제약 오류를 모두 중복으로 삼키지 않는다. 현재 예시 서버가 이 경합을 통과한다고 가정하지 않는다.

```java
    @Column(name = "ref_type", nullable = false, length = 30)
    private String refType;

    @Column(name = "ref_id")
    private Long refId;

    private PointLedger(Member member, PointLedgerType type, long amount, long balanceAfter, String refType,
            Long refId) {
        this.member = member;
        this.type = type;
        this.amount = amount;
        this.balanceAfter = balanceAfter;
        this.refType = refType;
        this.refId = refId;
    }

    public static PointLedger create(Member member, PointLedgerType type, long amount, long balanceAfter,
```

```java
package com.example.board.point;

import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import com.example.board.common.BusinessException;
import com.example.board.common.ErrorCode;
import com.example.board.member.MemberRepository;

/** 잔액 갱신과 원장 기록을 호출자의 트랜잭션에 함께 묶는다(없으면 새로 연다). */
@Service
public class PointService {

    private final MemberRepository memberRepository;
    private final PointLedgerRepository ledgerRepository;

    public PointService(MemberRepository memberRepository, PointLedgerRepository ledgerRepository) {
        this.memberRepository = memberRepository;
        this.ledgerRepository = ledgerRepository;
    }

    @Transactional
    public void earn(Long memberId, int amount, String refType, Long refId) {
        if (memberRepository.addBalance(memberId, amount) == 0) {
            throw new BusinessException(ErrorCode.NOT_FOUND, "회원을 찾을 수 없습니다.");
        }
        record(memberId, PointLedgerType.EARN, amount, refType, refId);
    }

    @Transactional
    public void spend(Long memberId, int amount, String refType, Long refId) {
        if (memberRepository.subtractBalanceIfEnough(memberId, amount) == 0) {
            throw new BusinessException(ErrorCode.INSUFFICIENT_POINTS, "포인트가 부족합니다.");
        }
        record(memberId, PointLedgerType.SPEND, -amount, refType, refId);
    }

    private void record(Long memberId, PointLedgerType type, long signedAmount, String refType, Long refId) {
        long after = memberRepository.findBalance(memberId).orElseThrow();
        ledgerRepository.save(PointLedger.create(memberRepository.getReferenceById(memberId), type, signedAmount,
                after, refType, refId));
    }
}
```

```java
            for (Future<T> f : futures) {

            }
            return result;

            pool.shutdownNow();
```

```java
package com.example.board.coupon;

import java.util.List;

import org.springframework.dao.DataIntegrityViolationException;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import org.springframework.transaction.support.TransactionTemplate;

import com.example.board.common.BusinessException;
import com.example.board.common.ErrorCode;
import com.example.board.member.MemberRepository;

/** issue에는 @Transactional을 두지 않는다. 트랜잭션 경계를 안쪽(TransactionTemplate)에 두고 UNIQUE 위반을 바깥에서 잡기 위해서다. */
@Service
public class CouponService {

    private final CouponRepository couponRepository;
    private final MemberCouponRepository memberCouponRepository;
    private final MemberRepository memberRepository;
    private final TransactionTemplate tx;

    public CouponService(CouponRepository couponRepository, MemberCouponRepository memberCouponRepository,
            MemberRepository memberRepository, TransactionTemplate tx) {
        this.couponRepository = couponRepository;
        this.memberCouponRepository = memberCouponRepository;
        this.memberRepository = memberRepository;
        this.tx = tx;
    }

    /** 1인 1매, 선착순. 발급된 member_coupon의 id를 돌려준다. */
    public Long issue(Long couponId, Long memberId) {
        try {
            return tx.execute(s -> {
                if (memberCouponRepository.existsByCouponIdAndMemberId(couponId, memberId)) {
                    throw duplicate();
                }
                if (couponRepository.increaseIssued(couponId) == 0) {
                    if (!couponRepository.existsById(couponId)) {
                        throw new BusinessException(ErrorCode.NOT_FOUND, "쿠폰을 찾을 수 없습니다.");
                    }
                    throw new BusinessException(ErrorCode.COUPON_EXHAUSTED, "쿠폰이 모두 소진되었습니다.");
                }
                return memberCouponRepository.saveAndFlush(MemberCoupon.create(
                        couponRepository.getReferenceById(couponId), memberRepository.getReferenceById(memberId)))
                        .getId();
            });
        } catch (DataIntegrityViolationException duplicate) {
            // UNIQUE(coupon_id, member_id) 위반 = 동시 요청이 먼저 받았다. 수량 증가도 함께 롤백됐다.
            throw duplicate();
        }
    }

    @Transactional(readOnly = true)
    public List<MemberCouponResponse> myCoupons(Long memberId) {
        return memberCouponRepository.findAllWithCoupon(memberId).stream().map(MemberCouponResponse::from).toList();
    }

    private static BusinessException duplicate() {
        return new BusinessException(ErrorCode.DUPLICATE, "이미 받은 쿠폰입니다.");
    }
}
```

```java
package com.example.board.shop;

import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.FetchType;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.JoinColumn;
import jakarta.persistence.ManyToOne;
import jakarta.persistence.Table;

import com.example.board.common.BaseEntity;
import com.example.board.coupon.MemberCoupon;
import com.example.board.member.Member;

import lombok.AccessLevel;
import lombok.Getter;
import lombok.NoArgsConstructor;

@Getter
@Entity
@Table(name = "shop_order")
@NoArgsConstructor(access = AccessLevel.PROTECTED)
public class ShopOrder extends BaseEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "member_id", nullable = false)
    private Member member;

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "item_id", nullable = false)
    private ShopItem item;

    @Column(nullable = false)
    private int quantity;

    @Column(name = "paid_amount", nullable = false)
    private long paidAmount;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "member_coupon_id")
    private MemberCoupon memberCoupon;

    @Column(name = "idempotency_key", nullable = false, length = 64)
    private String idempotencyKey;

    private ShopOrder(Member member, ShopItem item, int quantity, long paidAmount, MemberCoupon memberCoupon,
            String idempotencyKey) {
        this.member = member;
        this.item = item;
        this.quantity = quantity;
        this.paidAmount = paidAmount;
        this.memberCoupon = memberCoupon;
        this.idempotencyKey = idempotencyKey;
    }

    public static ShopOrder create(Member member, ShopItem item, int quantity, long paidAmount,
            MemberCoupon memberCoupon, String idempotencyKey) {
        return new ShopOrder(member, item, quantity, paidAmount, memberCoupon, idempotencyKey);
    }

    /** 같은 키의 재요청이 처음 요청과 같은 본문인지 판단한다. */
    public boolean matches(Long itemId, int quantity, Long memberCouponId) {
        Long ownCoupon = memberCoupon == null ? null : memberCoupon.getId();
        return item.getId().equals(itemId) && this.quantity == quantity && java.util.Objects.equals(ownCoupon, memberCouponId);
    }
}
```

```java
package com.example.board.shop;

import java.time.LocalDateTime;
import java.time.ZoneId;
import java.util.Optional;

import org.springframework.dao.DataIntegrityViolationException;
import org.springframework.dao.PessimisticLockingFailureException;
import org.springframework.stereotype.Service;
import org.springframework.transaction.support.TransactionTemplate;

import com.example.board.common.BusinessException;
import com.example.board.common.ErrorCode;
import com.example.board.coupon.MemberCouponRepository;
import com.example.board.member.Member;
import com.example.board.member.MemberRepository;
import com.example.board.point.PointService;

/**
 * 이 클래스에는 @Transactional을 두지 않는다. 데드락 재시도는 트랜잭션 밖에서 해야
 * rollback-only가 된 트랜잭션을 다시 쓰지 않는다.
 */
@Service
public class OrderService {

    private static final int MAX_ATTEMPTS = 3;
    private static final int COUPON_DISCOUNT_PERCENT = 10;
    private static final ZoneId KST = ZoneId.of("Asia/Seoul");

    private final ShopItemRepository shopItemRepository;
    private final ShopOrderRepository shopOrderRepository;
    private final MemberCouponRepository memberCouponRepository;
    private final MemberRepository memberRepository;
    private final PointService pointService;
    private final TransactionTemplate tx;

    public OrderService(ShopItemRepository shopItemRepository, ShopOrderRepository shopOrderRepository,
            MemberCouponRepository memberCouponRepository, MemberRepository memberRepository,
            PointService pointService, TransactionTemplate tx) {
        this.shopItemRepository = shopItemRepository;
        this.shopOrderRepository = shopOrderRepository;
        this.memberCouponRepository = memberCouponRepository;
        this.memberRepository = memberRepository;
        this.pointService = pointService;
        this.tx = tx;
    }

    public OrderResponse order(Long memberId, String idempotencyKey, OrderRequest request) {
        for (int attempt = 1;; attempt++) {
            try {
                return placeOnce(memberId, idempotencyKey, request);
            } catch (PessimisticLockingFailureException deadlock) {
                if (attempt >= MAX_ATTEMPTS) {
                    throw deadlock;
                }
            }
        }
    }

    private OrderResponse placeOnce(Long memberId, String idempotencyKey, OrderRequest request) {
        try {
            return tx.execute(s -> place(memberId, idempotencyKey, request));
        } catch (DataIntegrityViolationException duplicateKey) {
            // UNIQUE(member_id, idempotency_key) 위반 = 같은 키의 주문이 먼저 커밋됐다. 처음 응답을 돌려준다.
            return tx.execute(s -> findReplay(memberId, idempotencyKey, request).orElseThrow(() -> duplicateKey));
        }
    }

    private OrderResponse place(Long memberId, String idempotencyKey, OrderRequest request) {
        // 회원 행을 먼저 잠가 같은 회원의 주문을 직렬화한다. 같은 키의 동시 요청도 여기서 순서가 정해지고,
        // 뒤에 온 요청은 잠금을 얻은 뒤 아래 조회로 먼저 커밋된 주문을 본다.
        Member member = memberRepository.findByIdForUpdate(memberId)
                .orElseThrow(() -> new BusinessException(ErrorCode.NOT_FOUND, "회원을 찾을 수 없습니다."));
        Optional<OrderResponse> replay = findReplay(memberId, idempotencyKey, request);
        if (replay.isPresent()) {
            return replay.get();
        }

        ShopItem item = shopItemRepository.findById(request.itemId())
                .orElseThrow(() -> new BusinessException(ErrorCode.NOT_FOUND, "아이템을 찾을 수 없습니다."));
        long total = item.getPrice() * request.quantity();
        Long memberCouponId = request.memberCouponId();
        long paid = memberCouponId == null ? total : total - total * COUPON_DISCOUNT_PERCENT / 100;

        // 재고 행 → 쿠폰 행 → 주문 INSERT 순으로 배타 잠금을 먼저 잡는다. INSERT의 FK 공유 잠금이 먼저 걸리면 동시 주문이 교착한다.
        if (shopItemRepository.decreaseStock(item.getId(), request.quantity()) == 0) {
            throw new BusinessException(ErrorCode.OUT_OF_STOCK, "재고가 부족합니다.");
        }
        if (memberCouponId != null
                && memberCouponRepository.markUsed(memberCouponId, memberId, LocalDateTime.now(KST)) == 0) {
            throw new BusinessException(ErrorCode.COUPON_UNUSABLE, "사용할 수 없는 쿠폰입니다.");
        }
        ShopOrder order = shopOrderRepository.saveAndFlush(ShopOrder.create(member, item, request.quantity(), paid,
                memberCouponId == null ? null : memberCouponRepository.getReferenceById(memberCouponId),
                idempotencyKey));
        if (paid > 0) {
            pointService.spend(memberId, Math.toIntExact(paid), "ORDER", order.getId());
        }
        return OrderResponse.from(order);
    }

    /** 같은 키의 주문이 있으면 같은 본문일 때만 처음 응답을 돌려주고, 다르면 422다. */
    private Optional<OrderResponse> findReplay(Long memberId, String idempotencyKey, OrderRequest request) {
        return shopOrderRepository.findByMemberIdAndIdempotencyKey(memberId, idempotencyKey).map(existing -> {
            if (!existing.matches(request.itemId(), request.quantity(), request.memberCouponId())) {
```

## 말하기 카드

하루가 끝나면 질문에 "문제 상황 → 원인 → 선택 → 결과" 순서로 소리 내어 답한 뒤, 접힌 "답에 들어가야 할 것"과 비교한다. 세 줄이 모두 나오면 통과다.

### TC-D07-1

**질문** 같은 회원의 구매 두 건이 동시에 들어왔는데 포인트가 한 번만 차감됐습니다. 원인과 수정은?

<details class="card-answer" data-card="TC-D07-1">
<summary>답에 들어가야 할 것</summary>

- 두 트랜잭션이 같은 잔액을 읽고 각자 계산해 쓰면, 나중 쓰기가 앞 쓰기를 덮어쓴다(갱신 손실)
- `UPDATE member SET point_balance = point_balance - ? WHERE id = ? AND point_balance >= ?`로 DB가 원자적으로 계산하게 하고, 바뀐 행이 0이면 409 `/errors/insufficient-points`로 처리한다
- 같은 트랜잭션에서 `point_ledger`에 이력을 쌓아 잔액과 이력의 합이 항상 맞게 한다

**근거** spec-v2 §6

</details>

### TC-D07-2

**질문** 쿠폰 발급 버튼을 연타하면 한 회원이 두 장을 받을 수 있나요? 어떻게 막았나요?

<details class="card-answer" data-card="TC-D07-2">
<summary>답에 들어가야 할 것</summary>

- "이미 받았는지 조회 후 INSERT"는 두 요청이 동시에 조회를 통과하면 둘 다 INSERT한다
- `member_coupon`의 UNIQUE(`coupon_id`, `member_id`)로 DB가 두 번째 INSERT를 거부하게 하고, 중복 키 예외를 409 `/errors/duplicate`로 바꾼다
- 중복 키 오류가 난 INSERT는 기존 행에 공유 락을 걸기 때문에 동시 INSERT가 많으면 데드락이 날 수 있어, 예외 처리를 함께 설계한다

**근거** spec-v2 §5-4

</details>

### TC-D07-3

**질문** 구매 중 데드락으로 실패한 요청을 재시도합니다. 재시도 코드를 `@Transactional` 메서드 안에 두면 안 되는 이유는?

<details class="card-answer" data-card="TC-D07-3">
<summary>답에 들어가야 할 것</summary>

- 데드락이 나면 InnoDB가 한쪽 트랜잭션 전체를 롤백한다
- 같은 트랜잭션·영속성 컨텍스트 안에서 다시 시도하면 이미 롤백된 작업을 이어 가게 되므로, 재시도는 바깥에서 새 트랜잭션으로 한다
- 여러 행을 잠글 때는 순서(예: id 오름차순)를 통일해 데드락 자체를 줄이고, 재시도에는 횟수 상한을 둔다

</details>

### TC-D07-4

**질문** 구매 요청이 네트워크 문제로 다시 전송되면 두 번 구매되나요? `Idempotency-Key`를 어떻게 처리했나요?

<details class="card-answer" data-card="TC-D07-4">
<summary>답에 들어가야 할 것</summary>

- 클라이언트는 같은 구매를 재시도할 때 같은 `Idempotency-Key`를 보낸다
- `shop_order`의 UNIQUE(`member_id`, `idempotency_key`)로 두 번째 주문 생성을 막고, 같은 키·같은 본문이면 처음 응답을 그대로 돌려준다
- 같은 키에 다른 본문이 오면 422로 거부한다

**근거** spec-v2 §5-4

</details>

```text
  - [C6-2] 같은 키·같은 본문 다시 → 처음과 같은 응답
  - [C6-3] 같은 키·다른 본문 → 422
  - [C6-4] 키 없음 → 400
  - [C6-5] 잔액 부족 → 409 /errors/insufficient-points
  - [C6-6] 남의 쿠폰 → 409 /errors/coupon-unusable
  - [R6] 함정을 피했는지 코드로 확인: 데드락 재시도를 @Transactional 메서드 안에 두면 이미 rollback-only가 된 같은 트랜잭션을 다시 쓰게 되므로 재시도는 트랜잭션 밖에서 한다.

말하기 카드
- [TC-D07-1] 같은 회원의 구매 두 건이 동시에 들어왔는데 포인트가 한 번만 차감됐습니다. 원인과 수정은?
    · 두 트랜잭션이 같은 잔액을 읽고 각자 계산해 쓰면, 나중 쓰기가 앞 쓰기를 덮어쓴다(갱신 손실)
    · UPDATE member SET point_balance = point_balance - ? WHERE id = ? AND point_balance >= ?로 DB가 원자적으로 계산하게 하고, 바뀐 행이 0이면 409 /errors/insufficient-points로 처리한다
    · 같은 트랜잭션에서 point_ledger에 이력을 쌓아 잔액과 이력의 합이 항상 맞게 한다
- [TC-D07-2] 쿠폰 발급 버튼을 연타하면 한 회원이 두 장을 받을 수 있나요? 어떻게 막았나요?
    · "이미 받았는지 조회 후 INSERT"는 두 요청이 동시에 조회를 통과하면 둘 다 INSERT한다
    · member_coupon의 UNIQUE(coupon_id, member_id)로 DB가 두 번째 INSERT를 거부하게 하고, 중복 키 예외를 409 /errors/duplicate로 바꾼다
    · 중복 키 오류가 난 INSERT는 기존 행에 공유 락을 걸기 때문에 동시 INSERT가 많으면 데드락이 날 수 있어, 예외 처리를 함께 설계한다
- [TC-D07-3] 구매 중 데드락으로 실패한 요청을 재시도합니다. 재시도 코드를 @Transactional 메서드 안에 두면 안 되는 이유는?
    · 데드락이 나면 InnoDB가 한쪽 트랜잭션 전체를 롤백한다
    · 같은 트랜잭션·영속성 컨텍스트 안에서 다시 시도하면 이미 롤백된 작업을 이어 가게 되므로, 재시도는 바깥에서 새 트랜잭션으로 한다
    · 여러 행을 잠글 때는 순서(예: id 오름차순)를 통일해 데드락 자체를 줄이고, 재시도에는 횟수 상한을 둔다
- [TC-D07-4] 구매 요청이 네트워크 문제로 다시 전송되면 두 번 구매되나요? Idempotency-Key를 어떻게 처리했나요?
    · 클라이언트는 같은 구매를 재시도할 때 같은 Idempotency-Key를 보낸다
    · shop_order의 UNIQUE(member_id, idempotency_key)로 두 번째 주문 생성을 막고, 같은 키·같은 본문이면 처음 응답을 그대로 돌려준다
    · 같은 키에 다른 본문이 오면 422로 거부한다

리뷰 초점
- 포인트·쿠폰 수량·재고를 "읽고 계산해서 저장"하는 코드가 남아 있지 않은지
- 구매 실패(잔액 부족·쿠폰 불가)에서 재고·포인트·쿠폰 상태가 모두 원래대로인지

③ 부족한 점과 이유 — 실패한 C 항목부터
```
