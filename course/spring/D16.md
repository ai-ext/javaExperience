## 말하기 카드

하루가 끝나면 질문에 "문제 상황 → 원인 → 선택 → 결과" 순서로 소리 내어 답한 뒤, 접힌 "답에 들어가야 할 것"과 비교한다. 세 줄이 모두 나오면 통과다.

### TC-D16-1

**질문** 왜 A·B를 골랐고 기존 수행과 무엇이 다른가요?

<details class="card-answer" data-card="TC-D16-1">
<summary>답에 들어가야 할 것</summary>

- 미수행 영역·기존 증거·A/B 선택 이유를 구분한다.
- 기존 수행과 달라진 요구나 실패 입력을 밝히고 실제 실패 로그를 제시한다.
- 이미 통과하면 새 미충족 계약을 합의하며 정상 코드를 약화하지 않는다.

</details>

### TC-D16-2

**질문** 실패를 재현했다고 원인까지 확정할 수 있나요?

<details class="card-answer" data-card="TC-D16-2">
<summary>답에 들어가야 할 것</summary>

- 증상 재현은 관찰이며 원인 확정에는 코드 경계와 반증이 추가로 필요하다.
- 같은 증상을 만드는 다른 가설 하나와 배제할 실험을 말한다.
- 실패 요청·로그·테스트 경로와 아직 확인하지 못한 조건을 제시한다.

</details>

### TC-D16-3

**질문** 사본과 기준 서버를 어떻게 구분했나요?

<details class="card-answer" data-card="TC-D16-3">
<summary>답에 들어가야 할 것</summary>

- 원본과 사본의 절대경로·브랜치/기준 SHA·포트·DB 이름을 말한다.
- 수정은 사본에서 수행하고 기준 서버의 파일·데이터를 보존한 방법을 제시한다.
- 실행 명령·실제 출력과 사본 정리 범위를 남긴다.

</details>

- 변경한 요청 수·지연에서도 통과하면 이를 결함으로 만들지 않는다. 미충족 새 계약을 합의한 뒤 RED를 확인한다. 새 요구 미합의는 확인 불가이며 기존 성공은 실패가 아니다.

오늘은 별도 회의 역할극 없이 완료 조건·SQL·카드를 검증한다.

각 C 항목은 실제 테스트·SQL·로그·문서 경로와 줄을 근거로 통과/실패/확인 불가로 판정한다. 티켓 A/B는 원인 서술·수정 전 RED·수정 후 GREEN·반례·diff를 확인하고 미선택 티켓을 실패로 채점하지 마라. 미수행 대신 정한 새 조건은 조건과 새 실패 증거를 요구한다. 이미 새 조건도 통과하면 통과 사실을 인정하고 정상 코드를 약화하지 마라. 해당 일자의 요구 합의 단계(D16~D18은 D16, D36은 D35)로 돌아가 담당자/훈련 진행자와 미충족 새 계약을 합의하도록 하며, 미합의·미실행은 확인 불가로 남긴다. 기존 2단계 제외 규칙을 3단계 필수 A/B에 자동 적용하지 마라.
회의가 있으면 M1~M5 각각 0(없음)/1(부분)/2(근거·합의까지)로 채점한다. 각 항목 1점 이상 및 총 8/10 이상이어야 회의 통과다. 한 항목 0점이면 총점과 무관하게 재훈련한다. 먼저 발언을 받고 반론을 하나 제시한 뒤 수정 발언을 기록한다. 외운 답 선공개는 금지한다.
독립 수행이면 해법/힌트를 주지 말고 도움 횟수와 범위를 기록한다. 스스로 주입해 원인을 알고 있으면 비공개 장애 진단은 확인 불가다. 설명만으로 구현·진단을 통과시키지 마라.

출력: ① | C 항목 | 기대 | 실제 근거 | 결과 | ② SQL·불변식 ③ | 카드 | 빠진 줄 | 결과 | ④ 회의 점수·반론·바뀐 결정 ⑤ 도움·미실행·남은 약점
마지막 줄: 필수 N/M 통과 · SQL S/T · 카드 K/L · 회의(해당 시) Q/10 · 독립 수행(해당 시) 통과/실패/확인 불가. 연차 도달을 보증하지 않는다.
