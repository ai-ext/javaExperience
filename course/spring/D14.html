#TC-D14-1

질문 (B12) "새 프론트 도메인에서만 호출이 실패한다." 서버 로그에 에러가 없는데 무엇을 봤나요?

답에 들어가야 할 것
  • 새 출처가 CORS 허용 목록에 없으면 preflight가 거부되고, 브라우저는 실제 요청을 서버로 보내지 않는다
  • CORS 처리가 인증보다 뒤에 있으면 인증 정보 없는 OPTIONS 요청이 401로 막힌다
  • 브라우저 개발자 도구 Network 탭에서 OPTIONS 요청의 상태 코드와 Access-Control-Allow-Origin 응답 헤더를 먼저 확인하고, 출처 추가는 명세의 허용 출처 목록과 함께 바꾼다

근거 06 §6, spec-v2 §3

#TC-D14-2

질문 (B13) "PG 결제 완료 콜백이 전부 401." 원인과 수정은?

답에 들어가야 할 것
  • PG 콜백에는 JWT가 없는데 /api/pg/callbacks가 인증 필요 규칙에 걸려 진입점이 401을 냈다
  • Security 디버그 로그(logging.level.org.springframework.security=DEBUG)로 어느 필터·규칙에서 막혔는지 확인한다
  • 콜백 경로를 넓은 규칙보다 앞에서 permitAll로 열고, 인증 대신 X-PG-Signature 서명 검증으로 보호한다

근거 06 §6, spec-v2 §7

#TC-D14-3

질문 (B15) "숨긴 글이 인기글에 1분간 계속 보인다." 캐시를 지웠는데도 왜 보였나요?

답에 들어가야 할 것
  • 숨김 트랜잭션이 커밋되기 전에 캐시를 지웠다
  • 그 사이 들어온 인기글 조회가 캐시 미스를 보고, 아직 커밋 전이라 숨기기 전 값을 DB에서 읽어 캐시에 다시 넣었다
  • 그 값이 TTL(60초) 동안 남았다. 캐시 삭제·캐시 적재·커밋 시각을 로그로 찍어 순서를 증명하고, 삭제를 커밋 후(AFTER_COMMIT)로 옮긴다

근거 08 #7, spec-v2 §8

#TC-D14-4

질문 (B16) "Redis 점검 시간에 글쓰기까지 멈췄다." 캐시 서버 점검이 왜 글쓰기를 막았나요?

답에 들어가야 할 것
  • Redis 명령 타임아웃을 설정하지 않아, 요청 스레드가 Lettuce 기본값(60초)까지 Redis 응답을 기다렸다
  • 글쓰기 흐름 안의 캐시 삭제 실패가 예외로 그대로 전파돼, 핵심 경로가 캐시 장애와 함께 실패했다
  • 스레드 덤프에서 Redis 응답을 기다리는 요청 스레드를 확인하고, 타임아웃을 500ms로 두며 캐시 실패는 로그만 남기고 진행한다

근거 10 §3, spec-v2 §8
