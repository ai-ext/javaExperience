#TC-D22-1

질문 1차 캐시와 RR의 반복 읽기는 어떻게 구분했나요?

답에 들어가야 할 것
  • 1차 캐시는 같은 EntityManager의 객체 재사용이고 RR은 DB snapshot 규칙이다.
  • 같은 EM·clear 후 EM·새 트랜잭션을 나눠 관찰한 결과를 제시한다.
  • RC/RR의 실제 격리 수준·commit 시각·예상과 다른 결과를 설명한다.

#TC-D22-2

질문 공유 태그는 글과 수명이 같나요?

답에 들어가야 할 것
  • 공유 태그는 여러 게시글이 참조하므로 한 게시글과 수명이 같지 않다.
  • 연결 행 삭제와 태그 자체 삭제를 나누고 다른 글의 참조 보존을 설명한다.
  • 공유 fixture의 삭제 전후 SQL·회귀 결과와 선택한 관계 비용을 제시한다.

#TC-D22-3

질문 새 연결에서 확인하는 이유는 무엇인가요?

답에 들어가야 할 것
  • 같은 연결/EM은 1차 캐시나 미커밋 변경을 보므로 외부 가시성 증거가 아니다.
  • 새 연결·새 트랜잭션의 격리 수준과 시작/조회 시각을 고정한다.
  • 독립 조회 결과로 확정 행을 검증하고 connection만 새로 만든 경우의 한계를 말한다.

각 C 항목은 실제 테스트·SQL·로그·문서 경로와 줄을 근거로 통과/실패/확인 불가로 판정한다. 티켓 A/B는 원인 서술·수정 전 RED·수정 후 GREEN·반례·diff를 확인하고 미선택 티켓을 실패로 채점하지 마라. 미수행 대신 정한 새 조건은 조건과 새 실패 증거를 요구한다. 이미 새 조건도 통과하면 통과 사실을 인정하고 정상 코드를 약화하지 마라. 해당 일자의 요구 합의 단계(D16~D18은 D16, D36은 D35)로 돌아가 담당자/훈련 진행자와 미충족 새 계약을 합의하도록 하며, 미합의·미실행은 확인 불가로 남긴다. 기존 2단계 제외 규칙을 3단계 필수 A/B에 자동 적용하지 마라.
회의가 있으면 M1~M5 각각 0(없음)/1(부분)/2(근거·합의까지)로 채점한다. 각 항목 1점 이상 및 총 8/10 이상이어야 회의 통과다. 한 항목 0점이면 총점과 무관하게 재훈련한다. 먼저 발언을 받고 반론을 하나 제시한 뒤 수정 발언을 기록한다. 외운 답 선공개는 금지한다.
