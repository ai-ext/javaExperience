#진단 도구 예행 관찰

1단계 내 서버에서 정상 요청 한 번을 관찰한다. 결함을 추측하기보다 도구가 무엇을 보여 주는지 기록하고 D12 B01·B02에서 같은 관찰법을 다시 쓴다.

  1. 스레드 덤프: 같은 JDK의 jcmd -l로 내 서버 PID를 확인하고 jcmd <PID> Thread.print > threads.txt를 실행한다. http-nio 요청 스레드 하나의 이름·상태·스택을 골라 지금 실행 중인지 대기 중인지 한 문장으로 적는다.

  2. 메트릭: 내 서버의 로컬 프로필에서만 Actuator의 web exposure에 health,metrics를 임시로 넣고 로컬 접근 권한을 허용한다. curl http://localhost:8080/actuator/metrics와 /actuator/metrics/http.server.requests를 요청 전후 비교한다. 인증이 필요하면 관리자 자격으로 요청한다. count·단위·증가량을 기록하고 노출·보안 설정은 관찰 뒤 원래대로 되돌린다.

  3. slow log: 내 로컬 disposable MySQL에서 SHOW VARIABLES LIKE 'slow_query_log'와 SHOW VARIABLES LIKE 'long_query_time', SHOW VARIABLES LIKE 'log_output' 값을 먼저 저장한다. 관리자 연결에서 SET GLOBAL log_output='TABLE'; SET GLOBAL slow_query_log=ON; 후 관찰 연결에서 SET SESSION long_query_time=0;으로 두고 내 목록 SELECT를 한 번 실행한다. 관리자 연결에서 SELECT start_time,query_time,rows_examined,sql_text FROM mysql.slow_log ORDER BY start_time DESC LIMIT 5;로 대상 쿼리를 찾는다. 종료 후 GLOBAL 두 설정과 log_output을 기존 값으로 되돌리고 관찰 연결을 닫는다. 공유·운영 DB에서는 실행하지 않는다.

  4. 실행 계획: 같은 목록 SELECT 앞에 EXPLAIN ANALYZE를 붙인다(조회가 실제 실행된다). 실제 행 수·loops·시간을 읽고 slow log의 읽은 행 수와 함께 한 문장으로 해석한다. 측정값을 기록하며 빠르다는 결론을 미리 정하지 않는다.

관찰 파일·설정 복원 기록과 도구별 해석 한 문장을 채점 때 제출한다.

            ApplicationEventPublisher events) {

        this.postRepository = postRepository;

    @Transactional(readOnly = true)
    public CursorPage<ReportResponse> reports(ReportStatus status, String cursor, int size) {
        Long afterId = CursorPage.decode(cursor);
        // 한 건 더 읽어 다음 쪽이 있는지만 판단한다
        List<Report> rows = reportRepository.findPage(status, afterId, PageRequest.of(0, size + 1));
        boolean hasNext = rows.size() > size;
        List<Report> page = hasNext ? rows.subList(0, size) : rows;
        String next = hasNext ? CursorPage.encode(page.get(page.size() - 1).getId()) : null;
        return new CursorPage<>(page.stream().map(ReportResponse::from).toList(), next);
    }

     * reportId가 없거나 다른 글의 신고면 404이고 아무것도 바꾸지 않는다.
     * 트랜잭션이 있어야 PostChangedEvent가 커밋 뒤 리스너(인기글 캐시 삭제)에 닿는다.
     */
    @Transactional
    public HidePostResponse hidePost(Long postId, Long reportId) {
        Post post = postRepository.findById(postId)
                .filter(p -> p.getStatus() != PostStatus.DELETED)
                .orElseThrow(() -> new BusinessException(ErrorCode.NOT_FOUND, "글을 찾을 수 없습니다."));
        Report report = null;
        if (reportId != null) {
            report = reportRepository.findById(reportId)
                    .filter(r -> r.isAbout(postId))
                    .orElseThrow(() -> new BusinessException(ErrorCode.NOT_FOUND, "이 글의 신고를 찾을 수 없습니다."));
        }
        post.hide();
        if (report != null) {
            report.resolve();
        }
        events.publishEvent(new PostChangedEvent(postId));
        return new HidePostResponse(postId, post.getStatus(), reportId);
    }

import org.aspectj.lang.ProceedingJoinPoint;
import org.aspectj.lang.annotation.Around;
import org.aspectj.lang.annotation.Aspect;
import org.springframework.core.Ordered;
import org.springframework.core.annotation.Order;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.stereotype.Component;

import com.example.board.common.BusinessException;
import com.example.board.member.AuthMember;

/**
 * @Audited 메서드가 끝나면 audit_log에 한 줄을 남긴다. 성공은 result=SUCCESS, 실패한 시도는 result=FAILURE와 오류 종류.
 * 기록은 AuditLogWriter가 별도 트랜잭션으로 쓰므로 업무가 롤백돼도 남는다.
 * 순서: 메서드 보안(@PreAuthorize, 200) → 이 aspect → 트랜잭션(LOWEST_PRECEDENCE).
 * 트랜잭션 바깥이라 proceed()가 돌아왔을 때 업무는 이미 커밋돼 있다(커밋 실패도 실패로 기록된다).
 * 권한 거부는 업무를 시도하기 전에 막힌 것이라 기록하지 않는다.
 */
@Aspect
@Component
@Order(Ordered.LOWEST_PRECEDENCE - 1)
public class AuditLogAspect {

    private final AuditLogWriter writer;

    public AuditLogAspect(AuditLogWriter writer) {
        this.writer = writer;
    }

    @Around("@annotation(audited)")
    public Object record(ProceedingJoinPoint joinPoint, Audited audited) throws Throwable {
        Long actorId = currentActorId();
        Long targetId = targetId(joinPoint.getArgs());
        Object result;
        try {
            result = joinPoint.proceed();
        } catch (Throwable e) {
            try {
                writer.write(actorId, audited.action(), audited.targetType(), targetId, failure(e));
            } catch (RuntimeException writeFailure) {
                // 기록 실패가 원래 예외를 가리지 않게 한다
                e.addSuppressed(writeFailure);
            }
            throw e;
        }
        writer.write(actorId, audited.action(), audited.targetType(), targetId, success(result));
        return result;
    }

    private static Long currentActorId() {
        Authentication auth = SecurityContextHolder.getContext().getAuthentication();
        if (auth != null && auth.getPrincipal() instanceof AuthMember member) {
            return member.id();
        }
        // 메서드 보안을 통과했다면 항상 인증된 회원이 있다. 행위자 없는 감사 기록은 남기지 않는다.
        throw new IllegalStateException("감사 대상 동작에 인증된 회원이 없습니다.");
    }

    /** 대상 id는 첫 번째 인자(Long)다. */
    private static Long targetId(Object[] args) {
        return args.length > 0 && args[0] instanceof Long id ? id : null;
    }

    private static String success(Object result) {
        String extra = result instanceof AuditDetail d ? d.auditDetail() : null;
        return extra == null ? "result=SUCCESS" : "result=SUCCESS, " + extra;
    }

    private static String failure(Throwable e) {
        String error = e instanceof BusinessException be ? be.errorCode().name() : e.getClass().getSimpleName();
        return "result=FAILURE, error=" + error;
    }
}

import java.io.IOException;

import org.springframework.stereotype.Component;
import org.springframework.web.multipart.MultipartFile;

import com.example.board.common.BusinessException;
import com.example.board.common.ErrorCode;

/**
 * 쿠폰 대량 지급 파일(.xlsx)의 첫 열에서 회원 id를 읽는다(spec-v2 5-6).
 * - 파일 오류(비었음, 5MB 초과, .xlsx 아님, 읽을 수 없음, 데이터 1,000행 초과)는 400이다.
 * - 첫 번째 비어 있지 않은 행의 첫 셀이 문자열 memberId면 헤더로 건너뛴다.
 * - 첫 셀이 비어 있는 행은 빈 행으로 건너뛰고 한도에도 세지 않는다. 값이 잘못된 행은 한도에 센다.
 * - 숫자 셀은 정수일 때만(1.0은 1), 문자열 셀은 정수 표기일 때만 받는다. 0·음수는 NOT_POSITIVE.
 */
@Component
public class ExcelMemberIdReader {

    static final long MAX_BYTES = 5L * 1024 * 1024;
    static final int MAX_ROWS = 1000;
    private static final String HEADER = "memberId";
    private static final Pattern INTEGER = Pattern.compile("[+-]?\\d{1,18}");
    // double이 정수를 정확히 담는 한계(2^53). 넘으면 엑셀에서 이미 자릿수가 깎였을 수 있다.
    private static final double MAX_EXACT = 9_007_199_254_740_992d;

    public ExcelReadResult read(MultipartFile file) {
        if (file == null || file.isEmpty()) {
            throw invalid("파일이 비어 있습니다.");
        }
        // 파싱보다 먼저 본다. 서블릿 업로드 한도는 MockMvc·직접 호출에서는 걸리지 않는다.
        if (file.getSize() > MAX_BYTES) {
            throw invalid("파일은 최대 5MB입니다.");
        }
        String name = file.getOriginalFilename();
        if (name == null || !name.toLowerCase(Locale.ROOT).endsWith(".xlsx")) {
            throw invalid(".xlsx 파일만 받습니다.");
        }
        try (XSSFWorkbook workbook = open(file)) {
            if (workbook.getNumberOfSheets() == 0) {
                throw invalid("시트가 없습니다.");
            }
            return read(workbook.getSheetAt(0));
        } catch (IOException e) {
            throw invalid("엑셀 파일을 읽을 수 없습니다.");
        }
    }

    private static XSSFWorkbook open(MultipartFile file) throws IOException {
        try (InputStream in = FileMagic.prepareToCheckMagic(file.getInputStream())) {
            // 확장자만 바꾼 .xls(OLE2)나 엑셀이 아닌 파일을 내용으로 거른다
            if (FileMagic.valueOf(in) != FileMagic.OOXML) {
                throw invalid(".xlsx 형식이 아닙니다.");
            }
            // zip bomb 방지 기본값(ZipSecureFile 최소 압축률 등)은 끄지 않는다
            return new XSSFWorkbook(in);
        } catch (RuntimeException e) {
            if (e instanceof BusinessException) {
                throw e;
            }
            // POI는 손상된 파일을 여러 런타임 예외(POIXMLException, NotOfficeXmlFileException 등)로 알린다.
            // 이 블록은 파일 열기 한 곳만 감싸므로 서버 버그를 입력 오류로 숨기지 않는다.
            throw invalid("엑셀 파일을 읽을 수 없습니다.");
        }
    }

    private static ExcelReadResult read(Sheet sheet) {
        DataFormatter formatter = new DataFormatter();
        List<MemberIdRow> rows = new ArrayList<>();
        List<Skipped> skipped = new ArrayList<>();
        boolean first = true;
        int dataRows = 0;
        // 시트 반복자는 실제로 있는 행만 돈다. getLastRowNum()으로 세면 서식만 남은 빈 행까지 센다.
        for (Row row : sheet) {
            Cell cell = row.getCell(0, Row.MissingCellPolicy.RETURN_BLANK_AS_NULL);
            if (cell == null || isBlankText(cell)) {
                continue;
            }
            if (first) {
                first = false;
                if (isHeader(cell)) {
                    continue;
                }
            }
            if (++dataRows > MAX_ROWS) {
                throw invalid("최대 1,000행까지 받습니다.");
            }
            int rowNumber = row.getRowNum() + 1;
            Long id = parse(cell);
            if (id == null) {
                skipped.add(new Skipped(rowNumber, formatter.formatCellValue(cell), "NOT_A_NUMBER"));
            } else if (id <= 0) {
                skipped.add(new Skipped(rowNumber, formatter.formatCellValue(cell), "NOT_POSITIVE"));
            } else {
                rows.add(new MemberIdRow(rowNumber, id));
            }
        }
        return new ExcelReadResult(rows, skipped);
    }

    /** 정수로 읽을 수 없으면 null. */
    private static Long parse(Cell cell) {
        CellType type = cell.getCellType() == CellType.FORMULA ? cell.getCachedFormulaResultType() : cell.getCellType();
        return switch (type) {
            case NUMERIC -> fromNumber(cell.getNumericCellValue());
            case STRING -> fromText(cell.getStringCellValue().trim());
            default -> null;
        };
    }

    // 엑셀은 숫자를 모두 double로 저장한다. 1을 넣어도 1.0으로 읽힌다.
    private static Long fromNumber(double value) {
        if (value != Math.rint(value) || Math.abs(value) > MAX_EXACT) {
            return null;
        }
        return (long) value;
    }

    private static Long fromText(String text) {
        return INTEGER.matcher(text).matches() ? Long.parseLong(text) : null;
    }

    private static boolean isBlankText(Cell cell) {
        return cell.getCellType() == CellType.STRING && cell.getStringCellValue().isBlank();
    }

    private static boolean isHeader(Cell cell) {
        return cell.getCellType() == CellType.STRING && cell.getStringCellValue().trim().equalsIgnoreCase(HEADER);
    }

    private static BusinessException invalid(String detail) {
        return new BusinessException(ErrorCode.VALIDATION, detail);
    }
}

 */
@Service
@PreAuthorize("hasRole('ADMIN')")
public class CouponBulkIssueService {

    private final ExcelMemberIdReader reader;
    private final CouponService couponService;
    private final CouponRepository couponRepository;
    private final MemberRepository memberRepository;

    public CouponBulkIssueService(ExcelMemberIdReader reader, CouponService couponService,
            CouponRepository couponRepository, MemberRepository memberRepository) {
        this.reader = reader;
        this.couponService = couponService;
        this.couponRepository = couponRepository;
        this.memberRepository = memberRepository;
    }

    /** 없는 쿠폰은 404, 파일 오류는 400. 행 오류는 건너뛰고 skipped[]에 행 번호 순으로 담는다. 같은 파일을 다시 올려도 안전하다. */
    @Audited(action = "BULK_ISSUE_COUPON", targetType = "COUPON")
    public BulkIssueResponse bulkIssue(Long couponId, MultipartFile file) {
        if (!couponRepository.existsById(couponId)) {
            throw new BusinessException(ErrorCode.NOT_FOUND, "쿠폰을 찾을 수 없습니다.");
        }
        ExcelReadResult read = reader.read(file);
        // 없는 회원을 먼저 거른다. 그대로 issue에 넘기면 FK 위반이 중복(ALREADY_ISSUED)으로 잘못 분류된다.
        Set<Long> existing = read.rows().isEmpty() ? Set.of()
                : new HashSet<>(memberRepository.findExistingIds(new HashSet<>(read.memberIds())));
        List<Skipped> skipped = new ArrayList<>(read.skipped());
        int issued = 0;
        for (MemberIdRow row : read.rows()) {
            if (!existing.contains(row.memberId())) {
                skipped.add(skip(row, "MEMBER_NOT_FOUND"));
                continue;
            }
            try {
                couponService.issue(couponId, row.memberId());
                issued++;
            } catch (BusinessException e) {
                skipped.add(skip(row, switch (e.errorCode()) {
                    // 파일 안에 같은 id가 두 번 있으면 두 번째도 여기로 온다
                    case DUPLICATE -> "ALREADY_ISSUED";
                    case COUPON_EXHAUSTED -> "COUPON_EXHAUSTED";
                    default -> throw e;
                }));
            }
        }
        skipped.sort(Comparator.comparingInt(Skipped::row));
        return new BulkIssueResponse(issued, skipped);
    }

    private static Skipped skip(MemberIdRow row, String reason) {
        return new Skipped(row.row(), String.valueOf(row.memberId()), reason);
    }
}

/** 테스트용 엑셀을 POI로 만든다(바이너리 파일을 저장소에 두지 않는다). 첫 열에만 값을 쓴다. */
final class Xlsx {

    /** 행은 만들되 첫 열 셀을 비워 둔다. */
    static final Object BLANK = new Object();

    private Xlsx() {
    }

    /** null은 행 자체를 만들지 않는다(빈 행). Number는 숫자 셀, String은 문자열 셀, Boolean은 논리 셀. */
    static byte[] xlsx(List<?> values) {
        return write(new XSSFWorkbook(), values);
    }

    static byte[] xls(List<?> values) {
        return write(new HSSFWorkbook(), values);
    }

    static List<Object> withHeader(List<?> values) {
        List<Object> all = new ArrayList<>();
        all.add("memberId");
        all.addAll(values);
        return all;
    }

    static MockMultipartFile file(String filename, byte[] bytes) {
        return new MockMultipartFile("file", filename,
                "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet", bytes);
    }

    private static byte[] write(Workbook wb, List<?> values) {
        try (wb; ByteArrayOutputStream out = new ByteArrayOutputStream()) {
            Sheet sheet = wb.createSheet("members");
            for (int i = 0; i < values.size(); i++) {
                Object v = values.get(i);
                if (v == null) {
                    continue;
                }
                Row row = sheet.createRow(i);
                if (v == BLANK) {
                    row.createCell(0);
                } else if (v instanceof Number n) {
                    row.createCell(0).setCellValue(n.doubleValue());
                } else if (v instanceof Boolean b) {
                    row.createCell(0).setCellValue(b);
                } else {
                    row.createCell(0).setCellValue(v.toString());
                }
            }
            wb.write(out);
            return out.toByteArray();
        } catch (IOException e) {
            throw new UncheckedIOException(e);
        }
    }
}

#말하기 카드

하루가 끝나면 질문에 "문제 상황 → 원인 → 선택 → 결과" 순서로 소리 내어 답한 뒤, 접힌 "답에 들어가야 할 것"과 비교한다. 세 줄이 모두 나오면 통과다.

#TC-D10-1

질문 AdminService의 한 메서드가 같은 클래스의 @PreAuthorize("hasRole('ADMIN')") 메서드를 부르는데, USER도 통과합니다. 왜 그런가요?

답에 들어가야 할 것
  • @PreAuthorize, @Transactional, 감사 로그 AOP는 프록시로 들어온 호출에만 적용되고, this로 부른 내부 호출은 프록시를 거치지 않는다
  • @PreAuthorize는 @EnableMethodSecurity를 켜야 동작하므로, 붙였는데 아무도 막지 않으면 이것부터 확인한다
  • 보호할 메서드는 바깥에서 직접 부르는 진입점에 두거나 별도 빈으로 빼고, URL 규칙(/api/admin/**는 ADMIN)을 첫 방어선으로 함께 둔다

#TC-D10-2

질문 서비스 테스트에 @Transactional을 붙였더니 통과했는데, 운영에서는 LazyInitializationException이 났습니다. 왜 그런가요?

답에 들어가야 할 것
  • 테스트의 @Transactional은 테스트 메서드 전체를 한 트랜잭션으로 감싸고 끝에 롤백한다
  • 그래서 서비스에 @Transactional이 빠져 있어도 테스트에서는 영속성 컨텍스트가 열려 있어 지연 로딩과 변경 감지가 동작한다
  • 서비스 동작을 검증하는 통합 테스트는 테스트 트랜잭션 없이 돌리고, 데이터는 테스트가 끝난 뒤 직접 정리한다

#TC-D10-3

질문 감사 로그를 서비스 코드에 직접 쓰지 않고 AOP로 뺐습니다. 감사 로그가 남지 않는 경우는 언제인가요?

답에 들어가야 할 것
  • 대상 메서드가 같은 클래스 안에서 호출되거나 private·final이면 프록시가 가로채지 못해 남지 않는다
  • 감사 로그를 업무 트랜잭션 안에서 쓰면 업무가 롤백될 때 로그도 함께 사라진다. 실패한 시도까지 남기려면 별도 빈의 REQUIRES_NEW 트랜잭션으로 쓴다
  • 기록할 값(actor_id, action, target_type, target_id)은 메서드 인자와 SecurityContext에서 얻는다

근거 spec-v2 §6

#TC-D10-4

질문 1,000행 엑셀로 쿠폰을 대량 지급하다 한 행이 실패하면 어떻게 되나요?

답에 들어가야 할 것
  • 명세는 부분 성공이다. 없는 회원이나 이미 보유한 행은 건너뛰고 {issued, skipped[]}로 알린다
  • 한 트랜잭션에서 행마다 중복 키 예외를 잡고 계속해도 JPA에서는 그 트랜잭션을 살려 쓸 수 없어(rollback-only 표시 또는 flush 시점 실패) 전체가 롤백된다
  • 그래서 대량 지급 메서드에는 @Transactional을 두지 않고 행마다 짧은 트랜잭션(CouponService.issue)으로 지급한다. 중복(UNIQUE)·소진은 그 행만 건너뛰므로 같은 파일을 다시 올려도 중복 지급되지 않는다

#TC-D10-5

질문 "신고 목록은 ADMIN만" 규칙을 어떤 테스트로 고정했나요?

답에 들어가야 할 것

말하기 카드
- [TC-D10-1] AdminService의 한 메서드가 같은 클래스의 @PreAuthorize("hasRole('ADMIN')") 메서드를 부르는데, USER도 통과합니다. 왜 그런가요?
    · @PreAuthorize, @Transactional, 감사 로그 AOP는 프록시로 들어온 호출에만 적용되고, this로 부른 내부 호출은 프록시를 거치지 않는다
    · @PreAuthorize는 @EnableMethodSecurity를 켜야 동작하므로, 붙였는데 아무도 막지 않으면 이것부터 확인한다
    · 보호할 메서드는 바깥에서 직접 부르는 진입점에 두거나 별도 빈으로 빼고, URL 규칙(/api/admin/는 ADMIN)을 첫 방어선으로 함께 둔다
- [TC-D10-2] 서비스 테스트에 @Transactional을 붙였더니 통과했는데, 운영에서는 LazyInitializationException이 났습니다. 왜 그런가요?
    · 테스트의 @Transactional은 테스트 메서드 전체를 한 트랜잭션으로 감싸고 끝에 롤백한다
    · 그래서 서비스에 @Transactional이 빠져 있어도 테스트에서는 영속성 컨텍스트가 열려 있어 지연 로딩과 변경 감지가 동작한다
    · 서비스 동작을 검증하는 통합 테스트는 테스트 트랜잭션 없이 돌리고, 데이터는 테스트가 끝난 뒤 직접 정리한다
- [TC-D10-3] 감사 로그를 서비스 코드에 직접 쓰지 않고 AOP로 뺐습니다. 감사 로그가 남지 않는 경우는 언제인가요?
    · 대상 메서드가 같은 클래스 안에서 호출되거나 private·final이면 프록시가 가로채지 못해 남지 않는다
    · 감사 로그를 업무 트랜잭션 안에서 쓰면 업무가 롤백될 때 로그도 함께 사라진다. 실패한 시도까지 남기려면 별도 빈의 REQUIRES_NEW 트랜잭션으로 쓴다
    · 기록할 값(actor_id, action, target_type, target_id)은 메서드 인자와 SecurityContext에서 얻는다
- [TC-D10-4] 1,000행 엑셀로 쿠폰을 대량 지급하다 한 행이 실패하면 어떻게 되나요?
    · 명세는 부분 성공이다. 없는 회원이나 이미 보유한 행은 건너뛰고 {issued, skipped[]}로 알린다
    · 한 트랜잭션에서 행마다 중복 키 예외를 잡고 계속해도 JPA에서는 그 트랜잭션을 살려 쓸 수 없어(rollback-only 표시 또는 flush 시점 실패) 전체가 롤백된다
    · 그래서 대량 지급 메서드에는 @Transactional을 두지 않고 행마다 짧은 트랜잭션(CouponService.issue)으로 지급한다. 중복(UNIQUE)·소진은 그 행만 건너뛰므로 같은 파일을 다시 올려도 중복 지급되지 않는다
- [TC-D10-5] "신고 목록은 ADMIN만" 규칙을 어떤 테스트로 고정했나요?
    · 토큰 없음(401), USER(403), ADMIN(200) 세 경우를 모두 보낸다. 성공 한 경우만 보면 규칙이 열려 있어도 통과한다
    · 테스트 컨텍스트에 실제 SecurityFilterChain과 JWT 필터가 올라와 있는지 확인한다. 보안 설정이 빠진 테스트는 아무것도 검증하지 않는다
    · @WithMockUser는 SecurityContext를 직접 채우므로 JWT 파싱 경로는 검증되지 않는다. JWT 필터는 실제 토큰으로 따로 확인한다
