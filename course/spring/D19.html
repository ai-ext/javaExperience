  1. 서로 다른 DB 연결 식별자를 기록한다.

    확인할 성질 내 물리 테이블·키·필터로 옮긴 SQL, 관찰 시각, 실제 출력과 기대 성질의 일치 여부를 남긴다. 예시는 실행 결과가 아니다.

  2. 같은 회원의 현재 상태와 요청의 관찰 시점을 대조한다.

#TC-D19-1

질문 ThreadLocal은 왜 싱글톤 필드와 다르게 보이나요?

답에 들어가야 할 것
  • 싱글톤 필드는 요청들이 공유하고 ThreadLocal은 현재 스레드마다 값을 보관한다.
  • 풀의 같은 스레드 재사용으로 요청 A의 값이 B에 남는 누출을 설명한다.
  • 풀 1개의 A/B 실제 출력과 일반 ThreadLocal의 비전달 한계를 제시한다.

#TC-D19-2

질문 요청 실패 뒤 정리는 어디서 보장하나요?

답에 들어가야 할 것
  • 성공·예외·취소 모두에서 finally의 remove가 실행되어야 한다.
  • A 실패 뒤 B에서 이전 값이 남지 않는 테스트 결과를 제시한다.
  • 비동기 작업도 자체 set/remove가 필요하며 정리 누락 비용을 말한다.

#TC-D19-3

질문 비동기 작업에는 어떤 문맥만 전달하나요?

답에 들어가야 할 것
  • 부모의 일반 ThreadLocal 값은 비동기 스레드로 자동 전달되지 않는다.
  • 요청 식별자 등 필요한 불변 값만 명시적 인자로 전달하는 기준을 말한다.
  • 민감 인증 객체 복사의 위험·작업 내부 정리·실제 비전달/전달 관찰을 제시한다.
