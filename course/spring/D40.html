#오늘의 SQL

내 프로젝트의 disposable 실습 DB를 쓴다. D23에서 정한 예약·대상·지급 상태의 물리 이름과 필터로 아래 예시를 반드시 매핑한다. 예시의 member_coupon은 1단계 비교 모델이며 새 예약 테이블의 구현 예시가 아니다. practice·원본 서버 DB는 수정하지 않는다.

  1. 장애 구간 전후 연결·대기 상태를 기록한다.

    확인할 성질 내 물리 테이블·키·필터로 옮긴 SQL, 관찰 시각, 실제 출력과 기대 성질의 일치 여부를 남긴다. 예시는 실행 결과가 아니다.

  2. 복구 후 잔액과 이력 합계를 대사한다.

    확인할 성질 내 물리 테이블·키·필터로 옮긴 SQL, 관찰 시각, 실제 출력과 기대 성질의 일치 여부를 남긴다. 예시는 실행 결과가 아니다.

#TC-D40-1

질문 원인 미확정인데 처음 무엇을 공유했나요?

답에 들어가야 할 것
  • 초기 공유는 영향 범위·발생 시각·확인 사실·미확인을 구분한다.
  • 현재 완화·담당·다음 보고 시각을 원인 추정과 분리해 전달한다.
  • 실제 첫 메시지·요청/DB/자원 증거와 사용한 판단 비용을 제시한다.

#TC-D40-2

질문 왜 원인 확정 전에 완화했거나 기다렸나요?

답에 들어가야 할 것
  • 지속 영향과 최소 증거 확보 시간을 근거로 완화/대기 결정을 말한다.
  • 재시작의 증거 손실·중복/누락 위험과 기다림 비용을 비교한다.
  • 완화/복구 시각·데이터 대사·원인 확정 시각을 구분해 제시한다.

#TC-D40-3

질문 반론을 받고 재발 방지안을 어떻게 바꿨나요?

답에 들어가야 할 것
  • 재시작 우선 반론과 원래 재발 방지안의 가정을 말한다.
  • 증거 손실·영향 비용·검증 가능성으로 수정안을 설명한다.
  • 수정 전후 결정·담당·기한·검증·실패 대응을 회의록으로 제시한다.
