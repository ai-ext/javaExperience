## 말하기 카드

하루가 끝나면 질문에 "문제 상황 → 원인 → 선택 → 결과" 순서로 소리 내어 답한 뒤, 접힌 "답에 들어가야 할 것"과 비교한다. 세 줄이 모두 나오면 통과다.

### TC-D34-1

**질문** synchronized는 왜 두 앱을 보호하지 못하나요?

<details class="card-answer" data-card="TC-D34-1">
<summary>답에 들어가야 할 것</summary>

- synchronized는 같은 JVM의 같은 모니터를 쓰는 스레드만 직렬화한다.
- 두 앱은 서로 다른 메모리/모니터이므로 DB의 공유 원자 경계가 필요하다.
- 두 PID 경쟁 결과와 선택한 조건부 갱신/잠금/lease 비용을 제시한다.

</details>

### TC-D34-2

**질문** 만료된 소유자의 늦은 완료를 어떻게 막나요?

<details class="card-answer" data-card="TC-D34-2">
<summary>답에 들어가야 할 것</summary>

- A의 소유권 획득·정지·만료·B 인수·A 재개의 순서를 말한다.
- 오래된 owner/세대의 완료를 거부하는 자신의 검증 경계를 설명한다.
- 실제 변경 행 수·소유권 세대·지급 식별 집합으로 늦은 완료 차단을 증명한다.

</details>

### TC-D34-3

**질문** 장애 후 누가 언제 작업을 가져가나요?

<details class="card-answer" data-card="TC-D34-3">
<summary>답에 들어가야 할 것</summary>

- 회수 주체·lease 만료 기준 시각·재시도 주기·대기 상한을 말한다.
- 열린 DB 락과 프로세스 STOP/KILL의 차이를 설명한다.
- B의 실제 회수 시간·중복/누락 대사·강제 회수 담당과 명령을 제시한다.

</details>

독립 수행이면 해법/힌트를 주지 말고 도움 횟수와 범위를 기록한다. 스스로 주입해 원인을 알고 있으면 비공개 장애 진단은 확인 불가다. 설명만으로 구현·진단을 통과시키지 마라.

마지막 줄: 필수 N/M 통과 · SQL S/T · 카드 K/L · 회의(해당 시) Q/10 · 독립 수행(해당 시) 통과/실패/확인 불가. 연차 도달을 보증하지 않는다.
