#오늘의 SQL

내 프로젝트의 disposable 실습 DB에서 기존 1단계 모델(게시글·회원·쿠폰)을 쓴다. 아래 예시를 내 테이블·열·키·필터로 매핑한다. 예약 모델은 D23 이후에 설계하며 오늘의 선행 조건이 아니다. practice·원본 서버 DB는 수정하지 않는다.

  1. 트랜잭션 안에서 바꾼 값을 확인한 뒤 rollback한다.

    확인할 성질 내 물리 테이블·키·필터로 옮긴 SQL, 관찰 시각, 실제 출력과 기대 성질의 일치 여부를 남긴다. 예시는 실행 결과가 아니다.

  2. rollback 종료 후 별도 연결에서 같은 행을 조회한다.

    확인할 성질 내 물리 테이블·키·필터로 옮긴 SQL, 관찰 시각, 실제 출력과 기대 성질의 일치 여부를 남긴다. 예시는 실행 결과가 아니다.

구현 예시 SQL · 직접 작성한 뒤 비교하기

아래는 비교용 SQL이다. 예약·대상·작업 모델은 내가 정한 물리 이름과 필터로 옮긴다. board-server의 설계 기준이다. 2단계에서는 같은 계열의 기존 스키마를 관찰한다. 내 물리 이름·키·정렬이 다르면 매핑해 비교한다. 아래 SQL은 실제 실행 결과가 아니며 예시 서버가 모든 불변식을 보장한다는 뜻도 아니다. 오류가 예상되는 문장은 하나씩 실행하고 실패 뒤 ROLLBACK을 별도로 보낸다.

문항 1 구현 예시

START TRANSACTION; SELECT id,title FROM post WHERE id=1; ROLLBACK;

문항 2 구현 예시

SELECT CONNECTION_ID(),id,title FROM post WHERE id=1;

#말하기 카드

하루가 끝나면 질문에 "문제 상황 → 원인 → 선택 → 결과" 순서로 소리 내어 답한 뒤, 접힌 "답에 들어가야 할 것"과 비교한다. 세 줄이 모두 나오면 통과다.

#TC-D21-1

질문 flush했는데 왜 다른 연결은 값을 못 볼 수 있나요?

답에 들어가야 할 것
  • flush는 SQL 전송이며 commit 완료와 다르다.
  • 별도 연결의 격리 수준·관찰 시각에 따라 미커밋 변경이 보이지 않음을 설명한다.
  • flush 후 rollback·commit 대조의 실제 SQL/행 결과를 제시한다.

#TC-D21-2

질문 rollback 뒤 Java 객체 값은 무엇을 증명하나요?

답에 들어가야 할 것
  • rollback 뒤 Java 객체 필드는 자동으로 원래 값이 되지 않을 수 있다.
  • 객체 값·영속성 컨텍스트·DB 확정 행은 서로 다른 증거다.
  • 종료 뒤 새 연결 조회로 rollback 결과를 확인하고 객체만 본 판단의 한계를 말한다.

#TC-D21-3

질문 관찰 테스트의 트랜잭션이 결과를 바꾸나요?

답에 들어가야 할 것
  • 테스트의 바깥 트랜잭션과 실제 서비스 프록시 경계를 구분한다.
  • 테스트 자동 rollback이 commit 관찰을 가리거나 같은 연결 조회를 만들 수 있다.
  • 트랜잭션 종료 후 별도 연결에서 확인한 명령·격리 수준·출력을 제시한다.

각 C 항목은 실제 테스트·SQL·로그·문서 경로와 줄을 근거로 통과/실패/확인 불가로 판정한다. 티켓 A/B는 원인 서술·수정 전 RED·수정 후 GREEN·반례·diff를 확인하고 미선택 티켓을 실패로 채점하지 마라. 미수행 대신 정한 새 조건은 조건과 새 실패 증거를 요구한다. 이미 새 조건도 통과하면 통과 사실을 인정하고 정상 코드를 약화하지 마라. 해당 일자의 요구 합의 단계(D16~D18은 D16, D36은 D35)로 돌아가 담당자/훈련 진행자와 미충족 새 계약을 합의하도록 하며, 미합의·미실행은 확인 불가로 남긴다. 기존 2단계 제외 규칙을 3단계 필수 A/B에 자동 적용하지 마라.
회의가 있으면 M1~M5 각각 0(없음)/1(부분)/2(근거·합의까지)로 채점한다. 각 항목 1점 이상 및 총 8/10 이상이어야 회의 통과다. 한 항목 0점이면 총점과 무관하게 재훈련한다. 먼저 발언을 받고 반론을 하나 제시한 뒤 수정 발언을 기록한다. 외운 답 선공개는 금지한다.
독립 수행이면 해법/힌트를 주지 말고 도움 횟수와 범위를 기록한다. 스스로 주입해 원인을 알고 있으면 비공개 장애 진단은 확인 불가다. 설명만으로 구현·진단을 통과시키지 마라.
