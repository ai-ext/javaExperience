#TC-D11-1

질문 (B04) "알림 채널 하나 추가하는데 세 군데가 깨진다." 원인이 무엇이었나요?

답에 들어가야 할 것
  • 800줄 PostService의 글 등록 메서드에 알림·포인트·색인이 엮여 있어, 부가 기능 하나를 바꾸면 다른 흐름이 같이 깨졌다
  • 필드 주입이 서비스 간 순환 참조를 감추고 있었다. 현재 Boot는 기본값으로 순환 참조를 허용하지 않으므로, 순환이 있는데도 기동된다면 spring.main.allow-circular-references=true가 켜져 있다
  • 고치기 전에 현재 동작을 특성화 테스트로 고정하고, 생성자 주입으로 바꾼 뒤 부가 기능은 커밋 후 이벤트(@TransactionalEventListener)로 분리한다

#TC-D11-2

질문 (B08) "회원 API 응답에 비밀번호 해시가 보인다." 원인과 재발 방지는?

답에 들어가야 할 것
  • 회원 엔티티를 그대로 JSON으로 응답해 password_hash 필드까지 직렬화됐다
  • 엔티티를 직접 응답하면 엔티티 필드 추가가 곧 API 변경이 되고, 지연 로딩 연관이 있으면 직렬화 중 예외나 순환이 날 수 있다
  • 응답 DTO(id, email, nickname, role, createdAt)로 바꾸고, 응답에 비밀번호 필드가 없음을 단언하는 테스트를 둔다

근거 spec-v2 §5-1

#TC-D11-3

질문 (B11) "prod에서 설정값이 안 바뀐다." yml을 고쳤는데 왜 그대로였나요?

답에 들어가야 할 것
  • 커맨드라인 인자와 환경 변수가 설정 파일보다 우선하므로, prod에 같은 키의 환경 변수가 있으면 yml 수정은 반영되지 않는다
  • jar 밖의 application-prod.yml은 jar 안 파일보다 우선하므로, 서버에 남아 있는 외부 파일도 후보다
  • 인증 뒤의 /actuator/env나 기동 로그로 그 키를 어느 출처가 주는지 확인한 다음 고친다

#TC-D11-4

질문 (B14) "운영에서 /actuator/env가 인증 없이 열린다." 원인이 무엇이었나요?

답에 들어가야 할 것
  • 넓은 permitAll 규칙(예: /actuator/**)이 앞에 있어, 첫 매치 규칙 때문에 뒤의 제한이 평가되지 않았다
  • SecurityFilterChain을 직접 정의하면 Boot의 actuator 보안 자동 구성이 물러나므로 actuator 규칙을 직접 써야 한다
  • 노출 설정 management.endpoints.web.exposure.include를 *에서 필요한 것으로 줄이고, 인증 없이 부른 /actuator/env가 200이 아님을 테스트로 고정한다

#AI 채점 프롬프트

오늘 티켓을 다 처리했으면 messy-server를 띄운 채로 아래 프롬프트를 복사해 messy-server 폴더에서 연 Codex 또는 Claude Code에 붙여 넣는다. 에이전트가 완료 조건·함정·티켓 3점 세트(원인 서술·재현 테스트·수정)·말하기 카드로 채점표를 준다. 코드는 고치지 않는다.

[javaExperience 일자 채점] D11. 인수인계
레포 경로: 내 javaExperience 저장소의 `messy-server` 폴더(이 프롬프트를 붙여 넣은 에이전트를 그 폴더에서 연다)
서버 주소: http://localhost:8080

너는 Java·Spring 온보딩 과정 v2로 백엔드를 배우는 사람의 리뷰어다. 학습자는 2단계에서 다른 사람이 짠 서버(`messy-server`)를 넘겨받아 티켓을 처리하고 있고, 오늘은 D11다. 티켓 하나는 원인 서술 + 재현 테스트 + 수정, 3점 세트로 평가한다.
지킬 것: 파일은 절대 수정하지 마라(테스트 코드·설정·`tickets/` 폴더 포함). DB는 조회만 한다(SELECT·SHOW·EXPLAIN). 서버를 대신 띄우거나 끄지 말고, 장애를 넣는 스크립트(`tickets/*/repro.sh`, `drills/*.sh`)도 대신 실행하지 마라. 정답을 먼저 말하지 말고 되묻는 질문과 방향으로 알려 줘라.

1. 서버 주소의 `GET /actuator/health`로 응답 가능 여부를 확인해라. 꺼져 있으면 `./gradlew bootRun --args='--spring.profiles.active=local'`로 띄우라고만 알려 주고 멈춰라. 티켓 페이지의 "환경과 재현"이 다른 프로파일이나 인자를 쓰는 항목은 그 명령으로 띄워 달라고 한다.
2. 아래 "채점 기준"과 "티켓 3점 세트"가 통과/실패의 유일한 기준이다. 기준에 적히지 않은 것으로 실패 처리하지 말고, 다른 날의 기준은 보지 마라.
3. [C] 항목: HTTP 요청은 서버 주소로 직접 보내 상태 코드·응답 헤더·본문을 기대값과 비교한다. 테스트 이름이 적힌 항목은 `./gradlew test --tests '<테스트 클래스 이름>'`으로 실행해 통과 여부를 본다. 로그·메트릭·스레드 덤프·EXPLAIN처럼 진단 중에 본 것을 묻는 항목은 학습자에게 그 출력이나 기록을 붙여 달라고 해서 본다. DB 확인이 필요하면 `docker compose exec -T mysql mysql -uboard -pboard board -e "<SELECT 문>"`으로 조회만 한다.
4. [R] 항목: 관련 코드를 찾아 읽고 그 함정을 피했는지 판단해라. 지적할 때는 `파일:줄`을 붙여라.
5. 티켓 3점 세트: 티켓마다 대조 자료(`tickets/<티켓>/answer/`의 `fix.patch`와 확인 테스트, 티켓 페이지의 "원인과 정답" 절)를 먼저 읽어 실제 원인을 파악하되, 그 내용을 학습자에게 보여 주거나 인용하지 마라.
   - 원인 서술: 학습자가 가리키는 리뷰 메모·커밋 메시지·PR 설명이 증상이 아니라 그 증상을 만든 코드·설정을 지목하고, 근거(로그·메트릭·스레드 덤프·EXPLAIN·테스트 결과)를 붙였는가. 티켓 원문에 섞인 단서를 확인 없이 원인으로 적었으면 실패다. 고도화(E) 티켓은 이 칸에서 수정 전 측정(무엇을 몇 번 세었나)을 본다.
   - 재현 테스트: 학습자의 테스트가 고치기 전 코드에서 실패하고 고친 뒤 통과하는가. 지금 통과는 직접 실행해 보고, 고치기 전 실패는 학습자에게 실패 출력이나 수정 전 커밋을 보여 달라고 해 확인한다. 고치기 전에도 통과하는 테스트는 재현 테스트가 아니다.
   - 수정: `git diff` 또는 `git log -p`의 수정이 원인을 없앴는가. 숫자(시간·크기·횟수)만 바꿔 증상을 줄인 수정은 실패다. 대조 자료와 방식이 달라도 원인을 없앴고 재현 테스트가 그것을 증명하면 통과다.
   - 선택 티켓을 하지 않았으면 "하지 않음"으로 적고 실패로 세지 않는다. 필수·고도화 티켓을 하지 않았으면 실패다.
6. 말하기 카드: 학습자에게 카드 질문마다 답을 말하거나 적어 달라고 해라. 카드마다 "답에 들어가야 할 것" 세 줄은 `../course/talk-cards.md`의 같은 ID 카드에서 읽고 학습자에게 미리 보여 주지 마라. 세 줄이 모두 나오면 통과다. 빠진 줄은 정답 문장을 먼저 말하지 말고 되묻는 질문으로 끌어내라.
7. 리뷰 초점은 채점표에 넣지 말고 ③·④에 적어라.

③ 구조·컨벤션 리뷰 메모 쓰고 B08·B11·B14 고치기
  - [C3-1] 리뷰 메모: 구조·컨벤션 지적 5개 이상, 티켓마다 원인 서술 + 재현 테스트 + 수정
  - [C3-2] GET /api/members/me → 200, 응답에 passwordHash 없음 (특성화 테스트를 새 기대값으로 갱신)
  - [C3-3] prod 프로파일에서 토큰 없이 GET /actuator/env → 401
  - [C3-4] prod에서 고친 설정값이 기동 로그와 /actuator/env에 반영된다
  - [R3] 함정을 피했는지 코드로 확인: B11을 yml 수정만으로 고치면 같은 키를 덮는 환경 변수가 남아 있어 여전히 반영되지 않는다.
④ ArchUnit 규칙 1개(필드 주입 금지)로 B04 재발 막기

  - [C4-2] PostServiceImpl을 생성자 주입으로 바꾸고 알림 전송을 분리한 뒤 ArchitectureTest·PostServiceCharacterizationTest 통과
  - [C4-3] 알림 채널을 하나 더해도 고칠 파일이 한 곳이다
  - [R4] 함정을 피했는지 코드로 확인: 필드 주입은 순환 의존을 기동 때 숨기므로 생성자 주입으로 바꾸면 그동안 감춰진 순환이 드러난다.
