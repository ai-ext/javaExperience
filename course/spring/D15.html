#D15. 설명 세션

마무리설명 세션오늘의 Java J15순서 2개말하기 카드 5장준비 중

이 날은 아직 준비 중이다. 순서 제목과 말하기 카드만 먼저 싣고, 티켓 페이지·힌트·채점 프롬프트는 2단계 자료가 끝난 뒤 채운다.

#오늘 순서

0/2 끝냄

  1. ①설명 세션: 말하기 카드 전체에서 무작위 10문항 설명하기
  2. ②회고 문서 "내가 겪은 문제 5개" 쓰기

체크는 이 브라우저에만 저장되고, 홈의 "오늘 할 일"이 이 체크로 다음 날을 고릅니다.

#오늘의 Java

J15. 종합: 쿠폰 할인 계산기 처음부터 만들기 — 4560분(선택 퀴즈 +1525분). Spring 순서를 시작하기 전에 오늘 쓰는 Java를 먼저 연습한다.

  • 주제: 종합: 작은 쿠폰 할인 계산기를 처음부터 만들기(인터페이스, 제네릭, stream, 예외, 테스트를 모두 사용)

#① 설명 세션: 말하기 카드 전체에서 무작위 10문항 설명하기

#② 회고 문서 "내가 겪은 문제 5개" 쓰기

준비 중: 이 순서의 만들 파일·겪을 것·완료 조건·힌트는 마무리 자료와 함께 채운다.

#말하기 카드

하루가 끝나면 질문에 "문제 상황 → 원인 → 선택 → 결과" 순서로 소리 내어 답한 뒤, 접힌 "답에 들어가야 할 것"과 비교한다. 세 줄이 모두 나오면 통과다.

#TC-D15-1

질문 15일 동안 겪은 문제 하나를 골라 "문제 상황 → 원인 → 선택 → 결과"로 2분 안에 설명해 보세요.

답에 들어가야 할 것
  • 증상을 관찰한 사실로 말한다(무엇이, 언제, 얼마나)
  • 원인을 짐작이 아니라 재현 테스트·로그·메트릭 같은 근거와 함께 말한다
  • 고른 해법과 버린 대안, 고친 뒤 무엇(테스트, 수치)으로 확인했는지 말한다

#TC-D15-2

질문 처음 진단이 틀렸던 티켓이 있었나요? 무엇에 속았고, 무엇으로 바로잡았나요?

답에 들어가야 할 것
  • 처음 세운 가설과 그 가설을 믿게 만든 단서를 말한다
  • 가설을 버리게 한 관찰(재현 결과, 로그, 메트릭, 스레드 덤프)을 말한다
  • 같은 증상을 다시 보면 먼저 확인할 것을 순서대로 말한다

#TC-D15-3

질문 1단계에서 직접 만든 코드에 2단계 티켓과 같은 결함이 있었나요? 그때는 왜 놓쳤나요?

답에 들어가야 할 것
  • 해당 코드 위치와 같은 원인의 티켓 번호를 댄다
  • 놓친 이유를 말한다(예: 테스트가 동시 요청이나 경계 시각을 다루지 않았다)
  • 같은 실수를 막을 장치(재현 테스트, ArchUnit 규칙, 리뷰 체크 항목)를 말한다

#TC-D15-4

질문 모의 장애 훈련에서 장애를 알아차리고 원인을 지목하기까지 무엇을 봤나요? 회고 문서에는 무엇을 남겼나요?

답에 들어가야 할 것
  • 처음 알아차린 신호(에러율, 응답 시간, Hikari pending 등)와 그 시각을 말한다
  • 원인을 좁힌 순서(메트릭 → 요청 ID로 로그 → 스레드 덤프 등)를 말한다
  • 사람 탓이 아니라 구조의 원인을 적고, 재발 방지 조치마다 확인 방법을 남겼다

#TC-D15-5

질문 지금 다시 만든다면 바꿀 설계 결정 하나는 무엇인가요? 바꾸는 데 드는 비용은?

답에 들어가야 할 것
  • 당시 결정과 그때의 근거를 말한다
  • 생각을 바꾸게 한 관찰(티켓, 측정 결과)을 말한다
  • 바꿀 때의 영향 범위와 옮겨 가는 방법(하위 호환, 데이터 이전)을 말한다
