#오늘의 SQL

1단계 내 DB 또는 2단계 DB 중 하나를 정해 데이터셋·관찰 시각을 명시한다. 오늘은 지난 SQL과 증거를 복습한다.

  1. 회원별 잔액·이력 합 대사를 다시 실행하고 D07 또는 D13 기록과 비교한다.

    확인할 성질 불일치 유무와 그 사이 수행한 요청을 설명한다. 이전 숫자를 현재 결과로 복사하지 않는다.

  2. 가장 설명하기 어려웠던 SELECT 하나를 골라 결과 행 수·실행 계획을 다시 기록한다.

    확인할 성질 정렬·필터·조인 다중성이 결과에 미친 영향을 내 SQL과 실제 출력으로 설명한다.

02 · 소리 내어 설명하기

#말하기 카드

하루가 끝나면 질문에 "문제 상황 → 원인 → 선택 → 결과" 순서로 소리 내어 답한 뒤, 접힌 "답에 들어가야 할 것"과 비교한다. 세 줄이 모두 나오면 통과다.

#TC-D15-1

질문 15일 동안 겪은 문제 하나를 골라 "문제 상황 → 원인 → 선택 → 결과"로 2분 안에 설명해 보세요.

답에 들어가야 할 것
  • 증상을 관찰한 사실로 말한다(무엇이, 언제, 얼마나)
  • 원인을 짐작이 아니라 재현 테스트·로그·메트릭 같은 근거와 함께 말한다
  • 고른 해법과 버린 대안, 고친 뒤 무엇(테스트, 수치)으로 확인했는지 말한다

#TC-D15-2

질문 처음 진단이 틀렸던 티켓이 있었나요? 있었다면 무엇으로 바로잡았나요? 없었다면 다른 가설을 어떻게 배제했나요?

답에 들어가야 할 것
  • 처음 세운 가설과 단서를 말한다. 오진이 없었다면 비교한 다른 가설도 말한다
  • 가설을 바로잡은 관찰을 말한다. 오진이 없었다면 다른 가설을 배제한 재현 테스트·로그·메트릭 등 근거를 말한다
  • 같은 증상을 다시 보면 먼저 확인할 것을 순서대로 말한다

#TC-D15-3

질문 1단계에서 직접 만든 코드에 2단계 티켓과 같은 결함이 있었나요? 있었다면 왜 놓쳤나요? 없었다면 어떻게 배제·예방했나요?

답에 들어가야 할 것
  • 대조한 코드 위치와 티켓 번호를 댄다
  • 결함을 놓친 이유를 말한다. 없었다면 해당 결함을 배제·예방한 테스트·로그·코드 조건 등 근거를 말한다
  • 재발 방지 또는 예방 장치(재현 테스트, ArchUnit 규칙, 리뷰 체크 항목)와 확인 방법을 말한다

#TC-D15-4

질문 모의 장애 훈련에서 장애를 알아차리고 원인을 지목하기까지 무엇을 봤나요? 회고 문서에는 무엇을 남겼나요?

답에 들어가야 할 것
  • 처음 알아차린 신호(에러율, 응답 시간, Hikari pending 등)와 그 시각을 말한다
  • 원인을 좁힌 순서(메트릭 → 요청 ID로 로그 → 스레드 덤프 등)를 말한다
  • 사람 탓이 아니라 구조의 원인을 적고, 재발 방지 조치마다 확인 방법을 남겼다

#TC-D15-5

질문 지금 다시 만든다면 바꿀 설계 결정 하나는 무엇인가요? 바꾸는 데 드는 비용은?

답에 들어가야 할 것
  • 당시 결정과 그때의 근거를 말한다
  • 생각을 바꾸게 한 관찰(티켓, 측정 결과)을 말한다
  • 바꿀 때의 영향 범위와 옮겨 가는 방법(하위 호환, 데이터 이전)을 말한다
