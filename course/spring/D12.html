#오늘의 SQL

messy-server DB(13311)의 실제 스키마와 티켓 재현 자료를 쓴다. 1단계 seed.sql·bulk.sql은 적재하지 않는다. 읽기 전용 진단 SQL·관찰 시각·실제 결과만 남긴다. 관찰 결과가 0행이어도 원인이나 정상 여부를 단정하지 않는다. 예시 SQL은 기존 서버 설계 기준이다.

  1. 재현 중 실행 중인 세션과 열린 트랜잭션을 같은 시각에 조회한다.

    확인할 성질 세션 식별·시작 시각·현재 SQL을 증거로 남긴다. 관찰 권한이 없으면 그 오류를 기록한다.

  2. 로그에서 실제 목록 SELECT를 찾아 실행 계획과 반환 건수를 비교한다.

    확인할 성질 관찰한 쿼리·바인딩 값·key·추정 행 수를 남긴다. ANALYZE는 SELECT임을 확인한 뒤 실행하며 실행 부담도 기록한다.

구현 예시 SQL · 직접 작성한 뒤 비교하기

board-server의 설계 기준이다. 2단계에서는 같은 계열의 기존 스키마를 관찰한다. 내 물리 이름·키·정렬이 다르면 매핑해 비교한다. 아래 SQL은 실제 실행 결과가 아니며 예시 서버가 모든 불변식을 보장한다는 뜻도 아니다. 오류가 예상되는 문장은 하나씩 실행하고 실패 뒤 ROLLBACK을 별도로 보낸다.

#TC-D12-1

질문 (B01) "PG가 느린 날 글 목록까지 멈춘다." 상관없어 보이는 두 기능이 왜 같이 멈췄나요?

답에 들어가야 할 것
  • 충전 서비스가 @Transactional 안에서 PG를 호출해, PG가 느린 동안 DB 커넥션을 쥔 채 기다렸다
  • 동시 충전 요청이 Hikari 풀(10개)을 모두 쥐자, 같은 풀을 쓰는 글 목록도 connection-timeout(2초)까지 기다리다 실패했다
  • Hikari 메트릭(active가 최대에 붙고 pending이 쌓임)과 스레드 덤프로 확인하고, PG 호출을 트랜잭션 밖으로 뺀다. 풀을 키우는 것은 해법이 아니다

#TC-D12-2

질문 (B02) "글 목록이 어느 날부터 느리다." 어떻게 원인 쿼리를 찾고 무엇을 고쳤나요?

답에 들어가야 할 것
  • slow query log로 후보를 찾는다. long_query_time 기본값이 10초라 낮춰야 잡힌다
  • EXPLAIN ANALYZE로 읽은 행 수와 실제 돌려준 행 수를 비교해 풀스캔이나 인덱스 비효율을 확인한다. 데이터가 적을 때는 풀스캔도 빨라 보여 드러나지 않았다
  • 복합 인덱스는 왼쪽 컬럼부터만 쓰이므로 조건·정렬에 맞게 순서를 고치고, 고친 뒤 EXPLAIN의 key, rows, Extra로 확인한다

#TC-D12-3

질문 (B03) "예외를 잡았는데도 구매가 롤백된다 / 안 된다." 두 증상의 원인은 각각 무엇이었나요?

답에 들어가야 할 것
  • 롤백 안 됨: order가 같은 클래스의 @Transactional placeOnce를 this로 불러 프록시를 거치지 않아 트랜잭션이 아예 열리지 않았다. 재고·쿠폰·주문·포인트가 각자 커밋돼 마지막 포인트 차감이 실패해도 앞의 변경이 남았다
  • 롤백됨: 감사 쿠폰 지급(REQUIRED)이 참여한 안쪽 grant의 예외를 catch로 삼켜도 트랜잭션에 rollback-only가 남아, 커밋 때 UnexpectedRollbackException으로 구매 전체가 롤백된다
  • 트랜잭션이 열리게 고치면 rollback-only가 "구매 전체 롤백"으로 드러나므로 두 증상을 테스트로 함께 고정하고, TransactionTemplate으로 실제 트랜잭션을 연 뒤 지급 실패는 예외 대신 조건부 UPDATE의 영향 행 수로 판단한다

#TC-D12-4

질문 (B05) "부하 때만 다른 사람 값이 섞인다." 왜 부하 때만 나타났나요?

답에 들어가야 할 것
  • 싱글톤 빈의 인스턴스 필드에 요청별 값을 저장해, 동시 요청이 서로의 값을 덮어썼다
  • 요청이 하나씩 올 때는 덮어쓸 상대가 없어 단위 테스트나 수동 확인으로는 재현되지 않았다
  • 여러 스레드로 동시에 호출하는 재현 테스트(ExecutorService, CountDownLatch)로 섞임을 먼저 보이고, 값을 지역 변수·인자로 옮긴 뒤 같은 테스트가 통과하는지 확인한다
