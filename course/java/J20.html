#만들 파일과 실행 위치

내 프로젝트 루트에서 src/test/java/J20EvidenceTest.java를 만든다. 기존 테스트로 동일 증거가 있으면 재실행·조건을 기록하고 재사용한다. java-track에 존재하지 않는 J16 이후 테스트가 있다고 가정하지 않는다.

#오늘 실험

Clock.fixed와 정책 인터페이스를 사용해 만료 직전·정각·직후를 검사하고, 작은 bounded executor에서 초과 작업의 거부를 관찰한다.

Clock.fixed는 J09의 만료 경계를 재사용하고 정책 비교는 J13을 재사용한다. 실행기 용량은 별도 실험이다. new ThreadPoolExecutor(2, 2, 0, TimeUnit.MILLISECONDS, new ArrayBlockingQueue<>(2), new ThreadPoolExecutor.AbortPolicy())로 worker와 queue 모두 상한을 둔다.

CountDownLatch started(2)와 release(1)를 둔다. 첫 두 작업은 started.countDown 후 release.await(2, SECONDS)한다. started.await가 성공한 뒤 작업 3·4를 제출하면 queue=2, 다섯 번째 submit은 RejectedExecutionException이어야 한다. sleep으로 순서를 추측하지 않는다.

finally에서 release.countDown·shutdown을 실행하고 awaitTermination(3초)이 false면 shutdownNow 후 다시 기다린다. shutdown 뒤 제출 거부도 확인한다. queue 크기·수용/거부 수·대기 시간을 기록한다. 예외 경로도 동일 정리하고 인터럽트는 복원한다. 이 숫자는 운영 적정값이 아니다.

#실행과 완료 조건

  • ./gradlew test --tests 'J20EvidenceTest' (직접 이 이름으로 만든 테스트). 기존 테스트를 재사용하면 실제 클래스 이름으로 실행한다.
  • Clock.fixed와 정책 인터페이스를 사용해 만료 직전·정각·직후를 검사하고, 작은 bounded executor에서 초과 작업의 거부를 관찰한다.
  • 선택한 경계의 기대값과 실제 출력·실행 명령을 남긴다. 단순 설명만으로 완료하지 않는다.

통합 관찰은 disposable DB/별도 JVM에서 실행한다. 실행 불가는 이유와 함께 확인 불가로 기록한다. 성공/실패·예상/실측을 나눈다.
