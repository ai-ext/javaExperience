#만들 파일과 실행 위치

내 프로젝트 루트에서 진행한다. 기존 코드·테스트를 읽고 영향·정책·회고와 연결한 증거 문서를 작성한다. 기존 테스트 재실행과 비교로 충족하며 새 테스트 클래스 생성은 필수가 아니다.

#오늘 실험

작업 분해를 의존 그래프로 표현하고 정책 변경 영향이 있는 테스트 목록을 코드에서 찾는다.

#실행과 완료 조건

  • ./gradlew test --tests <근거로 선택한 기존클래스명>을 실행하고 코드 경로·결과·문서와의 일치/차이를 기록한다.
  • 작업 분해를 의존 그래프로 표현하고 정책 변경 영향이 있는 테스트 목록을 코드에서 찾는다.
  • 선택한 경계의 기대값과 실제 출력·실행 명령을 남긴다. 단순 설명만으로 완료하지 않는다.

통합 관찰은 disposable DB/별도 JVM에서 실행한다. 실행 불가는 이유와 함께 확인 불가로 기록한다. 성공/실패·예상/실측을 나눈다.
