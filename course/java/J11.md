# J11. 리팩터링 ①: 특성화 테스트로 레거시 동작 고정하기

> 같은 날: D11 · 소요 30~60분 · 실행 `./gradlew :java-track:test --tests 'J11*'`

## 상황

D11부터는 남이 만든 코드를 넘겨받는다. D11 ②에서 글 작성·수정·삭제와 `GET /api/members/me`의 **지금 동작**을 특성화 테스트로 고정한다. 그다음 ③④에서 버그를 고치고 구조를 바꾼다. 고정한 테스트가 안전망이 되어, 고치는 동안 다른 동작이 바뀌면 바로 드러난다.
오늘은 Spring 없이 같은 일을 해 본다. 문서 없이 조건이 덧붙은 레거시 포인트 계산 메서드가 있다. 이 메서드가 지금 돌려주는 값을 테스트로 고정한다. 이 테스트가 정말 동작을 고정했는지는 메서드를 일부러 한 곳씩 망가뜨린 변형으로 확인한다.

## 빠른 연상

| | 보통 테스트(명세) | 특성화 테스트 |
|---|---|---|
| 기대값의 출처 | 요구사항, "이래야 한다" | 지금 코드를 불러서 **나온 값** |
| 이상한 동작을 만나면 | 버그로 보고 실패시킨다 | 그대로 적는다. 고치는 것은 나중 일이다 |
| 목적 | 새 기능이 맞는지 확인 | 리팩터링 중에 동작이 바뀌지 않았는지 감지 |
| 일상 비유 | 설계도대로 지었는지 검사 | 이사 전에 방마다 사진을 찍어 두기 |

흔한 착각: "특성화 테스트에도 옳은 값을 적어야 한다". 옳은 값을 적으면 고치기 전부터 실패한다. 그러면 테스트가 지금 동작을 고정하지 못하고 안전망 역할도 못 한다(D11 ②의 함정). `VIP`는 5만 원 보너스가 없다. 이 규칙이 이상해 보여도 지금 그렇게 돌아가고 있으므로 그대로 적는다.

레거시 코드(주어진 것):

```java
public int calculate(int amount, String grade, boolean couponUsed) {
    if (amount < 0) {
        return -1;
    }
    if (amount < 1000) {
        return 0;
    }
    int rate;
    if ("VIP".equals(grade)) {
        rate = 5;
    } else if ("GOLD".equals(grade)) {
        rate = 3;
    } else {
        rate = 1;
    }
    int point = amount * rate / 100;
    // 2021 여름 이벤트: 5만 원 이상 구매 보너스
    if (amount >= 50000) {
        if (!"VIP".equals(grade)) {
            point = point + 500;
        }
    }
    if (point > 3000) {
        point = 3000;
    }
    // 쿠폰을 쓰면 적립은 절반
    if (couponUsed) {
        point = point / 2;
    }
    return point;
}
```

쓰는 순서:

1. 분기마다 경계 양쪽 값을 고른다. 대상은 `if` 하나하나, `>=`인지 `>`인지, 나눗셈의 소수점 처리, null과 대소문자다.
2. 그 값으로 `calculate`를 불러 **나온 값을 그대로** 기대값에 적는다. `@ParameterizedTest`·`@CsvSource`를 쓰면 표처럼 쓸 수 있다.
3. 기본기 반복의 `PointTable.describeAll`을 먼저 채웠다면 조합 표 전체를 한 번에 고정할 수도 있다.

통과시킬 테스트(주제 과제):

- `J11CharacterizationTest` — 네가 쓴 테스트가 원본에서 모두 통과한다.
- `J11MutantTest` — 네 테스트를 원본과 변형 3개에 돌려 본다. 변형은 원본에서 한 곳만 바꾼 것이다.

## 기본기 반복

레거시 메서드의 입력 조합을 for 세 겹으로 만들어 결과를 `List<String>`에 모은다. 단정은 목록 하나로 한 번에 한다. 조합이 30개여도 단정문은 하나다. 어느 줄이 달라졌는지는 실패 메시지에 함께 나온다.

```java
/**
 * 금액 × 등급 × 쿠폰 여부(false, true 순)의 모든 조합으로 calculator를 불러 한 줄씩 모은다.
 * 한 줄은 "등급/금액/쿠폰=포인트" 모양이다. 예: "GOLD/50000/-=2000", "null/1000/쿠폰=5"
 */
public static List<String> describeAll(LegacyPointCalculator calculator, int[] amounts, String[] grades)
```

테스트 — `J11BasicsTest`:

- `금액_등급_쿠폰_조합을_순서대로_모아_한_번에_단정한다`
- `조합_수는_금액_수_곱하기_등급_수_곱하기_2다`
- `금액이나_등급이_비어_있으면_빈_목록이다`

## 타입 한 컷

배열 vs `List`. 레거시 코드는 `String[] gradeNames()`, `int[] gradeRates()`처럼 배열을 돌려준다.

| | 배열 `String[]` | `List<String>` (`ArrayList`) | `Arrays.asList(배열)` |
|---|---|---|---|
| 길이 | 만들 때 고정 | 늘고 준다 | **고정**(`add`하면 `UnsupportedOperationException`) |
| 원소 바꾸기 | 된다 | 된다 | 된다. **원본 배열도 같이 바뀐다**(배열 위의 뷰) |
| 공변성 | `String[]`을 `Object[]`에 대입 가능. 잘못 넣으면 실행 중 `ArrayStoreException` | `List<String>`을 `List<Object>`에 대입 불가. 컴파일에서 막는다 | List와 같다 |
| 기본형 | `int[]` 가능 | `List<int>` 불가(`List<Integer>`) | `Arrays.asList(int[])`는 `List<int[]>`, 원소 1개 |

함정: 배열을 List로 바꿀 때 `Arrays.asList`를 그대로 쓰면 두 가지가 터진다. ① 나중에 `add`하면 예외가 난다. ② 그 List를 고치면 레거시가 들고 있는 배열까지 바뀐다. 그래서 `new ArrayList<>(Arrays.asList(배열))`로 한 번 더 복사한다. `int[]`는 `Arrays.stream(values).boxed()`로 옮긴다.

과제: `GradeLists.toModifiableList(String[])`과 `GradeLists.toIntegerList(int[])`를 채운다.

확인 테스트 — `J11TypeCutTest`:

- `배열은_길이가_고정이고_List는_늘어난다`
- `함정_Arrays_asList는_크기가_고정이고_원본_배열과_연결돼_있다`
- `배열은_공변이라_잘못된_원소가_실행_중에야_터진다`
- `함정_int_배열을_Arrays_asList에_넣으면_원소가_하나다`

```java
// PointTable
public static List<String> describeAll(LegacyPointCalculator calculator, int[] amounts, String[] grades) {
    List<String> lines = new ArrayList<>();
    for (int amount : amounts) {
        for (String grade : grades) {
            for (boolean couponUsed : new boolean[] {false, true}) {
                int point = calculator.calculate(amount, grade, couponUsed);
                // 문자열 + 결합은 null을 "null"로 적는다
                lines.add(grade + "/" + amount + "/" + (couponUsed ? "쿠폰" : "-") + "=" + point);
            }
        }
    }
    return lines;
}
```

```java
// GradeLists
public static List<String> toModifiableList(String[] names) {
    // Arrays.asList는 배열 위에 씌운 고정 크기 뷰다. ArrayList로 한 번 더 복사해 배열과 연결을 끊는다
    return new ArrayList<>(Arrays.asList(names));
}

public static List<Integer> toIntegerList(int[] values) {
    // Arrays.asList(int[])는 List<int[]>(원소 1개)가 된다. 기본형 배열은 stream으로 하나씩 박싱한다
    return Arrays.stream(values).boxed().toList();
}
```

왜 이렇게 쓰나:

1. 분기마다 경계 양쪽(`49999`/`50000`, `999`/`1000`)과 이상한 규칙(VIP 보너스 없음, 소문자 등급, 내림)을 하나씩 고정해야 변형이 잡힌다. 변형 3개는 각각 다른 테스트가 잡는다. `>=`→`>`는 50000 경계가, VIP 예외 삭제는 VIP 50000이, 내림→반올림은 홀수 포인트에 쿠폰을 쓴 경우가 잡는다.
2. 조합 표(골든 마스터)는 빠뜨린 분기를 메워 준다. 하지만 어떤 규칙이 깨졌는지 이름으로 알려 주지는 못한다. 그래서 이름 붙인 경계 테스트와 같이 둔다.
3. 레거시가 돌려준 배열은 들고 있지 말고 내 List로 복사한다. 그래야 레거시 쪽 배열과 내 List가 서로를 바꾸지 않는다.
