#상황

D03은 회원·인증을 만드는 날이다. ② Member 엔티티에 Role enum을 붙이고, ④ JWT를 검증해 토큰 속 "role" 문자열을 다시 Role로 바꾸며, 인증된 요청의 주체를 값 객체로 넘긴다. D05에서는 이 역할로 "작성자 본인이나 관리자만 삭제"를 판정한다. 오늘은 Spring 없이 Role enum과 권한 판정 메서드를 가진 불변 객체 AuthMember를 만든다. HashSet에 넣었을 때 같은 회원으로 찾아지려면 equals와 hashCode를 함께 고쳐야 한다는 것도 확인한다.

#빠른 연상

문자열 상수 "ADMIN" enum Role TS로 치면
오타 실행해야 안다 컴파일이 막는다 string / 문자열 리터럴 유니온 'USER' | 'ADMIN'
값마다 데이터·메서드 못 붙인다 필드·생성자·메서드를 붙인다(label()) enum + 별도 객체
비교 equals 상수가 하나씩이라 ==도 안전 ===
문자열 ↔ 값 그대로 role.name() / Role.valueOf("ADMIN")
equals만 고침 equals + hashCode 함께 고침
a.equals(b)는 true 같다
HashSet·HashMap이 hashCode로 칸을 먼저 고르므로 다른 칸을 뒤져 못 찾는다 같은 칸에서 찾는다

흔한 착각: "equals를 고쳤으니 컬렉션에서도 같은 객체로 본다". 해시 컬렉션은 hashCode가 같은 것끼리만 equals를 부른다. 그래서 규칙은 "equals가 true면 hashCode도 같아야 한다"이다. record는 둘을 모든 필드로 함께 만들어 준다(J01).

규칙:

  • Role.from(value): 앞뒤 공백과 대소문자를 무시한다(" admin " → ADMIN). null·공백·없는 이름이면 IllegalArgumentException이고, 메시지에 허용 값(USER, ADMIN)을 모두 적는다.
  • AuthMember는 불변이다. 필드는 private final, 역할을 바꾸면 새 객체를 돌려준다(withRole). canModify(writerId)는 본인이거나 관리자면 true다.
  • id와 role이 같으면 equals가 true이고 hashCode도 같다.

#타입 한 컷

오토박싱·언박싱 NPE(Long → long). Long에 null이 들어 있는데 long으로 받으면, 컴파일러가 몰래 넣은 .longValue() 호출에서 NPE가 난다. 장애가 자주 나는 세 자리를 직접 터뜨린다.

자리 null이 오는 이유 터지는 코드 처리
① 합계 조회 행이 없으면 SQL SUM은 0이 아니라 NULL long sum = mapper.sumByMember(id); (매퍼·저장소 메서드가 돌려준 Long을 long 변수로 받음) Long으로 받아 null이면 0
② 캐시 조회 Map.get은 키가 없으면 null long cached = cache.get(id); null이면 0 (J05에서 getOrDefault)
③ 저장 직후 id 저장 전 엔티티의 Long id는 null long id = entry.getId(); null이면 원인을 적은 IllegalStateException

①의 MyBatis 쪽 주의: 별칭 resultType="long"은 java.lang.Long이라(기본형은 _long) null을 그대로 담는다. NPE는 그 Long을 호출부에서 long 변수로 받을 때 난다. 매퍼 메서드의 반환 타입 자체를 기본형 long으로 선언하면 NPE가 아니라 MyBatis가 BindingException("attempted to return null from a method with a primitive return type")을 던진다. 어느 쪽이든 반환 타입을 Long(또는 Optional<Long>)으로 두고 null을 처리한다.

함정: 세 코드 모두 컴파일은 된다. 값이 있는 회원으로만 테스트하면 통과하고, 이력이 없는 신규 회원이 처음 조회할 때 터진다.

과제: PointLookup의 세 메서드를 채운다. 값은 Long으로 먼저 받고 null을 처리한 뒤 long으로 돌려준다.

확인 테스트 — J03TypeCutTest:

  • 함정1_이력이_없는_회원의_합계를_long으로_받으면_NPE다
  • 함정2_캐시에_없는_회원을_long으로_꺼내면_NPE다
  • 함정3_저장_전_엔티티의_id를_long으로_받으면_NPE다_원인을_알리는_예외로_바꾼다
  • 값이_있으면_그대로_돌려준다

#실무 습관

null 다루는 습관 세 가지.

습관 하는 일 안 하면
Objects.requireNonNull(x, "x") 받는 순간 null을 거절하고, 메시지로 어느 인자인지 알려 준다 한참 뒤 다른 메서드에서 이유 모를 NPE
Objects.equals(a, b) 둘 중 하나가 null이어도 예외 없이 비교한다(둘 다 null이면 true) a.equals(b)는 a가 null이면 NPE
컬렉션은 null 대신 빈 리스트 호출하는 쪽이 null 검사 없이 for를 돈다 결과가 없을 때만 호출부가 NPE로 터진다

주어진 LeakyMemberDirectory는 찾는 회원이 없으면 null을 돌려주고, 닉네임을 row.nickname().equals(...)로 비교한다. 닉네임이 null인 옛 회원에서 터진다.

과제: MemberDirectory를 채워 세 습관을 모두 쓴다. AuthMember 생성자도 requireNonNull(role, "role")로 역할을 검사한다.

테스트 — J03HabitTest:

  • 없는_역할을_찾으면_null이_아니라_빈_리스트를_돌려준다
  • 닉네임이_null인_회원도_Objects_equals로_비교하면_NPE가_없다
  • 생성자에_null_목록을_넘기면_만들_때_바로_어느_인자인지_알려_준다
  • AuthMember에_역할_null을_넘기면_권한_판정이_아니라_만들_때_터진다
  • 받은_목록을_밖에서_바꿔도_디렉터리는_그대로다

#정답

펼치기 
// Role
public static Role from(String value) {
    if (value != null) {
        String name = value.strip().toUpperCase(Locale.ROOT);
        for (Role role : values()) {
            if (role.name().equals(name)) {
                return role;
            }
        }
    }
    // valueOf는 null이면 NPE, 없는 이름이면 허용 값을 알려 주지 않는 IAE를 던진다
    throw new IllegalArgumentException("역할은 " + Arrays.toString(values()) + " 중 하나여야 합니다: " + value);
}
// AuthMember
public AuthMember(long id, Role role) {
    this.id = id;
    // 나중에 canModify에서 터지지 않고, 잘못 만든 그 자리에서 터지게 한다
    this.role = Objects.requireNonNull(role, "role");
}

public boolean canModify(long writerId) {
    // enum은 상수가 하나씩이라 ==로 비교한다
    return role == Role.ADMIN || id == writerId;
}

public AuthMember withRole(Role newRole) {
    return new AuthMember(id, newRole);
}

@Override
public boolean equals(Object o) {
    if (this == o) {
        return true;
    }
    if (!(o instanceof AuthMember other)) {
        return false;
    }
    return id == other.id && role == other.role;
}

@Override
public int hashCode() {
    // equals에 쓴 필드를 그대로 쓴다. 같은 객체(equals true)는 반드시 hashCode가 같아야 한다
    return Objects.hash(id, role);
}
// MemberBasics
public static Map<Role, Integer> countByRole(List<MemberRow> rows) {
    // EnumMap은 enum 키 전용 Map이다. 키가 선언 순서(USER, ADMIN)로 정렬된다
    Map<Role, Integer> counts = new EnumMap<>(Role.class);
    for (Role role : Role.values()) {
        counts.put(role, 0);
    }
    for (MemberRow row : rows) {
        counts.put(row.role(), counts.get(row.role()) + 1);
    }
    return counts;
}

public static String requireNickname(String nickname) {
    if (nickname == null || nickname.isBlank()) {
        throw new IllegalArgumentException("닉네임이 비었습니다");
    }
    return nickname.strip();
}
// PointLookup
public long totalPoints(long memberId) {
    // long으로 바로 받으면 언박싱 순간 NPE. Long으로 받아 null을 먼저 본다
    Long sum = mapper.sumByMember(memberId);
    return sum == null ? 0L : sum;
}

public long cachedBalance(long memberId) {
    Long cached = balanceCache.get(memberId);
    return cached == null ? 0L : cached;
}

public long savedIdOf(PointEntry entry) {
    Long id = entry.getId();
    if (id == null) {
        throw new IllegalStateException("저장 전 엔티티라 id가 없습니다");
    }
    return id;
}
// MemberDirectory
private final List<MemberRow> rows;

public MemberDirectory(List<MemberRow> rows) {
    this.rows = List.copyOf(Objects.requireNonNull(rows, "rows"));
}

public List<String> nicknamesOf(Role role) {
    List<String> result = new ArrayList<>();
    for (MemberRow row : rows) {
        if (row.role() == role) {
            result.add(row.nickname());
        }
    }
    // 비어 있어도 그대로 돌려준다. 호출하는 쪽은 null 검사 없이 for를 돌 수 있다
    return result;
}

public boolean hasNickname(long id, String nickname) {
    for (MemberRow row : rows) {
        if (row.id() == id) {
            // a.equals(b)는 a가 null이면 NPE. Objects.equals는 둘 다 null이면 true, 하나만 null이면 false
            return Objects.equals(row.nickname(), nickname);
        }
    }
    return false;
}

왜 이렇게 쓰나:

  1. 밖에서 온 문자열은 valueOf에 바로 넘기지 않고 from 하나를 거치게 한다. 공백·대소문자를 정리하고, 실패하면 허용 값을 알려 주는 예외 하나로 모은다.
  2. 권한을 판정하는 값 객체는 불변으로 만든다. 한 요청 안에서 여러 곳이 같은 AuthMember를 넘겨받아도 누가 역할을 바꿀 수 없다. 해시 컬렉션의 키로 쓸 것이므로 equals와 hashCode는 같은 필드로 함께 만든다.
  3. null은 들어오는 곳에서 막고(requireNonNull), 비교는 Objects.equals로 하고, 나가는 컬렉션은 빈 리스트로 돌려준다. Long → long처럼 null이 기본형으로 바뀌는 자리는 래퍼로 먼저 받아 처리한다.
