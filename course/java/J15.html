#만들 것

"처음부터"가 과제지만 테스트가 컴파일되려면 공개 시그니처는 있어야 한다. 그래서 뼈대에는 클래스·생성자·공개 메서드 시그니처만 있고, 필드와 본문, 도우미 메서드는 모두 직접 설계한다.

규칙(금액은 모두 원 단위 long):

  • DiscountPolicy.discountOf(price)는 0 이상 price 이하의 할인액을 돌려준다. 쿠폰 조건에 맞지 않으면 InvalidCouponException을 던진다.
  • FixedAmountDiscount(amount, minOrderPrice): amount원을 빼되 가격까지만 뺀다. 가격이 minOrderPrice보다 작으면 쓸 수 없다. amount < 1이거나 minOrderPrice < 0이면 생성자가 IllegalArgumentException을 던진다.
  • RateDiscount(percent, maxDiscount): price × percent / 100을 빼되 원 단위 아래는 버리고(9,999원의 10% = 999원) maxDiscount를 넘지 않는다. Long.MAX_VALUE 같은 아주 큰 price에서도 계산 중간에 long이 넘치면 안 된다(그대로 곱하면 할인액이 -1이 된다). J04처럼 long으로 곱하는 것만으로는 부족하다. price가 이미 long이라 price * percent 자체가 넘친다. 힌트: 100으로 나눈 몫과 나머지로 나눠 price / 100 * percent + price % 100 * percent / 100처럼 계산하면 두 항 모두 넘치지 않고 내림 결과도 같다. BigInteger로 곱한 뒤 long으로 돌려도 된다. percent가 1~100이 아니거나 maxDiscount < 1이면 IllegalArgumentException.
  • CouponBook<P>: 같은 코드를 두 번 등록하면 IllegalArgumentException. 없는 코드는 빈 Optional.
  • DiscountCalculator.priceAfterDiscount(order): 쿠폰이 null이면 가격 그대로. 가격이 음수면 IllegalArgumentException, 없는 쿠폰이면 InvalidCouponException.

#상황

D15는 설명 세션 날이다. D15 ①에서 말하기 카드 10문항을 원인부터 설명하고, D15 ②에서 "내가 겪은 문제 5개"를 쓴다. 코드를 새로 쓰는 단계는 없다. 그래서 Java 트랙의 마지막 날은 지금까지 쓴 도구를 한 과제에 모은다. D07 상점의 쿠폰 할인(total - total * 10 / 100)을 정액·정률 두 정책으로 넓힌다. 인터페이스로 정책을 나누고, 제네릭 쿠폰북에 담고, stream으로 합계를 내고, 실패한 주문은 예외 하나로 모은다. 시간이 남으면 J1~J14 타입 한 컷을 퀴즈 8문항으로 다시 푼다(선택 과제).

#빠른 연상

흔한 착각: "RateDiscount가 DiscountPolicy니까 CouponBook<RateDiscount>도 CouponBook<DiscountPolicy>다". 제네릭은 공변이 아니다. CouponBook<DiscountPolicy>만 받는 메서드에는 CouponBook<RateDiscount>를 넘길 수 없다. 읽기만 한다면 CouponBook<? extends DiscountPolicy>로 받는다. 꺼낸 값은 DiscountPolicy로 읽을 수 있고, 대신 아무것도 넣을 수 없다.

#구현 예시

펼치기▸

왜 이렇게 쓰나:

  1. 할인 규칙이 바뀌는 자리를 DiscountPolicy 하나로 모으면 계산기는 "정책을 찾아 discountOf를 부른다"만 알면 된다. 새 쿠폰 종류는 구현 클래스를 하나 더 만드는 것으로 끝나고, if (type == RATE) 분기가 계산기에 쌓이지 않는다.
  2. 잘못된 쿠폰은 생성자에서 거절하므로(percent 0, 101) 만들어진 정책은 언제나 규칙을 지킨다. 계산 중 실패(최소 주문 금액 미달, 없는 쿠폰)는 사유를 담은 예외로 알리고, 목록 계산은 실패를 모두 모아 한 번에 돌려준다.
  3. 쿠폰북은 P extends DiscountPolicy로 "무엇을 담는가"를 타입으로 정하고, 계산기는 읽기만 하므로 ? extends DiscountPolicy로 받는다. 금액은 원 단위 long과 정수 나눗셈(내림)으로 계산해 double 오차가 들어올 틈을 없앤다.
