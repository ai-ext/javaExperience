# J38. 프로세스 경계와 캐시

> 소요 20~40분 · D38 연결 실험 · 기존 J 재사용과 새 경계 관찰을 구분한다.

## 만들 파일과 실행 위치

**내 프로젝트 루트**에서 진행한다. D38의 통합 관찰·테스트와 같은 증거를 사용한다. 실제 사용한 테스트 클래스 또는 요청/SQL 스크립트 경로·실행 명령·시각·예상/실제 결과를 기록한다. 별도 J38EvidenceTest.java를 만들 필요가 없다.

## 오늘 실험

단일 프로세스 공유 상태와 두 프로세스 캐시의 차이를 테스트로 표현하고 시간 상한을 명시한다.

J07은 프로세스 내부 공유 상태, J09는 Clock만 지원한다. 두 앱 캐시는 D38 통합 관찰에서 별도 PID·같은 DB/캐시·동일 요청 구간으로 측정한다. 단일 JVM 테스트만으로 두 앱의 재적재 횟수를 주장하지 않는다.

## 실행과 완료 조건

- 테스트를 사용했다면 `./gradlew test --tests <실제클래스명>`으로 재실행한다. 요청·SQL 관찰이면 해당 일자의 실제 명령과 출력을 보존한다.
- 단일 프로세스 공유 상태와 두 프로세스 캐시의 차이를 테스트로 표현하고 시간 상한을 명시한다.
- 선택한 경계의 기대값과 실제 출력·실행 명령을 남긴다. 단순 설명만으로 완료하지 않는다.

통합 관찰은 disposable DB/별도 JVM에서 실행한다. 실행 불가는 이유와 함께 확인 불가로 기록한다. 성공/실패·예상/실측을 나눈다.
