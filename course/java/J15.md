# J15. 종합: 쿠폰 할인 계산기 처음부터 만들기

> 같은 날: D15 · 소요 45~60분(선택 퀴즈 +15~25분) · 실행 `./gradlew :java-track:test --tests 'J15*'`

## 상황

D15는 설명 세션 날이다. D15 ①에서 말하기 카드 10문항을 원인부터 설명하고, D15 ②에서 "내가 겪은 문제 5개"를 쓴다. 코드를 새로 쓰는 단계는 없다.
그래서 Java 트랙의 마지막 날은 지금까지 쓴 도구를 한 과제에 모은다. D07 상점의 쿠폰 할인(`total - total * 10 / 100`)을 정액·정률 두 정책으로 넓힌다. 인터페이스로 정책을 나누고, 제네릭 쿠폰북에 담고, stream으로 합계를 내고, 실패한 주문은 예외 하나로 모은다. 시간이 남으면 J1~J14 타입 한 컷을 퀴즈 8문항으로 다시 푼다(선택 과제).

## 빠른 연상

```
            DiscountPolicy (인터페이스)        ← J04 선언 타입과 실제 타입
             ▲                 ▲
   FixedAmountDiscount    RateDiscount          ← J01 생성자에서 잘못된 값 거절
             │                 │
   CouponBook<P extends DiscountPolicy>         ← J06 제네릭·와일드카드, J06 Optional
             │
   DiscountCalculator(CouponBook<? extends DiscountPolicy>)
     ├ priceAfterDiscount(order)                ← J08 예외
     └ summarize(orders) → OrderSummary         ← J05 stream·mapToLong, J08 실패를 모아 예외로
```

흔한 착각: "`RateDiscount`가 `DiscountPolicy`니까 `CouponBook<RateDiscount>`도 `CouponBook<DiscountPolicy>`다". 제네릭은 공변이 아니다. `CouponBook<DiscountPolicy>`만 받는 메서드에는 `CouponBook<RateDiscount>`를 넘길 수 없다. 읽기만 한다면 `CouponBook<? extends DiscountPolicy>`로 받는다. 꺼낸 값은 `DiscountPolicy`로 읽을 수 있고, 대신 아무것도 넣을 수 없다.

규칙(금액은 모두 원 단위 `long`):

- `DiscountPolicy.discountOf(price)`는 0 이상 price 이하의 할인액을 돌려준다. 쿠폰 조건에 맞지 않으면 `InvalidCouponException`을 던진다.
- `FixedAmountDiscount(amount, minOrderPrice)`: amount원을 빼되 가격까지만 뺀다. 가격이 `minOrderPrice`보다 작으면 쓸 수 없다. `amount < 1`이거나 `minOrderPrice < 0`이면 생성자가 `IllegalArgumentException`을 던진다.
- `RateDiscount(percent, maxDiscount)`: price × percent / 100을 빼되 원 단위 아래는 버리고(9,999원의 10% = 999원) `maxDiscount`를 넘지 않는다. `Long.MAX_VALUE` 같은 아주 큰 price에서도 계산 중간에 `long`이 넘치면 안 된다(그대로 곱하면 할인액이 -1이 된다). J04처럼 `long`으로 곱하는 것만으로는 부족하다. price가 이미 `long`이라 `price * percent` 자체가 넘친다. 힌트: 100으로 나눈 몫과 나머지로 나눠 `price / 100 * percent + price % 100 * percent / 100`처럼 계산하면 두 항 모두 넘치지 않고 내림 결과도 같다. `BigInteger`로 곱한 뒤 `long`으로 돌려도 된다. percent가 1~100이 아니거나 `maxDiscount < 1`이면 `IllegalArgumentException`.
- `CouponBook<P>`: 같은 코드를 두 번 등록하면 `IllegalArgumentException`. 없는 코드는 빈 `Optional`.
- `DiscountCalculator.priceAfterDiscount(order)`: 쿠폰이 null이면 가격 그대로. 가격이 음수면 `IllegalArgumentException`, 없는 쿠폰이면 `InvalidCouponException`.

## 기본기 반복

주문 목록의 할인 전·후 합계를 stream(`mapToLong(…).sum()`)으로 계산한다. 계산에 실패한 주문이 있으면 합계 대신 **실패한 주문을 모두** 모아 `OrderCalculationException` 하나로 던진다. J08에서 충전 요청에 한 일을 주문에 다시 한다.

```java
/** 실패(InvalidCouponException·IllegalArgumentException)를 모두 모아 던지고, 없으면 stream으로 합계. 사유는 예외 메시지. */
public OrderSummary summarize(List<Order> orders)
```

테스트 — `J15BasicsTest`:

- `할인_전후_합계를_계산한다`
- `빈_목록이면_합계는_모두_0이다`
- `실패한_주문을_첫_실패에서_멈추지_않고_모두_모아_한_번에_던진다` (최소 주문 금액 미달·없는 쿠폰·음수 가격)

정리 퀴즈(선택 과제): J1~J14 타입 한 컷에서 고른 8문항. 기본 완료 조건에는 들어가지 않는다. 주제 과제와 기본기 반복을 끝내고 시간이 남으면 푼다. 테스트마다 함정이 어떻게 터지는지 먼저 보여 주고, `TypeQuiz`의 내 답을 확인한다.

| 문항 | 어디서 | 함정 | 답의 열쇠 |
|---|---|---|---|
| 1 `sizeOrDefault` | J01 `int` vs `Integer` | 보내지 않은 값은 null, 0은 보낸 값 | null 먼저 처리 |
| 2 `balanceOrZero` | J03 언박싱 NPE | `long b = map.get(k)`에서 NPE | `getOrDefault` |
| 3 `sameId` | J04 `==` vs `equals` | `Long` 127까지는 같은 객체임이 보장돼 `==`도 맞아 보인다. 그 밖은 보장이 없다 | `Objects.equals` |

```java
// FixedAmountDiscount
private final long amount;
private final long minOrderPrice;

public FixedAmountDiscount(long amount, long minOrderPrice) {
    if (amount < 1 || minOrderPrice < 0) {
        throw new IllegalArgumentException("정액 할인 값이 잘못됐습니다: amount=" + amount + ", minOrderPrice=" + minOrderPrice);
    }
    this.amount = amount;
    this.minOrderPrice = minOrderPrice;
}

@Override
public long discountOf(long price) {
    if (price < minOrderPrice) {
        throw new InvalidCouponException("최소 주문 금액 " + minOrderPrice + "원 미만입니다: " + price);
    }
    // 할인 뒤 가격이 음수가 되지 않게 가격까지만 뺀다
    return Math.min(amount, price);
}
```

```java
// RateDiscount (생성자는 같은 모양으로 percent 1~100, maxDiscount >= 1 검사)
@Override
public long discountOf(long price) {
    // price × percent를 먼저 곱하면 아주 큰 price에서 long이 넘친다. 100으로 나눈 몫과 나머지로 나눠 계산한다:
    // price × percent / 100 = (price / 100) × percent + (price % 100) × percent / 100
    // 앞 항은 price 이하라 넘치지 않고, 뒤 항은 99 × 100 이하다. 정수 나눗셈이라 원 단위 아래는 버린다(9,999 → 999)
    long discount = price / 100 * percent + price % 100 * percent / 100;
    return Math.min(discount, maxDiscount);
}
```

```java
// CouponBook
private final Map<String, P> policies = new HashMap<>();

public void register(String code, P policy) {
    // putIfAbsent는 이미 있으면 기존 값을 돌려주고 바꾸지 않는다
    if (policies.putIfAbsent(code, policy) != null) {
        throw new IllegalArgumentException("이미 등록된 쿠폰 코드입니다: " + code);
    }
}

public Optional<P> find(String code) {
    return Optional.ofNullable(policies.get(code));
}
```

```java
// DiscountCalculator
private final CouponBook<? extends DiscountPolicy> book;

public DiscountCalculator(CouponBook<? extends DiscountPolicy> book) {
    this.book = book;
}

public long priceAfterDiscount(Order order) {
    if (order.price() < 0) {
        throw new IllegalArgumentException("가격은 0 이상이어야 합니다: " + order.price());
    }
    if (order.couponCode() == null) {
        return order.price();
    }
    // ? extends DiscountPolicy에서 꺼낸 값은 DiscountPolicy로 읽을 수 있다
    DiscountPolicy policy = book.find(order.couponCode())
            .orElseThrow(() -> new InvalidCouponException("없는 쿠폰입니다: " + order.couponCode()));
    return order.price() - policy.discountOf(order.price());
}

public OrderSummary summarize(List<Order> orders) {
    List<OrderFailure> failures = new ArrayList<>();
    for (Order order : orders) {
        try {
            priceAfterDiscount(order);
        } catch (InvalidCouponException | IllegalArgumentException e) {
            failures.add(new OrderFailure(order.orderId(), e.getMessage()));
        }
    }
    if (!failures.isEmpty()) {
        throw new OrderCalculationException(failures);
    }
    long before = orders.stream().mapToLong(Order::price).sum();
    long after = orders.stream().mapToLong(this::priceAfterDiscount).sum();
    return new OrderSummary(before, after);
}
```

```java
// TypeQuiz (선택 과제)
public static int sizeOrDefault(Integer size) {
    return size == null ? 20 : size;
}

public static long balanceOrZero(Map<Long, Long> balances, Long memberId) {
    // get은 없으면 null을 돌려준다. long에 바로 담으면 언박싱 NPE
    return balances.getOrDefault(memberId, 0L);
}

public static boolean sameId(Long a, Long b) {
    return Objects.equals(a, b);
}

public static long total(List<Integer> prices) {
    return prices.stream().mapToLong(Integer::longValue).sum();
}

public static String nicknameOrLoad(Optional<String> cached, Supplier<String> loader) {
    return cached.orElseGet(loader);
}

public static LocalDate kstDate(Instant instant) {
    return instant.atZone(ZoneId.of("Asia/Seoul")).toLocalDate();
}

public static List<String> growableList(String[] tags) {
    // Arrays.asList는 배열을 감싼 고정 크기 뷰다. 새 ArrayList로 복사해 연결을 끊는다
    return new ArrayList<>(Arrays.asList(tags));
}

public static BigDecimal sumExactly(List<String> amounts) {
    // new BigDecimal(0.1)처럼 double에서 만들면 이미 오차가 들어간다. 문자열에서 만든다
    return amounts.stream().map(BigDecimal::new).reduce(BigDecimal.ZERO, BigDecimal::add);
}
```

왜 이렇게 쓰나:

1. 할인 규칙이 바뀌는 자리를 `DiscountPolicy` 하나로 모으면 계산기는 "정책을 찾아 `discountOf`를 부른다"만 알면 된다. 새 쿠폰 종류는 구현 클래스를 하나 더 만드는 것으로 끝나고, `if (type == RATE)` 분기가 계산기에 쌓이지 않는다.
2. 잘못된 쿠폰은 생성자에서 거절하므로(`percent` 0, 101) 만들어진 정책은 언제나 규칙을 지킨다. 계산 중 실패(최소 주문 금액 미달, 없는 쿠폰)는 사유를 담은 예외로 알리고, 목록 계산은 실패를 모두 모아 한 번에 돌려준다.
3. 쿠폰북은 `P extends DiscountPolicy`로 "무엇을 담는가"를 타입으로 정하고, 계산기는 읽기만 하므로 `? extends DiscountPolicy`로 받는다. 금액은 원 단위 `long`과 정수 나눗셈(내림)으로 계산해 `double` 오차가 들어올 틈을 없앤다.

</details>
