#만들 파일과 실행 위치

내 프로젝트 루트에서 진행한다. D22의 통합 관찰·테스트와 같은 증거를 사용한다. 실제 사용한 테스트 클래스 또는 요청/SQL 스크립트 경로·실행 명령·시각·예상/실제 결과를 기록한다. 별도 J22EvidenceTest.java를 만들 필요가 없다.

#오늘 실험

같은 EntityManager 재조회와 clear 뒤 재조회를 구분하고 RC/RR의 새 트랜잭션 관찰을 기록한다.

J10은 프록시·트랜잭션 경계 기초만 지원한다. EntityManager 1차 캐시와 RC/RR은 D22 통합 실험에서 검증한다. 같은 객체 재조회·clear 후 재조회·새 트랜잭션을 나누고 각 연결의 격리 수준과 commit 시각을 기록한다. J05 컬렉션 실습을 격리 수준 근거로 쓰지 않는다.

✓ 확인끝났는지 판단

#실행과 완료 조건

  • 테스트를 사용했다면 ./gradlew test --tests <실제클래스명>으로 재실행한다. 요청·SQL 관찰이면 해당 일자의 실제 명령과 출력을 보존한다.
  • 같은 EntityManager 재조회와 clear 뒤 재조회를 구분하고 RC/RR의 새 트랜잭션 관찰을 기록한다.
  • 선택한 경계의 기대값과 실제 출력·실행 명령을 남긴다. 단순 설명만으로 완료하지 않는다.

통합 관찰은 disposable DB/별도 JVM에서 실행한다. 실행 불가는 이유와 함께 확인 불가로 기록한다. 성공/실패·예상/실측을 나눈다.
