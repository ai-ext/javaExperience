# J39. JVM·CPU·대기·힙 관찰

> 소요 20~40분 · D39 연결 실험 · 기존 J 재사용과 새 경계 관찰을 구분한다.

## 만들 파일과 실행 위치

**내 프로젝트 루트**에서 진행한다. 운영 실습 출발 자료 D39의 JvmSignals.java·별도 JVM으로 관찰한다. PID·jcmd·ps·힙 출력과 시각을 제출하며 JUnit 파일은 필수가 아니다.

## 오늘 실험

제한된 Xmx의 별도 JVM에서 CPU 작업·외부 대기·보유 객체 증가를 각각 실행하고 jcmd 증거를 수집한다.

J07/J08은 스레드와 예외의 선수 지식일 뿐 JVM 진단 도구 설명은 아니다. 운영 실습 출발 자료 D39의 JvmSignals.java로 CPU·외부 HTTP 대기·힙 보유를 별도 JVM에서 만든다. -Xmx64m과 jcmd -l로 JVM을 식별하고 jcmd PID Thread.print·GC.heap_info·GC.class_histogram을 수집한다. ps의 CPU와 같은 시각에 대조한다. RUNNABLE 하나나 heap 증가만으로 병목/누수를 단정하지 않는다.

## 실행과 완료 조건

- [운영 실습 D39](../start/ops/README.md#d39-jvm-pidcpu외부-대기힙)의 공통 JDK 준비와 javac·java·jcmd 명령을 사용한다.
- 제한된 Xmx의 별도 JVM에서 CPU 작업·외부 대기·보유 객체 증가를 각각 실행하고 jcmd 증거를 수집한다.
- 선택한 경계의 기대값과 실제 출력·실행 명령을 남긴다. 단순 설명만으로 완료하지 않는다.

통합 관찰은 disposable DB/별도 JVM에서 실행한다. 실행 불가는 이유와 함께 확인 불가로 기록한다. 성공/실패·예상/실측을 나눈다.
