# J19. ThreadLocal과 문맥 정리

> 소요 20~40분 · D19 연결 실험 · 기존 J 재사용과 새 경계 관찰을 구분한다.

## 만들 파일과 실행 위치

**내 프로젝트 루트**에서 `src/test/java/J19EvidenceTest.java`를 만든다. 기존 테스트로 동일 증거가 있으면 재실행·조건을 기록하고 재사용한다. java-track에 존재하지 않는 J16 이후 테스트가 있다고 가정하지 않는다.

## 오늘 실험

Executors.newFixedThreadPool(1)에서 요청 A 성공·실패 뒤 요청 B를 실행한다. ThreadLocal.remove를 finally에 둔 전후 값과 비동기 스레드의 값을 비교한다.

ThreadLocal은 객체별이 아니라 현재 스레드별 값을 보관한다. 풀은 같은 스레드를 다음 요청에 재사용하므로 A의 값이 B에 남을 수 있다. remove는 현재 스레드 값만 지운다. J07은 공유 상태와 동시 실행의 기초이고 이 문맥 생명주기 자체는 새 실험이다.

`Executors.newFixedThreadPool(1)`에 A를 submit하여 `set("A")` 후 성공 또는 예외로 끝내고 Future.get(2, TimeUnit.SECONDS)로 종료를 기다린다. 그 뒤 B를 submit해 get()을 수집한다. 누출 관찰용 사본과 `try/finally { context.remove(); }` 사본을 분리한다. B의 예상값은 각각 A/null이며 실제 출력을 비교한다.

부모 스레드의 set 후 풀에서 submit한 작업의 get을 관찰한다. 일반 ThreadLocal은 부모 값을 자동 전달하지 않는다. 필요한 식별값만 명시적 인자로 전달하고 작업 내부에서 set/remove한다. 인증 객체 전체를 복제하지 않는다. finally에서 latch 해제·shutdownNow·awaitTermination(2초)을 실행하여 실패 경로도 정리한다.

## 실행과 완료 조건

- `./gradlew test --tests 'J19EvidenceTest'` (직접 이 이름으로 만든 테스트). 기존 테스트를 재사용하면 실제 클래스 이름으로 실행한다.
- Executors.newFixedThreadPool(1)에서 요청 A 성공·실패 뒤 요청 B를 실행한다. ThreadLocal.remove를 finally에 둔 전후 값과 비동기 스레드의 값을 비교한다.
- 선택한 경계의 기대값과 실제 출력·실행 명령을 남긴다. 단순 설명만으로 완료하지 않는다.

통합 관찰은 disposable DB/별도 JVM에서 실행한다. 실행 불가는 이유와 함께 확인 불가로 기록한다. 성공/실패·예상/실측을 나눈다.
