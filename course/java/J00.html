#상황

D1부터는 Spring 코드 안에서 메서드를 만들고, 필드를 선언하고, List<Post>를 돌며 DTO로 바꾸는 일이 매일 나온다. D04에서 글을 저장할 때는 태그 목록을 for로 돌고, 응답을 만들 때는 같은 일을 stream으로 한다. 그 전에 Spring 없이 순수 Java로 "메서드에 넘긴 값이 어떻게 복사되는가"와 "for를 stream으로 옮기는 법"을 손에 익혀 둔다. 시간이 없으면 건너뛰고 바로 J01로 간다.

#빠른 연상

넘기는 것 Java에서 복사되는 것 메서드 안에서 바꾸면 호출한 쪽은 JS/TS로 치면
int·long·boolean (기본형) 값 자체 그대로 number를 넘길 때와 같다
객체(Post)의 필드를 바꿈 참조(주소) 같이 바뀐다 (같은 객체를 가리키므로) 객체를 넘겨 obj.count++ 할 때와 같다
매개변수에 새 객체를 대입 참조(주소) 그대로 (매개변수만 새 객체를 가리킨다) 함수 안에서 obj = {...} 할 때와 같다

흔한 착각: "객체는 참조로 넘긴다(call by reference)". Java에는 참조 전달이 없다. 참조값을 복사해서 넘긴다. 그래서 필드를 바꾸면 보이고, 매개변수에 새 객체를 대입하면 보이지 않는다.

for → stream 대응:

for 반복문 stream
if (조건) { … } .filter(post -> 조건)
result.add(post.getTitle()) .map(Post::getTitle)
new ArrayList<>()에 모아 return .toList()

List<Post>는 "Post만 담는 List"라고 읽는다. 꺼낸 값은 캐스팅 없이 바로 Post다. .map(Post::getTitle)을 지나면 Stream<String>이 되고 .toList()의 결과는 List<String>이다.

#기본기 반복

값 전달 테스트 3개. ValuePassing의 세 메서드를 채우고, 테스트가 무엇을 단언하는지 읽은 뒤 결과를 먼저 예상해 본다.

메서드 할 일 테스트
likeInside(int likeCount) 매개변수에 1을 더해 대입하고 그 값을 돌려준다 메서드_안에서_int를_바꿔도_호출한_쪽은_그대로다
likeTwice(Post post) 받은 글의 like()를 두 번 부른다 메서드_안에서_객체_필드를_바꾸면_호출한_쪽도_바뀐다
replaceInside(Post post, String newTitle) 매개변수에 새 Post를 대입하고 그 글을 돌려준다 매개변수에_새_객체를_대입하면_호출한_쪽은_그대로다

#정답

펼치기 
// ValuePassing
public static int likeInside(int likeCount) {
    // 바뀌는 것은 복사된 값(매개변수)뿐이다. 호출한 쪽 변수는 그대로다
    likeCount = likeCount + 1;
    return likeCount;
}

public static void likeTwice(Post post) {
    // 복사된 참조도 같은 객체를 가리키므로 호출한 쪽에서도 바뀐 값이 보인다
    post.like();
    post.like();
}

public static Post replaceInside(Post post, String newTitle) {
    // 매개변수가 새 객체를 가리키게 될 뿐, 호출한 쪽 변수는 여전히 원래 글을 가리킨다
    post = new Post(newTitle, 0);
    return post;
}
// PostBoard
private final List<Post> posts = new ArrayList<>();

public int totalLikes() {
    int total = 0;
    for (int i = 0; i < posts.size(); i++) {
        total += posts.get(i).getLikeCount();
    }
    return total;
}

public List<String> titles() {
    List<String> titles = new ArrayList<>();
    for (Post post : posts) {
        titles.add(post.getTitle());
    }
    return titles;
}
// PostStreams
public static List<String> popularTitles(List<Post> posts, int minLikes) {
    return posts.stream()
            .filter(post -> post.getLikeCount() >= minLikes)
            .map(Post::getTitle)
            .toList();
}

왜 이렇게 쓰나:

  1. 필드는 선언하면서 new ArrayList<>()로 초기화한다. 초기화를 빼면 첫 add에서 NPE가 난다. static을 붙이면 모든 게시판이 목록 하나를 같이 쓴다.
  2. final은 "다른 리스트로 바꿔 끼우지 않는다"는 뜻일 뿐이고, 리스트 안의 내용은 여전히 바뀐다. 안까지 막는 법은 J01 실무 습관에서 다룬다.
  3. 조건으로 거르고 값만 뽑는 반복은 stream으로 쓰면 filter·map이라는 이름이 의도를 말해 준다. 인덱스가 필요하거나 중간에 멈춰야 하면 for가 더 읽기 쉽다.
