# J02. 예외 계층과 제네릭 Result, Lombok이 만드는 코드

> 같은 날: D02 · 소요 45~60분(선택 과제 +20~30분) · 실행 `./gradlew :java-track:test --tests 'J02*'`

## 상황

D02는 공통 기반을 세우는 날이다. ① `ErrorCode`와 `BusinessException`을 만들어 전역 예외 처리기가 코드 하나로 404·409를 내게 하고, ② `BaseEntity`를 만들며, ④ 상태 없는 닉네임 정규화는 static 유틸로 둔다.
오늘은 Spring 없이 예외 계층(`BusinessException` ← `NotFoundException`)과 성공 값·에러 코드를 담는 제네릭 `Result<T>`를 만든다. 엔티티 id가 왜 `Long`인지도 확인한다. D03부터 엔티티에 붙는 Lombok 애노테이션이 실제로 어떤 코드를 만드는지는 표로 읽고, 직접 써 보는 것은 선택 과제(실무 습관 칸)다.

## 빠른 연상

| | static | 인스턴스 | TS로 치면 |
|---|---|---|---|
| 어디에 붙나 | 클래스 하나에 하나 | `new`로 만든 객체마다 | `static` 멤버 / 일반 멤버 |
| 부르는 법 | `Result.success("값")` | `result.isSuccess()` | `Result.success()` / `result.isSuccess()` |
| `this`를 쓸 수 있나 | 없다 | 있다 | 같다 |
| 쓰는 곳 | 객체를 만드는 팩토리, 상태 없는 유틸(`NicknameNormalizer`) | 객체가 가진 값으로 답하는 메서드 | |

| 예외 계층 | 뜻 |
|---|---|
| `RuntimeException` ← `BusinessException` | 언체크 예외. `throws`를 적지 않아도 던질 수 있다 |
| `BusinessException` ← `NotFoundException` | 자식은 부모 생성자(`super(...)`)에 코드와 메시지를 넘긴다. `catch (BusinessException e)`가 자식도 잡는다 |

흔한 착각: "`Result<T>`의 `T`는 실행할 때 정해진다". `T`는 **컴파일할 때** 정해진다. `Result<Integer>`의 `value()`는 컴파일러가 `Integer`로 알고 있어서 형변환 없이 `int`로 쓸 수 있다. 실행 중에는 `T` 정보가 지워진다(`Result<Integer>`와 `Result<String>`이 같은 클래스다).

규칙:

- `BusinessException`은 `RuntimeException`을 상속한다. 메시지(`detail`)는 부모에게 넘기고, `ErrorCode`는 자기 필드에 담는다.
- `NotFoundException(target, id)`의 코드는 언제나 `NOT_FOUND`, 메시지는 `"찾을 수 없습니다: " + target + " id=" + id`다.
- `Result`는 생성자가 private이고 static 팩토리로만 만든다. 성공이면 `errorCode()`·`message()`가 null이고, 실패한 결과에서 `value()`를 꺼내면 `IllegalStateException`이다.

뼈대 발췌:

```java
public class NotFoundException extends BusinessException {

    public NotFoundException(String target, long id) {
        // TODO: 부모 생성자에 알맞은 ErrorCode와 메시지를 넘기세요(super 호출은 생성자의 첫 줄이어야 한다)
        super(null, null);
        throw new UnsupportedOperationException("J02: NotFoundException 생성자 — NOT_FOUND와 메시지를 부모 생성자에 넘기세요");
    }
}

public final class Result<T> {

    // TODO: 성공 값·에러 코드·메시지 필드를 선언하세요(만든 뒤 바뀌지 않게)

    private Result(T value, ErrorCode errorCode, String message) { … }

    /** 성공 결과를 만든다. 인스턴스가 없어도 부를 수 있도록 static이다. */
    public static <T> Result<T> success(T value) { … }

    /** 예외가 가진 에러 코드와 메시지로 실패 결과를 만든다. BusinessException의 자식(NotFoundException 등)도 받는다. */
    public static <T> Result<T> failure(BusinessException e) { … }

    public boolean isSuccess() { … }

    /** 성공 값을 돌려준다. 실패한 결과면 IllegalStateException. */
    public T value() { … }
    // errorCode · message도 같은 모양
}
```

`NotFoundException`의 `super(null, null)`은 컴파일되게 하려고 둔 자리다. `BusinessException`을 먼저 채우고, 이 줄을 알맞은 값으로 바꾼다.

- `NotFoundException은_부모_타입_BusinessException으로_잡힌다`

## 기본기 반복

글 목록의 좋아요 수를 for와 stream 두 가지로 더한다. 쉼표로 이어진 태그 문자열(`" java, spring ,jpa "`)을 `split`으로 나누고 `strip`으로 앞뒤 공백을 지운다. 빈 조각은 버린다.

```java
public static int sumLikesWithFor(List<PostRow> rows)
public static int sumLikesWithStream(List<PostRow> rows)
/** null이거나 공백뿐인 문자열이면 빈 리스트를 돌려준다. */
public static List<String> splitTags(String raw)
```

`trim()`과 `strip()`은 다르다. `trim()`은 코드값이 `' '` 이하인 문자만 지우고, `strip()`은 전각 공백(`　`) 같은 유니코드 공백도 지운다. 한글 입력기에서 들어온 공백은 `strip()`으로 지운다.

테스트 — `J02BasicsTest`:

- `좋아요_합계를_for와_stream으로_구해도_같다`
- `빈_목록의_좋아요_합계는_0이다`
- `쉼표로_나눈_태그의_앞뒤_공백을_지운다`
- `strip은_전각_공백도_지우지만_trim은_못_지운다`
- `빈_조각은_버리고_null이나_공백뿐인_문자열이면_빈_리스트다`

## 타입 한 컷

`long` vs `Long` — 엔티티 id는 왜 `Long`인가.

| | `long` (기본형) | `Long` (래퍼) |
|---|---|---|
| 저장 전 id 값 | `0` (기본값) | `null` |
| "아직 저장 전"을 표현 | 못 한다. 0이 저장 전인지 0번 글인지 모른다 | `id == null`이면 저장 전 |
| JPA(Spring Data)의 신규 판단 | 기본형이면 0을 신규로 본다(규칙을 외워야 한다) | null이면 신규 → INSERT, 아니면 기존 → 병합 |
| 담을 수 있는 곳 | 필드·지역 변수 | 필드·지역 변수·제네릭(`Map<Long, Post>`) |

함정: id를 `long`으로 선언하면(`PrimitiveIdPost`) 저장 전에도 `getId()`가 0이다. "아직 저장 전"이라는 상태를 타입이 표현하지 못한다.

과제: `BaseEntity.isNew()`(id가 null이면 저장 전)와 `PostRepository.save()`를 채운다. 새 글이면 sequence를 1 올려 id로 매기고 추가한다. 이미 id가 있으면 같은 칸을 덮어쓴다(개수가 늘지 않는다). Spring Data JPA의 `save`가 하는 신규·기존 판단과 같다.

확인 테스트 — `J02TypeCutTest`:

- `새로_만든_글은_id가_null이고_새_엔티티다`
- `저장하면_id가_1부터_매겨지고_새_엔티티가_아니게_된다`
- `id가_있는_글을_다시_저장하면_추가하지_않고_덮어쓴다`
- `함정_long_id는_저장_전에도_0이라_저장_전인지_알_수_없다`

## 실무 습관

Lombok이 만드는 코드. 이 모듈은 Lombok을 쓰지 않는다. 대신 애노테이션이 만들어 주는 코드를 손으로 써 본다. **이 칸의 과제는 전부 선택 과제다.** 기본 완료 조건(`--tests 'J02*'` 17개)에는 들어가지 않는다. 아래 표와 `LeakyCoupon` 설명은 D03부터 엔티티를 읽을 때 필요하니 과제를 건너뛰더라도 읽고 간다. 아래 표의 "만들어지는 코드"는 Lombok 1.18.46의 `delombok` 출력에서 `@Generated` 같은 표시만 걷어 낸 것이다.

| 애노테이션 | 만들어지는 코드 | 주의 |
|---|---|---|
| `@Getter` | 필드마다 `public 타입 getX() { return this.x; }` | `boolean` 필드는 `isX()`. 필드 이름이 `isOpen`이면 `isIsOpen`이 아니라 `isOpen()`. `Boolean`(래퍼) 필드는 `getX()` |
| `@RequiredArgsConstructor` | **final이고 선언에서 초기화하지 않은** 필드만 선언 순서대로 받는 public 생성자 | `private final Set<Long> ids = new HashSet<>();`처럼 초기화한 final 필드와 final이 아닌 필드는 받지 않는다(`@NonNull`을 붙인 비-final 필드는 예외로 받는다) |
| `@Builder` (생성자에 붙임) | `public static XBuilder builder()`, 중첩 클래스 `XBuilder`(매개변수마다 같은 이름의 필드와 `this`를 돌려주는 메서드, `build()`) | 빌더에서 넣지 않은 값은 오류 없이 `null`·`0`이 된다. 검사는 생성자에 둔다 |
| `@NoArgsConstructor(access = PROTECTED)` | `protected X() {}` | JPA가 리플렉션으로 쓰는 빈 생성자. 밖에서 `new X()`를 막는다 |
| `@Setter` | 필드마다 `public void setX(타입 x)` | 엔티티 규칙을 거치지 않고 아무 곳에서나 값을 바꾼다 |
| `@AllArgsConstructor` | 모든 필드를 받는 public 생성자 | id·발급 수량처럼 밖에서 정하면 안 되는 값까지 받는다 |

주어진 `LeakyCoupon`은 `@Getter @Setter @NoArgsConstructor @AllArgsConstructor`를 붙인 쿠폰 엔티티를 delombok한 코드다. `new LeakyCoupon(1L, "웰컴 쿠폰", 10, 50)`도, `setIssuedQuantity(999)`도 막지 못해 총량보다 많이 발급된 쿠폰이 생긴다.

과제(선택):

1. `Coupon`을 `@Getter @NoArgsConstructor(access = PROTECTED)` + private 생성자 모양으로 손으로 채운다. 검사는 private 생성자 한 곳에 둔다(이름이 비었거나 총량이 1보다 작으면 `IllegalArgumentException`). 발급 수량은 `issue()`로만 바뀐다(소진이면 `IllegalStateException`). 빌더 테스트 말고는 주어진 같은 패키지 전용 팩토리 `Coupon.create(name, totalQuantity)`로 쿠폰을 만든다(Lombok에는 없는 메서드다. 빌더를 채우지 않아도 1·2를 풀 수 있게 둔 것이다).
2. `CouponIssueService`를 `@RequiredArgsConstructor`가 만들 모양으로 채운다. 쿠폰은 생성자로 받고, 받은 회원 id 집합은 선언에서 바로 만든다. `issue(memberId)`는 1인 1매다.
3. `@Builder`가 private 생성자에 붙었을 때 만들 코드 — `public static CouponBuilder builder()`와 중첩 클래스 `CouponBuilder` — 를 손으로 채운다.

선택 과제 테스트 — `J02HabitTest` (클래스 전체에 `@Tag("optional")`. 기본 실행 `--tests 'J02*'`에는 들어가지 않고 `./gradlew :java-track:optionalTest --tests 'J02*'`로 돌린다):

- `Setter와_전체_생성자가_열린_쿠폰은_총량을_넘는_발급_수량을_막지_못한다_Coupon은_막는다`
- `쿠폰은_이름과_총량을_검사해_만들고_발급_수량은_0에서_시작한다`
- `Coupon에는_public_생성자와_setter가_없다`
- `RequiredArgsConstructor는_선언에서_초기화하지_않은_final_필드만_받는다`
- `한_회원에게는_한_번만_발급한다`
- `선택_빌더는_이름을_붙여_값을_넣고_발급_수량은_0에서_시작한다`
- `선택_빌더에서_총량을_빠뜨리면_0이_들어가_생성자_검사에_걸린다`

private final ErrorCode errorCode;

public BusinessException(ErrorCode errorCode, String detail) {
    // 메시지는 부모(RuntimeException)가 보관한다. super 호출은 생성자의 첫 줄이어야 한다
    super(detail);
    this.errorCode = errorCode;
}

// NotFoundException
public NotFoundException(String target, long id) {
    super(ErrorCode.NOT_FOUND, "찾을 수 없습니다: " + target + " id=" + id);
}

```java
// Result
private final T value;
private final ErrorCode errorCode;
private final String message;

private Result(T value, ErrorCode errorCode, String message) {
    this.value = value;
    this.errorCode = errorCode;
    this.message = message;
}

public static <T> Result<T> success(T value) {
    return new Result<>(value, null, null);
}

public static <T> Result<T> failure(BusinessException e) {
    // 매개변수 타입이 부모라서 자식 예외도 그대로 들어온다. errorCode()는 부모에 정의돼 있다
    return new Result<>(null, e.errorCode(), e.getMessage());
}

public boolean isSuccess() {
    return errorCode == null;
}

public T value() {
    if (!isSuccess()) {
        throw new IllegalStateException("실패한 결과에는 값이 없습니다: " + errorCode);
    }
    return value;
}

// PostBasics
public static int sumLikesWithFor(List<PostRow> rows) {
    int sum = 0;
    for (PostRow row : rows) {
        sum += row.likeCount();
    }
    return sum;
}

public static int sumLikesWithStream(List<PostRow> rows) {
    // Stream<PostRow> → IntStream으로 바꿔야 sum()이 있다
    return rows.stream().mapToInt(PostRow::likeCount).sum();
}

public static List<String> splitTags(String raw) {
    List<String> tags = new ArrayList<>();
    if (raw == null) {
        return tags;
    }
    for (String piece : raw.split(",")) {
        String tag = piece.strip();
        if (!tag.isEmpty()) {
            tags.add(tag);
        }
    }
    return tags;
}

// Coupon (선택 과제)
private Coupon(String name, int totalQuantity) {
    // 빌더와 학습용 팩토리(create)가 같은 이 생성자를 부르므로 검사는 여기 한 곳에 둔다
    if (name == null || name.isBlank()) {
        throw new IllegalArgumentException("쿠폰 이름이 비었습니다");
    }
    if (totalQuantity < 1) {
        throw new IllegalArgumentException("총량은 1 이상이어야 합니다: " + totalQuantity);
    }
    this.name = name;
    this.totalQuantity = totalQuantity;
}

// 주어진 코드(고치지 않는다): 기본 과제 테스트가 빌더 없이 쿠폰을 만드는 같은 패키지 전용 팩토리
static Coupon create(String name, int totalQuantity) {
    return new Coupon(name, totalQuantity);
}

public void issue() {
    if (issuedQuantity >= totalQuantity) {
        throw new IllegalStateException("쿠폰이 모두 소진되었습니다");
    }
    issuedQuantity++;
}

// 아래는 빌더(@Builder가 만드는 코드)
public static CouponBuilder builder() {
    return new CouponBuilder();
}

public static class CouponBuilder {

    private String name;
    private int totalQuantity;

    CouponBuilder() {
    }

    public CouponBuilder name(String name) {
        this.name = name;
        return this;
    }

    public CouponBuilder totalQuantity(int totalQuantity) {
        this.totalQuantity = totalQuantity;
        return this;
    }

    public Coupon build() {
        // 중첩 클래스는 바깥 클래스의 private 생성자를 부를 수 있다
        return new Coupon(name, totalQuantity);
    }
}
```

```java
// CouponIssueService (선택 과제)
private final Coupon coupon;
private final Set<Long> issuedMemberIds = new HashSet<>();

public CouponIssueService(Coupon coupon) {
    this.coupon = coupon;
}

public boolean issue(long memberId) {
    if (issuedMemberIds.contains(memberId)) {
        return false;
    }
    // 소진이면 여기서 예외가 나고, 회원은 기록되지 않는다
    coupon.issue();
    issuedMemberIds.add(memberId);
    return true;
}
```

왜 이렇게 쓰나:

1. 예외마다 `ErrorCode`를 들려 보내면 받는 쪽은 `BusinessException` 하나만 잡고 코드로 응답을 고른다. 자식 예외(`NotFoundException`)는 코드를 생성자에서 정해 두므로 던지는 쪽은 대상과 id만 안다.
2. `Result`는 생성자를 숨기고 이름 있는 static 팩토리(`success`·`failure`)로만 만든다. "값도 있고 에러 코드도 있는" 잘못된 조합을 만들 길이 없다. 엔티티 id를 `Long`으로 두는 것도 같은 생각이다. "아직 없음"을 null이라는 값으로 표현할 수 있어야 저장소가 신규와 기존을 가른다.
3. 엔티티에는 `@Setter`·`@AllArgsConstructor`를 열지 않는다. 생성은 검사가 있는 생성자(빌더나 정적 팩토리를 거쳐)로, 변경은 `issue()` 같은 의도가 드러나는 메서드로만 한다. Lombok을 쓸 때도 이 모양이 나오도록 애노테이션을 고른다.

</details>

## 오늘 Spring에서 다시 만나는 곳

- D02 ① `board-server/src/main/java/com/example/board/common/ErrorCode.java` — 오늘 받은 `ErrorCode`의 원본. 상태는 `HttpStatus`, 유형은 `/errors/...` 경로로 들고 있다.
- D02 ① `board-server/src/main/java/com/example/board/common/BusinessException.java` — `RuntimeException`을 상속하고 `super(detail)`로 메시지를 넘긴다. 오늘 만든 것과 같은 모양이다. board-server에는 `NotFoundException` 같은 자식 클래스가 없고, `new BusinessException(ErrorCode.NOT_FOUND, "글을 찾을 수 없습니다.")`처럼 코드를 직접 넘긴다.
- D02 ① `board-server/src/main/java/com/example/board/common/GlobalExceptionHandler.java` — `@ExceptionHandler(BusinessException.class)` 하나가 모든 업무 예외를 받아 `e.errorCode()`로 ProblemDetail을 만든다. 명세 v2는 응답 래퍼를 두지 않아서 `Result<T>` 같은 클래스는 board-server에 없다.
- D02 ② `board-server/src/main/java/com/example/board/common/BaseEntity.java` — `@MappedSuperclass`로 생성·수정 시각만 물려준다. id는 오늘과 달리 엔티티마다 `private Long id;`로 둔다.
- D02 ④ `board-server/src/main/java/com/example/board/common/NicknameNormalizer.java` — 상태가 없어 private 생성자 + static 메서드로 만든 유틸. 닉네임을 `strip()`으로 다듬는다.
- D03 ② `board-server/src/main/java/com/example/board/member/Member.java` — `@Getter`·`@NoArgsConstructor(access = AccessLevel.PROTECTED)`, `@GeneratedValue`로 DB가 매기는 `Long id`, private 생성자 + `Member.create(...)`. `@Setter`·`@AllArgsConstructor`가 없다.
- D04 ② `board-server/src/main/java/com/example/board/post/Tag.java` — 이날 함정이 "엔티티에 `@Setter`·`@AllArgsConstructor`를 열어 두면 아무 곳에서나 상태가 바뀐다"이다. `protected` 기본 생성자와 `Tag.create(name)`만 있다.
- D04 ④ `board-server/src/main/java/com/example/board/post/PostServiceImpl.java` — `private final` 필드를 받는 생성자를 손으로 썼다(D04에는 저장소 세 개, D07·D09에 `pointService`·`events`가 더해져 지금은 다섯 개). `@RequiredArgsConstructor`를 붙였다면 만들어졌을 코드와 같다(board-server는 생성자 애노테이션을 쓰지 않는다).
