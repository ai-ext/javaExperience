#상황

D05는 조회·수정·삭제를 만드는 날이다. ① 글 상세 조회에서 엔티티를 응답 DTO로 바꾸고, 없는 글은 Optional의 orElseThrow로 404를 낸다. ④ 댓글 목록은 엔티티 목록을 stream().map(CommentResponse::from).toList()로 바꿔 내보낸다. 오늘은 Spring 없이 같은 일을 한다. 엔티티 목록을 for로 한 번, stream으로 한 번 DTO 목록으로 바꾸고, 받은 쿠폰 중 지금 쓸 수 있는 것만 거른다. 리스트에서 지울 때와 Map에 모을 때 자주 터지는 함정도 함께 본다.

#빠른 연상

for 반복문 stream JS로 치면
List<PostResponse> result = new ArrayList<>(); posts.stream() posts
if (post.getStatus() == ACTIVE) .filter(post -> post.getStatus() == ACTIVE) .filter(...)
result.add(PostResponse.from(post)) .map(PostResponse::from) .map(...)
return result; .toList() (배열이 바로 나옴)
찾으면 return, 없으면 null .findFirst() → Optional<T> .find() → T | undefined

흔한 착각: "for를 stream으로 바꾸면 원래 리스트가 바뀐다". stream은 원본을 건드리지 않고 새 리스트를 만든다. 반대로 원본에서 지워야 할 때는 for 안에서 remove하지 말고 removeIf를 쓴다. .toList()가 돌려준 리스트는 고칠 수 없다(J01의 List.of와 같다).

  • 응답 목록에는 ACTIVE 글만 넣는다. PostResponse의 author는 작성자 닉네임, tagCount는 태그 수다.

  • findById는 없으면 빈 Optional을 돌려준다(null 금지).
  • removeUsed는 받은 리스트 자체에서 USED 쿠폰을 지운다.

#타입 한 컷

제네릭에는 왜 래퍼만 쓰나(List<int> 불가), 그리고 합계는 기본형 stream으로.

Stream<Integer> IntStream LongStream
담는 것 Integer 객체 int 값 long 값
만드는 법 list.stream() .mapToInt(Post::getLikeCount) .mapToLong(Post::getLikeCount)
sum() 없다(reduce로) 있다, int로 돌려줌 있다, long으로 돌려줌
넘침 - 21억을 넘으면 조용히 음수 넉넉하다

제네릭(List<T>, Map<K, V>)의 T에는 객체만 들어간다. 그래서 List<int>는 만들 수 없고 List<Integer>로 담는다(컴파일 오류라 테스트로 확인하지 않고 설명으로 다룬다). 숫자를 많이 다룰 때는 박싱이 없는 IntStream·LongStream으로 바꿔 계산한다.

함정: List<Integer>의 remove는 두 개다. remove(int index)는 위치로, remove(Object o)는 값으로 지운다. counts.remove(0)은 값 0이 아니라 0번 자리를 지운다.

과제: LikeSums.totalLikes(넘치지 않게 long으로)와 LikeSums.removeValue(값으로 지우기)를 채운다.

확인 테스트 — J05TypeCutTest:

  • 좋아요_합계는_mapToLong으로_구한다
  • 함정_int로_더하면_21억을_넘을_때_음수가_된다
  • 함정_List_Integer의_remove에_int를_넘기면_값이_아니라_위치를_지운다

#실무 습관

Map 실무 API. get으로 꺼내 고친 뒤 put하는 코드는 처음 보는 키에서 NPE가 난다(get이 null을 돌려준다).

하고 싶은 일 터지는 코드 실무 API
없으면 기본값으로 읽기 map.get(k) → null map.getOrDefault(k, List.of())
없으면 만들고 거기에 담기 map.get(k).add(v) → NPE map.computeIfAbsent(k, key -> new ArrayList<>()).add(v)
세기·더하기 map.put(k, map.get(k) + 1) → NPE map.merge(k, 1, Integer::sum)

과제: TagIndex를 채운다. add는 태그별 글 id 목록에 더하고, postIdsOf는 목록의 고칠 수 없는 복사본(List.copyOf)을, 없는 태그면 빈 리스트를, countTags는 태그별 등장 횟수를 돌려준다. 내부 리스트를 그대로 내주면 받은 쪽의 clear() 한 번에 색인이 비워진다(J01에서 막은 내부 리스트 노출과 같은 함정).

테스트 — J05HabitTest:

  • 함정_처음_보는_키를_get으로_꺼내_add하면_NPE다_computeIfAbsent는_리스트를_만든다
  • computeIfAbsent는_있는_키에는_새로_만들지_않고_이어_붙인다
  • 없는_태그를_찾으면_getOrDefault로_빈_리스트를_돌려준다
  • 돌려준_목록을_고쳐도_색인_안의_목록은_바뀌지_않는다
  • 함정_get에_1을_더해_넣으면_처음_보는_키에서_NPE다_merge는_없으면_1로_넣는다
✓ 확인끝났는지 판단

#정답

펼치기 
// PostResponse
public static PostResponse from(Post post) {
    return new PostResponse(post.getId(), post.getTitle(), post.getAuthorNickname(), post.getTags().size());
}

// PostMapper
public static List<PostResponse> toResponsesWithFor(List<Post> posts) {
    List<PostResponse> responses = new ArrayList<>();
    for (Post post : posts) {
        if (post.getStatus() == PostStatus.ACTIVE) {
            responses.add(PostResponse.from(post));
        }
    }
    return responses;
}

public static List<PostResponse> toResponsesWithStream(List<Post> posts) {
    // if → filter, add(변환) → map, 모으기 → toList
    return posts.stream()
            .filter(post -> post.getStatus() == PostStatus.ACTIVE)
            .map(PostResponse::from)
            .toList();
}
// CouponFinder
public static List<MemberCoupon> usable(List<MemberCoupon> coupons, int orderAmount, LocalDate today) {
    return coupons.stream()
            .filter(coupon -> coupon.status() == CouponStatus.UNUSED)
            // "만료일이 오늘 이후"(isAfter)로 쓰면 당일 쿠폰이 빠진다. "오늘이 만료일을 지나지 않았다"로 쓴다
            .filter(coupon -> !today.isAfter(coupon.expiresOn()))
            .filter(coupon -> orderAmount >= coupon.minOrderAmount())
            .toList();
}

public static Optional<MemberCoupon> findById(List<MemberCoupon> coupons, long id) {
    return coupons.stream()
            .filter(coupon -> coupon.id() == id)
            .findFirst();
}

public static void removeUsed(List<MemberCoupon> coupons) {
    // 향상된 for 안에서 remove하면 다음 차례에 ConcurrentModificationException. removeIf는 안에서 안전하게 지운다
    coupons.removeIf(coupon -> coupon.status() == CouponStatus.USED);
}
// PostStats
public static Map<String, Integer> likesByAuthor(List<Post> posts) {
    return posts.stream()
            .collect(Collectors.groupingBy(Post::getAuthorNickname, Collectors.summingInt(Post::getLikeCount)));
}
// LikeSums
public static long totalLikes(List<Post> posts) {
    // Stream<Post> → LongStream. 기본형 stream이라 박싱 없이 sum()을 바로 쓴다
    return posts.stream().mapToLong(Post::getLikeCount).sum();
}

public static void removeValue(List<Integer> counts, int value) {
    // remove(int)는 위치, remove(Object)는 값이다. Integer로 감싸야 값으로 지우는 쪽이 불린다
    counts.remove(Integer.valueOf(value));
}
// TagIndex
public void add(String tag, long postId) {
    // 키가 없을 때만 함수를 불러 새 리스트를 넣고, 있든 없든 그 키의 리스트를 돌려준다
    postIdsByTag.computeIfAbsent(tag, key -> new ArrayList<>()).add(postId);
}

public List<Long> postIdsOf(String tag) {
    // 내부 리스트를 그대로 내주면 밖에서 clear·add로 색인을 바꿀 수 있다(J01에서 막은 내부 리스트 노출). 복사본을 준다
    return List.copyOf(postIdsByTag.getOrDefault(tag, List.of()));
}

public static Map<String, Integer> countTags(List<Post> posts) {
    Map<String, Integer> counts = new HashMap<>();
    for (Post post : posts) {
        for (String tag : post.getTags()) {
            // 키가 없으면 1을 넣고, 있으면 (기존 값, 1)을 Integer::sum으로 합친다
            counts.merge(tag, 1, Integer::sum);
        }
    }
    return counts;
}

왜 이렇게 쓰나:

  1. 엔티티 → DTO 변환은 DTO의 static 팩토리(from) 한 곳에 두고, 목록은 map(PostResponse::from)으로 바꾼다. 어떤 값을 내보내는지가 한 곳에 모인다.
  2. "없을 수도 있는 하나"는 Optional로 돌려준다. 받는 쪽이 orElseThrow로 404를 내거나 isEmpty로 갈라야 해서 null을 잊고 지나칠 수 없다.
  3. 숫자를 모을 때는 기본형 stream(mapToLong)으로, Map에 모을 때는 computeIfAbsent·merge로 쓴다. get으로 꺼내 고치는 코드는 처음 보는 키에서 터진다.
