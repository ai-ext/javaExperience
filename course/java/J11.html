  • J11MutantTest — 네 테스트를 원본과 변형 6개에 돌려 본다. 변형은 원본에서 한 곳만 바꾼 것이다.

변형이 무엇을 바꿨는지는 LegacyPointCalculatorMutant.java에 있다. 먼저 보지 말고 테스트를 써 본다. 그다음 J11MutantTest의 실패 메시지(변형 [...]에서도 특성화 테스트가 모두 통과합니다)를 보고 빠진 경우를 더한다. 해피 패스만 확인하는 테스트로는 변형이 잡히지 않는다.

변형이 검사하는 것은 경계 일부다(5만 원·1000원 경계, 3000 상한, VIP 예외, 대소문자, 내림). 변형 6개를 다 잡아도 음수 금액(-1)·null 등급 같은 경우는 아무도 검사하지 않는다. 완료 조건 밖이지만 "분기마다 경계 양쪽" 목록은 스스로 끝까지 채운다. 리팩터링할 때 안전망이 되는 것은 변형 테스트가 아니라 네가 고정한 경우들이다.

#상황

D11부터는 남이 만든 코드를 넘겨받는다. D11 ②에서 글 작성·수정·삭제와 GET /api/members/me의 지금 동작을 특성화 테스트로 고정한다. 그다음 ③④에서 버그를 고치고 구조를 바꾼다. 고정한 테스트가 안전망이 되어, 고치는 동안 다른 동작이 바뀌면 바로 드러난다. 오늘은 Spring 없이 같은 일을 해 본다. 문서 없이 조건이 덧붙은 레거시 포인트 계산 메서드가 있다. 이 메서드가 지금 돌려주는 값을 테스트로 고정한다. 이 테스트가 정말 동작을 고정했는지는 메서드를 일부러 한 곳씩 망가뜨린 변형으로 확인한다.

#빠른 연상

보통 테스트(명세) 특성화 테스트
기대값의 출처 요구사항, "이래야 한다" 지금 코드를 불러서 나온 값
이상한 동작을 만나면 버그로 보고 실패시킨다 그대로 적는다. 고치는 것은 나중 일이다
목적 새 기능이 맞는지 확인 리팩터링 중에 동작이 바뀌지 않았는지 감지
일상 비유 설계도대로 지었는지 검사 이사 전에 방마다 사진을 찍어 두기

흔한 착각: "특성화 테스트에도 옳은 값을 적어야 한다". 옳은 값을 적으면 고치기 전부터 실패한다. 그러면 테스트가 지금 동작을 고정하지 못하고 안전망 역할도 못 한다(D11 ②의 함정). VIP는 5만 원 보너스가 없다. 이 규칙이 이상해 보여도 지금 그렇게 돌아가고 있으므로 그대로 적는다.

#타입 한 컷

배열 vs List. 레거시 코드는 String[] gradeNames(), int[] gradeRates()처럼 배열을 돌려준다.

배열 String[] List<String> (ArrayList) Arrays.asList(배열)
길이 만들 때 고정 늘고 준다 고정(add하면 UnsupportedOperationException)
원소 바꾸기 된다 된다 된다. 원본 배열도 같이 바뀐다(배열 위의 뷰)
공변성 String[]을 Object[]에 대입 가능. 잘못 넣으면 실행 중 ArrayStoreException List<String>을 List<Object>에 대입 불가. 컴파일에서 막는다 List와 같다
기본형 int[] 가능 List<int> 불가(List<Integer>) Arrays.asList(int[])는 List<int[]>, 원소 1개

함정: 배열을 List로 바꿀 때 Arrays.asList를 그대로 쓰면 두 가지가 터진다. ① 나중에 add하면 예외가 난다. ② 그 List를 고치면 레거시가 들고 있는 배열까지 바뀐다. 그래서 new ArrayList<>(Arrays.asList(배열))로 한 번 더 복사한다. int[]는 Arrays.stream(values).boxed()로 옮긴다.

과제: GradeLists.toModifiableList(String[])과 GradeLists.toIntegerList(int[])를 채운다.

확인 테스트 — J11TypeCutTest:

확인할 테스트 이름 4개
  • 배열은_길이가_고정이고_List는_늘어난다
  • 함정_Arrays_asList는_크기가_고정이고_원본_배열과_연결돼_있다
  • 배열은_공변이라_잘못된_원소가_실행_중에야_터진다
  • 함정_int_배열을_Arrays_asList에_넣으면_원소가_하나다
✓ 확인끝났는지 판단

#구현 예시

펼치기▸

왜 이렇게 쓰나:

  1. 분기마다 경계 양쪽(49999/50000, 999/1000)과 이상한 규칙(VIP 보너스 없음, 소문자 등급, 내림)을 하나씩 고정해야 변형이 잡힌다. 변형 6개는 각각 다른 테스트가 잡는다. >=→>는 50000 경계가, VIP 예외 삭제는 VIP 50000이, 내림→반올림은 홀수 포인트에 쿠폰을 쓴 경우가, <→<=는 1000원이, 상한 값 변경은 3000에서 잘린 경우가, equalsIgnoreCase는 소문자 vip가 잡는다. 음수와 null 등급은 변형이 없어도 같이 고정한다.
  2. 조합 표(골든 마스터)는 빠뜨린 분기를 메워 준다. 하지만 어떤 규칙이 깨졌는지 이름으로 알려 주지는 못한다. 그래서 이름 붙인 경계 테스트와 같이 둔다.
  3. 레거시가 돌려준 배열은 들고 있지 말고 내 List로 복사한다. 그래야 레거시 쪽 배열과 내 List가 서로를 바꾸지 않는다.
