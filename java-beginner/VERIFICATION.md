# 독립 HTML 확인 기록

확인일: 2026-10-25. 결과물은 `java-beginner.html`이며 기존 학습 사이트나 학습자의 Spring 구현을 수정하지 않았다.

## 후속 개편: 게시판부터 시작

- 사용자 교정에 따라 인사/계산 API의 초기 4회차를 제외하고, 사내 공지 게시판을 1단계 Day 1~8로 이동했다.
- 기존 후속 회차를 재배정하고 새 운영 변경 기능을 Day 54~57에 추가해 12개 기능·60회차를 유지했다. 현재 목표 API 계약은 36개다.
- 새 기능은 삭제 공지 보관/관리자 복구/이력, 부모가 삭제된 댓글·첨부 접근 차단, 기존 데이터 보존 migration, 호환 배포와 문제 대응이다.
- 회차별 업무 요청서 14개에 요청자·상황·요청·제약·확인할 결과를 작성했다.
- 같은 기능의 기획서가 동일한 이유를 안내하고 탭 이름을 ‘공통 기획서’로 바꿨다. 선택한 회차의 구현 범위를 별도로 표시하고 업무 요청은 ‘오늘 할 일’에 둔다.
- 진도 v1 원본은 지우지 않으며 v2로 대응 변환한다. 이전 인사 API의 완료는 게시판 완료로 자동 변환하지 않는다.
- 후속 자동 검사 명령: `node --test java-beginner/course.test.mjs java-beginner/progress.test.mjs java-beginner/request.test.mjs java-beginner/server.test.mjs`.
- 후속 자동 검사 7개 통과. Chrome에서 Day 1/2 공통 기획서의 공통 본문과 서로 다른 일별 구현 범위, Day 54의 OPS-010/Day 56의 QA-012 업무 요청 표시를 확인했다. 1440×900에서 요청 화면의 가로 넘침이 없으며 `preview-work-request.jpg`로 캡처했다.
- 아래 초판 브라우저 검증 기록의 인사 API·Day 46 등의 번호는 당시 과정 기준이다. 후속 개편의 화면 확인은 별도 기록한다.

## 작성 범위

- 12개 기능 묶음, 연속된 Day 1~60, 권장 하루 2~3시간.
- 기능마다 목적/사용 장면/범위/정책/완성 결과, 화면 항목, 저장 필드/타입/제약/데이터 예시/확인 SQL.
- 회차마다 구체적인 구현 과제, Java 개념, 확인 조건, 관련 API 연결.
- 실제 HTTP 요청 편집, 정상/실패 사례, 파일 선택, 세션 쿠키 전달, CSRF/Bearer 입력, 상태/본문/헤더/시간 표시.
- 생성된 자원 번호는 현재 창 메모리에서 이어 쓰며 수동 진도만 독립 저장 키에 기록.

## 자동 확인

`node java-beginner/build.mjs`가 단일 HTML을 생성하며 브라우저 JavaScript 구문을 검사한다. 외부 JavaScript/CSS/폰트를 가져오지 않는다.

`node --test java-beginner/course.test.mjs java-beginner/request.test.mjs java-beginner/server.test.mjs`로 다음을 확인한다.

- 60개 회차의 연속성·고유성, 기획/화면/DB/API/정상·실패 사례, 회차의 API 연결.
- 잘못된 JSON·지원하지 않는 메서드·외부 주소/상위 경로·금지 헤더 차단.
- 한글 쿼리, 경로 번호, 생성 번호 이어 쓰기, GET 본문 생략, HTTP 상태/필수 최상위 필드 판정.
- 실제 로컬 HTTP fixture로 메서드/본문/세션 쿠키/CSRF 헤더 전달, 404 보존, 리다이렉트 분리, 다른 출처 요청 차단, 연결 실패 502, 본문 중간 연결 단절의 실행기 오류 분리.
- 최초 새 탭 문서 탐색은 허용하며 API 전달에는 출처 검사를 유지한다.

## Chrome에서 확인한 조작

1. 전체 기능 목록, 게시판 회차 이동, 기능 기획서/화면·DB 탭 표시.
2. 학습 완료 표시 → 새로고침 후 유지 → 취소하여 초기 0회차로 복원.
3. “동시 취소” 검색 → Day 46 이동.
4. `qa/browser-fixture.mjs`의 격리 메모리 HTTP 서버에서 이름 요청 200 / 이름 누락 400.
5. 깨진 JSON을 전송 전에 차단, 공지 생성 응답 id=42를 상세 경로에 이어 쓰고 재조회.
6. 실패 예시의 999999999가 실제 생성 id=42를 덮어쓰지 않으며 정상 사례로 돌아오면 42 복원.
7. 실제 기본 대상 127.0.0.1:8080이 꺼진 상태에서 실행기 연결 실패 502 표시. API 성공으로 오표시하지 않음.
8. health 실패 사례에 503 / status=DOWN 목표 예시 표시.
9. PC 1366×768, 1440×900, 1920×1080에서 기능 카드 12개와 가로 넘침 없음 확인. `preview.jpg`는 실제 1440×900 화면 캡처.

## 확인 범위의 한계

- HTTP fixture 성공은 요청 도구 검증이다. 현재 과정의 36개 API 계약을 실제 Spring/MySQL에 모두 구현·실행한 것이 아니다.
- 기존 학습자의 미완성 Java는 수정하거나 대신 완성하지 않았고, 루트 Gradle 컴파일/통합 테스트는 작업 범위가 아니므로 실행하지 않았다.
- 파일 다운로드/업로드/로그인 쿠키의 전체 브라우저 흐름은 실제 학습 서버로 미실행이다. 쿠키 전달 규칙은 HTTP 통합 테스트로 확인했다.
- 브라우저 도구의 URL 정책이 file: 탐색을 거절해 파일 더블 클릭 경로는 브라우저 자동화로 확인하지 못했다. 이 제한을 우회하지 않고 localhost의 동일 HTML로 화면을 확인했다. 단일 파일의 데이터/CSS/JS 포함과 file 모드에서 API 전송을 비활성화하는 코드는 확인했다.
- imagegen 시안 제작·시안과의 동등성 검증은 요청 범위가 아니다. 이를 완료하거나 verified 상태라고 표시하지 않는다.
- 독립 결과물의 소스·빌드·확인 기록을 새 폴더 안에서 관리하며 기존 `tools/site` 빌드와 HTML·장부를 재생성하지 않았다.

## 검토에서 보완한 점

- 일부 응답을 받다가 연결이 끊겨도 실행기 502를 실제 API 응답으로 표시하지 않도록 본문 수신 완료 후에만 마커를 설정했다.
- CSRF 조회 준비를 Day 19로 앞당겨 Day 20 가입과 Day 21 로그인의 선행조건을 맞췄다.
- Day 24에 local 전용 ADMIN 테스트 계정 준비, Day 6/12에 Repository interface와 구현 객체·제네릭 설명을 추가했다.
